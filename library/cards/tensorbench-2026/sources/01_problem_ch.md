TensorBench 回答的不是泛化的“代码生成能力”问题，而是一个更窄的仓库级问题：编码智能体能否为真实编译器仓库增加功能或完成行为保持的重构，同时维持仓库在已测试范围内的正确状态。仓库级任务虽然困难，但既有测试通常并非为捕获任意机器生成回归而设计，逐补丁人工审核又难以扩展。TensorBench 选择 Python/C++ 稀疏与稠密张量编译器 Scorch，是因为其随机化回归测试可将大量外部可见结果与稠密 PyTorch 或既有未优化执行路径比较。

评测面包含固定在 5 个 Scorch commit 上的 199 个任务，其中 194 个是功能新增、5 个是重构。单条任务记录包含 instance ID、仓库 URL、base commit、自然语言描述、相关文件、安装与测试命令、超时、任务类型和主题分类。一次被评测 episode 还包括 scaffold/模型配置、可获得时的仓库观察与工具调用、最终 unified diff、实现与测试改动、pytest 输出以及终局通过/失败报告。

本卡归入“环境与智能体轨迹数据”，因为仓库状态、Docker 镜像、动作历史、补丁、测试和终止谓词共同构成数据对象。它不是智能体训练证据：论文报告的是评测与审计，而非 SFT 或 RL。其 L4 价值在于明确给出“fresh-checkout 可执行评分 + 独立对抗行为审计”的反馈边界，同时明确指出新功能主要由同一被测智能体编写的测试约束。官方 arXiv 全文与附录、TensorBench 项目页/榜单、Hugging Face 任务 artifact 和 Scorch 仓库支持上述事实；论文声称发布的 predictions 与 trajectories 目录当前无法逐文件核验。
