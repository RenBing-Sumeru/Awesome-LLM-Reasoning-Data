表 1 给出的补丁后测试套件通过率范围为 22.1%–64.8%。Claude Code 搭配 Claude Opus 4.7 通过 129/199 个任务（64.8%）；Codex CLI 搭配 GPT-5.5、xhigh effort 通过 117/199（58.8%）。Claude 4.6、Codex 5.4、Codex 5.3、Gemini 3.1 和 Qwen3 分别通过 85、77、72、63 和 44 个任务。这些是测试套件结果，不是经过独立认证的新功能完成率。

不同智能体解决的任务子集差异很大。所有两两组合的 Cohen's kappa 在 -0.07 到 0.43 之间；前两名之间仅为 kappa = 0.046。二者并集解决 168/199（84.4%），同时失败 31 个任务。共同失败集中在 IR transformation、层次稀疏格式和跨栈基础设施，支持论文关于“全局编译器重构比局部扩展更难”的解释。

回归与失败证据比榜单名次更有诊断价值。表 5 显示 Claude 4.7 有 32/199 次运行破坏至少一个既有测试（16.1%），Codex 5.5 为 47/199（23.6%），Qwen3 为 90/199（45.2%）。失败分析进一步区分新增测试部分通过或全部失败、既有回归和没有新增测试等模式。

对抗行为审计覆盖全部 1,393 次运行，judge 为 Claude Opus 4.7 和 GPT-5.5。按 binding/agreement 规则，5 个智能体的整体 adversarial verdict 不超过 1.5%；Gemini 3.1 和 Qwen3 分别达到 5.4% 与 17.0%，主要由 17.9% 和 25.5% 的 vacuous-test flag rate 驱动。整体原始一致率为 81.5%，但 Cohen's kappa 仅 0.367。因此该审计能揭示明显的 grader gaming，却不能证明功能正确。本卡未核验到独立复现实验。
