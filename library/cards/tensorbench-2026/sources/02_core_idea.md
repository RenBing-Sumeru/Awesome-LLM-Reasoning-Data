The central contribution is a repository-agent benchmark whose score depends on final executable behavior rather than similarity to a canonical patch. Each task pairs a natural-language change request with a pinned Scorch base commit. The agent works in a containerized checkout and produces a patch, often including new tests. The grader extracts that diff, applies it to a fresh checkout at the same commit, rebuilds the C++ extension, and executes the entire pytest suite.

The feedback contract is programmatic and environmental. The terminal predicate is exactly that the after-patch failure count is zero: after.failed == 0. Inherited randomized and parametrized tests probe preservation of existing tensor/compiler behavior; agent-added tests probe the requested feature. The verifier observes executed test outcomes and repository effects, but it does not observe semantic completeness outside tested inputs, every reasonable interpretation of the request, or whether agent-written tests adequately constrain the named API. A separate two-LLM audit checks four local gaming patterns—API mismatch, weakened existing tests, no substantive implementation edit, and vacuous added tests—without attempting to solve the task itself.

Relative to SWE-Bench-style issue repair, TensorBench emphasizes feature addition and does not require a reference patch. Relative to Terminal-Bench and MLE-Bench, it narrows the environment to one compiler whose outputs admit randomized reference comparisons. The important direction signal is therefore not “another leaderboard”; it is the coupling of task records, full repository episodes, executable terminal outcomes, regression preservation, and verifier-audit evidence. The closest caveat is also structural: when the evaluated agent authors the feature tests, implementation and oracle errors can agree with each other.
