核心贡献是一套仓库级智能体基准：评分依据最终可执行行为，而不是补丁与某个标准答案的相似度。每个任务把自然语言变更请求与固定的 Scorch base commit 配对。智能体在容器化 checkout 中工作并生成补丁，功能任务通常还包含新测试。评分器提取 diff，将其应用到同一 commit 的 fresh checkout，重新构建 C++ 扩展，然后执行完整 pytest 测试套件。

反馈契约同时是 programmatic 和 environmental。终止谓词精确定义为补丁后失败数为零，即 after.failed == 0。继承的随机化、参数化测试检查既有张量与编译器行为是否保持；智能体新增测试检查所请求的新功能。验证器能观察执行后的测试结果和仓库效应，却不能观察测试输入之外的语义完整性、自然语言请求的所有合理解释，也不能保证智能体自写测试充分约束了指定 API。另有两个 LLM 组成的审计面板检查四类局部投机：API 不匹配、削弱既有测试、没有实质实现改动、空洞新增测试；该审计不重新求解底层任务。

相较 SWE-Bench 一类 issue 修复基准，TensorBench 强调功能新增且不依赖 reference patch；相较 Terminal-Bench 和 MLE-Bench，它把环境收窄为一个可通过随机参考结果验证输出的编译器。真正的方向信号不是“又一个榜单”，而是把任务记录、完整仓库 episode、可执行终局结果、回归保持和验证器审计证据绑定在一起。其最关键风险也来自同一结构：当被测智能体自己编写新功能测试时，实现错误与 oracle 错误可能彼此一致。
