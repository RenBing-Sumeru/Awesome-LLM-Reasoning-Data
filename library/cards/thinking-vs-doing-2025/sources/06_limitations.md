**Method and credit assignment.** Positive-only episode filtering provides no process label for intermediate actions. A successful episode can contain redundant searches, accidental recoveries, or actions that would fail under a slightly different page state, yet every retained action becomes a positive BC target. Conversely, failed episodes that contain useful partial progress are excluded from the loss. The curriculum changes achievable behavior but does not solve this terminal-credit ambiguity.

**Verifier and judge risk.** WebVoyager's prompted judge can produce false positives and false negatives; the reported 88.9% aggregate accuracy leaves calibration, class balance, and attack robustness unknown. The public release does not pin the paper's Gemma 3 27B evaluator and instead exposes a 12B config plus code that reuses the policy's `agent.get_action` path. WebArena's programmatic evaluators are more direct but remain tied to task specifications and environment state, and neither feedback path establishes step correctness. The paper itself observes that repeated checking can harm correct answers, that the agent can over-rely on Bing resets, and that final-step self-verification can miss constraints such as a required repository year.

**Split and lineage risk.** In the pinned release, all 733 WebArena train IDs/questions also appear in the 812-row test file, although endpoint fields differ. This proves that the default released files do not encode a clean train/test task separation; it does not prove that the paper's original run used the same file state. WebVoyager's 128,072 train rows contain 104,756 unique `(web_name, question)` pairs but only 3,184 unique IDs. The 337 IDs shared with test are lineage-key collisions, not direct task contamination, because no exact `(web_name, question)` pair overlaps. Exact paper-run split IDs, random seeds, generator lineage, deduplication rules, and rejection statistics remain unknown.

**Release and replay risk.** The repository publishes tasks, code, configs, and two checkpoints, not `train_trajectories.pt`, `evaluate_trajectories.pt`, screenshots, successful/failed rollout manifests, or an immutable browser/environment snapshot. Live WebVoyager sites can change through content, cookies, layout, availability, or browser behavior; WebArena also requires pinned images and database state. The absence of raw and rejected episodes blocks independent audit of reward errors, domain weighting, replay age, and dropped failures.

**Configuration and rights risk.** Paper and scripts disagree on material settings: WebVoyager is 12 iterations/six GPUs in the paper versus 15 iterations/four devices in the public script; WebArena reports four GPUs while its script names two devices. The GitHub repository has no root LICENSE, tag, or release. Hugging Face checkpoint metadata says MIT, but that does not resolve upstream Gemma terms or rights in task text, website content, or screenshots. Privacy/consent and redaction procedures are unknown. Experiments cover web agents only; robotics and open-world computer use remain future work, and Table 3/Table 4 have not been independently reproduced for this Card.
