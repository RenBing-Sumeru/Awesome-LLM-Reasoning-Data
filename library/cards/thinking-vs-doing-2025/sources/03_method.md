**Inputs.** TTI trains separate agents for WebArena's self-hosted domains and WebVoyager's live websites. The paper reports 11K WebArena-domain tasks and 128K synthetically generated WebVoyager tasks. The pinned release instead contains 733 WebArena train rows and 128,072 WebVoyager train rows, so reproduction must not silently equate paper-scale collections with released files. The policy is `google/gemma-3-12b-it`. The exact exploratory task-generator model/checkpoint, its decoding settings, per-record lineage, rejection counts, and training temperature are unknown.

**Online interaction.** Per iteration, the paper reports sampling 512 tasks for rollout. The policy receives the task, URL, accessibility tree, set-of-marks screenshot, the latest three observations, and the entire action history. It emits thought plus one of six actions, then receives the browser's next observation. The environment loop stores `observation`, `next_observation`, `reward`, `done`, model `action`, `info`, answer and optional reference answer, and later attaches `trajectory_reward`, Monte-Carlo return, and `max_steps`. Episodes end on stop/ANSWER or the horizon.

**Verification and filtering.** WebArena runs task-specific ground-truth evaluators on the final state. WebVoyager sends the task, final answer, and screenshots to a prompted multimodal judge. The paper's full-scale detector is Gemma 3 27B; however, the released WebVoyager YAML pins only `google/gemma-3-12b-it`, and evaluation code calls the same `agent.get_action` object used for the policy. A paper-aligned evaluator checkpoint and invocation are therefore not reproducibly pinned. After collection, code saves trajectories locally, retains only non-empty episodes with positive terminal reward, removes terminal `ANSWER [N/A]`, and flattens surviving steps for supervised learning. Failed episodes do not enter the loss.

**Replay and curriculum.** TTI starts with horizon 10 and raises it toward 30 so shorter successful behaviors enter training before longer exploration. The paper describes replay with greater weight on recent trajectories. The public trainer additionally mixes linear recency and inverse-domain-frequency sampling weights equally when it must subsample. The paper reports updating from 512 successful on-policy trajectories per iteration, but total attempts, success rates, duplicate counts, failed counts, and replay-buffer sizes are undisclosed.

**Optimization and outputs.** The loss maximizes the likelihood of retained action text given the processed state: cross-entropy behavior cloning with AdamW and WarmupCosineLR. Paper settings report WebArena at 10 iterations, learning rate `1e-6`, batch size 4, gradient accumulation 2, four training GPUs, and evaluation horizon 30; WebVoyager reports 12 iterations, learning rate `4e-6`, and six GPUs with the same core rollout/update counts. The public scripts drift: WebArena names two CUDA devices, while WebVoyager uses 15 iterations and four devices. A reproduction must choose and report either a paper-aligned or release-aligned configuration rather than merging them.

**Released versus generated objects.** Runtime code writes `train_trajectories.pt` and `evaluate_trajectories.pt`, but neither file nor an equivalent rollout/screenshot corpus is public. The official repository exposes five task JSONL files, training/evaluation code, prompts/configs, and links to TTI-WebVoyager and TTI-WebArena checkpoints. It provides no root LICENSE, GitHub tag, or GitHub release. Reproduction therefore requires regenerating episodes under pinned browser, website, WebArena image/database, evaluator, checkpoint, random-seed, dependency, and CUDA/runtime states; several of those pins remain unknown.
