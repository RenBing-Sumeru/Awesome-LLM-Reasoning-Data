**Inputs。**TTI 分别为 WebArena self-hosted domains 和 WebVoyager live websites 训练 agents。论文报告了 11K 个 WebArena-domain tasks 和 128K 个 synthetically generated WebVoyager tasks；固定 commit 的公开发布则包含 733 条 WebArena train rows 和 128,072 条 WebVoyager train rows。因此，复现时不能默认论文规模的 collection 与公开文件完全相同。policy 是 `google/gemma-3-12b-it`。exploratory task-generator 的确切 model/checkpoint、decoding settings、逐记录 lineage、rejection counts 和训练 temperature 均为 unknown。

**Online interaction。**论文报告每次 iteration 抽取 512 个 tasks 进行 rollout。policy 接收 task、URL、accessibility tree、set-of-marks screenshot、最近三步 observations 和完整 action history；随后输出 thought 与六种 actions 之一，并获得浏览器的 next observation。environment loop 存储 `observation`、`next_observation`、`reward`、`done`、模型 `action`、`info`、answer 和可选 reference answer，之后再附加 `trajectory_reward`、Monte-Carlo return 与 `max_steps`。episode 在 stop/ANSWER 或达到 horizon 时结束。

**Verification and filtering。**WebArena 对 final state 运行 task-specific ground-truth evaluators。WebVoyager 将 task、final answer 与 screenshots 交给 prompted multimodal judge。论文的 full-scale detector 是 Gemma 3 27B；但公开 WebVoyager YAML 只固定了 `google/gemma-3-12b-it`，evaluation code 还调用与 policy 相同的 `agent.get_action` 对象。因此，paper-aligned evaluator checkpoint 与 invocation 并未被可复现地固定。收集完成后，代码先在本地保存 trajectories，再仅保留 terminal reward 为正的非空 episodes，移除 terminal `ANSWER [N/A]`，最后将保留步骤展平用于 supervised learning。失败 episodes 不进入 loss。

**Replay and curriculum。**TTI 从 horizon 10 开始并逐步提高到 30，使较短的成功行为先于更长的探索进入训练。论文描述 replay 时会提高近期 trajectories 的权重；公开 trainer 在必须 subsample 时，还等权混合 linear recency 与 inverse-domain-frequency sampling weights。论文报告每次 iteration 使用 512 条 successful on-policy trajectories 更新，但总尝试数、success rates、duplicate counts、failed counts 和 replay-buffer sizes 均未披露。

**Optimization and outputs。**loss 在 processed state 条件下最大化被保留 action text 的似然，即使用 AdamW 和 WarmupCosineLR 的 cross-entropy behavior cloning。论文设置中，WebArena 运行 10 iterations，learning rate 为 `1e-6`，batch size 为 4，gradient accumulation 为 2，使用四张 training GPUs，evaluation horizon 为 30；WebVoyager 报告 12 iterations、learning rate `4e-6` 和六张 GPUs，核心 rollout/update counts 相同。公开 scripts 存在漂移：WebArena 只列出两个 CUDA devices，而 WebVoyager 使用 15 iterations 和四个 devices。复现应明确选择并报告 paper-aligned 或 release-aligned configuration，而不能将二者混成一套设置。

**Released versus generated objects。**运行时代码会写出 `train_trajectories.pt` 与 `evaluate_trajectories.pt`，但这两个文件以及等价的 rollout/screenshot corpus 都未公开。官方仓库提供五个 task JSONL 文件、training/evaluation code、prompts/configs，并链接 TTI-WebVoyager 与 TTI-WebArena checkpoints；仓库没有 root LICENSE、GitHub tag 或 GitHub release。因此，复现必须重新生成 episodes，并固定 browser、website、WebArena image/database、evaluator、checkpoint、random seed、dependency 与 CUDA/runtime states；其中多项 pin 仍为 unknown。
