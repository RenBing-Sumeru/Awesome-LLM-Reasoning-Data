VerlTool addresses an engineering and research gap in agentic reinforcement learning: a policy that pauses to call tools needs an online rollout system that can maintain one environment state per trajectory, return observations without treating those observations as policy actions, and attach task-specific outcome feedback across heterogeneous domains. A static prompt-answer record cannot represent this interaction boundary, while a task-specific tool wrapper makes it difficult to compare or reuse training infrastructure across math, retrieval, SQL, visual reasoning, deep search, and software engineering (paper §§3.2–3.3; Appendix A).

The paper-level data object is an on-policy episode `tau={a0,o0,...,a_(n-1),o_(n-1),a_n}`. Each `a_i` is a model action-token segment and each `o_i` is a tool-observation segment. The Tool Server maintains per-trajectory environment state; current code also exposes trajectory identifiers, validity, termination, turn counts, stop reasons, and replay-cache fields, but those current-main fields are not a frozen paper-era serialization. Observation tokens are normally masked when the policy objective is computed (paper §3.2; current repository inspected at commit `383d4b1539ba387f94c3a117d3edc06b467c09d1`).
