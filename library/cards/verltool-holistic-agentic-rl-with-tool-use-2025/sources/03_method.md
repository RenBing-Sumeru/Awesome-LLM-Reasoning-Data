Inputs are six heterogeneous task recipes. VT-Math uses DeepMath prompts and a Python interpreter. VT-Search uses retrieval QA with an E5 retriever and a FAISS index built from a 2018 Wikipedia dump. VT-SQL uses SkyRL-SQL questions, databases, and executable ground-truth SQL. VT-VisualReasoner uses Pixel-Reasoner tasks with zoom/frame-selection tools. VT-DeepSearch trains on a 1K mixture from SimpleDeepSearcher and Web-Sailor using SERPER-backed Google Search with caching. VT-SWE uses R2E-Lite tasks through the R2E-Gym scaffold (Appendix A.1–A.6).

For each task, the online policy emits an action until the configured stop token. VeRL Workflow sends the action and auxiliary trajectory metadata to the Tool Server. A plugin implements `parse_action`, `load_env`, `conduct_action`, `update_env`, and `delete_env`, so different trajectories can retain independent state and issue tool calls asynchronously. The returned observation is appended to the policy context, and interaction repeats until a domain completion condition, maximum-turn limit, or failure. The policy objective is computed over action-token segments while normally masking observation tokens (paper §§3.2–3.3).

The verifier/reward stage is domain-specific. Math uses `R_acc=1` for a matched answer and `-1` otherwise, plus a tool term of 0 when correct and `-0.25` otherwise. Retrieval uses exact-match reward 1/-1. SQL uses execution-result agreement with reward 1/-1. Visual reasoning uses accuracy, curiosity, and redundant-call terms with `H=.3`, `N=1`, `alpha=.5`, and `beta=.05`. Deep search combines answer accuracy with a `0.1` any-tool-call bonus. SWE returns 1 only for normal termination plus all verification tests passing; timeout, exception, or excessive length returns 0 and masks gradients, with 90-second interaction, 300-second reward, and 20-minute episode timeouts (Appendix A).

Appendix Table 8 gives rollout batch sizes `128/512/256/128/128/32`, samples per task `16/16/5/8/16/8`, and maximum turns `1/2/5/3/5/100` for Math/Search/SQL/Visual/DeepSearch/SWE. Training temperature is 1.0 except VisualReasoner at 0.6; top-p is 1.0 except VisualReasoner at 0.95. GRPO is the common optimizer baseline and DAPO is also evaluated. Actor learning rate is `1e-6` except SWE at `2e-6`. These settings are domain-specific; the paper does not disclose one global rollout count, filter, or selection threshold.

Outputs are online episodes and their task scalar rewards used for RLVR, agent training, and evaluation. No evidence supports SFT, distillation, preference learning, or reward-model training from a released episode corpus. Official HF repositories verified for DeepSearch and SQL expose task prompts/reference objects plus a search cache or databases—not rollout episodes. Exact replay requires the paper code commit, `verl` submodule and dependency locks, model/checkpoint revisions, dataset/index/database/container snapshots, API behavior and credentials, caches, seeds, task splits, and episode manifests. No paper-pinned bundle supplies that complete chain, and the current SWE training README remains incomplete.
