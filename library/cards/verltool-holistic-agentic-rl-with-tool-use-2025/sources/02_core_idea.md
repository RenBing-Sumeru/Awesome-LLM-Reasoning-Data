VerlTool's contribution is a common agentic-RL boundary between rollout generation and tool execution: the VeRL Workflow produces policy actions and updates the actor, while a stateful Tool Server executes actions asynchronously and returns observations to the appropriate trajectory. A recognized stop token delimits each action; the server-side plugin parses it, loads or updates the environment, conducts the action, and eventually deletes per-trajectory state (paper §3.3).

The resulting feedback object combines an interleaved action-observation episode with a domain-specific scalar outcome. Math and retrieval use answer matching; SQL uses execution accuracy; visual reasoning combines answer accuracy with curiosity and redundant-call shaping; deep search adds `0.1` when any tool call occurs; and SWE assigns reward 1 only after normal termination with all verification tests passing. Tool validity and `done` signals describe whether a call is valid and whether the environment terminates; they are not demonstrated step-correctness labels. Likewise, masking observation tokens keeps off-policy environment text out of the action loss but does not certify that an observation is correct (paper §§3.2–3.3; Appendix A).

This is a mixed programmatic/environmental feedback contract attached to state/action interaction and the full episode, with the task scalar consumed by RL. The framework can observe tool requests, tool responses, environment termination, and task-specific final checks. It cannot, through those fields alone, determine whether intermediate reasoning is semantically sound, whether a retrieved snippet is faithful, or whether an unnecessary call was strategically justified.

The direction signal is a reusable interface and recipe across six very different agent domains, not a new static corpus or a universal verifier. Compared with a task-specific tool loop, VerlTool centralizes stateful execution and independently schedules tool-bound trajectories; compared with a trajectory dataset release, it generates episodes online during training and does not publish a paper-version six-domain replay collection. This distinction controls how the entry should be reused and audited.
