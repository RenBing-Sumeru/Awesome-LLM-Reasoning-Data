既有 agent 论文主要比较任务成功率，而 LLM serving 研究通常假设一次静态 inference request。本文的具体变化，是在同一系统分析中显式呈现动态推理的 LLM/tool 交替控制流、history 增长、branch concurrency、tail latency、KV-cache 压力和 GPU 能耗，再把这些量与 sequential/parallel test-time budget 关联起来。论文并未提出 CoT、ReAct、Reflexion、LATS、LLMCompiler、prefix caching 或相关 benchmark，其功率外推也不是新的实测数据集。对 Rollout, Search, and Test-Time Trace Data 而言，方向信号是研究隐含的审计 schema：可用轨迹必须保留 workflow 与预算参数、tool/LLM timing、model 与 serving version、hardware telemetry，以及逐请求记录到汇总指标的推导；仅有准确率并不充分。
