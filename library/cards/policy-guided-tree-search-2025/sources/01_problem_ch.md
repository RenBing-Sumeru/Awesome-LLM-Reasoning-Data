推理树方法可以提高 LLM 找到正确答案的机会，但其数据与计算契约很容易被最终结果掩盖。一个方法可能生成多个候选续写、返回早先状态、放弃某条路径，并对不同问题消耗不同预算，而最终 benchmark 记录只保留被选答案。固定树搜索启发式还会在不利用既往搜索 episode 学习的情况下决定预算投向。Policy-Guided Tree Search（PGTS）研究的是：学习式控制器能否比固定启发式更有效地在扩展、同级分支、回溯与终止之间分配树探索。

论文把该过程形式化为 Tree Search Markov Decision Process（TS-MDP）。对单个 benchmark 问题而言，环境由目标 LLM 及其潜在推理续写空间组成；可观察状态则是已经揭示的部分树，包括部分推理文本、当前节点、父子边、来自目标模型的节点 hidden-state 特征以及边上的即时奖励。控制器的动作改变树的遍历方式，而不是直接写出下一句推理。LLaMA 3.1 8B 或 70B 生成句子级或行级候选续写，另行训练的 GPS 图策略负责选择如何在已揭示树中移动。

这一分工使相关数据对象比最终 chain of thought 更丰富。可复用的 PGTS episode 应包含：问题与参考答案；每个已揭示部分状态；全部生成子节点及拓扑；当前节点；expand、branch、backtrack 或 stop 决策；动作 mask 与成本；即时及终点奖励分量；被选动作的 log-probability；value prediction；访问次数；被选、被放弃和从未访问的分支；停止原因；以及整条轨迹的 return。这些记录可用于控制器训练、测试时计算评估和搜索轨迹审计。

公开边界更窄。官方仓库提供实现及部分任务输入；其运行时树对象能够保留已生成但从未访问的子节点，也能保留访问后因回溯而放弃的路径。评估代码可以把 root tree 和策略轨迹序列化到 `.pth` 输出。然而，公开材料不包含论文运行的原始树、replay buffer、策略日志、结果 `.pth` 文件、训练后的 PGTS checkpoint 或分支状态清单。仓库 `data/` 目录是 benchmark/任务材料，不是 PGTS 轨迹发布。因此，本 Card 保持 `partial` 与 L4：论文、附录及固定版本代码足以支持细致配方说明，但不足以逐条核验或复用论文报告的搜索数据。
