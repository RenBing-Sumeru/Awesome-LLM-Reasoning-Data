Reasoning-tree methods can improve an LLM’s chance of finding a correct answer, but their data and compute contracts are easy to obscure. A method may generate several candidate continuations, revisit earlier states, abandon a path, and spend different budgets on different problems, while a final benchmark row preserves only the selected answer. Fixed tree-search heuristics also decide where that budget goes without learning from prior search episodes. Policy-Guided Tree Search (PGTS) asks whether a learned controller can allocate tree exploration among expansion, sibling branching, backtracking, and termination more efficiently than a fixed heuristic.

The paper formalizes this as a Tree Search Markov Decision Process (TS-MDP). For one benchmark problem, the environment comprises a target LLM and its latent space of possible reasoning continuations. The observable state is the revealed partial tree: partial reasoning text, the current node, parent–child edges, target-model hidden-state features at nodes, and immediate rewards on edges. The controller’s action changes the traversal rather than writing the next reasoning sentence. LLaMA 3.1 8B or 70B supplies candidate sentence- or line-level continuations; a separately trained GPS graph policy chooses how to move through the revealed tree.

This distinction makes the relevant data object richer than a final chain of thought. A reusable PGTS episode would contain the problem and reference answer; every revealed partial state; all generated children and topology; the current node; expand, branch, backtrack, or stop decisions; action masks and costs; immediate and terminal reward components; the selected action’s log-probability; value predictions; visit counts; the selected, abandoned, and never-visited branches; the stop reason; and the total trajectory return. Those records could support controller training, test-time-compute evaluation, and search-trace auditing.

The public boundary is narrower. The official repository contains the implementation and selected task inputs, and its runtime tree object can retain children that were generated but never visited as well as visited paths later abandoned by backtracking. Evaluation code can serialize a root tree and policy trajectory into `.pth` outputs. However, no paper-run raw trees, replay buffers, policy logs, result `.pth` files, trained PGTS checkpoint, or branch-status manifest is released. The repository’s `data/` directory is benchmark/task material, not a release of PGTS trajectories. The Card is therefore `partial` and L4: the paper, appendices, and pinned code support a detailed account of the recipe, but not item-level verification or reuse of the reported search data.
