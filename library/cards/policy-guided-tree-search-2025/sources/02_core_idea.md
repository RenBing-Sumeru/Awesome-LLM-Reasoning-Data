The central contribution is to learn tree navigation as a policy over an evolving reasoning graph. A two-layer GPS graph network encodes node features and parent–child structure, then supplies both policy logits and a value estimate. PPO trains this controller from random initialization on search trajectories. The target LLM remains the reasoning-step generator: PGTS learns where to continue, try a sibling, or retreat, not how to generate the reasoning text itself.

In the paper formulation, maximum depth \(D\) yields \(D+2\) constrained actions: expand the current leaf, branch to another child of the current parent, backtrack by a selected number of levels before taking another branch, or terminate. Invalid choices are masked according to depth and sibling availability. This action space gives search control an explicit state–action record rather than burying it inside a fixed MCTS selection rule.

The feedback contract is mixed. Intermediate edge rewards use the target model’s likelihood-based assessment rather than a proof of step correctness. Expand receives the new step reward minus its action cost. Branch receives the reward difference between the chosen sibling and current path minus cost. Backtrack revokes rewards attributed to the abandoned suffix, adds the newly chosen sibling reward, and subtracts its higher cost. Terminate receives the terminal-path reward minus cost; the paper allows this terminal reward to come from an outcome reward model or comparison with the ground-truth answer. Thus programmatic task checks may certify some final outcomes, while likelihood-shaped intermediate feedback remains model-based and potentially correlated with the node features.

The reported action costs are 0.1 for expand, 0.2 for branch, 0.5 for backtrack, and 0.0 for terminate. They make compute allocation part of the learning objective: two paths with the same terminal correctness can produce different returns because they used different navigation sequences. PPO stores state/action transitions with scalar rewards and trains a value function using discounted trajectory returns and generalized advantage estimates; the disclosed settings are clip range 0.2, discount 0.99, and GAE lambda 0.95.

A material implementation drift must remain visible. The paper and Algorithm 1 describe an explicit terminate action and \(D+2\) choices. At audited commit `32ce4537e904c34678cc993b6c5ad0d50c3484a4`, `pgts.py` instead maps action 0 to continue, action 1 to branch, and larger actions to depth-indexed backtracking; the public action count is `depth_limit + 1`. The run stops when the generated task state is terminal or `max_search_steps` is reached. This code behavior is not equivalent to a policy-selected terminate decision, so the Card does not silently merge the two contracts.
