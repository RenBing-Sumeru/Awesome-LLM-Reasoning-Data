**Inputs.** Each iteration draws 1,024 Numina-Math prompt/oracle-answer pairs and a current policy checkpoint. Primary experiments use Qwen2.5-Math-1.5B and Qwen2.5-Math-7B; Table 1 also includes Llama-3.2-1B-Instruct and Llama-3.2-3B-Instruct. The exact Numina revision and paper-run item manifest are unknown (Appendix C).

**Pilot generation and measurement.** The policy samples `N'` responses per prompt. The official stage-1 code uses temperature 1.0 and stores `problem`, `answer`, and all `outputs`. Math-Verify scores final answers. The accepted fraction estimates `p_i`; norms of log-likelihood gradients over accepted pilots estimate `G_i`. The released allocation code assigns zero raw weight when `p_i` or `G_i` is zero, an operational edge case that the run ledger should preserve.

**Allocation and additional generation.** Algorithm 2 normalizes the variance-motivated weights to a fixed global `N`, then Appendix C describes integer adjustment to make the sum exact. Main settings include `N'=8,N=8n` and `N'=32,N=32n`; Appendix C also reports `N'=8,N=4n` and `N'=16,N=16n`. Official stage-2 code again samples at temperature 1.0 and caps per-prompt additional counts through configuration. For GVM-GRPO, `n_i` is converted into repeated prompt copies with four rollouts per copy.

**Training consumers.** GVM-RAFT++ places dynamically sampled accepted responses into a replay buffer, takes multiple clipped importance-weighted updates, and refreshes the posterior/allocation approximately every ten M-steps; Appendix C reports nine realized update steps because the collected batch is slightly below 10,240 examples. GVM-GRPO applies the allocation before the standard group-relative update, using both positive and negative final rewards.

**Shared settings.** The paper reports prompt length 1,024, response length 3,072, context 4,096, mini-batch 256, constant learning rate `1e-6` without warmup, KL coefficient `0.001`, `alpha=0.001`, and `beta=2`. Implementation uses verl. A typical `N'=8,N=8n` GVM iteration is reported as 90 minutes on 4×H100; A6000 and H100 GPUs were used overall (Appendix C, Table 2).

**Outputs and reproducibility boundary.** A faithful run must retain source/item ID, policy checkpoint and chat template, seed, every pilot/additional response, extracted answer, Math-Verify version/output, `p_i`, gradient layer and reduction, `G_i`, integer `n_i`, accepted/rejected status, replay/group membership, optimizer step, token count, and compute. The repository exposes scripts and local intermediate schemas, but multiple Numina paths appear in code and no immutable manifest binds the released defaults to every reported table or figure.
