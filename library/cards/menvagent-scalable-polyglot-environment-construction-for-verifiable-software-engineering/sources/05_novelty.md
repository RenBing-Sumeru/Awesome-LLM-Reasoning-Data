SWE-bench-style environments are often manually authored or inferred through fixed rules from Python configuration files. Later work may ask an LLM to generate an installation script once, but lacks structured failure diagnosis and rarely reuses environments across tasks. MEnvAgent introduces a Planning–Execution–Verification loop and treats successful environments as inheritable assets: new tasks are incrementally repaired from repository-level images rather than rebuilt from scratch. The novelty lies in environment-data production and failure recovery, not in a new patch-generation model, and the release packages setup scripts together with instance-level testing contracts.
