The baseline is isolated code generation or contest-style evaluation, where a task often contains a short prompt and unit tests but little real project context. DevEval changes the evaluation object to repository-local generation with file positions, reference dependencies, original code, and project tests.

The direction signal is the move from synthetic or standalone snippets toward repository execution surfaces for coding agents. The quality signal is manual annotation plus released prompts, metadata, dependency data, and evaluation scripts. What is not new: Pass@k, unit-test execution, and code-completion prompting are existing mechanisms. Before reuse, inspect license terms, source-repository redistribution rights, test adequacy, failing ground-truth samples, dependency drift, and the artifact-count discrepancy between paper and release.
