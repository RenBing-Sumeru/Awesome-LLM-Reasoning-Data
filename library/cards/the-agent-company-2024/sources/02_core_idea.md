The one-sentence contribution is: TheAgentCompany packages an imagined software company as a versioned, multi-service agent environment in which manually authored workplace tasks are evaluated by weighted checkpoints, then releases model-specific results, screenshots, and full evaluation trajectories.

The core mechanism has three coupled objects. First, each task specifies an agent-visible intent plus hidden evaluation and environment setup. Second, the episode exposes browser/UI, terminal, code/workspace, file, and RocketChat observations while recording the agent's actions and transitions. Third, a mixed feedback contract maps the resulting state or trajectory to weighted checkpoint outcomes. Most evaluators are deterministic Python checks over final/intermediate state or trajectory; 51 of 175 tasks (29%) use an LLM judge for complex or unstructured deliverables, with rubrics or reference outputs. Full success requires every checkpoint to pass, while weighted checkpoint completion supplies a partial score and the benchmark also reports a binary full-completion indicator.

The feedback can observe evaluator-visible environment state, selected trajectory events, and outputs captured by task-specific predicates. It cannot certify untested semantic quality, intent compliance beyond those predicates, or the stability and calibration of the LLM judge. Runtime evaluator encryption discourages direct peeking, but published evaluator sources and public task prompts still permit benchmark-specific optimization and future contamination. State/action-level supervision in the metadata therefore means checkpoint-sensitive process evidence; it does not mean the release provides a calibrated reward after every reasoning step.

Relative to static completion benchmarks, the important change is that success depends on coordinated state changes across several services and, for some tasks, interaction with simulated colleagues. Relative to adjacent environment benchmarks such as `tau2-bench-2025` and `osworld-mcp-2025`, this Card's distinguishing evidence is the self-hosted company substrate, manually implemented weighted checkpoints, and official run directories retaining complete model/harness-specific episodes. Those related works remain useful comparison points, but the present evidence does not establish that TheAgentCompany's judge is more accurate or its tasks more representative.

The direction signal for reasoning-data research is the explicit linkage `task prompt -> environment state -> action history -> checkpoint feedback -> terminal outcome`. That linkage supports episode replay and verifier audit. It does not by itself justify SFT, preference learning, reward-model training, process supervision, or agent RL from the released logs; the paper-supported use is evaluation only.
