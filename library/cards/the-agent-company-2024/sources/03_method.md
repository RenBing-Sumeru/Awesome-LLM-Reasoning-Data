**Inputs and task construction.** The authors start from O*NET 29.1 job-task lists and U.S. labor statistics for occupational coverage, then combine those sources with coauthor domain experience and LLM brainstorming. The brainstorming model, prompts, sampling parameters, rejection rate, and random seeds are not disclosed. 20 CS students, software engineers, and project managers worked for two months, totaling about 3,000 person-hours; some tasks required more than ten hours. Each accepted task is manually implemented as an intent, weighted checkpoints, evaluator, initialization/finalization logic, dependencies, and a container image. Quality control includes screenshot evidence, evaluator tests, lead-author code review, final manual double-checking, and independent checkpoint-importance review, but per-task review logs are not released.

**Environment and rollout.** A run resets the task's Dockerized Linux workspace and self-hosted GitLab, ownCloud, Plane, and RocketChat services. The agent receives only the English task instruction from `task.md`, then uses browser, terminal, code/files, and communication actions. 41 tasks include simulated colleagues represented with Sotopia profiles; the paper baselines use Claude-3-5-Sonnet-20241022 for those NPCs. Main experiments use OpenHands CodeAct + Browsing, with versions 0.14.2 and 0.28.1 appearing across paper versions; an OWL RolePlay comparison is also reported. The archival paper evaluates twelve model backbones. A standard repeated-seed protocol, decoding temperature, and one uniform step/token budget across configurations are unknown.

**Verification and output.** Task-specific Python evaluators inspect final/intermediate environment state or selected trajectory information. For 51 tasks, LLM-based evaluation handles complex or unstructured outputs, using Claude-3-5-Sonnet-20241022 in the paper experiments; authors report review/testing by 3–5 contributors and CI, but release no independent calibration corpus. Evaluators produce checkpoint outcomes and weighted points. Full completion requires all checkpoints; partial score aggregates checkpoint credit and adds the documented full-completion bonus. Agent exit or budget exhaustion terminates the episode without implying success.

**Release path.** Each official experiment run occupies a named subdirectory of `evaluation/1.0.0/`. The inspected 2024-12-17 OpenHands 0.14.2 + Claude-3.5-Sonnet run contains a run README, per-task result JSON, per-step screenshots, and compressed trajectory JSON for successful, partial, and zero-score tasks. Leaderboard submission instructions require results, trajectories, screenshots, and a README, but completeness of every historical third-party run has not been verified. There is no reported quality filter selecting trajectories for training.

**Use and reproducibility boundary.** The pipeline output is a benchmark evaluation episode plus checkpoint and terminal feedback, not a training example selected by a teacher. Supported use is evaluation only. Reproduction should pin benchmark release 1.0.0, paper version, main-code commit, experiment run path/commit, task images, service backups, OpenHands version, model endpoints, NPC model, and judge model. Immutable image digests and full run manifests are not provided in the accepted evidence. No train/validation/test split or decontamination protocol is disclosed.
