The prior baseline for many agent evaluations is a prompt paired with a narrow tool surface and a terminal pass/fail check. TheAgentCompany changes the evaluation object into a long-horizon workplace episode spanning several self-hosted services, a local code/file/terminal workspace, and model-mediated colleagues. Its record joins an agent-visible intent, hidden weighted checkpoints, task-specific evaluators, state/action history, screenshots, partial checkpoint outcomes, and terminal full completion.

The important data contribution is not merely the 175-task count. It is the release boundary: benchmark release 1.0.0 provides task and environment implementations, while the official experiments repository stores model/harness-specific result JSON, screenshots, and compressed trajectories under versioned run paths. The inspected baseline retains successful, partial, and zero-score episodes, enabling analysis of both completion and failure rather than exposing only leaderboard aggregates. This is why `data_release` is justified even though the records are evaluation logs rather than a training dataset.

The feedback contribution is the use of weighted checkpoints over heterogeneous workplace state. Deterministic Python checks are combined with LLM judging for outputs that are difficult to reduce to exact predicates. This makes the verifier/environment interface visible enough to study state-sensitive credit and terminal success. It also exposes a key research problem: judge behavior, evaluator shortcuts, NPC behavior, and service state can all become part of the measured outcome.

The work does not individually introduce Docker sandboxes, browser/terminal agents, self-hosted collaboration software, checkpoint scoring, LLM-as-judge, role-play agents, or trajectory logging. Much of the contribution is careful benchmark construction and systems integration across those components. The task source also mixes established occupational lists, domain experience, and undisclosed LLM brainstorming rather than presenting a fully reproducible task-generation algorithm.

For reasoning-data research, the directional novelty is that prompts, environment transitions, actions, checkpoint feedback, and terminal results are available as one auditable episode object. Reuse checks remain essential: pin paper and run versions, establish experiment-log rights, audit evaluator and judge calibration, reconstruct task-level source lineage, measure contamination, verify failure retention, and review privacy/consent. Performance scale or venue acceptance is not a data-quality signal.
