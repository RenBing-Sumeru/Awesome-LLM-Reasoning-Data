- **No reusable release.** No official `D_seed`, `D_START`, accepted or rejected trajectory, codebase, START-0 or START checkpoint, Python environment, generation log, dataset card, model card, project page, or immutable release was verified. The work is an open paper describing a recipe, not an open data or environment artifact.
- **Scale units are ambiguous.** `D_seed=10K` and `D_START=40K` are reported as sample counts, but the paper does not separate unique prompts from multiple trajectories. Unique counts, candidate counts, acceptance yields, source allocations, duplicates, and hashes are unknown.
- **Printed totals conflict.** Table 9's six source components sum to 46,969 rather than its reported 49,969, a 3,000-item discrepancy. The printed math sources sum to 36,895, while Section 3.1 reports 40K math problems and Section 2.2 calls `D_START` 40K math reasoning samples. The stated 74% math and 26% code split also cannot be reconstructed from the printed components.
- **The verifier is not auditable.** Final-answer extraction, mathematical equivalence, coding tests, parsing failures, partial-credit behavior, and checker versions are unknown. Curator inference: false accepts could admit wrong trajectories, while false rejects could remove useful corrections; aggregate benchmark gains do not measure either error rate.
- **The environment is not replayable.** Python package versions, sandboxing, filesystem and network access, timeout, resource limits, state reset, exception serialization, and deterministic execution are not disclosed. Curator inference: environment drift or unsafe generated code can change both selection and model behavior.
- **Sampling and modification are incomplete.** The paper says each hint is checked through multiple sampling iterations but gives no rollout count, aggregation rule, seed, hint mixture, or retained paraphrase manifest. Figure 1 includes `score -> filter -> modify`, yet no general modification algorithm or edit provenance is defined.
- **Decoding statements conflict.** Section 3.4 specifies top-p 0.95 and temperature 0.6; Appendix H specifies greedy decoding. The paper does not map these settings to data generation and each evaluation, so the actual `D_seed` and `D_START` sampling protocol remains unknown.
- **Failure data are dropped.** The paper reports 10.4% correct-to-wrong and 67.0% wrong-to-wrong outcomes, plus repetition and incorrect-execution filtering, but releases no underlying failures, denominators, rejection reasons, or filter outputs. This prevents selection-bias analysis and reuse of informative negative trajectories.
- **Hinting can harm behavior.** The measured 10.4% correct-to-wrong rate means intervention can damage a correct solution. Repeated hints can plateau or reduce accuracy on GPQA and MATH500, and hard LiveCodeBench tasks improve by only two points. More hint interventions are not uniformly better.
- **Tool triggering is not tool quality.** A 100% Python trigger rate measures whether the model emits a tool call, not whether that call is necessary, safe, efficient, or semantically helpful. Curator inference: optimizing this proxy can reward gratuitous computation or exploit execution quirks.
- **Decontamination is not reproducible.** The authors cite the Qwen2.5-Math method, but no local normalization, threshold, removed count, benchmark coverage, or overlap ledger is published. Chronological LiveCodeBench separation does not address semantic overlap, upstream model pretraining, or the math and science benchmarks.
- **Licensing is unresolved.** The ACL paper is covered by CC BY 4.0, but that license does not cover the unreleased prompts, generated trajectories, environment, or checkpoints. The paper names no source-specific or generated-data license or derivative-use terms, despite the checklist pointing to source links as licensing documentation.
- **Safety analysis is absent.** Responsible NLP Checklist item A2 marks potential-risk discussion as absent. The paper does not assess execution of untrusted generated code, unsafe libraries, environment escape, filesystem or network misuse, or propagation of tool errors.
- **Statistical evidence is limited.** No confidence intervals, independent training reruns, seed-level variance, or checkpoint-selection policy is reported. Averaging multiple benchmark samples is not a substitute for training-run uncertainty.
- **Benchmark performance cannot certify the data.** Reported gains combine intervention, sampling, selection, trajectory format, full-parameter SFT, and evaluation budget. They do not establish record-level correctness, trace faithfulness, rights, provenance, contamination control, privacy or consent, or reproducibility.
- **Human work is underspecified.** The checklist describes simple annotation by the authors, but the paper does not identify which records were manually authored or modified, the instructions, workload, adjudication, or quality checks.
