The contribution in one sentence is: use function-specific hints to make a long-reasoning model expose Python-assisted corrective trajectories, retain trajectories that turn wrong answers into successful ones, and train the resulting intermediate model to generate a larger self-training set.

START separates inference-time intervention from training-time data construction:

- **Hint-infer** intercepts a reasoning completion at its termination point or last `wait`, appends a Python-oriented hint, and lets the model continue with code execution and refinement. This intervention can be repeated after another completion, making hint count a test-time-compute variable.
- **Hint-RFT** expands the intervention beyond one generic phrase. The authors define six functions—complex calculation, self-reflection, logic check, alternative method, general tool use, and deeper thinking—and use Qwen-2.5-72B to produce alternative expressions. For curation, hints can be inserted after `Wait`, after `Alternatively`, or at the end of reasoning.
- **Self-training expansion** uses accepted trajectories to fine-tune QwQ-32B-Preview into START-0; START-0 then generates the larger `D_START` used to fine-tune the final model.

The feedback contract is mixed environmental and programmatic selection. Python stdout, exceptions, and example or test mismatches are environment observations. Final-answer correctness before and after insertion supplies the main selection signal, while execution and repetition checks supply additional filters. No RL reward is optimized. The feedback can observe whether code ran under the authors' setup and whether an undisclosed checker considered the final answer successful. It cannot establish that intermediate reasoning is faithful, that a tool call was necessary or safe, or that a verifier-passing answer is semantically correct under edge cases.

This data object is a full tool-interaction trajectory used as answer- and episode-level SFT supervision, not process supervision. The paper illustrates code, outputs, self-checks, revisions, and final answers, but it supplies no step-level correctness labels, process rewards, or released state serialization.

The closest Atlas comparisons are `v-star-training-verifiers-self-taught-reasoners-2024` for self-training through selected model generations, `opencodereasoning-advancing-data-distillation-for-competitive-coding-2025` for constructing code-reasoning supervision, and `tool-zero-2025` for tool-augmented training. START's distinctive unit is the hint-induced **corrective transition**—wrong before intervention and successful after it—combined with executable Python observations and a second self-generation round. This is a mechanism comparison, not a claim that the unreleased START data are more reusable than those artifacts.

The direction signal for reasoning-data research is that a textual intervention can serve as a data-acquisition operator: it changes model behavior, exposes an interaction trace, and creates a before/after selection event. The audit signal is equally important: without the checker, environment, rejected candidates, and record lineage, the apparent feedback contract cannot be independently replayed.
