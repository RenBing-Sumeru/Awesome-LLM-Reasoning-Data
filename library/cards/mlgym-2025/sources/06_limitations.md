The largest evaluation risk is unlimited visible test feedback. Appendix B explicitly allows repeated `validate` calls so the agent can improve on the test set, and Best Attempt selects the best valid intermediate score. This is online optimization against the scoring surface, not a once-only held-out test. Read-only evaluator files remain inspectable, enabling targeted optimization of implementation details or blind spots.

Feedback semantics are easy to misstate. `MLGymEnv.step` currently returns reward 0 on every transition, while task metrics are stored in `info.score`. An RL system that consumes the native reward without an adapter would receive no task signal. Heterogeneous metrics and AUP additionally depend on direction conversion, infeasible-run treatment, task mixture, and best-of-4 selection.

Validity and quality are different. A valid run requires at least 1 evaluator score; it need not beat the baseline, generalize, or discover anything scientifically new. Failed and incomplete runs are retained, which is valuable for audit, but post-paper additions, corrections, deletions, and error-to-file mappings lack a stable release ledger. The exact mapping from the final paper's 624 runs to the current 676 file pairs is unavailable.

Replay is partial. `run_replay.py` can reissue recorded assistant actions, but current documentation uses `aigym/mlgym-agent:latest`; the repository has 0 tags, 0 GitHub releases, and a changelog containing only a heading. No paper-run OCI digest, complete data/task/evaluator/dependency/GPU manifest, checksum set, or end-to-end deterministic replay result is published. Mutable upstream datasets and hardware behavior can change scores even when actions are identical.

There is no benchmark-wide clean task split or decontamination audit. Constituent datasets use task-specific splits, yet repeated test-score exposure defeats a clean final holdout. Public tasks, baselines, evaluator code, and trajectories also create future model-training and benchmark-leakage surfaces; pretraining exposure and instance-level overlap are undisclosed.

Licensing is mixed. The README assigns most code CC BY-NC 4.0, SWE-Agent and Modded-NanoGPT portions MIT, and Gymnax/Gymnax-blines portions Apache-2.0. These notices do not provide one license for every upstream dataset, generated trajectory, submission, model output, or dependency; blanket commercial reuse is unsupported. No benchmark-wide PII, consent, deletion, or takedown audit is reported.

Security controls are incomplete. Agents run broad shell and training commands in a non-root container, with evaluator/data protected by normal read-only permissions, but paper-run policies for network access, package installation, secrets, malicious upstream artifacts, container capabilities, and GPU isolation are not fully specified.
