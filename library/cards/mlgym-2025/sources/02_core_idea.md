MLGym's core idea is to turn heterogeneous ML experimentation into a common container-and-command interface while leaving task-specific scoring to programmatic evaluators. An agent receives task and dataset instructions, optional starter artifacts, prior message history, and tool documentation; at each step it emits one shell or tool command and observes the textual result plus workspace state.

The action space includes non-interactive Bash; open, scroll, search, find, create, edit, and insert operations; `validate`; and terminal `submit`. Optional modules add literature search/PDF parsing and memory operations, but they are not all part of the reported paper comparison. A task-specific Python evaluator reads the flexible artifact and emits metrics such as accuracy, validation loss, R2, BLEU, game or RL return, or wall-clock time. No learned judge is used.

The decisive feedback contract is unusual for a benchmark. `validate` calls the scoring surface, returns the current test-set score, and does not terminate, so an agent may adapt repeatedly to visible test feedback. `submit` invokes scoring and terminates. Step or USD budget exhaustion can trigger autosubmission of the latest codebase when possible. A run is valid if at least one evaluator score exists; validity does not mean it beats the baseline or constitutes scientific novelty.

The public environment's native Gym transition reward is always 0. Task metrics are appended to `info.score`, and cross-task comparisons later transform metric direction into performance profiles and area under the profile (AUP). Treating `info.score` as an RL reward would require an explicit adapter and objective that the paper does not implement. The demonstrated supervision is evaluator feedback attached to steps and full episodes for evaluation and audit.

Relative to benchmark suites that expose only prompts and final scores, MLGym releases task configuration, execution traces, intermediate validation history, flexible submissions, failure states, and replay code in one environment abstraction. Relative to MLE-Bench, MLAgentBench, RE-Bench, ScienceAgentBench, and SWE-Agent, its claimed scope is 13 Level-1 research tasks under a uniform command loop. It does not demonstrate autonomous scientific discovery or policy training.
