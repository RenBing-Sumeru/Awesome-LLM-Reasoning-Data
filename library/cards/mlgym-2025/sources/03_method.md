Inputs are 13 author-curated tasks and their public datasets or environments. Task YAML binds task and dataset descriptions, dataset configuration, task entry point, starter/submission instructions, baseline paths and scores, evaluator paths and a read-only flag, dependencies, training-command timeout, and optional memory path. No task-candidate pool or rejection ledger is released.

At reset, MLGym launches a Docker or Podman environment with a non-root `/home/agent/workspace`, installs or exposes task dependencies, datasets, starter code, evaluator, GPU allocation, and the SWE-Agent-derived Agent-Computer Interface. The paper-run image digest manifest is unavailable; current documentation defaults to `aigym/mlgym-agent:latest`.

The scaffold composes the task/dataset prompt and ACI documentation, then runs a single-command ReAct loop. Each model generates discussion/thought and a parsed shell/tool action. The environment executes it and returns command output, current step/remaining-step counters, open-file and working-directory state, and—after `validate`—the evaluator score. The trajectory records action, observation, response, state, thought, and execution time together with role-tagged history and run-level `info`.

Paper experiments evaluate 12 models with 4 seeds for every task. Configurable models use temperature 0.0 and top-p 0.95; o1-preview and o3-mini use their API default temperature 1.0. Each run stops after 50 environment interactions or USD 4 API cost, whichever arrives first, with additional task-specific training timeouts. The paper reports Best Attempt over valid intermediate `validate` calls, Best Submission over final submissions across the 4 runs, and cross-task performance profile/AUP.

Task-specific Python evaluators score submissions. `validate` exposes the same test-set surface without terminating; `submit` scores and ends the episode. Exit paths also include budget autosubmission, skip/forfeit, format, runtime, cost, context, permission, and environment errors. The repository retains both valid and invalid current-grid runs rather than filtering to successes.

Outputs are task artifacts, `.traj` episodes, paired `results.json`, intermediate score histories, final metric dictionaries, exit status, and aggregate results. `run_replay.py` extracts recorded assistant message contents as actions, writes replay JSONL, and invokes the runner with `model_name=replay`. Deterministic replay still requires pinned task/data/evaluator/dependency versions, immutable image digests, hardware/runtime details, seeds, and environment reset state.
