For the `frontier_reports_data_disclosure_ledger` track, GLM-V is a strong example of why openness must be recorded by artifact class. A ledger should have separate rows for report disclosure, GLM-4.1V-9B-Base weights, GLM-4.1V-9B-Thinking weights, GLM-4.5V weights, inference/preprocessing code, reward-system code, reward-model weights, training infrastructure, and every data stage. Only the first six are confirmed in some public form; the training records and full optimizer stack are not.

A reproducible data ledger should assign stable IDs to each multimodal asset, prompt, response, generator/checkpoint, source/license record, deduplication cluster, offline difficulty label, human label, rollout group, boxed extraction, rule-verifier result, LLM-judge request/response, style reward, curriculum weight, selection decision, policy version, and final update. Store rejected as well as accepted records, with hashes and reason codes.

The report also offers practical design hypotheses to test independently: use source-specific filtering instead of one generic quality score; teach parseable answer formats before RL; separate semantic equivalence from exact OCR matching; unit-test each domain verifier; monitor cross-domain metrics for reward collapse; update difficulty online; and oversample before selecting informative mixed-outcome rollout groups. None should be treated as universally valid without ablations and failure logs.

For model reuse, pin each Hugging Face revision and repository commit, preserve the correct conversation template for GLM-4.1V versus GLM-4.5V, audit the MIT weight and Apache-2.0 code terms independently, and reproduce benchmark prompts and inference settings before comparing scores. Model cards are deployment evidence, not training-corpus documentation.

For future disclosure, publish final per-domain counts and mixture weights; source and rights manifests; SFT and RL record schemas; difficulty-label distributions; rollout and selection totals; reward-model/checker versions; verifier tests and error rates; RL hyperparameters and compute; contamination signatures and removals; and a record-level lineage connecting each released checkpoint to its data and feedback revisions.
