The method can be reconstructed only as a layered disclosure:

1. **Base and task sources.** Start from an unspecified GPT-5 checkpoint and specialize it for agentic coding. Training tasks cover building projects, adding features and tests, debugging, large refactors, and code review in varied real-world environments. Repository IDs, revisions, prompt sources, task counts, rights, filters, and mixture weights are unknown.
2. **Agent interaction.** The model navigates codebases, reasons over dependencies, edits files, runs commands and tests, and can produce project code, diffs, review comments, screenshots, citations, terminal logs, and test results. The report does not say which fields are retained in training trajectories, whether non-user-visible reasoning is stored, or how successful and failed episodes are selected.
3. **RL feedback.** Reinforcement learning is explicit. Desired outcomes are human-like code and PR preferences, precise instruction following, code-review quality, and iterative test passing. The representation could involve human preferences, learned graders, executable tests, policy labels, or mixed rewards, but the report does not choose among them or give weights, calibration, reward scale, terminal predicates, or RL algorithm.
4. **Safety data.** Reuse pre-existing safety data from the OpenAI hosted chat product and a codex-1 malware pipeline that generates prompts, code snippets, and environment configurations, including edge and adversarial cases; train refusal of high-risk requests and calibrated defensive or dual-use help (PDF §2.1.2, pp.3–4). Separately create new Instruction Hierarchy data for coding prompt injection and train the model to ignore attacks (§2.2.2, p.4). Counts, generators, labels, filters, overlap, and stage weights are undisclosed.
5. **Evaluation.** Code-review evaluation pairs recent popular open-source commits with model comments and experienced-engineer correctness and importance judgments. SWE-bench Verified, refactor repositories, mobile-web preferences, malware golden-set cases, prompt-injection attacks, Production Benchmarks, StrongReject, CTF, and Cyber Range supply other evaluation predicates. 6. **Deployment.** Codex CLI, IDE, cloud, and GitHub supply tool scaffolds and product controls. Cloud uses an isolated container with network disabled by default; local macOS uses Seatbelt and Linux uses seccomp plus landlock; users can approve broader access and configure project network policies (PDF §4, pp.6–7). These are deployment settings, not evidence of training substrate.

The general episode terminal predicate, rollout count, temperature, horizon, retries, optimizer, objective mix, compute, checkpoint selection, and stage allocation are unknown. A report that some test runs exceeded seven hours is evaluation or product observation, not a training horizon. CLI conversation compaction is also a product scaffold and must not be converted into compaction training evidence.

Reproduction would require task and repository manifests, pinned environments, action and observation schemas, review and preference records, successful and failed trajectories, test and grader versions, reward aggregation, global splits, decontamination, source rights, and item-to-checkpoint lineage. No such training package is released.
