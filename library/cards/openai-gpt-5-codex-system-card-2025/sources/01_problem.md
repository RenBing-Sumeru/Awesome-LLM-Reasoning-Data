OpenAI published the seven-page *Addendum to GPT-5 system card: GPT-5-Codex* on September 15, 2025. It describes GPT-5-Codex as a GPT-5 version optimized for agentic coding and explicitly states reinforcement learning on real-world coding tasks across varied environments (PDF p.1). The associated launch page expands the task taxonomy to building projects from scratch, adding features and tests, debugging, large-scale refactoring, and code review.

The concrete Atlas problem is not whether GPT-5-Codex can edit code, but what post-training records and feedback could produce those behaviors. A plausible disclosed episode contains a software-engineering prompt, repository or project context, environment state, commands or tool actions, file edits and diffs, test executions, and a terminal artifact or review comment. OpenAI names desired outcomes—human-like code and pull-request preferences, precise instruction following, code review, and iteratively running tests until passing—but does not disclose whether they are scalar rewards, preference pairs, executable predicates, judge outputs, or a mixed objective.

Safety training adds two other data families. The report inherits a codex-1 malware policy and synthetic pipeline producing prompts, code snippets, and environment configurations, then says new Instruction Hierarchy data were created for coding-environment prompt injection (PDF §§2.1.2–2.2.2, pp.3–4). Neither family is released with item schemas, counts, labels, generators, splits, or licenses.

This belongs in `frontier_reports_data_disclosure_ledger` because it exposes task-family and behavior-level deltas while leaving the record ledger closed. It does not release an SWE dataset, agent trajectories, reward code, model weights, or replay environments. The current Deployment Safety Hub marks the model as no longer in production; that lifecycle status does not change the 2025 source identity but prevents product claims from being treated as current-model guarantees.
