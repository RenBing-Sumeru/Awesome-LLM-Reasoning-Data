- The real-world SWE ledger is task-family only. Repository identities and revisions, prompts, environment images, tool schemas, task counts, mixture weights, source rights, action trajectories, non-user-visible reasoning, successful and failed attempts, filters, and retention rules are unavailable.
- “PR preferences” and human-like coding style name target behavior but do not establish pairwise records, annotator instructions, a preference model, scalar reward, optimization stage, weighting, or calibration. The main coding-agent feedback contract remains incomplete.
- Iteratively running tests until passing is observed and desired behavior, not evidence that executable tests are the training reward. Tests can also miss semantic regressions, security flaws, and specification violations; a model can overfit a harness or make narrow changes that pass visible checks. These are curator-inferred reward-hacking risks.
- Code-review evaluation has judgment risk. Experienced engineers score correctness and importance, but the repository and commit sample, rubric, labels per comment, inter-rater agreement, aggregation, false-positive and false-negative rates, and raw judgments are undisclosed. Recent public commits also create unresolved train/evaluation overlap.
- The malware pipeline is inherited from codex-1 rather than a newly disclosed GPT-5-Codex construction. Generator versions, prompts, counts, labels, filters, golden-set independence, and failed examples are unknown. Its Table 3 result cannot attribute broader coding performance to this safety data.
- New prompt-injection training data and the coding-focused evaluation lack a membership boundary, so robustness to unseen attacks cannot be distinguished from overlap. A 0.98 evaluation score also leaves unreported attack counts, uncertainty, severity mix, and failure examples.
- SWE-bench coverage of all 500 tasks fixes an infrastructure gap, not benchmark decontamination. Refactor repositories and recent code-review commits lack cutoff dates, hashes, duplicate checks, solution-overlap analysis, or a global train/development/test manifest.
- Employee-traffic token deciles, seven-hour tests, mobile-web preferences, safety benchmarks, CTFs, and Cyber Range are evaluation or observational surfaces. They conflate model, scaffold, task mix, budget, environment, and judge and cannot isolate the effect of training data.
- Sandbox, network policy, approvals, screenshots, citations, terminal logs, and test reports are deployment controls or evidence surfaces. They cannot be used to infer the training container, reward, task correctness, or current product behavior after the model was retired from production.
- The later Codex-family conflicting-edit user model, edit-preservation reward, native compaction training, internal PR hidden tests, and expanded Preparedness environments are not in this report. Backporting them would create false lineage.
- No task corpus, preference or review records, safety data, model weights, reward implementation, evaluator code, replay environment, source-license ledger, decontamination report, or item-level checkpoint lineage is released. Reuse is therefore blocked beyond reading and audit reference.
