The prior baseline is the May 2025 o3/o4-mini Codex addendum. It already disclosed RL on real-world coding tasks, human-style and PR-preference goals, a synthetic malware pipeline, coding prompt-injection data, and a concrete unexpected-state safety reward that penalized action-inconsistent completion claims. GPT-5-Codex changes the base family and improves disclosure of task specialization: full-project construction, features and tests, debugging, large refactors, and code review.

The most concrete new surface is code review. The report says the model is trained specifically to find critical flaws, compares PR intent with the diff, reasons over the codebase and dependencies, and runs code and tests. Its evaluation uses recent open-source commits and experienced engineers judging correctness and importance. This yields a human-judged `(commit context, review comment, correctness/importance judgment)` object, but the records, rubric, and training relationship remain unavailable.

Relative to base GPT-5, the delta is agentic coding specialization rather than a new broad-source claim: GPT-5's internet, partnership, and user or trainer source classes do not identify Codex tasks. Relative to GPT-5.1-Codex-Max and GPT-5.2-Codex, this earlier report is less specific about reward and environment interventions. It does not disclose a user model making conflicting edits, positive reinforcement for preserving those edits, native compaction training, or an internal PR benchmark graded by hidden unit tests.

RL, test execution, code review, human preferences, synthetic safety data, sandboxes, and long-running agents are not individually new. The novelty for the Atlas is disclosure granularity: task families and review evaluation become visible while the reward representation remains hidden. That gap makes the report useful for preventing a common inference error—turning observed test-passing behavior or evaluation graders into an unsupported training-verifier claim.

Before reuse, inspect task and repository manifests, revision pins, PR-intent and review-label schemas, preference representation, reward aggregation, test-to-reward mapping, failed trajectories, code-review false positives and negatives, global split, commit and benchmark overlap, licenses, and checkpoint lineage. Without them, this is a disclosure reference rather than an open construction recipe.
