A frontier model report can expose substantial training detail while still withholding the reusable objects needed for independent audit. Hunyuan-TurboS therefore needs four separate ledgers: disclosed training records and stage counts; documented construction, feedback, and optimization procedures; publicly accessible model or service artifacts; and benchmark results. Evidence in one ledger does not complete another.

The official report describes a 56B-active, 560B-total hybrid Transformer-Mamba2-MoE model with 256K context. Its data-facing claims include 16T base pre-training tokens, 3M supervised fine-tuning samples, adaptive long-short reasoning traces, multi-model deliberation, human preference annotations for a Generative Reward Model, executable code with unit tests, and two GRPO stages. The audit question is not whether these stages are named, but whether a record can be connected to its source, generator, filtering decision, reward, training stage, and final checkpoint.

The checked official artifacts do not close that chain. Tencent publishes the arXiv report and an official GitHub repository containing the report, README, and figures. An official Hugging Face Space provides a hosted API demo. The GitHub repository does not contain the construction or training code, and the Space is not a downloadable weight repository. No official training dataset or Hunyuan-TurboS weight files were located on these surfaces. Benchmark scores consequently remain model-behavior evidence, not evidence that the training records, rights, or verifier decisions are reproducible.
