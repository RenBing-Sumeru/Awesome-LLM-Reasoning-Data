一份前沿模型报告可以披露大量训练细节，却仍不公开独立审计所需的可复用对象。因此，阅读 Hunyuan-TurboS 时必须分开维护四本账：已披露的训练记录类型与阶段数量、已有文档的构造和反馈及优化流程、公众可访问的模型或服务工件，以及基准结果。任何一本账中的证据都不能替另一账补全缺口。

官方报告描述了一个激活参数 56B、总参数 560B、上下文长度 256K 的 Transformer-Mamba2-MoE 混合模型。与数据有关的披露包括 16T 基础预训练 token、300 万条监督微调样本、自适应长短推理轨迹、多模型 deliberation、用于 Generative Reward Model 的人工偏好标注、带单元测试的可执行代码，以及两个 GRPO 阶段。审计重点不是这些阶段是否被命名，而是能否把一条记录连接到其来源、生成器、筛选决定、奖励、训练阶段和最终 checkpoint。

已核验的官方工件没有补全这条链路。腾讯公开了 arXiv 报告，以及只包含报告、README 和图片的官方 GitHub 仓库；官方 Hugging Face Space 提供托管 API 演示。GitHub 仓库没有构造或训练代码，Space 也不是可下载权重仓库。在这些官方页面上没有找到训练数据集或 Hunyuan-TurboS 权重文件。因此，基准分数只能作为模型行为证据，不能证明训练记录、权利链或 verifier 决定可复现。
