来源账本不完整。报告描述了宽泛的预训练与 SFT 来源类别，却没有给出大多数材料的来源名称、采集日期、比例、记录标识、采购条款或机器可读的权利矩阵。URL 级与语义去重不能证明基准去污染，而且没有公开匹配或删除账本。

数量账本包含彼此不同且可能重叠的对象。16T 基础预训练 token、300B annealing token、30B 与 20B 上下文扩展 token、300 万条 SFT、约 20 万条偏好标签、超过 80 万条可执行代码、30 万条推理 RL 记录和 16 万条通用 RL 指令不能相加。它们的交集、唯一记录总数、混合权重、重复次数和 checkpoint 归属均为 unknown。

adaptive teacher 路径无法重放。精确的 Hunyuan-Base 与 Hunyuan-T1 checkpoint、生成指令、候选数、温度、停止上限、正确性 verifier、压缩转换和被保留的失败尝试历史均不可获得。最终答案正确并不能证明每个中间步骤有效。

deliberation 与偏好契约只得到部分说明。judge 据称基于 Hunyuan-TurboS 并由专家校准，但版本、维度提示、共识权重、校准样例、分歧率、迭代次数和弱点画像记录没有发布。约 20 万条偏好标签的一致率超过 93% 是有用信息，却不能替代标注规范、采样框、裁决过程与类别分布。

奖励系统覆盖广但不透明。GRM、GRM-CoT、Answer Consistency Model、critic、分类器和超过 30 个评分服务的 checkpoint、训练数据、提示、阈值、权重、分数分布、校准、误接受率和逐记录奖励向量都不可获得。参考答案错误、位置偏差、judge 偏差、分数融合与 reward hacking 仍是实质风险。

沙箱无法根据报告复现。报告披露了 36 种语言、分布式 CPU 执行、超过 1,000 个并发任务以及文件和网络隔离，却没有公开容器镜像、编译器、软件包、版本、资源限制、超时、单元测试来源、随机种子、日志和失败分类。超过 80 万条代码样本本身也没有发布。

RL 运行无法重放。报告说明了阶段数量、混合比例、温度 1.0、K3 裁剪、仅用于正 advantage 的 Best-of-N loss、动态过滤、删除零 advantage 样本和 group adjustment，但没有完整提示池、rollout group、采样输出、奖励、advantage、策略与参考模型版本、优化器状态、学习率、group size 或精确调度。

发布面很窄。官方 GitHub 仓库提供报告和图片，而非训练代码；官方 Hugging Face Space 是托管 API 演示，而非开放权重。在已核验官方页面上，没有找到官方数据文件、奖励 checkpoint、沙箱包、Angel-RL 实现或 Hunyuan-TurboS 权重分片。

最后，报告中的基准与 token 效率结果属于模型证据，不能证明数据质量、来源完整性、权利合规、过程正确性、无污染、安全覆盖或 verifier 可靠性。
