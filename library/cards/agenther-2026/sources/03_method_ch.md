输入来自 WebArena WA-TRAIN 与 ToolBench 官方 training split。论文报告把 WebArena 按类别、seed 0 划为 612 个 WA-TRAIN task 与 200 个 WA-HELDOUT task，并用 gpt-3.5-turbo-0125 收集 3,000 条失败加 500 条成功 WebArena trajectory，以及 5,000 条失败加 2,000 条成功 ToolBench trajectory。这些数字描述的是实验；完整 source corpus 与论文所称发布的 WebArena split JSON 都未出现在已检查 repository snapshot 中。

offline 构造包含四个阶段。第一，failure detector 预测六类 failure type、recoverability 与 severity；irrecoverable 运行以及论文 severity weight 低于 `delta=0.3` 的重大缺陷被拒绝。第二，gpt-4o-mini 提取 actual achievements 与 key observations，prompt 要求结论只能基于 observation。第三，gpt-4o-mini 生成与原 prompt 风格、复杂度相匹配的 hindsight prompt；Qwen2.5-72B-Instruct 独立判断完整记录 episode 是否满足它。relabeler 首次尝试用 `T=0.3`、重试用 `T=0.7`，verifier 用 `T=0`，最多尝试三次。两个 confidence 原则上都应达到 `theta=0.5`，但 Algorithm 1 允许采用 `0.4` 的最佳候选 fallback。第四，确定性的 converter 输出 SFT、DPO 或 ShareGPT 记录。

输出保留 full-episode supervision，但不同格式的序列化并不相同。SFT 把 hindsight prompt 与 assistant reconstruction 配对，并由 severity 缩放 loss。DPO 把 hindsight-goal conversation 作为 chosen，把 original-goal conversation 作为 rejected；二者使用同一 episode，并由 severity 缩放 margin。ShareGPT 交错保存 hindsight prompt、assistant thought/action turn、observation turn，并在存在时保留 final answer。公开代码中，SFT 与 DPO 的 assistant 字符串把每条 observation 截断为 300 个字符，而 ShareGPT 保留完整 observation text。因此即使 source input 更长，SFT/DPO artifact 也不是完整 replay log。

论文报告 open-weight training 使用 LoRA rank 16、alpha 32，SFT 训练 3 epoch，DPO 训练 1 epoch且 beta 0.1，最大 sequence length 4,096，框架为 ms-swift，硬件为 8 张 A100-80G。GPT-4o 使用 OpenAI fine-tuning API，另有 8-shot ICL 条件。精确 model/tokenizer revision、OpenAI API snapshot、environment step/token budget 与完整 training/evaluation command 均为 unknown。

verifier/environment 边界至关重要。benchmark environment 确认的是原任务 outcome，hindsight goal 并未被再次执行；learned judge 只检查序列化 observation record 是否支持目标，因此发布中没有面向新目标的可执行 terminal predicate。要复现实验，还需要独立 relabeler/verifier client、固定 prompt/model、raw 与 rejected record、task split、environment adapter、reset、tool/API version 和 replay manifest。已检查 package 不包含实验数据、fine-tuning script、evaluation script 或 annotation asset。
