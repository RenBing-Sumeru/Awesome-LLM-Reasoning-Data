AgentHER asks whether a failed agent run must be discarded when its recorded actions and observations may already constitute a valid demonstration for a different, achievable goal. The decision boundary is data construction, not a new WebArena or ToolBench benchmark: those environments supply source episodes and terminal outcomes, while AgentHER transforms selected failures into post-training records.

The input object is a failed run `(g_i, tau_i, f_i)`. The trajectory `tau_i` is an ordered sequence of thought, action, and observation triples, and the released schema adds `trajectory_id`, `original_prompt`, `final_answer`, `failure_reason`, and metadata. The construction later adds failure type, recoverability, severity, observation-grounded achievements, a hindsight prompt, two judge confidences, rationale, and output-format fields. One accepted episode can become an SFT conversation, a DPO chosen/rejected record, or a ShareGPT dialogue; AgentHER does not regenerate the underlying environment interaction.

The concrete gap is that success-only demonstration pipelines waste recoverable failures, but a useful alternative label must not reward an unsupported goal. The paper therefore makes failure selection, outcome extraction, hindsight-goal synthesis, judge agreement, and severity weighting part of the data contract. Original task success remains environment-specific, whereas the relabeled pair is accepted by learned judges over the recorded observations rather than by live environment replay.

This belongs in `environment_agent_trajectory_data` because the trainable object is a full web-navigation or API/tool-use episode. It is also a construction recipe, not evidence of RLVR: the reported uses are SFT, DPO/preference learning, and agent fine-tuning. The public package reads serialized JSON/JSONL trajectories but does not release the experimental corpus, environment adapters, executable terminal predicates, or replay manifests.
