The paper evaluates only WebArena and ToolBench. It explicitly leaves cross-environment contamination unresolved, does not provide a human-written hindsight-goal upper bound, and relies on two strong learned judges whose residual bias may affect rare task types. Its noisy-judge theory assumes independent, identically distributed errors and bounded marginal harm; the authors present it as a plausibility argument, not a deployment guarantee.

Selection has both false-positive and false-negative risk. Human majority vote finds 2.9% invalid MJ-X labels on WebArena and 4.0% on ToolBench, while 38.7% and 35.8% of confidence-filtered rejections are human-valid. The reported precision therefore does not describe recall or the original failure distribution. Algorithm 1's `0.4` single-judge fallback further weakens a simple claim that both judges must agree at `0.5`.

The inspected code cannot reproduce the paper's cross-model judge contract as configured. `AgentHERPipeline` constructs one `LLMClient` and injects it into the detector, extractor, and relabeler; `_second_judge` calls that same client. It does not instantiate separate gpt-4o-mini and Qwen2.5-72B-Instruct services. More seriously, the second-judge acceptance path tests `verdict.confidence >= min_confidence` but does not check `verdict.is_valid`, so a high-confidence negative verdict can pass.

Severity semantics point in opposite directions. The paper assigns major errors weights below `0.3` and drops them. The released `FailureAnalysis.severity` documents `0=mild` and `1=catastrophic`, rule-based detection raises severity for error keywords, and the pipeline discards values below `0.3` before propagating the same value as the training weight. Without reconciliation, code filtering and weighting do not implement the paper's stated meaning.

The training views also lose trajectory content. SFT and DPO serialization truncate every observation to 300 characters, while ShareGPT keeps full observation text. DPO changes the prompt between chosen and rejected records, which some downstream trainers may not support. None of these formats includes environment version, state snapshot, reset seed, terminal-predicate implementation, tool/API version, timestamp, or replay result, so they are offline text records rather than replayable episodes.

Release completeness is the largest blocker. At inspected commit `98072c34db5ee65a22e43f8621b5ec76a9c995e1`, there is no dataset release, Hugging Face page, tag, GitHub Release, experimental WebArena/ToolBench corpus, accepted/rejected relabeling set, WA split JSON, training script, evaluation script, environment adapter, replay manifest, or full annotation UI/guidelines/sample IDs. The repository PDF predates and differs from arXiv v4. Paper CC0-1.0 and code Apache-2.0 do not establish rights for trajectories, benchmark content, generated goals, thoughts, or observations. These gaps block direct training reuse and independent score reproduction.
