For `environment_agent_trajectory_data`, AgentHER is a concrete recipe for preserving failed episodes as structured data instead of deleting them. A builder can borrow the separation among original environment outcome, failure type and recoverability, observation-grounded achievement, hindsight goal, judge confidence, severity weight, and downstream serialization. That separation makes it possible to audit which component turns a failure into a training target.

The evidence supports three intended uses only: SFT on hindsight-goal demonstrations, preference learning/DPO over hindsight-versus-original goal records, and agent fine-tuning from the resulting episode text. It does not support RLVR, reward-model training, process supervision, or a claim that the public repository already provides a ready-to-train corpus. The scalar severity value weights supervised or preference losses; it is not an executable verifier reward.

For dataset construction research, the most useful experiment is to vary judge independence, confidence thresholds, fallback policy, severity semantics, and failure classes while reporting both accepted precision and rejected-set false negatives. Looping failures should remain a distinct slice because the paper finds lower recoverability, lower acceptance, and smaller gains. Any derivative DPO pipeline must explicitly support different prompts on the chosen and rejected sides.

For release engineering, this Card turns the track's replay requirement into a checklist: publish record-level raw, accepted, and rejected trajectories; preserve full observations; pin the task split and every environment, model, tool, prompt, tokenizer, and trainer revision; expose executable reset and terminal predicates; release train/eval scripts and replay manifests; state dataset-specific rights; and bind the paper version to an immutable code/data release.

The current reuse class is method/reference only until those artifacts exist and the implementation mismatches are fixed. The repository can help a team understand the package schema and offline relabeling logic, but it cannot reproduce the reported cross-model experiment or supply the reported training records. Evaluation scores should guide hypotheses about the recipe, not certify data quality.
