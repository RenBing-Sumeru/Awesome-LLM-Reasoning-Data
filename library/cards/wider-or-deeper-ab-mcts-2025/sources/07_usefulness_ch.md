对于 **Rollout, Search, and Test-Time Trace Data**，AB-MCTS 提供了把推理预算分配视为数据构造变量的具体配方。后续研究可以固定 prompt、模型快照、evaluator、temperature 和总生成调用数，再比较独立变宽、迭代变深、固定分支 MCTS、AB-MCTS-M 与 AB-MCTS-A。分析单位应是完整响应—修订树，而不只是提交答案。

具体用途包括：

- 为具有标量环境反馈的代码、ARC 或 ML-engineering 任务实现自适应变宽/变深生成器；
- 序列化 `MCTSResult` 树和逐调用日志，构建官方 artifact 缺失的原始轨迹发布；
- 研究哪些 prompt 更适合独立替代方案，哪些更适合反馈驱动修补，以及后验不确定性如何在二者之间移动预算；
- 同时保留搜索分数与隐藏评估结果，并阻止隐藏测试泄漏进生成，以审计对公开反馈的过拟合；
- 在 API 调用数、生成 token、墙钟时间、evaluator 运行时间和金钱成本匹配时比较预算；
- 将最终答案 selector 与 Pass@k discovery 分开评估，尤其关注树中存在正确分支但排名不在首位的情形。

对于数据集构造，一条最低可用记录应包含不可变任务/来源 ID、prompt、模型快照与 provider 设置、树节点 ID、父节点 ID、新生成或修订动作、先前回答与反馈上下文、生成 completion、evaluator 版本与 payload、标量分数、访问/价值统计、调用顺序、token 与成本计量、最终选择标志，以及在防泄漏边界之后保存的隐藏结果。由于已检查实现中没有显式剪枝路径，应保留全部节点；未选分支即使不是最终答案，也具有负例或替代证据价值。

在后训练方面，这些树未来可以支持对成功修订做 SFT、构造偏好、训练价值模型或开展过程研究，但论文没有执行或验证这些用途。它们是研究机会，不是本 Card 的证据支持型 `training_use` 标签；这里支持的用途仍只有 `test_time_compute` 与 `evaluation`。

适当的复用等级是：**强推理配方与捕获 schema 参考；有条件复现；无法直接复用轨迹数据**。TreeQuest 可在 Apache-2.0 下复用，但仍受依赖与 provider 条款约束；benchmark 输入、模型响应、ARC-AGI-2 材料和 supplemental bundle 各自需要权利审查。复现应尽可能固定精确模型快照，记录未解决的 `deepseek-chat` revision，严格区分主实验 128 次调用与 ARC-AGI-2 的 250 次调用协议，并发布完整树及被拒绝/未选分支。

本 Card 也为所分配 track 提供发布清单：可运行搜索代码还不够。可复用测试时轨迹发布需要实际原始树、全部模型响应、修订提示、evaluator 输出、分支选择历史、成本计量、模型/版本固定、切分与污染文档，以及明确许可证。
