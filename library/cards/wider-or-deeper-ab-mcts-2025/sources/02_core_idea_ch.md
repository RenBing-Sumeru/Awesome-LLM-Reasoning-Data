核心贡献是对下一次生成调用的两种用途进行自适应控制：通过采样新答案来**变宽**，或利用反馈修订已有回答来**变深**。AB-MCTS 不预设固定 branching factor，而是把生成新分支的可能性表示为 `GEN` 子节点，并用后验预测分数分布上的 Thompson sampling，将该选项同已有回答及其修订路径进行比较。

一次 expansion 生成一个完整答案节点并立即评估；扩展之后没有独立的随机 rollout 阶段。提示根节点只是容器，因此经过 \(n\) 次扩展后，树包含根节点和 \(n\) 个生成节点。根节点的子节点是对任务的独立回答；非根子节点则是修订，其请求包含原始任务、祖先回答和由该回答评估结果构造的反馈。因此，树深具有明确语义：它记录连续的反馈驱动响应修订；树宽则记录不同尝试。

论文提出两种 Bayesian 变体。AB-MCTS-M 通过 mixed model 处理新分支与已有子树；AB-MCTS-A 在节点上聚合证据，并根据 reward 设置使用共轭 Gaussian 或 Beta 模型。二者都对后验预测进行采样，以在利用高分回答区域和通过 `GEN` 探索之间取得平衡。回传价值引导后续遍历；标量证据来自外部 evaluator，而不是仅由语言模型自评。

公开实现使这棵抽象树具备丰富轨迹契约的潜力。`MCTSResult.save()` 可以 pickle 根节点及所有递归可达的 `Node`；节点保留父子关系、prompt、completion、评估结果、模型名、访问次数和价值。OpenAI-compatible 生成代码还可写入请求/响应日志以及 token 与价格用量。若两类 artifact 均被保留，一条深路径就能成为可审计的“先前回答—evaluator 反馈—修订请求—新回答—分数”序列。

必须把这种能力同实际发布完整性区分开。官方 supplemental ZIP 与公开仓库包含算法、任务适配器、可视化、checkpoint/resume 和 ask–tell 接口，却不包含论文运行中实际生成的树、全部回答、分数历史、未选分支或 API 日志。因此，该贡献是可复现的搜索 substrate 与轨迹 schema，而不是公开的响应树数据集。
