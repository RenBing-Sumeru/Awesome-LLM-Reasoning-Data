The core contribution is an adaptive controller over two uses of the next generation call: **widen** by sampling a new answer, or **deepen** by refining an existing response with feedback. Rather than fixing a branching factor, AB-MCTS represents the option to generate a new branch as a `GEN` child and uses Thompson sampling over posterior predictive score distributions to compare that option with existing responses and refinement paths.

One expansion produces one complete answer node and immediately evaluates it; there is no separate stochastic rollout phase after expansion. The prompt root is only a container, so after \(n\) expansion iterations the tree contains the root plus \(n\) generated nodes. Root children are independent answers to the task. A non-root child is a revision whose prompt includes the original task, its ancestor response, and feedback derived from that response’s evaluation. Tree depth therefore has a semantic meaning: it records successive feedback-conditioned response revision, while width records alternative attempts.

The paper develops two Bayesian variants. AB-MCTS-M treats new branches and existing subtrees through a mixed model. AB-MCTS-A aggregates evidence at nodes and uses conjugate Gaussian or Beta models, depending on the reward setting. Both use sampled posterior predictions to balance exploitation of high-scoring answer regions against exploration through `GEN`. Backed-up values guide later traversal; the external evaluator, not the language model alone, supplies the scalar evidence.

The released implementation gives this abstract tree a potentially rich trace contract. `MCTSResult.save()` can pickle the root and every recursively reachable `Node`; nodes retain parent and child relationships, prompt, completion, evaluation results, model name, visits, and values. OpenAI-compatible generation code can also write request/response logs plus token and price usage. With both artifacts retained, a deep path becomes an auditable sequence of prior answer, evaluator feedback, revision request, new answer, and score.

That capability must be separated from actual release completeness. The official supplemental ZIP and public repositories contain algorithms, task adapters, visualization, checkpoint/resume, and ask–tell interfaces, but not the realized paper-run trees, all generated responses, score histories, unselected branches, or API logs. The contribution is therefore a reproducible search substrate and trace schema, not a public response-tree dataset.
