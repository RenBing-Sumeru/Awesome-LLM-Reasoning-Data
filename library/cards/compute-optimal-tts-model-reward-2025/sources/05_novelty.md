The paper's novelty is to move compute-optimal test-time scaling from a policy-only selection problem to a policy–verifier–difficulty problem. It makes explicit that reward models are not neutral selectors: for search they change the future population of traces, and for sampling they change which trace is allowed to represent the answer. This exposes reward distribution shift as a central systems variable rather than a secondary implementation detail.

It also uses this perspective to reinterpret model-size comparisons. The contribution is not a new universal search algorithm; it is an experimental decision map showing that small policies can win when the reward signal and compute allocation fit the task. That is a useful corrective to raw pass@k or model-size claims, because it ties reported performance to the complete inference configuration that produced it.
