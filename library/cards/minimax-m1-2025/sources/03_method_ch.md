继续预训练与 SFT 必须和 RL 分开阅读。7.5T token 阶段改进 Web/PDF 解析，从网页、论坛和教材抽取自然问答，进行语义去重，并明确不使用合成数据。Long-CoT SFT 覆盖六类宽领域，但只被描述为人工策展的高质量样本；SFT 数量、来源清单、教师列表、候选预算、筛选账本以及记录到模型阶段的映射均未披露。

可验证 RL 池包含四部分。数学从数十万道公开来源与正式竞赛题出发，删除格式错误及不合适题型，对 RL 来源去重，与 SFT 严格隔离，过滤和常用数学测试的相似项，抽取参考答案，并只保留某个强模型 pass@10 严格位于 0 与 0.9 之间的题目，最终接近 50K。SynLogic 在 41 个任务类型上生成约 53K 个实例，以模型可解性设定难度边界，并在后期提高难度。公开在线判题平台与编程网站提供 30K 道竞赛编程题；缺少测试时由 MiniMax-Text-01 生成，再按通过率保留中等难度任务。

软件工程 RL 使用来自公共 GitHub 仓库的数千个 issue/PR 任务。报告中的每条样本包含问题描述、初始缺陷代码和关联测试。容器化沙盒会执行修改：全部相关测试通过时给正反馈，编译错误、运行失败或回归则得到零或负反馈。仓库版本、容器、依赖、生成测试、flaky test 处理、执行记录和最终任务 ID 均未发布。

25K 通用 RL 池区分客观 STEM/事实任务与没有唯一标准答案的任务。客观回答由 Generative Reward Model 依据五档尺度和 ground truth 比较，并通过人工标注基准以及 Best-of-N 与 pass@N 对照来校准。开放式提示来自内部标签池；未具名的内外部模型生成参考候选，经内部质量审查后，以 -1、0、1 做成对比较。约束遵循任务结合规则与模型反馈，多人盲评一致、位置交换一致和 Swiss Round 流程用于选择参考答案。底层记录、评审指令、模型检查点和决策日志都不可获得。

CISPO 使用类似 GRPO 的组相对优势，但裁剪重要性权重并保留 token 梯度贡献，同时采用 token 级归一化、动态采样和长度惩罚，不使用 KL 项。报告提到每个生成批次进行 16 次离策略更新、数值精度修复、AdamW 敏感性，以及当连续 3,000 个 token 的概率都高于 0.99 时提前截断。完整 rollout 组大小、训练解码设置和可执行配置为 unknown。

长输出课程依次经过 40K、48K、56K、64K、72K 与 80K 上限。阶段转换依据生成序列 perplexity 是否收敛，以及输出长度第 99 百分位是否接近当前上限。80K 阶段删除 40K 模型容易解出的提示，提高困难数学与代码的权重，并在重复、同质的输出扰乱训练后降低合成推理数据占比。论文描述了规则，但未给出阈值、逐阶段混合、留存数量或事件日志。

评测是独立的数据面。MiniMax 使用 temperature 1.0 与 top-p 0.95；AIME、GPQA 各平均 32 次采样，LiveCodeBench、FullStackBench 各平均 16 次。SWE-bench Verified 使用修改后的 Agentless scaffold，只评估兼容的 486 个任务而不是完整 500 个。TAU-bench 使用 GPT-4.1 用户模拟器、不加自定义工具且最多交互 40 步；MultiChallenge 由 GPT-4o 评判。这些设置都不能披露训练记录，也不能验证其质量。
