The largest gap is release scope. MiniMax publishes weights and inference/deployment assets, but no continual-pretraining corpus, Long-CoT SFT set, RL prompt set, sampled policy output, reward ledger, rejected candidate, or stage manifest. Aggregate counts cannot identify which records entered which run or allow another team to reconstruct the mixture.

Provenance and rights remain coarse. Terms such as public sources, official competitions, online judges, coding websites, books, Web/PDF, and public GitHub repositories omit item IDs, immutable revisions, extraction dates, transformations, attribution, and license chain. The Apache-2.0 labels on current official code and weight pages do not license unreleased upstream training material.

Verifier replay is not possible. Math answer extraction can mishandle equivalent forms; final-answer and format rewards do not validate reasoning; pass-rate difficulty depends on unidentified models. MiniMax-Text-01-generated tests may encode incomplete specifications, while containers, dependencies, flaky-test policy, and execution logs are absent. GenRM scoring inherits reference quality and judge bias; the paper reports length preference and online recalibration but not the reward artifacts or calibration results.

Training reproduction is also blocked. The exact CISPO implementation, full optimizer configuration, training decoding parameters, rollout group size, dynamic data weights, stage-transition thresholds, per-component rewards, early-truncation events, optimizer states, and checkpoints are unavailable. The reported three-week run and rental estimate are useful resource disclosures, not substitutes for an executable run manifest.

Decontamination is partial. Math RL describes n-gram and embedding checks against common tests, but benchmark identities and revisions, thresholds, matches, and removals are not published. Comparable evidence is absent for most continual-pretraining, SFT, general RL, software-engineering, tool-use, and long-context surfaces.

Evaluation has protocol dependencies. SWE-bench uses 486 compatible tasks and a modified Agentless scaffold; several benchmarks use many sampled responses; TAU-bench uses a model-based user and a 40-step cap; MultiChallenge uses model judgment. Scores under these settings do not establish trace correctness, rights, source diversity, verifier validity, safety coverage, or absence of contamination.
