官方 arXiv 报告对聚合级阶段披露较具体：给出 7.5T token 继续预训练预算与 70% 重点混合、SFT 领域构成和数学/代码约 60% 的比例、RL 各领域数量、通过率筛选、软件执行契约、GenRM 评分形式、CISPO 设计、长输出课程、部分稳定性修复，以及 512 张 H800 持续三周的 RL 训练。这些内容支持报告级配方，但不足以逐记录重放。

开放制品真实存在，但覆盖范围比论文配方更窄。官方 Hugging Face collection 包含 MiniMax-M1-40k、MiniMax-M1-80k 及对应的 Transformers 格式权重。官方 GitHub 仓库在 Apache-2.0 下提供报告、模型配置与实现、推理入口、tokenizer 资产以及部署和函数调用指南。尚未确认官方 M1 训练数据、策略 rollout、奖励轨迹、GenRM 检查点、沙盒包或端到端训练代码。

基准表只能支持指定设置下的模型行为。例如，报告在自己的 486 任务 SWE-bench Verified 设置上给 40K 与 80K 模型分别报告 55.6 和 56.0；由于排除了 14 个与 MiniMax 基础设施不兼容的任务，横向比较必须保留这一限定。数学/代码的多次采样分数、使用用户模拟器的 TAU-bench 和模型评判的 MultiChallenge 同样依赖评测协议。

消融与训练曲线为所研究运行中的 CISPO 和长输出扩展提供证据，却不能证明每条训练轨迹都正确、每组生成测试都完整表达 issue 规范、奖励模型能在基准外保持校准、数据权利完整或不存在污染。算力成本与基准表现属于模型和流程证据，不是数据质量证据。
