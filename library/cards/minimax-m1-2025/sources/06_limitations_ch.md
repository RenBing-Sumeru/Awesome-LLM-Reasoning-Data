最大缺口是发布范围。MiniMax 公开了权重与推理/部署资产，却没有发布继续预训练语料、Long-CoT SFT 集、RL 提示集、采样策略输出、奖励账本、被拒候选或阶段清单。聚合数量无法指出哪些记录进入哪个训练运行，也不能让其他团队重建混合。

来源与权利披露仍然粗粒度。“公开来源”“正式竞赛”“在线判题平台”“编程网站”“书籍”“Web/PDF”和“公共 GitHub 仓库”等标签缺少样本 ID、不可变版本、抽取日期、变换过程、署名与许可链。当前官方代码和权重页面的 Apache-2.0 标签不能为未发布的上游训练材料授予许可。

验证器无法重放。数学答案抽取可能误判等价形式，最终答案与格式奖励不验证推理过程，通过率难度又依赖未具名模型。MiniMax-Text-01 生成的测试可能只覆盖不完整规范，而容器、依赖、flaky test 政策和执行日志均不可获得。GenRM 评分继承参考答案质量与裁判偏差；论文报告了长度偏好和在线重校准，却没有发布奖励制品或校准结果。

训练复现同样受阻。精确 CISPO 实现、完整优化器配置、训练解码参数、rollout 组大小、动态数据权重、阶段转换阈值、各奖励分量、提前截断事件、优化器状态和检查点都未提供。持续三周的训练与租用成本估算是有用的资源披露，但不能替代可执行运行清单。

去污染只覆盖部分范围。数学 RL 描述了针对常用测试集的 n-gram 与 embedding 检查，但没有公布基准身份与版本、阈值、匹配项和删除项；大部分继续预训练、SFT、通用 RL、软件工程、工具使用和长上下文数据面缺少同等证据。

评测依赖具体协议。SWE-bench 只用 486 个兼容任务和修改后的 Agentless scaffold；多个基准会采样多条回答；TAU-bench 使用模型化用户并限制 40 步；MultiChallenge 由模型裁判评估。这些分数不能建立轨迹正确性、权利完整性、来源多样性、验证器有效性、安全覆盖或无污染结论。
