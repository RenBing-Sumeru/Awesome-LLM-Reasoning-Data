Continual pretraining and SFT must be read separately from RL. The 7.5T-token stage refines Web and PDF parsing, extracts natural QA pairs from webpages, forums, and textbooks, applies semantic deduplication, and explicitly avoids synthetic data. Long-CoT SFT covers six broad domains and is described only as curated high-quality examples. No SFT count, source manifest, teacher list, candidate budget, filter ledger, or model-stage assignment is disclosed.

The verifiable RL pool has four components. Math begins with hundreds of thousands of public and official-competition problems, removes malformed and unsuitable forms, deduplicates RL sources, separates them from SFT, filters similarity to common math tests, extracts reference answers, and keeps questions with a strong model's pass@10 strictly between 0 and 0.9, leaving nearly 50K. SynLogic generates about 53K instances across 41 task types with model-solvability bounds and later difficulty increases. Public online-judge and coding-site problems yield 30K competitive-programming items; MiniMax-Text-01 generates tests when they are missing, and pass rates select moderately challenging tasks.

Software-engineering RL uses several thousand issue/PR-derived tasks from public GitHub repositories. Each reported item includes a problem description, initial faulty code, and associated tests. A containerized sandbox executes changes: passing all relevant tests earns positive feedback, while compilation errors, runtime failures, or regressions produce zero or negative feedback. Repository revisions, containers, dependencies, generated tests, flaky-test policy, execution transcripts, and final task IDs are not released.

The 25K general RL pool separates objective STEM/factual tasks from tasks without one ground-truth answer. Objective responses receive a five-grade Generative Reward Model comparison against ground truth, calibrated with a human-annotated benchmark and Best-of-N versus pass@N analysis. Open-ended prompts come from an internally tagged pool; unidentified internal and external models generate reference candidates, internal review selects them, and pairwise comparison returns -1, 0, or 1. Constraint-following combines rule and model feedback, while multiple-blind and position-swapped agreement plus a Swiss Round procedure choose references. The underlying records, prompts, model checkpoints, and decision logs are unavailable.

CISPO uses GRPO-style group-relative advantage but clips importance weights, retains token contributions, applies token-level normalization, dynamic sampling, and a length penalty, and omits a KL term. The report mentions 16 off-policy updates per generation batch, numerical precision fixes, AdamW sensitivity, and early truncation after 3,000 consecutive tokens each exceed probability 0.99. Full rollout group size, training decoding settings, and an executable configuration are unknown.

The long-output curriculum proceeds through 40K, 48K, 56K, 64K, 72K, and 80K limits. Stage transitions use generated-sequence perplexity convergence and whether the 99th output-length percentile approaches the current limit. The 80K phase removes prompts the 40K model solves easily, favors harder math/code, and downsamples synthetic reasoning after repetitive, homogeneous outputs destabilize training. These rules are described, but thresholds, stage mixtures, survival counts, and event logs are not.

Evaluation is a separate data surface. MiniMax uses temperature 1.0 and top-p 0.95; AIME and GPQA average 32 samples, and LiveCodeBench and FullStackBench average 16. SWE-bench Verified uses a modified Agentless scaffold on 486 compatible tasks rather than all 500. TAU-bench uses a GPT-4.1 user simulator, no custom tools, and at most 40 interactions; MultiChallenge uses GPT-4o judgment. None of these evaluation settings discloses the training rows or validates their quality.
