**Inputs and successful baselines.** Tasks come from MATH, GSM8K, HumanEval, SciBench, MMLU-Pro/MMLU, and GAIA and are executed through LLM Debate, MacNet, AgentVerse, DyLAN, SmolAgents, or Magentic-One. All MAS agents are standardized to GPT-4o-mini at temperature 0 with a fixed random seed. For each source task, the pipeline first retains a trajectory whose task evaluator reports success. The exact GPT-4o-mini snapshot, upstream task versions, baseline count, and stable record-level baseline IDs are unknown (Paper §§4.1–4.3).

**Intervention and rollout.** A context-aware manipulator, run at temperature 0.7, builds unique target-agent/error-mode plans and randomly applies either prompt injection or response corruption. The perturbed system is rolled out under its framework. Exact manipulator model identity, plans or attempts per baseline, retry budget, total attempted injections, and construction API/token budget are not disclosed. DyLAN labels receive post-hoc refinement, but the rule and adjudication log are not released.

**Terminal verification and filtering.** Each benchmark has its own terminal evaluator: normalized comparison for mathematics, executable tests for HumanEval, unit/tolerance-aware checks for SciBench, A–J extraction for MMLU-Pro, and GPT-4o-mini semantic judgment for GAIA. The pipeline retains only interventions that change a successful baseline into evaluator-confirmed failure, `Z(τ_injected)=1`; non-failing injections and self-corrected episodes are absent from the inspected release. The ground-truth attribution map is the injection plan itself, so labeling is by construction rather than independent causal adjudication.

**Released object and split.** A retained row contains the full failed conversation/execution history, task and framework metadata, faulty-agent/error-mode labels, injection strategy, correct answer, and injected-agent provenance. The resulting corpus has 9,533 trajectories with 24,843 injection instances. The paper selects 100 trajectories from each of six benchmarks for Aegis-Bench (600); the remainder is split 80/20 with a fixed seed. The HF surface is approximately **7,147 train / 1,786 validation / 600 test**. The paper states trajectory-level non-overlap but does not disclose grouping by upstream task or successful baseline, deduplication, or decontamination.

**Training and evaluation interfaces.** SFT serializes the trajectory and taxonomy definitions as prompt `x` and targets JSON `o` containing faulty agents and modes. GRPO uses the structured partial-credit/penalty reward described in §5.2. DCL treats an episode as a bag of turns, learns evidence-turn attention and agent/error prototypes, and combines BCE, supervised contrastive, and hierarchy-consistency losses; successful baselines are described as positive anchors, but their presence in the public JSONL was not verified. Evaluation reports exact pair, agent, error, Micro-F1, and Macro-F1 metrics on Aegis-Bench and Who&When.

**Implementation and replay boundary.** SFT/GRPO use `verl`, four A800 GPUs, batch size 64, three epochs, maximum sequence length 8,192, and reported learning rates 3e-6/5e-6; GRPO reports LoRA rank 64 and KL coefficient 0.001. Reproduction must pin arXiv v6, GitHub commit `ced13443…`, HF revisions and hashes, model/API snapshots, evaluator code and GAIA judge prompt, dependencies, seeds, baseline lineage, and reset state. No common release manifest binds those objects, so the code/data release is useful for offline study but does not establish immutable end-to-end replay.
