- **构造式归因：** gold label 直接等于 planned target-agent/error-mode injection。同时扰动多个 agent 时，terminal failure 只能说明组合干预击败了 evaluator，不能证明每个标签都是独立必要原因。受控 MAST mode 还会低估 emergent、interaction-induced 或 unseen failure；论文也把固定 taxonomy 与受控 plan 明确列为限制。
- **只保留失败的选择：** 只有把 successful baseline 变成 evaluator-confirmed failure 的 intervention 才进入 9,533-row corpus。non-failing injection、self-correction、retry 与 rejected attempt 的数量和记录均为 unknown。这会移除 resilience 证据，并可能让 intervention artifact 或 evaluator weakness 成为标签捷径。
- **Mixed-verifier 风险：** 数学归一化、code test、科学数值 tolerance、multiple-choice extraction 与 GPT-4o-mini GAIA judge 各有不同 false-positive/false-negative mode。确切 evaluator version 与 GAIA judge prompt/model snapshot 未固定；format 或 judge 错误可能同时决定样本是否保留以及表观 ground truth。
- **划分与污染风险：** 约 7,147/1,786/600 的 train/validation/test 只在论文所述 trajectory level 不重叠。未披露按 upstream task 或 successful baseline 分组、deduplication 或 decontamination 方法。因此，共享 source content 的多个 injected variant 可能跨 split，而所有 in-domain split 都复用相同六类 benchmark。
- **Lineage 与 replay 不完整：** 公开 row 不能验证稳定的 baseline-to-variant link、确切 GPT-4o-mini/manipulator snapshot、每个 baseline 的 attempt 数、reset state、dependency lock 或逐记录 evaluator version。可变 GitHub/HF history 缺少统一 release manifest，不能因代码公开就假设端到端构造可相同重放。
- **发布与 license 边界：** HF data 与 GitHub code 声明 MIT，arXiv v6 为 CC BY 4.0；上游 benchmark item、framework output 与 model-generated trace 的权利未调和。论文称 model 已开源，但未核验到官方 model artifact 链接。data/code 可得不等于 model 可得，也不能解决上游 redistribution right。
- **标签审计缺口：** DyLAN post-hoc refinement 缺少可重建流程。三位专家、100 条 trajectory 的研究报告 κ 值，但没有 recruitment、raw label、逐 mode error、disagreement adjudication、compensation 或 consent，限制了 rare label 与 human comparison 的审计。
- **泛化与实验漂移：** SFT 在两个 epoch 后对 Who&When 出现 synthetic-style overfitting，所有测试模型也都遗漏 Appendix A.2 的 numeric root cause。正文与 Appendix D 对 DCL 使用 4 张 RTX 4090 还是 4 张 RTX 3090 存在冲突。因此报告的 benchmark improvement 不能证明广泛 failure coverage、data quality 或准确可复现性。
