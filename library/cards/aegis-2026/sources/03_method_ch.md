**输入与成功 baseline。** 任务来自 MATH、GSM8K、HumanEval、SciBench、MMLU-Pro/MMLU 与 GAIA，并通过 LLM Debate、MacNet、AgentVerse、DyLAN、SmolAgents 或 Magentic-One 执行。全部 MAS agent 统一使用 temperature 0 的 GPT-4o-mini 与固定 random seed。对每个 source task，pipeline 先保留 task evaluator 判为成功的 trajectory。确切 GPT-4o-mini snapshot、上游 task version、baseline 数量与稳定的 record-level baseline ID 均为 unknown（论文第 4.1–4.3 节）。

**干预与 rollout。** context-aware manipulator 在 temperature 0.7 下构造唯一的 target-agent/error-mode 计划，并随机采用 prompt injection 或 response corruption。受扰动系统继续在其 framework 中 rollout。确切 manipulator model 身份、每个 baseline 的 plan/attempt 数、retry budget、注入尝试总量与构造 API/token budget 均未披露。DyLAN label 接受 post-hoc refinement，但规则与 adjudication log 未发布。

**Terminal verification 与过滤。** 各 benchmark 使用不同 terminal evaluator：数学任务做 normalized comparison；HumanEval 执行 test；SciBench 采用 unit/tolerance-aware check；MMLU-Pro 抽取 A–J；GAIA 使用 GPT-4o-mini semantic judgment。pipeline 仅保留把成功 baseline 变成 evaluator-confirmed failure 的干预，即 `Z(τ_injected)=1`；在已检查的发布中看不到 non-failing injection 与 self-corrected episode。ground-truth attribution map 直接等于 injection plan，因此标签来自构造，而非独立 causal adjudication。

**发布对象与划分。** 一条保留 row 包含完整失败 conversation/execution history、task/framework metadata、faulty-agent/error-mode label、injection strategy、correct answer 与 injected-agent provenance。最终语料共有 9,533 条 trajectory、24,843 个 injection instance。论文从六个 benchmark 各选 100 条组成 Aegis-Bench（共 600 条），其余按固定 seed 以 80/20 划分。HF surface 约为 **7,147 train / 1,786 validation / 600 test**。论文声明 trajectory-level 不重叠，但没有披露是否按 upstream task 或 successful baseline 分组，也没有给出 deduplication 或 decontamination 程序。

**训练与评测接口。** SFT 将 trajectory 与 taxonomy definition 序列化为 prompt `x`，目标 `o` 是包含 faulty agent 与 mode 的 JSON。GRPO 使用第 5.2 节所述结构化 partial-credit/penalty reward。DCL 把 episode 视为 turn bag，学习 evidence-turn attention 与 agent/error prototype，并组合 BCE、supervised contrastive 与 hierarchy-consistency loss；论文把 successful baseline 描述为 positive anchor，但未核验其是否出现在公开 JSONL。评测在 Aegis-Bench 与 Who&When 上报告 exact pair、agent、error、Micro-F1 和 Macro-F1。

**实现与 replay 边界。** SFT/GRPO 使用 `verl`、4 张 A800 GPU、batch size 64、3 个 epoch、最大 sequence length 8,192，报告的 learning rate 分别为 3e-6/5e-6；GRPO 还报告 LoRA rank 64 与 KL coefficient 0.001。复现必须固定 arXiv v6、GitHub commit `ced13443…`、HF revision 与 hash、model/API snapshot、evaluator code 与 GAIA judge prompt、dependency、seed、baseline lineage 和 reset state。当前没有统一 release manifest 绑定这些对象，因此 code/data release 适合 offline study，但不能证明端到端 immutable replay。
