Retry prompting does not know whether the first answer was wrong. It spends the same extra budget on correct and incorrect paths and can cause unnecessary edits or right-to-wrong regressions. External verifiers can decide when to retry, but they add a separate scoring model or checker at inference. ReVISE asks whether one model can learn an explicit stop-or-refine action and then condition correction on its own previous reasoning.

The data problem is not just collecting “good” and “bad” solutions. Each sampled path must be paired with an outcome decision, converted into a control-token preference, and—when incorrect—linked to a continuation target. Stage membership matters because the first curriculum teaches when to stop, while the second teaches what to generate after choosing refinement. Flattening these pairs would hide the actual supervision contract.
