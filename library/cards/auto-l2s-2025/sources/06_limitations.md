The paper notes dependence on costly, high-quality paired long/short annotations, a coarse binary long-versus-short decision, and efficiency results tied to autoregressive decoding. Final-answer correctness is the construction verifier; it does not certify intermediate validity, and choosing the shortest correct sample can favor lucky or underspecified rationales. Teacher errors and stylistic artifacts can propagate into both modes.

The full paired dataset, rejected samples, exact counts, ties, data license, splits, decontamination, and correctness logs were not confirmed as released. The code repository has one visible commit and no root license file, while only the model repository declares Apache-2.0. Paper notation and implementation naming for the EASY routing token differ and require care. Results cover two base sizes and mostly math/reasoning benchmarks; accuracy losses on some tasks show that compression is not uniformly safe. Model weights do not resolve these data-audit gaps.
