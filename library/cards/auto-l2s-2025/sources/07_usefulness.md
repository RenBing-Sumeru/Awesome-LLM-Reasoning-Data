For this track, AutoL2S suggests a reusable long-to-short record with prompt/source ID, reference answer, long teacher and revision, long trace and correctness result, all k short candidates, answer extraction, rejection reasons, token lengths, chosen shortest trace, tie rule, routing annotation, final SFT sequence, rollout mode, binary utility, and post-training update. Keeping rejected candidates is important because the selected short trace alone hides search cost and verifier bias.

Such records can support reasoning compression, adaptive SFT, distillation, and audits of when short traces fail. They also let curators separate teacher-data effects from the routing token and GRPO-style optimizer. The released code and 7B checkpoint are useful for implementation study, but independent data reuse requires reconstructing or releasing the paired corpus and its provenance.
