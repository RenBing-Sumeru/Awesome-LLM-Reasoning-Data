The largest release limitation is object mismatch. The paper discusses process-level trajectories and Appendix C describes generating successful and failed trajectories, but the checked release publishes tasks and gold repair metadata, not structured state-action-observation episodes. Prompt/model output fields in current processing records do not substitute for commands, observations, filesystem deltas, retries, patches, tests, stdout/stderr, and terminal verdicts. Failed and successful experimental runs cannot be audited item by item.

The execution contract is not self-contained. `Evaluation/Execution` is a gitlink at `99729fb0454fb5ef3d031a7b62cb7532fe8fc114`, with no `.gitmodules` mapping in the checked snapshot. Repository defaults use a local environment with testing disabled and safe mode enabled, while the reported terminal evaluation requires Docker and tests. The paper does not disclose experiment-time numeric timeout, partial credit, reset, or replay semantics. Reconstructing Pass@1 therefore requires unverified integration outside the snapshot.

Process scores inherit judge and matching failure modes. The paper names GPT-4.1-mini, while released code defaults to `gpt-4o-mini`; the declared 0.7 similarity threshold is not applied in the inspected evaluator. The hard-coded combined match threshold above 0.5 gives exact type most of the weight, and set-based type scoring collapses repeated errors of the same category. LLM prompt sensitivity and API drift can change semantic accuracy. A passing live-dependency script may still be unsafe, non-reproducible, or semantically wrong in ways the predicate does not observe.

Release lineage has visible version drift: paper 323 repositories versus 320 JSONL names, 321 tree directories, and 329 revision records; paper levels 1-10 versus 48 released level0 tasks; and unreconciled error distributions. There is no train/dev/test or hidden split, no model-corpus decontamination audit, and no instance-level source-overlap manifest. Public READMEs and gold repairs can overlap model training data; repository pinning is not decontamination.

Environment replay and security remain weakly specified. `ubuntu:22.04` is not digest-pinned, pyenv is cloned without a commit, Miniconda lacks a published checksum in the recipe, and apt/PyPI/conda/GitHub resources remain live. Package/channel locks, cache state, egress policy, and per-task reset are unknown. The container runs as root and executes untrusted repository plus model-generated shell content; no privilege reduction, secret isolation, malware scan, supply-chain policy, or artifact quarantine is documented. Curator inference: reuse requires disposable, non-privileged, network-restricted infrastructure.

Finally, Apache-2.0 clearly covers repository code, but the release has no record-level license/attribution manifest for modified README content and upstream repositories. The paper asserts permission, anonymization, desensitization, and cleaning without releasing the item-level procedure. These gaps, together with absent rollout data, block training reuse; benchmark scores must not be treated as evidence of data quality.
