**Inputs.** Candidate Python repositories come from GitHub and existing manually verified environment benchmarks. The paper filters for at least 10 stars, more than 1,000 commits, and more than 10 closed issues. Professional annotators attempt the original setup and remove repositories with faulty instructions or incomplete dependencies. Exact source-mixture counts, annotator count, time budget, and rejected-repository manifest are not disclosed.

**Generation and collection.** Claude-4-Sonnet and Gemini 2.5 Pro minimally modify an original README, initially inserting exactly two errors. The generation response contains an error type, natural-language description, correction candidates, and a golden answer. The taxonomy is E1 dependency installation, E2 command/syntax, E4 path or missing file, E6 logical order, E7 version compatibility, and E8 other. Model allocation, temperature, seed, retries, and decoding parameters are unknown.

**Execution validation and selection.** GPT-4.1-mini produces a Bash script that follows the README for Ubuntu 22.04/Miniconda. The script is executed in Docker. An injection is retained only when the erroneous instructions fail and the proposed repair allows execution to progress through the affected step. GPT-4.1-mini then checks README support, error validity, type, and gold fix; humans review the survivors. The authors report 98.5% LLM-human agreement, but do not provide sample size, adjudication protocol, agreement formula, or confusion matrix. From 1,772 two-error README variants, 1,230 valid variants remain; errors are then split and merged into tasks of different levels.

**Released outputs.** The checked commit releases 4,201 main JSONL rows, 4,201 per-task JSON files, 4,201 matching README files, and 9,471 error objects. The main task row has `readme`, `repo_name`, `level`, and `errors`; it has no record-level repository URL, revision, Dockerfile, split, trajectory, result, or environment snapshot. Revisions are in a separate 329-row manifest, so reuse must normalize names to construct a task-to-revision relation. Evaluated agents output detected-error JSON and a corrected shell script; the current `AnalysisResult` schema also retains raw output and token usage, but those processing fields are not an environment trajectory.

**Verifier and evaluation.** Process scoring combines error-type precision/recall/F1 with LLM-judged description and fix accuracy. The checked matcher accepts a hard-coded combined score above 0.5: exact type contributes 0.6, description similarity 0.3 times confidence, and fix similarity 0.1 times confidence. The released evaluator defaults to `gpt-4o-mini`, temperature 0.1, and 500 output tokens, although the paper names GPT-4.1-mini; a configured 0.7 similarity threshold is not applied by the inspected path, which trusts the judge boolean. Terminal Pass@1 requires successful build, correct test execution, and normal exit. The exact end-to-end execution implementation is unavailable because `Evaluation/Execution` is gitlink `99729fb0454fb5ef3d031a7b62cb7532fe8fc114` without a `.gitmodules` mapping.

**Environment, budget, and reuse.** The released Dockerfile starts from Ubuntu 22.04 and installs Python standalone builds, Miniconda 25.3.1-1, Poetry, uv, pipenv, Pyright, Node 20, jq, and build tools using live endpoints. Repository defaults include API timeout 120 s, environment timeout 300 s, Bash timeout 60 s, five iterations, three retries, and a seed used only for optional sampling; these are not verified paper-experiment settings. The public use supported by the release is evaluation. Reproduction must pin commit `86ab7858613b85f4a8316f3cda3c83086b8cf7c2`, supply the missing executor, lock image/packages/network/cache/reset behavior, and retain every script, observation, test log, verdict, and run identifier.
