
The pipeline has four linked stages. First, behavior-cloning SFT on the 9,460 program-solver trajectories gives an instruction-tuned Qwen2.5-3B or Llama3.1-8B policy the basic action syntax and website skills needed to obtain nonzero rewards. Second, for each RL task, multiple browser instances start from the same page but maintain independent context, including cookies; the current policy asynchronously generates a group of distinct multi-turn histories. Third, dynamic context compression replaces earlier full HTML observations with simplified placeholders while preserving the action history, reducing memory use and shifting the loss mask as the context changes. Fourth, task-specific binary terminal rewards are normalized within each group to form relative advantages for multi-turn GRPO (M-GRPO).

The feedback contract is environmental and programmatic, not a language-model judgment. A task receives success or failure from WebArena's built-in string-match, URL-match, or program-execution checker over the final answer or web state. The reward supervises the full episode and induces token-level policy updates over action outputs, but it does not label intermediate decisions. Compared with plain BC, the policy trains on its own current failures and successes; compared with DigiRL- or WebRL-style off-policy recipes, WebAgent-R1 does not report a replay buffer, trajectory filter, or separately trained outcome reward model. The test-time analysis is a separate mechanism: it increases the allowed number of environment interactions, rather than selecting a longer single response, and measures how that episode budget changes success.
