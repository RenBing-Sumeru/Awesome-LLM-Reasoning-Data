
The feedback is sparse and terminal. String match, URL match, and program execution can verify task-specific conditions, but they do not assign credit to intermediate actions, measure reasoning faithfulness, or rule out unintended state changes that still satisfy a checker. The paper explicitly leaves fine-grained reward shaping to future work. Dynamic context compression also replaces earlier HTML with simplified placeholders; although action history is preserved, the paper does not quantify what observation evidence is lost or how compression errors affect later decisions.

Reproduction and data audit remain partial. The paper does not disclose the M-GRPO group size, total online rollout count, random seeds, exact task schedule, default interaction cap, per-run failure distribution, decontamination procedure, or a frozen environment/state manifest. The repository contains code and setup instructions, but no independently verified online trajectories, reward logs, trained checkpoints, tagged release, or immutable WebArena images. The public 9,460-trajectory BC set is stated to be Apache-2.0, while rights and licensing for newly generated online episodes are not separately documented because those episodes are not released.

The evidence is limited to text-only interaction with five WebArena-Lite sites and one held-out set of 165 tasks. Website state, authentication, cookies, task ordering, and reset behavior can change the trajectory distribution. Average gains hide regressions on individual sites, and WebAgent-R1-Zero demonstrates that sparse-reward RL may fail when the initial policy cannot emit valid actions. Long-CoT augmentation also gives a better SFT start but a smaller RL improvement, so more verbose traces are not automatically better exploration data. Finally, higher benchmark success establishes neither uniform trajectory quality nor reusable data; it only supports the evaluated policy-environment-checker configuration.
