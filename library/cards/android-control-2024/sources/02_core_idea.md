The contribution is a paired-granularity trajectory corpus plus a controlled scale study: humans execute Android tasks on physical phones while recording both a task-level goal and an instruction immediately before each action, after which the same episodes are transformed into high-level-only (HL) and low-plus-high-level (LL) state-action examples (Paper §3.1, pp. 4–5; §4.2, pp. 6–7).

One released episode contains `episode_id`, `goal`, PNG `screenshots`, serialized `accessibility_trees`, screenshot dimensions, JSON `actions`, and `step_instructions`. Actions sit between consecutive screenshots, so there is one fewer action than observation; low-level instructions align one-to-one with actions and may repeat when an instruction requires multiple actions (Appendix B.2, pp. 14–15; official repository README, “Dataset format”). The native action space is `click`, `long_press`, `input_text`, `scroll`, `navigate_home`, `navigate_back`, `open_app`, and `wait` (Paper Table 2, p. 5).

The feedback contract is programmatic but narrow. Offline step accuracy compares a predicted next action and its arguments with the human reference, allowing only specified equivalences: a coordinate inside the target element bounds, `navigate_back` versus clicking an on-screen Back element, and `open_app` versus clicking matching app text (Paper §4.2, p. 7; Appendix D.3, pp. 20–21). It observes agreement with one demonstrated next action; it does not observe live task completion, delayed side effects, recovery after an error, or many alternative valid routes. Collection-time labels of successful, infeasible, or failed are human judgments, while the `terminate` action used by SeqIO is a training-only insertion rather than a released executable terminal predicate (Paper §3.1, p. 5; Appendix C.2 and D.1).

Relative to UI-control datasets summarized in Table 1, including Android in the Wild as a baseline source for zero-shot evaluation, AndroidControl’s distinguishing object is the joint high-/low-level human instruction structure across broad app coverage, paired with explicit IDD, app-unseen, task-unseen, and category-unseen analysis. The research direction is supervised trajectory scaling under distribution shift, not RL reward design or online environment construction.
