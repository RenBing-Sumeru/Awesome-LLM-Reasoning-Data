**Inputs and collection.** An undisclosed LLM generates generic feature descriptions for 40 app categories. Twenty trained paid contractors choose apps, instantiate concrete tasks, write a high-level goal, and enter a low-level instruction before every action. Demonstrations were collected from April 2023 through April 2024 on physical Google Pixel phones running Android 8.0 or later through a companion Android app, Chrome web app, WebUSB, and ADB; the final four months introduced 20 LLM-generated personas (Paper §3.1, pp. 4–5; supplementary datasheet §1.1.3, p. 2). The exact LLM snapshots, prompts, decoding settings, and record-level persona assignments are unknown.

**Interaction and retention.** At every step, the recorder keeps a full-resolution PNG screenshot, serialized accessibility tree, and the next JSON action with arguments. Annotators label traces successful, infeasible, or failed. Failed/error episodes and raw discarded events are removed, while typos and grammatical errors in instructions are retained; scroll gestures are reduced to four directions (Paper §3.1, p. 5; datasheet §§1.1.2 and 1.1.4, pp. 2–3). The release does not expose a documented top-level status field, per-record quality ledger, adjudication process, failed episode count, or preprocessing code.

**Released output and splits.** The output is 20 GZIP TFRecord shards plus `splits.json` and `test_subsplits.json`. Paper Table 3 reports train 13,604 episodes/74,722 steps and validation 137/690; test subsets are IDD 721/3,897, app-unseen 631/3,475, task-unseen 803/4,464, and category-unseen 700/3,891. These test subsets can overlap and must not be summed. Direct inspection of the official manifest instead finds 13,603 train IDs, 137 validation IDs, and 1,543 test IDs; the one-episode train discrepancy is unresolved (Paper §3.3 and Table 3, pp. 5–6; official `splits.json` and `test_subsplits.json`, checked 2026-07-20).

**Training transformation.** SeqIO creates an HL task using only the goal and an LL task using both goal and current step instruction. Each input contains instruction text, a flattened textual accessibility-tree view of the current screen, and action history; the target is the next action. The evaluated agent does not consume screenshots. Element-based click/long-press targets without a matching accessibility node remain in history but are dropped as targets; LL targets without low-level instructions are also dropped, and an episode is removed only if all steps are discarded. SeqIO appends the training-only `terminate(successful|infeasible)` action (Paper §4.1–4.2, pp. 6–7; Appendix C.1–C.2 and D.1, pp. 16–19).

**Model, sampling, and evaluation.** PaLM-2S is LoRA-tuned on an HL/LL mixture. Scaling subsets randomly contain 5, 10, 100, 1k, 10k, or all paper-reported 13,604 training episodes; LoRA rank is 4 below 1k and 64 at 1k or more, decoding temperature is 0, and the best checkpoint is selected on validation. Offline next-action matching supplies the evaluation signal. Optimizer, learning rate, batch size, training seed, exact compute, and complete checkpoint policy are unknown (Paper §4.2, pp. 6–7; Figure 5 caption, p. 9).

Reproduction therefore requires pinning all shard hashes, both split files, a repository commit, and the paper version, then reimplementing collection preprocessing, SeqIO conversion, reference matching, and model training. No official training code, preprocessing code, evaluation script, configuration, checkpoint, tagged release, or replay environment is available in the checked repository; only the README and images are present, and the paper checklist states that code is not provided.
