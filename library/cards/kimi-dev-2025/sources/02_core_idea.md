The core idea is to make Agentless patch generation a skill prior for a tool-using SWE-Agent. GitHub issue/PR records first teach where and how code changes occur. Exact-localization reasoning and simulated file-tool conversations add repository navigation structure. Docker-verified BugFixer and TestWriter RL then ties outputs to observable repository behavior. Finally, public SWE-Agent trajectories adapt the prior to interactive tool use.

The feedback contract is deliberately sparse. A BugFixer rollout earns one only when all available ground-truth unit tests pass. A TestWriter rollout earns one only when its test fails on the buggy revision and passes after the ground-truth fix. The method does not add format or process rewards, so selection pressure comes from the task tests plus the sampling and curriculum rules.

This bridge is the paper's strongest construction claim. Under its reported comparison, an RL-trained prior reaches the base model's best agent pass@1 with \(2^{23}\) agent-SFT tokens, versus \(1.5\times2^{28}\) for the base model. That result is conditional on the paper's task suite, trajectory source, adaptation implementation, and evaluation protocol; it is not a general sample-efficiency guarantee.
