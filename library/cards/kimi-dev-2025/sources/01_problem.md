Kimi-Dev asks whether repository patching skill can be learned in a compact Agentless setting and then transferred into a longer-horizon software-engineering agent. The central data object is not merely a benchmark prompt: it is a repository issue anchored to a base revision, a patch or generated test, optional localization/tool traces, execution results from a task environment, and a binary verifier outcome.

The report combines several distinct supervision regimes. Mid-training uses GitHub pull-request diffs, commit packs, teacher-generated localization reasoning, and simulated file-tool interactions. Cold-start SFT teaches BugFixer and TestWriter behavior. RL then executes outputs against repository tests in Docker. A separate public-trajectory study measures whether this patch-centered skill prior reduces the amount of agent SFT needed.

This Card treats those regimes separately. Simulated observations teach repository-reading patterns but do not constitute an executable environment. The later Docker task pool supplies environment-grounded feedback, while the released evaluation harness and JSONL outputs are evidence artifacts rather than the full training environment or training corpus.
