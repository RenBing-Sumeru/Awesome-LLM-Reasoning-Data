Repository and test leakage remain incompletely controlled. Mid-training excludes repositories said to overlap SWE-bench, but the release provides no exclusion manifest, normalization rule, fork or mirror treatment, semantic-clone search, or audit of Qwen2.5 base-model exposure. Cold-start, RL, teacher outputs, public benchmark use, and checkpoint selection can introduce additional task knowledge that repository-name filtering does not cover.

Environment identity is insufficient for replay. A repository task depends on an exact base commit, dependency resolution, image digest, toolchain, test selection, timeout, network, filesystem reset, cache, retry, and flaky-test policy. The internal platform reports impressive capacity, but the open repository does not include the proprietary image builder, the paper-run image/task manifest, locked revisions for all 9,873 tasks, or reproducible Docker artifacts.

The available full test suite is a useful binary verifier, not a proof of semantic correctness. Tests may be incomplete, overly specific, flaky, or exploitable; infrastructure failures may be confused with model failures. TestWriter's fail-before/pass-after rule is stronger than unconditional test generation, but generated tests can still overfit the ground-truth patch. The paper does not release exploit checks, flaky reruns, timeout handling, or per-test reward records.

Split and lineage evidence is partial. Exact train/validation/evaluation task IDs and repository revisions are absent. The paper reports 5,016 public SWE-smith Claude 3.7 Sonnet trajectories, whereas the currently mutable public dataset has a different row count; the immutable dataset revision, selected row IDs, nested-subset shuffle seed, preprocessing, and exact license snapshot for the paper run are unknown.

Selection can distort the training distribution. The initial RL pool excludes pass@16-zero tasks, later reintroduces only tasks that become solvable, and late training replays recent positives. The total iteration count, total rollout count, failure archive, negative sampling, infrastructure-error retention, and whether failed trajectories remain available for audit are undisclosed.

Release labels do not settle source rights. MIT terms on the code, weights, and public trajectory release do not relicense GitHub issues, PR discussions, commits, repository tests, dependencies, or teacher outputs. Removing signatures and GitHub identifiers may reduce privacy exposure, but it also weakens attribution, source-level license review, takedown handling, and end-to-end provenance.
