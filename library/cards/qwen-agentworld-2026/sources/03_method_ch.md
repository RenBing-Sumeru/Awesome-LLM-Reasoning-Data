论文列出三条轨迹渠道。专用基础设施让合成任务在容器、MCP、终端、Android、浏览器和桌面后端中执行；公开交互轨迹包括终端录制、智能体工具调用日志和代码仓库执行轨迹，并经过多智能体清洗流水线；内部基础模型的 SFT 智能体轨迹构成第三条渠道。CPT 还加入工业控制、网络安全、法律、医疗、金融、时事和百科知识等专业语料。论文称 CPT、SFT 与 RL 数据池严格互斥，但没有发布成员清单。

所有记录都被规范化为同一动作—观测格式。过滤会删除少于两个 turn 的轨迹、调用未声明工具的 MCP/SWE 轨迹、故障 GUI 状态、空动作、重试循环，以及 GUI 状态不变的 turn。CPT 还依据词元重叠度、新颖度、Jaccard 和长度比，对低信息观测词元进行 loss masking，同时把被 mask 的 turn 保留为后续上下文。训练时，每条轨迹随机选择一个目标 turn。

SFT 从 AutoResearch 生成的十个模板 v2-v11 中抽取一个，截断超过 256K token 的输入，再由未具名推理模型生成三个候选。独立裁判选出最佳候选，若未达到未公开阈值则丢弃；10,250 个候选查询最终保留 7,094 条。报告中的 RL 训练池含 92,308 条轨迹，每条只贡献一个目标 turn，并过滤历史超过 128K token 的记录；GSPO 接收异步 rubric 分数，以及在可用处接收二元规则奖励。解码设置、RL rollout 数、裁判身份、分数校准、规则验证覆盖率、优化超参数和训练记录本身均未披露。
