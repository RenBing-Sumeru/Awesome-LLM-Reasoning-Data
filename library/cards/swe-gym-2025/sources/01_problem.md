The authoritative publication is the [PMLR record](https://proceedings.mlr.press/v267/pan25g.html) and its 21-page final paper, published in Proceedings of the 42nd International Conference on Machine Learning, PMLR volume 267, in 2025. Repository-level software-engineering agents need more than issue text and a gold patch. Training requires a reproducible code snapshot, dependencies, an action interface, executable tests, and a success signal that can label complete interaction trajectories. SWE-Gym builds this substrate from real GitHub issues and pull requests.

The validated release contains 2,438 Python tasks from 11 repositories. Each task binds a natural-language issue to repo, base commit, version, human patch/test patch, and PASS_TO_PASS/FAIL_TO_PASS tests. This turns an issue into an environment-backed data object suitable for agent SFT, outcome-verifier training, and verifier-guided test-time selection.

The release is a family of separate objects, not one corpus: tasks, a Lite subset, Raw candidates, success-only SFT conversations, success/failure rollouts, verifier mixtures, Moatless data, models, forks, and Docker images. Their schemas, licenses, IDs, and revisions differ, so claims about openness must be made per artifact.

SWE-Gym belongs in Data Construction and Open Release Recipes because it covers the lifecycle from issue/PR extraction through semi-manual executable-environment setup, gold-patch test validation, trajectory sampling, success/failure filtering, SFT, outcome-verifier learning, Best@k selection, and multi-artifact release. It is not merely a repository-agent benchmark or a model leaderboard: the Atlas decision centers the construction and packaging contracts. No second category is needed for this Card.

The L4 evidence boundary is based on the venue-final paper plus inspected official code, task datasets, trajectory releases, model organization, environment/agent forks, and Docker surface. L4 does not certify safe reuse. The 64,689-to-2,438 rejection ledger, task-to-image digest/SBOM manifest, stable rollout-to-SFT/verifier lineage, several component licenses, semantic contamination audits, and count reconciliation remain unavailable.
