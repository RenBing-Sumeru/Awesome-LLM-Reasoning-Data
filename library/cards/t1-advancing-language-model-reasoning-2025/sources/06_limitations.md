The final-answer reward creates both false positives and false negatives: a completion may reach the right label through invalid reasoning, while a valid equivalent form may be rejected by an undisclosed parser. The paper's -1 penalty for repetition, excessive length, mixed language, or garbled characters can improve the reported run, but its rule and perplexity thresholds are not released; this creates a verifier-gaming and unfair-rejection risk outside the authors' setting. (Paper §3.2; Table 3.)

The synthesized chains are also not transparent process annotations. Their constituent attempts, critiques, verifier prompts, teacher identities, and merge decisions are unavailable, so hidden teacher habits and mistaken critiques cannot be audited row by row. The selection rule discards easy questions and keeps a narrow 16-sample pass-rate band, but the release does not preserve all rejected attempts or filter explanations. This can change difficulty, style, and error distributions in ways a downstream trainer cannot measure.

Artifact limitations are material. The dataset viewer reports a schema-cast error because the released files use incompatible columns. The checked README calls model weights and RL training data “coming soon,” yet the dataset revision contains `rl-data.jsonl`; the file name does not settle what was released. Dataset license, upstream rights, row-level provenance, benchmark-overlap analysis, executable training code, and a full configuration are unknown. Benchmark improvement should therefore not be read as proof of release quality or clean evaluation separation.
