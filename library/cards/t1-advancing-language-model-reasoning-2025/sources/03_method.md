Inputs → construction → feedback → selection → use are as follows. Start with MATH-train and NuminaMath. For each SFT question, collect multiple answers from unspecified LLMs; compare each with the label; request a critique of an incorrect answer or verification of a correct one; merge the problem, attempts, and feedback into one chain; rewrite mere enumeration into a trial-and-error abstraction. The authors filter noisy/inaccurate labels and easy problems. For RL-prompt selection they sample 16 answers and retain questions with pass rate strictly between 0 and 0.3, yielding the reported 30k prompt pool. (Appendix A.)

For RL, sample K=64 responses per retained prompt at high temperature. Give final-answer correctness reward 1/0, apply -1 to selected bad responses, normalize rewards with leave-one-out RLOO, add entropy, and use a KL term normalized across rollouts against an EMA reference policy. Updates are reported every 32 prompts. SFT uses three epochs, 1e-5 learning rate, and cosine scheduling; RL reports 1.5e-6 and KL coefficient 2e-4. Maximum generation length is 10,240 for GLM-4-9B/Qwen2.5-14B and 16,384 for Qwen2.5-32B. (Appendix B.)

The declared uses are SFT, RL with verifiable outcomes, and inference-budget analysis. Evaluation uses greedy Pass@1 on MATH500, AIME 2024 (32 runs averaged for each model), Omni-MATH, and GPQA. To reproduce the method, a user would additionally need the unnamed teacher models, prompts, answer parser, bad-response rule/perplexity thresholds, exact seeds/decoding, optimizer/runtime configuration, and a mapping from released rows to construction and experiment stages. The checked GitHub repository supplies a README/LICENSE rather than this complete executable scaffold.
