对 `data_construction_open_release_recipes` 而言,OpenMMReasoner 最适合作为一个完整案例,用来观察同一公开项目如何打包推理数据生命周期的不同阶段。读者可以把来源问题、教师轨迹、保留的 SFT 对话、RL 任务规范、在线策略回答、终局奖励、优化器更新与最终检查点逐层映射,而不把它们压缩成一个"数据集"。

SFT 发布可用于混合比例分析、格式研究、替代采样/过滤实验与冷启动复现。RL 发布可用于 prompt 池分析、奖励 parser 审计、替代去重、课程设计和在线 GSPO 重建。两个检查点则支持 base、cold-start 与 RL 阶段的受控比较。在确认生成策略、rollout 数、采样配置与 seed 前,复用者不应把 `avg_reward` 当作可迁移质量标签。

可审计重建至少应保留三份 ledger。来源 ledger 记录上游数据集与 row ID、图像来源、许可证、split 和去重近邻。SFT 决策 ledger 记录教师版本、渲染输入、采样序号与 seed、完整候选回答、规则结果、学习式裁判请求与结果、保留/拒绝状态及原因。RL ledger 记录 prompt 版本、当前策略 checkpoint、全部 16 条回答、抽取答案、正确性与格式分量、裁判回退、组统计、GSPO update,以及 overlength 或零方差过滤。

该配方还可支持本轨道关心的受控问题:匹配算力后答案多样性是否仍有收益;不做过滤的 SFT 在独立过程检查下是否稳健;图像/文本去重如何改变来源比例;学习式裁判何时与规则分歧;匹配采样 token 后 8 与 16 条 rollout 是否仍改变稳定性。这些研究必须重建缺失谱系,而不能把 benchmark 表格当作数据质量证书。
