The construction can be audited as five stages.

1. **Source and teacher study.** The SFT pipeline begins with approximately 103K question-answer pairs from LLaVA-CoT, OpenVLThinker, and WeMath2.0. Candidate teacher traces undergo format checking and final-answer verification. The paper reports that Qwen3-VL-235B-Instruct performs best among the tested teachers and that the one-sample stage retains about 59K traces. The exact endpoint revision, generation seed, and item-level verification ledger are unknown.
2. **SFT scaling and mixing.** The selected teacher produces up to eight verified answers per question, yielding about 583K general-reasoning traces. Experiments with length and difficulty filtering reduce the reported downstream average, so the final recipe keeps this general set without those filters. Adding MMR1 image-math and MiroMind-M1 text-math data yields 874K rows. LMMs-Engine trains Qwen2.5-VL-7B-Instruct with online packing, a 61,440-token packing length, AdamW, cosine scheduling, learning rate 5e-5, and 4,300 reported steps.
3. **RL prompt preparation.** The paper names MMEureka, ViRL, TQA, We-Math, PuzzleVQA, AlgoPuzzleVQA, and ThinkLiteVL as source families. It extracts and verifies final answers, then removes similar questions using image and text embeddings. The public deduplication implementation performs cross-source nearest-neighbor removal and defaults to a 0.99 threshold, but the exact paper-run threshold and removed IDs are unknown.
4. **Online generation and reward.** The final released example starts from `OpenMMReasoner-ColdStart`, samples 16 responses per prompt at temperature 1.0, caps prompts at 4,096 tokens and responses at 28,696 tokens, and trains with global batch size 128. Accuracy first uses answer extraction, multiple-choice or relaxed exact matching, and `math_verify`; if these fail and learned judging is enabled, the code queries a separately served judge. Format compliance contributes 0.1 and answer correctness 0.9. The 16 response texts, extracted answers, judge calls, and per-response rewards are transient training objects and are not in RL-74K.
5. **GSPO optimization and evaluation.** verl and vLLM provide the online environment; the chosen launch uses GSPO, 1,232 paper-reported RL steps, constant learning-rate scheduling at 1e-6, weight decay 0.1, and an overlength strategy. The paper compares GSPO, GRPO, and DAPO and uses 16 rollouts in the selected configuration. Evaluation separately applies a rule-first, learned-judge-second answer procedure; its temperature and generation budget are not the RL sampling settings.

The repository is a runnable scaffold rather than an immutable experiment package. Paths and service addresses require editing, no GitHub release pins the paper state, and the live Hub schema does not exactly match the eight training files listed by the launch script. Reproduction therefore requires recording commit, dataset revisions, model revisions, judge endpoint, all environment variables, and generated rollout logs.
