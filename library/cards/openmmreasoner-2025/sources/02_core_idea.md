The contribution is a linked but non-uniform two-stage recipe. On the SFT side, the paper starts from about 103K public questions, selects Qwen3-VL-235B-Instruct as the teacher, retains candidates after format and final-answer verification, scales answer diversity up to eight samples per question, and reports about 583K verified general-reasoning traces. Mixing MMR1 image-math and MiroMind-M1 text-math data produces the final 874K cold-start mixture.

The released SFT object has five configurations: OpenVLThinker-sft-iter3 (22.2K), WeMath (6.94K), llava_cot (554K), m1_sft (92K), and mmr1 (199K). Each row is essentially `id` plus `messages`; the messages contain an instruction, a multimodal or textual user request, and an assistant response using think and answer tags. The row does not carry the teacher revision, sampling index, validator decisions, rejected candidates, or upstream license lineage.

On the RL side, the paper sources questions from multimodal science, mathematics, charts, and puzzles, verifies extractable answers, and deduplicates questions by image and text similarity. The released train row is a task specification, not a completed trajectory: core fields are `prompt`, `images`, `data_source`, `ability`, `reward_model.ground_truth`, `reward_model.style`, `tokens`, and `avg_reward`, with additional source-specific columns. During training, the current policy then samples 16 new responses for a prompt and receives terminal rewards.

The feedback chain has three separate layers. First, the release supplies a ground-truth-oriented reward specification. Second, the code tries rule matching and `math_verify`, then optionally falls back to the default Qwen3-235B-A22B-Instruct-2507 judge. Third, answer accuracy is mixed with format compliance as `0.9 * R_acc + 0.1 * R_fmt`. None of these layers is a direct label of local step validity.
