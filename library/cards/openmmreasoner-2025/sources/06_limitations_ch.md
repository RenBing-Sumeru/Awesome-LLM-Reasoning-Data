- **发布组成存在歧义。** 实时 RL collection 只有在把 1,724 行 validation 配置与约 7.3 万行训练记录相加后才达到约 7.47 万。论文与启动脚本提到 8 个训练文件并包含 PuzzleVQA,但所检查的 collection 没有公开 PuzzleVQA train 配置。论文运行到 Hub 的精确映射为 unknown。
- **rollout 未发布。** GSPO 在线采样 16 条回答,补充材料也称曾记录 rollout 日志用于分析;但 RL-74K 保存的是 prompt 与元数据,而非这些回答。回答文本、rollout ID、抽取答案、规则结果、学习式裁判调用、组统计、被拒回答和 update-step 连接均不可用。
- **`tokens` 与 `avg_reward` 文档不足。** 训练 schema 暴露这两个字段,但官方数据页没有说明生成它们的精确模型版本、rollout 数、解码设置、seed 或运行。validation 有 `tokens` 却没有 `avg_reward`,因此这些字段在论文运行中的确切含义为 unknown。
- **SFT 验证尚未完全操作化。** 论文称采用严格逐步验证,但方法部分具体说明的是格式验证,以及规则与学习式裁判执行的最终答案检查。公开 SFT 行没有步骤标签、验证轨迹、置信度、教师版本、采样序号或被拒替代。
- **验证器错误会传播。** 宽松匹配与 parser 可能错误处理等价形式,`math_verify` 只覆盖受支持表达式,回退裁判还会受模型版本和评估指令影响。公开材料没有给出校准集、重复判定一致率、假阳性/假阴性分析或逐来源错误率。
- **终局奖励不等于推理真实。** 选定奖励由 90% 答案正确性与 10% 格式遵循组成。正确最终答案可能来自错误或缺乏视觉依据的推理,有效路径也可能因答案抽取或格式问题受罚;没有过程有效性监督弥补这一缺口。
- **选择会改变观测分布。** SFT 保留通过验证的候选,随后不采用所测长度/难度过滤;RL 验证答案并移除相似问题。缺少接受/拒绝计数和 row ID 时,无法审计逐来源存活率、答案多样性、去重不对称性和失败覆盖。
- **去污染与权利信息不完整。** 没有公开 ledger 对合并后的 SFT/RL 来源执行完整精确、近重复或语义级训练-评估重叠检查。代码为 Apache-2.0,RL-74K 为 CC-BY-NC-4.0,但 SFT-874K 没有顶层许可证,逐记录上游文本、图像与教师输出权利均为 unknown。
- **复现对象持续变化。** 检查时仓库没有正式 release。启动文件包含本地路径与服务 endpoint,而模型、数据、代码和裁判仓库可独立更新;硬件小时数、随机 seed 与 checksum 均为 unknown。
- **外部有效性较窄。** 实验只使用一个 Qwen2.5-VL-Instruct 系列,并主要围绕图像任务。视频、音频、更丰富时序输入、其他架构系列以及进一步扩大 SFT/RL 后的上限均未建立。

Benchmark 收益是下游模型证据,不能认证 rationale 忠实性、来源干净程度、奖励校准、许可安全或发布完整质量。
