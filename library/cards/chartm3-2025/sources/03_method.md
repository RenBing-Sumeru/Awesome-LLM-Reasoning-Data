The reconstructable pipeline is:

1. **Build a template database.** Derive a 9-major/62-minor taxonomy from Matplotlib, Vega, EChart, and Seaborn. Claude 3.5 generates structured data/code templates and recreates styles from collected finance, scientific, and other real-world charts. Templates receive domain, theme, purpose, definition, scenario, and data-characteristic tags, with manual refinement. Source URLs, per-template provenance, and rights records are unknown.
2. **Generate data and charts.** Author key questions over 60 domains, then use RAG to select a representative chart type/template. An LLM writes contextual narrative and Python data-generation code containing trends, stochastic functions, controlled noise, and optional outliers; execution produces CSV rather than accepting a directly generated table. Another LLM pass analyzes visualization requirements, randomizes style guidance, and writes `preprocess`/`plot` functions. Rendering failures return code and error messages for iterative repair. Generator identities, sandbox/library versions, timeout, maximum retries, and random seeds are unknown.
3. **Generate questions, programs, rationales, and answers.** Qwen2.5-VL-72B is used to formulate questions from visible chart information. For computation-heavy tasks, a two-pass prompt first generates the question and analytical Python code from chart code/source data, then executes that program. The next prompt tells the model to trust the code output, write a step-by-step explanation as if derived from the chart, and avoid mentioning code. This produces a useful executable lineage but risks rationales that depend on privileged source values rather than legible pixels.
4. **Filter and refine.** Remove malformed outputs and execution failures. Train a Qwen2-VL-2B chart-quality classifier from 700 positive and 500 negative examples after correcting model prelabels. Use multimodal judges for chart relevance, data accuracy, and logical consistency. Estimate difficulty as the number of failures across ten high-temperature small-model attempts and remove overly easy items. For the benchmark, rebalance difficulty, manually verify/correct items, tune the judge prompt, and delete cases with inconsistent judgments. A roughly 5,800-item audit by Claude 3.5 with human/Claude dual checking of initially incorrect cases finds 508 requiring modification or removal and reports 91.24% instruction accuracy.
5. **Train with distinct targets.** Full CoT-SFT freezes the vision encoder and trains for two epochs at learning rate 1e-5 and batch size 64. The 30K GRPO set samples difficulty 3--9 and contains 6,958 true/false, 6,734 multiple-choice, 2,657 short-answer, and 13,651 fill-in items. GRPO uses seven rollouts per prompt, a global batch of seven prompts, learning rate 1e-6, KL coefficient 0.04, k2 KL approximation, and eight A100 80GB GPUs. Binary format reward checks the required think/answer tags; answer reward is exact match for closed forms and Qwen3-32B judgment for open forms. The supplied CoT is not rewarded.
