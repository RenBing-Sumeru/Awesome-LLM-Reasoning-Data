Chart-reasoning data must keep five views mutually consistent: the chart pixels, underlying table, analytical computation, question, and final answer. A Python program can execute successfully while the chart remains occluded or misleading; a calculation can be correct over source data while depending on values that a vision-only solver cannot read. Natural-language rationales add another boundary because fluent steps may be written after the numerical result is already known.

ChartM3 addresses this construction problem with a staged pipeline that produces data code, rendering code, chart images, analysis code, multi-step explanations, and answers, followed by execution, learned-model, and human checks. It reports both SFT and RLVR uses. The feedback contract is therefore mixed rather than fully programmatic, and no author-confirmed code or dataset artifact was verified. This Card treats the paper as a detailed construction blueprint, not as an independently inspectable release.
