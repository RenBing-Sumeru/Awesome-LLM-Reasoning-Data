Inputs are a query set S, a total generation budget B, a response generator, a reward oracle r, a per-round batch size K, and an elimination threshold gamma. Each round generates K new responses for every active query, scores them, preserves all responses and the best-so-far candidate, and removes a query whose best new score reaches gamma. The run stops when B is exhausted or the active set is empty. Coverage asks whether any retained response is correct; accuracy asks whether the selected best response is correct. The default cost unit is one complete generation, while an extension accounts for token budgets.

The paper instantiates selection and stopping differently by benchmark. MATH-500 combines learned PRM, LLM-judge, and ground-truth variants; AIME25 uses answer self-consistency; LiveCodeBench uses execution correctness. Experiments use Llama-3.2-1B-Instruct, Llama-3.1-8B-Instruct, DeepSeek-R1-Distill-Llama-8B, Qwen3-4B, and Gemini-2.5-Flash-Lite. Reported average budgets are 4, 8, 16, and 32 generations, except smaller Gemini budgets; generation temperature is 0.6, results are averaged over four random runs, and Qwen3-4B uses a 38,912-token maximum. The two-stage baseline searches stage-one ratios of 25%, 50%, and 75% and reports the best.

A reproducible trace should retain prompt version, model and sampler configuration, every response, raw and normalized oracle result, oracle identity, answer equivalence rule, K, gamma, max-sample cap, active-set updates, token counts, random seed, and final selection. No official code, allocation-history dataset, or versioned experiment log is linked in the accepted metadata, so executable fidelity, exact seeds, release license, and trace completeness remain unknown.
