The contribution is a pure-exploration-style bandit formulation in which each query is an arm and one pull generates one additional response. The base Elimination algorithm maintains an active query set and, in rounds, samples K responses for every active query. It updates the best observed response and removes a query when its oracle score reaches a threshold gamma. Unspent budget is thereby transferred from queries considered solved to queries that still appear uncertain. Outputs are the response set for coverage evaluation and the best-scoring response for accuracy evaluation.

The feedback contract is mixed and task-specific. The paper uses Qwen2.5-Math-PRM-7B for Llama-family MATH-500 runs, Gemini-3.0-Flash as an LLM judge for Gemini-2.5-Flash-Lite, self-consistency for AIME25, and executable ground truth for LiveCodeBench; it also reports ground-truth-oracle analyses when available. Self-consistency eliminates a query after sufficient answer agreement rather than after a learned score. UCB, gap-based, and entropy exploration variants change which unresolved queries receive samples, and a per-query cap limits overspending.

Relative to uniform Best-of-N and two-stage explore-then-commit allocation, the main change is fully adaptive redistribution across queries without training an auxiliary allocator. The category fit is Rollout, Search, and Test-Time Trace Data because allocation decisions, oracle outputs, eliminated queries, and budgets are first-class records; final benchmark answers alone cannot reconstruct them.
