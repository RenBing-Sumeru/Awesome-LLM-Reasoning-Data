The closest baseline is WebArena, which supplies the self-hosted websites, task representation, and evaluator family. The authors re-examine 229 of 684 non-map WebArena tasks failed by all three BrowserGym agents and report that 134/229 (58.5%, or 20.0% of all 684) contain annotation errors or evaluation issues: 75 annotation errors and 59 evaluation issues. This audit motivates clearer instructions and evaluators as agent capability rises, but it is an analysis of WebArena rather than proof that WebChoreArena has zero defects.

WebChoreArena changes the task distribution and authoring target. It adds 532 newly curated chores centered on massive memory, calculation, and long-term memory; declares text/image requirements; standardizes answer formats where exact matching is used; and repeatedly tests and cross-checks tasks. The 65 cross-site tasks and 50-step execution budget make retained state and constraint tracking first-class evaluation variables rather than incidental navigation burden.

The work does not introduce the underlying websites, BrowserGym, AgentOccam, exact/must-include matching, URL checks, DOM inspection, or GPT-based fuzzy judgment. It also does not contribute a training objective, selected demonstration set, or released policy-rollout corpus. Its direction signal for reasoning-data research is therefore a more explicit environment task and terminal-feedback interface, not a new post-training recipe.

Before reuse, an evaluator should verify the fixed task JSON, reconcile the README schema with the actual records, pin the upstream environment and model APIs, inspect alternative-valid-answer behavior, preserve task order and reset semantics, and retain crashes and failed episodes. Without those checks, improved scores may reflect version drift, retries, or verifier behavior rather than stronger long-horizon reasoning.
