核心构造是在单个完整 ReAct 交互步骤的粒度上进行共享前缀树采样。对于每个提示，策略先生成 \(M\) 条相互独立的完整链。随后在每棵树中随机选择 \(N\) 个非答案节点，复用从根到该节点的前缀，并生成一个新后缀直至另一个终点叶子；该扩展过程重复 \(L\) 轮。完成轨迹的数量为

\[
M(LN+1).
\]

在默认 \(M=2\)、\(N=2\)、\(L=1\) 时，forest 包含两个独立根，每棵树有三个完成叶子，总计六个叶子。由于新增的四个叶子复用了已经生成的前缀，预期 token/工具调用开销约等于四条完全独立轨迹，而不是六条。这是论文关于数据效率的核心命题：名义上包含六个完整回答的分组并不等价于六个独立样本，因为它们的 ancestry 与边际生成成本不同。

公开实现还有参数 \(K\)，控制每棵树返回多少个叶子。manager 对 \(K\) 个叶子采样，在内存中剪掉未选叶子或子树，打包所选完整响应，随后删除整棵树。默认脚本使用 \(K=3\)，因此默认配置下每棵树生成的三个叶子都会被选择。不过，在更大或非默认树中，一部分叶子可能被丢弃；公开发布既没有 retained/rejected manifest，也没有被删除的树拓扑。

反馈是终点层面的程序化规则。单跳与多跳 QA 使用归一化 exact match，web-agent QA 使用归一化 answer-token F1，无效结构会受到 0.2 的格式惩罚。Tree-GRPO 先在每棵树内对所选叶子的结果归一化，再在同一提示的全部树之间归一化，最后把树内与树间分量相加，作为策略学习的 advantage/return。树内分量比较共享前缀的续写，因此可作为由结果派生的局部偏好信号；树间分量比较独立根树，并在小树内部奖励变化不足时提供更宽的基线。

这一机制属于隐式过程监督，不是显式过程标签发布。论文在二值结果假设下证明，树内 GRPO 与 step-level DPO 的梯度方向一致，但权重不同。该理论分析不表示系统实际生成或发布了 step-DPO pair、分支点标签或逐节点奖励；对于使用连续 F1 的 web-agent 训练，它也只是分析层面的简化。
