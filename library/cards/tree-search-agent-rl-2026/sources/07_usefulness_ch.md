对于 **Rollout, Search, and Test-Time Trace Data**，Tree-GRPO 提供了一个具体配方，用于研究 rollout 拓扑如何改变固定训练预算所能产生的监督数量与粒度。后续对照研究可以固定提示池、当前策略、终点奖励和预期 token/工具预算，再改变 \(M\)、\(N\)、\(L\)、\(K\)、扩展节点采样方式，以及是否合并树内与树间 advantage。

有证据支持的用途包括：

- 为在线 RLVR 或 agent training 实现共享前缀 ReAct rollout，并在生成 token、工具调用和墙钟预算匹配时与独立 chain sampling 比较；
- 把完整 thought-action-observation 交互作为候选过程单元，再检验结果派生的分支比较是否与显式步骤标注或因果干预一致；
- 审计树内与树间归一化的贡献，包括小树方差、全同奖励组与训练崩溃条件；
- 测量名义叶子数、独立根数、边际后缀生成数、所选叶子数和真正不同轨迹数之间的差异；
- 构建包含稳定 prompt/tree/node ID、父子链接、扩展选择、全部所选和被拒绝叶子、程序化评分细节、分组统计、advantage、策略版本与 checkpoint 链接的发布格式；
- 在固定 Wikipedia/E5 与 web-search 快照下测试重放，而不是把实时检索当作静态环境。

适当的复用等级是：**强构造与审计参考；有条件的实现/复现；直接训练数据复用不可用**。官方代码可在 Apache-2.0 许可下指导新实现，但论文运行轨迹、processed QA bundle、所选/被拒绝叶子、奖励 ledger 与环境快照均未发布。上游数据集、检索观察和生成轨迹的权利也仍为 unknown。

本 Card 还能提示评估设计中的常见错误。默认六叶配置应与预期生成成本约等于四条独立轨迹的设置比较，而不能把它当成 ancestry 无关的六条独立链。研究应分别报告实际 token、工具调用、不同根、扩展后缀、所选/未选叶子、奖励方差和墙钟成本。

它也可作为本 track 的发布清单。只有当运行时拓扑、反馈决定、拒绝边界、环境状态和谱系在优化器更新后仍被保留，树搜索论文才能转化为可审计推理数据。Benchmark EM/F1 提升本身不能证明这些缺失对象可复用、已授权、已去污染或质量高。
