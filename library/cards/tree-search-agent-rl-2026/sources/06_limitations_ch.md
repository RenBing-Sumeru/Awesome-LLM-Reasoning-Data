**核心轨迹对象未发布。** 实现构造带稳定运行时 ID 的父子树，但返回的是所选完整响应、mask、分数/统计与 `tree_uid`，而不是序列化完整拓扑。打包后树会被删除。官方没有发布原始树、论文运行所选轨迹、全部分支、扩展选择、被拒绝/剪枝叶子、节点 ancestry 或分支点比较的语料。

**选择与奖励谱系不完整。** 默认 \(M=2,N=2,L=1,K=3\) 会保留每棵树的全部三个叶子，但非默认配置可以只采样 \(K\) 个叶子并剪掉其余部分。没有 retention manifest 说明哪条轨迹被选择、未选择、判为无效、剪枝或失败。逐叶 EM/F1/格式结果、树内与树间归一化组、最终 advantage、策略版本、优化器更新与 checkpoint 没有在公开记录级 ledger 中连通。

**结果验证范围窄。** Exact match、answer-token F1 与格式检查不能验证检索 grounding、来源归因、中间逻辑有效性或事实稳健性。错误路径可能因终点字符串正确而得到奖励；有效路径也可能因归一化或提取失败被惩罚。结果派生的信用可能被分配给较早分支，尽管真正决定结果的是后续推理、检索噪声或下游动作。step-DPO 分析假设二值结果，而 web-agent 训练使用连续 F1。

**环境不可重放。** 本地 QA 依赖 Wikipedia-2018 上的 E5 索引；web QA 依赖 Bing/web-search 响应。精确语料与索引哈希、检索构建、查询/响应日志、cache、endpoint 版本和论文运行环境快照均未提供。因此，名义上相同的动作可能得到不同观察，最终也会得到不同奖励。

**效率与探索存在权衡。** 共享前缀降低边际生成成本，但也让叶子相关。过小的 \(M\)、通过 \(N\) 或 \(L\) 进行过多扩展，或者任务深度太浅，都可能减少独立探索并使结果下降。树内叶子很少时，树内基线方差较高，可能促成训练崩溃；树间项能够缓解，但不能消除该风险。
