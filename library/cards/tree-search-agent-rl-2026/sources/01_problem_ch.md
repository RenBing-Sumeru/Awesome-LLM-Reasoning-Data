仅依赖结果奖励的 agent 训练存在信用分配问题。搜索 agent 在给出答案前可能执行多个完整 ReAct 步骤，每一步都包含 thought、文本搜索动作和检索观察，但 exact match 或 F1 奖励只在叶节点产生。普通 GRPO 会针对同一提示独立采样多条完整链；每条链分别消耗完整的 token 与工具调用预算，终点层面的组内比较也无法直接指出：哪一个共享的较早决策把成功续写与失败续写区分开来。

Tree-GRPO 研究能否通过改变 rollout 对象的结构，在不另行训练 process reward model 的情况下，让结果反馈提供更局部的训练信号。它构造以提示为条件的 forest，树中每个节点都是完整的 thought-action-observation agent step。每棵树先由当前策略生成一条完整轨迹，再把选中的非答案节点作为共享前缀，从这些前缀继续生成新后缀。完成的叶子带有终点答案和程序化结果分数；树成员关系使优化器既能在单棵树内比较相关叶子，也能比较同一提示下产生的全部叶子。

内存中的数据对象比答案列表更丰富。它包括提示与目标答案、`tree_uid` 与 `node_uid`、父子指针、深度、共享前缀、生成响应、information/turn mask、有效动作与搜索统计、终点 EM/F1 加格式分数，以及树内/树间相对优势。其谱系为：来源 QA 记录 → 预处理提示与 ground truth → 当前策略 ReAct forest → 检索观察 → 完成叶子 → 程序化结果 → 树相对优势 → Tree-GRPO 更新。

该工作属于 **Rollout, Search, and Test-Time Trace Data** 的核心案例，尽管这里的搜索发生在在线训练阶段，而不是测试时推理阶段。树拓扑、前缀复用、扩展决定、叶子保留和 rollout 预算共同决定哪些轨迹进入策略更新，以及它们携带什么监督。公开 artifact 的边界尤其关键：官方仓库发布了构造与训练代码，但没有核验到包含所选轨迹、原始树、全部分支、被拒绝叶子、逐记录奖励/优势或可重放环境状态的官方数据集。

因此，本 Card 是 L4 双语配方与审计记录，不表示 Tree-GRPO 已发布可复用的推理轨迹语料。引文、venue、论文、代码和实现行为已经核验；状态仍为 `partial`，因为核心运行时对象在使用后被删除而非发布，记录级 provenance 与复用权利也尚未解决。
