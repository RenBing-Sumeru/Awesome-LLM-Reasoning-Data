Outcome-reward agent training has a credit-assignment problem. A search agent may take several complete ReAct steps—each combining a thought, textual search action, and retrieved observation—before producing an answer, yet an exact-match or F1 reward arrives only at the leaf. Ordinary GRPO groups independently sampled full chains for one prompt. Those chains consume their complete token and tool-call budgets separately, and a terminal group comparison does not expose which shared earlier decision separated a successful continuation from a failed one.

Tree-GRPO asks whether the rollout object can be structured so that outcome feedback supplies a more local training signal without a separately trained process reward model. It generates a prompt-conditioned forest whose nodes are complete thought-action-observation agent steps. Each tree begins as a full current-policy trajectory, then selected non-answer nodes become shared prefixes from which new suffixes are generated. Completed leaves carry terminal answers and programmatic outcome scores; tree membership allows the optimizer to compare related leaves within a tree as well as all leaves produced for the prompt.

The in-memory data object is richer than a list of answers. It includes the prompt and target, `tree_uid` and `node_uid`, parent-child pointers, depth, shared prefixes, generated responses, information and turn masks, validity/search statistics, terminal EM/F1-plus-format scores, and intra-tree/inter-tree relative advantages. The lineage is: source QA row → processed prompt and ground truth → current-policy ReAct forest → retrieval observations → completed leaves → programmatic outcome → tree-relative advantages → Tree-GRPO update.

This is a core case for **Rollout, Search, and Test-Time Trace Data**, even though the search occurs during online training rather than test-time inference. The topology, prefix reuse, expansion decisions, leaf retention, and rollout budget determine which traces enter the policy update and what supervision they carry. The public artifact boundary is crucial: the official repository releases construction and training code, but no official dataset of selected trajectories, raw trees, all branches, rejected leaves, per-record rewards/advantages, or replayable environment states was verified.

The Card is therefore an L4 bilingual recipe-and-audit record, not a claim that Tree-GRPO released a reusable reasoning-trace corpus. Citation, venue, paper, code, and implementation behavior are verified; status remains `partial` because the central runtime object is deleted rather than published, and its record-level provenance and reuse rights remain unresolved.
