- 应把第 3.1 节与算法 1 连起来读：\(M\) 个独立根加上每轮 \(N\) 次扩展、共 \(L\) 轮，得到 \(M(LN+1)\) 个叶子；默认 \(2,2,1\) 表示六个叶子，预期成本约等于四条独立完整轨迹。
- 必须把 \(K\) 与构造公式分开追踪。默认 \(K=3\) 保留每棵默认树的全部三个叶子，但通用实现可以剪掉未选叶子并删除树；公开发布没有留下 retained/rejected manifest。
- 应追踪完整反馈路径：本地 QA 使用 EM，web-agent QA 使用连续 F1，结构不合法受到 0.2 惩罚，所选结果再转化为树内与树间 advantage 之和。这些是结果派生信号，不是已发布的步骤标签。
- 阅读 benchmark 与消融表时要同时查看失败证据：论文设置中 agent-step 分支优于 token/sentence 分支，但小树方差、探索损失、过早坚持路径和训练崩溃仍可能发生。
- 复用前应要求原始树与全部分支、逐叶 reward/advantage ledger、不可变 split ID、论文运行检索快照、完整解码与预算日志、去污染、上游/衍生数据权利和机构核验。代码可见与 benchmark 提升不能替代这些记录。
