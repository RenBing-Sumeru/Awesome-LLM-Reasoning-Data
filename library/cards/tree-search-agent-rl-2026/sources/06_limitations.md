**The central trace object is not released.** The implementation constructs parent/child trees with stable runtime IDs, but returns selected full responses, masks, scores/statistics, and `tree_uid` rather than serializing the complete topology. After packing, the tree is deleted. There is no official corpus of raw trees, selected paper-run trajectories, all branches, expansion choices, rejected/pruned leaves, node ancestry, or branch-point comparisons.

**Selection and reward lineage are incomplete.** Default \(M=2,N=2,L=1,K=3\) retains all three leaves per tree, but non-default configurations can sample \(K\) leaves and prune others. No retention manifest explains which trajectory was selected, unselected, invalid, pruned, or failed. Per-leaf EM/F1/format outcomes, intra-tree and inter-tree normalization groups, final advantages, policy version, optimizer update, and checkpoint are not linked in a public record-level ledger.

**Outcome verification is narrow.** Exact match, answer-token F1, and format checks do not verify retrieval grounding, source attribution, intermediate logical validity, or factual robustness. A correct terminal string may reward a flawed path; a valid path may be penalized by normalization or extraction. Outcome-derived credit can be assigned to an earlier branch even when later reasoning, retrieval noise, or a downstream action caused the result. The step-DPO analysis assumes binary outcomes, whereas web-agent training uses graded F1.

**The environment is not replayable.** Local QA depends on an E5 index over Wikipedia-2018; web QA depends on Bing/web-search responses. The exact corpus and index hashes, retrieval build, query/response logs, cache, endpoint version, and paper-run environment snapshots are unavailable. A nominally identical action can therefore receive different observations and ultimately a different reward.

**Source and split provenance is partial.** Named source datasets and paper-reported counts are available, but immutable revisions, exact row IDs, file hashes, the 2,000-record ASearcher sampling seed, processed Parquets, and duplicate controls are not. The repository still describes web-agent data as forthcoming. No exact-match, near-duplicate, semantic-overlap, benchmark-contamination, or search-corpus leakage audit was found.

**Configuration reproduction is incomplete.** Scripts disclose temperature 1, optimizer settings, and core tree parameters, but not a complete top-p/top-k/seed contract or realized per-record token/tool budgets. Paper-level response caps of 4,096/8,000 differ from released `data.max_response_length` values of 500/2,000, and their mapping is undocumented. There is no immutable paper-run configuration and result bundle tying tables to code versions.

**Efficiency and exploration trade off.** Shared prefixes reduce marginal generation cost but correlate the leaves. Too-small \(M\), too much expansion through \(N\) or \(L\), or a shallow task can reduce independent exploration and degrade results. With few leaves, the intra-tree baseline has high variance and can contribute to training collapse; the inter-tree term mitigates but does not remove that risk.

**Rights and institutional metadata remain unresolved.** Apache-2.0 covers the official repository code only. The paper and repository do not consolidate rights for Natural Questions, HotpotQA, ASearcher-35K, WebDancer, evaluation sets, Wikipedia-derived observations, Bing results, processed rows, or generated trajectories. Public availability is not permission to redistribute or train on those objects. The checked evidence ledger also does not verify author affiliations, so `institutions.json` intentionally remains unresolved rather than inferring an organization from the repository namespace.

Status remains `partial`, and curation remains L4 rather than L5/L6. Benchmark results do not close these release, provenance, verifier, replay, or rights gaps.
