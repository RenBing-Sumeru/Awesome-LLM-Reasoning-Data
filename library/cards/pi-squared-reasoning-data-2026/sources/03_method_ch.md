1. **收集结构化来源。** 输入：浏览量高且较新的 Wikipedia 页面。操作：提取表格、跟随相关链接，并按表格尺寸和内容过滤。输出：从 6,614 个页面得到 2,834 张合格表格。检查：只保留能支持非平凡关系查询、而不只是直接查值的表格。
2. **生成分析 QA。** 输入：一张表格及其元数据。操作：Qwen3.5-35B 扩展上下文，编写真实多跳问题和 SQL；LLM 质量评分检查复杂度、自包含性与自然性，最多重生成 3 次。输出：候选问题与可执行查询。检查：拒绝低评分或格式错误的问题。
3. **独立确定两次答案。** 输入：候选 QA 和表格。操作：执行生成的 SQL，并用 Python 独立求解相同查询，再规范化两边结果。输出：经过验证的短答案。检查：只有 SQL 与 Python 一致时才保留。
4. **构建真实长上下文。** 输入：已验证 QA、Wikipedia 页面、链接页面和约 10 篇网页搜索文章。操作：把文档压缩到最多 96K token，同时保留答案证据，并从教师模型输入中删除原表格。输出：非结构化多文档上下文。检查：确认压缩后仍含全部必要证据。
5. **反向生成轨迹并划分。** 输入：上下文、问题与已验证答案。操作：根据目标学生模型家族选择 GPT-OSS-120B 或 Qwen3.5-35B 编写逐步解法；人工复核形成 π²-Bench。输出：1,174 条 QA 轨迹，其中 922 条训练样本和 228 条 benchmark 记录。检查：训练与 benchmark 不重叠，并修订 benchmark 缺陷。
6. **执行微调。** 输入：922 条训练记录。操作：使用 LoRA rank 8 训练约 1 个 epoch 或 200 步，最大序列长度为 128K。输出：π²-20B-A3B 与 π²-4B 模型。检查：在固定 reasoning effort 下比较同一个 base model 的训练前后结果。

复现信息：官方代码、JSONL 数据与模型均有链接。需要固定 Wikipedia 与网页快照、搜索结果、表格过滤、Qwen 与教师模型版本、SQL/Python 结果规范化、压缩策略、学生家族映射和 LoRA 设置；数据许可仍未确认。
