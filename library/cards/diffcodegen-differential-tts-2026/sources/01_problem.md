Sampling makes code generation more likely to contain a correct program, but a real assistant must return one program rather than an oracle pass@k score. Existing test-time methods often use public tests or ask an LLM to generate and judge additional test cases. Public tests are usually absent for a new function, while extra model calls consume time and tokens and can make selection as expensive as generating the candidates themselves.

The paper asks how to select a good program from several sampled implementations when no trusted test suite exists. The desired selector must use the computation already available in a programming environment, distinguish implementations by their observable behavior, and avoid treating a model-generated verdict as a reliable oracle. It should improve pass@1 while keeping the marginal cost of selection far below that of an additional reasoning or verification rollout.
