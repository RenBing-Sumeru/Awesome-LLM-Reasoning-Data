DiffCodeGen treats independently generated programs as multiple implementations of the same natural-language specification. Differential testing supplies a pseudo-oracle: if most candidates agree on outputs for diverse valid inputs while one differs, the outlier is more likely to contain a bug. This does not need an expected output for every fuzzed input, only the assumption that correct implementations should behave consistently under the same specification.

The method first creates diverse candidates, then uses coverage-guided fuzzing to find inputs that exercise meaningful code paths. It executes every candidate on those inputs, represents each program by its observed behavior, clusters the candidates, and returns the medoid of the largest behavior cluster. The central allocation decision is to spend inference budget on multiple first-pass candidates and executable analysis, not on a second LLM-based selector.
