The contribution is not simply to fuzz LLM-generated code. It makes differential agreement among multiple sampled programs the selection signal for test-time scaling, and joins it with coverage guidance so that candidate disagreement is sought in informative execution regions. This replaces a common second model pass with an executable behavioral test, retaining the benefits of diversity while avoiding a dependence on public unit tests.

The method also distinguishes candidate generation from candidate verification. Sampling, beam search, and prompt variation deliberately create alternative implementations; the clustering stage exploits their agreement without assuming any one candidate is a gold reference. It does not prove that the majority behavior is correct when all candidates share the same misconception, but it creates a concrete non-neural consumer for parallel code samples and therefore changes the accuracy-cost curve at inference.
