报告的实验显示，在四个语言模型上，该方法相对比较的无需测试基线都有稳定收益。论文强调它在选择候选时不需要额外的大语言模型选择调用。在 LiveCodeBench 上，对本地部署模型，它的执行时间约为先前测试时方法的五分之一；对 API 模型，它约使用这些方法百分之五的时间，并消耗约百分之四的输入词元。这些比较支持的是效率主张，而不只是 pass@k 式的机会主张。

证据还说明为何覆盖率重要。随机输入可能反复触发常见路径，无法暴露语义分歧；而覆盖引导输入会在聚类前探索较少见分支。该方法可与推理模型及其他测试时程序组合，因为其选择阶段与模型无关。pass@1 仍是合适的部署指标：最终程序在不知道基准隐藏测试的情况下被选出。
