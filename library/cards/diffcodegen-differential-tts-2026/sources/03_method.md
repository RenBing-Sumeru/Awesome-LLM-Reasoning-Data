The differential-generation stage uses three ways to create candidate diversity: repeated stochastic sampling at temperature 0.7 and nucleus probability 0.95, beam search, and eighteen semantic-preserving prompt perturbations. For each collection, the method chooses a reference candidate, instruments it, and fuzzes it to obtain inputs. Script programs use AFL++ or py-afl; library functions use libFuzzer or Atheris, with a single LLM-generated fuzz driver only when necessary.

All candidates execute on the fuzzed inputs. Their outputs define behavior distances, which are clustered into two groups; the candidate with the smallest relative distance to peers in the largest group is selected. The paper evaluates four code models on LiveCodeBench, compares with test-free baselines, and measures pass@1 together with wall-clock time and token use. This separates the cost of generating alternatives from the much smaller selection cost that uses program execution rather than further model inference.
