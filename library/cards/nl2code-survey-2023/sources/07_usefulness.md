Read this paper when selecting a starting benchmark for natural-language-to-code work or when explaining why two code models differ. It is especially helpful for turning a vague comparison into concrete questions about data, tuning, model size, tests, and the definition of correct code.

Use the survey to frame a decision before running a comparison. First state whether the target is short function generation, a broader programming task, or a system that must work with particular libraries and constraints. Then ask which benchmark exposes that requirement, what executable tests actually check, and which model-side factors the cited evidence holds fixed. This prevents a convenient score from silently becoming a substitute for the target specification. The survey is strongest as a map from a practical question to candidate studies and evaluation surfaces; it cannot decide which trade-off is appropriate for an unseen engineering context.
