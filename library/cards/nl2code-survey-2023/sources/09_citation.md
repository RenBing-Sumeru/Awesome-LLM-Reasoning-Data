Before applying a comparison, verify the prompt format, programming language and library assumptions, model version, and executable tests used. These choices can change what a score means. The survey discusses 27 models and a HumanEval comparison, but does not turn heterogeneous systems into one interchangeable baseline. A model may be evaluated as a direct generator, with a particular decoding setup, or under a task framing unlike a target application. A test-suite result is evidence about listed cases, not a complete proof of functional behavior. Preserve that boundary in a reading list or design document. This card maps models, datasets, benchmarks, metrics, and factors for investigation; implementation and performance claims still belong to the cited primary paper.

It also helps readers avoid confusing a broad model comparison with an end-to-end software evaluation. Check what the task description asks for, what code artifact is scored, and what the stated tests omit. These distinctions are necessary before moving from a benchmark result to an engineering decision.
