The reconstructable construction pipeline is:

1. **Assemble source tasks.** Start from MATH 7.5K, DeepScaleR 40K, BigMath 251K, and KodCode 40K, about 339K records in total. For BigMath, keep problems whose reported solve rate is below 0.3. Exact source revisions, record IDs, deduplication, and per-source licenses are not carried into the final schema.
2. **Unify Code CoTs.** Prompt Qwen2.5-72B-Instruct once per source solution at temperature 0.6 to produce standardized executable Python. Run the program and compare with the expected answer where one exists. This yields 146K verified seeds: 122K math and 24K code/algorithmic records. The paper also uses a 109K subset in scaling comparisons; the row-level relation between Seed109K and the 146K pool is not released.
3. **Train and sample CodeGen.** Fine-tune Qwen2.5-Coder-7B on code only, without the original problem statements. At inference, sample at temperature 0.9 with a maximum of 1024 tokens. The pipeline produces about 5.3M candidate programs. The exact samples-per-seed allocation, random seeds, retry policy, and complete training manifest are unknown.
4. **Filter sampled programs.** Reject syntax or runtime failures and executions exceeding 10 seconds. Require at least six non-comment lines and use AST analysis to ensure every variable declared in the input dictionary participates in the program. Apply exact output agreement when ground truth exists. About 4.6M candidates survive, implying an approximate 86.8% stage acceptance rate; the input and survivor counts are rounded, so this percentage is not exact.
5. **Reverse instructions.** Give each surviving code sample plus representative input-output examples to Qwen3-8B, with thinking disabled, temperature 0.7, top-p 0.8, top-k 20, and min-p 0. Generate a natural-language problem. In a separate call/configuration stage, generate a language CoT for that new problem.
6. **Apply final checks.** Extract the final language answer and require agreement with the code execution result. Ask Qwen3-32B binary questions about problem solvability, answer correctness, and code/language-CoT consistency; retain accepted pairs. Approximately 1.3M survive, and the live file contains 1,348,799 rows. Relative to the rounded 4.6M reversal inputs, final retention is about 29.3%; relative to 5.3M sampled programs, it is about 25.4%.
7. **Package and train.** Publish `instruction`, `output`, `answer`, and `code` in one JSONL train split. For downstream evidence, fine-tune DeepSeekMath-7B, Qwen2.5-Math-7B, and LLaMA3-8B for three epochs using LLaMA-Factory, AdamW, learning rate `5e-6`, batch size 128, cosine decay, warm-up ratio 0.03, cutoff 4096, and weight decay 0.1. Evaluate zero-shot with greedy decoding and maximum generation length 2048.

Table 5 reports construction time on one machine with eight A100 GPUs: 2 hours for Code-CoT unification, 8 for scaling, 5 for question reversal, and 40 for answer generation, totaling 55 hours. The paper does not report token throughput, energy, failed-run cost, model-serving stack, or whether judging time is included separately.

The official repository is a partial reproduction surface. It pins LLaMA-Factory v0.9.1 in the README and contains execution/input-output extraction, answer filtering, CodeGen/downstream training scripts, and two evaluation toolkits. It does not expose a complete source conversion, 5.3M sampling, Qwen3 reversal, final Qwen3-32B judging, rejection logging, or release-assembly pipeline. The current CodeGen script uses one epoch, learning rate `5e-6`, and cutoff 2048; downstream `scripts/sft.sh` uses three epochs, `5e-6`, and cutoff 4096. These scripts should be treated as current repository evidence, not as an immutable manifest for every paper run.
