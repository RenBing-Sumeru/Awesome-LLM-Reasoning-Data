For `data_construction_open_release_recipes`, Caco is a worked example of using an executable intermediate representation to expand reasoning patterns before rendering them as natural language. A reproduction can compare three design choices directly: prompt-conditioned rewriting versus unconditional program sampling, rule/execution filters versus model-only filtering, and reversal from code versus direct teacher question generation.

The public rows can support supervised fine-tuning and synthetic-distillation studies. `instruction`/`output` is the documented SFT pair; `answer` enables final-answer extraction and consistency checks; `code` enables code-language alignment analysis, program clustering, controlled re-execution, and alternative renderer experiments. Reusers should preserve all four fields and add immutable row IDs rather than discarding the executable provenance immediately.

The release is also useful for verifier research, provided its labels are not treated as ground truth. Audits can sample rows for independent mathematical review, compare program execution with extracted answers, test whether representative inputs determine the generated instruction, measure Qwen3 judge false accepts, and stratify errors by source family, program structure, or reversal complexity. The visible contradictory geometry row makes such audits a concrete necessity rather than a theoretical concern.

For construction studies, the reported funnel supplies useful operating points: about 339K sources, 146K verified seed programs, 5.3M samples, 4.6M execution/structure survivors, and 1,348,799 released pairs, with a reported 55 hours on eight A100 GPUs. Reimplementations should log exact counts rather than rounded totals and retain every rejection reason, execution trace, prompt/model revision, random seed, and parent link. They should also use a sandbox with explicit filesystem/network/resource policies.

Reuse class: supported for `sft`, synthetic `distillation`, data-scaling studies, program-language consistency research, and verifier/audit benchmarks after independent filtering. Conditional reuse requires row-level source/license reconstruction and evaluation-set decontamination. Full end-to-end regeneration is blocked by missing pipeline stages and manifests.
