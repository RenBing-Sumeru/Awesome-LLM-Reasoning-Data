Caco moves augmentation from question space into executable reasoning-program space. Its CodeGen model sees only standardized Code CoTs during training and samples programs unconditionally at inference. A generated program can therefore recombine decompositions, intermediate computations, and control structure without being anchored to a seed question's wording. A separate model then infers a plausible instruction from the program and representative input-output examples.

The feedback contract has four distinct layers:

1. **Reference-backed seed verification.** Converted seed programs must parse and run; when a source answer is available, execution output must match it. This is the strongest layer because an external expected answer constrains the program.
2. **Program validity and structure.** Generated programs must execute within 10 seconds, contain at least six non-comment lines, and use every input-dictionary variable according to AST analysis. These tests establish bounded execution and nontrivial syntactic structure, not mathematical truth.
3. **Cross-representation answer agreement.** After Qwen3-8B generates an instruction and a separate language CoT, the extracted language answer is compared with the program's output. This detects direct answer disagreement but can preserve the same mistake on both sides.
4. **Model-based semantic judgment.** Qwen3-32B judges problem solvability, answer correctness, and consistency between code and language reasoning. The paper supplies yes/no prompts, but not record-level decisions, judge calibration against humans/formal solvers, thresholds beyond the binary answers, or disagreement handling.

The resulting supervision is mixed. Released `instruction`/`output` pairs provide sequence-level SFT targets; `answer` supports answer-level checking; `code` exposes the intermediate executable trace for audit or derived experiments. The paper trains downstream models only with supervised fine-tuning/distillation-style synthetic supervision. It proposes RL with verifiable rewards as future work; there is no reported RL objective, policy rollout, reward study, or RL-trained result, so the Card does not add `rlvr`.

The closest conceptual families are problem-rewriting augmentation, teacher-generated reasoning distillation, and execution-filtered code synthesis. Caco's specific contribution is their ordering: unify heterogeneous solutions into executable patterns, generate patterns without prompts, then reverse them into instructions under answer and semantic checks. The novelty is an integrated scalable data-construction recipe and open final corpus, not a proof that program execution guarantees semantic correctness.

The paper's current release is more auditable than an instruction/output-only corpus because it includes `answer` and `code`. It remains less auditable than the construction process itself: execution outputs, representative test inputs, source IDs, generator parents, acceptance/rejection labels, prompt/model revisions, and judge rationales are not attached to rows.
