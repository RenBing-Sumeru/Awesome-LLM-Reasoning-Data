- Program execution is not semantic proof. A program may run, finish within 10 seconds, use every input variable, and agree with its own generated language trace while encoding a false premise, wrong formula, unit error, or unintended task.
- A concrete released-row audit illustrates the boundary: the Hugging Face preview includes a problem about a parallelogram inscribed in a circle with a 60-degree adjacent angle, while its code and answer compute the area of a side-3 rhombus. A cyclic parallelogram must be a rectangle, so the stated 60-degree condition is inconsistent. This row survived execution, answer agreement, and the reported judge pipeline.
- Problem reversal can lose constraints, simplify the originating program, or generate an ambiguous/contradictory specification. The authors acknowledge that predefined program types limit unconventional problems and that back-translation can lose detail or simplify questions.
- Final semantic verification is correlated with generation: Qwen3-8B writes the reversed problem and language CoT, and Qwen3-32B judges solvability, correctness, and consistency. The reported 100K verification audit also uses Qwen3-32B. No independent human/formal calibration, confusion matrix, adversarial set, or false-accept/false-reject estimate is provided.
- The release has no row-level upstream ID, parent seed/program, seed-versus-generated flag, representative tests, execution output, generator/judge revision, prompt revision, judge decision, rejection reason, or retry count. Consequently, one cannot reconstruct why a row survived or estimate stage-specific selection bias from the public file.
- The repository is incomplete for end-to-end regeneration. It provides extraction/execution, answer filtering, training scripts, and evaluation toolkits, but not the complete seed conversion, 5.3M sampling, Qwen3 reversal, Qwen3-32B judging, rejection manifests, or release packaging. It has four commits and no release tag at the checked snapshot.
- The one-split release provides no validation/test partition. The paper reports embedding-based diversity, not systematic exact, near-duplicate, or semantic overlap against all evaluation sets. Benchmark gains therefore cannot be used as evidence that the corpus is clean.
- The paper describes a controlled Python runtime and a 10-second limit but does not specify process/container isolation, network or filesystem restrictions, dependency allowlists, memory/CPU limits, or malicious-code review. Users must not execute released or newly generated programs outside a hardened sandbox.
- The dataset card declares Apache-2.0 and the code repository MIT, but final rows do not include upstream source or license fields. Compatibility, attribution, and redistribution conditions for all MATH, DeepScaleR, BigMath, and KodCode inputs remain a record-level audit obligation.
- The paper's future-work claim that executable traces could support RLVR is not an implemented training contract. There is no released RL reward definition, rollout budget, policy training code, or RL result, so `rlvr` reuse remains unsupported.
