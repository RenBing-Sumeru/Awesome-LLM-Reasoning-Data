APPS asks Python code to pass tests, while Lean datasets such as MiniF2F ask for proofs of given mathematical theorems; existing verified-coding sets are much smaller. FVAPPS places function implementation and property proof from technical-interview problems in one Lean file. `#eval` retains concrete behavior checks, while theorems lift finite tests into universal specifications. Translating Python to Lean and using `sorry` benchmarks are not individually new. The change is systematic conversion of 4,715 general programming tasks into unified implementation-plus-proof obligations, with a 1,083-task quality-controlled subset.
