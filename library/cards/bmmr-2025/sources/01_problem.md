Multimodal reasoning data is often concentrated in mathematics or K–12 science, while broad university-level reasoning spans disciplines with different visual conventions, answer types, and standards of evidence. A corpus that mixes geometry diagrams, scientific plots, maps, technical figures, and text-heavy humanities questions must solve more than prompt collection: it must retain cross-modal dependence, attach usable reasoning and answers, control subject balance, and define how correctness is judged across multiple-choice, fill-in-the-blank, and open-ended formats.

BMMR addresses this gap with two released objects. BMMR-Train contains 88,991 bilingual image-conditioned conversation records intended for supervised fine-tuning. BMMR-Eval contains 20,458 questions divided into five difficulty levels for evaluation; the paper reports 8 top-level disciplines, 16 second-level disciplines, 40 third-level areas, and 300 UNESCO-defined subfields across the complete dataset. These objects should not be collapsed: Train supplies reference reasoning traces, whereas Eval supplies questions, reference answers, metadata, and a rule-scored benchmark interface.

The work also identifies a feedback problem. Final-answer matching can reward a guessed answer or a flawed derivation, and it can reject a semantically valid answer that does not match the parser. The proposed BMMR-Verifier therefore takes the question and image, a reference solution, and a model response, then assigns a probability to a binary `+` token after each newline-delimited step. This is a learned process score, distinct from both the model-agreement filters used to curate BMMR and the final-answer rules shipped in the public evaluation repository.

For an auditable atlas, the central question is not whether the paper reports high downstream scores. It is which data and decisions are reusable. The public release now contains both Train and Eval, plus final-answer evaluation scripts. It does not contain the verifier checkpoint, its 140k training pairs, the 32-way rollout trajectories, per-step targets, verifier training code, or the row-level source and curation ledger. BMMR is therefore a substantial but partial open construction recipe.
