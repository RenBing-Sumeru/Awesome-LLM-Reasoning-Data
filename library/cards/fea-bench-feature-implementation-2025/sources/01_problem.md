Repository-level coding benchmarks mainly ask models to repair existing bugs, whereas real development also requires adding classes, APIs, or modules from requirements and modifying related call sites. Feature implementation combines architectural understanding, completion of new components, and edits to multiple existing locations. Function-level generation and bug-fix benchmarks do not measure this incremental-development capability well.

FEA-Bench constructs executable tasks from real GitHub feature pull requests, binding requirements, base repositories, gold modifications, and relevant unit tests. Candidate implementations must pass tests in repository environments, making the benchmark specifically evaluate the path from natural-language feature requests to cross-file implementations.
