The contribution couples a maintained live-web task suite with a trajectory-aware evaluator. An agent starts from the designated site and emits browser actions against changing pages. The current v2 submission schema stores task metadata and an ordered action history; each step can bind an index, screenshot, URL, normalized action, nullable thought, and optional action status. Its SUCCESS or FAILED status only says whether the action had a visible effect. It is not the episode reward.

Episode feedback comes from two contracts. Human annotators assign failure, success, or not executable, with at least two annotators per trajectory and a third adjudicator for conflict. WebJudge produces a binary outcome through a staged procedure: extract task key points, summarize and score screenshot relevance, retain frames at threshold 3, then judge the outcome from the task, key points, selected screenshots, and factual action history. It excludes the agent's final answer and thoughts because those fields can hallucinate completion and differ across agent implementations.

WebJudge-7B is a released Qwen2.5-VL-7B derivative trained for the screenshot-summary and relevance stage. It is not a fully self-contained replacement for the entire evaluator: reported inference still uses an LLM for key-point extraction and final outcome judgment. This boundary makes the reward-modeling claim specific and auditable rather than treating all released tasks or agent trajectories as preference data.
