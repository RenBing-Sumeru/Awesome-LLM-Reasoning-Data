Online-Mind2Web asks whether apparent web-agent progress survives a move from cached pages or stale demonstrations to the live web. The authors first sampled 650 original Mind2Web tasks and found that 47% were invalid or paired with outdated reference trajectories. They therefore built a 300-task suite spanning 136 websites and 12 domains: 167 selected Mind2Web tasks, 24 rewritten tasks, 34 Mind2Web-Live tasks, and 75 newly authored tasks. Difficulty is defined by reference length: 83 easy tasks require at most 5 steps, 143 medium tasks require 6–10, and 74 hard tasks require at least 11.

The released task object is intentionally small: task ID, starting website, natural-language task, and reference length. The evaluated data object is larger and time-dependent: a browser episode contains screenshots, URLs when available, actions, optional thoughts, a final answer, and post-hoc feedback. Because execution occurs on public websites, the task and observation distribution can change after publication. The benchmark is therefore both an evaluation set and a maintenance process, not an immutable trajectory dataset.

For an atlas of reasoning data, the central question is provenance and feedback: which prompt version produced which live episode, what the agent observed and did, whether each action visibly took effect, and why humans or WebJudge judged the terminal outcome successful. Official artifacts expose the current tasks, evaluator, labels, example trajectories, submission schema, and WebJudge-7B. They do not establish a complete public corpus of every paper trajectory or a frozen website state sufficient for exact replay.
