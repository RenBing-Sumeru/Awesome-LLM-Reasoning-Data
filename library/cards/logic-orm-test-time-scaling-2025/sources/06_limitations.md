Binary final-label agreement is a weak verifier for reasoning validity. A trace can contain an invalid inference, contradict a premise, or fabricate an intermediate fact and still receive reward 1 if it ends on the correct A/B/C label. Conversely, a largely valid derivation with a parsing or final-label error becomes negative. The paper acknowledges that outcome supervision does not establish faithfulness of the reasoning process, so the released rewards must not be interpreted as step-level correctness.

Echo filtering is model-mediated and selective. The retained wrong traces are precisely those that one GPT-4o judgment setup fails to recognize as wrong. This can be useful adversarial curriculum, but it may encode judge-specific blind spots, prompt artifacts, and systematic correlations between an asserted label and generated language. The exact GPT-4o API snapshot, generation seeds, raw judge outputs, and complete decoding configuration are undisclosed, preventing a stability audit across model versions or repeated runs.

The release is missing the most consequential construction records. The 19,105-row file has no field distinguishing ordinary CoT from Echo, no asserted-answer field, no stable candidate ID, and no judge verdict. Raw forced-label candidates, discarded obvious errors, filtering reasons, and the JustLogic resampling index manifest are absent. Only FOLIO traces are public even though six ORMs cover FOLIO, ProverQA, and JustLogic. As a result, the ProverQA and JustLogic models cannot be tied to auditable record-level training data.

The test-time side is not released as a trace artifact. Historical candidate pools, ORM scores, selected indices, candidate ranks, winning traces, and rejected Best-of-N attempts are unavailable. The released inference main loop emits unscored generations and does not execute the complete ranking path as an end-to-end reproduction. Without scored candidate logs, one cannot measure calibration, ranking reversals, score ties, failure concentration by candidate count, or whether the chosen answer changes for reasons unrelated to logical validity.

Counts and code disagree in ways that should remain unresolved rather than silently normalized. JustLogic Appendix Table 4 prints total 49,197, whereas the two class counts sum to 69,197 and Appendix B describes a sampling target that does not settle the discrepancy. The paper and shell specify three ORM epochs, while `finetune_orm.py` uses two. The GPT generation helper defaults to eight candidates although FOLIO uses ten, and the Qwen generator implements only the Uncertain/C Echo prompt. The release provides components, not a single verified command that regenerates every dataset and result.

Data governance is incomplete. The JSON arrays have no named train/validation/test split, row-level source version, or stable ID; the trainer creates an internal 100-row validation set after shuffling with seed 42. No decontamination, prompt deduplication, train/test-overlap analysis, or upstream snapshot manifest is reported, and each FOLIO file contains one exact duplicate record twice. The paper is CC BY 4.0, repository code is MIT, and model cards declare MIT, but there is no dataset-specific license or derived-data rights statement covering the FOLIO JSON, upstream ProverQA/JustLogic material, or GPT-4o outputs. Reuse rights therefore remain unresolved even though the files are publicly accessible.
