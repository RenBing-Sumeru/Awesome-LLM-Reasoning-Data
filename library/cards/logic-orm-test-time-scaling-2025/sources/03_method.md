The construction and use pipeline has six stages:

1. **Prompt sources.** The paper uses the training portions of ProverQA (5,000 questions), JustLogic (4,900), and FOLIO (about 1,000). FOLIO is human-annotated; JustLogic is synthetic across seven reasoning depths; ProverQA includes three difficulty levels and noisy-premise variants. Only FOLIO-derived trace files are public.
2. **Multi-sample CoT generation.** GPT-4o is the main generator for all three datasets; Qwen2.5-7B-Instruct also supplies preliminary ProverQA variants. Standard prompts request step-by-step reasoning ending in `\boxed{}`. Paper budgets are eight candidates per ProverQA and JustLogic input and ten per FOLIO input. The released GPT helper uses temperature 0.6 but defaults to eight generations, so reproducing the ten-sample FOLIO setting requires changing that default.
3. **Outcome labeling.** The parser maps the boxed True/False/Uncertain response to A/B/C. Exact agreement with the benchmark label yields integer reward 1; a different parsed label yields 0. Public rows contain `input`, `label`, `reasons`, `predicted_answer`, `reasoning_label`, `system`, and `reward`; `reasoning_label` and `system` are empty throughout the checked files.
4. **Echo generation and filtering.** Three forced-label prompt families ask for rationales supporting True, False, or Uncertain. Wrong Echo traces pass to a GPT-4o judge configured in released code at temperature 0.1 and at most four output tokens. Recognized errors are discarded and judge-blind errors retained. For JustLogic, the paper additionally describes resampling by within-question BLEU diversity and inverse input frequency with \(\alpha=0.8\) and \(\beta=0.2\). Raw Echo generations, judge messages, rejected rows, and selected indices are unavailable.
5. **ORM training.** Qwen2.5-7B-Instruct is adapted with LoRA so that, after the full question and trace, it predicts a final `+` or `-` token. The paper reports one A100, three epochs, total batch 64, and learning rate \(5\times10^{-4}\). The official shell passes three epochs, but `finetune_orm.py` hard-codes two. The trainer loads either JSON as one train split and creates a shuffled 100-row validation partition with seed 42; no stable row IDs or released split manifest bind a weight checkpoint to exact rows.
6. **Best-of-N use.** A reasoner samples N complete solutions at temperature 0.6; the ORM scores them and the maximum-scoring trace is selected. The exact N values behind every plotted curve are not enumerated in prose. Released inference examples default to 32 candidates and 2,048 new tokens, but the checked-in main loop writes unscored generations and does not preserve the ORM scores, winning index, or rejected candidates.

The public data counts sharpen the boundary. The CoT file has 10,009 rows over 1,001 unique inputs, with 7,383 positives and 2,626 negatives. The combined Echo-CoT file has 19,105 rows with the same 7,383 positives and 11,722 negatives. A multiset comparison shows that it contains the complete CoT file plus 9,096 additional rows, all negative. This is a useful released hard-negative set, but it is not a record of the raw three-way Echo generation pool: Appendix Table 2 reports substantially larger True-, False-, and Uncertain-prompted candidate sets before filtering.
