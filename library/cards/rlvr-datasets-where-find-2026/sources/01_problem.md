RLVR training sets are often named and cited as if each release were an independent source. In practice, prompts pass through nested aggregation, filtering, answer replacement, multiple-choice conversion, and rewriting. Dataset-level attribution cannot show which original collection supplied a record, which transformations it underwent, whether it overlaps an evaluation set, or whether answers remain consistent across copies.

The paper separates two decisions. A lineage audit asks where each canonical question-answer instance first entered the ecosystem and where it reappeared. A training-data audit asks which sources and records supply useful, verifiable, contamination-controlled signal for a particular RLVR model. ATLAS addresses the first decision; Source-level Counterfactual Attribution (SCA), the composite score Q, and DAPO++ address the second.

For this atlas, the central issue is the difference between a public file and an auditable construction recipe. The paper analyzes 1,450,827 instances and reports 20 atomic-source labels, but the repository ships tracing code and a 17,000-row DAPO++ Parquet rather than the complete lineage dictionary, SCA annotations, or selection ledger. The analysis corpus, source-conditioned labels, released training file, and downstream benchmark must therefore be evaluated as separate evidence surfaces.
