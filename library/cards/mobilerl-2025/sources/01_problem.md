MobileRL is a 2025 arXiv preprint about online reinforcement learning for mobile GUI agents. This Card uses arXiv:2509.18119v2, submitted on 2025-09-10 and revised on 2025-10-24, together with the official `THUDM/MobileRL` repository and `xuyifan/MobileRL-9B` checkpoint. The repository HEAD inspected on 2026-07-20 is `82f3b7e9028098f0683b97dbe228bad300a55fb1`; it contains evaluation code, not the training pipeline or rollout data.

The problem is not merely predicting the next tap. Online mobile RL must obtain rare successes from expensive Android emulators, cope with a heavy-tailed task-difficulty distribution, and assign useful credit to multi-turn trajectories whose reward arrives only at completion. Uniform on-policy sampling repeatedly spends compute on impossible tasks and discards scarce difficult successes, while action-only imitation does not teach recovery from the policy's own errors.

MobileRL treats training as three linked data objects. Reasoning-free SFT uses 97.9k action steps: 21.3k AndroidControl-Low, 14.3k AndroidControl-High, and 62.2k human-annotation/self-exploration steps. Reasoning SFT uses 23.6k steps from the same groups—7.2k, 4.1k, and 12.2k—with model-generated reasoning retained only when the action matches the expert target. Online RL then samples state-action trajectories over 2,000 AndroidWorld and 1,103 AndroidLab training tasks.

An RL episode binds a natural-language instruction and initial Android state to repeated screenshot/compressed-XML observations, optional reasoning, structured GUI actions, environment transitions, a terminal Finish or 50-turn cutoff, and a binary outcome. AndroidWorld supplies rule-based verifiable rewards. AndroidLab's generated training tasks lack ground-truth tests, so a learned VLM reward model judges the complete screenshot/action trace. SPA length shaping, AdaPR replay selection, negative pruning, and FCF task failure histories then determine which trajectory tokens receive policy gradients.

This object belongs in `environment_agent_trajectory_data` because the environment, rollout, terminal verifier, replay buffer, and dropped failures jointly define the supervision. The paper evidences SFT, RLVR on rule-verifiable AndroidWorld tasks, and mobile agent training. It does not release the SFT corpora, 3,103 RL tasks, training code, AndroidLab reward-model data/checkpoint, replay state, or complete successful and failed rollouts. The current evidence supports L4-depth analysis but retains `L3_summary_ready` and `partial` workflow status.
