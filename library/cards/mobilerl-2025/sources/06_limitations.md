- **Training artifacts are incomplete.** The official repository at inspected HEAD exposes evaluation, AndroidLab support, scripts, Docker configuration, and patches, but not the paper's SFT data, 3,103 RL tasks, training implementation, AndroidLab reward model/data, replay buffer, failure histories, or full rollout corpus. The Hugging Face artifact is a model checkpoint, not a trajectory release.
- **Learned-verifier error.** The AndroidLab reward model reports 86% accuracy on 1,000 verified traces, so 14% are misclassified on that set; no confusion matrix, class-conditional rate, adversarial suite, or independent calibration is released. Proprietary VLM majority labels may share correlated bias.
- **Reward and selection gaming.** SPA can reward a short verifier-satisfying shortcut if the terminal checker misses collateral changes or unsafe actions. AdaPR amplifies judged successes; negative pruning and FCF remove low-reward behavior/tasks. These mechanisms can reduce failure diversity and hide systematic hard cases even when aggregate success rises.
- **Best-result scope differs by backbone.** Qwen benefits from mixed AndroidWorld/AndroidLab RL, whereas the reported best MobileRL-9B is trained only on AndroidWorld because the learned AndroidLab reward is less reliable. A single “MobileRL” score therefore does not identify one common task mixture or verifier regime.
- **Limited decontamination.** AndroidWorld removes exact task-content plus initial-state collisions; AndroidLab uses manual test non-overlap verification. No semantic/template deduplication, cross-source overlap, or evaluated-model pretraining contamination analysis is reported.
- **Version sensitivity.** Full-resolution MobileRL-9B scores 80.2%/53.6%; compressed images score 75.8%/46.8%. The evaluation README expects 1–2 point variation from deployment, inference engine, and image compression. APKs, AVD/OS images, random seeds, and paper-era result manifests are not fully pinned in the training release.
- **Representation limits.** Compressed XML can omit interactable elements in popular complex apps, while bounding-box grounding depends on accessibility metadata. The authors identify movement toward vision-only interaction as future work.
- **Domain and reset limits.** Testing excludes out-of-domain public-use apps because login, VM reliability, manual judgment, and state restoration are difficult. Emulator success does not establish robustness on real devices, unseen UI layouts, authenticated services, or irreversible actions.
- **Resource barrier.** Each AVD consumes over 5 GB memory and 30 GB storage; four 1-TB CPU machines stably support only 256 parallel rollouts. A step takes more than 10 minutes and 100 training steps more than 25 hours, limiting independent reproduction and ablation breadth.
- **Privacy evidence is procedural.** The paper describes regex masking for textual identifiers and visual masking for faces, QR codes, and OCR text before storage, but publishes no recall/precision audit, residual sensitive-data sample, or annotator consent/compensation record.
- **Mobile security is under-specified.** No comprehensive permission, credential, network, prompt-injection, malicious-content, collateral-action, or data-exfiltration evaluation is reported. Emulator isolation does not by itself establish safe deployment.
- **Rights do not transfer automatically.** The code is MIT, the model card is Apache-2.0, and the manuscript is CC BY 4.0; these do not establish rights for unreleased screenshots/XML, human annotations, AndroidControl transformations, generated tasks, app content, rollouts, or proprietary-VLM labels.
