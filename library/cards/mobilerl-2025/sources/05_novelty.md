The closest baseline is offline mobile-agent post-training: action-only demonstrations, static screenshots, offline RL, or DPO over fixed records. Those settings expose expert behavior but not the current policy's closed-loop errors, recovery attempts, or environment-dependent success. Single-step GUI RL likewise does not address credit across a 50-turn interaction or the cost of running many Android devices.

MobileRL changes both the data object and selection rule. Its RL record is a live screenshot/XML/action trajectory with a terminal outcome, a length-sensitive reward, a group-relative advantage, possible replay membership, and a task failure history. AdaPR gives scarce difficult successes another update; FCF changes the task distribution using repeated all-zero groups; negative pruning explicitly discards low-advantage failures. Thus, “the dataset” is not a fixed file but a policy- and verifier-dependent stream whose membership evolves during optimization.

The feedback interface is also deliberately heterogeneous. AndroidWorld uses executable rule-based checks; AndroidLab training relies on a learned VLM judge distilled from proprietary-majority labels. The paper's comparison of smoother AndroidWorld learning and less reliable AndroidLab rewards makes verifier quality part of the method rather than a hidden benchmark detail.

Individual components are not unprecedented: two-stage SFT, GRPO, experience replay, curricula, length shaping, VLM judges, Dockerized emulators, and bounding-box actions all have prior art. The contribution is their integration for expensive multi-turn Android sampling, plus explicit per-task difficulty adaptation. The reported ability to orchestrate many AVDs is a systems contribution, not evidence that selected trajectories are unbiased or reusable.

For reasoning-data research, the work is directionally important because it makes an often-hidden choice auditable: which successes are replayed and which failures/tasks disappear. Before reuse, a team must inspect selection-induced coverage loss, reward-model errors, split/overlap controls, replay and removal logs, environment versioning, and data rights. The released evaluation code and checkpoint do not expose those training-time decisions.
