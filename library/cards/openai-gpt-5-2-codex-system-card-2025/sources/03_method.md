The disclosed training path can be reconstructed only at interface level. Inputs are undisclosed coding tasks, repository states, and a separate user model. During an RL rollout, the user model makes conflicting edits while GPT-5.2-Codex issues coding or tool actions in the mutable workspace. A preservation mechanism then determines whether the model reverted those user changes, and non-reversion receives positive reinforcement. The resulting policy checkpoint is GPT-5.2-Codex. Repository selection, prompt sourcing, user-model checkpoint, observation and patch schema, episode termination, filtering, rollout count, temperature, RL algorithm, reward scale, objective mixture, optimizer, schedule, compute, and retained trajectories are unknown.

The report separately says that GPT-5.2-Codex integrations receive cyber safety training to help with educational or defensive requests while refusing or de-escalating operational abuse. Training examples, label sources, graders, counts, objective weights, and membership are not disclosed. Context compaction is credited with long-horizon improvements, but its algorithm, trigger, retained state, training curriculum, and production budget are also unknown.

Evaluation follows different pipelines. OpenAI PR tasks pair a pre-PR internal repository with a human-written prompt, tests, and hints; the agent edits files with command-line tools and Python, and hidden unit tests supply an all-tests-pass terminal predicate. Professional CTF uses 16 rollouts and reports pass@12; CVE-Bench uses 3 rollouts per task and reports pass@1 on 34 of 40 tasks because 6 could not be ported; Cyber Range runs 16 trials and marks a scenario passed if any trial succeeds. External cyber elicitation uses auto-compaction, xhigh reasoning, and up to 1,000 turns. These are evaluation sampling and terminal contracts, not training settings.

The only explicit split control is narrow: cyber policy-compliance evaluation data are stated not to overlap training, and some named bio evaluations are held out or described as uncontaminated. No global train/dev/test manifest, code-repository overlap audit, or destructive-action split is disclosed. Reproduction would require pinned repositories, container and tool versions, prompts, user-model and policy checkpoints, complete action traces, reward implementation, hidden tests or equivalent public tests, grader versions, sampling budgets, and item-level lineage.
