This Card is safe as a reading and audit reference, not as a training-data or evaluation-package release. It provides a concrete schema target for future collaborative-coding datasets: task and repository revision, workspace state, actor identity, conflicting edit and provenance, agent actions, final patch, preservation or reversion label, semantic test outcome, reward components, and terminal status.

For reward design, the report motivates separating task correctness from change preservation. A reproducible baseline should publish both predicates, define how necessary conflict resolution is treated, retain successful and failed episodes, and report detector calibration and semantic false positives. It should also test superficial strategies that preserve a diff while neutralizing its behavior.

For evaluation design, the OpenAI PR description is a useful template for full-episode coding tasks: a pinned pre-change repository, human-written requirement, executable hidden tests, command/tool access, and an all-tests-pass terminal predicate. Reuse is blocked because the internal repositories, prompts, tests, hints, containers, and trajectories are not released; public analogues must be independently constructed and licensed.

For frontier-report auditing, the Card supplies a checklist: label each item as training, evaluation, or deployment; keep sampling budgets attached to the correct layer; do not convert product sandboxing into training-environment evidence; and require source, split, reward, lineage, and license records before claiming a reusable recipe.
