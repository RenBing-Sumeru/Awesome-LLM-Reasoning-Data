SWE-bench-style data constructs repair tasks from issues and patches, while HumanEval-style data maps natural language to isolated functions. The former omits new-feature development and the latter lacks repository complexity. SWE-Dev instead reverse-extracts a feature from a complete, test-covered implementation: dynamic call graphs define the boundary, code is masked, and a PRD is generated, allowing original developer tests to become natural verifiers. This is not merely renaming bug fixes. The data object changes to an incomplete repository plus requirement document, with both a 14K training set and 500 manually checked evaluation tasks.
