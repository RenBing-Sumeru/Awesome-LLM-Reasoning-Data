1. **逆向任务偏置：** PRD 根据现成实现和测试生成，需求通常与唯一 gold code 高度对齐，缺少真实产品开发中的歧义、设计协商和多种正确实现。应人工比较 PRD 与真实 issue，并允许测试通过的非 gold 方案。

2. **测试覆盖：** 隐藏边界由 tracing 决定，只能捕获已运行测试触达的行为；测试未覆盖的需求不会进入 verifier。复用时应运行全量测试、检查隐藏测试并报告 flaky rate。

3. **生态与泄漏：** 数据集中于 Python/PyPI，训练和测试可能共享库模式或近似实现；外部模型也可能见过开源仓库。必须按仓库与时间切分、去除重复实现，并冻结容器和依赖。
