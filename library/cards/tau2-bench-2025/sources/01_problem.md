The paper addresses a limitation of customer-service agent benchmarks in which the simulated user only describes a problem while the service agent alone controls the environment. Real interactions can require both parties to act: an agent may change an account in a CRM while the user checks a phone setting or performs a device-side operation. tau2-bench models this as a Dec-POMDP-style dual-control episode. The agent and simulated user exchange natural-language messages, call separate typed tools, observe tool outputs, and jointly change shared state; only one player acts per turn.

The reusable object is more than a dialogue. A task record includes an id, description, structured user scenario and persona, known and unknown information, ticket, initialization data/actions, optional message history, reference actions, environment assertions, communication and natural-language checks, and a reward basis. A released episode binds that specification to ordered assistant/user/tool messages, tool-call arguments and observations, state transitions, timestamps, usage/cost, termination reason, verifier-component outcomes, final scalar reward, trial, and seed. This structure places the paper in `environment_agent_trajectory_data`: the environment is part of both the generation process and the success test.

The strongest new construction evidence concerns telecom. 15 atomic subtask groups across service, mobile-data, and MMS issues are composed into 2,285 full tasks, from which 114 tasks are sampled for the paper's evaluation. Airline and retail are inherited benchmark domains rather than evidence that the same dual-control construction was applied everywhere.
