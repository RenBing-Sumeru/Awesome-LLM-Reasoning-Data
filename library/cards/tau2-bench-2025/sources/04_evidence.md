Construction-scale evidence is anchored to paper Table 1, Appendix A, and the `v0.1.0` JSON release. The telecom generator yields 2,285 full combinations from 15 atomic subtask groups; the released full-task file has 2,285 rows and the sampled evaluation file has 114. Appendix A divides those 114 into 29 service, 36 mobile-data, and 49 MMS tasks covering 2–9 subtasks. The paper reports domain evaluation counts of 50 airline, 115 retail, and 114 telecom, but the pinned release contains 50, 114, and 114 rows. This 1-item retail discrepancy is unresolved and prevents reporting an unqualified single benchmark total.

The evaluation uses four trials per task at temperature 0. On telecom pass^1, the paper reports 34% for GPT-4.1, approximately 42% for o4-mini, and 49% for Claude 3.7 Sonnet. Moving from the No-User condition to Default lowers pass^1 by 18 percentage points for GPT-4.1 and 25 points for o4-mini. These author-reported results support the claim that dual control exposes coordination difficulty under the stated model, simulator, and budget conditions. They do not show that the released trajectories are high-quality training examples, that the evaluator is unbiased, or that the ranking generalizes beyond these APIs and tasks.

The user-simulator audit provides a direct negative signal. Two annotators assess each sampled trace against four criteria. Table 2 reports 3/50 critical telecom errors, 5/50 benign errors, and 8/50 total errors; airline and retail show higher rates. A phrase elsewhere in the paper says there were no critical errors, contradicting the table and surrounding prose. This Card uses the table value, flags the inconsistency, and treats the audit as evidence that simulator failures can become false agent failures rather than as proof that simulation is reliable.

Release evidence is record-level. `v0.1.0` contains 26 final result JSON files across model, domain, and ablation combinations. The inspected GPT-4.1 telecom-default file has 456 task-trial episodes: 156 with reward 1 and 300 with reward 0. Each run includes messages, tool calls, component outcomes, termination metadata, trials, and seeds. This confirms success/failure retention for that file, not completeness of every possible run or a uniform data-selection policy.

The repository supports executable inspection but exact closed-model reproduction remains conditional. Code and mock data can be pinned, while external model availability, provider behavior, credentials, and serving revisions can drift. No independent reproduction, adversarial verifier calibration, contamination audit, or training ablation is part of the accepted evidence. Benchmark performance is therefore evidence about measured agent behavior under a fixed configuration, not evidence of data quality.
