- The paper-era release is version-sensitive. `v0.1.3` later removed default natural-language assertion checks, `v0.2.1` added Gym and train/test splits, and `v1.0.0` refactored the system into tau3 while recording many airline/retail fixes and new modes. Current telecom `tasks.json` contains all 2,285 tasks with a separate `base=114` split, whereas `v0.1.0` placed the 114-task sample directly in `tasks.json`. Unpinned tasks, scores, or replay claims are not comparable.
- Paper Table 1 reports 115 retail tasks while `v0.1.0` contains 114. The source of the missing or extra record is unknown. A benchmark total must name whether it comes from the paper or the pinned release.
- User simulation can produce false failures through premature stopping, omitted constraints, invented details, invalid tool use, or turn-structure violations. Table 2 records 3/50 critical and 5/50 benign telecom errors, contradicting a separate “no critical errors” phrase. The audit sample is small and does not calibrate error rates for every model/domain configuration.
- Deterministic environment assertions and action gates can miss semantic requirements or reward shortcut state changes; natural-language assertions inherit judge variance and rubric bias. No independent calibration set, adversarial predicate suite, false-positive/false-negative estimate, or reward-hacking study is released. Public tasks, policies, reference actions, and evaluator code also permit benchmark-specific optimization.
- The generator's LLM identity, prompts, sampling, rejection counts, and item-level review history are undisclosed. Inherited airline/retail task ancestry is incomplete. These gaps prevent reconstruction of the source mixture and selection process even though the telecom composition code is released.
- `v0.1.0` has no train/dev/test split manifest and no disclosed prompt/model-pretraining overlap or decontamination protocol. Public release creates future contamination risk. Later splits cannot be projected backward onto the paper without changing the evaluated artifact.
- Exact replay depends on closed model APIs, LiteLLM/provider behavior, credentials, serving revisions, and configuration in addition to local code and data. Trial seeds do not freeze external sampling implementations. Reproducing historical model behavior may therefore be impossible even with the paper-era tag.
- The inspected GPT-4.1 telecom-default file retains 156 successful and 300 failed episodes, but completeness of all possible experiments is not claimed. There is no trajectory-quality filter or training-oriented selection protocol, so the logs should not be treated as curated demonstrations or preference data.
- The repository root is MIT and the arXiv paper is CC BY 4.0, but no separate dataset/trajectory rights statement covers inherited tau-bench materials, generated model outputs, and all provider terms. Mock customer data reduces direct privacy risk, yet annotator recruitment, compensation, consent, and agreement statistics for the simulator audit are unknown.
- The paper evaluates agents; it does not report SFT, preference optimization, reward-model training, process supervision, or agent RL. Later Gym/RL interfaces do not retroactively support those uses. Benchmark scores do not establish training-data quality, real-customer validity, or generalization beyond telecom, airline, and retail settings.
