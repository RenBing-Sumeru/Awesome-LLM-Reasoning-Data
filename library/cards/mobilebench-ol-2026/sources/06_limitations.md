- **Public evaluation surface:** No train/dev/test or hidden partition is defined. Goals, golden-step counts, key nodes, and rule material are public, enabling memorization, task-specific tuning, and XPath verifier gaming. The from-scratch authoring claim reduces direct copied-task risk but is not a training-corpus overlap audit.
- **Verifier error:** Table 12 contains 5 false positives and 22 false negatives. XPath predicates observe selected GUI elements/actions, not complete task semantics, off-screen server state, privacy, or harmful intermediate side effects. Explicit Complete signaling can also separate actual task completion from the reported label.
- **Reset and state leakage:** Human reset success is above 90%, not perfect. Task/app inverse operations cannot guarantee an identical device, account, cache, recommendation, inventory, message, or server state. Infeasible tasks are handled by broadened success conditions, which can change what the benchmark rewards.
- **Environment drift and replay:** The paper uses three physical phones, versioned apps, verified accounts, and a remote platform, but exact phone/OS images, credentials policy, account fixtures, server state, dependency lock, and public platform snapshot are unknown. The paper promises 80 APKs; no verified official APK bundle is present in the inspected repository.
- **Trajectory-release boundary:** At least five paths per task informed rule validation, and baseline episodes produced all reported results, yet the complete successful, failed, reset-failed, timed-out, retried, and discarded trajectory corpus is absent. README documents locally generated trajectories, not an immutable paper-result release.
- **Noise and budget confounds:** Disturbances occur with 20% step probability, but seeds and event manifests are unknown. Retry count changes pass rate substantially, and a three-times-golden-step cap plus fixed waits can turn scaffold efficiency into an apparent reasoning difference.
- **Data/release quality:** The repository has no semantic release or checksum manifest, and GitHub reports illegal quoting in `longtail.csv` at line 118. Parser behavior, mutable `main`, and app updates can change tasks or labels; the paper itself observes up to 5% score fluctuation after version updates.
- **Rights, privacy, and scope:** Dataset terms are CC BY-NC-SA 4.0 and code is Apache-2.0, but third-party APK/content/account rights are not resolved by those licenses. Authors state privacy-exposing data were removed, while the filter specification and account-safety audit remain unreleased. The benchmark lacks cross-app tasks and cannot establish deployment safety.
