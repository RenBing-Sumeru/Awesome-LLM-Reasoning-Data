MobileBench-OL is a real-device mobile-GUI evaluation benchmark published in *Findings of the Association for Computational Linguistics: ACL 2026*. The official paper, DOI, arXiv record, and Xiaomi Research repository are verified. Its question is narrower than generic phone automation: can an agent execute Chinese-app tasks under long horizons, unfamiliar interfaces, exploration requirements, and stochastic real-world disturbances while an automatic evaluator and reset process keep trials comparable?

The benchmark reports 1,080 evaluation cases across 80 apps and five subsets: Base 310, Long-Tail 340, Long-Horizon 60, GUI-Reasoning 60, and Noise-Robust 310. Noise-Robust reuses Base tasks as seeds, so these counts represent 770 distinct task specifications plus 310 Base-derived noisy cases, not 1,080 independent prompts. Long-Horizon tasks require at least 20 golden steps; GUI-Reasoning difficulty is based on icon discovery, hidden functions, and hierarchical navigation rather than step count (Paper §3.2, Table 4).

One released task record contains a task identifier, natural-language goal, app home-page information, human golden-step count, key nodes or rule material, and optional reset fields. When executed, it becomes a full episode over screenshots, XML UI state, normalized actions, responses, termination reason, rule matches, and success. The primary object is therefore an evaluation task/environment/verifier specification. It is not a frozen corpus of the paper's agent trajectories.

This belongs in `environment_agent_trajectory_data` because the result depends on a live device state, app/network behavior, an action-observation loop, environmental predicates, and state reset. It does not establish a training recipe, safe real-device deployment, or cross-app reasoning: `training_use` is evaluation only, and the authors explicitly list complex cross-app tasks as absent.

The Card reaches L4 collection depth by tying task counts, episode fields, feedback rules, reported scores, release contents, licenses, and replay risks to primary sources. Its central boundary is that the code and task/rule CSVs are public, while the complete successful/failed validation and experiment trajectories, promised APK bundle, account fixtures, and immutable device snapshot were not verified in the official release.
