Primary source: https://arxiv.org/abs/2605.11006. Public status: arXiv preprint, 2026. Most code benchmarks score whether generated code passes tests, but that says little about which execution-relevant program structure a model can recover from existing source.

The evaluation object is source program, prompt/task metadata, predicted call-graph edges, execution-witnessed reference edges, precision, recall, and F1. The feedback contract is execution tracers mechanically witness positive runtime call edges; normalized edge sets are scored with precision/recall/F1. This belongs in the collection as an auditable benchmark or environment surface; it is not by itself proof of deployable reliability, and training use should be inferred only where the paper explicitly releases data for that purpose.
