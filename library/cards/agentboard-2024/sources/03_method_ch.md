1. 输入：9 个环境之一的任务、初始 observation、可用动作接口、选定的 LLM agent scaffold，以及最终成功和过程进展指标定义。
2. 流程：让 agent 在环境中运行；把每次回复解析成动作；执行动作；记录 observation、action 和环境反馈；在完成、失败、达到最大轮数或超时时停止；计算最终指标和过程指标。
3. 输出：轨迹、终止成功/失败、progress-rate 或同类过程分数，以及按环境和模型聚合的表格。
4. 验收者：环境实现决定状态转移和终止成功；progress metric 编码任务特定的部分完成度，而不是只依赖自由文本 LLM judge。

复现时必须记录仓库 commit、1,012 任务快照、环境依赖、动作解析器、prompt、模型版本、最大轮数、工具/API 凭据和失败处理规则。只有使用同一套任务进展分解时，progress score 才可比较。
