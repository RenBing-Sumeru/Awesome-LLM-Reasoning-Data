Inputs are 300 Online-Mind2Web tasks covering 136 real websites and 50 self-constructed C-WebShop Chinese e-commerce tasks from Taobao. In the reported systems, Browser-use is paired with Qwen3-14B for Online-Mind2Web, and SeeAct is paired with Qwen2.5-VL-72B for C-WebShop. The exact task IDs, task split, site snapshots, model revisions, browser versions, and task rights are unknown.

For collection, each task is executed multiple times to obtain terminally successful and failed trajectories. Each episode conceptually stores a user instruction, screenshot-or-DOM states, actions such as click/type/scroll, transitions, and a terminal label. The generator checkpoint, executions per task, decoding parameters, step or time cap, reset/session policy, raw counts, and retention rule are not disclosed.

For tree construction, linear episodes for one task are merged into unique state nodes and action edges. Candidate states must share a standardized URL, retaining essential parameters, and must also share either the effective action sequence after the URL change or an identical image hash. The tree is then used for backtracking intermediate progress, identifying correction behavior, and detecting redundant cycles. URL canonicalization, the definition of an effective action, the image-hash algorithm, and merge-quality evaluation are unavailable.

For feedback, every branch receives: shortest-path subgoal progress; `-1` for a detected cycle; `+1` when an undisclosed VLM judges the expected UI modification effective; and `+1` for valid action format. The total is `R_acc + R_format + R_red + alpha*R_subgoal`, where alpha is only reported within 2–5. Exact goal-node construction, per-experiment alpha, VLM identity and prompt, expected-change representation, action grammar, and terminal success predicate are not disclosed.

For selection, cumulative branch rewards order divergent actions at the same node into chosen/rejected pairs. A dynamic factor `|r_w-r_l| / sigma(R_s)` weights high-difference decision points in a DPO-style objective against a reference policy. The method does not specify tie resolution, minimum gap, duplicate removal, branch balancing, pair count, or numerical handling when within-node variance is zero or very small.

For optimization and evaluation, both TGPO and DPO begin from SFT-trained models. All compared optimization methods are trained for 2 epochs on 8 H20 GPUs at learning rate `1e-5`. Batch size, optimizer, beta, scheduler, sequence length, random seeds, checkpoint selection, and the SFT recipe are unknown. The paper uses the derived pairs for preference learning and agent training, and reports evaluation on the two task pools; it does not release a trainable dataset.

The output pipeline is therefore: task -> repeated web episodes -> heuristic state merge -> trajectory tree -> four process-reward components -> cumulative branch ranking -> weighted node-level chosen/rejected pair -> SFT-initialized preference update -> task evaluation. Reproduction requires the missing code, raw and processed data, model revisions/checkpoints, immutable browser environments, split manifest, verifier configuration, licenses, and exact training configuration.
