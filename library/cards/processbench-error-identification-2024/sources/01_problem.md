ProcessBench asks whether a model can identify the first erroneous step in a mathematical reasoning trace, not merely whether it can solve the original problem. The primary source is the arXiv/ACL 2025 paper by the Qwen Team and Alibaba Inc.; the official GitHub repository and Hugging Face dataset publish the benchmark record shape and evaluation entry point.

The gap is a feedback one: final-answer correctness is too coarse for scalable oversight of multi-step math reasoning, while existing process datasets either have easier problems, synthetic errors, limited step-level error-identification coverage, or process labels that do not directly test earliest-error localization. ProcessBench defines one benchmark instance as a math problem, a model-generated step-by-step solution, a generator id, a final-answer-correct flag, and a human-expert label. The label is `-1` when all steps are correct, otherwise it is the zero-indexed first step containing a mathematical, logical, conceptual, or completeness error.

This Card includes the paper because it supplies an evaluation surface for process supervision and PRM/critic auditing. It is not a training recipe by itself, not a proof checker, and not evidence that final-answer reward can validate a reasoning trace. Its atlas value is the explicit step-level feedback contract: a model prediction is accepted only when it matches the annotated earliest-error index or the all-correct label.
