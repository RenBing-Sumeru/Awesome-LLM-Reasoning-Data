ProcessBench 关注的问题不是“模型能不能做对数学题”，而是“模型能不能在一段数学推理中找出最早出错的步骤”。一手来源是 Qwen Team / Alibaba Inc. 的 arXiv 论文和 ACL 2025 版本；官方 GitHub 与 Hugging Face 数据集给出了 benchmark 的数据入口和字段示例。

它补的是反馈粒度缺口：只看最终答案无法判断中间推理是否可靠，而已有过程监督数据要么题目较易、要么错误合成、要么没有把“最早错误定位”做成独立评测。一个样本包含数学题、模型生成的分步解答、生成器 id、最终答案是否正确，以及专家标注的 label。`label = -1` 表示所有步骤正确，非负整数表示从 0 开始计数的最早错误步骤。

这张卡收录它，是因为它给 PRM、critic model 和推理过程监督提供了可审计的 evaluation surface。它不是训练配方，不是形式化 proof checker，也不能证明 final-answer reward 足以监督推理链。它的核心验收契约很窄：预测必须匹配专家标注的最早错误步骤，或匹配“全程正确”的 `-1`。
