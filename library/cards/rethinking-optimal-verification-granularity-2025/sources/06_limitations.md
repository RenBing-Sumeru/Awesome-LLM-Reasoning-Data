The smallest “step” is defined by a double newline, so g depends on prompt style and model formatting rather than a semantic unit guaranteed across generators. A PRM score is only an estimate of prefix quality; noise or miscalibration can make frequent pruning remove recoverable paths, while sparse verification can extend errors. The optimal g changes with model pair, difficulty, and budget, limiting transfer of a precomputed policy.

Despite the term adaptive, g is fixed throughout each problem. CM-g and AM-g use validation accuracy, so small validation subsets or difficulty labels can overfit the policy; oracle-tuned values use test data and are not deployable. Experiments are math-focused, and modeled FLOPs do not capture every systems cost or latency effect.

The code release is not a verified data release. Raw trees, rejected prefixes, verifier-score logs, exact prompts, environment snapshots, complete seeds, and a trace-level manifest remain unverified; decontamination and source/model license compatibility are also unresolved. Reported benchmark and compute gains evaluate a selector, not the intrinsic correctness or completeness of stored process records.
