Inputs are original Putnam problem statements and the target proof-assistant language. The construction pipeline is: manually encode each problem as a formal theorem; handle language-specific libraries and syntax; for answer-exhibiting problems, expose factored variants when the answer can be separated from proof correctness; run model or prover attempts under a fixed prompt/scaffold and attempt budget; submit candidate proofs to the target proof assistant.

Outputs are formalized benchmark files, optional informal statements, leaderboard rows, and solved/unsolved outcomes per language and evaluation setting. The verifier is the Lean 4, Isabelle, or Coq checking stack, not a learned judge. Reproducibility depends on repository commit, language version, library version, timeout, prompt, attempt count, and whether the task uses the answer-given or answer-finding variant. Evaluation-only scores should not be converted into training rewards unless proof attempts, failures, and checker feedback are separately logged.
