outcome verifier 是首要建模限制。正则抽取与 SymPy 等价判断可能拒绝以未支持形式表达的正确答案，也可能接受最终数值偶然一致的响应；两者都不验证中间 CoT。论文明确不进一步区分答案正确与过程正确，也未报告经过校准的假接受/假拒绝研究或对抗格式测试。

难度与预算并不是 prompt 的固有属性。它们依赖 DeepSeekMath-7B-RL、temperature 1.6、top-p 0.95、答案 checker 和试验次数。论文正文把 fail rate 定义为错误响应占比，但附录 B.2 的展示公式与此不一致；仓库用 `1-pass_rate` 加以明确。仓库也说明 Prop2Diff 仍需人工步骤，其公开 Uniform 示例甚至使用需人工停止的潜在无界试验。报告运行所用的精确上限、随机种子、调度与不可变环境文件并未完整固定。

发布元数据并不对称。最终 SFT 集只有 `query` 与 `response`；已接受响应池和 query-info 表补充了有用沿袭与聚合采样计数，但尚不能确认完整的被拒响应文本已发布。因此，外部人员无法独立检查 checker 错误、重复失败模式，以及究竟丢弃了多少种不同的错误 rationale。pool 中的 `proc_correct_prob` 为 null，也与没有过程监督这一事实一致。

来源与评测审计仍不完整。作者修正了错误 GSM8K 标签并发布 `gsm8k-fix`，但论文没有提供独立标签审计或完整变更理由。论文也未报告语义去重或预训练重叠分析。MATH 与 GSM8K 同时提供训练 prompt 和域内测试面，而四个域外评测也不能排除模型预训练污染。

代码与 DART Hugging Face card 声明 MIT，但这本身不能证明每个上游 MATH/GSM8K 条目及其合成衍生物都具有兼容权利。本次检查的 GitHub 仓库没有 tagged release，各数据集和模型又位于独立的可变仓库。复用者还需固定 revision、来源级许可证、逐行 manifest，以及依赖和 parser 版本，才能把该发布视为完整可复现的训练数据。
