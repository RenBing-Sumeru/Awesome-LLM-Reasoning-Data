The outcome verifier is the central modeling limitation. Regex extraction and SymPy equivalence can reject a valid answer rendered in an unsupported form or accept a response whose final value matches by accident; neither operation validates the intermediate CoT. The paper explicitly declines to distinguish answer correctness from process correctness. No calibrated false-accept/false-reject study or adversarial formatting test is reported.

Difficulty and budget are not intrinsic prompt properties. They depend on DeepSeekMath-7B-RL, temperature 1.6, top-p 0.95, the answer checker, and the number of trials. The paper body defines fail rate as the proportion incorrect, but Appendix B.2 displays an inconsistent equation; the repository clarifies `1-pass_rate`. The repository also says Prop2Diff still needs manual effort, and its public Uniform example uses potentially unbounded trials that must be stopped manually. Exact reported caps, seeds, scheduling, and immutable environment files are not fully pinned.

Release metadata is asymmetric. Final SFT sets contain only `query` and `response`; accepted-response pools and query-info tables restore useful provenance and aggregate sampling counts, but complete rejected-response text is not established. This prevents independent inspection of checker mistakes, repeated failure modes, and how many distinct bad rationales were discarded. The pool field `proc_correct_prob` is null, consistent with the absence of process supervision.

Source and evaluation audits remain partial. The authors correct erroneous GSM8K labels and release `gsm8k-fix`, yet the paper does not provide an independent label audit or a complete change rationale. No semantic deduplication or pretraining-overlap analysis is reported. MATH and GSM8K supply both training prompts and in-domain test surfaces, and the four out-of-domain evaluations do not remove possible model-pretraining contamination.

The code and DART Hugging Face cards declare MIT, but this does not by itself establish compatible rights for every upstream MATH/GSM8K item or synthetic derivative. The checked GitHub repository has no tagged release, while datasets and models are separate mutable repositories. Reusers need immutable revisions, source-level licensing, a row manifest, and dependency/parser versions before treating the release as fully reproducible training data.
