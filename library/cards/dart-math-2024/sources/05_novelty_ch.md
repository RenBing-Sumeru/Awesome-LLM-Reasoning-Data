作者分析的 MetaMathQA 增广等早期 rejection-tuning 流水线，会先给每题固定数量的原始响应，再让 verifier 随题目变化的通过率决定每个 prompt 最终贡献多少样本。这样，保留分布就意外地受题目难度支配：即使生成器投入更多试验后能够解出某道难题，该题仍可能从合成数据中消失。

DART 改变的是筛选目标。Uniform 让每题的已接受响应数相同；Prop2Diff 让已接受数量与生成器相关的失败率成比例，并另行保证覆盖。新数据对象并不是另一种 rationale，反馈接口仍是最终答案检查；具体贡献是把预算分配、目标达成率和逐题采样元数据提升为构造配方的一等要素。

ToRA 与 MARIO 已经会在未解题上投入额外计算，DART 也复用了标准 CoT 生成、rejection filtering 和 SFT。论文附录 A 的区分是：这些前序方法主要优化覆盖，而 DART 显式控制最终难度分布。因此，它不是单纯扩大语料：两个 DART 数据集仍约为 590k，并且与 VRT 的比较固定了最终保留规模。

对 reasoning-data 研究而言，这一方向的意义在于分开三个经常混淆的量：原始生成试验数、覆盖的唯一 prompt 数，以及最终接受的训练响应数。复用前仍需检查：难度估计能否迁移到其他生成器、parser 错误是否与难度相关，以及在对齐原始合成计算量而不只是最终数据规模后，增益是否仍存在。
