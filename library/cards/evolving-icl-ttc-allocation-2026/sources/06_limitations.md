The central procedure is transductive: it uses test questions and their verifier outcomes to construct demonstrations for other test questions. That can be appropriate for a batched deployment workload, but it can invalidate a conventional independent-example benchmark interpretation and makes ordering, grouping, and verifier access part of the result. Incorrectly verified answers may contaminate later prompts, retrieval can select superficially similar but misleading examples, and added demonstrations consume input context that the reported output-token accounting does not fully expose. The method also depends on API-model reproducibility and has no official implementation release to audit its exact prompts, embeddings, and response-processing details.
