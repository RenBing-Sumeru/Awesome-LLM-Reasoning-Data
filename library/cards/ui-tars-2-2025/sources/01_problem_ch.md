GUI 智能体的训练样本并不是“指令—最终答案”二元组，而是在可变软件环境中展开的一段 episode：策略接收任务、近期交互上下文与压缩记忆，读取像素或工具输出，发出 GUI 或 SDK 动作，再观察下一状态，直到成功、失败或触及预算边界。因而，合格的披露需要同时说明任务来源、状态与观测表示、动作空间、记忆、环境版本、终止规则、奖励以及记录血缘。

UI-TARS-2 处理的是如何规模化生成并优化这类长时程 episode。报告覆盖桌面、移动端、浏览器、终端、软件开发、MCP 风格工具和游戏场景；动作可以改写共享文件系统，后续观测也依赖此前动作。因此，一条轨迹只有和有状态环境及其重置条件放在一起才有可解释性。

该报告的方法级披露较丰富，但没有形成开放训练数据资产。论文列出来源类型、标注过程、过滤阶段、三条反馈路径与大规模沙箱架构，却未发布任务清单、episode 语料、接受/拒绝路由账本、奖励记录、环境镜像或 UI-TARS-2 权重。这里的审计重点，是把“被描述的数据工厂”与“已发布且可回放的数据集”严格区分开。
