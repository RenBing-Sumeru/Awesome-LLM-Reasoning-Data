The cold start combines several channels. CT uses task tutorials, instructional videos, internet demonstrations, in-house data, and later the training data from UI-TARS and UI-TARS-1.5, including open-source agent trajectories and in-house annotations. CT and SFT also mix agent material with general chat and reasoning data, with a smaller agent fraction in CT and a larger one in SFT. Counts, mixture weights, collection dates, and source licenses are unknown.

For in-situ CT annotation, software installed on annotators' personal computers records normal application use while annotators verbalize decisions through a think-aloud audio protocol. The paper distinguishes experts demonstrating complex tasks from novices exploring unfamiliar tasks. It builds a hierarchical task graph, assigns importance and difficulty scores, verifies executability, deduplicates tasks, and uses dual-annotator review. Audio is transcribed by ASR, aligned with screen actions, and refined by language models. Consent, redaction, retention, and privacy controls are not described.

Interactive SFT is on-policy and human-in-the-loop. In a controlled cloud VM or browser sandbox, the current model proposes a reasoning trace and action. An annotator either accepts the proposal or replaces it with a better trace/action, and the resulting complete episode is stored. The task pool and model are refreshed periodically so supervision follows the current policy distribution. Candidate counts, acceptance rates, disagreement handling, and annotator qualification rules are unknown.

RL task construction has three branches. GUI-Browsing creates screenshot-only information-seeking tasks without a search API: facts from authoritative sources are obfuscated, revealing attributes are removed, linked pages form multi-hop chains, and trivial prior-knowledge or single-search tasks are filtered. GUI-General starts from public website collections, excludes inaccessible, login-gated, static-information, and casual-game sites, uses a vision-language model to extract functions, removes simple functions, and composes executable multi-condition instructions; the report states coverage of 690 websites. Gameplay uses public HTML5/WebGL games and model-generated games whose code exposes state variables to JavaScript verifiers.

Reward follows the task branch. Function-verifiable games receive binary final correctness. GUI-Browsing predictions are compared with reference answers by a judge, identified in the analysis as GPT-4o. GUI-General lacks a formal verifier or reference answer, so UI-TARS-2 acts as a generative outcome reward model and emits a scalar success score from the complete text history plus the last five screenshots. This reward model is trained with targeted annotation and single-turn RL, but its data, checkpoint, prompt, calibration, threshold, and sampling procedure are not released.

Rollouts are fully asynchronous. A server-mode inference service is decoupled from the agent framework; stateful environments persist across tool calls; training begins when completed traces in a dynamic pool meet a minimum batch threshold, while unfinished traces remain for later iterations. PPO uses primarily final-outcome rewards, optional format rewards and length penalties, Decoupled GAE, Length-Adaptive GAE, value-model pretraining, and asymmetric clipping. Domain-specialized policies are then merged by parameter interpolation. The report leaves the numerical coefficients, learning rates, batch sizes, rollout counts, sampling settings, pool threshold, and compute budget unknown.
