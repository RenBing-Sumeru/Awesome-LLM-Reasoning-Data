冷启动由多条渠道组成。CT 使用任务教程、教学视频、互联网演示和内部数据，后续还纳入 UI-TARS 与 UI-TARS-1.5 的训练数据，其中包括开源智能体轨迹和内部标注。CT 与 SFT 还会混入通用对话和推理数据；CT 中智能体数据占比较小，SFT 中占比较大。总量、混合权重、采集日期和来源许可均为 unknown。

在 in-situ CT 标注中，标注软件安装在标注员个人电脑上，记录其正常使用应用的过程，同时采用 think-aloud 音频协议口述决策。论文区分了演示复杂任务的专家与探索陌生任务的新手，并构建分层任务图，设置重要度和难度分数，执行可运行性检查、去重和双人复核。音频经 ASR 转写，与屏幕动作对齐，再由语言模型润色。报告没有说明同意机制、脱敏、保留期限和隐私控制。

Interactive SFT 是 on-policy 的人机协同流程。在受控云虚拟机或浏览器沙箱内，当前模型提出推理轨迹和动作；标注员接受该建议，或改写为更合适的轨迹/动作，最终保存完整 episode。任务池与模型定期刷新，使监督分布跟随当前策略。候选数量、接受率、分歧处理和标注员资质规则均为 unknown。

RL 任务构造分三支。GUI-Browsing 构造仅依赖截图且不能调用搜索 API 的信息检索任务：从权威来源取事实，隐藏泄露答案的属性，以页面链接形成多跳链，并过滤可凭先验知识或单次搜索完成的任务。GUI-General 从公开网站集合出发，排除不可访问、需要登录、仅提供静态信息和休闲游戏的网站，再由视觉语言模型提取功能、删除过于简单的功能并组合可执行的多条件指令；报告给出的覆盖量是 690 个网站。Gameplay 使用公开 HTML5/WebGL 小游戏和模型生成游戏，后者在代码中暴露可由 JavaScript 验证器查询的状态变量。

奖励随任务分支变化。函数可验证的游戏获得最终二元正确性；GUI-Browsing 由 judge 对照参考答案，分析章节明确该 judge 为 GPT-4o；GUI-General 没有形式化验证器或参考答案，因此由 UI-TARS-2 充当 generative outcome reward model，根据完整文本历史与最后五张截图输出标量成功分。该 reward model 通过定向标注和单轮 RL 训练，但其数据、权重、输入指令、校准、阈值和采样流程均未发布。

rollout 完全异步：server-mode 推理服务与 agent framework 解耦，有状态环境在多次工具调用之间保持执行状态；动态池中完成的轨迹达到最小 batch 阈值后即开始训练，未完成轨迹留到后续迭代。PPO 主要使用最终结果奖励，并按场景加入格式奖励和长度惩罚，同时采用 Decoupled GAE、Length-Adaptive GAE、value-model pretraining 与非对称 clipping。各领域专用策略最后通过参数插值合并。系数、学习率、batch 大小、rollout 数量、采样设置、池阈值和算力预算均为 unknown。
