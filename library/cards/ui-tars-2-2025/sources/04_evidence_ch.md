最强的证据是“描述性披露”，而不是“资产发布”。第 2.1—2.6 节明确说明 ReAct episode、两级记忆、统一虚拟机与浏览器沙箱、CT/SFT/RL 飞轮、标注路径、任务合成、三类奖励、异步 rollout 池、PPO 稳定化方法和参数插值。这些信息足以在组件层面对预期流程进行审计，却不能提供复现流程所需的记录。

若干定量披露对方法描述形成约束：GUI-General 的任务构造覆盖 690 个网站；评估使用内部 15-game collection；reward model 分析使用 300 条人工标注的内部 GUI-agent 轨迹，并报告二元结果分类 F1 为 83.8，同时承认假阳性率相对较高。假阳性现象直接关系奖励可靠性；F1 分数并不能证明训练 episode 的来源或标签质量。

论文还给出 RL 奖励上升、交互轮数变化、value pretraining 与 PPO 变体消融，以及下游 benchmark 结果。这些结果可以支撑“模型在作者设置中的行为表现”，但不能证明底层数据的质量、合法性、代表性、去重程度或可复现性；而且内部环境兼容性问题使 TerminalBench 的 80 个任务中有 5 个未参与评估。

实际发布证据比论文中的方法主张更窄。官方 UI-TARS 仓库公告 UI-TARS-2，并链接技术报告和 showcase；UI-TARS-desktop 是采用 Apache-2.0 的客户端与 agent stack。经核验，这两个仓库均未提供报告所述任务语料、轨迹与奖励记录、虚拟机镜像、游戏验证器包或 UI-TARS-2 权重。ByteDance Seed 官方 Hugging Face 检索也没有对应数据集；名称相近的 UI-TARS-2B-SFT 指向更早的 arXiv:2501.12326，不能视为本报告权重。
