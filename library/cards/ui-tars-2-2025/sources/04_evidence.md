The strongest evidence is descriptive rather than distributive. Sections 2.1-2.6 specify the ReAct episode, two-level memory, unified VM and browser sandboxes, CT/SFT/RL flywheel, annotation paths, task synthesis, three reward routes, asynchronous rollout pool, PPO stabilizers, and parameter interpolation. These details make the intended pipeline auditable at the component level, but they do not provide records with which to reproduce it.

Several quantitative disclosures constrain the account. The GUI-General task builder covers 690 websites. The evaluation uses a 15-game in-house collection. The reward-model analysis uses an in-house set of 300 human-annotated GUI-agent traces and reports F1 83.8 for binary outcome classification, while also acknowledging a relatively high false-positive rate. That false-positive finding is directly relevant to reward reliability; the F1 score is not evidence that the training episodes are correctly sourced or labeled.

The report presents rising RL rewards, interaction-round dynamics, ablations for value pretraining and PPO variants, and downstream benchmark results. These can support claims about the trained model's observed behavior under the authors' setup. They do not establish the quality, legality, representativeness, deduplication, or reproducibility of the underlying data, and the internal environment prevented evaluation on five of 80 TerminalBench tasks.

Release evidence is narrower than the paper's method claims. The official UI-TARS repository announces UI-TARS-2 and links the report and showcase; UI-TARS-desktop is an Apache-2.0 client and agent stack. Neither checked repository provides the reported task corpus, trajectory and reward records, VM images, game-verifier bundle, or UI-TARS-2 model weights. ByteDance Seed's official Hugging Face search returns no corresponding dataset; the similarly named UI-TARS-2B-SFT model points to the earlier arXiv:2501.12326 paper and must not be treated as this report's checkpoint.
