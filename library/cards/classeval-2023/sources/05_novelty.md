The prior baseline is function-level code generation where a prompt and unit tests often cover one isolated entry point. ClassEval changes the object to an object-oriented class with constructor state, fields, method dependencies, imports, and multiple strategy-specific prompts. The direction signal is that code reasoning benchmarks should expose dependency metadata and class/method-level verdicts separately. The quality signal is the manually crafted dataset, explicit JSON schema, official evaluation code, leaderboard, and Hugging Face release. What is not new: unit-test execution and Pass@k. Before reuse, inspect test coverage, hidden/public policy, Python/runtime dependencies, data license, solution leakage, and whether generated code can exploit tests.
