ClassEval asks whether LLM code ability on single-function benchmarks transfers to class-level Python programming, using the August 2023 arXiv paper and official FudanSELab release as primary sources. The gap is that HumanEval/MBPP-style tasks usually test standalone methods, while real code often requires constructors, fields, inter-method dependencies, imports, and whole-class tests. The data object is a JSON task with class skeleton, tests, ground-truth class code, method metadata, dependencies, and expected outputs through executable tests. This card belongs as a code-executable evaluation surface, not a training dataset. Its atlas value is the clear terminal predicate: generated class code either passes the official tests or it does not.
