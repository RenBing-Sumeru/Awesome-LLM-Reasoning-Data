Go-Browse combines a global reset-and-explore loop with local instruction-first collection. Its outer loop maintains a frontier of discovered but not fully explored URLs and stores trajectory edges, so a later episode can reset to a useful page instead of rediscovering it from the root. At each frontier node, NavExplorer interactively proposes navigation tasks, PageExplorer proposes local tasks, FeasibilityChecker lets Claude-3.7-Sonnet attempt each task and asks a GPT-4o VLM judge whether the attempt succeeded, and cheaper Solvers then sample two prefixed and two unprefixed trajectories. The primary feedback object is therefore a judgment-filtered environment episode: a binary success decision is used for feasibility and dataset inclusion, while WebArena task-specific rewards are used only for benchmark evaluation. Compared with NNetNav-style interaction-first episodes, the graph retains cross-episode navigation knowledge; compared with ordinary instruction-first collection, task proposal occurs at many dynamically reached pages rather than only a root observation.
