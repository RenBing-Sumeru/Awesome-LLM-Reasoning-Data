For Rollout, Search, and Test-Time Trace Data, Go-Browse is useful as a design and audit case for multi-attempt browser collection: a reusable record can preserve the URL frontier, graph edge/prefix, task proposal, each feasibility attempt, judge output, prefixed versus unprefixed start state, solver identity, step observations/actions/errors, reward, and acceptance outcome. For Environment and Agent Trajectory Data, the raw release provides state-action episodes tied to a concrete BrowserGym/WebArena substrate, while the processed release provides prompt/completion records suited to SFT and the released checkpoint provides a downstream reference. The success/failure trajectories could support future agent-training or verifier studies, but the paper only demonstrates successful-trajectory SFT and evaluation; RL use remains a proposed direction. Before reuse, practitioners should pin revisions, reconcile raw/processed rows, inspect failure and judge records, establish environment resetability and rights, and keep collection-time VLM judgment separate from benchmark task reward.
