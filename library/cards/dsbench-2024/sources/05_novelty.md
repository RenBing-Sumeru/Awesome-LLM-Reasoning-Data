The prior baseline is data-science evaluation with simplified code snippets, single tables, or narrow APIs. DSBench changes the object to longer, file-heavy workflows where an agent must inspect task background, manipulate data files, reason over tables or images, and deliver either an analysis answer or a modeling result.

The direction signal is evaluation of autonomous data-science workflow execution, not just code syntax or library completion. The quality signal is realistic source material, separate analysis/modeling tracks, released scripts, and reported gap metrics against strong agents. What is not new: using Kaggle/ModelOff-style tasks, notebooks, and metric aggregation. Reuse checks should inspect data ownership, non-commercial restrictions, processed-file provenance, judge dependency, API costs, and whether hidden/source data can still be obtained.
