For the `rollout_search_test_time_trace_data` track, WebSeer is a concrete schema for recovery-oriented search episodes. A reusable record should preserve the input and accepted answers; every reasoning segment, query, URL, page-reader prompt and response, Python call, observation, submission, scalar feedback, verifier judgment and evidence path; plus attempt index, stopping reason, environment/API versions, model revision, and reward settings. Rejected verifier samples and budget-stopped episodes are needed for calibration and failure analysis, not only successful repaired traces.

The SFT and RL releases can support agent SFT, on-policy RL experiments, trajectory analysis, and studies of when extra test-time search is useful, provided their revisions and licenses are pinned. Researchers should keep three objects separate: released training episodes, repository model outputs, and benchmark evaluation records. The last of these measures a system and should not be backfilled as a quality label for every intermediate step.
