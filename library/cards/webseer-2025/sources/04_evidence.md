The paper evaluates the trained policy on open-domain QA suites and reports 72.3% on HotpotQA and 90.0% on SimpleQA for its 14B model. More informative for the recipe are the ablations: restricting RL to a single answer lowers scores on both reported ablation tasks, and removing the cold start destabilizes training. The scale analysis also reports that 3B and 7B runs can develop repetitive text or malformed tool-call JSON even when reward initially rises. These observations support the roles of multi-submission feedback and cold-start data; they do not validate every trajectory or establish a general scaling law.

Official artifacts include the Apache-2.0 GitHub repository, `WebSeer-14b`, an Apache-2.0 SFT dataset, and an Apache-2.0 RL dataset. The SFT repository exposes a train Parquet file; the RL repository exposes train and test Parquet files. The GitHub repository includes training code and model-output files, but its README says complete evaluation scripts will be released later. It has no tagged release, so a reproducer must pin a commit as well as the dataset and model revisions.

Benchmark accuracy is evidence about the evaluated system under its stated tools and judge. It is not proof that the released data have complete lineage, calibrated verifier labels, adequate decontamination, or replayable web observations.
