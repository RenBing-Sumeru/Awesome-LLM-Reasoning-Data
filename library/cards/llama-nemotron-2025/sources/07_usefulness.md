For `frontier_reports_data_disclosure_ledger`, this is a strong anchor Card because it separates disclosure into inspectable layers. The weights are verifiably hosted on official NVIDIA model pages. The post-training dataset is an official versioned artifact with visible schemas and files. The paper documents domain generation and selection, and it identifies SFT, GRPO, RLOO, RPO, rewards, and model-specific schedules. Benchmark claims remain a fourth, separate layer.

Data builders can reuse the domain patterns without assuming the published corpus is perfectly replayable. Useful patterns include explicit reasoning-mode metadata; keeping prompt, output, generator, license, version, and model membership; using multiple candidates; domain-appropriate answer, syntax, format, or reward checks; reporting candidate budgets; and filtering RL prompts by empirical difficulty. A stronger implementation should also retain rejected candidates, verifier outputs, source IDs, immutable revisions, and stage-specific manifests.

Auditors can use the release to test whether claimed openness is operational. They should pin the dataset commit, count raw rows by configuration and category, compare those counts to Table 2 and generator tables, test schema consistency, sample license/provenance fields, inspect reasoning-on/off pairing, and reproduce verifier decisions on a stratified sample. For RL, they should distinguish released prompts from unreleased policy rollouts and reward histories.

The dataset's scale and model scores should not be used as a proxy for quality. Appropriate reuse requires per-record rights review, independent decontamination against the user's evaluation suite, process-aware validation of reasoning, safety and PII sampling, and explicit accounting of which released rows enter each training stage. Those additions would turn a strong disclosure artifact into a more reproducible recipe.
