The data design teaches a single model to switch between detailed reasoning and direct answering. Reasoning examples receive the system instruction `detailed thinking on`; direct-response examples receive `detailed thinking off`. For some prompts, the release contains paired responses in both modes. The SFT rows expose input messages, output text, category, license, reasoning mode, generator, intended model membership, version, and system-message instruction, making the control signal visible rather than implicit.

Construction is domain-specific rather than governed by one universal teacher or verifier. Math uses AoPS extraction, many candidate solutions, answer-equivalence judgment, and majority voting when a final answer cannot be extracted. Code uses competitive-programming sources, deduplication, contamination checks, DeepSeek-R1 generation, trace/code parsing, and syntax validation. Science combines StackOverflow and synthetic questions, benchmark decontamination, DeepSeek-R1 traces, and majority voting. General prompts use multiple generations and Llama-3.1-Nemotron-70B-Reward rejection sampling. A Feedback/Edit/Select pipeline refines 20,000 first-turn general prompts.

The training contract also varies by model. SFT transfers reasoning traces and reasoning-mode control to all three models. Large-scale scientific-reasoning GRPO is applied only to LN-Ultra, with answer and format rewards. LN-Super and LN-Ultra receive short instruction-following RL; chat alignment uses online RPO for Super and GRPO for Ultra, while Nano uses two offline RPO rounds. The released RL configuration exposes instruction-following prompt constraints, but not the full policy rollout and reward history for these stages.
