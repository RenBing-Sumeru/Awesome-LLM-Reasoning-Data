- **Question boundary and contamination.** The benchmark release contains 830 filtered queries, not BrowseComp's original 1,266. Because the parent questions and answers are public and reversibly decodable, future models may absorb them. The reported roughly 20% o3 and 26% GPT-5 parametric-only accuracy is a possible exposure signal, not a contamination measurement.
- **Reversible canary.** Query payloads use a public canary and base64/XOR transform derived from a public SHA-256 key. The key and decryptor are public, so this deters accidental ingestion but provides neither secrecy nor model-weight decontamination.
- **Incomplete qrels.** Human evidence and gold labels cover the constructed pool, not every relevant document in the world or in an expanded corpus. Added relevant documents can be scored as false negatives; o3-generated candidate URLs also bias which evidence enters the pool. Retrieval and citation metrics must therefore be read as judgments against incomplete qrels.
- **Citation predicate.** Citation scoring matches numeric document IDs against evidence qrels. It does not check whether the cited passage entails the associated claim, whether the citation is placed correctly, or whether the final explanation is complete.
- **Judge drift.** The archival paper uses GPT-4.1 for semantic equivalence, while current public code defaults to Qwen/Qwen3-32B. Appendix G reports 65.18%, 70.12%, and 71.69% for substring, GPT-4.1, and Qwen3 grading on the same GPT-5 plus Qwen3-retriever condition. A score without the judge snapshot, prompt, and configuration is not an exact reproduction.
- **Failure retention.** Current producer code can serialize returned responses with non-completed status, and evaluation treats non-completed or missing-output runs as failures or parse errors. Query-level exceptions may stop before any record is written. Construction rejects are disclosed only as aggregate counts, and the four public run files have not been exhaustively audited for row count or completed/incomplete/error distributions.
- **Partial trajectory release.** Only BM25+GPT-5, BM25+o3, Qwen3-Embedding-8B+GPT-5, and Qwen3-Embedding-8B+o3 archives are visible. No released trajectories were verified for other evaluated agents or retrievers, and coverage of all 830 items in each visible file is unknown.
- **Extraction and task scope.** Selenium/Trafilatura text extraction omits or degrades interactive pages, dynamic layouts, multimedia, and some PDF content. Forty-two map/distance tasks and thirteen ambiguous or non-unique-answer tasks were among explicit removals. The retained benchmark assesses short answers and document citations, not full deep-research reports.
- **Version and exact replay.** Code and Hugging Face artifacts have separate histories, the repository has no release tag, the corpus revision is unknown, and no immutable manifest binds queries, corpus, indexes, trajectories, prompts, dependencies, agents, and graders. Proprietary API snapshots, seeds, retry state, some service versions, and rollout counts are undisclosed; exact historical replay is therefore false even though controlled reruns are more feasible than on a live web.
- **License and privacy.** Code and the query/corpus/index repository cards show MIT metadata, arXiv v1 is CC BY 4.0, the archival-paper license is recorded as unknown, and the trajectory repository has no verified license. Repository-level MIT metadata does not establish rights to relicense scraped third-party pages. PII scanning, robots/terms review, takedown procedure, and annotator compensation and consent are unknown.
- **Use boundary.** Evidence supports evaluation only. The paper does not establish SFT, distillation, preference learning, reward modeling, process supervision, RLVR, or agent-training use, and benchmark performance does not prove data quality or training utility.
