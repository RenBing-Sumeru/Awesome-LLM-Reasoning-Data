**方法与反馈。** Lean checking 只对编码后的 statement 和当前 dependency environment 精确，不能证明人工 formalization 忠实表达原始自然语言题目。通过检查的 sketch 也可能引入数学上有效、搜索上无用的 subgoal。LEAP 将这一区分交给 LLM reviewer；Putnam A5 ablation 展示了一项收益，但论文没有报告 reviewer calibration、false-positive/false-negative rate、替代 reviewer 或 prompt-change robustness。搜索成本高且不稳定：Putnam 成功证明使用 46 至约 3,000 次 LLM call，论文的 future work 也把 branch prioritization 与 compute allocation 列为开放问题。

**数据与发布。** 官方仓库提供 benchmark CSV 和成功 proof file，但没有 LEAP 实现、prompt、model configuration、DAG state schema、compiler-feedback history、reviewer output 或失败/被拒候选。成功样本-only 发布使 branch waste、verifier-triggered repair、reviewer bias 和 failure retention 无法审计。公开物也没有 Lean toolchain、Mathlib lock 或 LeanSearch-index manifest。仓库虽声明软件为 Apache-2.0、其他材料为 CC-BY，下游仍应保留逐题 source metadata，并单独审查原始竞赛材料的权利。

**实验与泛化。** 结果依赖 Gemini 3.1 Pro、LEAP 的两个 rollout 和各方法不同的预算；solve-rate comparison 不是 compute-matched comparison。Geometry 仍只有 Basic 1/6、Advanced 1/8。论文未报告 pretraining overlap 或 decontamination，两个对照系统为 proprietary 或难以完整复现。case study 形式化的是 Hamiltonian decomposition 构造中 Color-2 planar routing subproblem，而非完整 open problem。Curator inference：即使算法描述不变，model-service drift、Mathlib 更新或 retrieval index 变化也可能改变验收与搜索行为。
