- SFT success boundary: the 9,022 claimed released SFT trajectories are real transcripts, but SFT scenarios omit check functions and the public SFT environment returns zero reward. Retention verifies syntax, completion markers, length, and an LLM impossibility judgment—not terminal task success.
- RL release boundary: verifier-bearing RL scenarios are public and the paper describes online RL episodes, yet no RL rollout corpus, per-step reward archive, complete final-state log, or success/failure accounting was found. The runtime schema must not be reported as released data.
- Verifier coverage: generated Boolean checks may omit intended constraints, over-constrain valid solutions, depend on brittle state fields, or reward terminal-state shortcuts. This is a curator inference grounded in the generated-check contract; no independent false-positive/false-negative, coverage, reward-hacking, or adversarial audit is reported.
- Selection semantics: environment acceptance combines warning with pass in a not-fail rate of at least 0.85. Raw votes, disagreement, calibration, rejected checks, and the 75 rejected environment programs/logs are missing, so strict correctness and selection bias cannot be reconstructed.
- Termination versus correctness: Task Completed, ###STOP###, and action limits end episodes independently of checklist reward. A trajectory can terminate cleanly while incomplete or incorrect, and a generated check can be gamed without violating the stop rule.
- Executable-code risk: environment classes and check strings run through Python exec with builtins available. The release is not sandboxed; malicious or defective generated code can affect files, processes, credentials, or network state unless replay is isolated. This is a code-safety boundary, not proof that the inspected release is malicious.
- Loader defect: the pinned SFT trajectory revision mixes incompatible raw and instruction/input/output/system/history schemas, causing DatasetGenerationCastError in the default Hugging Face builder/viewer. Individual raw files remain accessible, but default loading is not a reproducible one-command path.
- Version and replay: no tag, GitHub Release, dependency lock, or immutable manifest binds arXiv v2, commit 87e6673, four HF revisions, prompts, endpoints, seeds, and exact model artifacts. State diffs, dependency images, complete rewards, and paper-run replay fixtures are also missing.
- Split, overlap, and contamination: the paper uses 140 environments for SFT and 51 for RL, then evaluates on BFCL-v3 multi-turn, Tau-Bench, and ACEBench-Agent. Split seed/policy, semantic deduplication, source/benchmark overlap, and pretraining or future-public-exposure audits are undisclosed.
- Lineage and rights: repository and dataset cards state MIT, but per-row API-Bank/ToolACE provenance, upstream transformation rights, provider-output terms, prompts, generator/checker responses, and the scope of the root license over every object are not separately established.
- Failure retention: malformed, incomplete, length-invalid, and LLM-judged-impossible SFT cases are dropped; 75 environments are rejected; RL rollouts are not published. Rejection counts by trajectory reason, discarded samples, raw checks, and successful/failed episode corpora are unavailable.
- Generalization and simulator limits: authors note synthesis bias, limited open environments, and missing real latency, network, and error dynamics. The simulated-user model/version, prompts, decoding, retry behavior, and stop-policy details are incomplete. The Qwen3-1.7B Tau-Bench decline also shows that RL gains are not uniform.
