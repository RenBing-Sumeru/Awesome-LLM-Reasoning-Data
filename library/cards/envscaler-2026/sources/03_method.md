Inputs and discovery. The source pool is API-Bank and ToolACE. Tasks are filtered for stateful, domain-specific tool interaction, transformed by LLMs into environment descriptions, embedded, and deduplicated. GPT-4.1 and Qwen3-235B-Instruct-2507 support discovery and programming; GPT-4.1-mini and Qwen3-30B-A3B-Instruct-2507 support checking and assessment. Per-record upstream IDs, source-mixture weights, complete transformation prompts, model endpoint dates, decoding settings, and retry policy are not released.

Environment synthesis and selection. SkelBuilder produces Python state, constraints, operations/tools, class code, definitions, and documentation. The paper reports 266 synthesized candidates. Each receives 100 checking rounds, and the released selector keeps an environment when not_fail_num / total_num is at least 0.85. The numerator combines pass and warning, so 0.85 is a pass-or-warning threshold, not a strict 85% correctness rate. The process retains 191 environments and rejects 75, or 28.2%; the rejected programs and complete check-agent records are unavailable.

Scenario construction. ScenGenerator synthesizes initial configuration, task text, checklist items, and executable Python Boolean check functions. The SFT branch selects 140 environments and releases 4,684 task/configuration rows with the check functions intentionally omitted. The RL branch uses the remaining 51 environments and releases 2,550 task/configuration rows with checklist_with_func. The split seed, selection policy beyond the 140/51 counts, semantic overlap, and decontamination analysis are unknown.

SFT interaction and filtering. Qwen3-30B-A3B-Thinking-2507 generates both conversation and non-conversation trajectories. The public filtering path rejects invalid syntax, incomplete episodes, LLM-judged-impossible tasks, and trajectories outside 3–29 actions for non-conversation or 5–39 for conversation. Non-conversation retention requires Task Completed; conversation retention requires user ###STOP###. Roughly 9K remain, and the pinned dataset claims 9,022 trajectories. Because SFT scenarios omit checks and the SFT environment returns zero reward, this is format/completion/action-count filtering rather than terminal-state success verification.

SFT optimization. The paper and configuration use full-parameter LlamaFactory SFT for three epochs at learning rate 1e-6, maximum length 32K, and effective batch size 256. Multi-round examples use mask_history so only the final-turn reasoning/action is supervised. The scaling study trains Qwen3-1.7B, Qwen3-4B, and Qwen3-8B variants; exact model-artifact revisions for every run are not bound in one manifest.

RL interaction and reward. RL uses non-conversation interaction, ROLL/Reinforce++, KL coefficient 0.1, 64 tasks with 8 rollouts each per update step, and up to roughly 200 steps. This implies 512 online rollouts per update step, not a released corpus. The paper sets maximum trajectory length to 32K and per-interaction generation length to 4K; the example configuration additionally uses seed 42, temperature 0.99, top-p 0.99, top-k 100, learning rate 1e-6, max_steps 201, and max_actions 40. Final reward is passed Boolean checks divided by total checks.

Runtime and safety. The interaction runner may preserve task information, tools, messages, user messages, per-step observations/actions/rewards, terminated/truncated flags, total reward, final observation/information, and step count. That schema is runtime capability, not evidence that RL episodes were released. Environment class strings and check-function strings execute through Python exec with builtins available. The code is not a security sandbox; any replay must isolate these artifacts as untrusted executable code.

Release reconstruction. The evidence freeze binds paper v2, code commit 87e6673, and four HF revisions: 191-Env 3d30c6a, SFT-Scenario bf3bf86, RL-Scenario a140615, and SFT-Traj-9K 0279d9a. No Git tag, GitHub Release, dependency lock, or immutable manifest binds all of them to prompts, model endpoints, and seeds. The SFT trajectory revision also mixes a raw trajectory file with a transformed instruction/input/output/system/history file. Their incompatible schemas make the default Hugging Face builder/viewer fail with DatasetGenerationCastError, although individual raw files remain downloadable.
