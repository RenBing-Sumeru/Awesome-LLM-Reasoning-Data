**Task sourcing and gold extraction.** CodeScout begins from SWE-Smith issue-resolution instances. The paper reports a filtered pool of about 39K Python issues across 128 repositories; the pinned processed task artifact contains 39,287 rows. Processing excludes pull requests that create or delete files, drops empty issue descriptions, and ignores non-Python targets. The gold patch is parsed into modified files, modules/classes, and functions/methods. The authors extend LocAgent-style parsing to cover added members and class attributes, imports and global variables, while ignoring docstring-only edits.

**Environment and agent interface.** Each task supplies a faulty repository state before the resolution pull request. The processed SWE-Smith build path applies the bug-inducing patch, after which OpenHands-Bash exposes a Unix terminal at a known repository path. The agent searches with ordinary command-line tools; the paper reports ripgrep 15.1.0. Project dependencies are not installed and tests are not executed. The structured `LocalizationFinish` tool submits one or more file locations, optionally refined to class and function names.

**Validity and reward.** A prediction must contain exactly one parseable finish action and pass path/location sanity checks. The verifier computes set precision and recall at three granularities and converts each to F1; empty or invalid submissions receive zero. The sum of file, module, and entity F1 is in [0,3]. CodeScout-14B adds one reward point for exactly four turns, independently of localization correctness. This auxiliary term encourages a particular interaction length, but it does not make the terminal localization label process-level supervision.

**Direct 4B and 14B rollout generation.** CodeScout-4B starts from Qwen3-4B-Instruct-2507. CodeScout-14B starts from Qwen3-14B with thinking disabled and a modified chat template. Both sample at temperature 1.0 under an asynchronous SkyRL/OpenHands pipeline. Paper-side 4B training uses 200 steps, batch size 8, eight rollouts per instance, 40K context, and six turns. Paper-side 14B training uses 300 steps, batch size 32, four rollouts per instance, 50K context with YaRN, and four turns.

**Optimization scaffold.** The method uses modified asynchronous GSPO with sequence-level importance ratios and allows rollout policies to be up to four optimizer steps stale. It omits a KL term, entropy loss, and advantage standard-deviation normalization. Reported shared settings include AdamW, constant learning rate \(10^{-6}\), clipping bounds \(3\times10^{-4}\) and \(4\times10^{-4}\), one update epoch per batch, and eight H100 GPUs. In-progress inference is terminated after weight synchronization; maximum-step, no-finish rollouts have their policy-loss mask set to zero.

**Separate 1.7B RFT/RL path.** CodeScout-14B samples trajectories on 7.7K random training instances. Only trajectories with file, module, and entity F1 all equal to 1 are retained, producing 4K RFT examples. Qwen3-1.7B is fine-tuned for one epoch and then receives RL on 800 disjoint instances, using 100 steps, batch size 8, eight rollouts, 32K context, and four turns. These 1.7B rollouts are not in the checked public training-rollout release.

**Published layout.** The official Hugging Face artifact has two configurations and two one-file `train` splits: `CodeScout_14B/train-00000-of-00001.parquet` with 39,040 rows and `CodeScout_4B/train-00000-of-00001.parquet` with 15,805. Top-level fields are `instance_id`, `reward_dict`, `chat_messages`, `step`, and `rollout_number`. Conversations contain role/content blocks, tool calls and IDs, plus tool schemas. Rows do not contain repository URL, exact commit, applied patch, gold targets, checkpoint SHA, seed, token count, stop reason, loss mask, logprobs, or error category.

**Version and configuration audit.** The inspected code is commit `34789dcb21cc9e6595c2d27ad832f69ab146006f`; the rollout release is commit `65a3599683b901be691621f9eab7cd932a9a2c5f`. Current scripts do not directly reproduce the paper settings: the 14B script defaults to eight rollouts and six turns rather than four/four, while the 4B script defaults to ten turns rather than six. Although Hydra overrides can change some values, the exact paper launch commands have not been published.
