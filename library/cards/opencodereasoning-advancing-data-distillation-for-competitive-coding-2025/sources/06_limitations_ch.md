- **功能有效性：**格式检查和 Tree-sitter 可以拒绝畸形输出，但无法发现错误算法、遗漏边界条件或看似可信却无效的推理。发布 schema 没有为每一行附加单元测试结果。
- **选择混杂：**“错误”和“正确”的两个 151,251 行子集覆盖不同的难度和问题分布；不筛选条件还有 445,618 行，规模也更大，因此消融无法把目标正确性隔离为单一因果变量。
- **版本漂移：**论文总数为 736,712 行和 28,904 个问题；HF 1.0 总数为 735,255 和 28,319。当前面向 OCR-2 的配方使用 32 个种子与 28,768 个生成 token，而没有冻结 OCR-1 的 16k 设置。
- **去重与污染：**精确匹配去重会遗漏语义重复。阈值 0.7 的检索筛查和两个 LLM judge 可能产生假阴性，人工检查的 90 对也没有公开决策 manifest。
- **Lineage 与失败：**原始随机种子、rollout 数、job/chunk manifest、拒绝率、被拒响应和逐行执行结果均不可用。split_1 还依赖通过索引重建的外部 APPS/TACO 行。

- **评测：**OCR 行基于重复生成取平均，而表 2 说明 baseline 只运行一次。结果覆盖竞赛编程，不能证明一般代码正确性、安全性、可维护性或跨领域推理质量。
