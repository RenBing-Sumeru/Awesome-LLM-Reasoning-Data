主要评测使用 LiveCodeBench 2408-2502（279 个问题）和 CodeContests。论文报告 LiveCodeBench 的平均 pass@1 基于 64 次生成，CodeContests 基于 16 次生成，而表 2 说明 baseline 行只运行一次。在完整 Python 语料上做 3 个 epoch 的 SFT 后，OCR-Qwen-32B 在 LiveCodeBench 和 CodeContests 上达到 61.8 与 24.6；R1-Distill-Qwen-32B 为 58.1/18.3，QwQ-32B 为 61.3/20.2，DeepSeek-R1 为 65.6/26.2。OCR-Qwen-7B-Instruct 达到 51.3/18.1。这些是论文评测协议下的模型结果，不是对行级正确性的直接测量。

扩展曲线从 25k 增长到 100k，最终达到 736k 条样本；作者报告曲线尚未饱和，并把最后阶段的最大增益归因于加入独特、多样且困难的问题。论文没有用完整析因设计分离“唯一问题数”和“响应总数”的影响。

执行过滤消融给出最重要的负结果：

| Qwen2.5-14B-Instruct 训练子集 | 行数 | LiveCodeBench | CodeContests |
|---|---:|---:|---:|
| 全部 CodeContests 来源行 | 445,618 | 54.1 | 16.59 |
| 通过单元测试的行 | 151,251 | 47.0 | 15.34 |
| 等量且全部失败的行 | 151,251 | 52.3 | 15.53 |

作者将这一结果与失败样本中困难问题占比更高联系起来，并主张重视指令多样性。可支持的结论更窄：在该选择设置中，只保留正确解会删除有用的问题覆盖；它不能说明错误推理本质上是更好的训练数据。

对 OCR-Qwen-32B-Instruct，加入 356K 条 C++ 样本后，LiveCodeBench/CodeContests/IOI 从 61.7/24.4/145.5 变为 61.5/25.5/175.5，说明存在语言特定的 IOI 迁移，但 Python benchmark 没有一致增益。最后，论文的 736,712 条总数与 HF 1.0 卡片的 735,255 不同；这一发布差异是固定版本的依据，不是数据质量证据。
