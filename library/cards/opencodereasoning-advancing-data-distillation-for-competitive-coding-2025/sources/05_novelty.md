Earlier reasoning-distillation releases discussed in the paper commonly contain 17k-114k question-solution pairs; KODCODE reports 447K DeepSeek-R1 samples but trains on smaller LLM-test-validated subsets. OpenCodeReasoning's concrete change is to combine 736,712 Python responses, 28,904 paper-version questions, explicit source fields, a contamination workflow, staged scaling, and correctness/language ablations in one release-and-training study.

The teacher, nucleus sampling, answer-level SFT, Tree-sitter parsing, public question sources, unit tests, and LLM-as-judge screening are existing components. The work's contribution is their scale and controlled comparison, especially the observation that execution-only filtering changes the problem distribution and can reduce downstream scores. It is not a new verifier, reward model, or process-supervision interface.

For reasoning-data research, the directional value is to treat instruction support, response multiplicity, correctness labels, and training scale as separate variables. Reuse still requires checking whether the released revision preserves the experimental mixture, whether semantic duplicates remain, how many candidates each question received, which failures were dropped, and whether source licenses permit the intended training use.
