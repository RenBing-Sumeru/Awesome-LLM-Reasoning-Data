- **Functional validity:** format checks and Tree-sitter can reject malformed output but cannot detect wrong algorithms, missing edge cases, or persuasive yet invalid reasoning. The release schema does not attach a unit-test result to every row.
- **Selection confounding:** the “incorrect” and “correct” 151,251-row subsets cover different difficulty and instruction distributions. The 445,618-row no-filter condition is also larger, so the ablation cannot isolate target correctness as a single causal variable.
- **Version drift:** paper totals are 736,712 rows and 28,904 questions; HF 1.0 totals are 735,255 and 28,319. The current OCR-2-oriented recipe uses 32 seeds and 28,768 generated tokens instead of freezing the OCR-1 16k setup.
- **Deduplication and contamination:** exact-match deduplication misses semantic duplicates. The 0.7 retrieval screen and two LLM judges can produce false negatives, and the 90 manually reviewed pairs are not accompanied by a public decision manifest.
- **Lineage and failures:** original random seeds, rollout count, job/chunk manifests, rejection yields, rejected responses, and per-row execution outcomes are unavailable. split_1 also depends on external APPS/TACO rows reconstructed from indices.
- **Rights:** the HF release is labeled CC BY 4.0 but tells users to inspect each underlying dataset license; platform terms and source licenses are not replaced by the aggregate label. Apache-2.0 covers the current code, not automatically the data.
- **Evaluation:** OCR rows are averaged over repeated generations while Table 2 says baselines were run once. Results cover competitive programming and do not establish general code correctness, security, maintainability, or cross-domain reasoning quality.
- **Reproducibility:** hardware type and training hyperparameters are disclosed, but hardware count, original packing/order manifests, checkpoint hashes, complete compute, and an independent OCR-1 reproduction are not verified.
