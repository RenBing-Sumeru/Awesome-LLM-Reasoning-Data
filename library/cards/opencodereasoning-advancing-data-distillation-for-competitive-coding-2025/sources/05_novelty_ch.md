论文讨论的早期推理蒸馏发布通常含 17k-114k 个问题—解答对；KODCODE 报告 447K 条 DeepSeek-R1 样本，但只在经过 LLM 测试验证的较小子集上训练。OpenCodeReasoning 的具体变化，是在同一项发布与训练研究中结合 736,712 条 Python 响应、论文版本的 28,904 个问题、显式来源字段、污染流程、分阶段扩展，以及正确性和语言消融。

教师、nucleus sampling、answer-level SFT、Tree-sitter 解析、公开问题源、单元测试和 LLM-as-judge 筛查都是已有组件。该工作的贡献是扩大并受控比较这些组件，尤其是观察到“只按执行结果筛选”会改变问题分布，并可能降低下游分数。它不是新的 verifier、reward model 或过程监督接口。

对推理数据研究，其方向性价值是把问题支持集、每题响应数、正确性标签和训练规模视为独立变量。复用前仍要检查：发布版本是否保留实验混合、是否残留语义重复、每题生成了多少候选、哪些失败被丢弃，以及来源许可是否允许预期训练用途。
