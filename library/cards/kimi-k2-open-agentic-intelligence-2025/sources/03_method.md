For agentic SFT, the tool repository combines real MCP tool specifications fetched from GitHub with hierarchically evolved synthetic tools. The report says the system synthesizes thousands of agents from system-level instructions and tool combinations, creates tasks with explicit success, tool-use, and evaluation rubrics, and simulates multi-turn interactions using LLM-generated user personas. A stateful tool simulator executes calls, updates state, and introduces controlled successes, partial failures, and edge cases. An LLM judge retains only trajectories meeting the task rubrics.

The report adds real sandboxes when simulation fidelity is insufficient, especially for coding and software engineering. These environments execute code and use objective signals such as test-suite pass rates. For RL, it reports a Gym-like framework with math, STEM, logic, instruction-following, faithfulness, coding/SWE, safety, and general tasks. Math/STEM/logic prompts use expert annotation, internal extraction, and open datasets; pass@k of the SFT model selects moderate difficulty. Coding uses open and synthetic problems/judges plus human-written unit tests retrieved from pre-training data, while SWE environments are built from GitHub pull requests, issues, and executable tests.

Feedback is mixed. Instruction following combines code-interpreter checks, LLM-as-judge, and hack detection; faithfulness uses a sentence-level judge reward model; safety uses evolved attacks and a judge with binary rubric labels. For subjective tasks, K2 self-critique performs pairwise rankings against core, prescriptive anti-reward-hacking, and human-annotated rubrics. On-policy verifiable rollouts refine the critic. The report does not release tool lists, data records, prompts, rubric text, judge implementations, calibration, thresholds, or retained and rejected counts.
