SuperGLUE 可作为“饱和评测如何更新”的 benchmark 设计范式。它展示了如何保留单一 headline metric，同时保留每任务指标、诊断集、私有测试标签和使用规则。

复用时至少要保留这些字段：任务名、原始数据来源、split、输入字段、答案格式、参考标签、scorer 指标、任务级分数、聚合规则、诊断类别、提交日期和数据使用政策。若用于现代 LLM prompt 评测，还要记录 prompt 模板、解码设置、答案解析器和污染审计证据。

它也能作为审计清单：不要只比较聚合分数而不看任务级失败；不要把诊断分数混进主分数，除非官方 scorer 如此定义；不要把评测标签直接当 reward 数据，除非另做许可和反馈契约审查。
