1. **性能噪声：** 运行时间受 CPU、缓存、并行任务、热身和依赖实现影响，微小差异可能不可复现。评测必须固定硬件与资源，重复运行并报告置信区间，而非一次 wall-clock。

2. **数据规模与生态：** 140 题仅来自 9 个 Python 仓库，性能优化类型和硬件有限；不能代表 C++、GPU、分布式系统或内存/能耗优化。

3. **目标泄漏与 oracle：** 提供 target functions 会显著简化定位，realistic 描述又可能从 PR 回译并带线索；数据全部是 test split，反复调参会污染 benchmark。应分开报告两种设置，并避免用 140 题训练。
