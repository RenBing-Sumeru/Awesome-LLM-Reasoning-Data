The contribution is an evaluation framework in which a customer-service task carries an ordered sequence of goals and the transcript is scored not only for final progress but also for how the assistant notices and responds to a shift. The task object determines `required_shifts = len(goals) - 1`; a persona-conditioned LLM user simulator exposes only `known_info`, follows the ordered goals, and never calls tools, while the evaluated assistant performs all domain-API interactions.

The evaluation surface is a full user-agent-tool episode over tau-bench-derived banking, airline, and retail APIs. The assistant observes user messages and tool/API responses; the evaluator observes the full transcript, tool-call names and arguments, API outcomes, allowed goal sequence, and task assertions. Shift markers are hidden from the evaluated assistant but available to post-hoc evaluation. The exact released serialization is unknown because the supplementary ZIP was not inspected.

The feedback contract is mixed rather than a single success bit. Task Success Rate (TSR) weights communication information at 0.25, action execution at 0.45, and natural-language assertions at 0.30. Tool Use Efficiency (TUE) combines tool correctness at 0.6 and parameter validity at 0.4. Tool Call Redundancy Rate (TCRR) counts exact duplicates within a three-turn window or calls to the same function beyond a batch threshold of two. Goal-Shift Recovery and Turns (GSRT) uses an undisclosed post-hoc LLM detector to identify acknowledgment, first relevant tool, and outcome turns; binary recovery requires acknowledgment and no transfer to a human, even when the relevant tool or shifted-goal outcome is absent. Separately, `gpt-4o-mini` judges communication relevance, clarity, helpfulness, and adherence to user intent from the full transcript.

The environment/API layer can observe executable calls, schema-valid parameters, API responses, state changes, and exact repeated-call patterns. The communication judge can assess transcript-level language but inherits snapshot, prompt, calibration, style, and verbosity sensitivity. The unspecified shift detector introduces a second learned-judgment surface whose model, prompt, calibration, and repeatability are unknown. Neither learned component establishes semantic correctness outside its rubric.

Compared with tau-bench-style static customer-service evaluation, the concrete change is to represent user-intent change as an ordered task field and attach recovery latency and acknowledgment measures to the resulting episode. Compared with tau2-bench, which emphasizes dual control and executable action by both agent and user, AgentChangeBench retains assistant-only tool control and emphasizes mid-dialogue goal transitions. Its direction signal is therefore dynamic-intent evaluation, not a new training objective or proof that the resulting trajectories are high-quality training data.
