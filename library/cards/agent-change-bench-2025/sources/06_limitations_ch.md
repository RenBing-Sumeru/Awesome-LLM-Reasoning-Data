- **范围与 task model。** benchmark 只覆盖 banking、airline 与 retail 中的 benign persona。goal shift 预先声明、按顺序发生且通常明确提示；它没有测试 implicit、ambiguous、interleaved、adversarial、browser、OS、code 或 robotic change。因此结果不能证明对无限制 goal drift 或真实客户的 robustness。
- **Recovery 定义。** GSRT 的 binary recovery predicate 只要求 acknowledgment 且没有 human transfer；relevant tool use 与 shifted-goal outcome 虽然被计时，却不决定 recovery。当 agent 礼貌确认变化但没有行动或成功时，这可能产生 false positive；detector 漏检则可能产生 false negative。shift detector 的 model、prompt、calibration、repetition policy 与 error rate 均未披露。
- **Judge 依赖。** `gpt-4o-mini` 从 transcript 判断 communication，但准确 snapshot、prompt、temperature、calibration 与 repeated-judgment protocol 为 unknown。score 可能随 style、verbosity、措辞或服务更新而变化。natural-language assertion 与 task-specific predicate 也可能遗漏语义要求，或奖励 benchmark-specific behavior。
- **Metric 盲点。** TCRR 能发现三轮窗口内的 exact duplicate call 或同一 function 的过量调用，但可能漏掉 argument 不同、语义上重复的 call，也可能惩罚瞬时故障后的合理 retry。API/schema validity 不等于选择了正确 action sequence，加权 TSR 还可能掩盖具体失败 component。
- **构造不确定性。** task generator、完整 prompt、decoding setting、batch 数、acceptance yield、rejected candidate、逐条 lineage 与 review decision 均未披露。声称的 10% manual audit 缺少 annotator 数、sampling rule、agreement statistic、adjudication 与 revision history。隐藏的 generator/simulator trait 因而可能塑造 benchmark。
- **计数与结果冲突。** 已陈述 source component 相加为 314，而论文报告 315 个 task；2,835-sequence claim 没有 task/run manifest；Table 7 又与后续 persona-recovery prose 冲突。在底层 artifact 被调和前，这些问题阻止 record-level scale 与 persona-result audit。
- **Release 与 replay。** supplementary ZIP 虽被官方列出，但无法取回。没有经过检查的 manifest 能证明 task file、harness code、database snapshot、dependency、checksum、逐 run log、split、success/failure retention 或 replay instruction。闭源 model endpoint、未知 simulator/judge seed 与未固定的 tau-bench-derived environment 进一步阻止准确历史 replay。
