AgentChangeBench asks whether a tool-using conversational agent can remain effective after the user's goal changes during an ongoing episode. The stable primary record is arXiv:2510.18170v1, submitted on 2025-10-20; the accepted venue is the NeurIPS 2025 Workshop on Multi-Turn Interactions in Large Language Models (MTI-LLM), where the work appeared as a poster. The official arXiv, NeurIPS virtual, and MTI-LLM OpenReview pages support the bibliographic record. A parallel LAW @ NeurIPS 2025 OpenReview version is treated as version drift, not a separate paper.

The benchmark contains 315 declarative customer-service tasks: 50 banking, 100 airline, and 165 retail. Each task specifies a persona, known and unknown information, ordered goals, the number of required shifts, an initial environment state, allowed actions/tools, evaluation criteria, natural-language assertions, and information that the assistant must communicate. The evaluated episode then adds user and assistant turns, assistant-only tool calls, API observations, goal-shift events, post-shift acknowledgment/tool/outcome timestamps, transfer events, and metric outputs. This task-plus-episode structure is the reason for assigning the paper to `environment_agent_trajectory_data`.

The neighboring problem is ordinary static task success. AgentChangeBench instead makes mid-dialogue change observable as an evaluation event and separates communication, action execution, redundant tool use, and recovery timing. Its shifts are nevertheless predeclared, ordered, and often explicitly signaled; the work does not cover implicit, ambiguous, interleaved, adversarial, code, browser, OS, or robotic goal drift. It is therefore a focused evaluation surface rather than a general model of evolving user intent.

The paper reports 2,835 task sequences, but no accessible manifest maps that number to task IDs or run records. Multiplying 315 tasks by three proprietary models and three runs yields 2,835, but that equality is a curator inference, not a published serialization contract. L4-depth analysis is possible from the paper and appendices for the task schema, construction pipeline, environment, metrics, results, and risks. The accepted metadata remains `L3_summary_ready`, because the officially listed supplementary ZIP could not be retrieved and its contents, license, split, checksum, failure retention, and replay completeness remain unverified.
