The relevant prior-work baseline is static customer-service agent evaluation over tau-bench-like APIs: an assistant receives a user request, calls tools, and is scored on task completion. AgentChangeBench changes the task object by adding personas, ordered goals, a declared number of required shifts, progression rules, hidden shift markers, and timestamps for acknowledgment, first relevant tool use, and outcome after each change.

The concrete novelty is the decomposition of goal-shift behavior. TSR keeps communication, action execution, and natural-language assertions separate; TUE exposes correctness and parameter validity; TCRR measures local exact-call redundancy; GSRT exposes acknowledgment, tool, and outcome latency plus a binary recovery rule. This creates an audit surface where an agent can complete the original goal yet adapt slowly, communicate poorly, repeat calls, or acknowledge a change without producing the shifted outcome.

The constituent techniques are not individually new. The work reuses tau-bench-derived customer-service environments, LLM user simulation, tool/API validation, LLM-as-judge communication assessment, persona conditioning, and transcript-derived metrics. Its five personas, three domains, three proprietary model families, and task scale are an engineering integration and evaluation expansion, not evidence of a new verifier class or training method.

For reasoning-data research, the direction signal is that environment/trajectory benchmarks should represent changing objectives and expose multiple feedback channels instead of one terminal pass/fail label. The quality signal is schema and metric specificity, not high model scores. Reuse still requires an inspectable task-to-run manifest, reconciled counts and persona results, a pinned environment and judge stack, calibrated false-positive/false-negative behavior, retained failures, explicit splits/decontamination, and a license covering inherited templates, generated episodes, data, and code.
