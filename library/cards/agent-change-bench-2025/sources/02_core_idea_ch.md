论文的核心贡献是一套 evaluation framework：客服 task 携带有序 goal sequence，transcript 不仅按最终进展打分，还衡量 assistant 是否发现并响应 goal shift。task object 规定 `required_shifts = len(goals) - 1`；persona-conditioned LLM user simulator 只暴露 `known_info`，依次执行 ordered goals，且从不调用工具，所有 domain API interaction 都由被评测 assistant 执行。

evaluation surface 是运行在 tau-bench-derived banking、airline 与 retail API 上的完整 user-agent-tool episode。assistant 能观察 user message 与 tool/API response；evaluator 能观察完整 transcript、tool-call name/argument、API outcome、允许的 goal sequence 与 task assertion。shift marker 对被评测 assistant 隐藏，但供 post-hoc evaluation 使用。由于 supplementary ZIP 未被检查，准确的 release serialization 仍为 unknown。

反馈契约是 mixed，而不是单一 success bit。Task Success Rate (TSR) 对 communication information、action execution 与 natural-language assertion 的权重分别为 0.25、0.45、0.30。Tool Use Efficiency (TUE) 由 tool correctness 0.6 与 parameter validity 0.4 组成。Tool Call Redundancy Rate (TCRR) 统计三轮窗口内完全相同的重复调用，或同一 function 在一个 batch 中超过阈值 2 的调用。Goal-Shift Recovery and Turns (GSRT) 使用未披露的 post-hoc LLM detector 定位 acknowledgment、first relevant tool 与 outcome turn；binary recovery 只要求已经 acknowledgment 且没有 transfer to human，即使缺少 relevant tool 或 shifted-goal outcome 也可能算恢复。另有 `gpt-4o-mini` 读取完整 transcript，判断 communication 的 relevance、clarity、helpfulness 与对 user intent 的 adherence。

environment/API 层能够观察可执行 call、schema-valid parameter、API response、state change 与完全相同的 repeated-call pattern。communication judge 可以评估 transcript-level language，但受 model snapshot、prompt、calibration、style 与 verbosity 影响。未披露的 shift detector 构成第二个 learned-judgment surface，其 model、prompt、calibration 与 repeatability 均为 unknown。这两个 learned component 都不能证明 rubric 之外的语义正确性。

与 tau-bench 风格的静态客服评测相比，实际变化是把用户意图改变表示为 ordered task field，并给 episode 附加 recovery latency 与 acknowledgment 指标。与强调 dual control、agent 和 user 都能执行动作的 tau2-bench 相比，AgentChangeBench 保留 assistant-only tool control，重点是对话中途的 goal transition。因此它代表的是 dynamic-intent evaluation 方向，而不是新的 training objective，也没有证明这些 trajectory 是高质量训练数据。
