# 用途

**推理 SFT 构建者：**从可检查的数学、代码或逻辑指令和能力足够的生成模型出发，复用“带标记动作加执行反馈”的配方，并导出保留父子谱系的指令与回答记录。产物是 SFT 语料，成功标准是在固定 token 预算下优于源答案基线；若最终答案无法可靠检查，就不应沿用这套接受规则。

**数据审计者：**加载两个官方 Parquet 文件，用编号和父编号连接记录，检查 SFT 回答是否来自正确分支，以及偏好轨迹是否保留促成纠错的失败上下文。产物是谱系与标签一致性报告；成功检查必须覆盖字段、数量、重复、检查器假阳性和来源许可，而不能只看模型分数。

**混合数据设计者：**把 UltraInteract 示范与受控的通用指令子集结合，在同一基础模型上训练完整、源答案替换、不含 UltraInteract 和仅含 UltraInteract 四种设置，并报告各领域准确率与指令遵循退化。只有算力允许匹配训练预算且评测切分固定时才适合这样使用，否则表 5 的数据组成和规模影响仍互相混杂。
