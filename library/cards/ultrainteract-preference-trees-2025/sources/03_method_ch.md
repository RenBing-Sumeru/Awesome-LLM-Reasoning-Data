# 方法

步骤 1——选择困难且可检查的指令。
输入：十二个数学、代码和逻辑数据集，其中带有答案、推理说明、测试用例或其它标准信号。
操作：保留多样的任务形式，重点选择 `GPT-3.5-Turbo` 无法解决的问题，并按附录 A.1 对部分来源做分层抽样或难度过滤。
输出与流转：85,918 个带来源标签和监督材料的指令根节点进入偏好树构造。
检查或停止规则：来源必须支持明确的推理模式；除 `Magicoder-Evol-Instruct` 外，还必须能客观检查正确性，否则不用于构造偏好对。

步骤 2——生成多样的正确与错误动作。
输入：一条指令、随机选择的思维链或模块化编程模式、默认生成模型、其它开放模型、工具和标准标注。
操作：生成模型先分解问题，再写出带标记的文本或代码动作；每轮采样 20 个动作，最多用更强模型重试三轮，仍无法得到正确动作时再按任务类型提供标准推理或答案。
输出与流转：语法有效的候选动作在构造成功时至少含一个正确动作，随后进入配对和分支扩展。
检查或停止规则：数据集答案、测试用例或执行结果判断正确性；删除 Python 语法失败项，且不把 GPT-4 Turbo 对 Magicoder 记录的判断当作严格偏好标签。

步骤 3——把失败动作扩展成偏好树。
输入：一对正确与错误动作，以及此前的交互历史。
操作：Python 环境返回输出或报错和二元正确性信号；GPT-4 读取历史及标准答案，定位错误并给出批评，再由生成模型沿失败分支重试。
输出与流转：每条指令逐步形成从根到叶的交互轨迹，以及每轮的正确和错误分支。
检查或停止规则：正确动作关闭所在分支，错误动作可以继续扩展，每棵树最多五轮后停止。

步骤 4——过滤、去污染并序列化训练记录。
输入：构造完成的偏好树、来源元数据、正确性标签和评测测试集。
操作：把正确动作和以正确动作结束的轨迹导出为 SFT 格式，把成对分支导出为偏好格式；对 LeetCode 做精确匹配，对其它同任务测试集做八元组匹配并删除重合项。
输出与流转：当前公开 Parquet 文件包含 288,579 条 SFT 记录和 219,522 条偏好记录。
检查或停止规则：只有客观检查通过的动作才进入偏好对；文件字段和一条真实 SFT 记录必须可读，发布文件与论文统计的差异继续保留为审计项。

步骤 5——训练并比较 Eurus 消费模型。
输入：`Mistral-7B` 或 `CodeLLaMA-70B`、UltraInteract 正确动作，以及较小的通用指令混合数据。
操作：先进行一个周期的 SFT，再可选地对偏好数据使用 DPO、KTO 或 NCA，并用 UltraInteract 与配套反馈数据训练奖励模型。
输出与流转：得到 Eurus 的 SFT 与偏好模型、`Eurus-RM-7B`，以及固定的推理、指令遵循和多轮评测结果。
检查或停止规则：用基准准确率或成功率衡量模型；SFT 数据消融必须比较完整配方、标准答案替换、仅开放数据和仅 UltraInteract 四种设置。

**复现要求：**核验 ICLR 与 OpenReview 记录、精确的 Hugging Face 版本、两个 Parquet 字段结构、十二个来源版本、提示模板、生成与批评模型版本、标准答案适配器、语法与去污染脚本，以及一个训练周期的数据混合。固定模型采样顺序、每轮 20 个动作、五轮上限、SFT 混合规模、学习率和评测切分。论文未披露生成温度、总生成成本、逐来源许可核对、SFT 多出 1,600 条记录的原因和逐步语义审计。
