The construction pipeline is:

1. **Inputs.** Select public tasks from GAIA, AssistantBench, and SWE-Bench Verified. The exact pre-execution task-ID manifest is not separately published.
2. **Generation and collection.** Run Captain-Agent and Magentic-One on GAIA and AssistantBench, and SWE-Agent on SWE-Bench Verified, using a fixed configuration for each system-task pair, repeated trials, and temperature 0.3. An OpenAI-compatible middleware intercepts LLM request payloads, responses, decoding parameters, inter-agent content, and observable tool interactions. The exact per-run backend model, provider, seed, trial schedule, and step, token, or time budget are unknown.
3. **Preprocessing.** Use regex rules to extract agent names and classify plain versus tool outputs, retain raw trace content as far as possible, filter local paths and identifiers automatically, and manually inspect traces. Cleaning exclusions and record-level redaction decisions are not released.
4. **Outcome selection.** Apply official GAIA or AssistantBench answers, or SWE-Bench Verified test pass/fail, to the 380 cleaned executions. Retain the 220 failures: 73/126 Captain-Agent/GAIA, 12/21 Captain-Agent/AssistantBench, 74/119 Magentic-One/GAIA, 17/30 Magentic-One/AssistantBench, and 44/84 SWE-Agent/SWE-Bench Verified.
5. **Expert annotation.** Three experienced annotators complete an independent round, a joint consensus round for uncertain cases, and cross-review/re-annotation. They label the responsible agent and earliest decisive step under the recoverability-aware definition; final labels are unanimous. Pre-consensus Krippendorff's alpha is 0.72 for agent labels and 0.64 for step labels.
6. **Outputs and use.** Release one `trace_metadata.json` and one `step_records.json` per failed episode. The current ZIP contains exactly 220 of each. The paper uses these records to evaluate All-at-Once, Binary Search, Step-by-Step, Static Agentic, and Dynamic Agentic attribution; it does not train an agent or reward model.
