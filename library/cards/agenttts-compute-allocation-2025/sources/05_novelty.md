The closest repeated-sampling and best-of-n methods choose how much computation to use for one prediction. AgentTTS instead makes the allocation cross-stage: it jointly selects a model and sample count for every subtask, then evaluates the entire workflow under one budget. It also treats upstream quality as part of the downstream scaling curve, which is essential when retrieval, planning, coding, or tool selection changes the input received by a later model.

Its distinct contribution is not a new verifier or a better response fusion rule. It is an execution-feedback search scaffold that converts model-size preference, diminishing returns, and inter-stage dependence into stored guidelines for an LLM search agent. This makes the allocation procedure inspectable through its archive of trials and explanations. The result is still an optimization framework, so its guidance must be re-estimated when the available models, prices, stages, or evaluation rules change.
