For `environment_agent_trajectory_data`, GUI-360° provides a concrete Windows Office episode schema for studying multimodal agent behavior: request/template provenance, screenshots, accessibility state, reasoning, GUI/API action arguments and coordinates, statuses, and episode judgment. The separately published failures make it possible to compare successful and unsuccessful behavior, but users should first reconstruct attempt lineage and failure categories rather than treating every failed run as a uniform negative.

For `data_construction_open_release_recipes`, the paper offers an auditable baseline pipeline: source queries, instantiate template-bound tasks, apply feasibility labels, execute two model stages, judge whole trajectories, sanitize incomplete steps, split successes, preserve failures, and convert logs into task-specific training views. Reimplementations should explicitly version every hidden component that the official repository omits: query prompts, TrajAgent, EvaAgent prompt/rubric, VM/Office/MCP stack, reset and timeout policy, and terminal predicate.

The four processed views can support SFT baselines and ablations for coordinate grounding, screen parsing, visual-only next-action prediction, and next-action prediction with accessibility context. The released scorers can support static evaluation and verifier audits: point-in-box label noise, IoU/text matching sensitivity, action parser errors, alternative-action false negatives, accessibility metadata drift, and the gap between a logged step match and end-to-end task success.

Reuse class: usable for `sft`, GUI `agent_training` through supervised next-action/grounding objectives, and static `evaluation`, provided users pin files and address license, privacy, split, and provenance constraints. It is blocked for faithful VM replay, executable environment training, and RL reproduction. The abstract-level RL mention and released failures do not justify adding `rlvr` without an explicit reward, objective, rollout protocol, results, and code.
