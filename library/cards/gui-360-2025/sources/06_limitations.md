- The official repository does not contain the dedicated TrajAgent collection implementation, EvaAgent validation implementation or prompt/rubric, VM provisioning, Office/MCP version manifests, state reset scripts, timeout rules, or an executable terminal-state checker. Static logs and scorers therefore do not provide faithful environment replay.
- EvaAgent is a single GPT-4.1 judge calibrated only by a reported 86% human agreement on 100 trajectories. Missing confusion matrices, error rates, rubric criteria, disagreement handling, and adversarial tests leave both false acceptance and false rejection unresolved; access to generated thoughts may also let persuasive text influence judgment without environment proof.
- The successful corpus uses an 80/20 trajectory split over only 66 template families. No immutable IDs, grouping key, seed, template/source-family separation, deduplication, or contamination audit is disclosed, so train/benchmark overlap through templates, paraphrases, source queries, or similar UI states remains plausible.
- Table 2's application counts sum to 78,153, while §3.1 states 79,075 candidates, and the filtering percentages do not transparently reproduce 59,553 retained tasks. Exact source URLs, terms, crawl dates, per-record provenance, and rejected-query manifests are unavailable.
- Failure retention is substantial but incomplete as an audit object. The `fail/` tree contains 62,170 reported trajectories, yet failure types, retry/timeout/abort rules, whether all failed attempts are preserved, links to source tasks, and sanitizer drop logs are unknown.
- The paper mentions reinforcement learning, but no RL objective, reward, policy, rollout budget, isolated result table, or training code is released. Failed trajectories must not be treated as an SFT-free RLVR dataset or a ready reward contract.
- The paper documents four screenshot variants, while the current HF card documents only clean and annotated fields. GitHub and HF lack immutable whole-release tags, the HF viewer currently fails, and exact file/checkpoint mappings for paper tables are absent; schema and version drift must be pinned manually.
- GitHub code is MIT, and HF metadata declares MIT, but those declarations do not resolve rights for crawled query text, Microsoft Office screenshots/templates, fonts, icons, or other third-party UI content. The authors state that no PII or sensitive user data is included, but source URLs, consent/terms analysis, PII detector, redaction procedure, audit sample, and retention policy are not released.
