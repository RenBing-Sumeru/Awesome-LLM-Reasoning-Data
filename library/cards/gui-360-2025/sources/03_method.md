The reconstructable pipeline is:

1. **Source and instantiate tasks.** Mine prototypical Word, Excel, and PowerPoint queries from application help/tutorials, online forums/Q&A/community sites, and search queries. Match each query with an unspecified LLM to one of 66 manually instantiated Office templates, then rewrite it as a concrete executable request. Table 2 lists 27,903 Word, 28,552 Excel, and 21,698 PowerPoint raw queries; these sum to 78,153, whereas §3.1 states 79,075 candidates, so the input count is not reconciled.
2. **Filter task feasibility.** Use an unspecified LLM to label tasks as `NORMAL`, `NONEXEC`, `CROSSAPP`, `VERCTRL`, `TPLMISS`, or `INVALID`; retain `NORMAL`. The paper states that 59,553 candidates survive, but prompts, model version, thresholds, human adjudication, deduplication, and stage-wise records are unavailable.
3. **Execute episodes.** Run tasks on fifteen Windows 11 VMs with four CPU cores each. TrajAgent decomposes the request, dispatches execution agents, captures screenshots and UI Automation/accessibility state, selects mouse/keyboard GUI actions or Word/Excel/PowerPoint APIs exposed through MCP, records observations, thoughts, action arguments/coordinates, and statuses, and continues until finishing. GPT-4o handles the first execution round; GPT-4.1 retries failed tasks. Both are reported at temperature 0.0.
4. **Judge and sanitize.** GPT-4.1-based EvaAgent inspects the full episode and final application state and supplies reason, evidence, sub-scores, and a completion decision. Only successful/executable trajectories satisfying all undisclosed criteria enter the main corpus. Steps without an executed action, screenshot, or essential metadata are removed. The failed attempts remain under a separate HF `fail/` tree, but failure taxonomy, timeout/abort policy, attempt-to-task mapping, and sanitizer drop logs are unknown.
5. **Split and transform.** Split successful trajectories 80/20 by trajectory into train (13,750 trajectories, 105,368 steps) and GUI-360-Bench/test (3,439 trajectories, 26,284 steps). All three benchmark tasks share this partition. Convert the same logs into four SFT-ready directories: grounding, screen parsing, action prediction, and action prediction with accessibility context.
6. **Train and evaluate.** The paper uses Qwen2.5-VL-7B for the principal SFT/action-prediction experiments and also reports a UI-TARS-1.5-7B SFT grounding variant. The processed records support coordinate, structured-control, and structured-next-action targets. Static evaluators compute point-in-box grounding, IoU/text parsing metrics, and function/argument/status matching. They do not replay actions or supply an executable terminal reward.

Reported SFT and stated RL experiments use four NVIDIA A100 40GB GPUs, FP16, gradient accumulation, checkpointing, and a learning-rate search over `1e-5`, `5e-6`, and `1e-6`. Optimizer, batch size, epochs, scheduler, seeds, selected learning rate per run, checkpoint mapping, and all RL algorithm/reward/rollout details are unknown. Reproduction therefore requires pinning the arXiv version, GitHub commit and HF files, plus unavailable Windows/Office/MCP versions, VM image, locale/display, reset rules, TrajAgent/EvaAgent implementation and prompt, terminal checker, task/split IDs, and timeout/retry manifests.
