- 官方仓库不包含专用 TrajAgent collection implementation、EvaAgent validation implementation 或 prompt/rubric，也没有 VM provisioning、Office/MCP version manifest、state reset script、timeout rule 或 executable terminal-state checker。因此，静态日志与 scorer 不能提供 faithful environment replay。
- EvaAgent 是单一 GPT-4.1 judge，校准证据只有在 100 条 trajectory 上报告的 86% 人工一致率。缺少 confusion matrix、error rate、rubric criterion、disagreement handling 与 adversarial test，使 false acceptance 和 false rejection 都未解决；它还能读取生成的 thought，具有说服力的文本可能在没有 environment proof 时影响判断。
- 成功 corpus 在仅 66 个 template family 上按 trajectory 做 80/20 split。没有披露 immutable ID、grouping key、seed、template/source-family separation、deduplication 或 contamination audit，因此通过 template、paraphrase、source query 或相似 UI state 发生 train/benchmark overlap 仍属 plausible risk。
- Table 2 的应用计数合计 78,153，但 §3.1 写的是 79,075 个 candidate；已发布过滤比例也无法透明复现 59,553 个 retained task。精确 source URL、terms、crawl date、逐记录 provenance 与 rejected-query manifest 均未提供。
- Failure retention 规模可观，但作为 audit object 仍不完整。`fail/` tree 包含论文报告的 62,170 条 trajectory，但 failure type、retry/timeout/abort rule、是否保留全部 failed attempt、与 source task 的链接，以及 sanitizer drop log 都是 unknown。
- 论文提到 reinforcement learning，却没有发布 RL objective、reward、policy、rollout budget、独立 result table 或 training code。失败 trajectory 不应被当作无需进一步转换的 RLVR dataset 或现成 reward contract。
- 论文记录四种 screenshot variant，而当前 HF card 只记录 clean 与 annotated field。GitHub/HF 没有 immutable whole-release tag，HF viewer 当前失败，论文 table 也缺少精确 file/checkpoint mapping；schema 与 version drift 必须手工固定。
- GitHub code 使用 MIT，HF metadata 也声明 MIT，但这些声明不能解决 crawled query text、Microsoft Office screenshot/template、font、icon 或其他第三方 UI content 的 rights。作者称数据不含 PII 或 sensitive user data，但 source URL、consent/terms analysis、PII detector、redaction procedure、audit sample 与 retention policy 均未发布。
