The benchmark separates an open-ended replication into 3 stages: agent work in an isolated rollout container, execution of the selected submission in a fresh reproduction container, and rubric grading in the judge context. The candidate sees the paper and author addendum but not the rubric or judge-only notes. It must build a submission repository whose reproduction script regenerates the evidence needed for assessment.

Before reproduction, a URL monitor may disqualify a run. SimpleJudge then assigns each rubric leaf a binary 0/1 decision, explanation, and validity flag, after which sibling-relative weights produce parent scores and the final Replication Score. The agent receives no online rubric reward during its episode. This design yields a post-hoc verifier contract, but Result Match has only 566 of 8,316 leaves, so the score is structurally dominated by Code Development and Execution rather than direct agreement with the paper's findings.
