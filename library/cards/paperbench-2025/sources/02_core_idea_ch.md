该基准把开放式论文复现拆成 3 个阶段：智能体在隔离 rollout 容器中工作、在新鲜复现容器中执行选定提交物、最后在裁判上下文中按 rubric 评分。候选智能体能看到论文和作者补充说明，却看不到 rubric 与仅供裁判使用的说明；它必须构建一个提交仓库，并让其中的复现脚本重新生成评分所需证据。

复现之前，URL 监控器可以判定运行违规。随后 SimpleJudge 对每个叶节点给出二元 0/1 结论、解释和有效性标记，再按同级相对权重聚合父节点与最终 Replication Score。智能体在运行期间不会收到在线 rubric 奖励。这是一种事后验证契约，但 Result Match 仅占 8,316 个叶节点中的 566 个，因此总分在结构上更受 Code Development 与 Execution 支配，而不是主要反映与原论文结论的一致程度。
