The core pipeline is:

1. **Inputs and factual recording.** A caller supplies a task, a stochastic `Policy`, an `Environment`, a message codec, and optionally an `OutcomeFunction`. The recorder stores the exact request-facing `state_before`, the raw provider action, the resulting observation, and root/branch identifiers. The core tool loop accepts one `tool_call` or `final` action per turn; `final` terminates the episode, while exceeding the default `max_steps=20` raises `ReplayError` instead of saving a truncated run.
2. **Reconstruction and fidelity audit.** Deterministic replay rebuilds messages from recorded actions and observations and checks canonical state digests at each step. It then reissues policy calls while a `RecordedEnvironment` injects factual observations, reporting per-step action-signature match rates and whole-sequence reproduction. The signature compares tool choice plus hashed arguments, or `final`; it does not require token-identical text or reproduce live world state.
3. **Intervention and branching.** Choose one of `do_resample`, `do_action`, `do_observation`, `do_context`, or `do_policy`. Copy steps before branch index `k`, apply the intervention at `k`, and run the suffix. Counterfactual forward replay requests fresh outputs from the supplied Environment, so real tools may execute again unless the caller provides mocks.
4. **Outcome and selection.** Score every complete child with `RuleOutcome`, `JudgeOutcome`, or another caller function. Contrastive attribution holds `[0,k)` factual and resamples `k` plus all later stochastic choices K times. Code defaults to K=16; Figure 1 in arXiv v1 illustrates 48 rollouts per step. The selected point of commitment is the latest step whose rescue-effect interval excludes zero.
5. **Interaction attribution.** Shapley defines a coalition by holding selected factual actions while rerunning the rest. The code defaults to 64 permutations, antithetic reverse pairing, one rollout per coalition evaluation, fresh evaluations without cross-permutation caching, and optional sample or estimated-cost circuit breakers. Normal-approximation intervals summarize the sampled marginals.
6. **Outputs and use.** Persist root and child JSON trajectories plus a SQLite lineage index, then emit reconstruction reports, action-match summaries, contrastive effects, a causal-locus decision or abstention, and/or Shapley values. The supported use is evaluation and audit only; there is no optimizer, policy-training scaffold, CAR split, or released CAR trajectory dataset.

Reproduction must distinguish three artifact versions: arXiv v1 is the five-page synthetic-SCM paper; GitHub `v0.2.0` at commit `db90fa28b97164c35e7c524e4597b8cbdb3035af` contains later adapters and Who&When work; PyPI exposes only `0.0.1`. A real replay also needs pinned model/provider/runtime and tool versions, sampling state, an environment snapshot, reset and timeout rules, idempotency or approval controls, and rollback semantics. Those controls are not implemented as a common CAR contract.
