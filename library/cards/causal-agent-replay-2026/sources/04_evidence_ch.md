arXiv v1 的证据有意保持小规模且为 synthetic。在三步 planted pivotal SCM 中，中间的退款决策是因果失败点：重采样该步会出现 rescue，重采样更晚一步则不会。在 two-factor AND-interaction SCM 中，论文报告 Shapley value 为 0.44、0.45 和约 0，求和后的 efficiency 为 0.909，对应解析总效应 0.91。相应仓库测试使用 bad-action probability 0.3、80 个 permutation、每次 evaluation 12 个样本及 antithetic pairing。论文与测试还说明 isolated contrastive effect 会重复计算 interaction；代码断言要求它们的 total absolute effect 大于 1.2。这些结果验证 planted mechanism 上的行为，不能证明真实工具上的因果识别或数据质量。

仓库稿在 arXiv v1 之后加入了单独的 Who&When evaluation。它使用 Algorithm-Generated 的 126 个 instance，并让 `llama3.2` 3B 同时承担 agent surrogate、environment simulator 和 extract-then-compare judge，K 不大于 8，horizon 为五步。仓库稿报告完成 121 个 instance、5 个 infrastructure casualty，并在 120/121 上复现事实失败。其 point-estimate `argmax` 规则报告 agent accuracy 48.8%、exact-step accuracy 20.7%、plus or minus 3 范围内 71.9%；`cliff` 规则分别为 49.6%、15.7% 和 68.6%。带不确定性的结果是负面的：CI-gated locus 仅在 22/121 上触发，82% abstain，且 76% 的标注 mistake step 在 K 不大于 8 时没有任何 rescue。

这些 Who&When 数字是作者仅在仓库中报告的结果，不是 arXiv v2，也没有被独立复现。完整 result JSONL 已被 gitignore 且不在 HEAD 中，因此无法审计每个 instance 的 seed、实际 K、排除 ID 和错误原因。同样，官方 Python 3.12 tests 已检查源码，但由于审计环境缺少 `uv` 及 `structlog`、adapter packages 等依赖，未能在本地运行；这是本次审计环境的范围限制，不是项目测试失败的证据。这里任何 benchmark score 都不能证明 CAR trajectory 已被发布或已可用于训练。
