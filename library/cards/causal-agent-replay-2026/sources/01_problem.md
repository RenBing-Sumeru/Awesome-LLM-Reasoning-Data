Causal Agent Replay (CAR) addresses a diagnostic gap in stochastic LLM agents: a failed terminal outcome identifies that an episode went wrong, while a static reading of the transcript does not establish which decision caused the failure or whether rerunning from that point would change the outcome. The authoritative paper is the five-page arXiv `2606.08275v1`, submitted on 2026-06-06. The official repository extends the implementation after that submission, but there is no arXiv v2, conference record, DOI, or released CAR dataset.

CAR treats one audit object as a factual root `Trajectory` plus counterfactual child trajectories. A root contains caller-supplied task context; exact `state_before` snapshots with the system-level instruction, tool schemas, model/provider/sampling fields, and provider-native messages; one `tool_call` or `final` action per step; tool/environment observations marked `real`, `recorded`, or `mocked`; a final output; and an optional caller-defined outcome label and score. Each branch adds `parent_id`, `branched_at_step`, and `intervention_id`, then records its own suffix and outcome. This is a runtime record shape and replay method, not a downloadable corpus of training trajectories.

The work belongs in `environment_agent_trajectory_data` because it makes state, action, observation, terminal behavior, branch lineage, environment semantics, and replay fidelity first-class. Its decision boundary is evaluation and failure audit. It does not train a policy, release SFT/RLVR/process-supervision examples, or establish safe replay of real side-effecting tools. The Card's evidence covers arXiv v1, GitHub `v0.2.0`, code and tests by inspection, and PyPI `0.0.1`; live provider/tool replay and the later repository-only Who&When results were not independently reproduced.
