The confirmed archival record is *AgentRewardBench: Evaluating Automatic Evaluations of Web Agent Trajectories*, published at the Conference on Language Modeling (COLM) 2025. This Card uses arXiv:2504.08942v2, the official project page, GitHub revision `f838338886d723d40b586309465a38277803d9e6`, and Hugging Face revision `b6d17e646009d6cb63d5dd7be78807b680693f61` as its evidence boundary.

The paper asks whether automatic evaluators can determine if a web agent actually completed a task. Task-specific rules are executable and cheap but can miss semantically valid success; expert review is richer but slow and expensive; LLM judges are more flexible but their false-positive and false-negative behavior was not well characterized. This is consequential because the same success signal may be used to report benchmark performance or select trajectories, even though the paper itself evaluates signals rather than training a policy or reward model.

The reusable evaluation surface contains 1,302 completed trajectories generated from 351 tasks in AssistantBench, VisualWebArena, WebArena, WorkArena, and WorkArena++ by four LLM backbones. A trajectory is a full episode: goal, ordered observations, agent reasoning and actions, URLs and accessibility-tree representations, screenshot references, errors, and episode summaries. The release connects each episode to expert labels, stored environment reward, screenshots, and outputs from automatic evaluators, so the feedback layer can be inspected record by record.

The paper and release are not identical descriptions of that object. The paper reports 3,906 binary annotations—success, side effect, and repetition for 1,302 trajectories—whereas the pinned `annotations.csv` has 1,408 rows for 1,302 unique trajectory keys, including 106 double-annotated keys and a fourth, four-level optimality field. The Hugging Face release contains 1,302 cleaned trajectory JSONs, 1,302 episode screenshot directories, and 15 evaluator outputs per trajectory. These version differences are part of the audit surface, not details to smooth over.

For `environment_agent_trajectory_data`, the paper is useful because it exposes observations, actions, environment-derived feedback, expert judgment, judge output, terminal labels, and replay metadata in one offline corpus. Its accepted `curation_level` remains `L3_summary_ready` and its status remains `partial`: licensing, upstream rights, deterministic replay, decontamination, privacy review, and annotation reconciliation are unresolved.
