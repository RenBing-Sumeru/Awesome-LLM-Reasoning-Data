**任务来源与 rollout。** 作者选择 351 个 task ID：33 个 AssistantBench validation task、100 个 VisualWebArena task、100 个 WebArena task、18 个 WorkArena task 和 100 个 WorkArena++ Level-2 task。WebArena 与 VisualWebArena 按 domain 和原始 evaluation-method subgroup 抽样，WorkArena category 大致平衡。这是任务抽样，不是去污染流程。source model 为 `gpt-4o-2024-11-20`、Claude 3.7 Sonnet、`meta-llama/Llama-3.3-70B-Instruct` 和 `Qwen/Qwen2.5-VL-72B-Instruct`。三个 multimodal agent 运行全部 351 个任务；text-only Llama 运行 251 个非 VisualWebArena 任务，其中两个反复 timeout 的 WebArena 任务未纳入。发布轨迹数量由 `351 × 3 + 251 - 2 = 1,302` 得到。

**智能体环境与记录。** GenericAgent 通过 AgentLab 与 BrowserGym 运行，后两者提供 representation preprocessing、Gym-compatible environment、output parsing 和 browser action execution。论文报告最大输入 40,000 token、最大输出 8,192 token。每个 cleaned JSON 在记录级保存 agent、benchmark、experiment、goal、model 与 model argument、package version、seed、flag、validity、有序 step 和 summary information。step 可包含 URL、action、agent reasoning、accessibility-tree variant、screenshot path、open-page URL、focused element 与 bounding box、last-action error，以及 timing/token/cost statistic。这些是离线序列化记录，并未嵌入 live website 或 database snapshot。

**专家标注。** 六位网页智能体专家使用自定义 Gradio interface，查看 goal、step、reasoning、action 和 screenshot，也可以检查 environment 与 accessibility tree。论文称不确定性和分歧会经讨论趋于共识，前一半数据由专家现场并行标注。论文未披露招募、报酬、逐任务分配、是否盲评或不可变 adjudication log。论文还称 GPT-4o WebArena trajectory 接受了第二次 success 标注，agreement 为 89.3%。固定版本 CSV 中却有八个不同 annotator identifier、1,408 行、1,302 个唯一 key，其中 106 个 key 有两行；identifier 与数量差异的原因 unknown。按照 release scoring code 将首行视为 primary 的约定，1,302 个 key 的 success 标签为 355 个 `Successful`、946 个 `Unsuccessful` 与 1 个 `Unsure`。

**标签、划分与 evaluator。** 专家记录包含 success、side effect、optimality 和 looping。除原始 `Unsure` 外，第一、第二与第四项为 binary；optimality 是四级有序标签，原始 CSV 另有一行 `Unsure`。task-level manifest 将 51 个 dev 与 300 个 test task 映射为 196 条 dev 和 1,106 条 test trajectory。Hugging Face 把 annotation 展示为单一 `full` configuration，因此用户必须连接 `data/splits.csv`，并规范化 `.resized`/`.improved` task ID。简化 LLM judge 输入 goal、action/reasoning history 和可选的最终 screenshot/accessibility tree；固定代码的默认 evaluator 设置为 temperature 0.0、seed 0、最大 completion 1,024 token。`functional` 参照以累计 reward `>0.5` 为阈值。

**发布形态与用途边界。** 在 Hugging Face revision `b6d17e646009d6cb63d5dd7be78807b680693f61`，文件名 inventory 恰好包含 1,302 个 cleaned trajectory JSON、位于 1,302 个 episode directory 中的 27,299 个 PNG，以及 19,530 个 judgment JSON，即 15 种 evaluator configuration 乘 1,302 条 trajectory。按 inventory，每种配置对每条轨迹都有一个文件，但并未穷举重跑 response parsing，也未验证每个 screenshot reference。release 保留成功和失败的已完成 episode；持续 timeout 的尝试没有发布。论文实际展示的用途仅为 evaluator benchmarking 与 audit，不是 reward-model 或 policy training。
