**Task sourcing and rollouts.** The authors select 351 task IDs: 33 AssistantBench validation tasks, 100 VisualWebArena tasks, 100 WebArena tasks, 18 WorkArena tasks, and 100 WorkArena++ Level-2 tasks. WebArena and VisualWebArena are sampled across domain by original evaluation-method subgroups; WorkArena categories are approximately balanced. This is task sampling, not a decontamination procedure. The source models are `gpt-4o-2024-11-20`, Claude 3.7 Sonnet, `meta-llama/Llama-3.3-70B-Instruct`, and `Qwen/Qwen2.5-VL-72B-Instruct`. The three multimodal agents run all 351 tasks; text-only Llama runs 251 non-VisualWebArena tasks, with two repeatedly timing-out WebArena tasks absent. The arithmetic is `351 × 3 + 251 - 2 = 1,302` released trajectories.

**Agent environment and records.** GenericAgent systems run through AgentLab and BrowserGym, which provide representation preprocessing, Gym-compatible environments, output parsing, and browser action execution. The paper reports a 40,000-token maximum input and 8,192-token output budget. Each cleaned JSON carries record-level agent, benchmark, experiment, goal, model and model arguments, package version, seed, flags, validity, ordered steps, and summary information. Steps can include URL, action, agent reasoning, accessibility-tree variants, screenshot path, open-page URLs, focused elements and bounding boxes, last-action error, and timing/token/cost statistics. These are offline serializations; no live website or database snapshot is embedded.

**Expert annotation.** Six web-agent experts use a custom Gradio interface that displays the goal, steps, reasoning, actions, and screenshots; they may inspect environments and accessibility trees. The paper says uncertainty and disagreements are discussed toward consensus and that the first half was annotated concurrently in person. Recruitment, compensation, per-task assignment, blindedness, and an immutable adjudication log are not disclosed. The paper reports a second success annotation for GPT-4o WebArena trajectories and 89.3% agreement. In the pinned CSV, there are eight distinct annotator identifiers, 1,408 rows for 1,302 unique keys, and 106 keys with two rows; the reason for the identifier and count differences is unknown. Under the released scoring convention that treats the first row as primary, the 1,302 keys contain 355 `Successful`, 946 `Unsuccessful`, and one `Unsure` success label.

**Labels, splits, and evaluators.** Expert records contain success, side effect, optimality, and looping. Only the first, second, and fourth are binary apart from raw `Unsure`; optimality has four ordered levels and one raw `Unsure` row. The task-level manifest divides 51 dev and 300 test tasks into 196 dev and 1,106 test trajectories. Hugging Face presents annotations as one `full` configuration, so users must join `data/splits.csv` and normalize `.resized`/`.improved` task IDs. Simplified LLM judges consume the goal, action/reasoning history, and optional final screenshot/accessibility tree; the pinned default evaluator settings are temperature 0.0, seed 0, and 1,024 maximum completion tokens. The `functional` reference thresholds cumulative reward at `>0.5`.

**Release shape and use boundary.** At Hugging Face revision `b6d17e646009d6cb63d5dd7be78807b680693f61`, filename inventory yields exactly 1,302 cleaned trajectory JSONs, 27,299 PNGs in 1,302 episode directories, and 19,530 judgment JSONs: 15 evaluator configurations times 1,302 trajectories. Every configuration has one file per trajectory by inventory, although response parsing and every screenshot reference were not exhaustively rerun. The release retains successful and unsuccessful completed episodes; persistent timeout attempts are not released. The demonstrated workflow is evaluator benchmarking and audit only, not reward-model or policy training.
