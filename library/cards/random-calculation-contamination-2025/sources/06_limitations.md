The release is reproducible at the recipe level, not byte-for-byte. The generator does not fix a random seed or explicitly deduplicate candidates, the repository has no tagged immutable release, and the reported 700/300 memberships for the 5- and 10-operation RLVR subsets are not published. Although direct inspection found no duplicate prompt within any checked-in result file, that property is not guaranteed by the released procedure. Neither the repository nor dataset declares a license.

The data schema is thin. Records expose prompts and final answers but no expression AST, sampled atom/operator provenance, exact symbolic value, derivation trace, verifier log, or per-item difficulty evidence. Operation count measures recursive syntax, not necessarily conceptual difficulty; cancellation, repeated subexpressions, number magnitude, and numerical conditioning can make examples with the same count differ substantially.

The verifier inherits parser and numerical assumptions. latex2sympy2 conversion, SymPy evaluation, and float serialization can create precision or representation edge cases. In the generator's nominal 0.001 check, both the answer string and SymPy value are converted to `float`, so it does not compare the serialized value with a preserved arbitrary-precision reference. The continuous reward likewise checks answer proximity; neither mechanism establishes that a generated rationale is valid.

"Generated after model release" is a useful temporal control, not a guarantee of zero contamination. Models may have seen equivalent structures, learned the underlying algorithms, or adapted to benchmark templates. Partial-prompt reconstruction, answer recovery, response overlap, and KL divergence are behavioral indicators with alternative explanations; they do not identify exact training records or causally isolate memorization.

The experimental conclusions are bounded by two model families, two RandomCalculation levels for RLVR, a specific optimizer and reward design, and arithmetic expressions rather than broader mathematical reasoning. The official repository exposes generation and evaluation code but no complete RL training implementation or exact split manifest. The reported downstream scores and training curves should therefore not be used as standalone evidence of dataset quality or end-to-end reproducibility.
