Prior tool-use benchmarks already score function selection, arguments, execution, or final answers, and LLM judges, semantic retrieval, ReAct, and API catalogs are not individually new. TRAJECT-Bench changes the evaluation object by making a fully parameterized multi-call reference trajectory first-class and by separating two structures: unordered independent parallel calls and ordered output-dependent sequential chains. Simple/hard query pairs then vary linguistic directness while holding the intended reference behavior fixed.

The construction recipe is also more specific than scaling a prompt set. RapidAPI-derived tools are executed and filtered for errors, trivial output, overlap, description quality, and parameter complexity. Parallel examples begin from 50 manually collected task types and LLM-synthesized call sets; sequential examples begin from a directed compatibility graph, manually authored chain templates, and explicit data bindings before LLM instantiation. Automatic validation and human review are part of the claimed process, although the exact models, prompts, rejection statistics, and released run configuration remain unknown.

The feedback interface is the main direction signal for reasoning-data research. Tool identity, argument use, retrieval, and sequential order receive programmatic checks; trajectory satisfaction and final-answer equivalence receive model judgment; ReAct receives mutable environment observations. Keeping these components separate makes metric blind spots auditable. It also shows that “trajectory verified” is not one property: name equality, parameter equality, dependency order, semantic adequacy, and execution success are different contracts.

What is not new should remain explicit. The paper does not introduce a training objective, base model, teacher policy, dense process reward, preference dataset, new API provider, or deterministic environment snapshot. Its sequential structures are chains rather than arbitrary dependency graphs. A material share of the contribution is benchmark engineering and scale integration across 1,228 tools, not a new learning algorithm.

Before reuse, the novelty must be checked against artifact integrity rather than venue or scores. Researchers need to reconcile 5,670 versus 5,870, identify the intended Email/Mapping release state, pin code/data/schema/judges/APIs, audit alternate-valid trajectories and metric false positives/negatives, inspect dropped failures, and establish upstream rights. Until then, the work is a useful evaluation/audit direction signal, not a verified training corpus.
