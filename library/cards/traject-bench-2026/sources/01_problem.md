TRAJECT-Bench was first posted as arXiv:2510.04550 in October 2025 and is published as an ICLR 2026 conference paper; the official ICLR poster, OpenReview record, arXiv full text and appendices, author-maintained GitHub repository, and official Hugging Face dataset are the primary sources used here. The entry year follows the verified archival venue. The accepted metadata remains `L3_summary_ready`: this bilingual Card supplies L4-depth reading material without converting unresolved release evidence into a higher curation decision.

The paper asks how to evaluate an agent that must select, parameterize, and coordinate several tools, rather than merely call one API or produce a final answer. Existing tool-use scores can hide whether the model chose the right tools, supplied correct arguments, respected dependencies, and produced an answer consistent with execution. TRAJECT-Bench therefore evaluates the trajectory itself across independent parallel calls and dependency-bearing sequential calls (Paper §§1–4).

One hosted benchmark record contains a natural-language `query`, a reference `tool_list`, `trajectory_type`, `final_answer`, `task_name`, `task_description`, and `tool_count`. Reference calls carry tool identity and description, required and optional parameter names and values, parent/API/domain metadata, and—when sequential—output-to-input bindings or placeholders. The action space is a catalog of 1,228 curated RapidAPI-derived tools across travel, mapping, finance, weather, e-commerce, news/media, gaming, email, education, and music. This places the work in `environment_agent_trajectory_data`: tool schemas, actions, dependencies, live observations, and final answers form the evaluation surface.

The decision boundary is narrow. TRAJECT-Bench is a benchmark, data release, construction recipe, and agent-environment artifact used in the paper for evaluation and failure diagnosis. It is not evidence of SFT, distillation, preference optimization, reward-model training, RLVR, process supervision, or agent training. Its reference calls provide state/action-level targets and trajectory-level scores, but no step reward or token-level process label. Because the public split is `test`, the APIs are mutable, and the release lacks an immutable replay manifest, this Card treats the artifact as evaluation/audit only.

The central release inconsistency must remain visible. Section 3.2 states 5,670 queries, whereas Appendix Table 9 lists 2,000 simple parallel, 2,000 hard parallel, and 1,870 sequential items, totaling 5,870. The current Hugging Face raw tree omits sequential Email; the Viewer further omits parallel Mapping and lists only 28 configurations. These facts make the benchmark valuable for studying trajectory-aware evaluation, but they block an unqualified claim about a canonical complete corpus.
