Construction evidence is internally checkable but not fully reconciled. Paper §3.2 reports 5,670 queries. Appendix Table 9 instead reports 2,000 simple parallel, 2,000 hard parallel, and 1,870 sequential examples, whose arithmetic total is 5,870. Appendix Table 8's ten domain counts sum to 1,228 curated tools. The official README's parallel recipe—50 task types, eight tool counts from 3 through 10, and five trajectories per combination—reconstructs 2,000 parallel references. These sources support the tool and parallel-reference scales while leaving the canonical total unresolved.

The main author-reported diagnostic is trajectory length sensitivity. Under the models and prompting conditions evaluated in Paper §4.2 and Figure 2, performance declines as the number of reference tools increases, with the steepest reported drop from three to five tools. The paper's failure analysis identifies similar-tool confusion, parameter-blind selection or use, redundant calls, and incorrect intent inference. This supports the narrower claim that trajectory-aware metrics reveal failures hidden by answer-only scoring; it does not establish that longer reference trajectories are intrinsically higher-quality or that the reference is uniquely valid.

Retrieval experiments expose a separate bottleneck. In the Claude settings shown in Paper Table 4, hard-query retrieval rates are approximately 0.46–0.585 while trajectory Exact Match is only about 0.012–0.033. The condition varies retriever/tool-pool access with a default top-20 retrieval budget. The large gap indicates that retrieving some gold tools is insufficient for producing the complete reference trajectory on indirect queries. Because Inclusion is recall-only and Usage is conditional on common tools, no single submetric should be interpreted as overall task success.

Artifact inspection provides negative evidence about release completeness. The current Hugging Face raw structure has parallel directories for ten domains but sequential directories for only nine, with Email absent. The Viewer lists 28 configurations and additionally omits both parallel Mapping configurations. Viewer-listed rows total 5,270; the visible raw-domain pattern is consistent with the paper's 5,670 count only if the missing 200 sequential Email rows are excluded, but no pinned manifest confirms that interpretation. This is a curator reconciliation hypothesis, not an author statement.

The hosted Viewer also exposes some `final_answer` values containing API failures or JSON-generation errors, showing that the visible reference release is not obviously success-only. However, no full accepted/rejected/dropped ledger or archive of evaluated-model trajectories was verified. The experiments were not independently reproduced for this Card, judge calibration is absent, and live API/provider versions are unpinned. Benchmark performance is therefore evidence about the reported evaluation setup, not proof of data quality, training value, legal reusability, or deterministic replay.
