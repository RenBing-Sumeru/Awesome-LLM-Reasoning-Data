- **The released count is not a trajectory count.** The 2,215 train and 200 test items are executable environment definitions. Generated paper-run histories, per-epoch manifests, total rollouts, success/failure/error counts, terminal answers, and dropped-state counts are unavailable. The sampler retains initial and tool-calling states, including failed calls, but drops the terminal no-tool response; this prevents a complete public episode record.
- **The verifier is text-brittle.** After limited normalization, `answer_verify` uses substring containment. Expected text leaked into a verbose observation or colliding with another string can create a false positive. Semantically equivalent aliases, number/date formats, or structured outputs can create false negatives. The paper does not report calibration rates, adversarial tests, or a semantic adjudicator. A positive reward establishes agreement with this string contract, not correctness of reasoning or real-world facts.
- **The reward can be gamed.** The paper itself shows that completion-only feedback encourages tool overuse. The final-answer containment branch can also grant positive reward without requiring every intended tool step to be completed. Coarse penalties conflate malformed markup, parser failure, missing functions, timeouts, environment exceptions, and policy reasoning failures, complicating diagnosis.
- **Execution is unsafe without an external sandbox.** `call_function` executes row-provided Python through unrestricted in-process `exec`. A ten-second timeout does not restrict filesystem, network, subprocess, imports, persistence, secrets, CPU, or memory. Running untrusted or modified rows on a normal training host can execute arbitrary code; isolation and least privilege are requirements, not optional optimizations.
- **Synthetic consistency can diverge from reality.** GPT-4o-generated functions may encode stale, incomplete, or incorrect facts. Successful execution plus substring agreement only demonstrates internal consistency of the local environment. It does not establish that the tool is faithful to a real API, that the observation is factually correct, or that the call was causally useful.
- **Construction lineage is incomplete.** Appendix D supplies prompts for the five-stage process, but the repository does not include the end-to-end construction scripts, intermediate GPT-4o generations, source-fact identifiers, human review/adjudication logs, or item-level provenance. Exact sources, annotators, fact-checking, privacy, consent, and rights for manually authored questions and embedded facts are unknown.
- **Replay and release versioning are incomplete.** The final publication is ACL 2026 while the slug reflects the 2025 arXiv debut. Repository main was audited at `7022ef...`, but the paper pins no commit; there are no tags or GitHub releases. Exact checkpoints, seeds, complete decoding settings, paper-era VeRL revision, Python/CUDA/driver/container pins, and checkpoint-to-table mapping are unavailable. Released scripts set one epoch per invocation while the paper reports three resampled epochs.
- **Licensing and contamination remain unresolved.** Apache-2.0 is explicitly stated for code, not clearly for raw data, embedded implementations/facts, manually created inputs, or bundled upstream benchmark assets. Only custom train/test non-overlap is asserted; item-level evidence, broader deduplication, public-benchmark overlap, pretraining contamination, and privacy/consent audits are unknown.
- **Experimental scope is limited.** Reported gains concern the tested Qwen configurations and tool-use evaluation surfaces. Qwen 32B/72B variants are evaluation-only. The authors acknowledge greater improvement in tool invocation than underlying reasoning. Benchmark improvement is not proof of environment quality, verifier validity, safe data reuse, or general reasoning improvement.
