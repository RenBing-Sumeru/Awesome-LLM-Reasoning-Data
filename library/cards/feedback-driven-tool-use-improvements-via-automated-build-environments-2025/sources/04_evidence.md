The strongest release evidence is structural rather than a model score. At audited commit `7022ef0529bbff4901084f17e452eb49cad5fffc`, the official repository contains raw train/test environment JSONL, a stateful trajectory sampler, the substring verifier and deterministic reward implementation, six Qwen2.5/Qwen3 GRPO/Reinforce++ scripts, and evaluation data/code. The 200-row custom test file was parsed as 50 instances for each of the four scenario structures. The much larger train file matches the released row schema, while the paper's Table 1 reports 2,215 train environments split 500/500/500/715. This verifies the task/environment release shape, not the existence of 2,215 complete trajectories.

The paper's Table 2 reports that every displayed trained 7B/14B variant improves its overall tool-use average over the corresponding base. One concrete condition is Qwen3-8B in non-reasoning mode trained with GRPO: **45.43 overall versus 31.01 for the base model**. The comparison spans the custom in-domain test surface and the reported external tool-use evaluations under the authors' setup. It supports a policy-performance claim for this environment/reward recipe; it is not evidence that the released rows are correctly licensed, uncontaminated, semantically verified, or sufficient to replay the paper.

The reward ablation gives a more diagnostic result. The authors report that a precision-only objective leaves tasks incomplete, whereas a completion-only objective encourages excessive tool use; their combined reward yields a better balance between tool-call precision and completion (Section 6, Figure 4). This directly motivates the `2q/(p+1)` structure, which rewards newly solved subquestions while penalizing extra calls through the denominator. It also documents a reward-gaming mode: a completion signal alone can change call frequency without improving disciplined tool selection.

For general capabilities, the authors report no degradation across six public benchmarks (Table 4 and Figure 3). That claim is author-reported and was not independently reproduced for this Card. It should be read only within those tested models, checkpoints, metrics, and budgets; it does not establish broad preservation of reasoning, safety, or factuality.

Negative and boundary evidence matters. The paper's limitations state that the method improves tool invocation more than underlying reasoning and that current reasoning patterns remain poorly aligned with tool use. The repository further shows that a reward can be positive through final-answer substring containment without proving semantic correctness, and the sampler does not retain the terminal no-tool response. No generated trajectory corpus, exact trained checkpoints, or immutable run manifest is available for independent recoding of successes, failures, or paper-table results.
