The paper studies how to improve tool-using language models when useful supervision must come from interaction with an executable environment rather than from a static answer alone. Its canonical publication is **Findings of the Association for Computational Linguistics: ACL 2026**, DOI `10.18653/v1/2026.findings-acl.109`. The directory slug ends in `2025` because arXiv:2508.08791 first appeared on 2025-08-12; this date must not be confused with the formal venue year, 2026.

The released unit is a local tool environment, not a frozen trajectory. Each raw JSONL row begins with one user message and carries serialized JSON tool schemas, row-specific Python implementations, a mapping from tool names to hidden subanswers that remain unsolved, `solve_rate`, a scenario/source label, the split, and a final reference answer. The paper reports **2,215 training environments and 200 custom in-domain test environments**. Those counts describe environment/task definitions. They are not counts of sampled training episodes, complete command-observation histories, or retained trajectory files.

At sampling time, a Qwen2.5 or Qwen3 policy extends the initial row into a stateful `messages` history. Tool calls execute local Python functions, returned text or error strings become observations, and deterministic checks update `unsolved_set` and `solve_rate`. The sampler saves the initial state and the state after each tool-calling response. It stops when the policy produces a no-tool response or reaches 20 turns by default, but the terminal no-tool response itself is not appended to the saved output. The official repository does not contain the paper-run generated trajectory corpus.

This object belongs in `environment_agent_trajectory_data` because the environment defines observable state, tool actions, text observations, progress updates, termination, and scalar feedback consumed by agent RL. It is not evidence for a general process-supervision corpus: the so-called step-level signal is a response/state reward derived from tool outcomes and string matching, not a semantic correctness label for each reasoning step.

The paper and audited repository support L4-depth description of the environment rows, five-stage construction concept, sampler, verifier, reward, optimizer scaffold, evaluation, and failure boundaries. Canonical metadata remains `L3_summary_ready` and `partial`: the release omits the paper-run trajectories, end-to-end five-stage construction scripts, exact checkpoints and checkpoint-to-result mapping, immutable paper tag, complete replay environment, explicit data license, and broader contamination audit.
