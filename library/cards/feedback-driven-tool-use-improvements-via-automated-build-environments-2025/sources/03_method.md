**Inputs and environment construction.** The authors manually create user questions, final answers, and decomposed subquestions for four structures: single-hop, parallel single-hop, multi-hop, and parallel multi-hop. GPT-4o assists a five-stage process: scenario decomposition, tool-document generation, function integration, complexity scaling, and localized deployment. For construction, the paper reports temperature `0` and `max_tokens=2048`. The result is a row-specific set of JSON tool descriptions and Python implementations plus hidden subanswers and progress fields. The underlying fact sources, item identifiers, annotator/adjudication protocol, and source rights are not disclosed. Appendix D publishes prompts, but the audited repository has no end-to-end program implementing all five stages or preserving intermediate GPT-4o outputs and review logs.

**Released objects and splits.** `Data/jsonl/raw/train.jsonl` contains the reported 2,215 training environments: 500 single-hop, 500 parallel single-hop, 500 multi-hop, and 715 parallel multi-hop. The custom `test.jsonl` contains 200 environments, 50 per scenario. A row exposes `messages`, `tools`, `codes`, `unsolved_set`, `solve_rate`, `data_source`, `split`, and `answer`; several nested objects are JSON serialized inside strings. The authors state that the custom test set does not overlap training, but no item-level provenance manifest, deduplication program, or broader benchmark/pretraining contamination audit is released.

**Sampling and interaction.** The current Qwen2.5 or Qwen3 policy receives the accumulated message history and row-specific tool schemas. When it emits tool calls, `data_sample.py` resolves the named Python code, executes it locally, appends each returned value or error string with its `tool_call_id`, updates `unsolved_set` and `solve_rate`, and saves the resulting history state. The repository README's sampling recipe uses temperature `1.0` and at most 20 turns. The sampler saves the initial state and every tool-calling state even when a call fails or solves nothing; it exits on a no-tool response without saving that terminal response. Total sampled, successful, failed, retained, and dropped episode counts are unknown, and no paper-run trajectory files are released.

**Verifier, reward, and terminal behavior.** `answer_verify` lowercases, removes commas, strips whitespace, and tests whether the expected string is contained in the observation. Tool-calling reward is `2q/(p+1)`. Non-tool branches assign `-0.5` to blank output, `-0.3` to malformed tool markup, `1/(1+t)` to an output containing the final answer, `0.5` after all subquestions are solved, and `0` otherwise. The scalar is placed on the last valid response token. Environment completeness is `t=0`; final-answer validity is checked separately by containment. Sampling termination—no tool call or the default 20-turn limit—is not identical to successful task completion.

**Training and evaluation.** The trained bases are Qwen2.5-7B/14B-Instruct and Qwen3-8B/14B in non-reasoning and reasoning modes. The paper uses VeRL, GRPO or Reinforce++, learning rate `1e-6`, train batch size `512`, mini-batch size `32`, 16 rollouts per update, KL coefficient `0.001`, entropy coefficient `0.001`, three epochs with fresh trajectory resampling, and eight NVIDIA A100 GPUs. The released shell scripts set one epoch per invocation, so the paper's three-epoch orchestration is not fully captured by one immutable config. Qwen 32B/72B variants are evaluation-only and must not be listed as trained bases. Evaluation covers the 200-item custom test set, ToolHop, tau-bench, RoTBench, and six general-capability benchmarks.

**Reproduction boundary.** A responsible replay must pin repository commit `7022ef0529bbff4901084f17e452eb49cad5fffc`, exact model checkpoints, paper-era VeRL revision, Python/CUDA/driver/dependency versions, seeds, decoding settings, timeouts, and per-epoch state manifests. Row-provided Python must run in a disposable sandbox with restricted filesystem, network, subprocess, CPU, memory, and time; the implementation's in-process unrestricted `exec` plus a ten-second timeout is not a sandbox. No official trained checkpoint release or checkpoint-to-table map was verified.
