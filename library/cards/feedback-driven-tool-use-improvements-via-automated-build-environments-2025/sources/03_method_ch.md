**输入与 environment construction。** 作者为 single-hop、parallel single-hop、multi-hop 和 parallel multi-hop 四种结构人工创建 user question、final answer 与分解后的 subquestion。GPT-4o 辅助五阶段流程：scenario decomposition、tool-document generation、function integration、complexity scaling 与 localized deployment。论文报告 construction 使用 temperature `0`、`max_tokens=2048`。输出是逐条定制的 JSON tool description、Python implementation、隐藏 subanswer 与 progress field。底层 fact source、item identifier、annotator/adjudication protocol 和 source right 均未披露。Appendix D 提供 prompt，但经审计的 repository 没有实现全部五阶段的端到端程序，也没有保留中间 GPT-4o output 与 review log。

**公开对象与 split。** `Data/jsonl/raw/train.jsonl` 包含论文报告的 2,215 个 train environment：500 个 single-hop、500 个 parallel single-hop、500 个 multi-hop 与 715 个 parallel multi-hop。自建 `test.jsonl` 含 200 个 environment，每种 scenario 50 个。row 暴露 `messages`、`tools`、`codes`、`unsolved_set`、`solve_rate`、`data_source`、`split` 与 `answer`；其中多个嵌套对象以 JSON string 形式保存。作者声明自建 test set 与 training 不重叠，但没有公开 item-level provenance manifest、deduplication program 或更广泛的 benchmark/pretraining contamination audit。

**采样与交互。** 当前 Qwen2.5 或 Qwen3 policy 接收累积 message history 与逐条 tool schema。它发出 tool call 后，`data_sample.py` 找到对应 Python code，在本地执行，按 `tool_call_id` 追加每个返回值或 error string，更新 `unsolved_set` 和 `solve_rate`，再保存形成的 history state。repository README 的 sampling recipe 使用 temperature `1.0`，最多 20 turn。sampler 保存 initial state 与每个 tool-calling state，即使 call 失败或没有解决任何 subquestion；遇到 no-tool response 时直接退出，不保存该 terminal response。采样总量、成功/失败量、保留/丢弃 episode 数均为 unknown，paper-run trajectory file 也未公开。

**Verifier、reward 与 terminal behavior。** `answer_verify` 会转为小写、删除逗号、去除首尾空白，再检查 expected string 是否包含于 observation。tool-calling reward 为 `2q/(p+1)`。non-tool branch 对 blank output 给 `-0.5`，malformed tool markup 给 `-0.3`，包含 final answer 的 output 给 `1/(1+t)`，全部 subquestion 解决后给 `0.5`，其他情况给 `0`。scalar 附着在最后一个有效 response token。environment completeness 是 `t=0`；final-answer validity 另以 containment 检查。sampling termination——无 tool call 或达到默认 20-turn limit——不等同于 task success。

**训练与 evaluation。** 训练的 base 包括 Qwen2.5-7B/14B-Instruct，以及 Qwen3-8B/14B 的 non-reasoning 和 reasoning mode。论文使用 VeRL、GRPO 或 Reinforce++，learning rate `1e-6`、train batch size `512`、mini-batch size `32`、每次 update 16 个 rollout、KL coefficient `0.001`、entropy coefficient `0.001`，以 8 张 NVIDIA A100 训练 3 个 epoch，并在每个 epoch 重新采样 trajectory。公开 shell script 每次 invocation 设置为 1 个 epoch，因此论文的三阶段 orchestration 没有由单个 immutable config 完整表达。Qwen 32B/72B variant 只用于 evaluation，不能列为训练 base。evaluation 覆盖 200-item custom test set、ToolHop、tau-bench、RoTBench 和 6 个 general-capability benchmark。

**复现边界。** 可靠 replay 需要固定 repository commit `7022ef0529bbff4901084f17e452eb49cad5fffc`、准确 model checkpoint、paper-era VeRL revision、Python/CUDA/driver/dependency version、seed、decoding setting、timeout 与逐 epoch state manifest。row 提供的 Python 必须放在限制 filesystem、network、subprocess、CPU、memory 与 time 的 disposable sandbox 中运行；当前实现的 in-process unrestricted `exec` 加 10 秒 timeout 不是 sandbox。没有核验到 official trained checkpoint release 或 checkpoint-to-table map。
