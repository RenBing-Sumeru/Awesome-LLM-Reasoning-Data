For `environment_agent_trajectory_data`, MobileWorldBench provides a controlled way to study one transition without pretending to release an episode. A reusable row should bind source dataset/split/transition ID, current and next image hashes, natural-language action, reference change description or Yes/No target, generator identity/configuration, candidate set, filter decisions, judge model/prompt/parser, and missing-image status. Those fields would make state/action supervision auditable across MobileWorld and MobileWorldBench.

For SFT, MobileWorld supplies action-conditioned future-state descriptions and QA targets that can train a model to verbalize likely GUI changes. The demonstrated recipe fine-tunes Qwen3-VL-8B-Instruct for two epochs. Reusers should first recover exact Parquet schemas/counts, verify source-image rights and licenses, separate benchmark/test transitions by immutable hashes, record failed/no-change examples, and measure annotator/judge correlation. This is transition-prediction SFT, not full agent-trajectory training.

For evaluation, use both channels and preserve their distinct contracts. Report generation's accuracy, completeness, relevance, total score, judge version, prompt/parser, retry policy, and sampling configuration; report QA overall and per-class accuracy because Yes/No labels are imbalanced. Exclude or repair the row missing both images, and explicitly configure `gpt-4o-2024-08-06` if reproducing the paper rather than accepting the script's `gpt-4o-mini` default.

The static benchmark can support ablations on action representations, semantic versus visual prediction, judge stability, and best-of-three filtering. AndroidWorld results can motivate downstream planning experiments with predicted next states, but a live environment, reset protocol, action executor, and terminal success metric must be supplied separately. MobileWorldBench itself cannot measure those properties.

Current reuse classification is **SFT and evaluation only**. RL, reward-model training, full agent-episode training, or unrestricted redistribution is not supported by the verified release. Missing split hashes, decontamination, failure-retention statistics, exact manifests, artifact licenses, privacy/consent review, and judge pins remain blockers to stronger reuse claims.
