Methods such as OSS-Instruct first ask a strong model to synthesize new problems from source code and then generate answers and tests, making diversity dependent on the instruction teacher. UnitCoder changes the supervision entry point by treating pretraining functions directly as objects to verify and repair, with unit tests deciding acceptance while preserving original APIs and behavior. Automated tests and repair agents are not individually new. The novelty is treating failing code as material for iterative processing rather than discarding it, followed by post-refinement execution to preserve long-tail package-call distributions.
