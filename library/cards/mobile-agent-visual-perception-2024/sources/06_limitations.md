Correctness holds only for the tested apps, device setup, visual tools, model backend, and Mobile-Eval completion rules. A successful trajectory does not prove general mobile competence or robust recovery under unseen app updates.

The system depends on screenshot quality, OCR and icon localization, closed-model behavior, prompt choices, and live UI state. Failures can come from perception error, wrong coordinate grounding, bad decomposition, app latency, login state, or task ambiguity.

Reuse should not treat Mobile-Eval scores as training labels without preserving the full trace and environment provenance. Unknowns include exact public/private task split policy, long-term app reproducibility, and whether all evaluation judgments are machine-checkable.
