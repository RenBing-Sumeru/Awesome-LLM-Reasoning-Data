For `environment_agent_trajectory_data`, MMSearch-Plus is useful first as an evaluation boundary case. The public row supplies question, acceptable answers, images, category/difficulty/subtask, and a source reference; it does not supply the interaction object that the paper analyzes. A reusable derived episode should additionally pin source captures, queries, SerpAPI results, Gemini summaries, crops/SoM indices, hypotheses, model actions, invalid calls, timestamps, budgets, stopping reason, final answer, citations, judge prompt/output, and all success/failure/retry states.

The benchmark supports controlled studies of where multimodal search fails. With fixed items, APIs, caches, budget, and judge, researchers can compare no search, text search, image search, full rollout, and SoM; audit skipped image search and invalid-call loops; and separate localization, retrieval, summarization, synthesis, and stopping errors. Human SoM boxes must be reported as privileged supervision rather than silently merged with automatic agent capability.

The answer contract supports judge audits, not process certification. Researchers can construct human-labeled alternative-answer and citation sets, measure GPT-4o false positives/negatives, compare the optional rule baseline once released, and test whether answer accuracy changes when search evidence is held constant. Provenance-aware evaluation should score citation/evidence support separately because the published judge does not.

The supported reuse class is **evaluation and audit only**, matching `training_use: evaluation`. The HF split name `train` must not be interpreted as permission or evidence for training. Direct SFT, RL, preference, reward-model, or agent-policy reuse is blocked pending a complete trajectory release, explicit partition/refresh policy, contamination audit, frozen replay package, evaluator/SoM release, and item-level third-party rights review. Scores motivate these checks; they do not prove data quality.
