核心反转是：先发现可执行交互，再为它命名能够支持的任务。规则驱动的探索遍历可交互 GUI 元素并记录“动作前状态—动作—动作后状态”三元组。发现阶段的动作集合为 `CLICK`、`TYPE` 和 `SCROLL`；文本输入内容由 GPT-4o 生成，其余探索策略被论文描述为规则驱动。

GPT-4o 根据动作及其前后视觉证据，生成简洁的低层指令、后续操作分析和可执行的高层任务。随后由 GPT-4o 这类具备 GUI 操作能力的模型在环境中执行高层任务，得到完整轨迹。该顺序让任务表述扎根于已经发生的状态变化，而不是只看初始界面凭空设想任务。

第二个关键点是不以二元“完成/失败”直接丢弃数据。轨迹奖励模型（TRM）按完成度和连贯性给每条轨迹 1–5 分，并按 `P(g_i)=R_i/sum_k R_k` 采样。因此，不完整轨迹仍可进入训练，但权重较低。这是一项采样契约，并不证明所有保留步骤都正确。
