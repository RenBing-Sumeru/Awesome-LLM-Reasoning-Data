The largest dependency is GPT-4o: it supplies text-entry content, reverse-synthesizes instructions, executes tasks, and scores trajectories. The paper tests score alignment with Qwen2.5-VL-72B and humans, but correlated judges can share blind spots. The authors also state that task-executing model capability limits how many trajectories can be constructed successfully.

Incomplete episodes are deliberately retained through nonzero reward. This preserves useful prefixes but may teach dead ends, redundant actions, or incorrect partial plans. The TRM sees low-level instructions and only the last three states, so long-range omissions or side effects outside that window may be missed. Score calibration across apps, websites, and environment revisions is not established.

Release auditability remains partial. The mobile Hugging Face data has one train split and no documented task-, app-, or template-disjoint split. Decontamination against AndroidControl, AndroidWorld, WebArena, pretrained-model data, or generated task templates is unknown. Exact environment/app versions, reset state, credentials, network conditions, and deterministic replay protocol are not pinned. The paper gives no privacy review, PII-removal procedure, or security policy for model-generated interaction content.

The Hugging Face card declares MIT, but separate rights for screenshots, app assets, websites, model outputs, and Google Drive raw triples are not documented. The GitHub repository shows no formal release objects, so reproducible use should pin repository and dataset revisions independently.
