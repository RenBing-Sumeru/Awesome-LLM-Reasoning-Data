The paper's explicit limitation is that OCRM needs the SFT behavior-policy density for every reward-model comparison. This is available when the comparisons were generated by a retained, known SFT checkpoint. It is not generally available for pooled preference data from unknown or heterogeneous policies, and the paper leaves that extension open.

Formal softmax support is weaker than practical coverage. Later policies may assign high probability to response regions represented by few or no useful fixed comparisons. Importance weighting cannot manufacture missing examples. Large sequence-probability ratios also raise variance; the very small exponent `eta=0.001` and relative mixture `alpha=0.9` stabilize training by adding bias, so the practical estimator no longer has the exact unflattened correction guarantee.

Fixed labels preserve fixed mistakes. OCRM cannot repair a wrong synthetic preference, add evidence for a response mode absent from the pair set, or reveal a judge criterion not represented by Skywork-Reward-Llama-3.1-8B-v0.2. Using the same gold reward model to label and evaluate most runs can reward evaluator-specific agreement. The GPT 4.1 Nano study changes the evaluator but still uses one model for both roles; neither setup substitutes for human validation.

The stagewise algorithm is approximate. Reward-model retraining after every policy update is considered infeasible, but long intervals allow renewed drift. Short intervals interact badly with value-network resets because advantage estimates are initially inaccurate. The full method also changes the KL reference and resets optimizer/value state; ablations show these choices improve results, which complicates causal attribution.

Evidence breadth is limited. Only the main Pythia-1B TL;DR result uses three seeds, while most other model-task cells and ablations use one. Hyperparameters were not extensively tuned, some large-model baselines were omitted for compute reasons, and the five-stage extension is a single-seed result. An Alpaca-Farm analysis reports average semantic clusters decreasing from 11.90 for PPO to 11.72 and 11.31 for two- and three-stage OCRM.

Release auditability remains partial. Code is available under MIT, but there is no tagged release, immutable labeled-pair snapshot, stage-weight archive, effective-sample-size report, or unified upstream-license manifest. At inspected commit `89d4d19a41bcaa187c43dac2e23eb3fafba59e45`, the shell launchers use a module-directory name not present in the repository tree, so a reproducer must first reconcile it with the available `ocrm` package. Decontamination is undisclosed. Reproducing the claimed effective distribution therefore requires regenerating data and trusting the exact checkpoints, tokenization, log-probability conventions, and stage configuration.
