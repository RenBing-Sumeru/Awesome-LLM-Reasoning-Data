The canonical sources are the AAAI-26 proceedings article and arXiv:2511.09157v1. ProBench addresses a weakness of mobile-GUI benchmarks that judge only the final screen: a final state can look correct even when the agent skipped a required intermediate operation such as sorting, filtering, or selecting a location. The benchmark therefore adds action-derived process evidence to terminal evaluation without prescribing one rigid gold trajectory.

The paper defines **217 tasks across 34 applications: 149 State-related and 68 Process-related**. The language breakdown is **75 English tasks and 142 Chinese tasks**: English has 52 State plus 23 Process, while Chinese has 97 State plus 45 Process. The 34 applications consist of 14 English and 20 Chinese apps across system, tools, news, travel, shopping/finance, media, lifestyle, and social categories.

The evaluation object is a live single-app Android episode: natural-language instruction, real-time screenshots, historical operations, parsed actions, optional textualized action evidence, final screenshot, completion signal, and binary terminal outcome. State tasks are judged from instruction plus final screenshot. Process tasks additionally give the terminal judge the complete textualized sequence of observed actions.

No official ProBench code repository, project page, Hugging Face record, machine-readable task manifest, executable environment package, result file, or public success/failure trajectory corpus was confirmed. Appendix tables expose task text and the paper describes the runtime, but the release boundary prevents treating ProBench as reusable training data or a reproducible environment artifact. Supported `training_use` is evaluation only; canonical metadata remains `L3_summary_ready` and `status: partial`.
