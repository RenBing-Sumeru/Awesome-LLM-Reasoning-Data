ProBench's core contribution is a process-aware terminal evaluation contract. The evaluated agent still acts from screenshots and history; Process Provider separately converts the agent's own runtime actions into textual evidence. That evidence is supplied to the final judge together with the final screenshot. It is not a gold action sequence, dense process reward, agent-visible hint, or process-supervision label.

Process Provider offers two optional textualization mechanisms, not two reward functions. Structure Description Converter programmatically parses the accessibility tree after each click, locates the smallest enclosing clickable node, and extracts text, content description, resource ID, or child descriptions. MLLM-based Summarizer compares before/after screenshots, marks the click coordinate, and uses a multimodal model to summarize the operation. The main experiments use Structure Description Converter; Gemini 2.5 Pro is the terminal judge. The validation study also tests Gemini 2.5 Pro as the MLLM summarizer.

The feedback contract combines three components: live-device environmental state, programmatic action textualization, and judgment-required binary scoring. For State tasks, Gemini 2.5 Pro sees the task and final screenshot. For Process tasks, it also sees the full textualized action sequence. It returns True/False, aggregated as accuracy/success rate. A `COMPLETE` signal is required but insufficient: the judge must find the final state and, for Process tasks, critical operations satisfactory.

Relative to final-screen-only mobile benchmarks, the change is the inclusion of path-sensitive action evidence without enforcing one exact route. Relative to process supervision, the boundary is decisive: the action evidence is generated from the evaluated trajectory and consumed only by the terminal evaluator. No policy training, step label, process reward, or demonstration release is provided.
