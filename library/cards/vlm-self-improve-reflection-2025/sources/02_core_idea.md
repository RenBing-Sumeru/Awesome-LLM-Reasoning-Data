R3V represents each attempt as an image-grounded question or task, a complete generated rationale and final answer, and a binary terminal outcome. For TabMWP, ChartQA and CLEVR-Math, task-specific parsers compare the final answer with the reference; MiniWob uses the simulated environment's 0/1 success reward. This outcome partitions complete solutions into local positive and negative pools. It does not label individual reasoning steps.

The same accumulated pool is converted into three SFT task families. Direct solution training uses the latest available positive full solution. Self-refine places the latest negative full solution in the user context and uses the latest positive full solution as the assistant target; this is negative-conditioned imitation of an answer-correct peer completion, not a verified edit of the supplied error. Self-select shows exactly three shuffled candidates and trains the model to emit the correct final answer.

The construction scripts can create two three-candidate patterns for an eligible item: the latest two positives with the latest negative, and the latest positive with the latest two negatives. Both require mixed labels and at least one positive. At test time, the trained MLLM receives newly sampled candidate solutions and generates the final answer itself, so the selection ability becomes a test-time-compute mechanism rather than a separate calibrated scoring head.

The central data contribution is consequently a rollout-to-SFT transformation contract: terminally labelled full solutions are accumulated, recent positives and negatives are composed into direct, refinement, and selection conversations, and the updated model produces the next candidate distribution. The released data, however, contains prepared QA and GPT-CoT warm-up rows rather than this derived corpus.
