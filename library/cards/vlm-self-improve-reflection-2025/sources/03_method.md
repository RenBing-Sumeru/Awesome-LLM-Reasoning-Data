The paper covers TabMWP, ChartQA's human-written split, CLEVR-Math, MiniWob, the English GeoQA translation from UniGeo, and M3CoT. A source object contains an image, question, optional choices or structured context, and reference final answer; MiniWob additionally supplies HTML and asks for Python keyboard/mouse action code. Main experiments use Qwen-VL and LLaVA-1.5, while a stronger-backbone study uses Qwen2-VL-7B-Instruct on GeoQA. Exact base checkpoint and tokenizer revisions are not pinned.

GPT-4o provides warm-up CoT for 1,000 TabMWP, 800 ChartQA, 1,000 CLEVR-Math, 550 MiniWob, 936 M3CoT, and 536 GeoQA items in the main experiments. Thereafter the current task-specific MLLM samples complete rationale-answer solutions. The paper defaults to three new solutions per item per sampling iteration and reports four or five task-dependent iterations until saturation. The released helper samples with top-k 50, top-p 0.95, temperature 0.9, and at most 384 new tokens; generation, shuffle, and candidate-order seeds are undisclosed.

For answer verification, TabMWP extracts and normalizes option letters or free-form values before equality comparison. ChartQA accepts numeric predictions within 5 percent of the reference and otherwise uses case-insensitive exact text. CLEVR-Math extracts an integer following `Answer:` and compares equality. MiniWob supplies environmental success. GeoQA and M3CoT use their benchmark evaluators. These rules create positive and negative full-solution pools from terminal outcomes; no process verifier checks whether intermediate perception, symbols, calculations, or deductions are valid.

At each rebuild, a direct SFT object takes the latest positive. If both labels are present, a refinement object embeds the latest negative in the prompt and targets the latest positive. Selection objects contain exactly three candidates: when available, the latest two positives plus latest negative and the latest positive plus latest two negatives form separate records, after random display-order shuffling. The selector's target is the correct final answer extracted from a positive completion, not a candidate ID, confidence, reward, or explanation of why alternatives fail.

Multi-task causal SFT mixes direct solution, self-refine, and self-select objects. Table 6 reports global batch size 64, learning rate 3e-5, three epochs, constant schedule with warm-up ratio 0.1, weight decay 0, and AdamW. LoRA rank/alpha is 64/16 for Qwen-VL and 128/256 for LLaVA-1.5, with dropout 0.05 and DeepSpeed ZeRO-2. The updated checkpoint generates the next pool, so the generation distribution changes across iterations.

The main controller's default five loops train loop 0 on direct QA plus GPT warm-up, then sample three files from each completed earlier checkpoint and accumulate them for reconstruction. By the last loop this can expose up to 12 generated candidates per item from four checkpoints, although realized counts and parser failures are not published. Test-time selection normally samples three complete solutions, places them with the original image/question into the MLLM context, and takes one greedy selector response; no threshold, tie rule, or abstention mechanism is disclosed.

The main repository releases 40,457 direct-QA rows across TabMWP, ChartQA, and CLEVR-Math, plus 2,800 GPT-CoT warm-up rows per base-model variant—5,600 across the Qwen-VL and LLaVA-1.5 variants. These JSON records contain `image` and a two-turn `conversations` structure. The self-generated rollouts, terminal labels, iteration identities, derived direct/refine/select decisions, `D_REF` and `D_SEL` corpora, final mixed files, checkpoints, and run logs are generated locally and are not frozen in the release.
