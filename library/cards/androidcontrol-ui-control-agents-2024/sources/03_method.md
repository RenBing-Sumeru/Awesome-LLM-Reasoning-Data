1. Inputs: human Android demonstrations, high-level goals, per-step instructions, screenshots, accessibility trees, and action logs. 2. Pipeline: serialize each episode as compressed TFRecord; store screenshots and accessibility forests for every observation; encode actions as JSON dictionaries; generate split files designed to test generalization beyond trained apps and tasks; train/evaluate UI-control agents under different data scales. 3. Outputs: TFRecord files, a split file in the public GCS bucket, parsing examples, action-space documentation, and evaluation-ready demonstrations. 4. Feedback: offline comparison between predicted and reference actions, using action type and action-specific parameters such as coordinates, scroll direction, app name, or typed text. Reuse requires pinning the GCS bucket contents, split file, repository commit, TensorFlow/protobuf/android_env versions, action parser, and train-scale budget.
