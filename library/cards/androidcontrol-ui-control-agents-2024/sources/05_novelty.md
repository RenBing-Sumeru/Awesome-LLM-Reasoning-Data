The prior baseline is AITW and smaller or less explicitly split UI datasets. AndroidControl changes the benchmark object by combining screenshots, accessibility trees, high-level and step-level instructions, JSON actions, broad app coverage, and split files for app/task generalization. The direction signal is that GUI-agent evaluation must track data scale and out-of-distribution app composition, not only aggregate action accuracy. What is not new: human demonstrations, TFRecords, accessibility trees, and supervised action prediction. Before reuse, inspect bucket version, split leakage, duplicated app states, license scope, Android app availability, accessibility-tree parser dependency, coordinate normalization, and data-scale sampling protocol.
