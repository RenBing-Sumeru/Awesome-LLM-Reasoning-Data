Guided-ReST uses an optimal solution as a sequence of local landmarks for repairing the policy's own search, rather than as a complete response to imitate. The intended data operation preserves failed exploration as context, replaces one failed continuation with the next optimal subgoal, truncates the now-inconsistent suffix, and lets the same policy search onward. Preliminary Countdown evidence explains the design: as an optimal prefix grows from zero to three steps, success rises from 55.96% to 100%, but cross-entropy loss also rises from 0.0481 to 0.2539, suggesting that wholesale prefix distillation moves away from the policy distribution (Paper Table 1).

For Countdown, each node on the optimal path is a subgoal. If a trace reaches subgoal `t-1` but fails below it, the algorithm randomly selects an explored child, replaces that child's operation and resulting state with subgoal `t`, discards the inconsistent suffix, and samples a continuation. It repeats this process until the trace succeeds or all subgoals have been inserted. The resulting record contains policy exploration before the correction, explicit privileged structure at the correction, and a policy-generated suffix.

For code self-repair, a full turn is the search unit because a fine-grained code tree is impractical. A candidate program is executed; selected public-test failures become the next feedback message. During an augmentation round, the feedback also contains a ground-truth reference program and the policy regenerates the remaining turns. For the saved training view, the real program is replaced by the literal dummy marker `# REFERENCE CODE HERE`, while the paper reports loss only on the final model response. Thus the guide affects which continuation is generated without remaining verbatim in the SFT input.

The feedback contract is answer-level and programmatic, not process truth. Countdown checks whether the full trace legally reaches the target. In code, public-test results drive interaction, but the official implementation computes a binary score from all ground-truth tests attached to the task and retains only rows with positive score. These checks observe executable outcome and arithmetic legality; they do not judge explanation faithfulness, minimality, robustness, or whether a candidate exploits weak tests.

Compared with behavior cloning, SoS, ReST, sparse-reward PPO, and the single-round stronger-guide interaction discussed in related work, the distinguishing change is repeated, localized use of privileged information during data generation. The contribution is therefore a construction and masking contract, not the isolated invention of self-training, tree search, PPO, or execution feedback.
