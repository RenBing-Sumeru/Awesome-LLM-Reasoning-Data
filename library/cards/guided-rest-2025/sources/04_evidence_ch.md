最强证据说明的是方法在固定任务与模型设置下的行为，而不是对每条生成记录的数据审计。

**为什么使用局部引导。** 在 10,000 条 Countdown 样本的动机实验中，最优前缀从零步增加到一、二、三步时，搜索成功率由 55.96% 依次升至 85.28%、95.27% 和 100.00%；交叉熵损失也从 0.0481 升至 0.1245、0.2412 和 0.2539。作者用这一权衡支持局部改写，而不是直接模仿长最优前缀（论文 Table 1）。

**Countdown 准确率与候选覆盖。** 在 Llama-3.2-1B-Instruct、500,000 条 SoS 初始化轨迹、三轮各 200,000 道题的 Guided-ReST，以及可选 operation-level PPO 设置下，完整系统在 4,096-token 最大预算下对已见和未见目标都达到约 87% greedy accuracy。论文报告其比次优 PPO 高十个百分点以上，并用约一半 token 达到相近准确率（论文 §5.2、Figure 3）。在最终 PPO 之前，temperature 1.0 下，Guided-ReST 与 ReST 在已见目标上的 pass@1/pass@32 分别为 62.7/96.8 与 62.3/76.6，在未见目标上分别为 61.0/96.8 与 60.8/77.0（论文 Table 2）。随 k 增大的差距支持一个更窄的结论：在该设置下，这种数据生成流程扩大了正确候选覆盖。

**优化器与奖励消融。** 在 Countdown 最大预算下，operation-level PPO 达到 87%，token-level PPO 为 83%；论文报告前者在低预算区约有 2 倍 token 效率，在高预算区约有 1.5 倍（论文 §5.4、Figure 5）。另一种稠密奖励在到达最优子目标时增加 0.25，为减少重复子目标的 reward hacking，每个子目标只计奖一次；该方案整体收益很小，并在高预算下略有下降（论文 §5.5、Figure 6）。这个负结果说明构造期特权引导不等价于 reward shaping。

**代码自修复。** 在 Qwen2.5-7B-Instruct、16,000 道训练题、每题八个 episode、最多四轮和三次 SFT 迭代下，Guided-ReST 在 165 道 CodeContests 题上的 pass@1/pass@32 为 10.5/33.9，ReST 为 9.4/30.4；在 408 道 CodeForces 题上，两者分别为 9.7/37.6 和 9.7/35.9（论文 Table 3）。作者把增益描述为中等，并将较小效果归因于训练题更少、episode-level augmentation 不完整和搜索能力较弱。CodeContests 因训练混合中含同源题而被明确视为近分布，CodeForces 才是更有信息量的分布外检查。
