Guided-ReST addresses a data-construction problem: how can a model learn useful search behavior from its own failed and successful attempts when ordinary outcome-filtered self-training rarely gives a weak policy enough positive trajectories? Stream of Search (SoS) first trains a model on linearized symbolic traces containing generation, exploration, verification, and backtracking. Those traces improve search generalization over behavior cloning an optimal path, but they can spend a fixed token budget on irrelevant branches. ReST retains successful self-generated traces, yet supplies no localized correction when the current policy fails.

The official record is the NeurIPS 2025 Main Conference paper, with arXiv v2 and OpenReview records and an official implementation. The work belongs in **Data Construction and Open Release Recipes** because its central contribution is a transformation from answer-keyed tasks, current-policy behavior, and privileged optimal artifacts into verified SFT trajectories. It is not a new benchmark, a human preference dataset, a learned reward model, or a frozen corpus release.

The paper studies two record types. A Countdown record starts from four integers and a target and contains a language-form tree-search trace over legal arithmetic states and operations. A code self-repair record is a multi-turn message sequence: a complete reasoning-and-code attempt, execution feedback, a revision instruction, and another attempt. In both settings the current policy authors the generated behavior; an optimal Countdown path or reference program is available only to the construction process; and a programmatic checker determines whether a candidate can be retained.

Three data views must remain separate. The **privileged construction view** contains optimal subgoals or reference code. The **training view** contains an edited Countdown trace or a code episode in which the real reference program is replaced by the documented dummy marker. The **inference view** receives neither optimal artifact. This Card reaches the accepted L4 boundary because the paper, supplement, venue metadata, affiliations, code, license, sampling settings, filtering scripts, and workflow state were checked; generated buffers, checkpoints, and a frozen data release remain unavailable.
