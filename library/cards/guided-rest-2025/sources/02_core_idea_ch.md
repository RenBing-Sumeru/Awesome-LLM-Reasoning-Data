Guided-ReST 不把最优解当作整段模仿答案，而是将其拆成一系列局部地标，用来修补策略自己的搜索。该数据操作保留失败探索作为上下文，把一条失败延续替换成下一个最优子目标，删除因此失效的后缀，再让同一个策略继续搜索。Countdown 预实验说明了这一设计：最优前缀从零步增加到三步时，成功率由 55.96% 上升到 100%，但交叉熵损失也从 0.0481 增至 0.2539，说明整段前缀蒸馏会逐渐偏离当前策略分布（论文 Table 1）。

在 Countdown 中，最优路径上的每个节点都是一个子目标。如果轨迹已到达子目标 `t-1`，却在其下方搜索失败，算法会随机选取一个已探索子节点，用子目标 `t` 替换该节点的运算和结果状态，删除不再一致的后缀，再采样续写。这个过程持续到轨迹成功或所有子目标都被插入。最终记录同时包含纠正前的策略探索、纠正点处的显式特权结构，以及纠正后的策略生成后缀。

在代码自修复中，细粒度代码树不实用，因此一整轮交互就是搜索单位。候选程序被执行，选出的公开测试失败会成为下一条反馈消息；进入增强轮次时，反馈还会加入 ground-truth reference program，随后由策略重新生成剩余轮次。保存训练视图时，真实程序被字面 dummy marker `# REFERENCE CODE HERE` 替换；论文同时说明只对最后一次模型回复计算损失。因此，引导改变了被生成的续写，但不会以真实参考程序原文留在 SFT 输入中。

反馈契约是答案级、程序化判断，而不是过程真值。Countdown 检查整条轨迹是否通过合法运算到达目标数。代码场景用公开测试结果推动交互，但官方实现会根据任务附带的全部 ground-truth tests 计算二元分数，并只保留正分记录。这些检查能够观察可执行结果和算术合法性，却不能判断解释是否忠实、程序是否最简或稳健，也不能排除候选利用弱测试的可能。

与 behavior cloning、SoS、ReST、稀疏奖励 PPO，以及 related work 中讨论的单轮强 guide 交互相比，真正不同之处是构造数据时反复、局部地使用特权信息。因此，这项贡献是一份构造与遮蔽契约，而不是单独发明 self-training、树搜索、PPO 或 execution feedback。
