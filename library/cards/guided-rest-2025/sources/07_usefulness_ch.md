对 **Data Construction and Open Release Recipes** 方向而言，这项工作提供了一个具体模式：利用特权引导完成蒸馏，但不让部署接口看到同样的信息。它在节点级与 episode-level 搜索中都说明了任务来源、策略作者、oracle 产物、局部变换、程序化接收检查、迭代日程、优化器和评测预算。

**配方重建。** 应把流水线拆成独立阶段：任务与解答来源、无引导策略生成、失败定位、特权续写、构造视图到训练视图的变换、程序化打分、正向记录筛选、迭代 SFT，以及可选 Countdown PPO。只有分开这些阶段，才能检验增益来自引导、更强 verifier、更多样本还是后续优化。

**Countdown 最小可审计记录。** 至少保留任务 ID 与 split、输入整数、目标数、来源版本、原始策略轨迹、被选子节点及其父节点、注入子目标索引与运算、截断位置、重新生成后缀、完整合法性判定、生成器 checkpoint、采样配置、迭代轮次和拒绝原因。改写前后轨迹都需保存，才能测量注入了多少 oracle 结构。

**代码最小可审计记录。** 至少保留任务来源与版本、prompt、轮次边界、每次代码尝试、公开测试选择规则与反馈、全测试分数、成功轮次、参考解 provenance、`privileged_generation_only` 标记、精确 dummy 替换变换、loss mask、执行 harness 与 sandbox 版本、采样 seed 和记录是否被保留。遮蔽前视图含特权参考代码，可能需要访问和许可证控制；只有训练视图无法重建这次介入。

**受控研究。** 应在相同基础模型、唯一任务池、尝试次数、verifier、token 预算和优化器下，对比 behavior cloning、SoS、ReST、Guided-ReST 与 Guided-ReST 加 PPO。接收记录数、pass@k 曲线、token 效率曲线和语料统计应分别报告。还应审计“公开反馈停止”与“全测试筛选”的差异，并在生成器不可见的留出测试上独立重执行入选代码。

**复用判断。** 官方实现适合作为配方与审计参考；生成数据在直接训练复用方面属于 **blocked pending verification**，因为未核验到冻结轨迹快照、record manifest、拒绝集合、去污染报告或统一上游许可证。复用前应固定仓库 commit 与作者托管输入版本，冻结环境镜像，对 prompt 和 tests 计算哈希，在所有具名代码来源之间重做重复与污染检查，并同时发布接收和拒绝记录的 lineage。
