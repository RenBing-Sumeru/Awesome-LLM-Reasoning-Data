**Access to privileged solutions is the core assumption.** Guided-ReST requires an optimal Countdown path or a reference program. Countdown also assumes an oracle that identifies the first incorrect step and the corresponding backtrack location. The authors note that ordinary instruction-following models may not localize reasoning errors reliably; replacing the oracle with a stronger model would introduce teacher error and calibration questions not tested here.

**The privileged boundary is task-dependent.** Countdown deliberately inserts optimal operations and arithmetic states into retained traces. This can teach useful recovery structure, but it can also transmit target templates or make memorization hard to distinguish from search skill. Code repair creates a clearer text boundary by replacing the real reference program before SFT, yet a reproduction still needs to inspect serialized messages, loss masks, paths, and test fixtures to ensure privileged tokens do not survive elsewhere.

**Interaction feedback and selection feedback differ.** Code turns expose selected public-test failures, whereas the official preparation pipeline scores candidates against all task ground-truth tests and keeps positive rows. This can suppress visible public-test failures while hiding why other candidates were rejected. Test coverage, harness errors, timeouts, nondeterminism, and sandbox differences create false positives or false negatives; passing all available tests still does not establish semantic correctness outside them.

**Outcome checks do not certify process quality.** Countdown legality and code execution verify outcomes under their parsers and tests. They do not measure whether a rationale is faithful, whether a search branch was necessary, whether an explanation is safe, or whether a program is robust. Binary filtering also removes failed traces that would be useful for audit or contrastive supervision. The paper does not publish acceptance rates, rejection reasons, duplicate rates, or trace-length distributions.

**Split and contamination evidence is incomplete.** The unseen-target Countdown split reduces direct target memorization but does not audit structural template reuse. CodeContests is explicitly near-distribution because the training mixture contains that source. The paper and checked repository do not disclose a decontamination procedure across SYNTHETIC-1, APPS, CodeContests, TACO, and CodeForces, nor exact source revisions and per-source counts.

**Release reproducibility is partial.** The code is Apache-2.0 and provides commands, but the checked repository has no tag or release, generated rollout buffers, checkpoints, record manifest, or frozen environment image. The repository's license does not automatically determine rights for upstream problems, reference programs, or generated derivatives. Direct training reuse is therefore blocked pending a frozen snapshot, lineage and overlap audit, and license verification; the recipe is usable as an implementation and audit reference.

**Experimental scope is narrow.** The evidence covers four-number Countdown and Python code self-repair with executable tests. Code gains are moderate, episode-level guidance does not identify fine-grained code subgoals, and code receives no PPO experiment. The main results have no error bars, total generation cost is undisclosed, and benchmark improvement must not be treated as proof that every selected trajectory is high-quality or broadly reusable.
