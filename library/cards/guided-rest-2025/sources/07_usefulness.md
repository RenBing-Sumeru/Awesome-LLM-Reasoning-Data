For the **Data Construction and Open Release Recipes** track, this work is a concrete pattern for distilling privileged guidance without exposing the same interface at deployment. It identifies the task source, policy author, oracle artifact, localized transformation, programmatic acceptance check, iteration schedule, optimizer, and evaluation budget for both node-level and episode-level search.

**Recipe reconstruction.** Reimplement the pipeline as separate stages: task and solution sourcing; unguided policy generation; failure localization; privileged continuation; construction-view to training-view transformation; programmatic scoring; positive-row filtering; iterative SFT; and optional Countdown PPO. Keeping these stages separate makes it possible to test whether gains come from guidance, a stronger verifier, more samples, or downstream optimization.

**Minimum auditable Countdown record.** Preserve task ID and split, input integers, target, source revision, original policy trace, selected child and parent node, injected subgoal index and operation, truncation offset, regenerated suffix, full legality verdict, generator checkpoint, sampling configuration, iteration, and rejection reason. Both pre-edit and post-edit traces are needed to measure how much oracle structure was inserted.

**Minimum auditable code record.** Preserve task source and revision, prompt, turn boundaries, every code attempt, public-test selection rule and feedback, all-tests score, success turn, reference-solution provenance, a `privileged_generation_only` flag, the exact dummy replacement transform, loss mask, execution-harness and sandbox version, sampling seed, and whether the row was retained. The pre-mask view contains privileged reference code and may require access and license controls; the train view alone cannot reconstruct the intervention.

**Controlled studies.** Compare behavior cloning, SoS, ReST, Guided-ReST, and Guided-ReST plus PPO at matched base model, unique task pool, number of attempts, verifier, token budget, and optimizer. Report accepted-record counts, pass@k curves, token-efficiency curves, and corpus statistics separately. Audit the difference between public-feedback stopping and all-tests filtering, and independently re-execute selected code on held-out tests unavailable to the generator.

**Reuse decision.** The implementation is suitable as a recipe and audit reference. The generated data are **blocked pending verification** for direct training reuse because no frozen trajectory snapshot, record manifest, rejected set, decontamination report, or consolidated upstream license was verified. Before reuse, pin the repository commit and author-hosted input revisions, freeze an environment image, hash prompts and tests, rerun duplicate and contamination checks across all named code sources, and publish accepted plus rejected record lineage.
