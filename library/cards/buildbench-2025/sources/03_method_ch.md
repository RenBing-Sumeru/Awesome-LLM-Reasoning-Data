**输入与 task construction。** 作者从 2008 年 4 月 1 日至 2024 年 1 月 1 日的 277 万个 C 与 423 万个 C++ GitHub repository population 出发，删除名称/描述命中低质量 keyword、star 少于 50 或属于 fork 的 repository，余下 657 万个。随后按作者所述的 95% confidence/5% error 理由随机抽取 385 个 candidate。12 名据称拥有 3 年以上 systems research 经验的研究生耗时约 150 小时尝试全部 candidate。错误或不可 cross-compile 的 OS target、trivial/unbuildable content、缺少关键文件或 dependency 无法解析，以及在 best effort 下仍无法解决的 compile/link failure 会被排除，最终得到 148 个可编译 evaluation task。另有 70 个 popular repository 作为 validation set；人工 best-effort 的准确时间/action 阈值没有操作化定义。

**Episode setup 与 retrieval。** 每个 repository 都在一个全新的 Ubuntu 22.04 Docker container 中开始，agent 拥有 root 权限，环境仅预装少量 package。agent 接收 repository、README 与根目录文件列表。可选的 LLM-assisted retriever 先提炼 README，判断 instruction 是否充分；每个 iteration 最多继续访问 3 个新的 repository 或 external-documentation link，抓取并总结内容，最多重复 3 个 iteration。live document、package index、submodule 与 cache 均未固定。

**Interaction loop。** Bash Command Generator 生成一批 `S_k`；Execution Agent 运行它并返回 result `f_k`，其中包括 build error，用于基于 observation 的下一轮修改。action 可以切换目录、安装 dependency、配置 debug build、compile/install 或复制 artifact、retry，以及修改 source。Appendix D 记录了 agent 替换过时 OpenCV constant 后成功 build 的案例，因此 source patching 属于实际展示的 behavior。loop 在 `Success(f_k)` 触发或达到最大 step `K` 时停止，但 `Success` 的实现与 `K` 的数值都未披露。offline scoring 再依据 termination、binary presence 与人工 target filename 计算 unvalidated Completion、Strict Success 与 Flexible Success。

**Model 与预算。** single-turn baseline 使用 GPT o3-mini 和 Claude 3.7 Sonnet。OSS-Build-Agent 评测 GPT-4o、GPT o3-mini、Claude 3.7 Sonnet、Gemini 2.5 Flash、Qwen3 235B 与 Qwen3 Coder 485B；CompileAgent 使用 GPT-4o。准确 API snapshot ID、temperature、seed、token/cost limit、wall-clock timeout 与 turn cap 数值均为 unknown。多数 configuration 只有一次 dataset-wide run；GPT-4o with retrieval 重复 3 次，并同时报告 mean/standard deviation 与 pass@1–pass@3。OSS-Build-Agent 平均有 6.6 次 error-resolution attempt；CompileAgent 的 7.5 step 使用不同的 one-command-at-a-time action unit。

**输出与 release。** 当前固定的 test revision 暴露 385 条 metadata、385 条 repository-level label（148 条 `Yes`、237 条 `No`）以及 130 个 retrieval-label object；test label 为全部 385 条记录提供 `commit_hash`。固定的 validation revision 暴露 70 条记录（65 条 `Yes`、5 条 `No`），但没有 repository commit hash。两个 release 都不包含完整 command history、stdout/stderr log、state snapshot、patch、binary、逐 run terminal report 或 trajectory value，也没有 step-level correctness label 或 state-action reward。

**用途与 reproducibility 边界。** 论文只报告 evaluation 与 failure analysis，没有报告 SFT、preference optimization、reward-model training、process supervision、RLVR 或 agent policy training。复现必须固定 arXiv version、两个 Hugging Face revision、每个 source commit、container image/Dockerfile、dependency 与 package-index snapshot、submodule、documentation snapshot、network/cache policy、timeout 与 `K`、model snapshot、seed、command log、patch、binary 与 evaluator version。没有核验到公开且与论文关联的 OSS-Build-Agent repository，因此 `artifacts.code` 正确保持 `null`。去除 fork 与 date/star filter 只是 selection control，不是 model-corpus 或 benchmark-overlap decontamination procedure。
