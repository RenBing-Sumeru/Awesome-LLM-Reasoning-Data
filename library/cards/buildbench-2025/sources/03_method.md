**Inputs and task construction.** The authors query a population of 2.77 million C and 4.23 million C++ GitHub repositories dated from 2008-04-01 through 2024-01-01. They remove repositories whose names/descriptions match low-quality keywords, have fewer than 50 stars, or are forks, leaving 6.57 million. A random sample of 385 is chosen under the authors' 95% confidence/5% error rationale. Twelve systems graduate students with more than three years of reported systems-research experience spend about 150 hours attempting all candidates. They exclude wrong or non-cross-compilable OS targets, trivial/unbuildable content, missing critical files or unresolvable dependencies, and compile/link failures unresolved under best effort. This yields 148 compilable evaluation tasks. A separate set of 70 popular repositories is used for validation; the exact human best-effort time/action threshold is not operationalized.

**Episode setup and retrieval.** Each repository starts in a fresh Ubuntu 22.04 Docker container with root access and minimal pre-installed packages. The agent receives the repository, README, and root file list. The optional LLM-assisted retriever first distills the README, judges whether instructions are sufficient, follows up to three new repository or external-documentation links per iteration, fetches and summarizes them, and repeats for at most three iterations. Live documents, package indexes, submodules, and caches are not pinned.

**Interaction loop.** A Bash Command Generator produces a batch `S_k`; the Execution Agent runs it and returns result `f_k`, including build errors, for observation-driven revision. Actions can navigate directories, install dependencies, configure a debug build, compile/install or copy artifacts, retry, and modify source. Appendix D documents replacing obsolete OpenCV constants before a successful build, so source patching is part of the demonstrated behavior. The loop stops at `Success(f_k)` or maximum step `K`, but neither the implementation of `Success` nor numeric `K` is disclosed. Offline scoring then computes unvalidated Completion, Strict Success, and Flexible Success from termination, binary presence, and expert target filenames.

**Models and budgets.** Single-turn baselines use GPT o3-mini and Claude 3.7 Sonnet. OSS-Build-Agent is evaluated with GPT-4o, GPT o3-mini, Claude 3.7 Sonnet, Gemini 2.5 Flash, Qwen3 235B, and Qwen3 Coder 485B; CompileAgent uses GPT-4o. Exact API snapshot IDs, temperature, seeds, token/cost limits, wall-clock timeout, and numerical turn cap are unknown. Most configurations use one dataset-wide run. GPT-4o with retrieval is repeated three times and reported through both mean/standard deviation and pass@1–pass@3. OSS-Build-Agent averages 6.6 error-resolution attempts; CompileAgent's reported 7.5 steps use a different, one-command-at-a-time action unit.

**Outputs and release.** The current pinned test revision exposes 385 metadata rows, 385 repository-level labels (148 `Yes`, 237 `No`), and 130 retrieval-label objects. Test labels include `commit_hash` for all 385 rows. The pinned validation revision exposes 70 rows (65 `Yes`, 5 `No`) but no repository commit hash. Neither release contains full command histories, stdout/stderr logs, state snapshots, patches, binaries, per-run terminal reports, or trajectory values. There are no step-level correctness labels or state-action rewards.

**Use and reproducibility boundary.** The paper reports evaluation and failure analysis only; it does not report SFT, preference optimization, reward-model training, process supervision, RLVR, or agent policy training. Reproduction must pin the arXiv version, both Hugging Face revisions, each source commit, container image/Dockerfile, dependency and package-index snapshots, submodules, documentation snapshots, network and cache policy, timeout and `K`, model snapshots, seeds, command logs, patches, binaries, and evaluator version. No public paper-linked OSS-Build-Agent repository was verified, so `artifacts.code` correctly remains `null`. Fork removal and date/star filters are selection controls, not a model-corpus or benchmark-overlap decontamination procedure.
