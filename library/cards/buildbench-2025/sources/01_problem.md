BuildBench asks whether an LLM agent can compile real C/C++ repositories when success depends on interacting with a changing software environment rather than emitting a static answer. The primary paper record is arXiv:2509.25248v1, submitted on 2025-09-27. The official NeurIPS page identifies it as a poster at the NeurIPS 2025 Deep Learning for Code in the Agentic Era (DL4C) workshop and links OpenReview note `ZqFdnJLXHP`; it is not a NeurIPS main-conference paper.

The evaluation task is a pinned GitHub repository plus README and root-file-list context, an Ubuntu 22.04 container, optional repository/web documentation, and expert labels for whether the repository is compilable and which executable filenames should be produced. During an evaluated episode, the agent emits Bash command batches, observes execution results and compilation errors, may install dependencies or patch source, and iterates until an undisclosed online success function fires or an undisclosed maximum turn count is reached. The episode is scored by completion and target-binary filename predicates.

This task/environment/terminal-outcome structure places the work in `environment_agent_trajectory_data`. The neighboring object it does **not** provide is a public trajectory-training corpus: the current test release has 385 repository-metadata rows and 385 manual-label rows—148 compilable and 237 non-compilable—plus 130 documentation-retrieval label records; the validation release has 70 rows. The field called “Build Trajectory” is a chain of documentation URLs, not a command-observation rollout. Complete commands, observations, patches, binaries, retry histories, and per-run verdicts are not released.

The paper evaluates agents on the 148 human-verified compilable repositories and uses a separately selected 70-repository validation set for method development. The retained 237 negative candidate labels make construction failures partially auditable, but they do not substitute for failed agent episodes. The paper and pinned data revisions support a detailed account of the benchmark object, construction process, environment, terminal predicates, results, and release drift. Canonical metadata nevertheless remains `L3_summary_ready`; this Card does not upgrade the accepted curation level while the public scaffold, executable evaluator, environment locks, rollout logs, rights manifest, security policy, and paper-to-release changelog remain missing.
