The main paper result is reported on the 148 human-verified compilable test repositories. OSS-Build-Agent with LLM-assisted retrieval and Claude 3.7 Sonnet reaches 85.2% unvalidated Completion, 66.4% Strict Success, and 71.8% Flexible Success (Table 1). The same-model Claude 3.7 Sonnet single-turn baseline reaches 21.5% strict and 22.1% flexible, a 49.7 percentage-point strict difference. This supports the claim that the evaluated retrieval-plus-iterative-execution scaffold outperforms the paper's single-turn baseline under BuildBench's filename metrics; it does not show that released records are suitable training data.

Repeated GPT-4o retrieval runs expose instability rather than a single deterministic score. Across three runs, strict success is 53.0% ± 6.8 and flexible success is 57.6% ± 6.5; pass@3 rises to 65.5% strict and 70.3% flexible (Table 2 and Figure 4). These results show that multi-turn retrieval and execution paths vary materially. They also make run IDs, seeds, documentation snapshots, model snapshots, cache state, and full trajectories necessary for replay, yet those artifacts are not released.

On the 130 test repositories with URL-level retrieval labels, the GPT-4o OSS-Build-Agent retriever accesses the ground-truth documentation URL for 73.8%, versus 46.2% for CompileAgent (Section 6.2). This is a navigation predicate over labeled URLs, not proof that the retrieved content is correct, stable, sufficient, or license-compatible. The reported 6.6 OSS-Build-Agent error-resolution attempts and 7.5 CompileAgent steps should not be treated as identical efficiency units because the latter operates one command at a time.

The failure analysis provides a negative result: in the inspected o3-mini plus retrieval condition, 69 repositories have errors the agent recognizes but does not fix before termination (Section 6.3 and Figure 5). Appendix examples include using CMake from the wrong directory and failing to address a root-cause submodule ownership error before a downstream `make install` failure. These cases support brittleness in diagnosis and recovery, but complete per-run logs are unavailable for independent recoding.

The current official data artifacts add release evidence beyond the paper: 385 candidate labels retain 148 positives and 237 negatives, the test labels now pin all 385 source commits, the validation release contains 70 rows, and the retrieval JSON contains 130 records. However, only 126 of the 237 negative test rows have a non-empty failure reason, and none of these repository labels is a failed agent rollout. All performance values above are author-reported and have not been independently reproduced in this Card. Benchmark performance is evidence about systems under this benchmark contract, not evidence that the data release is complete, uncontaminated, secure, or high quality for training.
