BuildBench 研究的问题是：当成功依赖与不断变化的软件环境交互，而不是输出静态答案时，LLM agent 能否编译真实 C/C++ repository。论文主要记录为 2025 年 9 月 27 日提交的 arXiv:2509.25248v1。NeurIPS 官方页面将其标为 NeurIPS 2025 Deep Learning for Code in the Agentic Era (DL4C) workshop poster，并链接 OpenReview note `ZqFdnJLXHP`；它不是 NeurIPS main-conference paper。

evaluation task 由固定的 GitHub repository、README 与根目录文件列表上下文、Ubuntu 22.04 container、可选的 repository/web documentation，以及人工给出的 compilability 与目标 executable filename 标签组成。在评测 episode 中，agent 生成 Bash command batch，观察 execution result 与 compilation error，可以安装 dependency 或修改 source，并持续迭代，直到未披露的 online success function 触发或达到未披露的最大 turn 数。episode 最后由 completion 与 target-binary filename predicate 评分。

这种 task/environment/terminal-outcome 结构使论文归入 `environment_agent_trajectory_data`。但它**没有**提供相邻的数据对象——公开 trajectory-training corpus。当前 test release 包含 385 条 repository metadata 和 385 条 manual label，其中 148 条可编译、237 条不可编译，另有 130 条 documentation-retrieval label；validation release 有 70 条记录。名为“Build Trajectory”的字段是一条 documentation URL chain，而非 command-observation rollout。完整 command、observation、patch、binary、retry history 与逐 run verdict 都未发布。

论文只在 148 个经过人工确认可编译的 repository 上评测 agent，并使用另行选取的 70-repository validation set 开发方法。保留的 237 个 negative candidate label 让部分构造失败可审计，但不能替代 failed agent episode。论文与两个固定 data revision 足以支持对 benchmark object、construction process、environment、terminal predicate、result 与 release drift 的深入说明；canonical metadata 仍保持 `L3_summary_ready`。在 public scaffold、executable evaluator、environment lock、rollout log、rights manifest、security policy 与 paper-to-release changelog 缺失时，本 Card 不升级 accepted curation level。
