- **Verifier false positives and false negatives.** Unvalidated Completion can count intermediate binaries left by a failed build or a successfully built submodule/vendored package. Strict/Flexible Success improves target awareness but matches filenames, not function, runtime behavior, semantic fidelity, provenance, or security. A stale or incorrect artifact with an expected name can be a false positive; a correct executable with a different name can be a false negative. The online `Success(f_k)` implementation and numeric `K` are unknown.
- **Source mutation changes the object being judged.** The scaffold permits source edits, and the paper demonstrates an OpenCV API patch. No allowed-change policy, patch diff requirement, semantic-equivalence test, or separation between “build original source” and “repair then build” is disclosed. A successful filename predicate may therefore describe a modified program whose intended behavior was never checked.
- **Environment and replay are under-specified.** “Fresh Ubuntu 22.04 container” does not pin a Dockerfile/image digest, preinstalled packages, compiler and dependency versions, package-index snapshot, submodule policy, network allowlist, retrieved-page snapshot, cache state, wall-clock timeout, numeric `K`, model/API snapshot, seeds, or replay command. Live web pages and mutable dependency services can change both observations and outcomes. No public paper-linked OSS-Build-Agent or evaluator implementation was verified.
- **The release is not a rollout corpus.** The current test data preserve 148 positive and 237 negative repository labels, but only 126 negatives contain a failure reason. Complete successful and failed command-observation trajectories, stdout/stderr, patches, artifacts, retry histories, and per-run terminal outcomes are absent. The 130-record retrieval file and “Build Trajectory” column contain URL chains, not shell commands or environment observations.
- **Paper-time to current schema drift is not mapped.** The paper-time test label commit `d0a2dfa8a309897f7bb299eb4fff067a58442d06` had six fields and no source commits. Current test revision `3c3fcb66ddd525219857a40c91d94a8b32c59e14` adds failure metadata, `commit_hash`, and `retrieval_labels.json`; no paper-linked tag or changelog explains the migration. Validation revision `971b6834230b5cbc4695d42bddc5ff51cf1267c8` still lacks source commit hashes.
- **Overlap and contamination remain open.** Fork removal does not detect copied, vendored, renamed, or code-clone overlap. No instance-level deduplication against CompileAgentBench or other repository-agent benchmarks is reported, and there is no audit of whether evaluated model pretraining contained repositories, READMEs, documentation, fixes, or target names. The 2024 source cutoff and star/keyword filters are not decontamination evidence.
- **Licensing is layered and incomplete.** Both Hugging Face dataset cards declare CC BY 4.0, but this does not supersede rights in linked repositories, dependencies, documentation, generated patches, or binaries. At the pinned revisions, 92 of 385 test license cells are blank, 60 are `NOASSERTION`, and 18 of 70 validation licenses are `NOASSERTION`. No end-to-end attribution/rights manifest is released.
- **Execution has a serious security boundary.** The disclosed agent runs untrusted repositories and build scripts as root, installs packages, follows external URLs, and may edit source. The paper reports no threat model, egress restriction, sandbox-hardening profile, secret policy, supply-chain isolation, or artifact malware scan. Reuse in a privileged or networked host would be unsafe; this is a curator inference from the disclosed execution surface.
- **Scope and use are limited.** The benchmark covers sampled GitHub C/C++ repositories meeting the filters and evaluates compilation under filename predicates. It does not establish general software-engineering capability, runtime correctness, portability, maintainability, or security. Benchmark gains are not evidence of data quality or training utility, and the paper supports `evaluation` and `audit` only.
