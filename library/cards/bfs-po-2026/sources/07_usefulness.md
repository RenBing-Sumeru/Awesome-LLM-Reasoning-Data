For the Rollout, Search, and Test-Time Trace Data track, BFS-PO supplies a concrete schema for training-time search traces. A reusable record would need the question and ground truth, policy/checkpoint version, every complete path, token log-probabilities or entropies, the selected shortest-correct path, each backtracking token, all new branches, parser output, terminal correctness, length penalty, internal node rewards, branch advantages, stopping reason, and optimizer update; rejected and failed branches must remain distinguishable from selected paths. Such records would let curators compare whether gains come from search budget, verifier behavior, the length signal, or the optimizer rather than treating final accuracy as a data label. The paper can guide RLVR implementation and audit design, but it cannot currently serve as a reusable rollout release because those records and the code are unavailable.
