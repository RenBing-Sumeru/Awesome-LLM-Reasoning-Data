For the Data Construction and Open Release Recipes track, SWE-Factory is a concrete blueprint for issue/PR sourcing, binary-resource repair, four-role environment generation, execution-feedback refinement, gold-patch validation, trajectory collection, and full-parameter agent SFT. A useful replication can ablate binary recovery, role separation, execution feedback, memory retrieval, and exit-code semantics while holding the same task pool and budget fixed.

The release also supplies an audit case study. Curators can compare the 671 task rows, 2,809 messages-only trajectories, and 430 Gym environments to test whether a release preserves object identity across construction stages. A stronger implementation should keep task and rollout IDs, Dockerfile and evaluation-script revisions, image digests, verifier logs, outcome labels, rejection reasons, human corrections, training subsets, and checkpoint/prediction bindings in one signed manifest.

Verifier designers can retain the standardized marker while separating assertion failures from infrastructure errors and timeouts. Human audits should publish record IDs, independent annotations, agreement and adjudication, corrected parser outcomes, and false-positive/false-negative analysis. Container builders should add digest-pinned images, dependency locks, SBOMs, resource hashes, and network/secret controls for untrusted repository execution.

Reuse class is **recipe and audit reference now; training or evaluation reuse is blocked pending verification**. The code, 671 tasks, 2,809 trajectories, 430 Gym rows, and checkpoints are useful starting artifacts, but users must independently resolve upstream rights, checkpoint licenses, source contamination, row lineage, trajectory success, and environment immutability. The accepted training-use boundary is SFT, agent training, and evaluation; no preference, process-reward, or RL claim should be inferred.
