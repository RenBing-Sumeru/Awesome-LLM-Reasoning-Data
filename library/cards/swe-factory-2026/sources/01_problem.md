The FSE 2026 Research Papers record accepts this work as **SWE Data Construction, Automatically!** Its system name is SWE-Factory. The accepted title and author list should control the Card; the older arXiv/repository citation title, **SWE-Factory: Your Automated Factory for Issue Resolution Training Data and Evaluation Benchmarks**, belongs to an earlier identity surface that used Yingtian Zou where the accepted version lists Haoyu Song. Headline results also changed across versions: the accepted record reports 337 valid environments from 671 issues with GPT-4.1 mini at $0.047 per instance. No final ACM DOI or proceedings BibTeX is verified.

GitHub issue-resolution datasets are not reusable from issue text and merged code alone. An executable task also needs a base commit, complete test resources, dependencies, a Docker environment, an evaluation script, and a terminal predicate that says whether the original repository state fails and the gold patch passes. Existing collection pipelines can omit binary test-file content, require manual environment engineering, and need project-specific log parsers.

SWE-Factory is in the Data Construction and Open Release Recipes track because it connects the full construction chain: issue/pull-request pairing, binary test-resource repair, multi-agent environment generation, execution-grounded refinement, programmatic fail-to-pass validation, trajectory collection, SFT, and artifact release. It is not evidence for preference learning or online RL, and benchmark improvement does not by itself certify the released data.

The release exposes three non-equivalent data objects. The pinned repository contains 671 raw SweSetupBench rows with repository, pull request, base commit, issue text, gold patch, and test patch. The primary Hugging Face release contains 2,809 Kimi-K2 interaction rows whose public schema is only `messages`. The later SWE-Factory-Gym release contains 430 task/environment rows with repository fields, patches, Dockerfile, and evaluation scripts. Their missing cross-release mapping is a central L4 audit boundary.
