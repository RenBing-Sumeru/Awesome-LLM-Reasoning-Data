The paper's benchmark pool begins with 2,441 GitHub issues from 12 repositories in Python, Java, JavaScript, and TypeScript, limited to issues created before 2025-03-01. Each issue is paired with a merged pull request; pairs without test changes are discarded. Within each repository/version stratum, 20% is sampled with a minimum of one, producing 671 SweSetupBench tasks. Collection repairs binary resources that GitHub diffs omit by generating direct-download commands and removing incomplete binary hunks before evaluation.

For each task, SWE-Builder runs Repository Explorer, Environment Manager, Test Manager, and Test Analyst. The first three gather context and propose a Dockerfile/evaluation script; Test Analyst uses `build_image`, `start_container`, and `run_eval` to supply execution feedback. A successful pair is stored for same-repository/version retrieval. Accepted-paper experiments use GPT-4.1-mini-2025-04-14, Kimi-K2, or DeepSeek-V3-0324 at temperature 0.1, up to five Builder iterations, ten context-retrieval rounds, and 20 parallel subprocesses.

Filtering is gold-patch fail-to-pass. The evaluation script must save the test exit status and emit the standardized marker. The original state plus test patch must be nonzero; after applying the gold patch it must be zero. No learned reward model is involved. Three experienced researchers inspect logs to evaluate the parser, but their record-level annotations, disagreements, adjudication, and corrections are not released.

For training, GPT-4.1 mini constructs 2,877 Python environments from ten repositories stated to be distinct from SWE-bench; tool installation succeeds for 2,809. Kimi-K2 samples one trajectory per prepared task at temperature 0.2 with at most 40 interactions using DeepSWE's Execute Bash, Search, File Editor, and Finish/Submit tools. The public 2,809-row train split serializes these episodes only as interleaved `messages`; it does not expose task ID, Dockerfile, evaluation script, verifier outcome, reward, or success.

Five models—Qwen2.5-Coder-Instruct 3B/7B/14B, Llama-3.1-8B-Instruct, and non-thinking Qwen3-8B-Instruct—receive full-parameter SFT with MS-Swift. The paper states eight A800 GPUs, three training iterations, maximum length 65,536, bf16, learning rate 1e-5, warmup 0.05, FlashAttention, packing, YaRN, and model-dependent sequence parallelism. Evaluation uses vLLM on one A100 with temperature 0 and up to 40 agent iterations on SWE-bench Verified and Lite.

Reproduction must pin the accepted-paper PDF, repository commit, Hugging Face revisions, prompts, Builder model and budget, task membership, Dockerfiles, base-image digests, package locks, evaluation scripts, and trajectory/checkpoint mapping. The linked `Appendix.pdf` is absent, the repository has no paper-run tag, and current README/run examples use different temperature and parallelism values.
