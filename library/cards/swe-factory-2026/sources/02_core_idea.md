SWE-Factory automates the path from a real issue and merged pull request to an executable coding-agent task: recover omitted binary test resources, have four agents construct and debug the environment, and accept the task only when a gold-patch fail-to-pass check succeeds.

The four SWE-Builder roles separate responsibilities. Repository Explorer retrieves setup and testing context. Environment Manager writes the Dockerfile. Test Manager writes the evaluation script. Test Analyst builds the image, starts the container, runs evaluation, and returns execution evidence for refinement. Successful Dockerfile/script pairs enter a memory pool; a later task retrieves the closest earlier version from the same repository. The memory stores recipes, not immutable built images.

The feedback contract is environmental and programmatic. An evaluation script applies the test patch, captures the test command status, and emits `OMNIGRIL_EXIT_CODE`. A task is valid only when the relevant tests return nonzero before the gold patch and zero after it; missing markers are errors. This observes execution status but not the semantics of the failure: a crash, dependency error, timeout, or assertion failure can all be nonzero. Gold-patch validation is also label-aware, so incorrect issue/PR linkage, tests, or gold patches can propagate into acceptance.

Relative to SWE-bench-style manual environment construction and SWE-Gym's semi-manual repository setup, the concrete change is automated environment-recipe production plus a standardized exit-code parser. Binary-resource recovery, multi-agent role decomposition, execution feedback, and same-repository/version memory are integrated into the construction loop. Unit tests, Docker, gold patches, and SFT are established components; the contribution is their automation and packaging into a reproducible-looking but still partially released lifecycle.
