For the Data Construction and Open Release Recipes track, SPIRAL is a concrete blueprint for replacing a fixed prompt corpus with an environment-generated online curriculum. A reproduction can reuse the shared-policy two-role loop, per-game/per-role EMA baseline, vectorized actor collection, terminal rule feedback, and periodic game-state dumps. It is particularly useful as an ablation baseline for static demonstrations versus online RL, fixed versus co-evolving opponents, global versus role-conditioned baselines, and single-game versus multi-game curricula.

An auditable implementation should persist game and dependency versions, initial state and seed, role prompt, every observation and complete response, parsed action, action-validity flag, transition, termination reason, terminal return, baseline, advantage, policy checkpoint, and update configuration. It should also retain failed, invalid, zero-advantage, and truncated episodes; run multiple seeds; evaluate parser/environment exploitation; and test reasoning faithfulness separately from win rate and benchmark accuracy.

Reuse class is split by artifact. The code is suitable as a recipe reproduction starting point after pinning commit and dependencies. The paper's reported online stream is reading/audit reference only because it is not frozen. The static Qwen3-32B SFT comparison dataset is blocked for training reuse until its Dataset Viewer schema, split, lineage, and license are independently confirmed. The released models are evaluation or initialization candidates only after their own model cards and licenses are checked.
