Inputs are a base model, a set of two-player TextArena games, role/game prompts, environment transition and action-parsing code, and an initial-state sampler. SPIRAL samples a game and state, assigns the active role, obtains a structured observation, and asks the shared policy for a complete response containing reasoning and an action. The parser extracts the action; the environment advances the state; turns alternate until normal termination, an invalid action, or the implementation's maximum-turn truncation. The collected object is a policy-dependent sequence of observations, responses, parsed actions, transitions, role returns, and game identity. (Paper §3 and Algorithm 1; official repository `train_spiral.py`.)

For normal game termination, the paper defines sparse returns `R0 ∈ {-1,0,1}` and `R1 = -R0`. RAE updates a separate baseline for each game/role with EMA decay 0.95 and applies the resulting scalar advantage to all complete responses from that role; response-length normalization is disabled. The current repository adds two implementation branches that matter for audit: an invalid action immediately terminates with -1.5 for the actor and 0.5 for the other player, while maximum-turn truncation produces 0/0. Zero-advantage trajectories are filtered by default. These code paths should not be silently equated with the paper's normal zero-sum outcome equation.

The main paper reports 400 policy-iteration steps with 128 samples per step on 8 H100 GPUs. Appendix D Table 6 fixes AdamW, learning rate 1e-6, batch size 128, discount 1.0, EMA decay 0.95, two proximal update epochs, policy clipping 0.2, gradient clipping 1.0, weight decay 0, temperature 1.0, top-p 1.0, top-k -1, and zero KL coefficients. It reports an 8,192-token maximum response. The checked `run.sh` at commit `068b06f6afce2e45ae3eb5d8bf677e9d69c83642` is a Kuhn Poker Qwen3-4B-Base example with 4,096 generated tokens, 32,768 context length, and `max_train=51200`; this is a released example, not proof that it exactly reproduces every paper run.

Training consumes the live environment stream through on-policy policy-gradient updates. Evaluation is zero-shot except for base-model few-shot prompts following the Qwen3 report, uses temperature 0.6/top-p 0.95, and covers eight academic benchmarks plus held-out games. The paper states that no benchmark-related problems or mathematics data enter SPIRAL training, but supplies no item-level overlap report. Reproduction should pin the repository commit, Oat/vLLM/TextArena versions, model revision, game IDs, prompt templates, parser, seeds, rollout batches, checkpoints, and reward branches, and should archive the generated game-state JSON/pickle files.

The separate SFT baseline is built from approximately 25,000 winning trajectories generated by Qwen3-32B self-play. Its official Hugging Face URL is verified, but it is not the online SPIRAL stream. During this curation pass the Dataset Viewer endpoint was unavailable, so its exact row count, schema, splits, and license remain unverified.
