The prior-work baseline is not “reasoning from games” in general. The paper situates SPIRAL against offline single-game language self-play, LoRA-based multi-agent adaptation, fixed opponents, single-agent multi-turn RL, and single-turn self-generated reasoning tasks. Established components include zero-sum self-play, Monte Carlo policy gradients, TextArena environments, vLLM inference, Oat's actor-learner architecture, and terminal game rewards. (Paper §2–§3.)

The concrete change is the data-generating interface: one shared full-parameter policy plays both roles across multiple multi-turn games, trajectories are consumed online, and the next batch is generated against the updated policy. RAE makes this interface trainable by centering returns for each game/role instead of treating structural role advantage as learning signal. Thus the data distribution, opponent, and learner co-evolve; there is no final fixed prompt pool that explains the recipe.

The direction signal is the conversion of a replayable environment into a post-training source of tasks, traces, and rule-grounded feedback. Evidence for that mechanism includes fixed-opponent comparisons, the RAE collapse ablation, multi-game versus single-game results, higher-complexity game transfer, and three-seed reporting. Conference acceptance and benchmark gains are not themselves quality guarantees, and GPT-4.1 pattern labels remain interpretation rather than a verifier.

What is not new is self-play, terminal reward, REINFORCE, or multi-agent games. The open contribution is also a recipe rather than a complete data release: code and a static SFT comparison set are public, but the policy-dependent online streams are not frozen. Before reuse, inspect parser and invalid-action behavior, environment versions, baseline initialization, truncation, zero-advantage filtering, run seeds, code-license notices, and whether archived rollouts preserve failures as well as wins.
