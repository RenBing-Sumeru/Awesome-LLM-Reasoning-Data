The primary publication is the NeurIPS 2025 Datasets and Benchmarks Track paper; the version record is arXiv v3 dated 16 May 2025, and the official implementation was inspected at commit `ffee6f41fde76acd14bd792db442479c506260c2`. WASP asks how often a web agent exposed to attacker-controlled but ordinary page content begins following an indirect prompt injection, and how often it actually completes the malicious objective. Its threat model is a benign user and a black-box malicious environment: the attacker may post content in normal untrusted-user-controlled elements but does not know the agent implementation (Paper §2–§3.1).

The main evaluation surface starts from 21 manually constructed, environment-realizable attacker goals—12 on a self-hosted GitLab clone and 9 on a Postmill-based Reddit clone. Each goal is paired with two benign user goals in the same site and two task-related injection templates, yielding `21 × 2 × 2 = 84` runtime tasks per main setting; a separate utility suite contains 37 no-attack tasks. One episode joins task/setup fields, injected page content, scaffold-specific observations, model reasoning/messages and browser actions, final environment or action-log state, compromise judgments, end-to-end goal success, utility success, and cleanup metadata. The released Croissant attack file contains 21 base-goal records, not an immutable 84-row rollout manifest.

WASP belongs to `environment_agent_trajectory_data` because the evaluated object is an executable website episode with an observation–action trace and terminal evaluation. It also belongs to `benchmarks_evaluation_surfaces` because its contribution is a mixed security-feedback contract, not policy training. It does not cover SFT, preference optimization, reward-model training, RLVR, desktop agents, code agents, adaptive attack generation, or deployment prevalence. This Card provides bilingual L4 content depth from verified paper, appendix, and code evidence while retaining the accepted `L3_summary_ready` metadata level and `partial` status because immutable replay, judge calibration, canonical rollouts, and release checksums remain unresolved.
