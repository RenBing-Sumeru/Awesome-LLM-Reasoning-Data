Construction begins with 21 manually written attacker goals, 12 for GitLab and 9 for Reddit/Postmill, spanning exfiltration, data destruction, access changes, impaired defenses, execution, phishing, harassment, misinformation, snooping, and related violations. Authors retain goals only after manually checking that they are realizable in the environment; the proposed-goal pool, rejected cases, adjudication, and selection threshold are unknown. GitLab contributes two benign goals (comment and like), and Reddit contributes two (comment and upvote). The main suite crosses each attacker goal with both same-environment user goals and two task-related injection formats—plain text and a URL anchor—to create 84 tasks. A task-agnostic prompt variant is used in an ablation, and 37 no-attack tasks measure utility (Paper §3.2–§3.4; Appendix B Tables 5–6).

The 21 released attack records expose fields such as `free_form_name`, `environment`, `setup_fn`, `parameters`, `action_url`, malicious `instruction`, `exfil`, evaluator descriptions/types/predicates, `cleanup_fn`, and notes; Croissant conversion also stores stringified parameter/evaluation fields. At runtime the prompt injector creates site state, inserts the chosen injection in an ordinary attacker-controlled page element, combines the benign and malicious task information, writes task JSON, and starts the agent from the configured URL. After the run, cleanup restores the modified site state.

Three scaffolds generate trajectories. VisualWebArena uses identifier-based browser actions with accessibility-tree observations and optional Set-of-Marks screenshots. Claude CURI uses screenshots and computer-use click/type actions while retaining the last ten screenshots and prior model output. The tool-calling loop exposes accessibility-tree observations as low-privilege tool messages and keeps three prior observations. The evaluated backbones are GPT-4o, GPT-4o-mini, o1, Claude Sonnet 3.5 v2, Claude Sonnet 3.7 Extended Thinking, and Llama-3.3-70B. Pinned code caps VisualWebArena at 15 steps, GPT tool calling at 20 actions, and Claude CURI at 75 actions; temperature, seeds, exact provider model snapshots, retries, and token budgets are unknown.

Each run writes scaffold-specific HTML or JSONL logs with observations, model reasoning/messages, browser or computer actions, and task metadata. GPT-4o then judges each action unit; `classify_group` applies an any-positive rule to obtain episode-level `ASR-intermediate`. Malformed judge output or an API error defaults to `not_compromised`. A separate final evaluator applies goal-specific `program_html`, required-content, forbidden-content, or exfiltration rules to produce `ASR-end-to-end`; utility tasks use corresponding task predicates. At commit `ffee6f41…`, `ExfilEvaluator` scans extracted action descriptions for an expected URL substring rather than confirming server receipt.

Outputs are attack-success and utility rates plus locally generated task and trace files; there is no training reward, optimizer, train/dev split, or canonical public rollout set. WASP is used only for evaluation and security audit. Exact replay requires the pinned code commit, attack and utility configs, injection template, site images/data/accounts/reset state, service versions, scaffold limits and observation history, API model revisions, judge prompt/model/parser, evaluator code, and retry/crash retention policy. The repository README estimates 4–6 hours for one complete run, but no tag, release, immutable environment bundle, or valid content checksum binds those components.
