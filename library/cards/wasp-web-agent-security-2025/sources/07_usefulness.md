For the assigned `environment_agent_trajectory_data` track, WASP is useful as an evaluation and audit reference because it binds a task/config record to a live web environment, an observation–action episode, and two non-equivalent feedback layers. A controlled study can distinguish refusal, intermediate hijacking, malicious partial progress, completed harm, benign-task failure, and disagreement between judge and environment predicates.

As a benchmark recipe, reconstruct the 84-task cross-product rather than treating the 21 Croissant attack rows as the full suite. Report `ASR-intermediate`, `ASR-end-to-end`, and utility together; stratify by site, goal category, injection format, scaffold, and action cap; and pin API model versions. Low terminal ASR without intermediate and utility results cannot separate robustness from agent incapability.

As a verifier-audit case, rescore the same trajectories with the fixed GPT-4o prompt/parser and alternative judges, then inspect action-level disagreements before any-positive aggregation. Separately test each DOM/log predicate against controlled positive, negative, stale-state, and partial-execution cases. The exfiltration rule should be compared with a receipt-based evaluator that verifies destination, secret completeness, and value validity.

As a release-audit case, bind every instantiated task and locally generated rollout to the base goal, benign goal, injection template, site snapshot, setup/cleanup result, model/scaffold settings, judge output, terminal-evaluator output, retry status, and checksum. Replace Croissant's `sha256: main` with content digests and record the archived commit, mixed licenses, and scraped-content provenance.

Reuse is safe for evaluation and audit only. The paper trains no models, the release has no canonical rollout corpus, and the accepted metadata does not support SFT, distillation, preference learning, reward modeling, RLVR, agent-policy training, or safety-alignment training.
