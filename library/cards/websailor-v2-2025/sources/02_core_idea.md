WebSailor-V2's central move is to couple topology-aware synthetic task generation with a simulator-to-live-web post-training loop. V2 expands a seed-centered graph with deliberately dense and cyclic links, samples connected subgraphs by random walk, checks structural non-isomorphism with Weisfeiler-Leman, and distributes question focus across orbit-node roles. The final paper names semantic ambiguity, plausible distractor noise, and structural constraints over bridges or cut vertices as uncertainty mechanisms (Paper §§3.1–3.4).

The resulting object is not merely a QA row. An SFT example is a successful ReAct solution containing repeated thought, action, and observation turns plus a final answer. An RL example is a current-policy episode in the same interaction format, sampled either against offline Wikipedia tools or a managed live tool service. Search, Visit, Google Scholar, Python interpreter, and Final Answer define the action surface (Paper §2; Appendix B).

The feedback contract is the largest unresolved boundary. The tailored GRPO objective uses one episode reward `R_i` and a leave-one-out group-relative advantage, but the paper never defines how `R_i` is computed. It does not name a rule, judge, answer-equivalence test, or calibration protocol. Benchmark accuracy uses LLM judges, but that does not prove the training reward uses the same mechanism. The Card therefore records `verification_contract: unknown` and does not broaden training use to RLVR.

Relative to WebSailor-V1, V2 changes graph density and sampling, broadens uncertainty types, switches from a 72B dense model to a 30B-A3B MoE, expands context from 32k to 128k and ReAct iterations to 100, and adds the offline/live dual environment. V1's public 20-row QA sample, inference code, and WebSailor checkpoints remain V1 artifacts; they cannot fill V2's release gaps.
