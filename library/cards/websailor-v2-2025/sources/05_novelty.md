The closest prior work is WebSailor-V1 rather than generic chain-of-thought distillation. V1 already uses web-derived graph tasks, ReAct trajectories, rejection-style cold start, and agentic RL. V2's data-side change is denser cyclic graph construction, random-walk extraction in place of attempted exhaustive enumeration, orbit-aware QA focus, and uncertainty definitions beyond obfuscation. The final paper makes those changes concrete with semantic ambiguity, distractor noise, structural constraints, and 30K-plus instruction pairs (§§3.1–3.4).

The environment-side change is the dual simulator/live architecture. Offline Wikipedia enables fast and controllable algorithm tests; the managed live layer tries to suppress real API variance through caching, retries, QPS limits, degradation, and backups. This is an engineering integration, not a released general-purpose environment, because code, snapshots, caches, and replay fixtures are absent (§4.2).

The optimizer is a tailored GRPO rather than a wholly new learning principle. Strict on-policy sampling, token-level gradients, leave-one-out advantages, selective negative exclusion, and large batches/groups are assembled for expensive agent episodes. The paper explicitly argues that data and environment stability matter more than fine algorithm differences. Because `R_i` is undefined and group size is unknown, the optimizer contribution cannot be fully reconstructed.

For reasoning-data research, the directional novelty is the coupling of graph topology, uncertainty type, trajectory selection, and environment stability. Reuse should test which gain comes from V2 task structure, SFT trace quality, expanded context, the base-model change, or RL—and should never attribute V1 public artifacts to V2 without explicit lineage.
