The pipeline begins with roughly 15,000 mathematics problems, primarily from GSM8K and MATH. OmegaPRM applies divide-and-conquer Monte Carlo tree search with UCB-style state selection and generates about 20 rollouts per problem. The authors augment this pool with MathShepherd and RLHFlow process-reward data, while explicitly excluding PRM800k to reduce evaluation leakage. The resulting noisy pool contains about 1.2 million rollouts with step reasoning and candidate error positions.

DeepSeek-V3 reviews each complete rollout together with the proposed OmegaPRM error assessment. A sample is retained when the judge confirms that assessment and discarded when the two contradict each other; the paper says this removes about half of the noisy pool. Positive and negative steps are then rebalanced, but the target class ratio and sampling rule are not reported.

DeepSeek-R1-Distill-Qwen-32B converts retained material into stepwise targets. Straightforward correct steps receive a short System-1 plus verdict. Errors, and correct steps considered complex enough to need analysis, receive System-2 explanations ending in plus or minus. The paper reports approximately 117,000 curated reasoning traces. The current public Hugging Face dataset instead exposes 156,321 train rows with a single top-level `conversations` field; no manifest reconciles the two counts or exposes source, judge, rejection, and rebalancing fields.

The main student is DeepSeek-R1-Distill-Qwen-14B, trained by ordinary autoregressive cross-entropy. Appendix A.1 reports a 2048-token maximum input, LoRA rank and alpha of 16, dropout 0.1, three epochs, per-device batch size 2, gradient accumulation 8, learning rate 2e-5, weight decay 0.01, FP16, and eight NVIDIA A800-SXM4-80GB GPUs.

At inference, Dyve verifies cumulative prefixes in sequence, allows between one and 8192 output tokens for each response, and halts at the first parsed negative verdict. If every step is positive, it accepts the complete trace. The current repository implementation uses a trailing-symbol heuristic to parse plus and minus signs; because the repository has no tagged release or paper-to-commit manifest, that code should be treated as current artifact behavior rather than a guaranteed reconstruction of the reported run.
