Shepherd 最适合作为有状态智能体监督采集的蓝图。数据构建者可以在同一谱系图中保留类型化意图/结果对、环境修改、提交祖先关系、fork 点、sibling 后缀与终局奖励。该结构支持树式 RL、反事实评测、失败定位、监督智能体训练、轨迹压缩和安全审计，而不必抹平环境状态。

对 RLVR，关键教训是把 verifier 契约与底座分开。Shepherd 提供回滚、分支和分组，任务则提供终局结果奖励。可复用发布因此必须同时给出两者：精确任务/verifier 版本，以及把每个根与 sibling 连接到环境镜像、随机种子、奖励和生成策略/checkpoint 的清单。

对安全研究，意图拦截和可逆 scope 为执行前审批、沙箱隔离与失败后 discard 提供了具体挂钩，但它们并不是完整安全策略。部署仍需要 effect 分类、补偿处理器、secret/PII 控制、访问规则，以及对不可逆外部动作的明确处置。

维护中的框架适合开展新实验，冻结的 `shepherd-experiments` 快照才是论文对应 artifact。复现者应固定后者，不能在缺少论文依赖、任务版本和运行清单的情况下，推断当前 early-alpha API 会自动复现论文结果。
