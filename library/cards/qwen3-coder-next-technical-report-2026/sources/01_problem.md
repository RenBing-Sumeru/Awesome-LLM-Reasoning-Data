Coding-agent reports can describe runnable repositories, unit tests, tool trajectories, and reinforcement learning while leaving readers unable to identify the concrete tasks, source revisions, images, test generators, rejected records, and reward rules that created the claimed supervision. In software engineering, a task is not fully specified by an issue and patch alone: repository state, dependencies, test harness, remote access, and terminal conditions also affect what an agent can learn and how a result can be gamed.

Qwen3-Coder-Next provides substantial but partial information about executable task construction and agentic training. It names GitHub pull requests, open and proprietary sources, synthetic repository changes, Docker environments, and multiple feedback mechanisms, while withholding the training tasks, environments, trajectories, audit logs, and full provenance. This Card records the disclosed data and feedback contracts without treating released weights or inference code as an open training-data recipe.
