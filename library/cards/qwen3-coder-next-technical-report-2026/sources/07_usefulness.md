This report is useful as a checklist for executable software-engineering data: record repository state, patch, test, dependencies, container image, verifier behavior, tool observation, terminal rule, and reward penalties separately. It also makes clear why a task count or a released model does not substitute for task manifests, revision lineage, and test or environment release.

For agentic RL, it illustrates how execution signals, pairwise judgments, completion reward, and formatting constraints can coexist. Researchers evaluating similar pipelines should request environment snapshots, verifier error analysis, train/evaluation separation, residual-overlap audits, rejected-trajectory logs, and explicit defenses against git and network reward shortcuts before treating results as reproducible evidence.
