报告从 pull request 和合成仓库改动构建可执行的软件工程监督。一个任务可包含有缺陷的仓库状态、修复、测试 patch、Docker 环境、验证脚本，以及最终的多轮工具轨迹。这使代码智能体训练从静态答案预测转为与任务专属执行基底交互。

反馈契约是混合的，包括执行脚本、多数共识保留的合成单元测试、Mini-SWE-agent 验证、多维成对 judge、终止完成 reward，以及对未完成 rollout 或无效工具格式的惩罚。报告随后描述了分阶段的中期训练、SFT、领域专家训练、蒸馏、单轮执行 RL 和多轮 agentic RL。

从披露账本看，关键价值在于可见的构建与验证轮廓，以及明确的未发布边界。它不是对底层任务语料、容器镜像、验证日志、reward 实现或完整生产训练日程的发布。
