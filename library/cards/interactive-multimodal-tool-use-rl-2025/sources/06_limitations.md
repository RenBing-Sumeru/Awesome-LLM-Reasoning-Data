- No official paper-specific code, sandbox, task set, rollout corpus, checkpoint, model card, or project page was verified. The experiments say the curated tasks and ground-truth calls “will” be open-sourced, and `paper.tex` leaves commented placeholders such as `Code: To be`; code, data, project, and model links therefore remain null.
- The rule verifier checks successful database-changing calls against ground truth but omits tau-bench's phrasing-sensitive expected-output check. A trajectory can satisfy the write predicate while giving an incomplete, misleading, or otherwise poor conversational response (paper §2.1; appendix output-check tables).
- GPT-4.1 adjudication has no disclosed model snapshot, temperature, calibration, inter-judge agreement, or cost. Allowing only one `-1` per trajectory can under-penalize multiple major deviations, while later errors may receive only `0` (Appendix “LLM Judge Setup for Turn-Level Evaluation”).
- Stable GRPO/PPO consumes an aggregate trajectory scalar rather than a truly local process reward. Direct turn-final-token assignment was unstable, so the reported method does not show that each judged turn receives reliable local credit (paper §3.2; §5.1).
- Training is retail-only, tau-bench covers only two domains, and airline generalization is weak. Exact split manifests, APIGen-MT/tau-bench overlap checks, task deduplication, decontamination, successful/failed rollout retention, database hashes, hardware, compute hours, seeds, variance, and checkpoint selection are unknown.
- Speech evaluation changes the task by removing authentication and directly providing the user profile because TTS makes `name_number` identifiers error-prone. Its scores are therefore not directly comparable to an otherwise identical text protocol (paper §4.3–§4.4).
