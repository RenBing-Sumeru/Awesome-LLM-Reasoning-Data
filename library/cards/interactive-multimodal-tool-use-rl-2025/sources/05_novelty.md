The closest baseline is long-horizon tool-use RL driven by a sparse environment success signal, including tau-bench-style terminal verification. Existing process-reward work can localize errors, but this paper applies localization to simulated user/tool conversations and anchors the judge with the hidden user instruction and ground-truth call trajectory (paper §2; §3.2).

The concrete change is a two-channel feedback interface: executable database state changes provide a rule terminal result, while GPT-4.1 provides `{-1,0,1}` turn adjudication; a fixed 10×/5×/`1/T` aggregation converts both into the reward used for online agent RL. The paper also carries this interface from Qwen3-8B text training to Qwen2.5-Omni-7B speech-text interaction through SeedTTS and a 30-step GRPO curriculum warm-up (paper §3.2; §4.3).

The useful direction signal is not merely “process supervision”: it is the distinction between where feedback is authored and where optimization consumes it. Turn-level labels exist, but the stable training recipe uses their episode-level sum. This makes reward granularity an explicit ablation axis for trajectory-data research and exposes a failure case for naive token-local reward assignment (paper §5.1).

The upstream pieces are not new: tau-bench seed data, SQLite, REST, MCP, GPT user simulation, SeedTTS, Qwen models, `verl`, `RL-Factory`, GRPO/PPO/RLOO, APIGen-MT, and DeepScaleR are reused or integrated. Scale and benchmark gains alone do not establish a reusable release. Before reuse, verify the promised paper-specific sandbox, exact tasks, task splits, rollout logs, checkpoints, environment snapshots, and licenses.
