SRCA turns an intermediate prefix into an answer probe without permanently altering the continuing chain. On a detected delimiter such as `### Step`, it saves the generation state, appends the fixed cue `So, the answer is `, records the immediate answer, then restores the original position and KV cache. This is Checkpoint Injection; the answer is a model prediction conditional on the prefix, not an external correctness label. (Paper §3.1.)

Answer-Clustered Search (ACS) uses that probe as a diversity key. At each step it samples N paths, asks a PRM for each path score, groups paths whose checkpoint answers are equal, sums scores within each group, and round-robins the best path from high-scoring groups until M beams survive. Checkpoint Candidate Augmentation (CCA) uses the same probe differently: concatenate the prefix, cue, and checkpoint answer into a complete candidate, score it alongside completed natural paths, and return the highest-PRM candidate. (Paper §3.2–§3.3; Algorithm 1.)

The feedback contract is mixed. PRM scores guide path survival and final choice; benchmark answers determine reported accuracy after the run. The PRM does not observe a gold answer during search, and a checkpoint answer is neither a verified proof step nor a generally calibrated reward. The closest comparisons are PRM-guided beam search, DVTS, Best-of-N, and weighted Best-of-N. SRCA changes the grouping key from path/tree structure or final answer frequency to an answer predicted from each intermediate prefix, then lets that prediction enter the final candidate pool.
