Beam search and DVTS already use a PRM to decide which paths to extend; Best-of-N and weighted Best-of-N already use scores to select completed answers. SRCA's specific change is to query an answer from every intermediate prefix, then reuse that answer twice. ACS uses it as a path-clustering key, and CCA uses it as a candidate endpoint. This makes the selected object's provenance more explicit than a final-answer-only selector: a final choice can originate from an incomplete prefix plus a temporary answer completion.

What is not new is equally important. The work does not introduce a new policy, a new PRM, benchmark data, an external verifier, or a training procedure. It reconfigures known autoregressive search ingredients—sampling, beam retention, PRM scoring, and final selection—at test time. Its claimed fault tolerance is conditional: an early checkpoint is useful only if its answer is correct enough and the PRM ranks the reconstructed candidate above later but worse continuations.

For the rollout-search track, the direction signal is the record design: preserve checkpoint probes and their selection lineage instead of retaining only final paths. Before reuse, inspect delimiter coverage, checkpoint-answer normalization, state rollback, PRM version/format/calibration, equality clustering, and whether gold benchmarks overlap the policy or PRM training sources. None of those records are officially released here, so SRCA is a paper-level recipe and audit reference rather than a ready-to-run data artifact.
