**Inputs and checkpoint operation.** A benchmark prompt is rendered with a system template that requests `## Step` formatting for complex questions. The policy detects a delimiter, uses the existing prefix to decode one checkpoint answer after `So, the answer is `, records it, and rolls the state back. Main experiments use Llama-3.2-1B-Instruct; Appendix B.3 additionally tests Qwen3-0.6B. The paper does not disclose code, seeds, parser rules, stop tokens, or a durable serialization of the saved state. (Paper §3.1, §4.1, Appendix A.3.)

**Search and reward.** At the first step sample N paths; at later steps, each of M survivors samples N/M children. For each current path, obtain its checkpoint answer and PRM score. Equal answers form a cluster; cluster score is the sum of member path scores. Sort clusters by that sum, select the highest path in each cluster round-robin until M paths remain, then continue. The main path score is the score at the final reasoning step. DeepSeek's Llama3.1-8B-PRM-Deepseek-Data is used as the probability of `+`; Skywork-o1-Open-PRM-Qwen-2.5-7B contributes its last-token 0–1 value-head score. (Paper §3.2, §4.1, Appendix A.4.)

**Candidate augmentation and budgets.** For every checkpoint, CCA makes `prefix + cue + checkpoint answer`, scores it with the PRM together with completed paths, and returns the highest score. Sampling uses temperature 0.8, top-p 0.9, N in {16, 32, 64, 128}, and M=4 for selector methods. Early stopping halts when a checkpoint score exceeds tau; tau=1 means no early stop. This is a training-free test-time method. Reproducing it requires exact policy/PRM revisions, prompt/normalization rules, PRM formatting, checkpoints, scores, clustering decisions, benchmark IDs, hardware and runtime—not just the paper's hyperparameters.
