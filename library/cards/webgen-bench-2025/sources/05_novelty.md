Prior baselines evaluate code agents mostly through coding problems, repository completion, issue resolution, or feature patches on existing projects. WebGen-Bench changes the object: the agent receives a non-expert website request and must produce a runnable multi-file web application from scratch. It also changes the feedback contract from unit tests or issue-resolution labels to browser-executed user operations plus a separate visual-quality judge.

The direction signal is the combination of open-ended generation with executable behavioral tests. The benchmark captures planning, file organization, UI implementation, dynamic behavior, and visual adherence in one environment. The quality signal comes from human-reviewed test cases, a disclosed UI-agent evaluation path, a human-alignment study for the automatic labels, and released code/data/model artifacts.

What is not new: browser automation, UI agents, prompt-based test generation, supervised fine-tuning, and website builders already existed. The reusable contribution is their assembly into a versioned website-generation evaluation surface with public instructions, tests, outputs, and training data. Before reuse, inspect the license, exact split, test-count discrepancy, raw schema, hidden dependency on external model APIs, framework forks, browser/runtime versions, evaluator prompts, timeout policy, and whether public benchmark examples have leaked into later model training.
