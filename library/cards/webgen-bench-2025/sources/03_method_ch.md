输入包括：作者从自由职业网站开发平台归纳出的项目类型、40 名计算机科学博士生头脑风暴出的功能和外观需求、由模型转换得到的网站生成指令，以及 Bolt.diy、OpenHands、Aider 等智能体生成的网站代码。

流程如下：

1. 作者归纳 20 类 Web 应用，人工创建 10,152 条项目描述，把它们转换成英文网站生成指令，并抽样得到 101 条测试指令，覆盖内容展示、用户交互、数据管理三类技术场景。
2. 对每条测试指令生成测试用例草稿，再由两名博士生独立审阅和修订。论文正文报告最终有 647 个测试用例，每条指令 4 到 11 个。
3. 被测智能体生成网站。官方仓库 README 给出 Bolt.diy、OpenHands、Aider 的复现实验路径，并说明包含生成输出和评测脚本。
4. 每个测试用例被转换成界面智能体的操作提示。浏览器智能体执行操作、观察截图和轨迹，然后输出 YES、NO 或 PARTIAL；达到交互上限时用最终决策提示给出结论。
5. 功能正确率由 YES/PARTIAL/NO 计算，其中 PARTIAL 计半分；外观质量根据截图另行给 1 到 5 分。
6. WebGen-Instruct 的训练指令会对测试集做去污染：5-gram Jaccard 相似度高于 0.6 的样本移除，句向量余弦相似度高于 0.55 的样本移除。论文报告得到 6,667 条训练指令，并从其中 2K 条生成 Bolt.diy 轨迹，经外观过滤保留 600 条用于监督微调。

输出物包括测试指令、测试用例、代码和评测脚本、生成网站输出、模型权重和 WebGen-Instruct 训练数据。复现时必须固定数据版本、仓库提交、浏览器和运行时、智能体框架分叉、界面智能体模型和提示、模型 API 行为、超时策略、依赖版本以及生成网站产物。逐行字段名应以实际数据版本为准。
