Inputs and SFT construction: the paper starts from Qwen2.5-Math-7B and changes `rope_theta` from 10,000 to 1,000,000 for reported 128K context support. It collects math prompts from AceMath, NuminaMath, and OpenMathReasoning and code prompts from TACO, APPS, OpenCoder-Stage2, and OpenCodeReasoning. Prompts are deduplicated; samples with 9-gram overlap to benchmark test items are removed; shorter DeepSeek-R1 responses are treated as a proxy for easier tasks and randomly downsampled. The resulting experimental pool has 247K math and 136K code prompts. DeepSeek-R1 generates the SFT outputs, and seven blends scale from 36K samples in v1 to 2.2M in v7. (Paper §3.1, Figs. 3–5.)

The checked release is not serialized as those seven blends. AceReason-1.1-SFT exposes one train split with `category`, `source`, `input`, and `output`, totaling 2,668,741 math plus 1,301,591 code rows. Its source labels and question counts do not match the paper's final pool one-to-one, and no release field records the v1-v7 membership, correctness check, rejection, or model checkpoint. A reproducer must therefore pin the public release revision and separately obtain the final consumed blend manifest, which is currently unknown.

RL pipeline: each global batch contains 128 prompts. The current policy samples (G=8\) or (16) responses per question, a rule verifier scores them against the ground-truth answer, and group-standardized scores become token-level advantages. veRL executes one policy-gradient update per batch using a token-level GRPO loss; the KL term is removed. Math verification is answer-level. Code verification compiles generated programs and executes predefined tests. Exact parsers, tests, environments, timeouts, reward code, optimizer settings, and stage temperatures are not disclosed. (Paper §3.2.1–3.2.2.)

Curriculum and selection: math-only RL runs at 8K, 16K, and 24K response limits, increasingly favoring difficult tasks and retaining about 2,500 hard questions at the 24K stage. Code RL then runs at 24K and 32K; from Code Stage-II's second epoch onward, tasks for which every previous-checkpoint rollout passes all tests are removed. A final math-only 32K stage likewise retains tasks not solved by every rollout. When an output is truncated, "overlong filtering" masks the entire sample without reward; the alternative assigns a negative reward. The paper finds this choice stage-dependent rather than universally beneficial.

Outputs and use: SFT consumes teacher demonstrations; RLVR consumes question-answer records and transient rollout groups with programmatic outcome reward; the final artifact is AceReason-Nemotron-1.1-7B. Reproduction requires the exact SFT subset, stage prompt manifests, 8-versus-16 allocation, temperatures, answer parser, code tests and runtime, overlong policy, optimizer/hardware/seeds, and checkpoint sequence. The official model page provides weights, inference prompts, and an evaluation-toolkit pointer, not the missing training implementation.
