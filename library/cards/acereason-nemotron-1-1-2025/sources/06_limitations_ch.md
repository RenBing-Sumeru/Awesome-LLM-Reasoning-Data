最大的审计缺口，是论文中的训练统计单位与公开发布之间并不一致。论文描述了一个经筛选的 383K 题目池，以及包含 2.2M 样本（1.2M 数学、1.0M 代码）的最终 v7 SFT 混合；公开 SFT 数据集则包含 3,970,332 条记录，来源题目数为 514,807。当前没有版本化清单把发布记录、重复采样或采样权重映射到 v1–v7，或映射到实际用于初始化 RL 的检查点。

公开 SFT 记录只有 `category`、`source`、`input` 和 `output` 四个字段。数据没有提供正确性判断、拒绝原因、验证器轨迹、生成随机种子、混合版本标识，也没有除单一 `train` split 之外的训练/验证/测试划分。论文说明回答经过筛选，并对较简单或较短样本做了下采样，但没有提供足够的逐行来源信息来重建这些决策。把较长教师回答当作高难问题的代理，是作者采用的操作性启发式，而不是难度的直接证据。

RL 配方同样不完整。论文披露每个提示生成 8 或 16 条 rollout、全局批次为 128 个提示、采用无 KL 正则的 token 级严格同策略 GRPO，并使用规则奖励；但没有说明全部阶段中 8 与 16 的具体分配，也没有给出完整优化器和随机种子设置、硬件、精确数学答案解析规则、代码执行沙箱、编译器/运行时版本、隐藏测试、失败日志或不可变提示清单。公开 AceReason-Math 数据集与数学 RL 有关，但尚未识别出对应的代码 RL 提示—测试资产。

规则验证会引入已知标签错误。论文明确指出，错误的代码测试会造成假阴性，过弱的测试会造成假阳性。只匹配最终答案也只检查结果，不能确认推理过程是否有效。组归一化奖励、token 级损失、难度筛选和截断处理都可能带来尚未被充分测量的选择偏差或长度效应。

七种 SFT 混合与分阶段 RL 对比具有参考价值，但不是完全受控的因果实验：混合规模、组成、回答长度、检查点历史和课程阶段可能同时变化。因此，基准分数提升本身不能验证数据正确性或整体质量。论文报告对具名评测集进行了重叠过滤，但没有发布匹配代码、针对每个来源的完整阈值，或可独立复现的污染报告。上游数据的许可与使用约束仍需逐源核验；本卡也未对报告结果进行独立复现。
