THROW combines the complementary behaviors of sampling and beam search in a two-stage policy. It first draws several deliberately short partial trajectories. A process reward model scores them, and the share that clears a score threshold becomes a difficulty indicator: many weak partial paths mean the prompt is treated as hard; enough strong paths mean it is treated as easy.

The second stage sends those two cases in opposite directions. Easy prompts undergo branch truncation, retaining only a few high-scoring candidates instead of finishing every sample. Hard prompts undergo controlled branch expansion from the best partial paths, concentrating extra decoding where it can repair a weak initial attempt. In this way, the same early evidence changes both the number of active branches and the amount of test-time compute spent on a prompt.
