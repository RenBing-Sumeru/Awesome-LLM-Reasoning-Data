- **模拟器边界。** MobileGym 追求 interaction fidelity，而不是复刻专有后端或像素级 Android。Synthetic app state、简化导航、缺失的延迟/网络/账户行为或作者建模的 UI 规律，都可能让 policy 利用无法迁移的模拟器特征。59-task 真机研究从 simulator signal bucket 中筛选，并排除 8 个无法等价或安全执行的任务，不能作为完整 suite 的代表性迁移估计（论文 §3.1、§5.2）。
- **Verifier gaming。** 确定性消除了随机 judge 方差，却不能消除 specification error。Agent 可能最大化手写 goal checks 的覆盖率，却违背未建模的用户意图；语义有效但状态表示不同也可能被误判。Whole-state diff 只能检测模拟器内的字段，并依赖 `expected_changes` 正确；官方 task authoring 文档本身也警告，漏列预期字段会产生误导性的 `clean` 信号（由反馈契约与官方 task spec 推断）。
- **“Dense” 不等于逐步。** Reward 是 episode 结束后计算的终局子检查通过比例，再乘若干折扣。它比二元成功提供更多等级，却不定位是哪一个动作带来进展；相关或容易的子检查可能主导 `p`，agent 也可能学习 partial-credit shortcut。AnswerSheet 的提交和格式要求还可能独立于信息检索能力惩罚弱模型；论文把同一 rollout 上切换 AnswerSheet 的严格消融留作未来工作（附录 G、K）。
- **Split 与污染。** Train160 与 Test256 在 class/template 层面严格不重叠，Test256 还包含更多 cross-app 任务，但论文没有报告 semantic near-duplicate、预训练模型暴露、world-data overlap 或下游基准污染审计。超过 27,000 个可能参数实例不代表训练实际看到同等数量的独立状态；当前脚本默认每模板只采一个实例，若不改变 `sample_n`，跨 epoch 会重复同一参数。
- **公开与 replay。** 仓库能够记录结果、截图、模型响应和 trajectory，但未核验到论文训练/评测 rollout、失败、reward vector、随机 seed 或 checkpoint 的不可变语料。当前脚本中的 `task_seed=42` 只固定当前采样行为；若未同时固定代码与数据 commit，就不能代表论文运行。仓库 v0.1.0 晚于 arXiv v2；当前 launch 默认值与论文硬件描述不同，当前 `mobilegym_flow.py` 还为 AnswerSheet 增加 10 步、而论文规定 15 步。这些都是具体的版本漂移风险。
