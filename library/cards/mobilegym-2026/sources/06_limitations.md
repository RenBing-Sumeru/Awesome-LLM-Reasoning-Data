- **Simulator boundary.** MobileGym targets interaction fidelity, not proprietary backends or pixel-level Android. Synthetic app state, simplified navigation, missing latency/network/account behavior, or author-modeled UI conventions can make policies exploit simulation regularities that do not transfer. The 59-task device study is selected from simulator signal buckets and excludes eight non-equivalent/unsafe tasks; it is not a representative full-suite transfer estimate (Paper §§3.1 and 5.2).
- **Verifier gaming.** Determinism removes stochastic judge variance but not specification error. An agent can maximize authored goal-check coverage while violating an unmodeled user intent, or incur a false negative when a semantically valid state differs from the expected representation. Whole-state diff only detects fields inside the simulator and depends on correct `expected_changes`; task-authoring documentation itself warns that omitted expected fields cause misleading `clean` signals (curator inference from the feedback contract and official task spec).
- **“Dense” does not mean stepwise.** Reward is the terminal fraction of passed subchecks plus multiplicative discounts, computed after an episode. It supplies more grades than binary success but does not localize which action caused progress. Correlated/easy subchecks can dominate `p`, and an agent may learn partial-credit shortcuts. AnswerSheet's submission and format requirements may also penalize weak models independently of information retrieval; the paper leaves a same-rollout AnswerSheet ablation to future work (Appendices G and K).
- **Split and contamination.** Train160 and Test256 are class/template-disjoint, and Test256 has more cross-app tasks, but no semantic-near-duplicate, pretrained-model exposure, world-data overlap, or downstream benchmark contamination audit is reported. More than 27,000 possible parameter instances do not imply that training saw that many unique states; the current script defaults to one sampled instance per template and repeats identical parameters across epochs unless `sample_n` changes.
- **Release and replay.** The repository can record results, screenshots, model responses, and trajectories, but no immutable corpus of the paper's training/evaluation rollouts, failures, reward vectors, random seeds, or checkpoint was verified. `task_seed=42` in the current script pins current sampling behavior, not the paper run unless code and data commits are also fixed. Repository v0.1.0 postdates arXiv v2; current launch defaults differ from the paper hardware description, and current `mobilegym_flow.py` gives AnswerSheet tasks 10 extra steps where the paper specifies 15. These are concrete version-drift risks.
- **Licensing and scope.** Core and RL code are Apache-2.0, while replaceable data/content and simulated assets are CC BY-NC 4.0 with third-party brand/content caveats. Code permission does not imply commercial permission for the companion data. Real-device evaluation also reintroduces manual reset and VLM judging, so simulator verifier reliability should not be projected onto those trajectories.
