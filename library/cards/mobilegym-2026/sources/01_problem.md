Mobile GUI-agent research needs more than screenshots and actions: online reinforcement learning requires many replicas of an identical initial state, and reliable evaluation requires a terminal predicate that can inspect changes hidden behind the rendered interface. Real apps make account state difficult to reset or fork, expose only partial state through `adb` or accessibility APIs, and may cause irreversible messages, transfers, or account changes. MobileGym addresses that infrastructure problem with an Android-like environment implemented in the browser rather than by reproducing proprietary app backends (Paper §§1 and 3.1).

The released research object is a simulator-and-task system, not a fixed trajectory corpus. MobileGym-Bench contains 416 parameterized task templates over 28 simulated apps: 160 train templates and 256 strictly disjoint test templates. At runtime, an instance binds instruction variants and parameters, patches the initial JSON state, lets an agent observe screenshots and issue GUI actions, and records terminal structured state, goal checks, diagnostics, and a scalar reward. The paper states that finite parameter ranges yield more than 27,000 instances, excluding continuous ranges (Paper §§4–4.2).

This belongs in `environment_agent_trajectory_data` because the consequential data object is an environment-linked episode: task template and seed, initial-state patch, screenshot/action sequence, final state, programmatic checks, termination status, and reward. It is not an offline demonstration release, a real-device benchmark, or evidence that the simulator reproduces proprietary services or pixel-level Android internals.

The Card reaches L4 content depth through arXiv v2, its appendices, the official project/repository, release and license pages, and current RL code. Its boundary is explicit: experiment rollouts, exact paper-run commit, trained checkpoint, and a complete reward/checkpoint ledger were not verified as released.
