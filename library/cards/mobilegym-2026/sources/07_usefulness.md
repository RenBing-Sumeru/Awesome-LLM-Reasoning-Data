For `environment_agent_trajectory_data`, MobileGym is a concrete blueprint for producing replayable-by-construction episodes: pin a template and sampled parameters, serialize the initial JSON state, record screenshot/action/model-response steps, retain final state and every goal-check result, and store termination and side-effect diagnostics. Researchers can use the released recorder/explorer to collect both successes and failures rather than exporting only positive transcripts.

For online agent training, the useful baseline is not a prepackaged rollout dataset but an environment-plus-reward recipe. Reproduce Train160 sampling, fork identical states for each GRPO group, compare binary success against terminal progress reward, and ablate the unclean/false-complete/overdue discounts. Because the reward is terminal subcheck density rather than action-level process supervision, a proper study should log subcheck correlations and test reward gaming before calling it process feedback.

For evaluation and verifier research, Test256 supports separate reporting of SR, PR, FC, OT, and USE. Useful audits include mutation tests for every `check_goals`, adversarial states that satisfy fields without user intent, alternate-valid-state tests, `expected_changes` coverage, seed stability, and AnswerSheet format sensitivity. The paper's VLM-judge error set motivates comparing code predicates with independently audited labels rather than assuming programmatic checks are ground truth.

For sim-to-real work, use the 59-task study as a protocol seed: declare task-selection buckets, list excluded unsafe/non-equivalent tasks, preserve simulator and device rollouts, and report absolute base/trained results in both environments. Do not summarize only the 95.1% retained-gain ratio.
