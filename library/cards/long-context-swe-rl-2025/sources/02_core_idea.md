The contribution is a two-step self-training recipe: first warm up Qwen2.5-72B-Instruct on self-generated repository episodes that pass executable tests, then continue with synchronous on-policy DAPO over groups of 10 long, multi-turn episodes whose terminal rewards are computed in isolated software environments.

Each episode couples an issue-conditioned repository state with a complete action-observation history. Available actions include arbitrary shell commands, line-range editing, search/navigation utilities, file creation, and a no-argument `submit`. The verifier observes the final environment and validation suite, not the correctness of each reasoning step. Before length shaping, a submitted patch receives 1 only if all required validation tests pass and 0 otherwise. A step penalty is zero for the first 10 turns and then decreases linearly toward -1 at the turn cap. Within each 10-rollout task group, final rewards are normalized; one trajectory-level advantage is broadcast to all tokens, and zero-advantage samples are dropped.

The feedback contract is consequently executable but sparse. It can test the final repository under the retained suite and penalize long episodes, but it cannot attribute credit to individual commands, certify semantic correctness beyond the tests, detect unsafe intermediate behavior, or teach calibrated abstention. RFT further changes the observed distribution by keeping only terminal successes, although malformed assistant turns inside a kept episode are masked. RL can use both successes and failures when the group has reward variation; homogeneous zero-advantage groups do not update the model.

Relative to the public SWE-rebench substrate, the paper adds paper-specific filtering, successful-episode RFT, two long-context RL stages, and a precise terminal reward/training interface. Relative to broad agentic RL recipes such as Agent-RLVR, its distinctive evidence surface is repository repair with full shell/edit observations, 65k/131k context, and executable validation. It does not introduce the underlying SWE-rebench tasks, shell-agent paradigm, binary test oracle, or DAPO objective, and it does not release a new trajectory dataset.
