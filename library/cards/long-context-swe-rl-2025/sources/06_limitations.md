Methodologically, terminal binary reward is extremely sparse for episodes spanning thousands of tokens. Broadcasting one scalar advantage to every token cannot identify which command, observation interpretation, or edit caused success or failure. The authors also note that binary success encourages submitting a patch “at any cost” rather than abstaining under uncertainty. Incomplete tests can admit behaviorally wrong patches, while brittle tests can reject valid alternatives; no retained-suite false-positive or false-negative audit is reported.

Selection changes the observed behavior distribution. RFT keeps only 6,548 passing episodes and discards failed attempts, so its warm-up data overrepresent tasks already solvable by the base agent. RL preserves successes and failures only when group-relative rewards vary; zero-advantage groups contribute no update. The frequency, composition, and post-training persistence of online rollouts are unknown. The exact score-3.0 metadata field and Stage 2 selection inequality/window are also unspecified.

The release is insufficient for episode replay. Public rows include `repo`, `base_commit`, `environment_setup_commit`, test patches, F2P/P2P lists, and installation metadata, and 7,500 containers were announced. However, there is no exact 7,249/2,028 task-to-image manifest, immutable OCI digest set, dependency lock, random seed list, action/observation log, submitted patch record, reward log, checkpoint, or training configuration bundle. Reset semantics between 10 rollouts—including persistence of files or processes, timeout cleanup, and network state—are unknown.

Version drift is demonstrated rather than hypothetical. The paper pins vLLM 0.7.4, and an inference-setting change already caused training degradation. The public execution fork is pinned in this audit to commit `980d0cca8aa4e73f1d9f894e906370bef8c4de8a`, while the dataset later gained a 6,542-row `filtered` split. That later object must not be confused with the paper's 6,548 RFT trajectories or 7,249-task training pool.

Contamination control is narrow. May/June are held out from training, but no broad repository deduplication, SWE-bench overlap audit, model-pretraining exposure analysis, or correction for repeated Verified-50 monitoring is reported. Consequently, the scores do not establish unseen-task generalization under a clean benchmark boundary.

Rights, privacy, and security remain unresolved. The manuscript and SWE-rebench card declare CC BY 4.0, the execution fork is MIT, and the dataset card requires respecting each source repository's license. Those statements do not reconcile rights in issues, comments, tests, dependencies, generated traces, model outputs, or checkpoints. No PII/consent/takedown process is described. The agent may run arbitrary shell commands and install packages in Kubernetes pods, but network isolation, credentials, syscall/capability restrictions, malicious-repository handling, and supply-chain controls are undisclosed.
