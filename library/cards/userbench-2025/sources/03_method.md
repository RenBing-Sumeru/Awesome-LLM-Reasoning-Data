**Inputs and construction.** Authors curate travel preferences and multiple indirect elicitation expressions for flight, hotel, apartment, rental-car, and restaurant. Table 2 reports 82 final preferences and 902 elicitation ways. Preferences are randomly combined into difficulty-tiered compositions such as Travel-22, 2222, 33, 233, 333, 44, 334, and 444. GPT-4o generates the ideal travel-arrangement statement. For every included aspect, GPT-4o also generates correct options satisfying all preferences, wrong options violating at least one, and noise options that are irrelevant or unrealistic, under human supervision. The exact construction prompts, GPT-4o endpoint, temperature, retry policy, random seed, rejection counts, curator assignment, and adjudication process are undisclosed.

**Task packaging and split.** Eight JSON files store scenario-level preference structure, implicit utterances, search arguments, typed options and reasons, correct/wrong/noise IDs, one `best_id`, and `best_id_thought`. The official release wraps these tasks in 32 train/test Parquet files for single- and multi-choice modes. Exhaustive ID inspection finds 3,122 unique tasks: 2,651 train and 471 test, with no ID overlap. Each choice variant repeats the same task IDs, producing 6,244 serialized rows but not 6,244 unique scenarios. Split logic, seed, semantic-near-duplicate checks, and decontamination are unknown.

**Reset and action loop.** A reset returns the task description, goal, feedback, step count, episode state, preference counts/ratio, and last reward. Every step requires `interact_with_env(thought, choice, content)`. A `search` requests options for an aspect; an `action` asks or converses with the user; an `answer` submits an option ID. The environment records action and conversation histories, tracks active/passive elicitation, and returns either a simulated-user utterance, search feedback plus shuffled pre-generated options, or answer feedback. The agent's `thought` is stored as an emitted field but is not independently verified.

**Judge, reward, and environment.** GPT-4o evaluates whether search text matches every ground-truth argument and identifies the requested aspect. A newly valid search yields 0.2 and exposes its option database. GPT-4o also classifies clarification utterances; a valid question about an available preference reveals the preference indirectly and yields 0.2. After three non-preference turns, the default environment passively reveals one remaining preference chosen with Python `random.choice`. Rule code parses answer IDs and gives 1.0 to `best_id`, 0.8 to another correct ID, and the default 0.0 to a wrong ID. An episode terminates when no best options remain or one answer has been recorded for every aspect in one-choice mode; it truncates at the step limit.

**Evaluation and release boundary.** Main experiments use GPT-4o as user simulator/judge, temperature 0, a maximum of 20 turns, 2,048 output tokens per turn, and one run per model-task; the paper reports eight H200 GPUs for evaluation hosting. Every fifth search is configured to simulate failure. The public repository releases task/environment data, evaluator code, prompts, schema, and Parquet launch records, but no complete corpus of paper-run episodes, raw judge outputs, retries, or environment logs. Reproduction should pin commit `80506d2`, all data files, dependencies, environment configuration, exact model endpoint, prompts, API behavior, and both Python and NumPy randomness. The paper performs evaluation only and reports no SFT, RL, or agent-training experiment.
