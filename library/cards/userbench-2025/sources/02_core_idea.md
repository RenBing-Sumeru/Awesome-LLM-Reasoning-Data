The one-sentence contribution is: UserBench couples a structured implicit-preference task bank with a Gymnasium travel environment so clarification, search, and recommendation behavior can be evaluated through mixed GPT-4o judgments and rule/state checks rather than only a final free-form answer.

Three layers form the mechanism. First, task construction combines curated preference concepts and indirect expressions across travel aspects, then uses GPT-4o under human supervision to generate an ideal arrangement and correct, wrong, and noise options. Second, a runtime interface requires one `interact_with_env` call per turn with an agent-emitted `thought`, a choice in `action`, `search`, or `answer`, and textual content. Third, the environment maintains elicited preferences, search state, remaining option labels, accumulated reward, and episode status while returning simulated-user replies or pre-generated search options.

The feedback contract is `mixed`. GPT-4o judges whether a free-form search includes the required ground-truth arguments and whether a clarification utterance targets an available preference; it also generates the implicit user reply. Code parses option IDs, checks correct and best sets, updates state, applies rewards, and decides termination/truncation. Default rewards are 0.2 for a newly valid search, 0.2 for a newly elicited preference, 1.0 for the designated best option, 0.8 for another correct option, and 0.0 for a wrong option. The Parquet field `reward_model.style: rule` therefore does not describe the whole evaluator.

This interface can observe prompt-judge classifications, exact option-ID membership, environment counters, tool history, and final state. It cannot establish that GPT-4o's semantic classifications are unbiased, that a lone `best_id` is uniquely preferable, that the agent's `thought` is faithful reasoning, or that synthetic travel interaction transfers to real users and live providers. Termination is not a success predicate: under one-choice mode, a wrong submission can consume an aspect and help end the episode.

The closest comparison class is a standard agent benchmark that scores task completion without making user preference discovery a first-class state variable. UserBench's concrete change is to expose implicit preferences through both active clarification and passive elicitation, then score search and answer behavior within the same environment. The work does not release the resulting model trajectories, so its directional value for reasoning data is the inspectable environment-feedback contract and task release, not a demonstrated training corpus.
