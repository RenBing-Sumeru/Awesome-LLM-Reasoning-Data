- The released object is not a trajectory corpus. Parquet rows launch tasks and environments; complete paper-run messages, actions, observations, raw judge outputs, retries, fallbacks, errors, seeds, and successful/failed episodes are unavailable. Retention bias and dropped-run accounting cannot be audited.
- Count documentation is inconsistent. Section 3.5 says 417 test points, Table 2 and the release have 471, the introduction claims 4K+ scenarios, and the public release has 3,122 unique IDs. The 6,244 Parquet rows duplicate single-/multi-choice variants and must not be treated as unique tasks; 10K+ is construction capacity.
- The paper Figure 8 and repository disagree on judge-type numbering. The public code mapping has existed since the first commit, so replay or reimplementation must follow a pinned code revision rather than assume the appendix labels are executable documentation.
- GPT-4o controls search validity, clarification validity, preference identification, simulated-user text, and two 0.2 rewards. No calibration set, false-positive/false-negative rate, repeated-judge variance, alternative-judge sensitivity, prompt-attack study, or adversarial audit is reported. Temperature 0 does not establish deterministic API behavior.
- Passive elicitation selects a remaining preference with unseeded Python `random.choice` by default, while option shuffling uses a module-level NumPy seed of 42. The evaluation script does not set the passive seed. One-run results can therefore vary through the environment even when agent and simulator temperature is 0.
- Exact-`best_id` reward can force a single winner among semantically tied correct options. The inspected restaurant record acknowledges equal cost levels yet assigns only one best ID. A complete 3,122-task audit of best-option ties, correct/wrong/noise semantics, and rationale consistency is unavailable.
- One-choice termination is not equivalent to success: any submitted option can consume an aspect, including a wrong option, and the episode may end after all aspects are consumed. Reward and termination must be analyzed separately.
- Split evidence establishes zero exact ID overlap between 2,651 train and 471 test tasks, but the split rule, seed, grouping policy, semantic-near-duplicate analysis, external benchmark overlap, model-pretraining contamination, and post-publication exposure policy are undisclosed.
- The root repository is Apache-2.0, but no separate dataset card or rights statement covers all generated scenarios/options, upstream preference sources, human supervision, and model-provider output terms. Annotator recruitment, qualifications, assignment, agreement, adjudication, compensation, and consent are unknown.
- The environment is a synthetic/mock travel domain with static pre-generated options. It can reward exact argument matching and option-ID behavior rather than robust live search or real-user preference handling. Main results are single runs and are not independently reproduced.
- The paper evaluates agents only. A 2,651-row train split and discussion of future SFT/RL support do not demonstrate SFT, RLVR, PRM, reward-model, or agent-RL use. Benchmark scores are not evidence of training-data quality.
- No tag or GitHub Release freezes the artifact. Data were added after arXiv v1, the exact dated GPT-4o endpoint is unknown, and dependencies/API behavior are not immutably specified. Reuse must pin commit `80506d2` or another explicit revision and record hashes and configuration.
