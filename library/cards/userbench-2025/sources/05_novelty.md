The prior baseline is an agent evaluation surface that exposes a task, tools, and a terminal answer or outcome but treats user requirements as already stated or as unconstrained dialogue. UserBench changes the data object by encoding a hidden preference inventory with multiple indirect expressions, allowing the agent to reveal that state through targeted questions, and connecting the revealed state to search arguments, option databases, answer labels, and per-transition rewards. The evaluation target is thus not merely itinerary correctness; it includes whether the agent gathered constraints and searched appropriately.

The construction contribution is a structured-to-interactive mapping. Curated preferences are composed across five travel aspects and difficulty tiers; GPT-4o generates an ideal request and correct/wrong/noise options under human supervision; JSON records preserve preference, search, option, and label structure; Parquet wrappers instantiate single- and multi-choice Gym tasks. This is more specific than scaling a prompt list, but it is not fully reconstructable because prompts, seeds, retries, rejection counts, review assignments, and split logic are undisclosed.

The feedback interface is also concrete. Clarification and search use a GPT-4o semantic judge, while answer scoring, state update, and termination use rules. State/action rewards expose whether a preference was newly elicited or a search newly validated, and terminal answer reward distinguishes one designated best option from other correct options. This mixed contract is useful precisely because its failure surfaces are visible: judge error, label ties, passive randomness, and non-success termination can each change the measured outcome.

UserBench does not newly introduce Gymnasium, function calling, LLM user simulation, synthetic travel data, implicit preferences, or LLM-as-judge individually. It integrates them into one user-centric benchmark and releases the task/environment specification. It also does not provide a trajectory release, a training recipe demonstrated by experiments, an independently calibrated verifier, or a guarantee that the root repository license resolves dataset and provider-output rights. The paper's benchmark performance cannot fill those gaps.

For reasoning-data research, the direction signal is the explicit chain `underspecified request -> elicitation/search action -> simulated or database observation -> preference/search state -> mixed reward -> answer and termination`. Reuse should begin by pinning the repository, reconciling counts and judge numbering, auditing `best_id` ties and false judge decisions, seeding all randomness, documenting split/decontamination and rights, and releasing both successful and failed episodes. Until then, the novelty supports evaluation and verifier study, not unrestricted training reuse.
