MacArena's core contribution is an online macOS benchmark in which each instruction is bound to a resettable UTM VM, raw GUI action interface, and task-specific final-state evaluator. Two VMs run through Apple's native Virtualization framework on Apple Silicon: `MacArena.utm` supports the 49 custom tasks, while `osworld.utm` supports the inherited OSWorld and macOSWorld tasks. The official VM bundle exposes nine files totaling **121,038,630,504 bytes (about 121 GB)**.

At each step the agent receives a full-desktop screenshot; the environment can optionally expose a macOS accessibility tree and terminal output. Actions cover mouse move/click/right-click/double-click/drag/scroll/down/up, keyboard typing/press/down/up/hotkey, and terminal `WAIT`, `FAIL`, or `DONE`. The agent terminates by emitting `DONE` or `FAIL`, or by reaching the 15-step horizon. This declaration is not itself success: the runner then invokes the task evaluator against final VM state.

The feedback contract is environmental and programmatic. OSWorld-style tasks combine result getters and metrics; macOSWorld-style and MacArena-specific tasks run shell, Python, or AppleScript commands in the VM. The evaluator returns a scalar in `[0,1]`. Runtime `env.step` returns reward 0, so no step-level reward or process supervision is present; feedback attaches to the complete episode after termination.

Compared with OSWorld and macOSWorld as source task collections, the concrete change is their execution in a common Apple-Silicon UTM substrate together with 49 additional macOS-native tasks, a unified action/controller layer, local trajectory recording, and final-state graders. The environment can observe scripted terminal properties but cannot guarantee semantic task correctness when an evaluator is wrong. The released Contacts task `450f6f33-bf2c-43bf-a349-4363e9b75740`, whose evaluator checks an unrelated Session/YouTube blocker state, demonstrates this boundary directly.
