**Task sources and construction.** The repository contains 421 task JSONs: 221 manually ported from OSWorld, 151 derived from macOSWorld, and 49 MacArena-specific. Custom tasks cover Advanced Apps 9, File Management 6, Productivity 14, System and Interface 8, and System Apps 12, across 20 applications. The paper says all tasks were manually created and reviewed for executability, lack of ambiguity, and correct specification. However, all 49 custom JSONs use `source: "synth_generation"`; no generator model, prompt, sampling process, adjudication, annotator count, or rejected-task statistics reconcile this label with the paper's wording.

**Environment setup and reset.** `MacArena.utm` and `osworld.utm` run aarch64 macOS through Apple's Virtualization framework on Apple Silicon with 1920×1200 dynamic display, 8192 MB memory, and shared networking; the audited app manifest states macOS Sequoia 15.5. The paper describes copy-on-use: clone a clean base VM before each episode and discard it afterward. The provider implements clone/delete reset, but the two-run helper fully resets only run 1; before run 2 it closes applications and calls the runner with `reset_env=False`. Residual files, preferences, or processes can therefore affect the second result.

**Interaction and evaluation.** Four agents—UI-TARS-1.5 7B, Qwen3-VL 2B, Qwen3-VL 4B, and OpenAI Computer Use Preview—are each evaluated **twice per task with a 15-step limit**. Every experimental step supplies a screenshot and receives raw mouse/keyboard action. The episode ends on `DONE`, `FAIL`, or horizon. The final evaluator inspects VM state and returns a scalar in `[0,1]`; `env.step` returns 0 throughout, so supervision is terminal and full-episode. The two-run helper retains `run_1` and `run_2` directories but aggregates the maximum score.

**Runtime outputs.** For every attempted local run, the runner can write per-step screenshot PNGs and `traj.jsonl` entries containing `step_num`, timestamp, action, reward, done, info, and screenshot filename. It also writes model-response history, runtime log, final `result.txt`, and an MP4 recording; exceptions append an error object. These capabilities describe locally generated data, not a released normalized corpus: no immutable public manifest of the paper's success, failure, timeout, screenshot, action, reward, response, and video records was confirmed.

**Reproduction boundary.** Reproduction should pin repository commit `dcdc7d366da12641578ab90f085d69db91651c58`, both UTM images and hashes, macOS/app versions, task JSON and upstream revisions, evaluator scripts, host/hypervisor configuration, model/API snapshot, prompt/action adapter, decoding settings, seeds, retry policy, reset flag, and external URLs. The paper-run seeds, exact model/API snapshots, decoding settings, actual meta-file, deterministic replay manifest, and public rollout hashes are unknown. Appendix A limits one Apple Silicon host to two guest VMs, so greater parallelism requires more hosts.
