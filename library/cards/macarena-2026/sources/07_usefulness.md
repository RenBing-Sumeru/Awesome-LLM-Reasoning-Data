For `environment_agent_trajectory_data`, MacArena is a concrete schema and systems reference for collecting GUI episodes. A defensible record should bind task ID/source revision, instruction, initialization, VM/app/hash manifest, screenshot or accessibility observation, normalized action, response and error, stop reason, final evaluator configuration/score, reset state, run index, and every emitted screenshot/log/video file. Keeping `run_1` and `run_2` separate is necessary because their reset conditions differ.

For `benchmarks_evaluation_surfaces`, the 421 task JSONs and final-state evaluators support execution-based comparison of computer-use agents on macOS. Reuse should pin the audited repository/task/VM versions, run each evaluator against positive and negative fixtures, correct the known Contacts/Session mismatch, and report both per-run scores rather than only the maximum. The 49 custom evaluators also provide a tractable starting set for a systematic verifier audit.

The runner can be used to create a local audit corpus containing screenshots, actions, zero per-step rewards, responses, exceptions, results, and videos for successful and failed attempts. Such a corpus should record explicit missingness and privacy/secret scans, and should not be called the paper's released trajectories. Because no canonical rollout corpus, split, decontamination audit, replay ledger, or training objective is published, this Card does not classify MacArena for agent training, SFT, or RL.

The benchmark is also useful for controlled version-drift studies: compare evaluator outcomes under fixed task JSONs while changing macOS/application versions, external resources, reset policy, or VM snapshot. This can reveal false positives/negatives and residual-state effects. The OSWorld/MacArena ranking reversal can motivate exposure-sensitive analysis, but only a separate lineage and model-training audit can test contamination.

Current reuse classification is **evaluation and audit only**. Direct training reuse or production-agent validation remains blocked pending corrected and tested evaluators, per-episode clean reset, reconciled construction provenance, explicit split/exposure policy, immutable rollout and replay manifests, privacy/security review, and component-level rights clarification.
