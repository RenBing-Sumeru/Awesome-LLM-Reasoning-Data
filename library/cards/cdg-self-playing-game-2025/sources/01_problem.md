Reasoning models can produce a correct answer yet abandon it after a plausible false criticism, or produce a wrong answer yet fail to use a valid diagnosis. CDG treats this distinction—not raw problem solving alone—as a data-construction problem: the training record must show whether a model should accept or reject feedback and what happened after that decision.

The semantic unit is a one-exchange episode `(question, initial solution, critique, revised solution)`. To interpret it, a curator also needs the reference answer, initial and final correctness, routed critic role, self-play loop, selection result, and checkpoint provenance. These fields distinguish four materially different outcomes: correcting an error, failing to correct it, resisting a fabricated error, and being misled away from a correct solution.

This object belongs in the data-construction and open-release-recipes track because the paper specifies a pipeline from benchmark training questions through role-conditioned generation, answer verification, multi-sample revision tests, thresholded selection, and role-specific fine-tuning. The official repository exposes code and links rollout data and a checkpoint, but it does not provide a single immutable manifest joining every raw question, sampled episode, verifier decision, selected training record, and trained model.
