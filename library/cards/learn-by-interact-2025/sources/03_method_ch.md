ICLR 终稿支持下面这条可重建流程，同时留下明确的复现边界。

1. **收集源资源。** SWE-bench-Lite 使用不重复的 Python 文件；其他环境使用 GitLab、Google Maps、Amazon、Reddit、Chrome、GIMP、LibreOffice、Ubuntu、Thunderbird、VLC、VS Code、dbt、Dagster、Astronomer、Airbyte、Superset、Metabase、Snowflake、BigQuery、JupyterLab 等服务或应用的公开文档、教程和 FAQ。精确快照、抓取日期、逐条 URL 与权利处置未披露。
2. **生成任务。** Claude-3.5-Sonnet 从每份文档采样三条指令。ICLR 终稿中，28,635 份文档对应 85,905 次任务尝试，也对应 85,905 条原始轨迹。温度为 0；精确模型修订版、其他解码参数、重试规则和随机种子未知。
3. **与环境交互。** Claude-3.5-Sonnet 接收指令、当前观察、交互历史和环境特定动作空间，预测动作并观察新状态。回合在智能体发出停止动作或达到环境最大步数时结束。环境/容器版本和各基准步数上限没有报告。
4. **后向构造候选。** 对每个连续子轨迹，模型生成步骤摘要或对片段目的的抽象描述。原始目标与轨迹不一致时，新目标可以改写为与现有行为相符。终稿报告 1,456,808 个候选对。
5. **筛选。** 先删除连续重复的动作—观察状态，再由 Claude-3.5-Sonnet 与 Gemini-1.5-Pro 评估连贯性、自然性、合理性和指令一致性；只有一致接受的样本保留，最终总数为 440,008。
6. **用于 ICL。** 每个智能体决策步最多检索五条基于观察的示例和五条基于模型的示例。后者先让 LLM 根据指令、历史和当前观察写查询，再用 `stella_en_1.5B_v5` 做稠密检索。
7. **用于 SFT。** 将指令—子轨迹对转换成下一动作预测，使用 LoRA 微调 CodeGemma-7B 或 Codestral-22B。已报告配置为批大小 128、学习率 \(2\times10^{-5}\)、warmup 比例 0.03、最大长度 8192、三轮训练和 80GB H100；LoRA rank、GPU 数量、运行时间、总 token、成本与完整命令未知。

忠实复现还需要源快照、环境镜像、精确提示词与 API 修订版、原始到派生记录的 ID、委员会输出、拒绝候选、随机种子和不可变清单。当前未找到这些官方可复用工件。
