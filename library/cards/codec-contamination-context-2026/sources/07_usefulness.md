An evaluation team with an open-weight model and candidate benchmark texts can run CoDeC before reporting scores: serialize each item, sample same-source demonstrations, save both likelihoods, and produce a per-dataset audit percentage. Success is clean separation from matched post-cutoff controls and stable results over resampling. Model developers can additionally monitor the score during training to flag early leaks. Do not use it as a black-box API test when token log-probabilities are unavailable, or as proof of verbatim copying without follow-up evidence. For multiple versions of one benchmark, audit train, validation, and test partitions separately rather than extrapolating one partition's result.
