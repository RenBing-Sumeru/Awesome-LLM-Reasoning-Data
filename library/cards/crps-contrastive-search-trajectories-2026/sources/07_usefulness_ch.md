对分配的 **Data Construction and Open Release Recipes** 方向而言，CRPS 是把高成本搜索轨迹转成紧凑 SFT 数据的具体案例。当各方法共享相同种子问题和原始轨迹池时，它可用于受控比较只选择成功路径的 MCTS、局部修订、无引导教师生成、随机对比和分布感知对比合成。

真正可复用的轨迹级发布应远多于当前两个字段。至少应记录不可变种子/来源 ID 与版本、explorer checkpoint 及提示版本、每个 MCTS 节点、父节点、语义步骤、动作、深度、访问次数、Q 估计、UCT 输入与终局奖励、正锚点及并列裁决、硬/软候选池、采样概率与选中 pair ID、全局/局部批评 JSON、解析修复、合成请求/响应与重试次数、抽取答案、精确/SymPy 验证器版本与判定、拒绝原因、最终采样方式、随机种子和校验和。

这些记录可支持搜索策略重放、对比选择研究、过程奖励模型或批评器训练、批评忠实性评测，并审计增益究竟来自搜索多样性、专有分析模型知识还是额外推理。终局正确性、搜索置信度、分析模型批评、语义分歧标签和最终 SFT 接收应保持为不同信号，不能折叠为单一质量分。

直接复用 CRPS-30K 做 SFT 时，应固定 Hugging Face revision，报告实际观察到的 27,256 行与 9,939 个唯一问题，对数据文件取哈希，检查重复解答与规范化后的 prompt，抽样审计中间数学步骤，并核验 GSM8K/MATH 版本、许可证及其与评测集的重叠。不得把该产物改称恰好 30,000 条记录，也不能从最终文本反推真实过程标签。

复现配方时，应固定 Git commit 和模型版本，澄清 `gpt-5-mini` backend，发布经过测试的 lockfile 与软件许可证，披露硬/软比例和重试策略，并报告包含 explorer GPU 工作及分析/合成 API 用量的端到端成本。当前发布在完成上述检查后可用于 SFT 实验与配方比较，但不足以重建每个对比决策、直接训练负轨迹，或审计批评忠实性。
