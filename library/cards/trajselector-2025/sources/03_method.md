
Corpus construction starts from the questions and ground-truth answers in OpenR1-Math-220K and DeepMath-103K. Qwen3-8B generates one response per source example with thinking enabled through vLLM (temperature 0.6, top-p 0.95, top-k 20, min-p 0, and a 10,000-token cap). Math-Verify assigns final-answer correctness. All incorrect responses are retained, correct responses are downsampled, and the records are shuffled to produce a 1:1 set: 11,592 positive plus 11,592 negative DeepMath records and 55,258 plus 55,258 OpenR1 records, for 133,700 total.

For each response, only the text between the think-tagged region is segmented, using the literal blank-line delimiter \n\n. The sampler's last hidden state at the final token of every segment is projected to the 0.6B score model. The score head produces wrong, buffer, and right probabilities; the training loss rewards right+buffer for an outcome-positive step and wrong+buffer for an outcome-negative step. The sampler is frozen while the full process score model is trained for three epochs with AdamW, learning rate 1e-4, weight decay 0.1, DeepSpeed ZeRO-2, bfloat16, per-device batch size 2, gradient accumulation 4, and eight H100 GPUs.

At inference, Qwen3-8B generates N candidates with the same documented decoding settings. TrajSelector computes each step's right probability, averages within each trajectory, and returns the candidate with the largest mean. This is an offline, external test-time selection substrate rather than an interactive environment.
