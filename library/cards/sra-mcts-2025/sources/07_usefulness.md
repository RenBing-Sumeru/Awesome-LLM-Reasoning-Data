For the rollout/search/test-time-trace track, SRA-MCTS is useful as a compact MCTS-to-SFT recipe for code reasoning and as a negative example of what is lost by flattening a tree. A reusable record should keep the LeetCode source and revision, overlap decision, model and decoding settings, node and parent IDs, state, action, raw self-score, rubric decision, reflection, visit count, UCT value, backpropagated reward, stopping reason, all rejected siblings, the selected thinking, regex transformation log, generated code, execution environment, tests, and terminal result. This would support process-supervision research, search-policy audits, SFT, and comparisons between model judgment and executable correctness without conflating them.
