SRA-MCTS 用 State、Action、Reward 和 Reflection 表示每个节点。UCT 选择叶节点；扩展阶段采样多个不重复的下一步；同一 LLM 通过渐进 rubric 评估每个 state-action pair 并写出 reflection；分数回传后影响后续选择。Reflection 也可输出停止信号，随后被选中的自然语言步骤拼接成 thinking，并用于提示代码生成。最终 SFT 数据对象是 question-thinking-code triple。这里采用的是 self-driven 而非 verifier-driven process supervision：搜索 value 来自 LLM 判断，而可执行 benchmark tests 用于下游评测，论文没有将其描述为构造阶段 reward。该工作的轨道相关性在于把搜索树转换为训练轨迹，也在于只保留选中路径时产生的审计缺口。
