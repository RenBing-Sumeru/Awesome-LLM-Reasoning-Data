SRA-MCTS represents each node with State, Action, Reward, and Reflection. UCT selects a leaf; expansion samples several non-duplicate next steps; the same LLM evaluates each state-action pair through a progressive rubric and writes a reflection; scores are backpropagated to influence later selection. A reflection can also emit the stopping signal, after which the selected natural-language steps are concatenated as thinking and used to prompt code generation. The final SFT object is a question-thinking-code triple. This is self-driven rather than verifier-driven process supervision: the search value is an LLM judgment, while executable benchmark tests are used for downstream evaluation, not described as the construction reward. Its track relevance is the conversion of a search tree into a training trajectory and the audit gap created when only the selected path is retained.
