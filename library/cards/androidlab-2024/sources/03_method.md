1. Inputs: an Android task instruction, a predefined virtual-device state, and either compressed XML or a screenshot with set-of-mark labels. 2. Pipeline: the agent observes the state, emits one action from the shared action space, receives the next Android observation, and repeats until finish or budget exhaustion. 3. Outputs: task-level success, sub-goal success, action-efficiency metrics, and optionally instruction-tuning records with task, screen, XML, and operation fields. 4. Feedback contract: benchmark tasks are decomposed into required page states, and UI-tree matching plus task-specific checks decide completion; higher-level metrics include success rate, sub-goal success rate, reversed redundancy ratio, and reasonable operation ratio. 5. Reuse notes: pin the repository commit, Android virtual device image, app data snapshot, benchmark split, evaluator code, action budget, and whether XML, SoM, ReAct, or SeeAct prompting is used.
