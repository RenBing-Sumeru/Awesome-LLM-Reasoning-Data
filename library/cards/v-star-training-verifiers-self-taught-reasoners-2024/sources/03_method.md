The mathematics pipeline uses GSM8K training problems and original rationales; the code pipeline uses MBPP training tasks and reference programs. For GSM8K, the first generator is LLaMA2 SFT-trained on the original data for 2 epochs. For MBPP, iteration 1 samples with a 3-shot prompt from pretrained CodeLLaMA, and Appendix B publishes that prompt. Experiments adapt 7B and 13B LLaMA2 or CodeLLaMA models with LoRA.

Main experiments run 3 iterations. At each iteration, the current generator samples 16 complete solutions per training query. A math solution is positive when its extracted final answer equals the reference answer; a code solution is positive when it passes all invoked tests. Positives are added to `D_GEN`; positives and negatives are added to `D_VER`. The next generator is trained from the pretrained base model on the enlarged `D_GEN`, then supplies the following round's 16 samples. This yields a nominal 48 self-generated candidates per query.

For each query, the verifier dataset takes the Cartesian product of available correct and incorrect solutions. The SFT model trained on original data is the DPO reference; its original training lasts 2 epochs for GSM8K and 3 for MBPP. DPO increases verifier likelihood for the correct member relative to the incorrect member. The paper does not disclose learning rates, batches, LoRA ranks, selected DPO beta, sequence limits, hardware, generation temperature, seeds, deduplication, pair balancing, or pair subsampling.

At inference, the generator produces 128 candidates per test problem. The paper estimates Best-of-64 from that fixed pool with a combinatorial formula after sorting candidates by verifier score; the formula assumes no tied scores. A separate GSM8K scaling plot subsamples from 1,000 generations. Best-of-1 ignores the verifier and equals generator Pass@1, while the main 7B curves saturate at k of at least 16.

The optional verifier-in-loop study differs from the main recipe: it samples 64 MBPP completions, retains the top 8 by verifier score, and adds enough incorrect examples to cap the retained set at 16 per query. The authors find no substantial gain, so the simpler programmatically labeled loop remains the recommended version in the paper.
