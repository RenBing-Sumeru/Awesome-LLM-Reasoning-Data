For the Preference and Reward Feedback Data track, V-STaR is a precise example of synthetic preference construction: binary programmatic outcomes are converted into correct-versus-incorrect pairs, and DPO trains a full-solution verifier whose native deployment signal is sequence likelihood. It helps readers distinguish a human preference, a terminal label, a DPO pair, an ORM score, and a Best-of-k selection score.

For the Data Construction and Open Release Recipes track, the two-buffer lineage is the main reusable lesson. Correct traces improve the generator; both accepted and rejected traces improve the verifier; later generator iterations refresh the error distribution. This recipe can guide self-training experiments wherever a reliable terminal predicate exists, including mathematics, code, formal proofs, or constrained tool tasks.

Responsible reuse requires rebuilding the missing audit layer. Pin source datasets and base checkpoints; save query IDs, generation seeds, iteration IDs, raw outcomes, execution errors, and pair provenance; measure label errors and pair imbalance; normalize and calibrate verifier scores; and test false positives, false negatives, and gaming on generators not seen during verifier training. Untrusted code must run in a documented sandbox.

The method should not be relabeled as process supervision or RLVR. It trains the generator with SFT, trains the verifier with offline DPO, and uses the verifier for test-time ranking. Extending it to policy optimization or open-ended feedback requires a new reward contract and new evidence.
