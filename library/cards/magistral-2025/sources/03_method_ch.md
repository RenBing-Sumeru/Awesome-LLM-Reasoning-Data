数学池最初包含 699k 道噪声题。完整性与答案可验证性检查、删除证明题和多问问题、以及把选择题改写为陈述题之后，剩下 501k 道。难度筛选先使用 Mistral Large 2 的采样答案，再训练一个 24B RL 检查点作为更强 grader。后者对原始问题各生成 16 个回答，移除过易、持续无法求解及与参考答案存在共识性冲突的题目，最终保留 38k 道。

35k 代码池来自来源未具体披露的竞赛数据。流程删除没有解法或测试不足的问题，在现有测试上运行候选解法，丢弃一致性不足的测试；若所有解法都未通过某个仍具一致性的测试，则用解法输出的众数修订预期结果；缺失测试时还会生成新测试并经过相同检查。适用题面会复制为 Python 或 C++ 要求。RL 阶段以 C++20 编译代码，编译超时为 10 秒；再运行同一回答组共享的 20 个随机抽取测试，每个测试限时 4 秒、内存 300 MB。

格式是硬门控：回答必须包含一对且仅一对推理标签，数学答案需把最终表达式放入方框，代码答案需使用带语言标记的 Markdown 代码块。格式有效获得 0.1，终局正确再增加 0.9；接近长度上限时施加软惩罚。为减少语言切换，10% 的英文问题被翻译为法语、西班牙语、意大利语、德语、中文和俄语；去除 LaTeX 与代码后，fastText 分别识别问题、推理和答案的语言，三者一致时增加奖励。

在线系统让 trainer、generator 与 verifier 异步持续工作。完成的序列被分配到数据并行 rank，队列大小限制离策略滞后；权重刷新时，在途生成仍沿用较旧的键值缓存。改进版 GRPO 移除 KL 正则，对 token 损失和 minibatch advantage 做归一化，把上侧裁剪阈值调到 0.26-0.28，并删除全对或全错的零 advantage 组。Small 使用 Medium 后期正确轨迹，以及 Medium 在筛选后的 OpenThoughts 与 OpenR1 代码提示上生成的回答，并混入 10% 通用指令数据；四个 epoch 的 SFT 之后再做 RL，batch 为 2048 条序列，温度为 1.0，非惩罚长度上限为 32k。
