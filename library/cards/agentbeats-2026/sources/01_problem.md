AgentBeats documentation also links an ICML poster titled *Position: Agent Evaluation Should Be Agentified for Openness, Standardization, and Reproducibility*. Because that title differs from the assigned paper and no official identity mapping was verified, this Card does not treat ICML as the venue of the arXiv record.

Agent assessment is usually packaged as benchmark-specific code: task retrieval, environment startup, tool exposure, subject-agent interaction, stopping, scoring, and result formatting are coupled to one harness. That makes it difficult to connect independently developed agents and judges or to compare what their scores mean. AgentBeats addresses this interface problem through Agentified Agent Assessment (AAA): the benchmark becomes a judge agent, the evaluated system becomes a subject agent, and a delegator binds their endpoints and configuration using A2A for task messaging and MCP for tools.

The relevant data object is an assessment episode, not a standalone prompt or answer. Its protocol envelope contains the assessment request, participant roles/endpoints, configuration, judge-issued task, optional A2A/MCP events, tool or environment observations, subject response and output artifact, final environment state, judge metrics, score, and a JSON result report whose inner schema remains assessment-specific. A judge can use fixed or adaptive tasks and can score with programmatic tests, environment predicates, semantic prompts/LLM judgment, or a mixture.

This episode-and-feedback boundary places the work in environment_agent_trajectory_data, even though the paper does not release a centralized trajectory dataset. The evidence reaches Card depth for the protocol, roles, deployment modes, field study, coding case, feedback contract, and audit risks. The accepted curation_level nevertheless remains L3_summary_ready: exact arXiv-v2 implementation commits, images, configurations, record-level traces/results, replay manifests, rights, decontamination, and retention policy are still unknown.
