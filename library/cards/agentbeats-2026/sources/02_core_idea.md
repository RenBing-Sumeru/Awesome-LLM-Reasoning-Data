The one-sentence contribution is: AgentBeats turns assessment logic into a judge agent that owns tasks, tools, environments, stopping, metrics, and result reporting behind A2A/MCP, so independently hosted subject agents can produce comparable protocol-level evaluation episodes without sharing one internal harness.

Three roles define the mechanism. A delegator selects participants and sends the kick-off request plus role-to-endpoint mapping and configuration. The judge retrieves or generates tasks, prepares data, environment, and tools, issues A2A instructions, receives subject messages or completion updates, observes exposed MCP/environment effects, and produces predefined metrics and a result report. One or more subject agents attempt the task through their own A2A responses and any MCP capabilities exposed by the judge. Agent construction, registration, and execution are distinct lifecycle stages; local, remote, hosted, proxy, and CI modes place those stages on different infrastructure.

The feedback contract is intentionally heterogeneous. Programmatic tests and environment predicates can inspect executable artifacts or final state; semantic judges can inspect responses through prompts or LLM scoring; a judge can combine both. In the coding case, completion or timeout ends interaction, then benchmark evaluation scripts score collected artifacts and environment state. This feedback observes only what the judge exposes and records. It does not prove that predicates are complete, that an LLM judge is calibrated, that remote logs/reset behavior are sufficient, or that scores from different judges share a common reward meaning. A “judge agent” is therefore not synonymous with “LLM-as-judge.”

Relative to a conventional benchmark wrapper, AAA moves assessment ownership behind a standard agent interface rather than requiring every subject to adopt benchmark-specific orchestration. Relative to an executable environment benchmark such as tau2-bench, AgentBeats standardizes the outer participant and transport contract across heterogeneous assessments rather than publishing one fixed task/episode schema. The resulting object is useful for interface and feedback audit, but protocol standardization alone does not create a licensed trajectory corpus or exact replay package.

For reasoning-data research, the key chain is: delegator configuration -> judge task/data/environment -> subject A2A/MCP episode -> response/artifact/final state -> judge metric/result. Full-episode and state/action-level fields describe observable evaluation surfaces. The paper uses them for evaluation and comparative audit only; its discussion of possible RL integration is not evidence of agent_training or rlvr.
