**输入与 authoring。** judge agent 掌管 benchmark data 或 task generation、environment setup、tool server、evaluation flow、metric、scoring 与 reporting。subject agent 暴露 A2A endpoint，并在需要时使用 judge 提供的 MCP tool；delegator 提供参与方 role/endpoint 与 configuration。field study 中的 judge 和 subject 由社区参与者编写。研究排除了不可访问或 malformed 的 repository，并对其余仓库去重，但没有发布冻结 inventory、exclusion ledger、deduplication key 与 prompt-extraction 实现。

**构造、注册与部署。** agent blueprint 可以由 Git repository 或 Docker image 表示，再部署成 A2A endpoint。平台把 construction、registration 与 assessment execution 分开。论文描述 local、remote、hosted、proxy 与 CI 五种 mode，它们在 agent 运行位置、assessment 发起方以及 result 出现在平台记录、log 还是提交 artifact 上存在差异。当前 leaderboard template 使用 scenario/component manifest、GitHub Actions、result directory、Docker image、secret、sharding 与 Amber，但它是滚动更新的 artifact，而不是 arXiv v2 的不可变实验 stack。

**Episode 执行。** delegator 发起 assessment。judge 加载固定 data 或生成/自适应 task，准备 environment 与 MCP tool，并通过 A2A 发送 task instruction 或访问方式。subject 作出 response、调用 tool、改变 environment 并报告 completion；judge 按自身 policy 继续或停止。输出外层由可观察的 message/update、tool call 与 observation、subject response 或 artifact、final state、metric、score 和 JSON report 组成。系统不强制统一 action vocabulary 或内部 result schema。

**Verifier、reward 与 termination。** 每个 judge 通过程序化 check、environment predicate、语义 prompt/LLM judgment 或混合方式定义 metric；termination 也由 assessment 决定。在 coding case 中，judge 启动隔离的 source-tree container，注入 subject runtime 或通过 MCP 提供 remote shell，等待 completion 或 timeout，收集 artifact，再运行 benchmark evaluation script。该过程生成 terminal solve score，而不是 token 级 dense supervision。由于 runtime injection 可能失败或扰动 container，流程包含 preflight 与 remote-shell fallback。

**Coding case 的选择与设置。** case study 使用 SWE-Bench Pro public split 的 731 个 instance、Terminal-Bench 2.0 全部 89 个 task，以及执行 ground-truth test 并丢弃失败项后保留的 1,222 个 DevEval instance。Claude Opus 4.7、GPT-5.4、Gemini 3.1 Pro、Qwen3.5-397B-A17B 分别与 Claude Code、Codex CLI、OpenCode、mini-SWE-agent 配对。各 agent 使用 default setting；reported thinking effort 依次为 xHigh、Medium、High，以及仅开启 thinking 而未给出进一步 level。主实验成本约 6,000 美元。temperature、seed、逐 instance rollout 数、retry、准确 time limit 与完整 configuration 仍为 unknown。
