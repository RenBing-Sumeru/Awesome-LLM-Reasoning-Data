**Sources and original traces.** The method defines task inputs from \(D_{\mathrm{train}}\) and reports mathematical-reasoning experiments on GSM8K, MATH/MATH-500, and AIME24 surfaces. Exact construction rows, upstream revisions, source IDs, prompt counts, and construction/evaluation mappings are not disclosed. The formal method says target model \(S\) generates \(r_0\) from the question and an initial prompt requesting step-by-step reasoning with a boxed final answer. Tables 9–11, however, report compressor-dependent “Original Len” values repeated across target models, and Figure 8 says “Compressor Origin Length”; operational authorship of the original traces therefore remains ambiguous.

**Sequential generator.** One API compressor rewrites the previous rationale per round. The prompt contains the question, prior thought process, and final answer, and requests a simplified thought process without adding information. GPT-4o-mini is the main compressor. Compressor comparisons include GPT-3.5-turbo, GPT-4.1-nano, GPT-4.1-mini, GPT-4o, and DeepSeek-V3. The target models reported are LLaMA-3.1-8B-Instruct, Qwen2.5-3B/7B-Instruct, and DeepSeek-R1-Distill-Qwen-1.5B/7B. Exact model and tokenizer revisions, temperature, top-p/top-k, seeds, retry policy, timeouts, and per-call output caps are unknown.

**Selection and rejection.** Algorithm 1 starts from \(r_0\), generates one \(r_i\) from \(r_{i-1}\), and compares token counts. A strict increase causes the loop to break and retain \(r_{i-1}\); the longer \(r_i\) is the rebound/rejected round. Equality continues. If no rebound occurs before maximum round \(T\), the last non-increasing revision is selected. No correctness, semantic-equivalence, PPL, or process-verification gate is specified. \(T\), the tokenizer revision, per-example stop logs, exceptions, and actual retained/rejected counts are unknown.

**Round ranges and budget.** The paper does not disclose one global construction budget. Figure 3 spans fixed rounds 2–10, Tables 9–11 report rounds 2–5, the GSM8K example spans 0–5, and the MATH example spans 0–8. Appendix A.5 lists maximum inference tokens and maximum training sequence length as 16,384, but it does not identify 16,384 as a compression-call budget. Per-example API calls, input/output tokens, latency, price, failures, and retries are unavailable.

**Performance estimator.** A separate Performance Estimation Hypothesis predicts downstream fine-tuned accuracy and CoT length for compressor choice from configuration-level features such as compression rate, compressed-CoT PPL, original length, and target/compressor training accuracy. Bayesian Ridge is the default, with Random Forest as a comparison. Each target model has \(n=20\) configuration rows and the paper reports 5-fold cross-validation with an 80/20 train/test procedure. This estimator is not the per-example stopping rule, and the unavailable implementation does not show whether correlated rounds from one compressor were grouped across folds.

**SFT construction.** Selected \(r^*\) plus its answer forms the concise SFT target; an undisclosed fraction of original traces is mixed in. LLaMA-Factory LoRA settings are rank 8, alpha 16, learning rate \(2\times10^{-5}\), batch size 32, three epochs, maximum sequence length 16,384, bfloat16, AdamW, and cosine warmup. The paper reports about 1.5 hours for a 7B model. Hardware, seed, LoRA target modules, warmup fraction, framework revision, mixture ratio, and record counts are unknown.

**Release surface.** The author-designated GitHub repository’s checked revision contains only `README.md`. Installation text refers to `requirements.txt`, and an MIT badge links to `LICENSE`, but neither file exists in the current or historical tree. No code, prompts-as-files, configs, data, schema, split manifests, checkpoints, or evaluation harness is released. The repository URL is verified as official; implementation and corpus availability are not.
