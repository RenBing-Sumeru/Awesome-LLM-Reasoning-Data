Long-to-short reasoning data raises a problem that ordinary answer filtering does not resolve: how should a long rationale be shortened without losing the information needed to reach its answer, and which revision should become the training target? A fixed number of compression passes treats every trace alike. A final-answer accuracy check can reject wrong endpoints, but it does not explain how much intermediate reasoning to retain. MACC frames compression as a sequential path over successively rewritten rationales and chooses a stopping point adaptively.

For each mathematical task \(x\), the paper’s formal data object begins with an original Chain-of-Thought \(r_0\) generated by target model \(S\). An API compressor rewrites the preceding rationale once per round to produce \(r_1,\ldots,r_T\). Crucially, every compression request includes the question, the prior thought process, and the final answer; the revisions are therefore answer-conditioned artifacts, not answer-blind inference traces. The selector compares tokenized lengths only. If \(r_i\) is strictly longer than \(r_{i-1}\), Algorithm 1 stops and retains \(r_{i-1}\); equality does not stop the published pseudocode.

The intended training object is the selected full compressed rationale \(r^*\) joined with its final answer. Selected compressed traces and an undisclosed fraction of original traces are used for supervised fine-tuning, with `&lt;compress&gt;` marking concise-generation examples. The supported training use is **SFT only**. The paper does not provide evidence for preference learning, reward-model training, process supervision, RLVR, or a knowledge-distillation objective.

MACC belongs in **Rollout, Search, and Test-Time Trace Data** because an original rationale becomes a sequential revision path, the round budget and tokenization affect selection, and one rebound candidate is rejected when the path terminates. A reusable record would need the original trace, every revision, parent/round index, final-answer exposure, token counts, stop decision, selected round, and final SFT text. None of those record-level chains is released.

The official repository boundary is unusually important. At checked commit `2046df78636495de86e9c015820295b16f1f63fd`, the current tree contains only `README.md`; its full history contains no runnable implementation, requirements file, configuration, prompts as files, generated corpus, model artifact, evaluation harness, or license text. The Card can document a verified paper recipe at L4, but it cannot treat the repository as code availability or the paper’s aggregate tables as a public dataset.
