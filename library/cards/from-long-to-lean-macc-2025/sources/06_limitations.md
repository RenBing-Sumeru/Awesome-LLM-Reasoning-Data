**Length is not validity.** The stopping predicate observes only whether the newest revision is longer than the previous one. A shorter rationale can omit a necessary premise, introduce a logical error, or merely paraphrase more tersely; a longer one can repair an error. No per-round answer checker, semantic-equivalence judge, process verifier, or faithfulness metric gates selection. PPL and benchmark accuracy are configuration aggregates, not per-record safeguards.

**Answer exposure changes the object.** Every compressor call receives the final answer. The selected rationale is therefore label-conditioned and cannot be audited as an answer-blind trace of how the target model originally solved the problem. It may rationalize the known endpoint, copy answer-dependent cues, or conceal a broken derivation. Downstream SFT accuracy does not reveal whether those behaviors occur in individual records.

**Published selector inconsistency.** Algorithm 1 says a strict rebound selects the preceding revision and equality continues. Appendix Table 6 nevertheless marks GPT-4o-mini round 8 in blue although it is visibly longer than rounds 4–7. Table 5 also marks selections even when later candidates are textually identical or nearly identical. Without exact token counts, tokenizer revision, selected-round fields, and stop logs, the appendix labels cannot be reconstructed or reconciled with the pseudocode.

**No implementation or generated corpus.** The official repository at the checked commit contains only `README.md`. It has no code, `requirements.txt`, prompts as files, configs, model/API pins, data, schema, counts, splits, checkpoints, training records, or evaluation harness. Original \(r_0\), all intermediate \(r_i\), the discarded rebound, selected \(r^*\), and final SFT examples are absent. The conceptual Algorithm 1 output \((x,r^*)\) is not a machine-readable release.

**Unknown budget and model drift.** Maximum construction round \(T\) is undisclosed, while different figures and tables use ranges 2–10, 2–5, 0–5, and 0–8. Temperature, top-p/top-k, seeds, timeouts, retries, per-call caps, input/output tokens, latency, cost, failures, and API snapshots are unknown. External providers can change model behavior; unpinned compressors and tokenizers can change revision text, token lengths, rebound points, and the selected corpus. The reported 16,384 maximum inference/training length does not establish the compression-call budget.

**Source, split, and lineage ambiguity.** Exact GSM8K/MATH/MATH-500/AIME24 construction rows and upstream versions are unavailable. Formal Section 3.2 assigns \(r_0\) to target model \(S\), but compressor-dependent original lengths and “Compressor Origin Length” leave operational authorship unresolved. The generated-data split, prompt count, mixture ratio of original versus selected traces, exclusions, transformation hashes, and record-level train/evaluation mapping are unknown.

**Estimator leakage risk.** The performance estimator uses only \(n=20\) configuration rows per target model with 5-fold cross-validation and an 80/20 procedure. The paper does not report grouping related rounds from the same compressor, so neighboring configurations may occur across train and test folds. This is an audit risk, not evidence that leakage occurred; unavailable code prevents resolution.

**Contamination and rights.** No prompt deduplication, train-test overlap, semantic decontamination, answer-template leakage, or family-level split audit is disclosed. The ACL paper is CC BY 4.0, but that does not license code or generated data. The repository README’s MIT badge points to a nonexistent `LICENSE`; implementation and generated-corpus licenses remain `unknown`, as do upstream benchmark and API-output redistribution rights.

**Generalization and attribution.** The study covers mathematical reasoning and depends on external compressors, creating model-specific bias, preprocessing latency, and resource costs noted by the authors. Task-agnostic prompts and limited estimator features may not transfer to other domains. Benchmark gains mix trace selection, answer access, extra API preprocessing, compressor strength, original-trace mixture, and SFT; they cannot by themselves attribute improvement to higher-quality compressed data.
