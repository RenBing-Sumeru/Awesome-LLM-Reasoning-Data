Gold contract 包含人为政策。等价公式、格式偏差、舍入、多个答案的部分覆盖，或先错后改是否算正确，取决于题目和标注规则。论文指出人类与模型的惩罚阈值存在分歧，却未披露标注者人数、分工、一致性或不可变的裁决日志。相关模型裁判之间的共识也可能在人工审核前保留相关错误。

Benchmark 具有有意的选择性。证明型、开放式、参考答案不完整和数值容差含糊的问题会被过滤。字符串去重主要删除 Invalid 回答，相似度过滤减少 Incorrect 回答，因此最终 1,092/1,526/199 的标签分布是构造出来的，不是自然分布。二分类打分和 RL 会合并 Incorrect 与 Invalid，丢失该 benchmark 引入的诊断差异，并可能在题目或参考答案本身有缺陷时错误地提供策略奖励。

构建说明存在未解决的版本与数量边界。论文一处提到超过 30 个 meta error pattern，另一处提到超过 40 个高影响类别，附录又列出 34 个合成模板，但没有发布统一的条目级映射。附录 A.8 正文称错误驱动样本为 224,294 条，表 13 则为 24,294 条；只有后者与 54,420 和 18,118 相加得到总数 96,832。本卡将 224,294 视为未解决的疑似笔误，而不是第二个语料规模。

发布完整性仍为 partial。Hugging Face 提供 2,817 条测试 split 和三个检查点，但没有 96,832 条训练样本、投票、理由、过滤决策、被拒记录、合成提示或条目级谱系。在核验的 commit `2d7cba6df0b21f9c6121786ac1e5770c68473598` 中，GitHub 仓库只包含推理提示和评测 notebook，没有构建、训练或 GRPO 代码，也没有 license 文件，尽管 README 使用了 Apache 2.0 徽章。数据集和模型页面声明了许可证，但 16 个上游 benchmark 与生成输出的继承权利没有审计。论文也未报告语义去污染、外部重叠分析、置信区间或独立复现。
