Outcome verification sits between an unstructured model response and a reference answer. Regex and symbolic matchers are cheap but task-specific and brittle; general LLM judges handle more formats but require prompt tuning and can hallucinate. The paper argues that the field lacks both a difficult cross-domain benchmark for this decision and a small verifier trained for formulas, multi-part answers, sequences, and abnormal responses.

CompassVerifier addresses this as a data-construction problem. OpenCompass collects more than 1,325,293 question–reference–response triples from 53 model variants across 16 named benchmarks. Staged voting, filtering, and expert adjudication create a 2,817-row test benchmark, while consensus examples and targeted synthesis form a reported 96,832-example verifier-training corpus. The released row is an answer-level judgment object, not a process-correctness trace: question, gold answer, model response, source, domain, answer type, and A/Correct, B/Incorrect, or C/Invalid label.
