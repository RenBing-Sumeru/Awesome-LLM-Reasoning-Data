The framework accepts task-defined scalar rewards rather than imposing a universal verifier. AIR can optionally turn monitoring signals, such as a tool-call return status, into intermediate reward. In the paper demonstrations, text-to-SQL with Spider and calculator-assisted Calc-X math use final-answer correctness. The MuSiQue question-answering demonstration with a Wikipedia retriever uses 0.9 times word-level final-answer F1 plus 0.1 times format validity for tagged think/query/answer output. Those are three task-specific examples, not a framework-wide default reward, a reward dataset or proof that all future captured traces are programmatically verifiable. Execution completion is determined by the user task and agent runtime; a universal terminal schema and terminal-event ledger are unknown.
