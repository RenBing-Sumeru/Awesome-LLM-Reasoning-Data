DockSmith addresses a prerequisite that software-engineering agent datasets often hide: before an agent can repair code, the repository must be converted into an environment that builds, runs the intended tests, returns useful diagnostics, and supplies a trustworthy terminal signal. The canonical bibliographic source is the ICML 2026 final version on OpenReview; arXiv v2 supplies section and appendix locators but has a materially different author list. The paper is included in the Environment and Agent Trajectory Data track because its supervision comes from an interactive repository/Docker state-action-observation loop rather than from a static issue-answer pair.

The source pool begins with merged pull requests from GitHub repositories having at least 500 stars and 200 forks. The paper targets ten languages and more than 15,000 repositories, keeps substantive code changes with test-related modifications, and may use a language model to expand brief PR descriptions. Approximately 200,000 curated PR-derived instances exist before Docker rollout and verification. A human merge and test-related edit support task sourcing; they do not prove that a generated Dockerfile, evaluation script, or later trajectory succeeds.

One paper-level instance is a multi-turn environment-construction episode: repository and task context; actions by Context Retrieval, Dockerfile, Eval Script, and Test Analysis agents; Dockerfile/evaluation-script artifacts; shell, build, and test commands; execution logs and failure summaries; repairs; and a terminal build/test outcome. The public data object is narrower. It contains 39,719 per-agent chat fragments associated with 2,876 instance IDs, with message fields `role`, `content`, and `loss_mask` plus sidecar index fields such as `sample_id`, `instance_id`, `agent_type`, `source_file`, and `num_assistants`. These 39,719 fragments are not 39,719 complete episodes, and the exact count of full post-filter training episodes is unknown.

The source bodies are prepared at L4 content depth by connecting task source, environment interaction, execution feedback, success-only SFT selection, released fragment schema, reported evidence, and audit boundaries; canonical `curation_level` remains `L3_summary_ready` pending the human workflow. Downstream benchmark scores are not treated as proof that every fragment is correct, safe, licensed, or replayable.
