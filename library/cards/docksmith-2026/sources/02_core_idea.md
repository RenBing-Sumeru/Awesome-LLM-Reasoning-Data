The central contribution is to turn Docker environment construction itself into execution-grounded agent supervision: four specialized LLM agents iteratively retrieve repository context, write the Dockerfile, manage the evaluation script, analyze test failures, and repair their artifacts until the build-and-test contract succeeds or the run stops.

The agents operate over shared state consisting of repository/version and issue context, retrieved dependency, CI, build, and test information, current Dockerfile and evaluation-script artifacts, recent invocation traces, prior logs, and structured failure summaries. Actions include repository browsing, file edits, shell/build/test commands, diagnoses, and repairs. Docker execution returns observations for the next iteration. A loop controller watches recent agent combinations and failure signatures; after several rounds without improvement it forces diversification. A success memory retrieves previously validated `(Dockerfile, eval script)` pairs as cross-task demonstrations. The models, prompts, retrieval index, similarity rule, loop window, stagnation threshold, and intervention policy are not disclosed.

The feedback contract has two distinct parts. Training selection is programmatic and environment-grounded: only instances with successful Docker build and task-specific test execution enter the SFT curation stage. A representative appendix trace ends with `OMNIGRIL_EXIT_CODE=0` and `is_finish: true`, but no complete machine-readable predicate manifest is released for all tasks. Separately, GPT-5.1 labels error events by stage, code, and severity for the paper's analysis; those judgment-based labels are not described as training rewards. No scalar reward, preference pair, process-reward target, or RL objective is reported.

The closest referenced systems serve different roles. The Docker loop is derived from SWE-Factory, while Nex Agent-SFT supplies the general SWE/coding trajectories used in mixed-training experiments. DockSmith's distinctive object is the environment-building interaction and its execution-selected SFT representation. Compared with a static PR or issue-patch record, it preserves actions and observations; compared with a replay-complete episode release, it falls short because public rows are per-agent fragments and omit an immutable episode/environment manifest.
