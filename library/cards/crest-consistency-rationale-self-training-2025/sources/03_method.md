Prompt sourcing keeps the datasets separate. Table 5 reports train/validation/test counts of 4,638/500/1,000 for ReClor, 3,370/869/1,172 for ARC, and 8,520/1,221/1,221 for CommonsenseQA. Because the official CommonsenseQA test is not used directly, the paper uses its development split as test and removes an equally sized validation subset from training. The repository publishes these prepared files, few-shot examples and templates, but not generated CREST outputs.

For each training item, Meta-Llama-3-8B, Gemma-7B or, in Appendix A, Phi-2 samples 16 rationales with temperature 0.8, top-p 0.95 and a 512-token output budget. The released generator builds its prompt from the first 20 records in the selected dataset-specific few-shot file by default; the paper does not separately report that count. A second greedy pass conditions on each rationale and predicts the original option. Dataset labels split the candidates into `z=1` and `z=0`. The released code then unfolds each `z=1` candidate into one prompt per answer option, greedily predicts whether that option is correct, parses the text, and sums matches into `z_tilde`.

The paper's candidate counts follow directly from 16 attempts per train item: 74,208 for ReClor, 53,920 for ARC and 136,320 for CommonsenseQA per base model. Follow-up volume is lower and run-dependent because only `z=1` candidates are unfolded and because `F` varies. Table 6 publishes aggregate counts by `z` and `z_tilde`, but neither the paper nor repository publishes the corresponding records, option-level prediction vectors or rejection decisions.

SFT writes the rationale plus labeled answer as the completion and computes loss only on that output span. LoRA uses rank 16, alpha 16 and gate/down/up/q/k/v/o projections. The paper reports six SFT epochs, while the released stage-2 script defaults to four; its threshold is written as `F-t`, with the ReClor example using threshold 1, equivalent to `t=3` for four options. Validation selects the best checkpoint without early stopping.

Preference construction enumerates within-question `P_z` and strict `P_z_tilde` pairs, then formats each as a prompt plus chosen and rejected rationale-answer completions. TRL DPO starts from the SFT adapter, uses `beta=0.1`, trains four epochs, and samples `(1-lambda)` of each batch budget from `P_z` and `lambda` from `P_z_tilde`. The paper searches 3,000 or 5,000 maximum steps and reports 5,000 for its best Llama/ReClor run; the public stage-3 script defaults to 3,000. The code seeds pair shuffling with 42, but rationale-generation seeds and the exact sampled pair ledger are unknown.

The feedback environment is entirely offline. Ground-truth option labels provide the reference, while the same base checkpoint produces the original and option-wise predictions. GPT-4o does not label training data; it evaluates 100 ReClor validation responses with FLASK in a separate analysis. For Llama-3-8B/ReClor on one RTX A6000, the reported costs are 12, 3.2, 7.4 and 19.2 GPU-hours for rationale generation, evaluation, SFT and preference learning.
