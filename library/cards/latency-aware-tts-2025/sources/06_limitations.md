Latency-optimal settings depend on accelerator memory bandwidth, batch size, model architecture, speculative-draft acceptance, serving stack, and network overhead; a configuration measured on one platform need not transfer. The method also uses majority voting for its parallel selection, so tasks requiring a stronger verifier may change the trade-off. Greedy search reduces configuration trials but does not guarantee a global optimum. Production use should include tail latency, queueing, energy, and monetary cost rather than treating one benchmark wall-clock measurement as the complete deployment objective.
