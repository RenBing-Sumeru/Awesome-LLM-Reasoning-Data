Most tool-use benchmarks reduce the problem to one prompt and one stateless function call. A dialogue agent instead accumulates obligations across turns: a user can provide an argument later, refer to an earlier result, change a constraint, require confirmation before a transaction, or ask for a response without another call. DialogTool asks whether a model can preserve and use that state across the complete tool lifecycle rather than succeed at isolated API selection.

The benchmark organizes this lifecycle into six tasks: tool creation; tool awareness; tool selection; tool execution; response generation; and role play. Its data object is a multi-turn dialogue trajectory whose state includes dialogue history, selected App/API, required and optional arguments, prior API outputs, transaction status, and a role configuration. At turn (t), the agent observes dialogue context and environment state, chooses a tool-related or non-tool action, optionally emits an API call, receives a deterministic VirtualMobile result and updated state, and generates the next response.

This is not a single end-to-end success benchmark. Creation is tested by executing generated functions; awareness, selection, and execution are scored against labels; response similarity uses lexical metrics; and role style uses a model judge with human validation. No official downloadable DialogTool/VirtualMobile artifact or complete evaluated rollout set was verified, so the paper defines a useful episode contract but does not supply a replay-ready trajectory corpus.
