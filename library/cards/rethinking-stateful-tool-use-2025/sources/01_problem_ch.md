多数工具使用基准把问题压缩为一次 prompt 和一次无状态函数调用。真实对话智能体却要跨轮积累约束：用户可能稍后补充参数、引用之前的结果、修改条件、在事务执行前要求确认，或直接询问旧结果而无需再次调用。DialogTool 关注的正是模型能否维持并利用这种状态，而非只在孤立样本中选对 API。

基准把工具全生命周期拆成六项任务：工具创建、工具感知、工具选择、工具执行、响应生成和角色扮演。其数据对象是多轮对话 trajectory；状态包含历史、App/API、必需和可选参数、既往 API 输出、事务状态与角色配置。在第 (t) 轮，智能体读取对话和环境状态，选择工具相关或非工具 action，必要时发出 API 调用，接收 VirtualMobile 的确定性结果与新状态，再生成回复。

它不是单一端到端成功基准：创建由可执行测试验证，感知/选择/执行与标签比较，响应使用 lexical metrics，角色风格由模型 judge 并经人工验证。没有核实到官方可下载的 DialogTool/VirtualMobile 或完整模型 rollout，因此论文定义了有价值的 episode 合同，却没有提供可直接 replay 的轨迹语料。
