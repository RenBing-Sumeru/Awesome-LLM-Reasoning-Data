**Construction.** The authors select SGD and MultiWOZ for natural multi-turn tool invocation and detailed domain/intent/slot annotations. A Python “setting shift” converts all annotations except utterances into action/App/API/argument labels. Fifty manually collected movie/TV role configurations—name, gender, MBTI, language, emotion, and interaction attributes—condition rewrites of system utterances; user utterances remain unchanged. The rewriting model and acceptance procedure are unknown.

**Environment.** Authors manually implement every App/API in Python and attach natural-language schemas. Unique source lookup outputs become deterministic databases; the stated correctness criterion is that the same dialogue input returns the same output. State attributes track Apps, APIs, and previous results. The paper does not publish reset, serialization, transaction rollback, concurrency, or environment-version procedures.

**Scale and split.** Table 2 reports 16,142 training dialogues, 329,964 turns, and 85,191 calls across 20 Apps/45 APIs; evaluation has 900 dialogues, 15,568 turns, and 4,274 calls across 15 Apps/30 APIs. Training/evaluation contain 10,739/360 multi-App dialogues and 50/16 roles. The derivation and overlap controls are undisclosed. The prose says “approximately 33k turns,” conflicting with the table's 329,964 training turns.

**Evaluation.** Tool creation provides full schemas and one demonstration, then runs generated Python against all test calls: 32 APIs need creation, with 363 average and 93 minimum test cases. Awareness predicts an action; selection predicts App/API; execution also fills/formats arguments; response and role tasks generate text. Thirteen models run at temperature and top-p 0.1. No reflection scaffold, token/tool budget, seed, retry policy, full rollout retention, or end-to-end terminal success predicate is reported.
