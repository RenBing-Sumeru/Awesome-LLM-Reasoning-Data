DialogTool's contribution is to connect the traditional task-oriented dialogue state machine with the full tool lifecycle. Rather than evaluating only whether a model names the right API, it separates when to use a tool, which App/API to select, whether all arguments are recoverable from history and correctly formatted, how state changes after execution, how tool results enter a response, and whether response style remains role-consistent.

The App→API→argument hierarchy is operational as well as descriptive. It narrows the search space and mirrors how a mobile interface groups functions. The transactional flag and Confirm action also make tool use dependent on dialogue state rather than the latest utterance alone. VirtualMobile's deterministic stored outputs provide executable tests for generated Python tools and repeatable API results.

For Track 6, novelty lies in the layered supervision object: dialogue/action labels, schemas, arguments, environment transitions, outputs, responses, and heterogeneous verifiers. It is not a novelty claim about released trajectory volume: official data/code and evaluated rollouts were not verified, and the paper does not define a universal terminal reward across its six tasks.
