Use this paper when deciding whether a planning project needs a language model to write plans, to build a formal model, or both. It gives readers vocabulary for separating natural-language interpretation from formal planning and for identifying the handoff to an automated planner. It is especially valuable for projects where reliability depends on a planner checking a formal representation.

Use its framing to write a system specification before selecting tools: define what information enters in language, what formal object must be produced, which planner consumes it, and what outcome counts as success. This prevents an interface decision from being hidden inside a broad claim about planning. The cited literature then supplies concrete methods suitable for the chosen representation.
