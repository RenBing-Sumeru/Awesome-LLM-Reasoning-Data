Training questions come from HotpotQA and 2WikiMultihopQA. A main rollout records ordered reasoning/search/result segments and the terminal answer. After each search turn, OASES extracts the information state available at that point, prompts the same model to answer from that state alone, and scores the answer against the reference with EM/F1. Consecutive state-score deltas are assigned to the triggering search segments; the terminal outcome score is assigned to the final answer. Retrieved-result tokens are masked from policy loss. Each evaluation rollout receives its own terminal state-answer score. Search and evaluation records are combined, returns and GAE advantages are computed, and PPO updates shared actor/critic parameters with an additional format penalty.

The default model is Qwen2.5-7B-Instruct, implementation uses verl, and retrieval uses E5 over Wikipedia. Evaluation covers NQ, HotpotQA, 2WikiMultihopQA, Bamboogle, and MuSiQue. The paper reports one main rollout plus a variable number of prefix evaluations, with evaluation overhead decreasing during training. No author-attributed code/data link is confirmed in the Card. Exact dataset revisions, Wikipedia snapshot/index, retrieval cache, sampling parameters, full search/evaluation buffers, rejected formats, seeds, and per-record reward ledgers remain unknown.
