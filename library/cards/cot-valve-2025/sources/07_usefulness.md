For the rollout/search/test-time-trace track, CoT-Valve is useful as a long-to-short distillation case where several traces for one prompt share an intended answer but differ in budget. A reusable training record should retain the source question and license, base and reasoning checkpoint identifiers, interpolation or extrapolation coefficient, generation prompt and seed, every candidate trace, token count, extracted answer, correctness result and checker version, and whether the row was retained despite failure. This supports SFT, progressive compression, budget-conditioned evaluation, and audits of whether shorter traces omit essential steps. Builders should keep answer correctness, step validity, and token efficiency as separate fields rather than selecting the shortest correct-looking trace as an automatic quality label.
