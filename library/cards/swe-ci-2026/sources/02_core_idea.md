SWE-CI turns future tests into a closed CI feedback contract. The Architect compares target-test failures with the current repository, then writes at most 5 urgent, high-level requirements. The Programmer receives that document, plans the implementation, edits the current code, and returns it for pytest evaluation. Accepted repository state and test evidence flow into the next epoch, making the consequences of earlier design decisions observable over as many as 20 epochs.

The native verifier is executable rather than judgment-based. Passed-test counts are normalized against the base and target states; current summarization averages the sequence as EvoScore with gamma 1 and separately reports Resolved, Zero_regression, and ZRR. This is a scalar reward over state transitions, not an online learned reward delivered to the model. Runner completion is also not the semantic reward: an unresolved episode that reaches the epoch cap can complete without an orchestration exception while never passing every target test.
