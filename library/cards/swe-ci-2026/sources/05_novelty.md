The distinctive contribution is evaluation over an evolving repository state rather than a single issue-to-patch snapshot. A test gap is translated into an incremental requirement, the code is modified, and the resulting test state becomes the next problem. This exposes regression and accumulated technical debt that a terminal pass/fail score would hide. The public harness also preserves structured iteration records and timestamped states instead of returning only a final patch.

The release has become more useful than the original paper alone suggests. In addition to benchmark code, task archives, and Docker environments, an official 115 GB repository now claims to publish all raw experimental trajectories after light sanitization, organized across v1/v2, iFlow/OpenCode, and TDD/RDD settings. That makes process-level audit possible, but the release still lacks a machine-readable coverage and success manifest. The novelty is therefore both the CI data object and the explicit separation between task packages, executable feedback, state trajectories, and aggregate metrics.
