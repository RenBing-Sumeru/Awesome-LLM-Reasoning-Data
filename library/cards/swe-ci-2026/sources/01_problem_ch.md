SWE-CI 于 2026 年以 arXiv 预印本形式发布，它提出了不同于一次性 issue 修复的问题：当需求沿长期代码演化序列持续到来时，智能体能否让仓库保持功能正确？论文基准包含来自 68 个公开 Python 仓库的 100 个任务。每个任务将一个 base commit 与较晚的 target commit 配对，两者之间的真实历史平均跨越 233 天和 71 个连续提交。

因此，任务对象不只是一个 issue 和最终 patch。它包含两个仓库状态、target-test gap、打包源码树、预构建环境以及反复发生的 Architect–Programmer 交互。完整可用的数据记录还应包含需求文档、仓库快照、pytest 报告、剩余 gap、日志、终止状态和派生 reward。核心审计问题是：这些运行级对象是否都带有足够血缘被公开，而不只是发布任务包与汇总分数，从而能够区分智能体失败、harness 失败和真正成功的维护。
