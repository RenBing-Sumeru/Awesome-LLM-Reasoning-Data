SWE-CI, released as an arXiv preprint in 2026, asks a different question from one-shot issue repair: can an agent keep a repository functionally correct as requirements arrive over an extended code-evolution sequence? The paper's benchmark contains 100 tasks drawn from 68 public Python repositories. Each task pairs a base commit with a later target commit; the authentic history between them spans 233 days and 71 consecutive commits on average.

The task object is therefore not merely an issue and final patch. It includes two repository states, a target-test gap, a packaged source tree, a pre-built environment, and repeated Architect–Programmer interactions. A useful data record also includes requirement documents, repository snapshots, pytest reports, remaining gaps, logs, terminal state, and derived rewards. The central audit question is whether all of those run-level objects—not just task packages and headline scores—are released with enough lineage to distinguish agent failure, harness failure, and successful maintenance.
