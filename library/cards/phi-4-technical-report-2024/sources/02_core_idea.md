Phi-4's data strategy combines curriculum allocation with synthetic transformation. Organic web, academic, book, code, and Q&A material is filtered for educational or reasoning value. Some records enter the mixture directly; others become seeds for exercises, discussions, Q&A pairs, code instructions, or structured reasoning documents through multi-stage generation, rewriting, self-revision, and instruction reversal.

The 400B figure is the approximate unweighted size of about 50 synthetic source families, not the final training-token count. The released model card reports 9.8T training tokens and a 16K context window, but neither source publishes the final per-family weights, repetition counts, or unique-record inventory. The report's mixture search varies synthetic, web-rewrite, filtered-web, targeted-acquisition, organic, and code allocations through smaller ablations before transferring the chosen recipe to phi-4.

Post-training has three distinct supervision objects. SFT uses about 8B chat-formatted tokens from math, code, reasoning, conversation, model-identity, safety, and 40-language multilingual data; multiple responses are generated and an LLM-based evaluator selects the best. First-round DPO uses Pivotal Token Search to estimate how individual token choices change oracle-checked completion success and constructs token-local preference pairs. Second-round DPO forms full-response pairs from GPT-4o, GPT-4t, and phi-4 generations, then uses GPT-4o to score accuracy, style, and detail.

The feedback contract is therefore mixed, not a single quality label. Code tests and mathematical answer comparison are programmatic outcome checks for some Pivotal Token Search tasks. GPT-4o is a judgment-based pair selector in the second round. The SFT evaluator is described only at role level. No released record carries the generator, score, oracle result, acceptance decision, or final stage membership.
