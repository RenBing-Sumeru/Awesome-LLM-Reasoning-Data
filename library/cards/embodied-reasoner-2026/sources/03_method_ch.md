可重建的流水线包含三个数据阶段：

1. **构造任务与教师轨迹。** 从 search、manipulate、transport 和 composite 四类任务出发，覆盖十个训练子任务。利用模拟器元数据和 GPT-4o 生成的约束检查选择有效对象/容器组合，再把实例化模板改写为多样指令，并按需组合简单任务。对象隶属图给出最小有序关键动作序列，也可插入额外搜索动作。随后在 AI2-THOR 中执行动作并捕获观察。GPT-4o 接收此前交互以及已经选定的下一动作，生成五类思考中的一种或多种。用得到的 1,128 条轨迹微调 Qwen2-VL-7B-Instruct，形成 Embodied-Interactor。
2. **收集经环境筛选的探索。** Embodied-Interactor 在新任务上跨多轮进行多次高温采样。数据引擎充当过程/终态验证器：所有关键动作必须按序出现，且最终模拟器状态满足任务；额外探索动作不会自动导致失败。最终保留的 6,246 条 episode 用于训练 Embodied-Explorer。候选总数、拒绝数、通过率、temperature、top-p、重试预算和随机种子均为 unknown。
3. **生成反思/纠正监督。** Embodied-Explorer 对先前任务再次 rollout。对于成功 episode，引擎注入导航或操作异常，并在重试前加入反思思考；对于失败 episode，则与合成关键动作比较，定位首个错误动作，追加 self-reflection 和纠正后续，并屏蔽错误的部分轨迹。第三阶段只在反思与纠正 token 上计算损失。两种来源共得到 2,016 条轨迹，但其混合比例、选择标准、异常分布和首错定位准确率均为 unknown。

三个阶段都采用多轮图文对话，并只在 assistant 的推理/动作 token 上计算学习损失。仓库公开了任务引擎、数据格式、定制 LLaMA-Factory 依赖和通用训练/评测脚本，但没有给出与论文逐阶段匹配的优化器、硬件、batch 调度、学习率、epoch、检查点映射和随机种子清单。
