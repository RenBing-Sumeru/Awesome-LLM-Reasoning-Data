The reconstructable pipeline has three data stages:

1. **Build tasks and teacher traces.** Start from search, manipulate, transport, and composite task families covering ten training subtasks. Use simulator metadata and GPT-4o-generated constraint checks to choose valid object/container combinations, then rewrite instantiated templates as varied instructions and combine simple tasks when needed. An object-affiliation graph yields a minimum ordered key-action sequence; extra search actions can be inserted. Execute the actions in AI2-THOR to capture observations. GPT-4o receives the preceding interaction plus the already selected next action and writes one or more of five thought types. Fine-tune Qwen2-VL-7B-Instruct on 1,128 resulting trajectories to obtain Embodied-Interactor.
2. **Collect environment-filtered exploration.** On new tasks, Embodied-Interactor samples multiple high-temperature trajectories across iterative rounds. The data engine functions as a process/terminal verifier: every key action must appear in order and the final simulator state must satisfy the task. Extra exploratory actions do not automatically fail an episode. The 6,246 accepted episodes train Embodied-Explorer; total candidates, rejects, pass rate, temperature, top-p, retry budget, and seeds are unknown.
3. **Create reflection/correction supervision.** Embodied-Explorer rolls out earlier tasks. For successful episodes, the engine injects navigation or manipulation anomalies and adds reflective reasoning before retry. For failures, it compares the rollout with synthesized key actions, locates the first incorrect action, appends self-reflection and a corrective continuation, and masks the erroneous partial trajectory. Stage-3 loss applies only to reflection and corrected tokens. The two sources yield 2,016 trajectories, but their mixture, selection criteria, anomaly distribution, and first-error accuracy are unknown.

All stages use multi-turn image-text dialogue with learning loss on assistant reasoning/action tokens. The repository exposes the task engine, dataset format, a custom LLaMA-Factory dependency, and generic train/evaluation scripts. It does not expose a paper-matching stage-by-stage manifest with exact optimizer, hardware, batch schedule, learning rate, epochs, checkpoint mapping, or random seeds.
