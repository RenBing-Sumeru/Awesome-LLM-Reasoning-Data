For ordinary math or code generation, increasing a token budget is a workable proxy for giving a model more test-time computation. That proxy breaks for an agent that calls search, execution, or training tools: a short response can wait a long time for a tool, while a longer response can finish earlier when feedback is fast. Policies that count tokens or tool calls but ignore latency cannot reliably decide whether to reason longer, interact again, or stop before a real deadline.

The paper asks how test-time scaling should be defined and optimized when the environmental cost is part of inference. The target is a policy that observes elapsed time and adapts both interaction frequency and per-round deliberation to a wall-clock budget. It must handle regimes in which model generation dominates, tool execution dominates, or neither is predictable in advance, rather than assuming a fixed conversion from tokens to time.
