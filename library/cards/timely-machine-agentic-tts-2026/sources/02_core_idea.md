Timely Machine replaces the usual token-length view of test time with wall-clock duration. The cost of an episode is the sum of model-generation and tool-execution time, so the same interaction count can have very different budgets under different tools. When feedback is fast, a smaller model can exploit its speed to obtain more rounds; when feedback is slow, the number of rounds is constrained by the tool and higher-quality actions from a larger model become more valuable.

The work operationalizes this idea through Timely-Eval and Timely-RL. Timely-Eval varies delays in text games, evaluates code-and-training interactions, and gives a timer tool to ordinary reasoning tasks. Timely-RL first cold-starts a model on timed traces and then rewards correct, timely completion together with useful budget utilization. It therefore trains an allocation policy over reasoning and interaction in physical time rather than an unconditional preference for more tokens.
