For Rollout, Search, and Test-Time Trace Data, ST-BoN is a useful counterexample to schemas that assume every selector is a reward model or every candidate is fully generated. A curated record should preserve the shared prompt and reference answer, N and sampling parameters, each prefix and stop reason, model and layer definitions, CoE feature values, per-step distances, buffer-window winners, final selection, continuation, latency, memory accounting, and task evaluator.

This separation supports fair comparisons between Full-BoN, self-consistency, reward-model BoN, and early truncation under matched budgets. It also lets auditors ask whether savings come from fewer decoded tokens, different N, a stronger model, or the selector. The current official release is useful for implementation study, but reuse as a trace dataset requires additional export and provenance work.
