PORTool 用有界分叉、共享前缀的探索替代独立 rollout。树节点包含策略生成的推理/工具调用步骤，以及执行后的响应或错误。子节点是在相同交互历史下产生的不同下一步候选，因此 sibling 比较控制了前缀，无需事后近似匹配“相同状态”。

全部 8 条轨迹在 21 工具环境中终止后，固定的 GPT-4o evaluator 将每条完整路径标为 true、false 或 unable_to_answer。每条路径独立判断 5 次并取多数票。后代结果按剩余长度折扣，再聚合为前缀一致的步骤重要度。一个有界的格式/执行组件奖励可解析调用和成功执行，但正确性主导的缩放保证它不能推翻终局结果信号。

优化混合了同一棵树的两种视角。轨迹相对 advantage 比较完整路径，提供粗粒度全局反馈；分叉相对 advantage 比较共享前缀的 sibling 步骤，在真实决策处分配局部信用。PORTool 并非只选择成功演示：成功与失败分支必须共存才能产生相对信用，但论文没有公开持久化保留政策，也没有发布这些树。
