SetUpAgent turns repository documentation and execution feedback into historically constrained install/test commands, allowing issue-resolving pull requests to become executable SWA-Bench and SWEE-Bench instances without per-repository manual setup.

Its mechanism has three author-defined phases. Command extraction reads repository text, CI/CD files, and referenced web pages; dependency resolution uses `uv` and excludes versions released after the issue date. Iterative testing runs the proposed commands in a clean Docker container, classifies installation, testing, or Python failures with an LLM, and revises commands for at most four iterations. Validation first uses an LLM success judgment, then requests per-test output, selects a parser, and accepts the setup when at least 95% of parsed tests pass (Paper §3.3 and Figures 1–4, pp. 2–4; Appendix B, pp. 13–20).

The feedback contract has two distinct layers. During construction, LLM judgments, process exit behavior, test parsing, and the 95% threshold decide whether an environment is usable; an instance is retained only when reference executions before and after the human fix succeed and at least one F2P test exists. During model evaluation, the inspected harness sets `resolved=true` only when every declared F2P and P2P test passes after the candidate patch. This contract observes patch application and declared test behavior, but it cannot prove semantic issue resolution outside the tests, detect all flaky or misparsed tests, or certify that a 95%-passing setup is fully correct.

The closest baseline is SWE-bench, which also evaluates repository patches with human tests but relies on a small manually configured repository set. The change is automated historical environment construction and expansion to applications and hundreds of repositories, not a new code-agent policy or a released trajectory schema. The direction signal is that an agent benchmark's environment generator, dependency cutoff, parser, test partitions, and terminal predicate are first-class evaluation data rather than incidental infrastructure.
