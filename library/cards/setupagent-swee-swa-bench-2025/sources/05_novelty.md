SWE-bench established the repository-level issue-resolution task and test-based patch evaluation, but its historically accurate environments required substantial manual effort and covered 12 selected repositories. Earlier automated benchmark generation could source issues or patches without fully solving historical dependency setup, test-command discovery, and heterogeneous result parsing at the same scale.

The specific change is to make environment reconstruction an automated, feedback-bearing pipeline: extract commands from multiple repository evidence sources, enforce issue-time dependency cutoffs with `uv`, repair commands from clean-container failures, validate with an LLM plus test parsing, reuse successful commands across nearby versions, and then derive F2P/P2P/P2F/F2F partitions from reference executions. This enables an application-focused benchmark and a broader repository benchmark without claiming a new agent-learning algorithm.

For reasoning-data research, the direction signal is the richer evaluation object. The issue text and reference patch are insufficient by themselves; the dependency date, setup commands, parser, Docker state, test partitions, and terminal predicate jointly determine the label. SWA-Bench also tests a distribution that differs from library-centric SWE-bench, while SWEE-Bench broadens the repository pool. These are evaluation-surface changes, not evidence that the released data is suitable for training.

What is not new includes GitHub issue/PR mining, Docker execution, LLM-based command suggestion, unit-test evaluation, SWE-bench's patch task, and F2P/P2P-style outcome checks. Much of the contribution is systems integration and scale. Before reuse, inspect the non-default harness branch, test-parser behavior, paper-to-Hub count drift, missing SetUpAgent generator code, mutable Docker tags, one-split release, dataset license, and lack of rejected setup records.
