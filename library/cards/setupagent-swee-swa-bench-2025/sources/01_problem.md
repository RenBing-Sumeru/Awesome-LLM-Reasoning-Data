The authoritative source is the ICML 2025 paper in PMLR volume 267, pages 61240–61265; the arXiv v1 record is used only where version differences are stated. The paper asks how to construct repository-level coding benchmarks beyond a small manually configured repository set when each issue must be replayed in a historically accurate dependency and test environment. SWE-bench's manual setup burden and concentration on 12 popular repositories motivate the problem (Paper §1, pp. 1–2; PMLR record).

The engineering gap is not task generation alone. A usable instance needs an executable pre-fix checkout, the correct historical dependencies, commands that run the intended tests, a reference code patch and test patch, and a parser that converts heterogeneous logs into test outcomes. SetUpAgent automates this environment layer, after which the authors construct SWA-Bench for Python applications and SWEE-Bench for a broader PyPI-oriented repository pool (Paper §§3–4, pp. 3–6).

This Card belongs to `environment_agent_trajectory_data` because the evaluation object couples a repository state to an executable Docker environment and a terminal success predicate. It does not document a released agent trajectory corpus: public rows contain tasks, patches, setup commands, test partitions, and environment references, but no action/observation stream, tool-call history, reasoning trace, or per-step reward.

One benchmark instance includes `repo`, `base_commit`, issue text and hints, human reference `patch` and `test_patch`, timestamps, PASS_TO_PASS/PASS_TO_FAIL/FAIL_TO_PASS/FAIL_TO_FAIL lists, install and test commands, parser/framework metadata, and a Docker image root. The Atlas value is therefore the explicit connection between task provenance, environment reconstruction, executable feedback, and release audit. The evidence is sufficient for a bilingual Card, while SetUpAgent source, immutable environment manifests, dataset license, and release-count reconciliation remain unknown.
