核心构造是把 Mathlib4 证明状态图中的可证明节点转换为监督式定理—证明记录。

| 契约要素 | 生成阶段对象 | 公开发布 |
|---|---|---|
| 任务/状态 | Lean 局部假设与目标 | 序列化证明状态字符串 |
| 动作 | 针对当前状态实例化的 tactic | 只出现在目标证明文本中 |
| 观察 | LeanDojo 返回错误、后继状态或 `ProofFinished` | 未保留 |
| 搜索结构 | 具有 tactic 标签边和前驱关系的有向图 | 未保留 |
| 成功信号 | 至多八个 tactic 内可达 `ProofFinished` | 只能从目标推断，无验证记录 |
| 选中目标 | tactic 数最少的路径，再按 tactic 字符串总长度打破平局 | 证明/tactic 字符串 |
| 失败 | 无效 tactic 与未成功的探索尝试 | 未保留 |
| 来源 | Mathlib4 种子定理、图、状态血缘与环境 | 逐行未保留 |

反馈契约是程序化且基于环境的。Lean 通过 LeanDojo 执行每个候选 tactic：错误会拒绝该转移，状态变化会扩展图，`ProofFinished` 提供终态成功信号。正确性不由人工评审或学习式奖励模型决定。这比文本匹配更强，但发布行没有附带执行结果、环境哈希或独立重放结果。

LeanNavigator 用标准化 tactic 模板缩小候选动作问题。变量替换为 `{var0}` 等占位符，假设替换为 `{hypothesis}`，无法识别的片段替换为 `{unknown}`。经对比学习训练的 GPTNeo-350M 把状态与有效模板映射到相近位置；FAISS 返回 100 个最近模板，再用作用域内符号填充，每个状态最多生成 200 个 tactic。

公开数据只适合监督式证明或 tactic 预测。它没有 rollout 组、奖励、拒绝候选、策略 log probability 或图级过程标签，不能据此声称支持 RLVR、奖励模型、偏好学习或过程监督。
