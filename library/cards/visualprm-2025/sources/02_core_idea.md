For an image I, question q, and a solution split into steps, VisualPRM400K assigns each prefix a Monte Carlo expected accuracy. From prefix s_1:i, an InternVL2.5-series model samples 16 completions. If k completions end with an answer accepted by the source-dependent checker, mc_i = k/16. The released value-based target is '+' when mc_i > 0 and '-' when mc_i = 0. This is an any-success rule: one accepted completion is enough to mark the current prefix positive.

The conceptual record contains the image, question, ordered steps, and mc_i values. For training, it is rendered as a multi-turn conversation. The first user turn includes the image, question, and first step; each later user turn introduces one additional step; the paired assistant output is the discrete quality token. VisualPRM is conditioned on the full available visual/problem context and preceding steps when predicting the current label.

At inference, a step score is the probability-weighted value of the discrete output tokens. The reported value-based model uses positive/negative outputs; the paper also studies an advantage variant with superior/equal/inferior targets derived from changes in mc_i. Step scores are aggregated by their mean unless another ablation is specified, producing a response-level value used to rank Best-of-N candidates.

The scorer is not the same as the construction verifier. Terminal answer checkers create the Monte Carlo targets; VisualPRM learns to imitate the resulting process labels; Best-of-N then uses the learned scores for selection. Errors or biases in the continuation generator and answer checker can therefore propagate into the learned reward even when the model later performs well on a benchmark.
