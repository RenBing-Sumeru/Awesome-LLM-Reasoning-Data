The authors evaluate multiple few-shot and agentic state-of-the-art methods on 161 problems, and all struggle on the terminal criterion requiring both a correct specification and a fully verified implementation, showing that ordinary code-generation ability does not saturate the benchmark. Every success requires both a proof of equivalence to the hidden specification and an implementation correctness proof accepted by Lean, preventing credit from incomplete finite tests. Detailed fields and evaluation code are public for replay. This supports rigor, but the dataset is small and Lean expressiveness and proof-search cost are entangled with programming ability.
