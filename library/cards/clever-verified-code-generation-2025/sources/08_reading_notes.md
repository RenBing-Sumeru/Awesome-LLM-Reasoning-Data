1. **One-sentence position:** CLEVER requires models to generate a correct formal specification and then a Lean implementation proved to satisfy it.
2. **Method takeaway:** Hidden specifications, equivalence proofs, implementation correctness theorems, and vacuity audits are central.
3. **Data takeaway:** It contains 161 manually curated tasks with signatures, docstrings, specifications, isomorphism proofs, implementations, and helper lemmas.
4. **Evidence anchor:** All state-of-the-art approaches struggle with full verification, and successes receive dual confirmation from Lean’s type checker.
5. **Reuse decision:** It suits strict vericoding, but failure sources must be separated and proof-search failure must not be equated with algorithmic error.
