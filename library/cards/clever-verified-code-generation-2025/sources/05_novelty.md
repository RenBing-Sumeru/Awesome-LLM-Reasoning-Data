APPS and HumanEval use tests for implementation checking, while formal datasets such as FVAPPS usually provide specifications and evaluate only implementation or proof completion. CLEVER hides the specification and first requires models to derive it from natural language and prove equivalence to ground truth before implementing code. Manual curation avoids LLM annotations and vacuous specifications. The novelty is not the first use of Lean for code verification but a natural-language–formal-specification–implementation–proof chain in which specification errors cannot be concealed by later hard-coding.
