Ordinary code generation uses finite tests that can be overfit through examples, hard-coded outputs, or specification ambiguity. Some formally verified code datasets provide specifications that leak implementation logic or rely on LLM-generated annotations and goals permitting vacuous proofs. A passing proof then does not show that a model correctly derived a specification from natural language and implemented it. The absence of a high-quality benchmark limits comparison of end-to-end verified code generation.

CLEVER manually curates 161 Lean problems with two stages: generate a formal specification equivalent to a held-out ground-truth specification from signatures, docstrings, and test information, then generate a Lean implementation provably satisfying that specification. Outputs are verified post hoc by Lean’s type checker rather than tests or an LLM judge.
