Parallel sampling improves reasoning accuracy but keeps many long traces alive even after some have become unpromising. Similarity pruning can discard distinct correct paths, and verbal confidence can be miscalibrated. More importantly, token reduction alone misses the serving bottleneck: concurrent long traces fill GPU KV cache, force preemption, and create waiting time that can dominate end-to-end latency.

The paper asks which traces should be stopped and when stopping produces a system-level benefit. It needs an early quality signal that is cheap enough to use during decoding, and a trigger aligned with actual resource pressure rather than a fixed token or confidence threshold. The desired policy frees memory before a poor trace causes other useful traces to queue, while retaining enough diversity for final answer selection.
