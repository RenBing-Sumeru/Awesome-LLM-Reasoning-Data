Prior work typically occupies one of three positions: prompt a capable model to search without training; perform SFT on selected web trajectories; or apply outcome-based RL to search behavior. WebDancer does not invent those components. Its concrete change is to connect task synthesis, two teacher styles, trajectory rejection sampling, observation-masked SFT, live-web rollouts, model-based terminal reward, and DAPO dynamic sampling in one reported agent pipeline.

The new data object is not merely a QA pair. A constructed question has an answer-preserving lineage, can yield several attempted ReAct trajectories, passes validity/correctness/quality filters, enters either SFT or RL, and during RL becomes a 16-execution group whose reward variance determines whether the prompt contributes an update. This makes selection state and environment feedback part of the effective training corpus.

The Short-CoT/Long-CoT split is also a useful direction signal. GPT-4o produces compact ReAct demonstrations, while QwQ-Plus supplies longer reasoning without receiving its previous thoughts on the next call. Table 3 shows that this teacher choice changes both success and invalid-output rates, exposing cross-model trace transfer as a data-design variable rather than a generic distillation benefit.

What is not new includes ReAct, GPT-4o/QwQ teachers, Qwen backbones, Qwen-Agents, web search and page summarization, SFT, DAPO, verl, LLM-as-judge, and the GAIA/WebWalkerQA benchmarks. The “end-to-end” claim describes their integration and training order; it does not establish a new deterministic environment or fully open release.

Before reuse, verify the full prompt lineage, correct interpretation of the action-count filter, exact SFT/RL split, judge prompt and snapshot, failed-sample retention, web-service versions, benchmark overlap, and dataset-specific rights. Without those checks, the work is most reliable as a construction and audit reference plus a small released-sample inspection point. (Paper §§1–3, Table 3, Appendices D–E.)
