Inputs are 60,000 CRAWLQA pairs, 40,000 E2HQA pairs, and a separate open-only mixture drawn from MuSiQue, Bamboogle, PopQA, 2Wiki, and HotpotQA after a simple RAG filter removes easy questions. CRAWLQA uses GPT-4o over recursively crawled web content. E2HQA repeatedly searches around an entity and rewrites the original question so the new subproblem must be solved before the unchanged concise answer can be recovered.

Trajectory generation runs in Qwen-Agents ReAct with search and visit. GPT-4o produces Short-CoT trajectories. QwQ-Plus produces Long-CoT thoughts and actions from historical actions and observations; prior thoughts are withheld from its next call, but current `reasoning_content` is retained as supervision. Each QA is sampled at most five times. The paper's multi-stage funnel discards malformed ReAct output, uses GPT-4o to keep correct answers, then applies repetition/hallucination rules and prompted criteria for information non-redundancy, goal alignment, logical reasoning, and accuracy. Appendix D additionally limits a repeated 10-gram to four occurrences. The prose about filtering trajectories “with more than two actions” conflicts with Table 4 mean action counts above two, so the exact threshold direction is not reconstructable.

The retained records are converted to multi-turn ChatML. Thought uses the `think` tag, JSON actions the `tool_call` tag, observations the `tool_response` tag, and the final response the `answer` tag. Table 4 reports 7,678 Short-CoT trajectories with mean action count 4.56 and mean thought length 510.03 tokens, plus 6,550 Long-CoT trajectories with mean action count 2.31 and mean thought length 1,599.39 tokens. SFT trains Qwen2.5-7B/32B on Short-CoT and QwQ-32B on Long-CoT while masking observation-token loss.

For RL, QA pairs not used by SFT seed live-web rollouts. DAPO samples 16 executions per question, optimizes only model-generated tokens, and dynamically excludes groups that are all correct or all wrong. Format validity is binary; answer correctness is a binary Qwen-72B-Instruct judgment; reward is `0.1 * score_format + 0.9 * score_answer`. Non-RL inference uses temperature 0.6 and top-p 0.95; RL rollouts use temperature 1.0 and top-p 1.0. The paper reports 32 nodes with eight H20 96GB GPUs per node and notes that only a small subset, for example 5,000 pairs, can be used in RL because of cost and stability.

Outputs are SFT policies and DAPO-refined web agents evaluated on GAIA and WebWalkerQA, with later analysis on BrowseComp. Public reproduction can inspect 200 QA samples, 200 cold-start trajectory samples, demo/inference code, and WebDancer-32B. It cannot reconstruct the complete training split, rejected examples, judge decisions, on-policy rewards, modified verl configuration, or historical web observations. Reproduction must therefore pin repository/model revisions, tool providers, search/page state, prompts, judge snapshot, dependencies, seeds, and episode budgets.
