1. Inputs: natural-language Android tasks, real-device interaction demonstrations, screenshots, accessibility or UI metadata where available, and low-level actions. 2. Pipeline: collect human demonstrations across task families; serialize each step into an observation and action record; normalize actions into types such as tap, swipe, text entry, navigation, or no-op; split the data into named benchmark subsets; provide scripts to download and convert the records. 3. Outputs: episodes, step-level action labels, screen observations, task instructions, and evaluation examples in the Google Research repository. 4. Feedback: an offline evaluator compares model-predicted actions with demonstration labels, including action type and parameter agreement. Reuse requires pinning the repository commit, GCS/data version, subset split, action-space conversion, tokenizer/text-entry normalization, screen resolution assumptions, and any model inference budget.
