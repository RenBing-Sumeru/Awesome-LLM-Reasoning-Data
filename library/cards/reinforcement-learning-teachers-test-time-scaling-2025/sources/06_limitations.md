The frozen reward student is both a strength and a coupling risk. Explanations can optimize Qwen2.5-7B-Instruct's token probabilities without being equally useful to another student. Solution likelihood and explanation KL do not verify each step, and access to the known answer permits post-hoc rationalization or answer leakage. The ablation shows that a poorly balanced reward can induce repetition and excessive length.

The release lacks the generated explanations, per-example component rewards, malformed or low-ranked outputs, discarded long candidates, exact 1,000-pair indices, teacher checkpoint, run seeds, and row-to-checkpoint lineage. The 7B and 32B Hugging Face models are explicitly distilled students. The mutable repository has no release tag; code should be pinned to an observed revision.

Evaluation uses downstream accuracy as a proxy for trace utility. It does not directly measure step validity, factual error, student-specific overfitting, or explanation faithfulness. Source-to-benchmark decontamination is unreported. Apache-2.0 covers the repository and declared upstream artifacts, but no separately licensed generated-trace release exists. Larger-student cropping and candidate reselection also change the data object in a way that cannot be audited without the missing candidate manifest.
