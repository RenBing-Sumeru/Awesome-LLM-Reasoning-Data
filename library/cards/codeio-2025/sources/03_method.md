1. **Collect and filter code.** Merge about 810.5K raw files from CodeMix, PythonEdu-R, and smaller algorithm, mathematics, and coding sources. CodeMix keeps medium-difficulty files; PythonEdu-R removes pure algorithms and non-reasoning code.
2. **Normalize functions.** DeepSeek-V2.5 extracts the main logic into an executable entry function, removes file/visualization side effects, specifies JSON-serializable inputs and outputs, writes a query, and creates a constrained input generator.
3. **Create I/O tasks.** Run each input generator, execute the function, and reject randomness, failures, timeouts, and overly complex objects. This leaves 454.9K functions and about 3.52M nearly balanced input-prediction and output-prediction instances.
4. **Write and check traces.** Prompt DeepSeek-V2.5 with the query, function, I/O specification, and one known side of the pair. Check output predictions against cached ground truth and input predictions by re-execution; the result can be success, mismatch, exception, no answer, or timeout.
5. **Build CODE I/O++.** If the first prediction is wrong, append the execution feedback and request one revision, then re-check it. Roughly 50% are initially correct and about 10% of the incorrect responses recover; both correct and incorrect final records are retained.
6. **Train in two stages.** Run one epoch of CODE I/O or CODE I/O++ SFT, then 700 steps on 1.18M general instruction samples. Evaluate the resulting Qwen, Llama, DeepSeek, and Gemma models across 14 reasoning measurements.

Reproduction must pin raw-source revisions, teacher version, transform prompts, Python environment, timeout/object limits, input-generator seeds, execution result, and public-subset revision. The paper does not disclose one complete generation-cost budget.
