1. **收集并筛选代码。** 从 CodeMix、PythonEdu-R 以及较小的算法、数学与在线编程来源合并约 810.5K 个原始文件。CodeMix 只保留中等难度文件，PythonEdu-R 删除纯算法和非推理代码。
2. **规范化函数。** DeepSeek-V2.5 把主要逻辑抽成可执行入口函数，删除文件读写与可视化副作用，声明可 JSON 序列化的输入输出，再编写自然语言问题和满足约束的输入生成器。
3. **构造 I/O 任务。** 运行输入生成器和目标函数，删除带随机性、无法执行、超时或对象过于复杂的样本，最终得到 454.9K 个函数与约 3.52M 条大致各占一半的输入预测和输出预测实例。
4. **生成并检查轨迹。** 把问题、函数、I/O 说明和已知一侧交给 DeepSeek-V2.5。输出预测与缓存真值匹配，输入预测则通过重新执行检查；结果可能是成功、不匹配、异常、无答案或超时。
5. **构造 CODE I/O++。** 首答错误时附加执行反馈并要求修订一次，再次执行检查。约 50% 样本首轮正确，错误首答中约 10% 能修正；最终无论正确与否都保留。
6. **两阶段训练。** 先对 CODE I/O 或 CODE I/O++ 训练一轮，再用 1.18M 条通用 instruction 样本训练 700 步，最后在 14 组推理测量上评估 Qwen、Llama、DeepSeek 与 Gemma backbone。

复现必须固定原始来源 revision、teacher 版本、转换 prompt、Python 环境、超时与对象复杂度限制、输入生成器随机种子、每次执行结果和公开子集 revision。论文没有披露完整的生成成本预算。
