# Evidence

**Claim 1:** interpolation records improve a fixed consumer beyond seed traces alone. **Controlled setup:** Table 4 fine-tunes CodeLlama-34B with the same recipe on either 49k GSM8K/MATH LCE records or the full 80k mixture including 31k interpolated problems. **Result:** the five-task average rises from 66.2 to 70.2; GSM8K moves 77.3 to 81.7, MATH 44.0 to 45.2, and out-of-domain SVAMP/Mathematics/SimulEq all improve. **Boundary:** the full mixture changes both record count and problem distribution, so the comparison does not isolate interpolation quality from scale.

**Claim 2:** actual execution, not predicted execution text, carries the decisive feedback. **Controlled setup:** Table 5 uses CodeLlama-34B and the 80k mixture; a model trained with execution-result loss averages 35.1 when it predicts results itself and 69.1 when Python supplies them, while masking execution-result loss with live execution reaches 70.2. **Result:** live execution adds 34.0 average points over predicted results, whereas masking result loss changes 69.1 to 70.2. **Boundary:** this supports the runtime feedback contract, not correctness of every training trace or safety of arbitrary code execution.
