The paper describes a three-stage construction pipeline followed by two task-oriented training views.

1. Static analysis extracts a functional schema for each target website, including domain semantics, available interactions, and logical dependencies such as sort, filter, and conditional constraints. An unnamed LLM conditions on that schema to synthesize simple information-retrieval, multi-constraint navigation, or conditional-dependency tasks. The paper does not disclose the generator model, prompt, temperature, seed, retry policy, or task rejection counts.
2. Human annotators execute the synthesized tasks on live sites through WebChain Builder. For each action, the logger records complete pre- and post-action DOM snapshots, the action type and arguments, viewport coordinates, target bounding box, XPath, CSS selector, target text, and timestamp. The corpus also carries viewport screenshots, available full-page screenshots, and Accessibility tree snapshots. Recruitment, compensation, annotator training, agreement, and per-trajectory adjudication are unknown.
3. Contextual enrichment parses all interactive elements in the viewport, not only the selected target, to create dense grounding alternatives and negatives. An unnamed VLM receives the task, prior state/action history, and current GUI state to produce an action-level Chain-of-Thought-style rationale. Because the rationale is synthesized after the action, it is not evidence of the annotator's original reasoning; the model, prompt, sampling, and acceptance procedure are undisclosed.

The official release organizes these objects into raw JSON/image archives and processed Parquet files. `processed/high_parquet` targets long-horizon planning using the task, history, and current page image; `processed/low_parquet` targets local grounding and action localization. The repository warns that raw folders need custom parsers and that the release is not one standardized Hugging Face schema. It also states that full-page screenshot coverage is not exhaustive.

Feedback differs by stage. Collection retains trajectories described as human-verified, but the inspected artifacts do not expose a domain-general executable completion predicate or per-trajectory decision log. In training experiments, a scalar step reward combines action-type agreement with action-content agreement: a click matches when its coordinate lies inside the reference target box, while typed text matches when the prediction lexically covers the reference text. This contract measures agreement with recorded behavior; it does not independently query the live environment to prove final task success.

The training scaffold first develops spatial grounding and planning capabilities separately, then applies Long-Chain-oriented RLVR. The paper uses Qwen2.5-VL-3B and Qwen2.5-VL-7B in reported experiments. Exact software versions and a complete runnable training manifest were not found in the author-linked GitHub repository, which contained only documentation and two images when checked.
