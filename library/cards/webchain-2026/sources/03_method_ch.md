论文给出三阶段构造流程，之后再形成面向两类任务的训练视图。

1. 静态分析先提取目标网站的功能 schema，包括 domain 语义、可用交互，以及排序、筛选和条件约束等逻辑依赖。一个未具名 LLM 以此为条件，合成简单信息检索、多约束导航或条件依赖任务。论文没有披露生成模型、prompt、temperature、seed、重试策略和任务拒绝数量。
2. 人类标注者通过 WebChain Builder 在真实网站上执行合成任务。每次动作都会记录完整的动作前后 DOM、动作类型与参数、视口坐标、目标 bounding box、XPath、CSS selector、目标文本和时间戳；语料还带有视口截图、可用时的全页面截图与 Accessibility tree。标注者招募、报酬、培训、一致性和逐轨迹裁决仍为 unknown。
3. 上下文增强会解析视口中的全部可交互元素，而不只记录被点击的目标，以构造密集 grounding 候选与负例。另一个未具名 VLM 接收任务、此前状态/动作历史和当前 GUI 状态，生成动作级 Chain-of-Thought 风格解释。由于解释是在动作之后合成的，它不能证明标注者当时的真实推理；所用模型、prompt、采样与接受规则均未披露。

官方发布物将这些对象组织为原始 JSON/图片归档和加工后的 Parquet。`processed/high_parquet` 使用任务、历史与当前页面图像面向长程规划，`processed/low_parquet` 面向局部 grounding 与动作定位。仓库明确提示原始目录需要自定义解析器，全部文件并不共享一套标准 Hugging Face schema，而且全页面截图不完整。

不同阶段的反馈含义不同。采集结果被称为“人工核验”，但已检查的材料没有给出跨 domain 的可执行完成谓词或逐轨迹判定日志。训练实验中的标量 step reward 同时考察动作类型与动作内容：点击坐标落入参考目标框即匹配，预测输入文本在词汇上覆盖参考文本即匹配。这一契约衡量的是与记录行为的一致性，并不会独立查询真实环境来证明任务最终完成。

训练 scaffold 先分别建立空间 grounding 与规划能力，再执行 Long-Chain-oriented RLVR。论文实验采用 Qwen2.5-VL-3B 和 Qwen2.5-VL-7B；但作者链接的 GitHub 仓库在检查时只有说明文档和两张图片，没有精确软件版本或完整可运行训练 manifest。
