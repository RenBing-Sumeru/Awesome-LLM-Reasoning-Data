For the Data Construction and Open Release Recipes track, the paper is a compact map of where a math-data pipeline can intervene: source selection, OCR cleanup, educational rewriting, teacher distillation, failure-guided retrieval, generation, consistency filtering, LLM judging, deduplication, and mixture evaluation. Its negative results are particularly useful for avoiding automatic assumptions that more tokens, longer traces, or rule-generated complexity imply better training records.

Builders can adapt the 80/20 design as a first screening experiment, but should hold total tokens, optimizer steps, model checkpoint, sampling exposure, and evaluation protocol constant; repeat runs; report confidence intervals; and include cross-domain regressions rather than only a target benchmark. A factorial ablation is needed to separate teacher strength, format, filtering, and volume. Benchmark items used for error-guided generation should be isolated from final evaluation.

A reusable release should include stable source and record IDs, book pages and rights, OCR versions, prompts and model revisions, decoding and seed, raw and rewritten pairs, answer groups, filter decisions, rejected samples, retrieval indices and ranks, MinHash parameters, mixture membership, training schedules, checkpoints, and split/decontamination reports. Until those exist, the work is a recipe-comparison report, not a directly reusable data release.

Reuse class: suitable now as a reading and audit reference and as a blueprint for independently implemented controls. Direct training reuse is blocked because the constructed corpora and baseline mixture are unavailable; reproducing the reported rankings is also blocked by missing code, run configurations, seeds, and checkpoint-to-table mapping.
