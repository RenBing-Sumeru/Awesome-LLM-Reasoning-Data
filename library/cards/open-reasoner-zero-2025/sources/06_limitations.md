- **“Zero” can be overstated.** The main RL stage skips SFT and distillation, but Qwen2.5 Base already embodies pretraining data and the RL pipeline consumes curated prompt/reference pairs. Humans design the template, filters, checker, optimizer, and benchmarks.
- **The training object is not released.** Missing artifacts include complete successful and failed responses, 64-way groups, hard-mining attempts, terminal rewards, stop/truncation states, critic values, advantages, policy log probabilities, PPO ratios, failed GRPO trajectories, and immutable logs.
- **Public row counts overstate unique prompts.** Exact duplicate rows number 2,503/56,878 in original, 24,025/72,444 in extended, and 611/13,451 in hard after whitespace normalization. No duplicate-group or weighting rationale is supplied.
- **Source and rights lineage is absent.** Rows lack upstream dataset/record IDs, transformations, licenses, attribution requirements, privacy/consent fields, and curation decisions. Package-level MIT metadata does not prove compatibility with every competition, dataset, or AoPS source term.
- **The overlap signal is unresolved.** Six exact MATH500 prompts occur in the extended release, but none in the configured original 57k file. Missing 129k/annealing run manifests prevent deciding whether they entered reported checkpoints; the finding is a release warning, not a contamination verdict.
- **Verifier prose and code differ.** The paper calls the reward exact matching, while code requires boxed-answer parsing, normalization, and mathematical-equivalence logic. Parser failures and equivalence false positives/negatives are not systematically reported.
- **Terminal correctness is not process correctness.** Every response token inherits the same final outcome. The critic predicts expected terminal reward and may learn surface regularities; it does not verify intermediate mathematical steps.
- **Configuration and node topology drift.** Released configs point only to 57k, not the complete 129k/hard-annealing or mixed-domain recipe. README says 16 nodes for 32B, while a config declares 32 training nodes per group. Exact topology, GPU-hours, wall time, energy, and failed-run compute are unknown.
- **No immutable paper release exists.** The audit pins a default-branch commit, but the repository has no tag, GitHub Release, exact dependency lock, seeds, checkpoint hashes, or run-to-log manifest.
- **Hard mining can amplify verifier blind spots.** Selecting fewer than four successes among 64 attempts targets empirical difficulty under one policy/checker, not semantic importance. The 64 attempts and selection decisions are unavailable for audit.
- **Reported failures are not reusable.** GRPO repetition/truncation collapse and English-plus-Chinese instability are described, but their response streams, filtered examples, labels, and checkpoints are missing.
- **Benchmark results are not release-quality proof.** Scores cannot certify deduplication, decontamination, licensing, reward robustness, rollout lineage, or independent reproducibility. “One tenth of the steps” is also not compute-normalized.
