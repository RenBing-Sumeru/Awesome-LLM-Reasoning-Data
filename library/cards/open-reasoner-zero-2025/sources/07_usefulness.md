For the **Data Construction & Open Release Recipes** track, ORZ is useful as a base-model RLVR blueprint, critic-analysis target, and release-disclosure benchmark.

1. **Reproduce the minimal PPO contract.** Pin the audited code SHA, original 57k file, base policy/critic checkpoints, prompt template, checker, 64-way sampling, \(\gamma=\lambda=1\), clipping, optimizer settings, and effective zero KL/entropy contributions before changing one component at a time.
2. **Build a trajectory ledger.** For every prompt group, persist all 64 responses, token IDs, stop reasons, extracted answers, verifier outputs, terminal rewards, critic values, advantages, policy probabilities, training step, checkpoint hashes, and rejection causes.
3. **Audit the checker.** Stratify parse failures, missing boxes, equivalent forms, units, intervals, sets, matrices, symbolic identities, multiple answers, and malformed tags. Compare paper-style raw matching, released normalization/equivalence, and an independent verifier.
4. **Deduplicate and preserve weighting.** Assign normalized prompt hashes and upstream record IDs. Report both row-weighted and unique-prompt-weighted training statistics so the 24,025 duplicate rows in the extended file do not silently change the curriculum.
5. **Resolve contamination before evaluation.** Quarantine the six exact MATH500 overlaps, reconstruct the actual 129k/annealing row manifest, and add semantic checks against every benchmark. Do not infer checkpoint contamination from release overlap alone.
6. **Audit critic behavior.** Test whether value estimates track mathematical progress, formatting, length, repetition, or benchmark identity. A lower value for repetitive prefixes does not by itself demonstrate reasoning-step understanding.
7. **Publish failure and curriculum records.** Release the hard-mining 64-way attempts, GRPO collapse trajectories, English/Chinese ablation labels, filtered rows, logs, and checkpoint mappings so failures can become reusable audit data.
8. **Complete provenance and rights.** Add per-row source, source revision, transformations, license, attribution, consent/privacy fields, and duplicate groups; keep package code/model licensing separate from upstream data rights.

Reuse classification: strong recipe and implementation reference; conditionally reusable prompt data and checkpoints after deduplication, provenance, license, and overlap review. It is not a fixed paper-run rollout corpus and does not support direct process-supervision or reward-model replay without regenerating and recording the missing online objects.
