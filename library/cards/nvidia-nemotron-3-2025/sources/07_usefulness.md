This report is useful for auditing the phrase "open model" at multiple layers. Readers can separately record released weights, public software, open-subset reference recipes, released data, gated data, private data, and unresolved redistribution rights. It also provides a concrete example of how a multi-environment RL claim should be decomposed into task families, environment versions, terminal predicates, rewards, rollouts, and calibration.

For reproducibility work, the open recipes are valuable reference implementations, but they should be evaluated as open-subset methods rather than as the complete production recipe. A full audit would require immutable source manifests, source-to-model allocation, data licenses and gates, environment and benchmark revisions, rollout and rejection logs, reward definitions, calibration results, and a documented overlap protocol.
