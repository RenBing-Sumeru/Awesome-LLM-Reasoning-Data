First, labels in CodeCriticBench still depend on references, tests, humans, or model judges, so omissions and bias become reward blind spots. Second, although the release contains more than ten thousand code-generation and code-QA critique cases, coverage of tasks, languages, model sources, and hard cases remains limited, and public release creates contamination risk. Third, offline scores do not automatically translate into RL, search, or deployment gains. Reuse should audit problem-level deduplication, agreement, false positives, unseen-model generalization, licensing, and category-level results.
