Closest prior work usually uses general preference pairs, final-answer correctness, or one holistic score without data specifically designed for the key failures and usage conditions of code critique. This paper changes the feedback object and evaluation contract by centering CodeCriticBench and placing task input, candidate response, and auditable evidence in one record, with labels produced through execution tests, reference comparison, and human multidimensional annotation. The contribution is the combination of dataset construction, fine-grained organization, and practical use rather than merely another model or pairwise format.
