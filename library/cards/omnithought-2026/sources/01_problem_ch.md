OmniThought 以 ACL 2026 长文发表，处理的是一个仅靠最终答案过滤无法解决的数据选择问题：多条思维链可能得到被接收的答案，却在逻辑有效性、不必要的冗长、方法难度、教师风格以及与特定学生模型的适配性上不同。该工作试图构建一个大规模、跨领域、多教师的轨迹池，并把这些差异显式化，以支持后训练选择。

公开对象采用嵌套结构。一个外层行包含 `question`；其 `reasoning` 列表包含多条候选记录，字段包括推理轨迹、最终解答、完整回答、教师身份、推理有效性布尔值，以及 Reasoning Verbosity（RV）和 Cognitive Difficulty（CD）评分对象。在固定 revision `274ec6417efb435421fb222319d1bb47291ea69b` 上，官方 README 元数据声明单一 `train` split 有 708,009 行。论文报告嵌套 CoT 超过两百万条，并称每个保留问题至少有两条被接收候选；但本卡没有从 24.2 GB 完整下载中独立计算精确嵌套总数。

判定边界非常重要。最终解答有效性决定是否保留，而逻辑过程有效性另行存储；因此，即使推理判断为负，只要答案正确，轨迹仍可能被保留。RV/CD 是依赖 judge 的整轨元数据，不是正确性证明或步骤标签。代码候选使用执行测试，数学和科学则结合规则检查与模型判断；相应的 runner、测试、答案规则和逐候选验证证据均未发布。

对本图谱而言，OmniThought 是数据构造与发布案例，而不是模型排行榜条目。它披露了来源族、嵌套数据对象、验证提示、评分定义、选择公式以及 SFT/DPO/GRPO 研究，同时仍缺少逐行题源、生成设置、可重放验证器、被拒候选和训练子集 lineage。
