Published as an ACL 2026 long paper, OmniThought addresses a data-selection problem that final-answer filtering alone cannot solve: multiple chains of thought can reach an accepted answer, yet differ in logical validity, unnecessary verbosity, method difficulty, teacher style, and suitability for a particular student model. The work asks how to build a large, multi-domain, multi-teacher trace pool and make those differences explicit enough for post-training selection.

The released object is nested. One outer row contains a `question`; its `reasoning` list contains multiple candidate records with the trace, final solution, full response, teacher identity, a reasoning-validity boolean, and Reasoning Verbosity (RV) and Cognitive Difficulty (CD) score objects. At pinned revision `274ec6417efb435421fb222319d1bb47291ea69b`, the official README metadata declares 708,009 rows in one `train` split. The paper reports more than two million nested CoTs and at least two accepted candidates per retained problem, but the exact nested total has not been independently counted from the full 24.2 GB download.

The decision boundary matters. Final-solution validity governs retention, while logical-process validity is stored separately; an answer-correct trace may remain even if the reasoning judgment is negative. RV/CD are holistic, judge-dependent metadata rather than correctness proofs or step labels. Code candidates use execution tests, whereas math and science use rule checks combined with model judgment. The corresponding runner, tests, answer rules, and per-candidate verifier evidence are not released.

For the atlas, OmniThought is a construction-and-release case rather than a model leaderboard entry. It exposes source families, a nested data object, validator prompts, score definitions, selection equations, and SFT/DPO/GRPO studies, while leaving row-level prompt provenance, generation settings, verifier replay, rejected candidates, and selected-subset lineage unresolved.
