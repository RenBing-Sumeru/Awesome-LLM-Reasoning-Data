The comparison is observational and heterogeneous. RepairAgent, AutoCodeRover, and OpenHands differ in architecture, backbone model, task suite, tools, terminal predicate, and iteration budget. Forty sampled runs per agent may miss rare behaviors, and the success-associated motifs do not establish causality. Only RepairAgent is tied to GPT-3.5 in this paper; the exact AutoCodeRover/OpenHands backbones and decoding settings are unknown.

Parsing and selection can distort the object. AutoCodeRover is parsed heuristically from semi-structured logs. Known tools are mapped automatically, remaining actions are manually inspected, and 8.3% of actions that fit no class are removed from subsequent action analysis. The exact random seed, sampling frame, and selection script for the 40 runs per agent are not disclosed, so another curator cannot reconstruct the same sample from the original evaluations.

Human annotation has unresolved reliability risk. Roughly 14,000 adjacent pairs were labeled through five months of first-author work plus joint discussion and partial agreement checks. The paper acknowledges subjectivity but supplies no numeric agreement statistic, complete double-coding fraction, adjudication log, or versioned guidelines. False coherence or misalignment labels can therefore alter claims about how agents use feedback.

The official release contains a specific cross-file inconsistency: rq1/repairagent_iterations.csv and the README/action-annotation lists each contain 10 successful and 30 failed RepairAgent entries, but the 30 failed instance names do not match. The repository does not explain which manifest underlies each paper figure or table. This is a lineage blocker, not a cosmetic naming issue.

Replay and versioning remain incomplete. The checked repository main was observed at commit 358870ec56aa38e9f221fd59c7078eb79b405cdf on 2026-01-23, after data-adding changes following arXiv v2. No GitHub release or immutable tag was verified. Parsed text and CSVs are public, but pinned containers, dependencies, source-repository revisions, agent/tool versions, reset semantics, checksums, and a raw-log replay manifest are not documented. Parser commands expect external raw inputs, and the README references a stats directory that was not visible in the verified root.

Rights and contamination also block training reuse. The repository has a root MIT License, but separate terms for benchmark issue text, source code, patches, generated thoughts, and tool outputs are not documented. The paper reports no decontamination or model-exposure audit for public SWE-bench Lite and Defects4J tasks. Completeness of raw terminal output, final patches, failed/invalid actions, and discarded material is unknown. These gaps justify evaluation/audit use only, not SFT, process supervision, reward modeling, RLVR, or agent training.
