The input pool consists of original evaluation logs from three systems. For RepairAgent, the study keeps main repair trajectories and excludes mutation sub-trajectories. For AutoCodeRover it uses V1 because later versions were unavailable, takes the first of three runs, and evaluates SWE-bench Lite instances. OpenHands contributes CodeAct SWE-bench Lite issue-resolution runs. The authors randomly sample 40 trajectories per agent with proportional selection of roughly 10 successful cases, but disclose neither the seed nor an immutable sampling-frame revision.

Parsing is agent-specific. RepairAgent and OpenHands provide structured JSON that requires tailored extraction. AutoCodeRover emits semi-structured output, so the parser heuristically detects tool calls, assigns preceding text as thought, and locates call results. The common analytical episode is an ordered sequence of thought, action, and result; released RQ1 CSVs also store instance_id, n_iterations, is_resolved, and token metrics. The release exposes several parsed pair views rather than a single canonical row schema.

Action analysis first maps known tools automatically, then manually inspects remaining actions. The final vocabulary has eight categories: Explore, Locate, Search, Reproduce, Generate Fix, Run tests, Refactor, and Explain. Actions that fit none of these classes—8.3%—are excluded from subsequent action analyses. The authors compare successful and failed trajectories through fixed-length action n-grams with n=4.

For semantic analysis, adjacent components are organized into five relation families: thought-action, thought-thought, action-action, result-thought, and result-action. Roughly 14,000 pairs are open-coded. The first author performs annotation over five months; both authors discuss the vocabulary, resolve ambiguous cases, cross-validate annotations, and revisit anomalies. The paper does not report a full double-coded fraction, numeric agreement result, adjudication log, or versioned guideline.

Terminal verification differs by substrate. AutoCodeRover and OpenHands use SWE-bench tests to decide whether the final patch resolves the issue. RepairAgent uses Defects4J plausibility followed by manual equality or semantic-equivalence checking against the developer patch. RepairAgent has a 40-iteration cap and OpenHands a 100-iteration cap; exact decoding parameters, retries, costs, and the AutoCodeRover/OpenHands backbone models used for these logs are unknown. Only RepairAgent's GPT-3.5 backbone is identified.

The outputs are trajectory statistics, parsed thought/action/result views, action-category CSVs, five families of semantic annotations, sequence-mining results, and successful/failed comparisons. Their supported use is evaluation and audit. No SFT, PRM, reward-model, RLVR, or agent-policy training is performed. Reproduction requires pinning agent and benchmark commits, raw logs, parser versions, selected instance manifests, environments, tool versions, reset semantics, annotation guidelines, and the repository snapshot; those pins are not all supplied.
