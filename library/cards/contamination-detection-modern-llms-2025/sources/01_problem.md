The final paper appears in the main proceedings of COLING 2025, pages 5058–5070. It asks whether five widely used or exploratory contamination detectors remain dependable on four modern language models and eight benchmarks, especially when exposure is introduced through instruction tuning rather than unchanged pretraining text. The evaluated models are GPT-4 (`gpt-4-0613`), Claude 3 Sonnet, LLaMA-3-70B-Chat, and LLaMA-2-70B-Chat; the benchmarks are GSM8K, MMLU, BIG-Bench-Hard, ARC-Challenge, DROP, HumanEval, AGNews, and IMDB.

The study does not define a single data object. Each audit case joins a model and benchmark split to one of five probe interfaces: a Word Perturbation Quiz (WPQ), a Local Order Quiz, guided versus general Token Completion Overlap, Min-K% token likelihood, or Canonical Order likelihood comparison. Their outputs are heterogeneous—quiz correctness, exact/near matches, ROUGE-L bootstrap p-values, low-token likelihood summaries, and order-preference p-values—and the paper reports mostly model-by-split aggregates rather than instance-level true/false contamination labels.

A second object is the controlled oracle construction. Selected benchmark fractions are intentionally added to LLaMA-2-70B-Chat through three epochs of instruction tuning at learning rate `8e-6`. The questions are preserved, original answers are replaced with LLaMA-2-generated chain-of-thought answers, and four consecutive examples are packed into each training item. This establishes known **newly added exposure**, not a historically clean model: exposure already present in the base checkpoint remains unknown.

The public repository is a partial probe release. It contains fifteen JSON-formatted `.txt` files with 100 rows each (1,500 rows) and fifteen Token Overlap CSVs with ten rows each (150 rows). These are processed benchmark slices, not contamination annotations. It does not contain the oracle SFT corpus, checkpoint, complete original-order banks, generated choices or completions, detector outputs, or run logs.

This work belongs in **Data Construction & Open Release Recipes** because its main value for the track is the inspectable conversion from benchmark rows into method-specific audit records and a known-added-exposure SFT control. It is not a clean contamination benchmark, a universal detector, or a reasoning-training corpus. The `sft` tag records how the oracle is constructed; the released detector probes are intended for audit and evaluation, not as model-training rewards.
