The five contracts have different confounds. WPQ can reward recognition of natural wording, unchanged labels, proper nouns, numbers, or formatting artifacts rather than memorization. Token Completion Overlap uses only ten records, prompt-sensitive suffixes, GPT-4 match judgment, and an independently resampled 10,000-draw bootstrap after rounding scores to two decimals; it has no fixed bootstrap seed. Min-K% has no operational threshold for an unlabeled corpus and reverses its expected direction in the oracle.

Both order methods assume that original dataset order survived training. Shuffling during pretraining can erase the signal, while semantic or categorical adjacency can reveal the successor without memorization. More seriously, the released Local Order negative sampler does not exclude the true successor before inserting it, so a quiz can contain the correct successor twice and violate its exactly-one-correct-option prompt contract. Canonical Order computes its t statistic using population standard deviation (`ddof=0`) but evaluates it with a Student-t distribution at `n-1` degrees of freedom; this nonstandard choice matters with ten shards.

The oracle establishes known newly added exposure, not total contamination. The LLaMA-2 base model may already have seen benchmark material, and no token-budget-matched nonbenchmark SFT control isolates general calibration or distribution changes caused by fine-tuning. Generated chain-of-thought also changes the answer form, so the experiment probes one realistic but specific exposure mechanism. No independent training repetitions, confidence intervals for quiz accuracies, sampling robustness, or multiple-comparison correction are reported.

The repository is not turnkey. `main.py` searches for `.json` order files while the released records end in `.txt`; Local Order needs an absent `full_datasets` directory; Canonical Order references absent `canonical` directories and an unset example fine-tuned model. Min-K and Canonical scripts depend on Together likelihood behavior and credentials that the user must supply. The oracle generation/training code, checkpoint, outputs, likelihood vectors, permutations, perturbations, completions, parser failures, and run logs are missing. Pinned Python requirements do not specify a full platform/CUDA/container environment.

Reuse rights are unresolved. The COLING paper is CC BY 4.0, but the GitHub repository has no LICENSE, dataset card, or per-source rights ledger. The fifteen processed benchmark families have no attached upstream revisions or row-level provenance. The inspected commit is a post-publication repository state with no formal release tag, so it cannot be assumed to be the exact paper snapshot.

One textual inconsistency also remains: a results sentence names Claude 3 Haiku, while the method description, Table 1, its caption, Table 3, and the released runner name Claude 3 Sonnet. This Card uses Sonnet because it has the stronger repeated support, but the exact checkpoint used in every pipeline remains unknown.
