已披露流程如下：

1. **感知收集。** 自动爬取与人工辅助探索从网站、应用和操作系统（含嵌套页面）收集截图与元数据。解析器提取元素类型、层级/深度、边界框和文本。VLM 合成元素描述、密集描述与状态转换描述、视觉问答和标记集监督。
2. **动作归一化。** 经人工审核的 PC 任务与 MM-Mind2Web、GUIAct、AITW、AITZ、AndroidControl、GUI-Odyssey、AMEX 标准轨迹被映射到统一的桌面端与移动端结构。`Finished()` 表示完成，`CallUser()` 请求用户介入登录或认证等环节。
3. **教程知识。** 源于 MINT/OmniCorpus 的 GUI 教程先经过 fastText 分类器（人工正例与随机负例），再由 LLM 精筛，并进行 URL/LSH 去重、广告与噪声移除和 LLM 改写。数据量、过滤器、模型与权利未知。
4. **思维增强。** Action Reflection 让未披露的 VLM 根据上下文与目标动作生成逐步思维，存在事后合理化风险。Thought bootstrapping 不显示目标动作，而是采样多个思维—动作候选，再选择动作与正确目标匹配的思维。候选数、temperature 和被淘汰的思维记录不可用。
5. **在线 VM 飞轮。** 人类或模型给出的目标驱动最新 checkpoint 在数百台虚拟 PC 上多轮运行。规则移除异常、冗余或未引起状态变化的动作；VLM 拒绝低分轨迹；人工抽查并定位首个错误，丢弃错误后的轨迹，只保留有效前缀。VM 镜像、轮数、轨迹、阈值、保留率和标注一致性未知。
6. **Reflection 数据。** 标注者在首个错误处给出纠正后的思维与动作；错误后反思从实际错误状态继续，并标注恢复思维与动作。SFT 损失仅施加于纠正步骤。DPO 在给定指令和历史状态的条件下，将纠正动作与错误动作配对，并以 SFT 模型为参考模型。
7. **三阶段训练。** 约 50B token 覆盖三个阶段：除 Reflection 调优外的上述语料用于持续预训练，采用数值未披露的恒定 LR；随后在高质量感知、定位、动作与 Reflection 子集上进行退火训练，得到 UI-TARS-SFT；最后在人类在线纠错样本对上执行 DPO，得到 UI-TARS-DPO。各阶段 token、配比、优化器、LR、beta、batch、算力和选择方法均未知。

评测反馈必须与训练反馈分开。OSWorld 环境成功率取三次运行的平均值，使用 15/50 步预算；AndroidWorld 对任务参数进行随机化。System 1 直接输出动作，System 2 先生成思维再输出动作，并在 Best-of-N 取 1、16、64 时进行研究。这些测试阶段的采样和选择设置不能证明训练阶段的采样器或奖励机制。
