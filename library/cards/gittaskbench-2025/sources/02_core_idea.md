GitTaskBench's central contribution is a small, heterogeneous suite of repository-bound tasks whose success is decided by executable checks over the final artifact after the agent has navigated repository understanding, code modification, environment setup, and execution.

The core object has two layers. The task layer exposes `task_id`, task description, prompt, repository name/path/URL and understanding guidance, working subdirectory, and input files. The evaluation layer supplies the output directory, test script, optional ground truth and parameters, then records `Process`, `Result`, `TimePoint`, and `comments` in JSONL. At the audited GitHub commit, the public tree contains 54 queries, 54 task configs, 54 primary task test scripts, and 18 bundled `code_base` projects. These assets specify an evaluation surface; they do not record the sequence of shell commands, file edits, observations, or internal reasoning that produced an answer.

The feedback contract is deliberately two-stage. `Process` supports Execution Completion Rate (ECR): the required output must exist, be non-empty, and be parseable by the test script. `Result` supports Task Pass Rate (TPR): the task-specific functions must satisfy functional, completeness, similarity, or quality thresholds. The episode's programmatic terminal success is the final grader record with `Result=true`; `Process=true` alone means only that a consumable output was created. Alpha is a separate mixed score combining binary execution success, estimated market value, API cost, and a five-rater human quality score. Thus the grader observes final outputs and execution results, but it cannot certify the hidden quality of the entire interaction path or cover behavior that its tests omit.

Relative to issue-and-patch benchmarks, GitTaskBench broadens the output surface to multimodal real-world artifacts and makes autonomous setup/execution part of the task. PaperBench is the closest atlas comparison: both bind long-horizon agent work to an executable environment and terminal evaluation, but PaperBench asks agents to reproduce research papers using hierarchical rubrics, whereas GitTaskBench associates 54 operational tasks with 18 existing repositories and custom output graders. The direction signal is environment-mediated evaluation with explicit terminal predicates, not a newly released training trajectory format.
