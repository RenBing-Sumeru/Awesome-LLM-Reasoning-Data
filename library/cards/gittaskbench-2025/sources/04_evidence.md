The main experiment compares combinations of Aider, OpenHands, and SWE-Agent with the evaluated language models under the framework and sampling settings described in the extended appendix. The paper averages two independent runs per reported framework/model setting. Its strongest reported setting, OpenHands with Claude 3.7, reaches 72.22% ECR and 48.15% TPR. The gap is substantive: producing a non-empty parseable output is not the same as satisfying the task-specific functional or quality checks. (arXiv v2, Table 3, p. 7)

The error analysis reports that environment-setup errors account for 65.04% of analyzed failures. Other documented categories include workflow planning, repository comprehension, runtime timeout or freezing, and instruction non-compliance. Appendix cases show outputs that bypass the intended repository, mock required behavior, use wrong filenames or formats, or redirect debugging text into the expected artifact. These cases demonstrate why ECR is only a process-completion signal and why TPR remains bounded by grader coverage. (AAAI paper, Error Analysis, p. 7; arXiv Appendix F)

Artifact inspection strengthens the scale and release claims but also narrows them. At the audited GitHub SHA, there are 54 query JSON files, 54 task configurations, 54 primary task test scripts, 18 bundled repository directories, and only 43 `test_results_for_show/*/results.jsonl` files. Those 43 files include both success and failure examples, but they are not complete results for all 54 tasks, and their producing model, framework, run, and configuration are not identified. They are task-level terminal records, not successful and failed rollout trajectories.

The author-maintained Hugging Face revision has 276 files totaling 82.8 MB and includes the 54 queries, inputs/prompts, and primary task scripts. It omits the GitHub release's `code_base`, task configs, ground truths, result examples, and benchmark runner. Consequently, the HF artifact is useful for inspecting task definitions but is not a standalone replay package.

These are author-reported results and curator-verified artifact counts, not an independent replication. Benchmark performance does not establish that every task is unambiguous, every grader measures the intended behavior, the benchmark is uncontaminated, or the release is legally reusable as a unit. The empirical evidence supports GitTaskBench as a challenging evaluation surface and documents environmental failure pressure; it does not support using the release as a high-quality trajectory-training corpus.
