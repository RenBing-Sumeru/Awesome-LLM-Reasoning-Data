**Inputs.** The authors select real-life domains through literature review, expert consultation, practical experience, and LLM-assisted deep research. Candidate repositories must be Python-based, have at least 50 GitHub stars, show activity within the preceding five years, and offer ready-to-use weights or relatively simple setup; stars, forks, license, commit history, and functionality are inspected. The resulting 54 tasks cover image (16), video (3), speech (8), physiological-signal (3), security/privacy (9), web-scraping (6), and office-document (9) work across 18 repositories. (AAAI paper, p. 3; arXiv Appendix A, Table 4)

**Construction and completeness checks.** Task and repository selection are co-refined: experts formulate non-trivial tasks, inspect repository capabilities, execute the tasks, adjust parameters, and create expected outputs or ground truth where applicable. Five computer-science PhDs verify dependencies, configuration, data, models, and expected results by following repository instructions; the paper reports that every retained task is human-completable. The public package links prompts and inputs to repository code, working directories, output paths, configs, ground truth where applicable, and custom test scripts. No per-candidate rejection ledger or train/dev/test split is reported.

**Episode.** An evaluated agent receives the selected repository and task prompt. Its intended workflow is repository understanding, code generation or modification, environment setup, code execution, and writing the final task-specific artifact. The experiments use Aider v0.84.1.dev-21-gb2592267, OpenHands 0.33.0, and SWE-Agent v1.0.1-61-gaa4e8ea1. The extended paper reports 9 vCPUs, 33 GB RAM, and 2965 GiB SSD per run; Aider uses local Python 3.12 Conda, OpenHands uses its official runtime container, and SWE-Agent uses Ubuntu 20.04 Docker with Python 3.12. Model sampling uses temperature 0.5, top-p 1.0, model-default top-k, and a 4096-token response cap, subject to framework requirements. Reported framework/model results average two independent runs.

**Verifier and outputs.** Each task's Python grader checks output existence, non-emptiness, and parseability for `Process`/ECR, then applies task-specific criteria for `Result`/TPR. The last JSONL record provides `Process`, `Result`, `TimePoint`, and comments; `Result=true` is the terminal success predicate. Alpha adds human and economic terms and should not be conflated with the programmatic predicate. Supervision attaches to the final artifact/episode outcome, not to verified intermediate reasoning steps.

**Replay requirements.** A serious reproduction should pin GitHub commit `df188a73013393d036442bfb0f323c4c995fa5e1`, not merely `main`, and separately record each upstream repository commit, container image digest, OS packages, dependency locks, external model/data hashes, network policy, framework/model configuration, random seeds, timeouts, and a run manifest. The public GitHub tree has no tag or Release and no task-level upstream-commit manifest. The Hugging Face snapshot at `22ca28cedaa927f8c65224df3c61a0ed4c0b93eb` omits `code_base`, configs, ground truths, result examples, and the runner, so it cannot independently replay the benchmark.
