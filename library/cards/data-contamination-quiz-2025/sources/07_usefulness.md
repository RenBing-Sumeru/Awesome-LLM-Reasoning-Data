A benchmark maintainer can select a partition, generate and inspect DCQ variants, run BDQ and all BCQ permutations against an API-only model, and publish the resulting report with the lower and upper estimates. Success is a near-zero range on a known clean control and a sensible response to controlled additions when available. The released scripts and intermediate files make the protocol auditable. Do not use DCQ to claim that semantic contamination is absent, or where items cannot be perturbed while preserving their decisive wording or labels. A report should include sample scope, the BDQ preference distribution, and all BCQ results so readers can distinguish a memory signal from an accidental preference for one position.
