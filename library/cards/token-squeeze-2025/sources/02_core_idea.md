TokenSqueeze turns a model's own rollouts into length-sensitive preference supervision. For N samples, it computes p, the fraction judged correct by final-answer comparison, sets \`q = alpha*(1-p)\`, and selects the first \`ceil(q*c)\` after sorting c correct traces by token length. Easier prompts favor shorter positives; harder prompts can retain more depth. Each selected positive is paired with a longer incorrect response, up to 64 pairs per problem (paper §3.1).

For intra-step refinement, a trace \`(prompt, s1, ..., sN)\` yields 64 rewrites per step under preceding context. The selector keeps the shortest rewrite whose estimated divergence between original and rewritten *future continuation distributions* is below epsilon. The published approximation uses one sampled continuation and a 512-token window; it is a local distributional proxy, not a proof of logical validity (paper §3.2; Appendix B).

The data contract is: math prompt/reference answer -> sampled tagged responses -> equality outcome/length -> chosen correct plus longer incorrect pair -> optional rewritten chosen trace/KL -> length-aware DPO plus SFT. Feedback observes answer equality, candidate length, and local distribution change; it cannot observe proof validity, faithfulness, shortcutting, or contamination.

Closest context is shortest-correct self-training. *Self-Training Elicits Concise Reasoning* selects one shortest parser-correct rollout per prompt for SFT. TokenSqueeze instead selects a difficulty-adaptive positive set, uses longer incorrect rejections, KL-gates step rewrites, and adds length-aware DPO.
