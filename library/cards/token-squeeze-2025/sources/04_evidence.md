Evidence is experimental and recipe-level, not row-level data certification. On MATH500, the 7B baseline reports 92.8% accuracy, Len-T 3,638, Len-A 4,190, and AUC 83.6. TokenSqueeze reports 92.4%, 1,773 (-51.3%), 2,045 (-51.2%), and 87.5. This supports roughly 50% token reduction with baseline-close accuracy; it is not an independent verification of the generated corpus (paper Table 1).

For 7B AIME24, Table 1 reports 55.5% / Len-T 7,543 / Len-A 13,337 / AUC 41.6 for baseline versus 57.5% / 5,157 / 9,189 / 48.5 for TokenSqueeze. On LiveCodeBench it reports 31.3% / 3,961 / 20,690 / 27.5 versus 35.0% / 3,200 / 15,635 / 31.6. Math uses temperature .6, 16 independent runs, and a 32,768-token cap; LiveCodeBench uses temperature .2 and the 2024-08-01--2025-01-31 window, also averaged over 16 runs (paper §4.1; Appendix A.3).

Ablations identify conditional mechanisms. Q-DYN yields AIME24 57.3 / 6,190 / 46.5 and MATH500 92.8 / 2,180 / 86.7 (accuracy/length/AUC), versus shortest selection at 53.3 / 5,960 / 43.7 and 90.8 / 1,926 / 85.5. Table 3 compares MATH500 No Refinement (92.8, 2,180, 86.7) with TokenSqueeze (92.4, 1,773, 87.5); Table 4 gives pure DPO AIME24 accuracy 48.3 versus 57.5 for the full objective. These are author-reported, setup-specific effects, not proof that the KL gate validates each step (Tables 2-4).

The repository confirms the step ordering, input name, generation defaults, quantile=.2, KL threshold=.005, and author-linked 7B/1.5B models. It does not provide paper-matched response/rewrite/pair files, hashes, retention ledger, model cards, or a data-quality audit; no independent reproduction was found in inspected official materials.
