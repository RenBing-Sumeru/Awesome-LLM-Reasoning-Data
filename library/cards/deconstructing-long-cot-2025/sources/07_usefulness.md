For the `rollout_search_test_time_trace_data` category, this paper is useful as a schema for auditing offline traces produced by long-running reasoning policies: preserve the original rollout, terminal answer check, every parsed branch, cluster assignment, label, deletion decision, reconstruction prompt/output, and the student checkpoint that consumed it. A builder can compare “remove duplicate branches” against “remove all incorrect-looking branches” without confusing token reduction with trace quality, and can use the released code as a partial recipe after independently pinning inference models and validating mathematics. It should not be cited as a ready-to-download optimized corpus. A reusable release would need immutable final rows, rejected/intermediate outputs, exact source mappings, verifier error analysis, licenses, splits, and benchmark-overlap checks.
