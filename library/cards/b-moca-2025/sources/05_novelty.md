The prior baseline is mobile/OS agent evaluation with fixed environments, narrower task sets, or limited configuration diversity. B-MoCA changes the benchmark object by treating device configuration itself as a controlled generalization axis. The direction signal is the combination of realistic Android daily tasks, randomized test configurations, rule-based success detectors, and support for LLM, MLLM, and imitation-learning agents. The quality signal is an open release with source code and materials plus experiments across all tasks and representative long-horizon tasks. What is not new: Android emulation, ADB/Appium-style state inspection, and success-detector benchmarks. Reuse requires checking release branch, detector correctness, app/data licenses, environment IDs, stochastic tasks, language settings, and whether training demonstrations overlap test configurations.
