The method inserts periodic probes into a running reasoning program and asks what answer the program would give at each checkpoint. It compares the resulting answer sequence and normalizes the observed stabilization into Certaindex, a proxy for whether another compute interval is likely to produce a different terminal answer. The procedure can be applied to programs based on chain-of-thought, repeated sampling, tree search, or other multi-step inference patterns because it operates on answer evolution rather than their internal search rule.

Dynasor consumes this metric as a scheduling input. A request with a stable answer can leave the system early, while a request whose answer has not settled receives further tokens or rollouts. The implementation also uses the signal for dynamic allocation among requests and for gang scheduling of multi-stage programs. No separate reward model is required by the stated mechanism; the operational feedback comes from the program's own intermediate answers.
