Real software-engineering training data is commonly built from GitHub issues and repair pull requests. It depends on humans writing clear issue descriptions and usually produces one before–after task rather than the incremental process by which developers add functionality through tests. Many repositories already contain unit tests, but existing construction pipelines underuse the requirements and function dependencies encoded in those tests.

SWE-Flow asks whether Test-Driven Development steps can be reconstructed from tests themselves to synthesize executable software-development data automatically. It uses runtime dependency graphs to order function interactions and provides each step with a partial codebase, relevant tests, and the code changes that must be implemented.
