SWE 流水线从公开且采用宽松许可证的 GitHub 仓库中收集已合并 PR 及关联 issue。规则过滤要求存在相关测试；智能体迭代构建多语言 Docker 环境；PR 按任务类型标记；奖励分别实现为失败转通过/保持通过测试、新功能测试或性能检查。模型验证用于修复描述不充分的问题。增强方式包括注入缺陷、合并提交、把修复任务反转为 SWE-Test，以及近似可验证的代码审查任务。每个保留实例由问题描述、基于测试的奖励和可运行 Docker 环境组成。

AppDev 使用专家编写的元查询与评分规范，再由 Agent-as-a-Verifier 在沙箱中按执行、交互和美学标准进行拒绝采样。Terminal-Gym 从社区讨论中筛选可脚本化、兼容 Linux/Docker 且可验证的任务，重写为包含指令、文件、预期行为、环境和测试的结构化对象；环境失败时迭代修复，再删除提示、运行统一测试，并依据参考求解器通过率和环境修复次数偏向更难变体。

Cowork 各流水线保留产物专用契约。搜索任务附带证据规范，只接收有实际检索证据支撑的答案；开放式报告则用 rubric 评审。办公任务结合基准种子和分层合成情境，配套真实支持文档及多轴 rubric，并清除捏造事实或引用的轨迹。金融任务从真实工具轨迹反向推导；电子表格任务遍历工作簿，并把外部引擎重算后的单元格值与参考工作簿比较。幻灯片任务从源文档或真实 deck 出发，变化指令与教师，并叠加执行、智能体、版式规则和渲染图像评分。推理数据同时扩展问题和多条解法，通过歧义问题清洗、验证器边界案例测试、模型分歧交叉检查和轨迹 rubric 评分保证质量。

SFT 对领域专用奖励做大规模拒绝采样并多阶段清洗，保留覆盖对话、推理、代码和 cowork 的思考—动作—观察交错轨迹。RL 改造 CISPO，采用 episode 级 reward-to-go 与轨迹基线。复合奖励组合任务表现、稠密过程反馈（包括语言混杂和工具调用格式错误惩罚）及相对完成时间塑形。混合领域训练在每阶段同时采样推理、代码、智能体和通用任务，并逐步调整领域比例、上下文长度与难度。具体系数、采样比例、rollout 数、阈值和预算均未披露。
