The SWE pipeline starts from merged pull requests and linked issues in public, permissively licensed GitHub repositories. Rule filters require relevant tests; agents iteratively build multi-language Docker environments; PRs are tagged by task type; and rewards are specialized as fail-to-pass/pass-to-pass tests, new feature tests, or performance checks. Model-based validation repairs underspecified problem statements. Augmentations include bug injection, commit merging, SWE-Test inversion, and approximately verifiable code-review tasks. Each retained instance is described as a problem statement, test-based reward, and runnable Docker environment.

AppDev uses expert-authored meta-queries and rubrics, then Agent-as-a-Verifier rejection sampling in sandboxes over execution, interaction, and aesthetics. Terminal-Gym filters community threads for scriptable, Linux/Docker-compatible, verifiable tasks; rewrites them into structured instructions, files, expected behavior, environments, and tests; repairs failed environments; removes hints; applies unified tests; and favors harder variants using reference-solver pass rates and repair counts.

Cowork pipelines preserve artifact-specific contracts. Search tasks carry evidence specifications and accept only grounded answers, with rubric judges for open reports. Office tasks combine seeded and hierarchically synthesized scenarios with real supporting documents and multi-axis rubrics, followed by cleanup for fabricated facts or references. Financial tasks are reverse-derived from real tool traces; spreadsheet tasks walk workbooks and compare recalculated cell values with reference workbooks. Slide tasks use source documents or real decks, varied instructions and teachers, then layer execution, agent, layout-rule, and rendered-image scoring. Reasoning data scales queries and multiple solution paths while cleaning ambiguous prompts, testing verifier edge cases, cross-checking model disagreements, and rubric-scoring traces.

SFT uses rejection sampling against domain-specific rewards plus multi-stage cleaning to retain interleaved thinking/action/observation trajectories across chat, reasoning, code, and cowork. RL adapts CISPO with episode-level reward-to-go and a trajectory baseline. Composite rewards combine task performance, dense process feedback (including penalties for language mixing and malformed tool calls), and relative completion-time shaping. Mixed-domain stages jointly sample reasoning, coding, agent, and general tasks while changing domain ratios, context lengths, and difficulty. Exact coefficients, sampling ratios, rollout counts, thresholds, and budgets are not disclosed.
