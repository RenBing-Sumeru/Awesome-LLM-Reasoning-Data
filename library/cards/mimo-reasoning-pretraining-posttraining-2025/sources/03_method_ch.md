预训练混合网页、论文、书籍、代码与合成数据。小米报告为公式、代码块、论坛和 STEM 材料定制了 HTML 与 PDF 提取；网页 dump 经过 URL 和 MinHash 去重，随后由小语言模型分配领域标签和多维质量标签。合成阶段让未具名推理模型分析高推理深度 STEM 材料、解答数学和代码问题，并处理创意写作等通用查询。阶段 1 对除“推理任务查询的合成回答”之外的全部来源做再平衡；阶段 2 让数学和代码占 70%；阶段 3 加入 10% 合成回答并把上下文扩展到 32,768。最终总量约 25T token，但各来源数量与标签阈值为 unknown。

原始 SFT 数据约含 50 万条开源与专有蒸馏样本。处理流程移除与评测基准存在 16-gram 重叠的查询、语言混杂回答和不完整回答，并把每个查询的回答数限制为八条。训练把样本打包到 32,768 token，batch size 为 128；渲染后的报告没有显示精确恒定学习率。后续更新报告 600 万条 SFT，但没有样本或教师清单。

RL 策展得到 10 万个数学问题和 3 万个代码问题。数学流程用模型过滤证明题与选择题，做全局 n-gram 去重和基准去污染，用高级模型筛除无法解答或答案错误的问题，再对每个剩余问题运行 16 次 MiMo-SFT rollout；通过率超过 90% 的简单题被删除，约占原始数学池的一半。代码流程删除无测试任务、标准解无法通过全部测试的任务、高级模型在 16 次 rollout 中连一个测试也无法通过的任务，以及 MiMo-SFT 在 16 次 rollout 中全部解对的任务。

数学奖励使用 Math-Verify。代码方面，多个模型先生成解答，据此计算每个测试的通过率并按难度聚类。strict reward 只有在某个难度组及全部更简单组的测试均通过时才授予该组分数；soft reward 把组分数平分到组内测试；最终奖励是通过测试所得分数之和。用于测试标定的模型身份、rollout 数量、测试快照以及 strict/soft 的选择规则均为 unknown。

原始 RL 使用去除 KL loss、加入动态采样和 Clip-Higher 的 modified GRPO。动态采样超额生成，并把通过率为 0 或 1 的提示排除在更新批次之外。报告参数为 batch 512、actor mini-batch 32、每轮 16 次梯度更新、学习率 1e-6、最大长度 32,768、temperature 1.0、top-p 1.0；简单题池以 10% 概率抽取。Seamless Rollout Engine 基于 verl、Ray 和 vLLM，采用连续 rollout、异步规则评估和遵循 FIFO 的提前终止。后续 RL-0530 变体改用 on-policy RL，并把生成长度从 32K 提至 38K、再提至 48K；完整优化器设置为 unknown。
