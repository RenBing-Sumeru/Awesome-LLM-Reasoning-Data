Pretraining combines web pages, papers, books, code, and synthetic data. Xiaomi reports specialized HTML and PDF extraction for equations, code blocks, forums, and STEM material. Webpage dumps undergo URL and MinHash deduplication, then small language models assign domain and multidimensional quality tags. Synthetic generation asks unnamed reasoning models to analyze selected STEM material, solve math and code problems, and answer general queries such as creative writing. Stage 1 rebalances all sources except synthetic responses to reasoning-task queries; Stage 2 makes math and code 70%; Stage 3 adds 10% synthetic responses and extends context to 32,768. The final total is about 25T tokens, but per-source counts and exact tagger thresholds are unknown.

The original SFT data mix is about 500K open-source and proprietary distilled samples. It removes queries with 16-gram overlap against evaluation benchmarks, mixed-language responses, and incomplete responses, then caps each query at eight responses. Samples are packed to 32,768 tokens with batch size 128; the rendered report does not expose the exact constant learning rate. A later update reports 6M SFT instances, but no sample or teacher manifest.

RL curation yields 100K math and 30K code problems. Math uses model filtering for proof and multiple-choice items, global n-gram deduplication, benchmark decontamination, advanced-model screening for impossible or wrong-answer items, and 16 MiMo-SFT rollouts per remaining problem; pass rate above 90% removes easy items, about half of the original math pool. Code drops tasks without tests, invalid golden solutions, tasks for which advanced models solve no test in 16 rollouts, and tasks solved perfectly by MiMo-SFT across 16 rollouts.

Math rewards use Math-Verify. For code, multiple models produce solutions used to estimate each test's pass rate and cluster tests by difficulty. The strict reward grants a group's score only after all tests in that group and easier groups pass; the soft reward distributes group score over individual tests. Final reward sums passed-test scores. Identities and rollout counts for test calibration, test snapshots, and the rule for choosing strict versus soft reward are unknown.

Original RL uses modified GRPO with no KL loss, dynamic sampling that oversamples and excludes pass-rate-zero and pass-rate-one prompts from update batches, and Clip-Higher. Reported settings are batch 512, actor mini-batch 32, 16 gradient updates per iteration, learning rate 1e-6, maximum length 32,768, temperature 1.0, and top-p 1.0. An easy pool is sampled with 10% probability. Seamless Rollout Engine runs on verl, Ray, and vLLM with continuous rollout, asynchronous rule evaluation, and FIFO-aware early termination. The later RL-0530 variant instead reports on-policy RL with generation length raised from 32K to 38K to 48K; its complete optimizer settings are unknown.
