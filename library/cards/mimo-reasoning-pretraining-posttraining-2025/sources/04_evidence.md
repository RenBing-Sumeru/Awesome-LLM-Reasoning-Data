Artifact evidence confirms model release, not data release. XiaomiMiMo publishes MiMo-7B-Base, MiMo-7B-SFT, MiMo-7B-RL-Zero, MiMo-7B-RL, and MiMo-7B-RL-0530 weight pages. The official MiMo repository contains the technical report, registry helper, model links, and deployment guidance. XiaomiMiMo also publishes a vLLM fork on `feat_mimo_mtp_stable_073` for MiMo/MTP inference. The checked official surfaces do not link a downloadable pretraining, SFT, RL-task, test, verifier, or rollout dataset, and the project repository does not contain the reported end-to-end training stack.

The report's ablations support several narrower claims. It states that difficulty filtering produces 100K math plus 30K code tasks; that 16-rollout easy filtering removes about half of the original math pool; and that a 10% easy-pool sampling probability improves late-training stability. On a five-step trace using 256 H20 GPUs, the full Seamless Rollout Engine reports 2.29x end-to-end speedup, lower idle time, and lower sample waste than naive dynamic sampling. Those are construction and systems measurements, not released data.

Model comparisons provide behavioral evidence. Table 5 contrasts Base, RL-Zero, SFT, and RL checkpoints, while Table 6 contrasts 500K-SFT and 6M-SFT variants and the later 48K-budget model. The report also observes that Base-to-RL code performance keeps improving between steps 2000 and 2500 while mathematics fluctuates and declines, and that a language-mixing penalty can itself be exploited. These observations expose failure modes, but benchmark changes cannot identify which records were correct, licensed, uncontaminated, or responsible for the gains.
