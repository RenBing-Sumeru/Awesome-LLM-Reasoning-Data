The base data object is a synthetic constrained instruction. Seed instruction-following prompts, with IFEval given as an example, are stripped of their original constraints by Llama-3.1-70B-Instruct. The same model uses sampled base prompts as few-shot demonstrations to generate 20 new unconstrained prompts at a time. New and seed-derived base prompts are embedded with all-mpnet-base-v2 and deduplicated by dot-product similarity. Each retained base prompt receives a non-conflicting combination of k in {4, 5, 6} constraints, randomly sampled or model-generated keyword arguments, and a natural-language rewrite. Appendix Table 7 reports 15,900, 15,739, and 15,559 prompts for k=4, 5, and 6: exactly 47,198, although the paper describes the total as about 48K.

The preference object is a synthetic prompt plus a chosen full response and a rejected full response. A code verifier evaluates every constraint and aggregates the binary outcomes into the fraction satisfied. RS independently samples complete policy responses and pairs responses whose aggregate scores exactly match requested chosen and rejected values `(c,r)`. MCTS instead searches over partial token-sequence responses; eligible sibling nodes inherit a shared prefix from their parent, and complete rollouts sampled from those siblings become the pair.

The two reward contracts must remain separate. During MCTS search, expansion combines averaged rollout verifier scores with the policy model's self-evaluation of content, weighted by lambda=0.2. For final pair extraction, the paper discards that blended search reward and applies only the programmatic verifier score so that RS and MCTS pairs use the same correctness criterion. The final DPO record schema is not published, so storage of constraint IDs, keyword arguments, shared-prefix boundaries, per-constraint outcomes, scores, and search statistics is unknown.
