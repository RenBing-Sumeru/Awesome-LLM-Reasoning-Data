The closest baseline is token-budget test-time scaling: budget forcing lengthens one chain, while repeated sampling/self-consistency creates several branches and majority-votes their answers. Speculative decoding separately accelerates sequential generation. None of those primitives is introduced by this paper. (Paper §2)

What changes is the unit of optimization. The paper treats an evaluation datum as a joint configuration-result record—output length, branch count, draft length, draft acceptance, aggregation, latency, and accuracy—rather than only a token count and score. It then searches how much concurrency to allocate to branch-wise versus sequence-wise parallelism. This makes system throughput part of scaling attribution and exposes the transition from memory-bound to compute-bound behavior.

The useful quality signal is conditional, not universal: Tables 1 and 3 report three-run means/standard deviations, Table 2 compares search cost, and Table 4 stress-tests request count. The work does not introduce a new final-answer verifier, candidate-quality label, training objective, or open trace release. Reuse therefore requires checking whether the target hardware, request regime, model/draft pair, and answer aggregation match the paper's conditions.
