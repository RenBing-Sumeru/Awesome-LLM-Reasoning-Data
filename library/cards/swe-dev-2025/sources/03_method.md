**Inputs.** The collection pipeline crawls 240k PyPI packages with GitHub URLs, retains 59k repositories after Stars ≥5 and PRs ≥3 filters, downloads 10,416 repositories, extracts 88k instances, and retains 38k from 4,413 repositories after filtering. The retained task provides issue/patch context; a complete public per-task source manifest was not found. (Paper §3.1; Appendix A.2.)

**Construction and verification.** From a 26k-instance subset, the authors generate 2,097 F2P functions; with existing tests, this yields 4,630 tests. Context extraction feeds Gherkin description generation, test-code generation, optional traceback revision, and execution. A valid test is intended to fail on the original repository state and pass after the reference patch. The repository offers Docker (Ubuntu 22.04) and non-Docker evaluator commands, but not a published digest/lock/replay record for every episode. (Paper §3.2; GitHub README and Dockerfile.)

**Rollout, selection, and use.** DeepSeek-V3 runs an OpenHands ReAct-like agent at 30 iterations and 32k max tokens in the ordinary experiments. The paper reports roughly 17k unevaluated and 2.3k correct trajectories. For the filtered scaling study, Llama-3.1-70B-Instruct retains `identical`/`mostly` patch comparisons. The paper studies SFT/RFT, KTO, and OREO with OpenRLHF; it does not establish a universal reward model. The released dataset instead exposes `input`, `from`, `f2p_pass`, `f2p_count`, `reward`, and `instance_id`; the semantics of `from` and every reward value, plus row-to-paper mapping, are not disclosed. Reproduction should pin the HF revision, GitHub commit, image/dependency versions, source snapshots, prompts, seeds, and commands before treating it as trainable data.
