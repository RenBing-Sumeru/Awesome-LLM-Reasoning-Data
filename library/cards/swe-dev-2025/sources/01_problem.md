SWE-Dev addresses a concrete post-training bottleneck for repository-level software engineering agents: issue/patch records often lack executable tests that can tell a useful repair from an ungrounded patch. The primary publication is Findings of ACL 2025, pp. 3742–3761 (ACL Anthology 2025.findings-acl.193; arXiv v2). It is about building and using a data-and-environment pipeline, not a claim that test-passing alone establishes real-world engineering quality.

The paper begins with PyPI packages that expose GitHub URLs, applies repository filters, and extracts issue/PR-derived repair instances. It reports 38,000 retained instances from 4,413 repositories. A task is more than an issue: the intended unit includes repository context, a problem statement and reference patch, a synthesized or existing test, an executable before/after check, and—where rollout collection succeeds—an OpenHands message trajectory. The current public training release is a different object: 20,147 rows across `sft` (17,871) and `rft` (2,276), each with a message list plus five scalar/string fields, not a complete replay bundle.

This Card belongs to `environment_agent_trajectory_data` because the central supervision is attached to interaction in a repository environment and a test-derived terminal condition. It is not a new held-out benchmark, a general code corpus, or proof that every released trace is high quality. L4 depth is supported for screening the data object, test contract, release schema, and major audit gaps; row-level source lineage, snapshotting, and evaluation-contamination evidence remain unknown. (Paper §3.1–§3.3; official HF dataset API checked 2026-07-23.)
