SWE-Dev 针对仓库级软件工程智能体后训练中的一个具体瓶颈：许多 issue/patch 记录没有可执行测试，因而无法区分有用修复与缺乏依据的补丁。其主要出版物是 Findings of ACL 2025，第 3742–3761 页（ACL Anthology 2025.findings-acl.193；arXiv v2）。论文讨论的是数据与环境流水线的构造和使用，并未声称“测试通过”本身就能证明真实工程质量。

论文从包含 GitHub URL 的 PyPI 包开始，筛选仓库并抽取由 issue/PR 派生的修复实例，报告从 4,413 个仓库保留了 38,000 个实例。一个任务不只是 issue：其意图单元包括仓库上下文、问题描述和参考补丁、合成或现有测试、可执行的修复前/后检查，以及在 rollout 成功收集时的 OpenHands 消息轨迹。当前公开训练发布物是另一种对象：`sft` 17,871 行、`rft` 2,276 行，共 20,147 行；每行有消息列表和五个标量/字符串字段，而不是完整的可重放包。

本 Card 归入 `environment_agent_trajectory_data`，因为核心监督附着于仓库环境中的交互以及由测试导出的终止条件。它不是新的留出 benchmark、通用代码语料，也不能证明每条公开轨迹都高质量。现有证据足以将数据对象、测试契约、发布 schema 和主要审计缺口写到 L4 深度；逐条来源、快照固定和评测污染证据仍为 unknown。（论文 §3.1–§3.3；官方 HF 数据集 API 于 2026-07-23 检查。）
