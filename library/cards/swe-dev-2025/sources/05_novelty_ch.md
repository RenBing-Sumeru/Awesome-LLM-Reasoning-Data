较早的 SWE 集合通常从历史 issue/patch 对开始，要么依赖已有测试，要么投入人工验证选中的任务。SWE-Dev 的具体改变是把“缺失测试构造”设为一等中间产物：它利用仓库上下文和参考补丁生成 Gherkin 场景与可执行测试，验证 F2P 条件，再使用所得环境收集并筛选智能体轨迹。公开发布物还以两种训练配置提供消息格式行，而不只提供 benchmark 任务列表。

论文的另一项独特研究问题是在一次 agent run 内进行扩展。它不只进行重复的独立采样，而是把交互轮数预算从 30 变到 75，并报告了收益及其递减；它还在共同任务设置下比较 RFT、KTO 与 OREO。这些是经验性的 recipe 组件；OpenHands、ReAct-like 交互、参考补丁、pytest 执行、rejection sampling 和 offline-RL 目标都不是该论文新提出的。

对 reasoning-data 研究而言，有价值的新接口在于合成测试与轨迹选择决策之间的连接：一行记录原则上可连接到任务、可执行信号和训练选择。复用前应检查该连接是否确实随所需 revision 发布；此处并没有。不存在把公开消息逐条连接到来源 commit、生成测试、运行日志、LLM 判断或 benchmark 排除决定的不可变清单。因此，这一新意支持研究构造 recipe，而不能把它当作已审计、可直接训练的语料。
