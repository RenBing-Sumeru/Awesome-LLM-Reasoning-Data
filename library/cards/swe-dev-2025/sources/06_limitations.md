The executable contract is narrower than semantic correctness. A generated test can pass after the reference patch because it encodes implementation details, accidentally depends on setup, or misses an important regression. Conversely, a semantically valid repair can fail a brittle generated test. The paper acknowledges many unsuccessful test-generation cases arise from environmental constraints, but does not release enough per-case execution material to distinguish environment failure, generation error, and issue ambiguity independently. (Paper §3.2.)

The LLM filter creates a second failure surface. Patch comparison against a reference patch can reward textual similarity or an incomplete interpretation of behavior; `identical`/`mostly` retention can select away novel valid solutions and hides the discarded distribution. This is a curator inference from the disclosed filtering mechanism, not an author-validated error rate. The paper does not publish a human-label calibration, threshold analysis, or row-level comparator rationale.

Release and audit limits matter for reuse. The current HF artifact has 20,147 rows and a small six-column schema, yet lacks per-row repository state, source issue/PR, patch, test file, Docker digest, command, log, decision trace, and license record. No dataset license is declared, no documented dev/test split or SWE-bench-Verified overlap audit is available, and paper/release counts lack a reconciliation manifest. The code and 32B model are MIT, but that does not transfer rights for upstream content. The model results are neither an independent reproduction nor a data-quality audit.
