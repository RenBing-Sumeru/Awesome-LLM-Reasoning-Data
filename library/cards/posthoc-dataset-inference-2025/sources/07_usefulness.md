For the `data_construction_open_release_recipes` track, this paper supplies an executable audit-data pattern: create matched natural/synthetic suffix pairs, measure the generator gap explicitly, add target-model features only in a second classifier, and retain known-member and known-non-member controls. A new reasoning-data release could adopt that structure to test possible training influence while logging prefix identity, source document, generator revision, MIA features, outlier decisions, random split, and corrected p-values.

The work is suitable as an evaluation and audit reference, a baseline for synthetic-holdout construction, and a failure-analysis checklist for distribution-shift-driven false accusations. It is not presently safe as a training-data release: the Google Drive archive lacks an explicit license and immutable manifest, and its rows are Pile-derived. It is also not a turnkey black-box audit for proprietary APIs because the implementation expects local likelihood access.

A responsible reuse should preregister the suspect set, generator and target checkpoint, token length, feature family, outlier rule, number of random runs, significance threshold, and multiplicity correction; run both positive and negative controls; report power and effect sizes alongside p-values; and avoid turning rejection into record-level or legal claims. The most useful replication would test independent generators, document-level splits, deliberately shifted negative controls, and text-only API constraints.
