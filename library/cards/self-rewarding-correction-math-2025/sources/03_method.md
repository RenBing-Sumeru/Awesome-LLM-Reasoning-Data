Prompt sourcing starts from NuminaMath-CoT. The paper assigns a 50K subset to self-rewarding IFT, 10K prompts to validation and model selection, and the remaining prompts to RL. The official `self_rewarding_sft_prompt` repository currently exposes 40K rows, while `self_rewarding_rl_prompt` is a separate processed NuminaMath-CoT release. No public manifest identifies the exact paper partitions, source-record revisions, duplicates, or evaluation-overlap removals.

For the main Qwen construction, Qwen2.5-Math-7B-base generates the initial solution, the self-evaluation, and any revision. The repository describes three sequential generation steps and labels outputs with a rule-based reward function. The paper uses the ToRA verification script backed by SymPy. It keeps at most one desired, correct-ending trajectory per base sample and reports about 32K trajectories, roughly balanced between correct and incorrect first attempts. The total candidates, per-stage yields, rollout count, construction temperature, seeds, and total compute are unknown.

The final Hugging Face dataset has exactly 31,990 rows in one train split. Each row exposes `gt` plus a `conversations` list of length three: a fixed system-message instruction, the user problem, and one assistant content field containing the selected long trajectory. It does not expose an upstream prompt ID, raw candidate ID, initial-correctness field, evaluation label field, revision field, trajectory type, verifier output, rejection reason, or join key. The 16.3K-row raw example and turn-level companion repositories are separate construction intermediates, not additional splits of the final dataset.

Qwen IFT packs examples into 8,192-token blocks and uses learning rate 1e-5, cosine scheduling, warm-up ratio 0.05, global batch size 32, and three training epochs; the paper selects the checkpoint after epoch one. Reported completions have a 4,096-token limit. The repository uses Axolotl for SFT and gives multiple package versions, but it has no immutable release tag or single environment lock covering the complete build. At checked commit `372bea99fec02ea7602b2c984537cb0b53262437`, `infer_math/process_prompt_turn1.py` does not parse because line 24 has an extra quote, while later preparation and PPO scripts retain unresolved user-supplied path sentinels; reproducing the pipeline therefore requires undocumented edits.

For iterative DPO, each iteration uses 20K prompts, samples multiple trajectories, and forms comparisons from correctness scores. Prompts with all-equal scores are omitted, leaving pairs for only 40% to 60% of prompts. The implementation is delegated to the separate Online-DPO-R1 repository. PPO follows a public veRL recipe and primarily uses terminal correctness; the paper also studies alternative multi-turn rewards, including one design that the policy learns to exploit by intentionally failing first and correcting later.

Evaluation uses greedy zero-shot CoT for the main Qwen results on MATH500, OlympiadBench, and Minerva Math, with Turn 1 accuracy, final accuracy, incorrect-to-correct transitions, correct-to-incorrect transitions, and class-conditional reward-model accuracy. Separate Llama experiments use a simplified two-turn format and report temperatures 1.0 and 0.7. These evaluation settings should not be copied into the unknown sequential-sampling decoding contract.
