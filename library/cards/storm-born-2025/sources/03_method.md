The evidence-backed pipeline is:

1. **Filter documents.** The paper says candidates are arXiv-hosted peer-reviewed papers published May 2023–October 2024, scored above weak accept on OpenReview, and rich in derivation language. More than five occurrences of markers such as “assume,” “derive,” and “proof” make a document likely to pass. Candidate counts, precise venues, source URLs/versions, thresholds beyond this heuristic, and rejected manifests are not reported.
2. **Extract expressions.** A lightweight multimodal model reads the document, identifies important numbered/displayed formulas, theorems, lemmas, and corollaries, removes exact LaTeX duplicates, and emits typed JSONL expressions. The authors moved away from OCR after incomplete formula-box extraction. Current code uses Gemini file/PDF input at temperature 0.0.
3. **Draft questions.** Query Draft reads the entire paper and each expression, locates prerequisite formulas/settings/symbol definitions, and writes at least one derivation or proof question that includes full dependencies rather than equation numbers alone. The reported production model is GPT-o1-Pro; Appendix B says it was used through the web UI, with papers converted to screenshots because no PDF API was available.
4. **Retrieve source answers.** Answer Retriever reads the whole document, finds the first occurrence and relevant appendix/sections, skips expressions without an answer, and extracts the complete derivation rather than inventing one. It is instructed to preserve meaning, include referenced formulas, and record an evidence location. GPT-o1-Pro is again the reported production model.
5. **Collect context and refine.** Context Collector recovers definitions, premises, and cited expressions needed to interpret the answer. Question Refiner integrates that evidence so a solver should not need the source document. Current public scripts use `gemini-2.0-flash-exp`, with temperature 0.05 for context collection and 0.0 for refinement; these code defaults are not a faithful specification of the manual GPT-o1-Pro run.
6. **Filter answer type.** Answer Filter asks `deepseek-chat` in the public code to classify a `question`/`whole_label` pair as derivation/proof versus definition/reference and keeps the former. The paper does not report classifier validation, false-accept/reject rates, or per-stage survivor counts.
7. **Apply expert selection.** Human mathematicians familiar with the source documents inspect 2,000 generated pairs, accept, reject, or revise them using reasoning type, clarity, correctness, and density, and form a top-100 set. The paper reports about 30 pairs and 15 expert minutes per paper, but the number of experts/documents and assignment/adjudication protocol are unknown.
8. **Package variants.** Publish 100 `paper`/`question`/`whole_label` rows, randomly split them 73/27, and derive four-option files. The code tree does not contain the split or distractor-generation pipeline, and the empty blank file does not instantiate the advertised fill-blank format.

Resource reporting is partial. The authors spent about USD 200 on one month of GPT-o1-Pro, about three weeks engineering prompts, and around 20 minutes of multi-agent processing per paper; failures sometimes required two or three attempts. Total candidate-paper count, token/call budget, expert hours, and compute are unknown.

The repository exposes individual agent scripts, a misspelled `pipline.py` orchestrator, cleaning/evaluation utilities, and final data. It does not preserve an environment lockfile, source PDFs, run configuration, raw/intermediate outputs, 2,000-item pool, expert history, or model revisions. It also includes a hard-coded Google credential-like string in `generate_v1.py`; this Card does not reproduce it. The `train/` directory contains images rather than training code, and the README's “typical” Axolotl command is illustrative, not an experimental manifest.
