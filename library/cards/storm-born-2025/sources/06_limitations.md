- The released source list does not follow the paper's literal selection description. It includes three named books, an older named paper, and arXiv IDs from January and February 2025 despite the stated May 2023–October 2024 window. No candidate manifest, OpenReview links/scores, venue labels, or filter logs explain these exceptions.
- Row-level grounding is too coarse for direct audit. `paper` is only a title or arXiv ID; the final file drops formula type/content, page/equation span, retrieved evidence, context, agent/model revision, retries, and human edits. None of the 100 answers retains the appendix prompt's requested `evidence:` suffix.
- The expert protocol is underspecified. The paper does not give the number of mathematicians, their topical qualifications, assignments, independence, double-review rate, agreement, adjudication, rejection counts, or revision history. It says there are five selection principles but lists only four.
- Difficulty evaluation is selection-conditioned. Experts deliberately choose the hardest 100, then report low model solve rates on those same items. This supports benchmark challenge but does not estimate performance on the generated pool or establish broad coverage.
- Automatic derivation evaluation uses DeepSeek-R1 even though the authors explicitly report that LLMs can give perfect scores to flawed derivations. No human correlation, judge version, repeatability, confidence interval, or adversarial calibration is reported.
- The 73/27 random split is not source-disjoint: 17 of 18 test sources also occur in train. Models can encounter related notation, definitions, theorem families, or document phrasing during SFT. The random seed and grouping policy are unknown.
- The 100-row choice file provides three distractors per question, but no distractor-generation script, source, validator, or human acceptance record is released. Option artifacts may make letter selection easier than producing a valid derivation.
- The 2,000-pair pool, top-500 set, separately labeled fullset, rejected candidates, and stage outputs used by the quality argument are absent. Counts before the 2,000 stage are unknown, so selection rates and failure distributions cannot be calculated.
- The code is not an exact reproduction package. Reported GPT-o1-Pro stages were manual web interactions with screenshot uploads, while public scripts default to Gemini and DeepSeek; dependencies are unpinned, the orchestrator filename is misspelled, and no run config/source PDFs are included.
- A generation script contains a hard-coded Google API-key-like credential. It should be considered exposed/revoked and replaced with environment-based secret loading; the value is intentionally omitted here.
- The README claims MIT, but the repository contains no LICENSE file and GitHub detects no license. Final answers extract or lightly edit third-party paper/book text, while rows lack source-license and attribution metadata. Public accessibility does not by itself grant redistribution or commercial-training rights.
- The paper claims freshness helps avoid contamination, but reports no exact, near-duplicate, semantic, or memorization audit. Later/older sources in the live release and document overlap across train/test make `decontamination` remain unknown.
