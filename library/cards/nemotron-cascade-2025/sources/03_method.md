
SFT has two length stages. Stage 1 trains for one epoch at 16K on general-domain data and thinking-only math, code, and science responses. Stage 2 trains for one epoch at 32K, recombining general data with longer math/code/science traces, tool-calling conversations, instruction-following records, and SWE localization, repair, and test-generation examples. DeepSeek-R1 is the main Stage-1 reasoning generator; DeepSeek-R1-0528 generates longer Stage-2 reasoning and SWE responses; DeepSeek-V3 variants provide general-domain modes; Qwen3-235B-A22B supplies tool-calling responses.

Construction is domain-specific. Math SFT uses AceReason-Nemotron-1.1-derived prompts, length filtering, multiple teacher responses, and 9-gram benchmark filtering. Code SFT draws from TACO, APPS, OpenCoder-Stage-2, and OpenCodeReasoning, deduplicates prompts, generates multiple responses, and applies 9-gram filtering. Science combines S1K and Llama-Nemotron post-training sources, rejects option-analysis-style questions, synthesizes rarer variants, and performs benchmark filtering. SWE uses SWE-Bench-Train, SWE-Fixer-Train, SWE-reBench, and SWE-Smith; repositories appearing in SWE-bench Verified are removed, and cross-source duplicates are matched by repository plus base commit.

The RL scaffold is strict on-policy GRPO in verl. Each iteration samples a response group from the current policy and performs one update; importance ratio is therefore one. The objective uses group-normalized rewards and token-level loss with no KL term. The cascade is RLHF -> IF-RL -> Math RL -> Code RL -> SWE RL. RLHF uses preference-data prompts with math and competitive programming removed. IF-RL uses two progressively harder constraint taxonomies. Math RL filters unsuitable, noisy, trivial, and unsolved questions. Code RL filters special-judge tasks, weak tests, duplicates, benchmark overlaps, trivial problems, and problems unsolved by the stronger difficulty model.

SWE separates easier supervised instances from harder RL instances by patch-similarity success among DeepSeek-R1-0528 samples. RL prompts contain ground-truth localization files, optionally mixed with noisy retrieved files; short prompts are discarded. The reward combines lexical and Kimi-Dev-72B semantic similarity to the human patch, so no Docker execution is used during SWE RL. For 8B, input context extends from 16K to 24K while output remains 16K; 14B uses a 32K input and 16K output.

The public collection verifies many inputs and checkpoints but not a complete run. It visibly includes Stage-1/Stage-2 SFT, SFT-SWE, RL-Math, RL-SWE, RL-RLHF, RM-Training, final weights, a 72B RM, and 8B intermediate checkpoints. Dedicated IF-RL and Code-RL datasets, exact verl commits/configurations, policy rollout groups, component rewards, dynamic-filter ledgers, seeds, and optimizer states are unknown.
