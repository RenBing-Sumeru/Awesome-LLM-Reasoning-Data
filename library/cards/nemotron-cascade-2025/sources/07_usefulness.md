
For `frontier_reports_data_disclosure_ledger`, Nemotron-Cascade is useful as a layered audit case. Layer one is the report: it names sources, generators, filtering, stage order, reward functions, and many hyperparameters. Layer two is released training input: several SFT, preference, math, and SWE repositories are downloadable. Layer three is model state: final weights, a 72B RM, and 8B intermediate checkpoints are official. Layer four is evaluation: benchmark tables and cached evaluation materials describe model behavior. Evidence in one layer does not make another complete.

Data builders can reuse the design principle of matching feedback to domain, but should preserve the contract explicitly. An auditable implementation would retain prompt source/revision, teacher and policy revision, all candidates, acceptance/rejection reason, verifier version and output, component rewards, group membership, dynamic-filter decisions, seed, and checkpoint step. It should also distinguish a functional code test from answer matching, constraint checking, preference scoring, or patch similarity.

Auditors can pin every dataset and model revision; independently count rows by configuration; reconcile counts with the paper; check whether dedicated IF-RL and Code-RL inputs are available; sample SFT-to-RL disjointness; replay math extraction and code tests; evaluate the scalar RM out of distribution; and compare execution-free SWE rewards with actual repository test outcomes. Rights and benchmark-overlap checks should be repeated for the reuser's own evaluation suite.

The model scores should not be used as a data-quality proxy. A responsible reuse decision depends on lineage, verifier error, contamination, rights, and whether the released object is a prompt set, supervised response set, preference pair set, policy rollout, or only a model checkpoint.
