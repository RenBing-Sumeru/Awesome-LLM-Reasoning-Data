
The one-sentence contribution is: replace joint multi-domain RL with a fixed cascade whose data, rollout budget, and feedback contract are specialized by stage. After two-stage SFT, the reported order is RLHF -> IF-RL -> Math RL -> Code RL -> SWE RL. General alignment is trained before narrower verifiable domains, and response/context budgets expand where longer reasoning or repository context is required.

The feedback object changes at every step. RLHF assigns a scalar score with Qwen2.5-CascadeRL-RM-72B. IF-RL checks explicit instruction constraints and dynamically removes prompts that provide no gradient. Math RL gives binary answer reward using the AceMath verifier, with an additional code-switching penalty. Code RL executes generated programs and rewards only all-tests-passed outputs. SWE RL does not execute patches: it combines Unidiff lexical similarity with Kimi-Dev-72B semantic comparison against the human patch.

This stage-specific design is the reason for inclusion in `frontier_reports_data_disclosure_ledger`. It exposes more of the feedback chain than a weights-only report and provides 8B checkpoints after SFT, RLHF, IF-RL, Math RL, and Code RL. The relevant comparison is not whether Cascade RL uses a new optimizer--it uses strict on-policy GRPO in verl--but whether separating heterogeneous domains makes the recipe and its failure surfaces easier to inspect.
