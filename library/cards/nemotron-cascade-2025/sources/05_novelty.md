
Sequential domain-wise RL is not new in isolation: the authors' earlier math-to-code work already used a cascade, and RLHF, GRPO, rule-based verification, program execution, and learned judges are established components. The report's distinguishing move is to scale this composition across alignment, instruction following, mathematics, competitive programming, and software repair while exposing intermediate checkpoints and many training inputs.

The direction signal is the explicit match between domain heterogeneity and feedback design. A slow execution verifier does not share the same infrastructure or error profile as a scalar preference model; a constraint checker can reward a formally compliant but poor answer; a patch-similarity judge scales without containers but ceases to be functional verification. Cascade RL makes those differences first-class curriculum decisions instead of hiding them behind one mixed reward label.

The release is unusually inspectable for a frontier report because weights, a scalar RM, intermediate checkpoints, and several data stages are all official artifacts. Its quality signal is disclosure breadth, not benchmark dominance. The remaining gaps--missing dedicated datasets for some described stages, count mismatches, absent rollouts and decisions, and unpinned code--are part of the novelty assessment rather than details to suppress.
