TerminalWorld's central contribution is to turn a public terminal demonstration into an executable evaluation contract: a goal-focused instruction, a cleaned Bash reference solution, a reconstructed Docker environment, and state-based tests that judge the resulting persistent state. The original transcript supplies behavioral evidence for construction, but an evaluated agent may take a different valid route (Paper §§3.2–3.4 and 5.4).

The construction object and evaluation episode must be separated. The released object stores the task specification, reference solution, environment artifacts, and verifier. At evaluation time, a new episode contains the instruction, environment state, agent shell commands, stdout/stderr and other observations, resulting state changes, and a terminal resolved/failure outcome. The release does not attach correctness to each command and does not publish the paper's complete successful and failed evaluation trajectories in its top-level manifest.

The feedback contract is both environmental and programmatic. Docker execution supplies state transitions; the task-specific test suite observes persistent pre/post conditions and artifacts after the episode. Admission uses a three-way sensitivity check: the complete reference solution must pass every test (`AllPassing`), a no-op must fail every test (`Nop`), and each truncated or ablated partial solution must make at least one test fail (`Partial`). A zero-exit reference replay at the earlier environment gate is necessary but is not the final correctness predicate (Paper §§3.3–3.4).

The verifier can accept behaviorally different command sequences when they reach the tested state, which is consistent with the reported 21.4% median human-agent command-set overlap. It cannot certify untested side effects, semantic requirements omitted by a test, absence of verifier gaming, or equivalence of every alternate valid final state. “Verified” means 4 experienced authors manually reviewed label correctness for 200 selected tasks; the paper explicitly distinguishes this from formal proof that the tests completely specify semantics (Paper §4.2 and the §1 footnote).

The closest paper-level comparison is Terminal-Bench. TerminalWorld changes the task-sourcing and construction surface by deriving tasks from public real-world terminal recordings, packaging reproducible environments, and validating generated tests against reference/no-op/partial behavior. Docker tasks, programmatic tests, and terminal-agent evaluation are not individually new; the direction signal is the explicit coupling of provenance, environment reconstruction, outcome verifier, and replay risk.
