- **Verifier coverage and gaming:** state tests observe only predicates encoded by the task suite. Missing conditions can yield false positives, overly strict expectations can reject alternate valid states, and public tests can invite verifier gaming. Reference/no-op/partial validation improves sensitivity but does not report task-level false-positive/false-negative rates or adversarial robustness. This is a curator risk inference from the disclosed feedback contract.
- **Evaluation infrastructure:** Harbor/tmux races, container-startup timeouts, and third-party-agent installation failures create non-task errors. About 10% of tasks use end-of-life Ubuntu, CentOS, or Debian images; mutable package mirrors, cached images, `force_build` behavior, and unpinned base-image digests can change outcomes without a change in agent reasoning (Appendix C).
- **Version and taxonomy drift:** arXiv v1 reports 18 categories, the stable README reports 19, and the checked live manifest contains 20 `terminal_domain` values. GitHub `main` and HF `main` are mutable, no tagged GitHub Release exists, and no task-archive hash manifest binds the paper, code, data rows, images, tests, and evaluator versions.
- **License conflict:** the HF card metadata/prose says CC BY 4.0, while the HF `LICENSE` file and all 1,530 checked manifest rows say CC BY-NC 4.0; Appendix A further restricts use to strictly non-commercial academic research. The arXiv paper's CC BY 4.0 distribution license applies to the paper, and the GitHub Apache-2.0 license applies to code; neither resolves dataset terms or rights inherited from source recordings.
- **Lineage and source removal:** Appendix A says the release distributes direct hyperlinks to source recordings rather than raw `.cast` files, but the current 8-field manifest has removed `source_url`, as reflected in HF history. Whether individual task archives retain verifiable source links is unknown. This weakens record-level provenance, source-removal handling, consent review, and right-to-be-forgotten auditability.
- **Construction opacity and failure retention:** current scripts expose model and budget defaults, but the exact production models, prompts, temperatures, seeds, overrides, retries, repair steps, discard decisions, and logs are unknown. Rejected candidates, full repair histories, and complete successful/failed evaluation trajectories are not available in the top-level manifest, limiting selection-bias and hidden-teacher-trait analysis.
- **Privacy and contamination:** regex/LLM filters for PII, credentials, and malicious commands reduce known risks but cannot establish complete removal. The canary warns against training use but is not a deduplication or model-exposure audit; no reproducible item-level, training-corpus, or downstream-benchmark decontamination procedure with thresholds is disclosed.
- **Generalization:** Verified-200 is intentionally complexity/diversity selected. Its 49.0%–62.5% reported pass-rate range is conditional on the selected tasks, tested models, 6 scaffolds, mutable environments, and paper-era harness. Benchmark performance is not proof of data quality or an unbiased estimate for the full release.
