**Reuse class: evaluation/inference recipe and audit reference; not cleared for training-data reuse.** Builders can use the repository to compare a fixed global cap, planning-only prompt, uniform allocation, and credit-weighted schedules under matched task/model conditions. Record planning tokens, target-model tokens, endpoint/model revision, schedule, and per-item score rather than only E3.

For the assigned rollout/search/test-time-trace track, the useful unit is the episode schema: retain original item identifier and version, decomposition prompt/output, credits, level budget, actual API usage, final prediction, evaluator version/output, and failures. This converts an allocation claim into an auditable trace record and makes it possible to separate planner effects from budget effects.

For evaluation design, MATH's programmatic answer check is more reproducible than TravelPlanner's LLM JSON conversion, but neither establishes safe reward use without false-positive/negative testing. For production use, implement an actual token-enforcement mechanism if needed, test schedule sensitivity and credit calibration, and keep benchmark prompts separate from any subsequent training mixture.
