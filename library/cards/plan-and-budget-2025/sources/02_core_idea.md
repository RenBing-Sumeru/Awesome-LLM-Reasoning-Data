The contribution is a training-free, model-agnostic test-time scaffold: Plan converts a query into ordered sub-questions with hints, and Budget uses their inferred difficulty/credits plus a schedule to tell the target model how much to reason on each part. The theoretical Budget Allocation Model (BAM; called BBAM in parts of the paper) motivates allocating more compute where uncertainty is higher; the implementation is a prompted allocation policy, not a learned verifier or reward model.

The feedback contract is mixed and task-level. MATH-500 uses parsed-answer checking with `math_verify`; NaturalInstructions uses ROUGE-L; TravelPlanner uses a secondary LLM to turn text into JSON before the TravelPlanner scorer. E3 = A^2 / T combines the resulting task score A and average billed completion tokens T. None of these signals tells the system whether an individual intermediate sub-question was correct; credits guide allocation but are not verified process labels.

The closest comparison surface is fixed global budgeting and planning-only baselines. Plan-and-Budget differs by making the allocation depend on sub-question credits and an optional decay schedule. It belongs in rollout/search/test-time trace data because the allocation metadata mediates between an input and a scored completion, even though raw author-run traces are not released.
