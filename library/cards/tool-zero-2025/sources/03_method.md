Inputs come from offline function-calling records. ToolACE supplies the main Tool-Zero-7B/32B training setting; xLAM is used for data/backbone generalizability analysis and is augmented with the separately linked 7.5K irrelevance subset. Records are dropped when calls cannot be parsed as JSON or Python code or candidate-tool lists cannot be parsed as JSON. Table 2 reports, after processing, xLAM with 67,500 single-turn and 10,254 augmented multi-turn records, and ToolACE with 97,300 single-turn and 1,966 multi-turn records. Record IDs, exact revisions, split manifests, rejection counts, and deduplication are unknown. (Paper §4.1, Table 2)

The multi-turn construction has four reported transformations: concatenate related single-turn dialogues; remove a tool and later reintroduce it; mask a parameter so the model must request clarification; and perturb or remove calls, parameters, or values so the model must validate results. Function and parameter names are also replaced with generic identifiers to reduce reliance on names. The model receives the user query or history plus candidate schemas and generates natural-language thought followed by serialized calls; offline history may contain observations, but the training recipe does not report online tool execution.

Each completion is scored by the format bit, early overlap reward, late exact-AST reward, multi-tool bonus, and invalid-parameter penalties. GG-GRPO sigmoid-mixes the general and strict tool rewards over training, normalizes rewards within a sampled group, and applies the resulting advantage to the whole completion. There is no critic, learned reward model, LLM judge, process label, tree search, or released environment-state terminal predicate. KL regularization is removed.

The named models initialize Qwen2.5-7B Base and Qwen2.5-32B Base; Appendix D also studies 1.5B and 3B. The canonical ACL appendix reports `kappa=0.1`, midpoint `25`, eight rollouts per prompt, temperature `0.8`, global batch `128`, mini-batch `1024`, learning rate `5e-7` with cosine decay, tensor parallel size `4`, clip epsilon `0.2`, maximum prompt and response lengths `2048/2048`, vLLM, and up to 28 hours on `5 × 8` Ascend 910B NPUs. The earlier OpenReview appendix reports four rollouts, so reproduction must pin the paper version.

Conceptual outputs are Tool-Zero checkpoints and completion-level reward records. No Tool-Zero checkpoint, processed corpus, record manifest, GG-GRPO implementation, paper-specific config, dependency lock, train/eval entry point, or evaluation output was verified. MindSpeed-RL is the cited optimizer framework only: checked repositories expose generic GRPO infrastructure, not a Tool-Zero/GG-GRPO reproduction. Faithful reconstruction therefore requires implementing the reward, pinning data and benchmark versions, and preserving successful, failed, malformed, and rejected records.
