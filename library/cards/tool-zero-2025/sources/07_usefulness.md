For `environment_agent_trajectory_data`, Tool Zero is useful as a specification for an auditable offline tool-use training record: preserve the query/history, candidate schemas, natural-language thought, selected tool subset, serialized calls, any supplied observations, ground-truth call, reference AST, every reward component, final scalar, source revision, augmentation provenance, and rejection status. The formal trajectory additionally suggests fields for environment/user observations, but those should not be invented for records that never executed tools.

For `training_usage_optimization_objectives`, the paper provides a controlled design target for reward-curriculum ablations: fixed overlap versus fixed AST reward, scheduled GG-GRPO, format reward removed, multi-tool bonus removed, name masking on/off, and each multi-turn transformation separately. Researchers should add semantic-equivalence tests, alternative valid calls, executable environment checks, reward-gaming probes, and retained failures before treating the rule verifier as reliable.

The paper is also an audit case study. Compare the public 11,300-row ToolACE subset with the 99,266 records reported for training; pin ACL versus OpenReview settings; distinguish a framework URL from method code; reconcile Tables 4, 5, and 9; and report sample-level train/evaluation overlap rather than tool-set overlap alone.

Reuse class: **reading/audit reference and reconstruction recipe; paper-specific training reuse is blocked pending verification**. The verified upstream ToolACE/xLAM datasets may be studied under their own cards and licenses, but they do not reconstruct the Tool-Zero corpus. The reported benchmark surfaces can guide evaluation design, yet no pinned Tool-Zero evaluation package or checkpoint is available.
