Tool Zero's central mechanism is GG-GRPO: direct GRPO from Qwen2.5 Base models with a scheduled programmatic reward that starts with partial reference-token overlap and gradually shifts to exact reference-AST equivalence. “Pure RL” therefore means no SFT initialization; it does not mean label-free learning, because ToolACE/xLAM reference calls remain inside the reward contract. (Paper §4.2–4.3, Eqs. 2–9)

The feedback attaches once to the generated completion. The final scalar is `R_final = R_format + R_tool`. The format component checks the ordered presence of the required think/answer delimiters. Early `r_general` gives partial credit from delimiter-token overlap with the reference in the range `[-0.5, 0.5]`; late `r_strict` is `1` only when the generated AST equals the reference AST. A sigmoid with reported `kappa=0.1` and midpoint `25` mixes the two, while multi-tool collaboration adds `0.3` and each invalid parameter value incurs a `0.3` penalty.

This verifier can observe output-format compliance, surface-token overlap, one-reference AST equivalence, multi-tool usage, and invalid reference parameter values. It cannot observe whether an alternative call or tool plan is semantically equivalent, whether the call succeeds in a live environment, whether the final world state satisfies the user's goal, or which reasoning step is correct. The supervision is therefore `full_episode` plus `scalar_reward`, not step-level process supervision.

Relative to vanilla GRPO and SFT baselines, the paper changes reward strictness during training and combines it with direct base-model RL. Tool-name masking and reference-based call scoring build on existing function-calling practice; ToolACE/xLAM, Qwen2.5, GRPO, AST matching, and MindSpeed-RL are not introduced by this work. The closest data/model comparisons reported are ToolACE and ToolRL, but the claimed value is the scheduled feedback contract rather than a new corpus.
