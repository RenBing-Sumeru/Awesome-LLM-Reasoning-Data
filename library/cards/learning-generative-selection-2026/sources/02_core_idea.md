The construction converts Best-of-N aggregation into a programmatically rewarded RL task. Qwen3-1.7B first supplies candidate solutions; Math-Verify-based symbolic checking labels math candidates, while provided OpenCodeReasoning unit tests label code candidates. A GenSelect prompt asks the same-size selector to compare all candidates and end with an index. DAPO rewards the selector when that index points to any candidate labeled correct. Candidate labels can therefore be precomputed, unlike synthesis-based aggregation where each newly generated answer must be verified online. The contract remains candidate-set conditional: the policy is trained to choose among supplied candidates, cannot repair an all-wrong pool, and inherits every false positive or false negative produced by the automatic verifier.
