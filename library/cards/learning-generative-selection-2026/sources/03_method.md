For mathematics, the authors start from 37K OpenMathReasoning problems on which Qwen3-1.7B has below-50% pass rate under a Math-Verify-based symbolic verifier. They sample two to sixteen Qwen3-1.7B solutions per prompt, retain sets containing at least one correct candidate but no more than 50% correct candidates, and resample up to four sets per problem. For code, they use OpenCodeReasoning problems and provided tests, execute Qwen3-1.7B candidates to obtain binary labels, and apply the same at-least-one-correct and at-most-50%-correct rules. Prompts over 16K tokens are discarded; code candidate responses over 12K tokens are also discarded. The paper does not report the code-problem count, final constructed-prompt count, candidate-generation temperature, manifest, seeds, or rejected-item log.

Separate Qwen3-1.7B math and code selectors are trained on NVIDIA H100 GPUs with VeRL and on-policy DAPO. The reported batch size is 128, learning rate 1e-6, and optimizer AdamW. Each math prompt receives 16 selector rollouts and each code prompt receives 8; selector sampling uses temperature 1.5, top-p 1.0, and a maximum output length of 16,384 tokens. These rollout counts describe on-policy selection attempts per prompt, not candidate-pool size. Evaluation uses the same GenSelect prompt and averages results over eight runs on AIME24, AIME25, HMMT25, and LiveCodeBench v6.
