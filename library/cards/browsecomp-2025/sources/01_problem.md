BrowseComp asks how to evaluate browsing agents after common factual QA and retrieval benchmarks have become too easy for systems that can search the live web. OpenAI released the benchmark on 10 April 2025; the arXiv record, *BrowseComp: A Simple Yet Challenging Benchmark for Browsing Agents* (arXiv:2504.12516), was first submitted on 16 April 2025. The paper studies original BrowseComp only. BrowseComp-Plus and other later derivatives are separate records, and none of their corpus, evidence, citation, or replay properties is transferred here.

The benchmark contains 1,266 human-authored, hard-to-find factual questions with intended short, stable answers. A released row has exactly four fields: obfuscated `problem`, obfuscated `answer`, plaintext `problem_topic`, and plaintext `canary`. The official CSV contains 1,266 rows, not browser actions, queries, page observations, source URLs, citations, timestamps, confidence records, or successful and failed run logs. During evaluation, a model produces a free-form response with an `Exact Answer` and confidence, and an LLM judge compares that response with the single reference answer.

It belongs in `environment_agent_trajectory_data` because it measures agents that interact with the changing live web and because its missing environment contract is itself important to audit. It is not a released trajectory corpus, citation benchmark, replayable browser environment, or training recipe. The verified paper, appendix, OpenAI release page, official CSV, and `simple-evals` code support an L4 bilingual Card, while the undisclosed paper grader, absent run traces, unpinned web substrate, and current scorer defect keep the accepted metadata at `L3_summary_ready` and the reuse class at evaluation/audit only.
