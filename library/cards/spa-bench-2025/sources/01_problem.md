The canonical source is the ICLR 2025 Spotlight paper. SPA-Bench evaluates smartphone agents on 340 bilingual Android tasks: 300 single-app and 40 cross-app tasks, evenly divided between English and Chinese. This yields 150 English and 150 Chinese single-app rows plus 20 English and 20 Chinese cross-app rows. The paper reports 39 English and 29 Chinese apps, while repository accounting reports 66 distinct apps—52 third-party, 7 Google, and 7 system apps. These are different counting views and should not be collapsed.

The concrete problem is that a mobile task is not fully represented by a text instruction or a final action label. Agents interact with changing Android applications through screenshots and sometimes XML, accessibility, OCR, icon, or marked-screen representations; they tap, swipe, type, navigate, and declare completion. Success depends on device/app/account state, action history, visible UI, external services, termination behavior, and an evaluator that can interpret flexible end states.

A released task row includes task ID, app scope, language, description, difficulty, human golden-step count, and for single-app tasks final key components plus package/activity. Cross-app rows add category and ordered app list. The repository also releases 40 per-task JSON files with ordered app-specific subtasks and `history`/`memory` fields. Human annotators created reference screenshot trajectories with 1 action between adjacent screenshots, but those demonstrations are not in the audited release.

An executed episode would contain ordered screenshots, optional action data, `log.json` or `error.json`, step and golden-step ratio, finish/exit signals, execution time, API cost, success/failure/error label, evaluator details, and termination reason. The framework can write this schema locally, yet the repository publishes no human screenshot trajectories, paper-run agent traces or results, rerun ledger, or successful/failed trajectory corpus.

SPA-Bench therefore belongs to both `environment_agent_trajectory_data` and `benchmarks_evaluation_surfaces`: it defines an ADB-connected state/action/observation environment and a mixed OCR/GPT-4o outcome contract. Demonstrated use is evaluation and diagnostic audit only. No SPA-Bench SFT/RL run, optimizer, reward stream, or trained checkpoint is released.
