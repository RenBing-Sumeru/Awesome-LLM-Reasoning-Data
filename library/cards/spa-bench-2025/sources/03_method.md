Task construction begins with common system, Google, and third-party apps. Annotators author or standardize daily-use instructions; most English cross-app tasks come from GUI Odyssey, with descriptions reformatted and trajectories recollected when needed. For each task, humans execute a reference screenshot sequence with 1 action between adjacent screenshots, count golden steps, and annotate final-state key text for single-app tasks. MLLM-generated cross-app subtasks with `history`/`memory` are human-reviewed.

Annotators cross-check instruction clarity, reference-trajectory accuracy, and final key components, then test tasks across Android devices, Android versions, and app versions and revalidate before experiments. The release contains the final 4 CSV strata and 40 cross-app JSONs, but not candidate/rejection decisions, annotator assignments, disagreement records, validation logs, or record-level GUI Odyssey attribution.

During evaluation, the multiprocessing framework connects an integrated agent to an emulator or physical device over ADB. The agent observes screenshots and any agent-specific XML/accessibility/OCR representation, issues taps, long presses, swipes, text input, navigation, or composite actions, and generates local screenshots/logs. Paper runs allow at most 2 times the human golden steps; current example config `MAX_ROUNDS: 0` must not be substituted for that paper protocol.

Execution stops on self-reported completion, maximum steps, or error. Unexpected network, Android, or CAPTCHA failures are automatically rerun; invalid actions and expected agent limitations count as agent errors. The paper does not release attempt counts, seeds, or a rerun selection ledger, so the boundary between instability and agent failure cannot be reconstructed.

Evaluation is separate from execution. Single-app runs pass through reverse-order PaddleOCR key matching and then GPT-4o judgment. Cross-app runs undergo ordered-app segmentation, sequential subtask judgment, and memory propagation. The local framework records `S`, `F`, or `E`, details, screenshots, steps, time, cost, finish/exit fields, and evaluator output; it can resume incomplete sessions. None of the paper-run results or trajectory directories is public.

Reset is cycle-level rather than proven per-task isolation. The paper restores a snapshot at each experimental cycle and resets emulators after assigned tasks; state stored by external services may require manual cleanup. WhatsApp/OneNote English tasks and most Chinese tasks use physical devices without snapshot support. Public code can clone a user-supplied AVD and launch copies with `-no-snapshot-save`, but the repository supplies no AVD/snapshot blob, APK/app/account manifest, or complete environment image.
