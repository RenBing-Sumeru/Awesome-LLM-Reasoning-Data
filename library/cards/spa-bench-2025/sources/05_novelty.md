Prior mobile-agent benchmarks often emphasize one app family, one language, fixed action matching, or final task success. SPA-Bench's concrete contribution is a bilingual 340-task live-app evaluation surface combining 300 single-app and 40 cross-app tasks, multiple observation/action interfaces, human golden-step references, and outcome judgments that tolerate different action sequences.

The verifier is a substantive part of the benchmark object. Single-app evaluation combines an OCR key-component gate with GPT-4o judgment; cross-app evaluation adds expected-app segmentation, sequential subtask checks, and propagated memory. Completion is evaluated separately from success, enabling premature and overdue termination analysis. These choices are more than a leaderboard wrapper because they define which screenshots, paths, and states count.

The data-release novelty is narrower than the paper's data-collection description. Public artifacts contain 340 task rows, 40 human-reviewed cross-app subtask JSONs, task/evaluator configs, and execution/evaluation code. Human reference screenshot trajectories, the 11-agent experimental runs, success/failure outputs, rerun histories, and device snapshots are described but not released. The method should not be cited as a public screenshot-trajectory dataset.

Most English cross-app tasks draw from GUI Odyssey, with descriptions reformatted and trajectories recollected when needed. This is source adaptation, not wholly independent task origin. Because public records omit record-level source IDs and no overlap matrix is available, the degree of semantic reuse cannot be measured.

For reasoning-data research, the direction signal is that environment state, termination belief, screenshot evidence, OCR gates, MLLM judgment, rerun selection, and reset policy jointly define the label. Before reuse, one must separate agent failure from infrastructure reruns, pin device/app/account/evaluator versions, test judge robustness, disclose source overlap, and clear rights and side effects.
