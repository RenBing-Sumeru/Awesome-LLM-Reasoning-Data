SPA-Bench's central mechanism is to pair a bilingual task collection and live Android execution harness with outcome evaluation that does not require exact action matching. An agent receives a natural-language instruction, observes the device through its own supported representation, executes device actions through ADB-integrated tooling, and stops on self-reported completion, the action budget, or error.

For single-app tasks, PaddleOCR scans screenshots in reverse order for every annotated final-state key component. Only trajectories passing this coarse gate reach a GPT-4o evaluator, which sees the task, screenshots, and optionally action information. A trajectory with 0 screenshots receives error `-1`. The design can recognize multiple action paths, but OCR strings alone cannot prove the intended state transition and the model judge remains probabilistic.

For cross-app tasks, GPT-4o first segments the screenshot trajectory by the expected ordered apps, rejects missing, invalid, or out-of-order segments, then judges human-reviewed subtasks sequentially. MLLM-extracted memory can propagate between subtasks. This supports multi-app dependencies, while encoding the expected app order and model-generated memory into the verifier contract.

The primary signal is binary success or failure, supplemented by successful-run step ratio, termination reason, premature/overdue termination, execution time, and API cost. Completion belief is separate from evaluator success, exposing agents that stop too early or keep acting after success. This is a terminal evaluation score, not a demonstrated policy-training reward or step-level correctness label.

The contribution is the coupling of multilingual live-app tasks, heterogeneous observation/action interfaces, human golden-step references, mixed deterministic/model evaluation, and termination diagnostics. It does not release the human demonstrations or experiment episodes, and it does not solve immutable mobile-state replay. The released reusable object is the 340-task definition, 40 cross-app subtask JSON files, framework/evaluator code, and local output schema.
