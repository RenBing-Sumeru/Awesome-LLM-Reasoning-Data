The central contribution is a longitudinal, user-conditioned mobile episode object that supports two different predictions: infer the user's likely current intent from profile/history/context, or predict the next GUI action from the current intent, phone state, action history, and a retrieved same-user demonstration. The same human episode therefore acts as an SFT target and as the source of benchmark inputs and references (Paper §§3–5).

For proactive suggestion, the input contains the user profile, timestamp, scenario, up to 20 previous intents, and zero to three initial screenshots; the output is one Chinese sentence naming the app and desired final effect. For personalized execution, the model receives the current intent, profile, screenshot, accessibility elements, executed-action history, and one earlier same-user action sequence retrieved by intent similarity, then emits one action in a live ADB loop. The stored `app/activity` launches the app for evaluation but is not exposed to the agent (Paper §§3.1–3.2, §5.1, Appendix A.7; official scripts).

The feedback contract is mixed. Suggestion uses `Sim1`, the average of multilingual sentence-embedding cosine similarity and Levenshtein similarity, plus `SR1`, a DeepSeek-V3 binary same-intent judgment. Execution uses manually inspected final-state success (`SR2`), automatic failure beyond 2.5 times the human demonstration length, an action-sequence personalization ratio (`Sim2`), and a step ratio. These signals can observe semantic resemblance, path resemblance, budget compliance, or a human-perceived final state; they do not provide a released dense reward, automatic per-step correctness, or a public executable success predicate. The proactive script omits `SR1`, while the execution script has no manual adjudicator and writes `success=0` (Paper §5.1; official scripts).

Compared with generalist mobile-agent systems evaluated in the paper, including UI-TARS-1.5-7B on execution, FingerTip 20K changes the data and evaluation surface rather than proposing a new agent architecture: longitudinal user identity, profile, time/scenario, prior intents, and retrieved same-user behavior become explicit inputs. Its distinguishing direction is personalized and proactive mobile-agent data, not a new Android action vocabulary or an automatically verified environment.
