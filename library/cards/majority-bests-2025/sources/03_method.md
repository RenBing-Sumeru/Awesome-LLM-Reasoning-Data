
The paper evaluates five 500-question benchmark slices: MATH500, GSM8K, MMLU-Pro-Math, MMLU-Pro-Chem, and CommonsenseQA. It generates 512 outputs per question at temperature 1 with Qwen2.5-3B-Instruct, Llama-3.1-8B-Instruct, or Gemma-2-9B-it, then scores them with ArmoRM-Llama3-8B-v0.1 and GRM-Llama3.2-3B-rewardmodel-ft. Language Model Evaluation Harness performs final-answer extraction and correctness evaluation. Main tables use N=128; for each budget N, the evaluation takes floor(512/N) disjoint slices from the cached pool. The paper studies fixed m=floor(sqrt(N)) and an adaptive rule that compares closed-form answer distributions for candidates floor(q^j N) with q=0.75. Selection runs on CPU and does not train the generator or reward model.

The official Git LFS release is organized by benchmark and generator. A checked JSONL record contains `doc_id`, the full `prompt`, the full `generation`, binary `generation_score`, extracted `generation_final_answer`, and a `rewards` dictionary with `grm3b`, `armorm`, and `skywork` values. The runner groups records by `doc_id`, forms arrays of final answers, rewards, and correctness scores, and can save per-problem decisions. Pools contain up to 512 outputs per question; the README exposes budgets up to 512 and scripts for BoN, self-consistency, Weighted BoN, and both MoB variants.

The release also lists a MATH500 GPT-4o-mini pool. It is an additional cached artifact rather than one of the three main open-generator settings described above, so its provenance and use should be tracked separately.
