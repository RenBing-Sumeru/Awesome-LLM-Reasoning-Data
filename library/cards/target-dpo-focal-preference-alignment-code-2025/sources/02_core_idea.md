The paper proposes Target-DPO and constructs CodeFlow by iteratively generating, locating failure regions, and revising code until tests pass. Changes between adjacent versions form fine-grained preferences, and training emphasizes tokens associated with the actual repair. CodeFlow releases roughly 59K code-preference records centered on a failing version, its subsequent repair, test feedback, and modified error region for the same problem. Samples arise from iterative test-driven refinement rather than comparing pass rates of independent completions. Data and training code are released with Target-DPO for code DPO and repair learning.
