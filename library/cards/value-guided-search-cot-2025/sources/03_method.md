**Inputs and pre-filtering.** Start from the 94K-problem default split of OpenR1-Math. After manually inspecting 100 sampled problems, the authors define rules that require exactly one parseable boxed answer and automatic verification, and remove multiple-choice, multipart, link-containing, ambiguous, or otherwise unverifiable tasks. The released OpenR1-Cleaned corpus has 49,394 rows: 48,394 train, 500 validation, and 500 test (Paper §2.2; Appendix D; official dataset card).

**Roll-ins, cuts, and rollouts.** For each cleaned prompt, sample 14 independent roll-ins from DeepSeek-R1-Distill-Qwen-1.5B, 7B, 14B, and 32B. The exact allocation across those four sizes is not disclosed. Draw four prefix locations per roll-in using the paper’s square-root-weighted cut-index distribution, then complete each prefix with the fixed DeepSeek-R1-Distill-Qwen-1.5B policy. This produces 56 pairs per prompt and 2.8 million pairs before post-filtering. Data-generation temperature, top-p, and random seeds are unknown.

**Verification, filtering, and serialized output.** Parse the final boxed answer and compare it with the ground truth through `math-verify`. Encode finished-incorrect as class 0, finished-correct as class 1, and incomplete/max-length as class 2; only class 1 has reward 1. Remove an entire prompt group when all 56 rollouts are incorrect or incomplete, eliminating roughly 10% of problems and leaving about 2.5 million pairs. OpenR1-VM exposes one 44,509-row train split with `message_id`, `problem`, `solution`, `answer`, `reward`, `roll_in_ids`, `roll_outs_ids`, `processed_answer`, and `labels`. It preserves negative outcomes within surviving groups, not the pre-filter rejects, all-failure groups, or a complete rejection manifest.

**Value-model training.** Initialize a 28-layer, hidden-size-1536 classifier from DeepSeek-R1-Distill-Qwen-1.5B, replace the LM head with a two-layer, three-class MLP, and apply cross-entropy at every rollout token using the terminal class. The paper’s final run uses 5 epochs, total batch size 1024, AdamW, cosine schedule with maximum learning rate \(10^{-4}\), and 16 nodes × 8 H100 GPUs for about 24 hours. It reports 35.7B total tokens and 14.4B loss-bearing tokens per epoch (Appendix E, Table 4). The repository’s four-GPU command is an example, not the reported final run.

**Search and evaluation.** Use SGLang to generate at most 16,384 tokens with temperature 0.6 and top-p 0.95. VGS expands 4,096-token blocks, scores the new prefixes, maintains beam width 2, uses budget-dependent DVTS, and returns a weighted-majority-vote answer. Here \(N\) is the number of generations/blocks sampled in parallel, swept from 4 to 1024; it must not be confused with the 56 training pairs per prompt. The headline generator budgets are \(N=256\), 128, and 64 for the 1.5B, 7B, and 14B generators.

**Reproduction and release checks.** Pin arXiv v2, the GitHub revision, OpenR1-Cleaned/OpenR1-VM snapshots, DeepSeek-VM-1.5B files, upstream tokenizer, `math-verify`, SGLang, benchmark versions, and seeds. The public model needs the repository’s custom `Qwen2ForClassifier`; the model repo does not package tokenizer files or that implementation. Appendix E mentions a 500-example value-model validation split, but OpenR1-VM publishes only train. The checked repository does not expose an end-to-end collection/pre-filter script, full historical search trees, or licenses for code and model weights.
