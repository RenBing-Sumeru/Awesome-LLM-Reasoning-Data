Long-context reasoning models can spend many tokens on repetitive or unproductive paths, yet search needs a signal that can rank partial continuations before a final answer is available. Existing process reward model pipelines commonly require a predefined step boundary and expensive labels at those steps. This paper asks whether outcome-verified rollouts can instead train a token-level value model that guides long-CoT search without declaring what counts as a reasoning step. The official record is the NeurIPS 2025 paper, cross-checked against arXiv v2, OpenReview, the author repository, two VGS-AI datasets, and the released DeepSeek-VM-1.5B model.

The central released data object is one OpenR1-VM prompt group. It contains the math problem, reference solution and answer, and 56 roll-in/roll-out pairs represented by token IDs, processed answers, boolean rewards, and labels for finished-incorrect, finished-correct, or incomplete outcomes. The paper reports about 2.5 million pairs after filtering; the public train split has 44,509 grouped rows. Incorrect and incomplete outcomes remain inside a retained group, but a group is removed if all 56 rollouts fail or remain incomplete.

The work belongs to **Rollout, Search, and Test-Time Trace Data** because the reusable object couples repeated partial trajectories, outcome labels, a learned selector, block-wise search topology, and an explicit inference budget. It is not human step supervision, a proof-producing verifier, an RL policy-training study, or a release of complete inference-time search trees. The fixed rollout policy’s success probability is the learning target; neither the terminal checker nor the value model establishes that every intermediate reasoning token is valid.

The Card reaches L4 because the full paper and appendices specify the collection budget, labels, model loss, training run, search settings, quantitative comparisons, and failure cases, while official releases expose the grouped dataset schema, code, and value-model weights. L4 here records a well-evidenced pipeline and its audit limits. It does not certify the missing rejection manifests, undisclosed generation parameters, absent historical discarded branches, or unresolved code/model licenses.
