长上下文推理模型可能把大量 token 消耗在重复或无效路径上，而搜索又需要在最终答案出现前对部分续写进行排序。既有 process reward model 流水线通常要先定义“步骤”边界，并为这些步骤收集昂贵标签。本文要回答的是：能否用经过结果核验的 rollout 训练 token-level value model，在不预先规定推理步骤的情况下引导长 CoT 搜索。官方依据为 NeurIPS 2025 论文，并与 arXiv v2、OpenReview、作者仓库、两个 VGS-AI 数据集以及已发布的 DeepSeek-VM-1.5B 模型交叉核验。

核心公开数据对象是一个 OpenR1-VM 提示组。每组包含数学问题、参考解和答案，以及 56 个以 token ID 表示的 roll-in/roll-out 对，同时保存处理后的答案、布尔 reward，以及“已结束但错误、已结束且正确、未完成”三类标签。论文称过滤后约有 250 万个 pair；公开 train split 有 44,509 个分组记录。入选组内仍保留错误和未完成结果，但如果 56 个 rollout 全部错误或未完成，整组会被移除。

本文属于 **Rollout, Search, and Test-Time Trace Data**，因为可复用对象把重复采样的部分轨迹、结果标签、学习式选择器、分块搜索拓扑和显式推理预算连接起来。它不是人工步骤监督，不是能生成证明的 verifier，不是 RL 策略训练研究，也没有发布完整的推理期搜索树。学习目标是固定 rollout policy 下的成功概率；终点检查器和 value model 都不能证明每个中间推理 token 有效。

本卡达到 L4，是因为论文全文及附录给出了采集预算、标签、模型损失、训练运行、搜索设置、定量比较与失败案例，官方发布又公开了分组数据 schema、代码和 value-model 权重。这里的 L4 表示流水线及其审计边界已有充分证据，并不认证缺失的拒绝清单、未披露的生成参数、未发布的历史丢弃分支，以及尚不明确的代码和模型许可证。
