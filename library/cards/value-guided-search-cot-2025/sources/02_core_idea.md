The contribution in one sentence is: turn cheap final-answer outcomes from randomly cut long-CoT rollouts into dense token-level value targets, then use the trained value model to select 4,096-token search blocks and weight final-answer voting.

For data construction, four DeepSeek-R1-Distill-Qwen sizes generate diverse roll-ins, while DeepSeek-R1-Distill-Qwen-1.5B is held fixed as the rollout policy. Each prompt receives 14 roll-ins and four random cuts per roll-in, producing 56 completions. Every rollout token receives the completed response’s three-class outcome label under a token-level cross-entropy objective. This attaches a trajectory-value target to every rollout prefix without claiming that the label identifies the first faulty step.

The feedback contract has two layers. `math-verify` checks the parsed final `\boxed{}` answer against the reference answer, assigning reward 1 only to a finished correct response; wrong or 16,384-token-capped responses receive zero reward. DeepSeek-VM-1.5B then predicts the probability that the fixed 1.5B policy will finish correctly from the current prefix. The first layer observes final-answer equivalence, not proof validity; the second approximates policy-conditional success and can be miscalibrated for stronger generators or subtle reasoning errors.

At inference, VGS samples blocks, scores their prefixes with the value model, retains a beam of width 2, optionally repeats search through DVTS, and applies weighted majority voting to final candidates. Relative to majority voting and best-of-N, selection can act before complete answers consume the full budget. Relative to conventional step-delimited PRM supervision, the data interface is random-prefix completion plus terminal outcome rather than per-step annotation. The direction is **outcome-supervised trajectory values for budgeted long-CoT search**, not a general claim that learned value replaces semantic process verification.
