可重建的流程如下：

1. **种子与概念抽取。** 从 7,500 个 MATH 训练问题—解答对开始；Qwen2.5-32B 按公开的 Prompt A.1 抽取 1-5 个原子概念。
2. **双重概念过滤。** Qwen2.5-7B 删除含糊、错误或过度具体的概念。BGE-M3 相似度为 0.90-1.00 时直接分组，0.70-0.90 时交由 LLM 判断是否同义，低于 0.70 则保持不同。LLM 为每组选择或合成代表标签，最终留下约 10K 个概念。附录 D 报告，仅用嵌入去重时通过作者质量检查的生成题占 26%，加入双重过滤后升至 45%。
3. **图与组合选择。** 共现概念之间建立加权显式边。GRIP 枚举 one-hop 概念对、共享邻居的 two-hop 概念对、枢纽与距离 3 条边的概念构成的 three-hop 对，以及由 3 或 4 个概念组成的全连接社群。低权 three-hop 关系会被删除，但截止值未披露。
4. **问题与解答生成。** Qwen2.5-32B 接收概念和 Prompt A.2，但不接收源题。未命名评分模型分配难度；Qwen2.5-Math-7B 生成低/中难度解答，Qwen2.5-Math-72B 生成高难度解答。temperature、top-p、token 上限、重试、随机种子和原始候选数均未知。
5. **多模型选择。** 三个开放数学模型以 0 到 1 评价题目的逻辑与表述完整性；一个未披露权重的加权平均值必须至少为 0.85。同一组模型再对解答作二元判断，只有全票接受才保留。流程没有使用符号执行、定理证明器或过程步骤验证器。
6. **输出与发布。** 论文报告用 8 张 A100 80GB GPU 和 vLLM 运行 36 小时后保留 2,123,345 对。官方补充 JSON 随机发布 24,957 行，只有 `KC1`、`KC2`、`question` 和 `solution`。
7. **下游 SFT。** 六个基础模型只在 GRIP-MATH 上训练，使用 LLaMAFactory、2 个 epoch、学习率 `5e-6`、全局 batch 128、序列长度 4,096、余弦日程、3% warm-up、DeepSpeed ZeRO Stage 3 和 FlashAttention 2。优化器、模型版本、随机种子和逐次运行计算量未说明。（论文第 3-4 节；附录 A、B、D。）

忠实复现还需要概念图、各分支计数、低权截止值、难度模型、精确的评审权重/提示、全部生成与拒绝记录、切分清单、模型版本和许可证。补充子集不含这些字段，因此只能支持逐行检查，不能支持端到端重建。
