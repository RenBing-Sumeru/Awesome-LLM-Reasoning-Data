The central contribution is a scale stress test: compare six self-scoring selectors and five random controls on two large heterogeneous instruction pools, then ask whether a cheap diversity-aware token-length rule is more practical than complex scores. The four quality selectors are LESS, IFD, SelectIT, and response cross-entropy; the two diversity selectors are DiverseEvol and ZIP. Main experiments select 10K records, and Appendix A.2 repeats the study at 50K.

The feedback contract is indirect. LESS observes gradient similarity, IFD compares conditioned and direct answer losses, SelectIT observes rating-token uncertainty, cross-entropy observes response surprise, DiverseEvol observes embedding distance, and ZIP observes compression redundancy. None checks whether a source answer is correct, safe, licensed, or uncontaminated. The final utility signal is model performance after SFT on BBH, GSM8K, HumanEval, MMLU, and IFEval, so a selector is judged at aggregate run level rather than by record-level correctness.

The paper's practical alternative clusters the source pool, allocates the selection quota in proportion to cluster sizes, and keeps longer records within each cluster. This combines diversity preservation with an inexpensive length proxy. The public utilities do not implement that terminal rule: `token_length/kmeans_sample.py` truncates to the first 100 embeddings and returns points nearest cluster centers instead of proportional longest-within-cluster records.

The closest Atlas comparison is `more-data-or-better-data-2025`, which holds a mathematical 80/20 baseline/candidate mixture and studies source, teacher, and format changes. This paper instead fixes selected subset sizes across general instruction pools and interrogates self-scoring versus random selection. Both show that a downstream benchmark delta is not a record-level verifier and that negative claims need selected IDs, run bindings, and contamination evidence.
