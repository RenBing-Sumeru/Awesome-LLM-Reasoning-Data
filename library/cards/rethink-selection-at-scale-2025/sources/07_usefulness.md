For dataset builders, the paper is a practical warning against treating a sophisticated self-score as intrinsic record quality. A credible selection study should compare multiple random subsets, separate selection compute from SFT compute, preserve diversity, report selector adaptations, and test whether the conclusion survives a second source pool, base model, and subset scale.

The K-means-plus-length idea can be reconstructed as a controlled baseline: compute token counts with a pinned tokenizer, cluster the complete pool, allocate integer quotas in proportion to cluster sizes, define rounding and tie-breaking, select the longest rows in every cluster, then hold SFT tokens, optimizer steps, and evaluation settings constant against random, length-only, cluster-center, and quality-score controls. The released KMeans script must not be used unchanged as the paper selector.

An auditable release should publish upstream revision and row ID, selector variant, score/embedding/cluster, query/response/total token count, random seed, keep/reject decision, subset membership, train-file hash, SFT checkpoint, and benchmark outputs. Both accepted and rejected records matter: without them, selector bias and failure cases cannot be inspected.
