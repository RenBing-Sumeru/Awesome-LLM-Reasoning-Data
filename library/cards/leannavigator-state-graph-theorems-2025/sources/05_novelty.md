Traditional Lean data expansion either collects repository theorems, translates natural-language problems, or generates complete statement–proof pairs and filters them by compilation. These approaches are limited by repository size or low generation success. LeanNavigator instead exploits the state space around every verified proof: intermediate goals discovered during search are promoted to new theorems, while existing paths to the terminal node automatically supply proofs. It does not invent Lean kernel verification or tactic search. The actual change is the use and granularity of search artifacts, allowing one seed theorem to yield many machine-verified samples with complete proof chains.
