The experimental estimates are expensive and not uniformly reconciled with the release. The paper samples 100 keep and 100 remove/resample continuations for every analyzed sentence, and 100 forced-answer completions per position. It states that 100 samples make the worst-case 95% confidence interval for accuracy approximately ±10%. The dataset card, however, describes released chunk files as typically containing 10–100 continuations. There is no manifest of valid, incorrect, missing-answer, malformed-answer, or API-error counts showing that every published estimate and every released file has the same effective sample size.

Public counts refer to incompatible units. Twenty questions, 40 Qwen base responses, 106 screening candidates in `selected_problems.json`, nine model-by-solution-type branches, 20,997 indexed file rows, 183 Parquet shards, and nested continuation arrays are not interchangeable. The Qwen sanity branch contains only two problem directories and the Llama tree has no matching sanity branch. Without an immutable branch/file/chunk/continuation manifest, users can overstate scale, treat variants as independent tasks, or silently duplicate raw and indexed representations.

Generation lineage is incomplete. Code supports four provider modes and defaults to Novita, but the exact provider, endpoint, model checkpoint revision, request date, and code revision are not stored per continuation. The exposed seed of 44 is not transmitted to API providers, so nominal seeding does not establish replayability. Temperature 0.6 and top-p 0.95 are documented, and code defaults include 16,384 maximum new tokens and 275 chunks, but those settings do not replace record-level provenance.

Source provenance and split semantics remain unresolved. The generator defaults to the MATH train split, while the release exposes only a file-index `default` split and does not provide the exact MATH revision or source split for every problem. No train/dev/test division for reuse, exact or semantic deduplication report, prompt-contamination audit, or benchmark-overlap analysis is published. The 20 selected questions are repeatedly represented across models and intervention branches, so question-level leakage is easy to introduce if consumers create downstream splits from file rows.

The verifier and semantic filter have known failure surfaces. Boxed-answer extraction and normalization can mis-handle malformed outputs or collapse distinctions between answer strings; failure categories are not summarized. The 0.8 all-MiniLM-L6-v2 threshold may classify paraphrases as counterfactual or semantically different statements as similar. GPT-4o function and dependency labels are automatic judgments from April–May 2025, not independently validated human annotations.

The causal interpretations are preliminary. The authors note the high cost of resampling, unresolved overdetermination by multiple sufficient paths, and the absence of a formal treatment of error correction. Receiver-head scores are confounded by sentence position. Attention suppression requires the model to process out-of-distribution information, and logits are only a proxy for sentence semantics. Agreement among resampling, attention, and masking reduces but does not eliminate these identification concerns.

Negative traces are present but incompletely audited. Incorrect base-solution branches and `is_correct: false` continuations allow useful failure analysis, yet the release does not report how many incorrect, unparseable, empty, provider-error, or partially generated records were retained or filtered. Generator error objects may be stored, but their release-wide frequency and treatment are unknown. Absence of this accounting makes it difficult to distinguish model failure from infrastructure or parsing failure.

Versioning and rights are partial. Hugging Face `main` has 176 commits; the file-index upload was spread across four commits on 2025-08-25, with no semantic release or immutable manifest. Consumers should pin the inspected revision rather than rely on moving `main`. The paper/OpenReview content is CC BY 4.0, code is MIT, and the HF dataset card declares MIT, but upstream MATH derivative-data rights are not analyzed. These licenses apply to different layers and should not be collapsed into one blanket reuse claim.

Finally, the venue is unresolved. Official sources identify the work as submitted to ICLR 2026 and under review, not as accepted or published there. Citation identity is verified through arXiv, but venue status must remain provisional until an official decision or proceedings page exists.
