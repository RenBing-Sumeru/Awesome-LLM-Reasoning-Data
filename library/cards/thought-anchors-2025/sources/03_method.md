The main MATH study uses DeepSeek-R1-Distill-Qwen-14B, a 48-layer model, with temperature 0.6 and top-p 0.95. The authors first run ten attempts on each of 1,000 problems and retain 20 with observed solve rates between 25% and 75%. They then choose one correct and one incorrect base trace for every selected question, yielding 40 Qwen base responses. The paper reports means of 144.2 sentences and 4,208 tokens per response. Appendix B repeats the 20-question design with 20 correct and 20 incorrect DeepSeek-R1-Distill-Llama-8B base solutions.

Each base response is split into sentence-like chunks. For chunk \(i\), the keep distribution is generated from the accumulated prefix including \(i\), while the remove/resample distribution is generated from the prefix ending at \(i-1\). Appendix N’s pseudocode expresses this as resampling from \(i+1\) for `R_keep` and from \(i\) for `R_remove`. The paper’s estimate therefore compares two banks of 100 continuations, or 200 continuations across both conditions. One stored `chunk_i/solutions.json` corresponds to one 100-rollout generation condition; users should not assume both conditions are duplicated inside the same file.

Forced-answer generation is organized separately. At each sentence position, the current prefix is followed by an unfinished boxed-answer cue and sampled 100 times. In the main resampling analysis, sentences after answer convergence are excluded: convergence is defined as more than 98% of resamples producing the same response. The analysis code can also omit chunks shorter than four characters. Repository defaults target 100 rollouts per chunk, a maximum of 16,384 new tokens, at most 275 chunks, and local batch size 8.

The terminal verifier extracts the final boxed expression, normalizes it, and compares it with the MATH reference. Final-answer strings are aggregated into empirical distributions for accuracy and KL calculations. The counterfactual subset is formed by embedding original and replacement sentences with all-MiniLM-L6-v2 and retaining pairs below cosine similarity 0.8. GPT-4o assigns one of eight functions—Problem Setup, Plan Generation, Fact Retrieval, Active Computation, Uncertainty Management, Result Consolidation, Self Checking, or Final Answer Emission—and identifies direct dependencies from an appendix prompt.

The release tree is organized by model, decoding setting, solution type, problem, and chunk. It includes correct and incorrect base-solution branches, forced-answer branches, and a Qwen-only two-problem `correct_base_solution_sanity` branch. Current raw structure has four branches for Llama-8B and five for Qwen-14B, hence nine model-by-solution-type branches rather than the ten suggested by a symmetric schematic. Qwen’s four main branches each expose 20 problem directories, plus two sanity directories; these are variants of the selected problems, not independent task sets.

The Hugging Face `default` split is a file index created by `push_hf_dataset.py`. It recursively records raw files as rows with file metadata and embedded text; the `content` of `solutions.json` contains arrays of continuations. The viewer estimate of 20,997 rows, 183 Parquet shards totaling 19.6 GB in `data/`, and 111 GB repository total therefore describe different storage and indexing layers. They cannot be summed or substituted for an exact nested-rollout count.

Code supports Novita, Together, Fireworks, and local generation and defaults to Novita, but the release does not record a provider, endpoint, checkpoint revision, request date, and seed for every continuation. Although the CLI exposes nominal seed 44, the API path deliberately does not transmit that seed, so deterministic API replay is not established. The exact MATH source split/revision and record-level lineage are also absent.

Paper v4 additionally analyzes sentence-causal graphs for 2,492 MMLU questions using Qwen3-30B-A3B. That experiment masks attention to a source sentence and measures changes in later-token logits, using roughly 100 times less compute than resampling. It belongs to the paper and code evidence but is not part of the `math-rollouts` Hugging Face release; it must not be counted as another released dataset branch.
