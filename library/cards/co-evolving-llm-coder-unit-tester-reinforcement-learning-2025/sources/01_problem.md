Code generation benefits from two capabilities that are usually optimized separately: producing a correct program and producing tests that can distinguish correct programs from plausible wrong ones. Existing unit-test fine-tuning methods often obtain supervision from ground-truth code, which limits use on tasks that have statements and tests but no trusted reference solution. CURE asks whether one LLM can improve as both coder and task-derived unit tester through reinforcement learning.

The relevant data object is an interaction episode, not just a final program. For one task, the policy samples code candidates and generated tests, executes every code against every test, executes code against private gold tests, and derives scalar rewards for both roles. The same policy is then updated alternately as coder and tester.

The paper's “without ground-truth code” boundary is important. CURE does not train from reference solution programs, but it does use ground-truth unit tests. Those private tests directly reward code candidates and define which sampled programs count as correct when estimating tester rewards. The method therefore reduces dependence on gold code; it is not free of gold supervision or external correctness anchors.
