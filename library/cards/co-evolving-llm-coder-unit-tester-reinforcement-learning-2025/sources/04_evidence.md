Artifact evidence is strong but uneven. The official repository releases training and evaluation code, the four-stage optimization pipeline, converted datasets, and ReasonFlux-Coder-4B/7B/14B weights. The public CodeContests_train dataset has 4,529 rows and an MIT dataset-card license. The repository can generate temporary rollout and result directories during a run, but it does not publish one immutable corpus containing every paper-run code trace, tester trace, execution matrix, reward, and failure.

Across LiveBench, MBPP, LiveCodeBench, CodeContests, and CodeForces, the paper reports average improvements over the corresponding base models of 37.8 percentage points in unit-test accuracy, 5.3 points in one-shot code accuracy, and 9.0 points in 16-code/16-test Best-of-N accuracy for the 7B and 14B models. The ablation finds that coder-only optimization does not improve tester accuracy, while the full derived tester reward outperforms a simplified “passes all correct codes” reward. This supports the claim that explicitly optimizing both roles matters under the studied setup.

The paper also applies ReasonFlux-Coder-4B as a tester for GPT-series coders and as a generated-test reward source for RL on Qwen2.5-14B-Instruct. These experiments show downstream utility within the reported pipelines. They do not establish that generated tests are universally correct, that the private test suites are complete, or that the co-evolution episodes form a high-quality reusable dataset.

For unit-test evaluation, CodeContests and MBPP use available reference code. For CodeForces, LiveBench, and LiveCodeBench, the paper uses QwQ-32B-generated programs retained after passing all gold tests as reference programs. Those references are operational proxies: passing finite tests does not prove semantic equivalence to a true solution.
