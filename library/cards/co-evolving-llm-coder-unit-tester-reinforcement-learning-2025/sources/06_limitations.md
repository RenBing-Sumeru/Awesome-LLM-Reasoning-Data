Gold-test coverage is the primary validity boundary. CURE treats a sampled program that passes all available private tests as correct when computing tester rewards. A semantically wrong program that slips through an incomplete suite becomes a false positive: it receives coder reward and can cause good generated tests that reject it to be penalized. The paper does not report mutation-score, coverage, or false-correct audits for this labeling step.

Co-evolution creates non-stationary feedback. Because one policy generates both programs and tests, both roles may converge on shared formatting, input distributions, or weak cases. Gold tests constrain this loop, but do not prevent co-adaptation outside their coverage. Generated-test accuracy, reward precision, and final hidden-test accuracy must therefore remain separate measurements.

Execution introduces operational risk. The public schema records a time limit, but the exact isolation boundary, dependency image, nondeterminism handling, timeout policy, and failure taxonomy for the reported runs are not packaged as an immutable environment. A 16-by-16 matrix also requires 256 generated code-test executions per task before private tests, so environment failures or resource limits can systematically shape reward.

Release reproducibility is partial. The data, code, configurations, and weights are public, but the GitHub repository has no tagged release and no visible code license. The current default optimization configuration uses 120 steps rather than the 350 reported for the 7B/14B models. Seeds, exact split membership, complete paper-run rollouts, execution logs, and rejected or malformed samples are not provided as a fixed bundle.

The evaluation is concentrated on Python stdio programming. Function-style tasks are converted to stdio, and several evaluation reference programs are QwQ-32B outputs accepted by finite tests. Results may not transfer to repository-level engineering, multi-file builds, stateful services, flaky tests, or security-sensitive execution. Public release of fields named private tests improves reproducibility but removes their secrecy for future evaluation.

Finally, accuracy improvements are evidence about the trained models and selectors under stated budgets. They are not evidence by themselves that the released prompts, tests, rollouts, or verifier labels are high-quality training data.
