For the `rollout_search_test_time_trace_data` track, CURE provides a clear schema for a two-role executable trajectory. A reusable episode should preserve the task and source revision; public examples and private gold tests as separate fields; policy checkpoint; role; raw coder and tester prompts/responses; sampling seed and decoding settings; every code-test execution, stdout, stderr, timeout, and parser outcome; the full interaction matrix; the gold-test-derived code label; both scalar rewards; optimizer step; and final evaluation outcome.

This schema supports several uses. During training, it can study how verifier errors propagate through coupled policy updates. During test-time compute, it can compare code/test sampling allocations and Best-of-N selection under equal execution budgets. For reward research, it can compare direct gold-test coder rewards, derived tester discrimination rewards, and generated-test rewards used to train another model. Failed and contradictory episodes are especially valuable for audit and should not be discarded.

Reuse must keep three boundaries explicit. Training-private tests are hidden from the model prompt but are publicly downloadable in the release. Generated tests are selectors or rewards, not final ground truth. Final benchmark private tests evaluate the selected program and must not be backfilled as labels for intermediate rollouts unless the intended use is clearly marked as post-hoc analysis.

Before extending the recipe, pin the repository commit and environment, publish exact train/evaluation manifests, audit gold-test coverage with mutations or adversarial candidates, report reward false positives, and version the generated-test policy separately from the coder policy checkpoint even when both roles share parameters.
