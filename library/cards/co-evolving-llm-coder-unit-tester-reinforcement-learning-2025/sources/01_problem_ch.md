代码生成依赖两种通常被分开优化的能力：生成正确程序，以及生成能够区分正确程序与貌似合理错误程序的测试。既有单元测试微调方法往往从标准代码获得监督，因此难以直接用于只有题目与测试、却没有可信参考解答的任务。CURE 研究的是：能否通过强化学习，让同一个 LLM 同时提升 coder 和任务派生 unit tester 两种能力。

这里关键的数据对象不是最终程序，而是一段交互 episode。针对一个任务，策略采样多份代码候选和生成测试，将每份代码与每个测试交叉执行，再让代码运行私有 gold tests，并据此为两个角色计算标量奖励；随后，同一策略在 coder 与 tester 角色之间交替更新。

论文所说的“without ground-truth code”必须准确理解。CURE 不使用参考解答程序训练，但仍使用 ground-truth unit tests。私有 gold tests 直接为代码候选提供奖励，并在估计 tester 奖励时定义哪些采样程序属于正确程序。因此，该方法降低的是对 gold code 的依赖，而不是消除所有 gold supervision 或外部正确性锚点。
