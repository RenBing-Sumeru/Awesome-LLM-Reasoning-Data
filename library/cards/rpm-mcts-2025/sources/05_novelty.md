Prior MCTS code-generation systems commonly rely on outcome rewards, LLM self-evaluation, a trained process reward model, or post-hoc code patching. RPM-MCTS instead uses a retrievable bank of correct algorithmic-step prefixes as a process-level prior, combines it with UCB for node selection, filters semantically redundant expansions, and feeds execution-guided error localization back into the tree. The contribution is this integration and its explicit step-level search trace, not MCTS, retrieval, execution feedback, or supervised distillation individually. For the Rollout, Search, and Test-Time Trace Data category, the direction signal is the proposed linkage among source problem, step node, retrieved neighbors and score, pruning outcome, sandbox/LLM feedback, correction boundary, backed-up value, and selected trajectory. The paper demonstrates that such trajectories can seed SFT, but the absence of a linked release prevents treating the 2.4K set as an available data resource.
