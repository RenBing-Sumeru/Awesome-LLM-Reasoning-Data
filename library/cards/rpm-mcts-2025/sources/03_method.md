The knowledge base is built from APPS and CodeContests training problems paired with correct implementations. Claude Sonnet 3.7 generates and decomposes each correct solution into algorithmic steps; the problem and successive step prefixes are embedded with BGE and stored in a vector database organized into 14 algorithm categories. RPM-MCTS then iterates selection, expansion, evaluation/reflection, and backpropagation. The root stores the problem, each action adds an algorithmic-step node, expansion uses sampling plus cosine-similarity filtering, and simulation prompts the LLM to finish the plan and generate code that is run against public tests. The scalar node value is a weighted combination of execution pass rate and LLM evaluation, while reflection attempts to identify the first faulty step and retain the preceding steps.

Experiments use Qwen3-8B, Qwen3-235B-A22B, and Claude Sonnet 3.7, with a maximum of five iterations for all compared search methods, across HumanEval+, MBPP+, APPS, and CodeContests. Separately, RPM-MCTS generates 2.4K code samples with reasoning steps using Doubao-1.5-pro-32K; these are mixed with a 170K foundational dataset for full fine-tuning. The official sources do not link code, the knowledge-base snapshot, complete trees, the 2.4K records, rejected candidates, or replayable sandbox fixtures. Exact decoding seeds, per-record lineage, split and decontamination records, and artifact licenses therefore remain unknown.
