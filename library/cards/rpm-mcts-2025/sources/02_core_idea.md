RPM-MCTS uses retrieval from historically correct algorithmic solutions “as Process Reward Model,” but this is not a separately trained PRM and the retrieval score is not verified step correctness. A node’s selection score combines UCB with the maximum non-negative cosine similarity between the current problem–prefix–candidate-step representation and entries in the knowledge base. Expansion samples multiple next steps and removes overly similar candidates. Simulation completes a plan and code, then combines the public-test pass rate with an LLM evaluation; sandbox feedback and LLM analysis localize an erroneous step, truncate the failing suffix, and add the retained correct prefix back to the tree. MCTS selection and backpropagation allocate search compute using these signals; they do not by themselves establish the quality of any resulting training record.
