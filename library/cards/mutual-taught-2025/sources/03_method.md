The reported pipeline can be reconstructed at the module level, although the official method implementation is unavailable.

1. **Inputs and partitioning.** Initialize the policy from Llama-3-8B-Instruct and the RM from FsfairX-Llama3-RM-v0.1. Start from about 60,000 UltraFeedback prompts. The paper partitions them into two policy-update portions and one RM-update portion; two thirds are used for policy updates and one third is reserved for RM updates. Separately, randomly sample a fixed 2,000-prompt UltraFeedback set `D_MS` for checkpoint selection. Exact record IDs and disjointness are unknown. (Paper §5.1; Appendix B–C)

2. **E-step candidate generation and pair construction.** For each policy-update prompt, sample `M=5` responses from the current policy at temperature 0.8 and top-p 0.95. Score all responses with the current RM. For length control, retain responses above the prompt-level average reward, choose the shortest of them as `chosen`, and use the lowest-scoring response as `rejected`. Train DPO for one epoch with the preceding policy as reference, beta 0.01, batch size 128, maximum sequence length 2,048, learning rate `7e-7`, cosine scheduling, and warmup ratio 0.1. (Paper Eq. 4; Appendix B)

3. **Policy checkpoint selection.** Save a checkpoint every 50 steps. On each prompt in `D_MS`, generate one response from a saved checkpoint and one from the policy at the start of the iteration. The current RM chooses the higher-scored response; average these comparisons into a win rate. Retain the checkpoint with the highest win rate. If the best checkpoint scores below `tau=60%`, stop and preserve the previous policy. The paper's four-iteration extension demonstrates this branch at iteration 4. (Paper Eq. 6–7; Appendix B, H)

4. **M-step policy-comparison records.** For each reward-update prompt, generate `y_t` from the selected policy and `y_{t-1}` from its predecessor. Assign the provisional pair direction `y_t` preferred over `y_{t-1}`. Compute `delta_r = r_{t-1}(y_t) - r_{t-1}(y_{t-1})` and set `epsilon_t` to the standard deviation of the previous-policy response scores over the reward-update data. The final Low-Quality Data Filtering strategy discards a pair when the updated response is confidently worse (`delta_r <= -epsilon_t`) and retains the rest, including margins between `-epsilon_t` and zero. (Paper Eq. 5, 8; Appendix F)

5. **Reward-model update and next iteration.** Train a Bradley–Terry RM on mixed data: self-training preferences previously ranked by the RM plus the filtered updated-versus-previous policy comparisons. Each RM iteration starts again from the base RM to mitigate repeated-prompt overfitting, rather than continuing from the last RM checkpoint. Use one epoch, batch size 512, maximum sequence length 2,048, learning rate `2e-6`, cosine scheduling, and 0.1 warmup. The updated RM then labels the next policy-update portion. The main setup uses two iterations and eight NVIDIA A100 GPUs. (Paper §5.1, §5.3; Appendix B)

The resulting training objects are DPO pairs, checkpoint-comparison outcomes, filtered policy-comparison pairs, RM scores, thresholds, policy/RM identities, and iteration links. A faithful implementation must version all of them, including discarded pairs. It must also fix the UltraFeedback revision, tokenizer and chat template, generation engine, FsfairX checkpoint, response-score convention, random seeds, `D_MS` membership, and evaluation harness versions. None of those record-level manifests or Mutual-Taught configs is available from the paper-linked repository: its only branch currently contains Alignment Handbook material, with no method-specific tags or releases.

The supervision granularity is pairwise preference plus scalar reward, not step-level process supervision. The training uses are preference learning and reward modeling. AlpacaEval-2, Arena-Hard, RewardBench, and the additional leaderboard tasks are evaluation surfaces only; they are not used as programmatic reward during the reported training.
