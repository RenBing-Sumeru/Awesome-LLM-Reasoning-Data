作者明确指出两项建模限制：复杂逻辑推理和长依赖任务可能收敛缓慢，无限制迭代可能导致过优化。附录 H 给出的不是纯假设，而是一个实际边界：第 4 次迭代让 AlpacaEval-2 长度控制胜率从 44.9 降到 40.3，随后 60% 模型选择阈值返回上一策略。该阈值被设为高于随机水平、同时允许继续更新，但它能否迁移到其他策略、judge 或领域并未建立。（论文 Limitations；附录 H）

核心标签假设具有自指性。更新响应之所以被标为 preferred，是因为策略针对当前 RM 做过优化，而不是人类或任务 oracle 比较了两个响应。随后，同一个 RM 又负责排序五个 E-step 候选、在 `D_MS` 上选择策略 checkpoint、计算 M-step 分数差，并提供筛选所用的不确定性尺度。因此，一个盲点或可利用的风格偏好可能影响所有门控。当高 RM 分数不代表人类偏好时会产生伪 pair false positive；有价值的策略变化被阈值压低时会产生 false negative。reward hacking、共享漂移和确认偏差是由依赖关系推导出的 curator inference，并非论文测得的失效率。

Low-Quality Data Filtering 有意保持宽松。它只丢弃 `delta_r <= -epsilon_t` 的 pair；若更新响应只比上一响应略低，仍会作为正则保留。其真实标签噪声率未知，附录 F 还显示不同筛选规则会在 AlpacaEval-2 策略表现与 RewardBench RM 表现之间产生权衡。方差阈值测量的是当前 RM 分数离散度，不是 pair 方向正确概率的校准值。长度控制也引入了额外捷径通道，因为 chosen 响应是高于平均分候选中最短的一个。

理论保证的前提比实验所验证的更强。附录 D 假设两个步骤都精确优化，且伪标签估计无偏，随后推导期望奖励单调改善。论文没有独立证据说明 DPO、神经 RM 拟合或更新策略对上一策略伪标签满足这些前提。基于 RM 的 checkpoint 选择只能保证被测 RM 标准上的改善，不能单独证明潜在人类偏好上的改善。

数据与发布可审计性不完整。论文没有披露不可变的 UltraFeedback 记录 ID、精确子集数量、2000 条选择提示是否不相交、去污染、生成 token 总量、主表随机种子与方差、接受/丢弃 pair 数量、伪标签准确率、奖励校准或完整运行日志，也没有发布动态 pair 流或失败样本。论文链接的 GitHub 仓库虽然声明 Apache-2.0，但当前内容是 Alignment Handbook，而非 Mutual-Taught 代码、配置、数据或 checkpoint；该许可证不能替代缺失方法 artifact 或上游数据的许可。

评测也存在循环性或代理性。GPT-4-Preview-1106 负责 AlpacaEval-2 与分布内 RM 比较，RewardBench 测量与 benchmark 偏好的符合程度。这些是有用外部评测面，但都不直接审计训练 pair 标签。主要指令跟随提升同时伴随 GSM8K、MMLU 下降以及 RewardBench 子类别非单调变化。因此，benchmark 表现只能支持有条件的训练配方结果，不能证明所构造数据高质量、无偏、无污染或广泛可迁移。
