Use BIRD to design data-grounded SQL evaluation schemas. Preserve question, db_id, schema, database snapshot, evidence, gold SQL, predicted SQL, execution result, VES, timeout, evaluator version, and split label. It is useful for auditing whether a model understands database values rather than only schema names, and for comparing EX versus efficiency-aware SQL generation. Treat training, dev, test, mini-dev, and cleaned splits as different artifacts.
