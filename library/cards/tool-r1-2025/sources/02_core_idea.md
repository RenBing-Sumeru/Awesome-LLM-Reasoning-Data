Tool-R1 combines a difficulty-aware per-question trajectory queue with response-masked GRPO and a mixed answer-plus-code reward so that recent online tool-use episodes can be reused without training the policy to imitate tool observations. The model-generated Thought and Python Code tokens contribute to the policy loss; tokens returned as Observation by the environment are masked. (Paper §3.1–3.3)

The feedback contract attaches to the full episode. Qwen2.5-3B-Instruct compares the question, reference answer, and predicted answer under accuracy, completeness, relevance, and precision, mapping Correct/Partially Correct/Wrong to `1/0.5/0`. Programmatic `R_parse=N_parsed/N_total` and environmental `R_exec=N_executed/N_parsed` supply auxiliary signals; the total is `R_answer + 0.3 R_parse + 0.3 R_exec`.

This contract can observe final-answer agreement as interpreted by a learned judge, whether code blocks parse, and whether parsed blocks run without runtime errors. It cannot establish step-level reasoning correctness, whether executable code was relevant or safe, whether a runnable action caused the answer, or whether the judge is calibrated. The result is full-episode scalar supervision, not process labels.

The direction is sample-efficient agent RL over executable code-composed tools and reusable online episodes. The paper's closest quantitative comparison is MAT Agent: MAT Agent is reported with 20k QA-plus-trajectory records, whereas Tool-R1 trains from 1.3k QA pairs and a dynamic rollout queue. The comparison is not a controlled data-only experiment because base models and system details differ.
