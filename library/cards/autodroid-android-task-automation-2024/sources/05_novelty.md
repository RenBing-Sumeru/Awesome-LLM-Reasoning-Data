The prior baseline is mobile automation through developer intents, demonstrations, task-specific reward definitions, or prompt-only GUI agents. AutoDroid changes the loop by letting the agent build app memory through dynamic exploration and then condition each step on simplified HTML plus retrieved app-specific guidance. The direction signal is executable mobile trajectory data with environment feedback, not merely screenshots or instructions. The quality signal is the DroidTask release concept: tasks, action traces, exploration memory, and an Android VM snapshot intended for reproduction. What is not new: LLM prompting, UI-tree representation, and Android automation tools. Reuse requires checking app licenses, VM availability, task split, success-detector code, risky-action policy, privacy handling, and whether public traces leak into training.
