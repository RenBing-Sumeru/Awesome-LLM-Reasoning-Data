The canonical paper is the 32-page proceedings version of **Multi-modal Agent Tuning: Building a VLM-Driven Agent for Efficient Tool Usage**, published at ICLR 2025 and listed in the official Spotlight program. The Card also checks arXiv:2412.15606 v2, the author project, code, dataset, and model releases. This verifies the citation and the existence of public artifacts; it does not certify the dataset license, source rights, or reproducibility.

The engineering problem is how to construct enough multimodal, multi-tool trajectories to train a VLM controller. Prior prompt-driven agents rely on fixed demonstrations, while existing VLM-agent data described by the paper concentrates on simple tasks with one or two tools. The paper therefore generates queries matched to files, lets an agent interact with tools, filters the resulting trajectories, and uses the retained thought-and-code sequence for supervised controller tuning (Paper Sections 1 and 3).

One paper-level MM-Traj item is `{F_opt, Q, T, C, O, A}`: optional files, a query, stepwise thoughts, executable Python calls, observations, and a final answer. The pinned HF row is a narrower serialization with `id`, heterogeneous `image`, string `answer`, and `conversations`. This distinction matters because verifier decisions, rejection reasons, source IDs, file hashes, and most construction provenance are absent from the released row.

The work belongs in **Data Construction and Open Release Recipes** because its main reusable contribution is the path from seed prompts and a 93K image-caption pool through file generation, ReAct rollout, an executable-code gate, two LLM judges, and SFT export. It is not a programmatically verified outcome release: execution only shows that code ran, while semantic correctness still depends on GPT-4o-mini judgments. It also does not provide preference pairs, process labels, a trained reward model, or RLVR data.

The Card reaches L4 because the paper, appendix prompts, official repositories, pinned release contents, counts, licenses, and concrete failure surfaces have been examined bilingually. Its reuse boundary remains conservative: MM-Traj is useful as a construction and audit case, but direct training reuse is blocked by conflicting license declarations, unreconciled source rights and counts, a broken viewer schema, missing rejected examples and judge outputs, and undisclosed sandbox and contamination controls.
