For the **Data Construction and Open Release Recipes** track, this work is useful as a construction pattern, release-audit case, and source of controlled ablations. Its current reuse class is **blocked pending verification for direct training**; the public records should not be treated as rights-cleared or independently verified examples.

- **Rebuild the episode schema.** Preserve `{F_opt,Q,T,C,O,A}` plus source IDs and licenses, file hashes, tool/environment revisions, executable status, both judge prompts and responses, rejection reasons, and train/checkpoint membership. Do not collapse the object to the released conversation alone.
- **Separate feedback channels.** Log runtime success, deterministic validators where available, query-file sufficiency, trajectory-quality judgment, and final-answer correctness as distinct fields. Compare the same-model dual judge with independent models, human audit, and domain-specific checkers.
- **Audit the funnel.** Publish counts for seeds, generated candidates, executable candidates, each rejection stage, retained unique tasks, JSON rows, referenced attachments, and physical archive files. A signed manifest should reconcile 23.5K, about 20K, 21,168, about 15K, and 19,307.
- **Use failures as data.** Release filtered trajectories and both false-accept and false-reject candidates. They can support judge calibration, rejection-policy comparisons, modality slices, and analysis of whether same-model filters select easier or stylistically familiar tasks.
- **Test modality robustness.** Rewrite the image-only verifier prompt into typed contracts for image, document, spreadsheet, presentation, audio, video, and mixed-file tasks. Report verifier behavior and schema validity separately by modality and attachment cardinality.
- **Make execution reproducible and safer.** Pin a container digest, package/tool/model versions, filesystem and network policy, credentials handling, timeouts, resources, state reset, malicious-file scanning, and stdout/stderr/exit records. Treat generated code and documents as untrusted inputs.
- **Run rights and contamination gates before reuse.** Resolve the dataset license, retain upstream item IDs and terms, provide attribution and takedown paths, and audit exact and semantic overlap with GTA, GAIA, training mixtures, upstream captions/images, and base-model pretraining.

The released checkpoint may be studied under its separately stated model license, and the code under MIT, but those grants do not settle dataset or upstream-asset rights. MM-Traj is not suitable as an evaluation set because its overlap with GTA/GAIA and other mixtures is not audited. It also does not directly support preference learning, PRM training, reward modeling, or RLVR replay because rejected pairs, process labels, scalar rewards, and an independently executable correctness verifier are absent.
