The contribution is a closed construction loop for multimodal tool-use SFT: GPT-4o mini creates tasks and non-image files, a GPT-4o-mini ReAct controller produces thought/code/observation trajectories, and the same model family supplies two filtering judgments before VLM trajectory tuning.

The data surface is an episode rather than a prompt-answer pair. Its behavior is the sequence of thought `T`, code action `C`, and resulting observation `O`, conditioned on optional files `F` and query `Q`; the final answer `A` closes the episode but is excluded from the training loss. Supervision therefore attaches to state-action behavior and full-episode acceptance. The release does not expose a standalone step label, scalar reward, preference pair, or verifier target.

The feedback contract is mixed. Python execution is environmental evidence: a tool call must run and yield an observation. The query-file judge asks whether the supplied files are relevant, sufficient, and solvable with the available tools. The trajectory judge asks whether tool choices, arguments, reasoning, observations, and the final answer are mutually consistent. Neither judge has an independent answer oracle, and both use GPT-4o mini, the same model used for generation. They can observe the serialized task and execution results, but cannot establish source rights, detect all hallucinated semantics, or reveal errors shared with the teacher.

The nearest baseline direction in the paper is prompt-engineered LLM/VLM tool agents, including the GPT-4-driven agent contrasted with T3-Agent in Figure 1, plus VLM-agent datasets built from manually defined templates and short one- or two-tool tasks. GTA and GAIA are evaluation surfaces, not substitutes for MM-Traj records. The concrete change is to synthesize matched multimodal files and longer executable trajectories at scale and then train an open VLM controller, rather than keeping a proprietary LLM controller behind in-context examples.

The directional lesson is not “two judges make data correct.” It is that multimodal agent data can be organized around executable actions and observation-conditioned continuation. The audit lesson is equally central: using one proprietary model as query generator, file generator, rollout policy, and both judges couples their failure modes and turns hidden judge preferences into an undocumented selection objective.
