Primary source: https://www.vals.ai/benchmarks/vibe-code. Venue/status: Vals AI benchmark page, 2025. The problem is to evaluate Generated application files plus rendered behavior under browser-based checks. under a benchmark surface whose feedback is application-specific point-and-click tests and verified functional criteria. The decision boundary is evaluation and audit: it is not a training recipe, not a general proof of model reliability, and not a reusable reward unless the official source separately releases that contract.

The data object is composed of task prompt, generated code files, browser interaction result, test outcome, application-level score. The benchmark matters because it measures a concrete surface that ordinary static QA or single-function coding tests do not fully cover. For screening, read the card with the source version, scorer, split policy, and released artifacts attached to any claimed score.
