The main correctness signal is a self-generated majority pseudo-label. A Solver can agree on a wrong answer, and replay can preserve that error across iterations. The paper does not disclose answer canonicalization, equivalence grouping, ties, malformed-output handling, or policies for correcting or deleting bad memory entries. Memory capacity, eviction, versioning, rejected-record counts, and a transition ledger are also unknown.

SAM is an uncalibrated proxy for skill equivalence. Its canonicalizer is explicitly instructed to infer an intended valid interpretation for ambiguous or flawed questions, so the representation can silently change the task. The generated code is not reported as being executed. Embedding similarity may merge different skills or separate equivalent ones, and thresholds are not calibrated against expert labels. A code bottleneck may also fail in domains that are difficult to formalize. (Paper Appendix A.2 and limitation discussion.)

GPT-4o supplies an answer recheck prompt, duplicate judgments, and labels for the five 200-question analysis sets, but exact model revision, decoding, adjudication, coverage, and error rates are unknown. Benchmark experiments report no seeds, repeated-run variance, generated-record counts, or systematic decontamination. Describing recent AIME items as likely uncontaminated is not an item-level overlap audit.

Reproducibility remains partial. The official repository has no training or inference code, data, weights, memory snapshots, environment lockfile, tagged release, or LICENSE. The paper gives eight-H20 hardware and a 4B per-iteration time, but not full compute, token counts, 8B costs, or long-run memory scaling. Benchmark improvements therefore cannot establish record correctness, data quality, or release completeness.
