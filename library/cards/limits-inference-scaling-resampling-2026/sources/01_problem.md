Verifier-gated resampling is often summarized as “sample until one answer passes.” This paper asks when that procedure can actually close the gap between a weak and a strong generator when the acceptance test is incomplete. Its empirical object is an ordered set of Python solutions for HumanEval+ or MBPP+: each record links a task and model to a candidate, its sampling attempt, the original-test decision, the extended-test decision, and a true-positive or false-positive label. Original HumanEval/MBPP tests are the operational gate; the stronger EvalPlus suites are used only for retrospective auditing.

The work is therefore an evaluation and failure analysis, not a new training corpus or an LLM-training recipe. It belongs in the data-construction and release-recipe track because rejection-sampled datasets inherit exactly this acceptance contract: if builders retain only weak-verifier passes, increasing generation volume can increase apparent yield without establishing correctness. The official repository releases analysis code and sample bundles, but release completeness, exact lineage, checksums, and output-data licensing remain only partially documented.
