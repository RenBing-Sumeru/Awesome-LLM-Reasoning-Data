由 verifier 把关的重采样通常被概括为“持续采样，直到某个答案通过”。本文追问：当验收测试不完备时，这一过程是否真能弥合弱生成器与强生成器之间的差距。其实验数据对象是 HumanEval+ 或 MBPP+ 上按顺序生成的一组 Python 解答；每条记录把任务和模型与候选代码、采样轮次、原始测试结果、扩展测试结果以及真阳性或假阳性标签关联起来。原始 HumanEval/MBPP 测试负责实际验收，更强的 EvalPlus 测试只用于事后审计。

因此，这项工作是评测与失效分析，而不是新的训练语料或 LLM 训练配方。它与数据构造和开放发布配方轨道直接相关，因为 rejection sampling 数据集继承了同样的验收契约：如果构造者只保留弱 verifier 通过的样本，增加生成量可能提高表面产量，却不能证明正确性。官方仓库发布了分析代码和样本包，但发布完整性、精确 lineage、校验和与输出数据许可仍只有部分说明。
