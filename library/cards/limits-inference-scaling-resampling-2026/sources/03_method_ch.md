在 HumanEval+ 上，多数模型的每个任务至少分析 200 个样本，Command Light 为 1,000 个；MBPP+ 的每个任务和模型使用 50 个样本。采样温度为 0.8，其余设置沿用 EvalPlus 默认值。样本池同时包含多个开放模型此前发布的 EvalPlus 样本，以及为 Llama 3.1、Phi-3、GPT-4o 和 Cohere Command 系列新采集的样本。

给定预算 K，流程按顺序检查候选，遇到第一个通过原始测试的候选即停止；扩展测试随后把这一候选标为真阳性或假阳性。对每个不超过 200 的 K，有限预算实验将同一批已存储候选随机重排 1,000 次，并在假阳性成本收益比为 0、1、2、4、8 时计算效用。理论附录用容易任务与困难任务的混合模型解释：以先前拒绝为条件会改变剩余任务的分布。

另一条基于 RACE 的代码质量分支，在温度 0.8 下，对每个任务、模型和指令采样 50 个解答，检查 camelCase、snake_case、行长度和行注释要求。官方仓库提供分析 notebook，并链接 HumanEval+、MBPP+ 和代码质量三份样本压缩包；但没有带标签的 release 或统一 manifest，精确 API 快照、随机种子、请求日期和完整校验和均未知。
