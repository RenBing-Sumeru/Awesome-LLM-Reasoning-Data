Predicate induction is stateful. Algorithm 1 stores validated definitions in a shared buffer, reuses names across problems, materializes definitions when needed, and promotes frequently invoked predicates. A generated row can therefore depend on a changing library, but the public release does not identify the buffer version or construction order.

Program generation is type-aware: the prompt enumerates forms for numbers, fractions, equations, expressions, intervals, solution sets, vectors, matrices, trigonometric values, formatted numbers, units, and other structured answers. On MATH-500, the paper reports 68.2% verified accuracy for the complete two-stage predicate-and-type system, 41.6% for one-stage generation without predicate guidance, and 26.3% when the two-stage system omits answer types.

For GRPO, the paper defines program-level rewards of 2.0 for a correct clean program, 1.9 for a correct program with a singleton-predicate penalty, 0.5 for an incorrect program that invokes all suggested predicates, and 0 otherwise. The pinned public training script uses Qwen2.5-3B-Instruct with rank-32 LoRA, 4-bit loading, six generations per prompt, a device batch of six, eight-step accumulation, 3e-6 learning rate, and 20 epochs. Its implementation gives partial credit when any suggested predicate is detected, which is weaker than the paper's “all predicates” condition.

The public 6,093-row split exposes only `instruction`, `input`, `output`, `domain`, `answer`, and `predicates`. Original CoT, MATH ID, generator, retry number, execution log, parsed result, verifier components, reward, rejection history, and recovery lineage are not row fields.
