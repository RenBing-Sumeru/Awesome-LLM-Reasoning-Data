For the Data Construction and Open Release track, Prolog-MATH is most useful as a construction and verifier audit case. It provides a concrete decomposition of problem sourcing, predicate induction, shared-library reuse, answer-type prompting, program synthesis, SWI-Prolog execution, symbolic filtering, retries, supervised warm-starting, and GRPO recovery.

A stronger release following this recipe would preserve an immutable MATH ID, source CoT and gold answer, predicate-buffer revision, proposed and materialized predicates, generator and decoding settings, every candidate program, raw stdout and stderr, parsed answer, verifier components, keep/reject reason, reward components, recovery model, and final union membership. Retaining rejected candidates would make both the verifier boundary and recovery process auditable.

Reuse class: **blocked pending verification for direct training**. The public file is useful for schema inspection, small controlled SFT trials, and verifier stress tests after pinning the Hub revision, independently rerunning programs, checking source and code rights, and reconciling counts. It should not be treated as the paper's complete 97.4% union or as process-supervision data.

Useful studies include testing final-answer equivalence against human program review, comparing all-predicate versus any-predicate partial reward, measuring false acceptance by symbolic answer type, and ablating source CoT, shared-buffer state, retries, and recovery models. Report release revision, executable environment, checker commit, pass/fail counts, and manual logic error rates separately from MATH-500 accuracy.
