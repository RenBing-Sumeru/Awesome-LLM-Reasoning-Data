Inputs combine tau-bench-derived Retail and Airline Python-function APIs, domain policies and records, API metadata, PersonaHub personas, and few-shot examples. The API graph links A to B when B can consume A's output and policy permits their co-occurrence. Random walks choose multi-API contexts; write APIs anchor ground-truth actions. The paper says the final proceedings setup has 5 read and 13 write APIs, while the current project page says 15 read and 13 write APIs. These are versioned-source differences, not counts that should be merged.

Phase 1 generates a task blueprint with model thought, user intent, ordered ground-truth actions, expected outputs, and a state diff. It then applies format/JSON validation, executable API-name/argument/type checks, policy tests expressed as Python unit tests, and LLM-committee rubric scoring with majority voting. Above-threshold tasks are accepted; failures receive summarized feedback for iterative refinement. The committee membership, model versions, numeric threshold, temperatures, seeds, and exact sampling distribution are unknown. Reverse task recombination concatenates validated actions and outputs, synthesizes a combined intent, and reruns policy and semantic validation.

Phase 2 rolls out the blueprint with an LLM user, GPT-4o in function-calling mode, and the executable environment. The user simulator chooses among four candidate replies with self-critique. A task can receive up to three trajectory attempts. Interaction stops when the user concludes—the appendix prompt uses `###STOP###`—or when a predefined turn limit is reached. A run is retained only if its final environment-state effects agree with ground-truth actions and its assistant responses agree with expected outputs. All unique successes are kept; failed Phase-2 runs are discarded. Exact response matching, turn limits, endpoint revisions, decoding settings, and per-row actor lineage are undisclosed.

For training, each retained trajectory is split at every assistant response. Prompt and non-assistant tokens are masked, so the loss predicts assistant text and function calls. Reported filtered behavioral cloning uses LLaMA-Factory, full fine-tuning, DeepSpeed ZeRO-3, FlashAttention 2, bfloat16, AdamW, at most three epochs, and one NVIDIA H200 node over Llama 3.1/3.2 Instruct and Qwen 2.5 Instruct bases. APIGen-MT trajectories are mixed with APIGen function-calling data and other xLAM/ActionStudio agentic data; exact counts, weights, deduplication, and checkpoint-specific mappings are unknown. This supports SFT/agent behavioral cloning, not preference learning, reward-model training, process supervision, or RL.

The public output is `Salesforce/APIGen-MT-5k`: 5,000 rows, one `train` split, one `apigen-mt_5k.json` file, and no public failed split. It is explicitly a subset of xLAM-2 training data. Appendix B scales APIGen-MT samples as high as 8k in experiments, and final xLAM models use additional datasets; therefore the gated 5k file is neither the largest experimental condition nor the complete xLAM mixture.
