The public release is a success-only transcript subset, not the construction corpus. Phase 2 attempts each task up to three times, aggregates unique successes, and explicitly discards failures. APIGen-MT-5k therefore hides invalid calls, near misses, unsuccessful recovery, rejection reasons, and the true attempt distribution. Its single `train` split offers no development/test partition, split seed, task-family grouping, or mapping to private paper-era data.

Replay is blocked by missing environment and lineage fields. Public rows lack the task blueprint, ground-truth actions and outputs, initial/reset and final state, state diff, reward, validator and committee logs, attempt ID, seed, terminal reason, exact API/policy/database revision, and executable replay manifest. A visible conversation can be consumed by SFT, but it cannot independently rerun the terminal predicate or establish which construction checks accepted that row.

The verifier stack has unmeasured error modes. Format and type checks do not establish semantic correctness. Python policy tests can be incomplete or wrong. Final-state and response matchers can produce false positives or false negatives, yet their implementation and adversarial evaluation are not released. LLM committee scores and majority voting can share correlated model or prompt bias; committee identities, calibration, threshold, and per-row votes are unknown. Best-of-N self-critique may select judge-preferred rather than human-realistic user behavior.

Generator and training attribution remain incomplete. GPT-4o and DeepSeek-V3 are used across generation, validation, and interplay, but exact dated endpoints, stage assignments, prompts beyond representative appendix examples, temperatures, seeds, retries, and per-row model lineage are unknown. The final xLAM models mix APIGen-MT with APIGen and other xLAM/ActionStudio data. Public 5k, experimental scale up to 8k, and checkpoint-specific mixtures are not mapped to one another, so model gains cannot be attributed to the public file.

Version and code evidence are insufficient for reconstruction. The final paper and current project page disagree on the read-API count. The dataset has no verified tag or named release, so mutable `main` must be replaced by fixed card/file commits and the checked SHA-256. The HF “Code” target is an HTML/CSS/JS project-site repository, not verified synthesis, validation, filtering, training, or evaluation code. The related xLAM repository is a living multi-project repository and says data are only partially released; it is not a frozen APIGen-MT implementation.

Reuse rights require more than reading the SPDX-style label. Access is gated and the card declares CC-BY-NC-4.0, while also stating that GPT-4-generated portions must not be used to develop models competing with OpenAI. Per-row restricted provenance, tau-bench and PersonaHub rights, model-provider output terms, and coverage of upstream components are unresolved. Synthetic generation and the authors' statement that no sensitive personal information was collected reduce some risks but do not replace a per-record PII, consent, or source-rights audit.

No dedicated deduplication, semantic-overlap, or benchmark-contamination audit was verified. Construction and tau-bench evaluation reuse the same Retail/Airline API and policy substrate, and BFCL instance-level overlap is unreported. The 200-trajectory human audit lacks disclosed sampler, annotator count, agreement, and adjudication. These limitations support `partial` status and conditional SFT reading, not claims of an unrestricted, decontaminated, replayable, or RL-ready release.
