The archival source is the NeurIPS 2025 Datasets and Benchmarks Track paper, with arXiv:2504.03601 v4 as a separately versioned preprint and the official APIGen-MT project and Hugging Face pages as artifact records. The paper addresses a concrete gap in tool-use data: single-turn function-calling examples do not capture a user who reveals information incrementally, an agent that alternates between replies and API calls, or a mutable environment whose final state decides whether the whole interaction succeeded.

For its Retail and Airline case study, APIGen-MT treats interaction as a POMDP over user input, latent environment state, agent actions, observations, transitions, and reward. The construction object begins as a task blueprint containing a user intent, ordered ground-truth actions, expected outputs, state changes, and validation results. Phase 2 turns a validated blueprint into a simulated human-agent-environment episode and keeps it only when final state effects and response outputs agree with the blueprint. This is a full-episode mixed feedback contract, not merely a syntactic function-call check.

The public object is narrower than the construction object. `Salesforce/APIGen-MT-5k` is a gated, CC-BY-NC-4.0 release of 5,000 success-filtered rows in one `train` split and one 128 MB JSON file. A row exposes `conversations`, `system`, and `tools`: human messages, structured `function_call` messages, tool `observation` results, assistant text, a policy prompt, and tool schemas. It does not expose the blueprint, ground-truth actions or outputs, initial/reset or final state, state diff, reward, verifier votes or logs, attempt ID, terminal reason, or replay manifest.

This work belongs in `environment_agent_trajectory_data` because its trainable record is an ordered state-action-observation-style tool-use transcript and its acceptance predicate depends on an executable environment. The adjacent boundary is important: it does not release a version-pinned environment package, failed-trajectory corpus, preference pairs, process labels, reward-model targets, or an RL-ready replay interface. Its paper-demonstrated training use is assistant-token behavioral cloning, represented here only as `sft` and `agent_training`.

The atlas value is the auditable chain from API/policy context to blueprint, mixed validation, simulated interaction, success filtering, and an SFT subset. The official citation and public data artifact are verified, but the accepted metadata remains `L3_summary_ready` because code, immutable environment/version binding, row-level lineage, replay metadata, complete mixture information, decontamination, and license reconciliation remain unresolved.
