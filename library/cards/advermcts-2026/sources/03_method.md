For each problem, the method proceeds as follows.

1. Initialize a persistent Solver MCTS from the problem statement and visible public tests. Expanded nodes are partial chain-of-thought continuations; rollouts produce complete Python programs.
2. Execute each program on public tests. Public-test pass rate is the intrinsic Solver reward. A program enters the shared code pool only if it passes every public test and every adversarial test retained so far.
3. Run the persistent Attacker MCTS conditioned on the current code pool. An Attacker node represents a testing strategy. Divergence-driven multi-sample test synthesis generates a batch of candidate inputs, executes all pooled programs, and selects the input with the greatest output disagreement.
4. Send a divergent input, the specification, and the competing outputs to the same-backbone LLM output Arbiter. If the Arbiter considers the test ambiguous or invalid, discard it. Otherwise retain the Arbiter's expected output as an adversarial test.
5. Append the accepted pair to problem-local dynamic test memory. Recheck pool admission, penalize Solver nodes whose programs fail the test, and continue the alternating searches.
6. At the end, rank programs hierarchically by public-test pass rate and then by pass rate across all retained adversarial tests. Hidden tests are used only to report Pass@1.

The main experiments sample 100 problems from each of APPS Introductory, Interview, and Competition and TACO Easy, Medium, and Hard: 600 problems total, with at most five visible public tests per problem. Main settings are 16 Solver rollouts, 2 Attacker rollouts, maximum tree width 3, Solver UCB coefficient 4, and penalty value 0.1. The paper evaluates Qwen3-4B-Instruct-2507 and Qwen3-8B, with a DeepSeek-V3.2 671B scaling experiment. It reports vLLM execution but does not disclose a complete hardware, token, wall-clock, or dollar-cost contract.

The official repository README recommends `--rollout 16 --attacker_rollout 2`. At inspected commit `f45427800a32dc6966429bc4f7baf61df5c6a15f`, the driver defaults include tree width 3, code-pool size 2, divergence threshold 0.2, five candidate tests per synthesis batch, and seed 0; the implementation uses temperature 0.7 for test-input sampling and 0.0 for Arbiter calls. Some class-level fallbacks differ, so the command-line configuration should be logged rather than reconstructed from one source file. The paper does not disclose numerical values for every algorithm symbol, and the exact paper-version configuration is therefore partly unknown.

The released executor combines an 11-second in-process alarm with a 15-second parent monitor, a 10 MB captured-output limit, 4 GiB address/data/stack limits, and guards against selected destructive or process operations. These controls improve reliability, but the inspected repository provides no container, namespace, seccomp, or documented network isolation. It should not be treated as a security sandbox for arbitrary untrusted programs.
