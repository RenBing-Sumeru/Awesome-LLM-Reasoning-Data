Rejection-sampling fine-tuning (RFT) normally samples several solutions for a math problem, keeps a verifier-accepted solution, and throws away every rejected trajectory. TrajFusion asks whether those rejected generations can be converted into useful supervised data without adding an online environment, a learned reward model, a preference objective, or a modified training loss.

The paper's data object is one fused assistant target per retained problem. It contains zero or more complete incorrect trajectories, fixed transition phrases that mark another attempt, one verifier-accepted correct trajectory, and a boxed final answer. The record is therefore a synthetic trial-and-error transcript for ordinary next-token SFT, not a set of preference pairs and not a process-reward trace. When no eligible error is selected, the target reduces to correct-only RFT.

This distinction matters for `data_construction_open_release_recipes`: the paper specifies a concrete sampling, filtering, answer-verification, error-grouping, selection, and sequence-fusion recipe. However, no official constructed dataset, code repository, model checkpoint, project page, or Hugging Face collection was confirmed. The bilingual Card is `L4_chinese_review_ready`, while the release remains `partial`; this does not imply that the 15K or 100K data can currently be downloaded or independently replayed.
