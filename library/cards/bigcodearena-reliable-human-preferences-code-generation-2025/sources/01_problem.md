Human preference is valuable for judging code-generating systems, but users cannot reliably assess a long program by reading it alone. A response may look clean, persuasive, or stylistically attractive while failing to run, producing the wrong output, or behaving incorrectly in its intended framework. Conversely, a correct answer can be penalized when its execution behavior is invisible to the person making the comparison. Pure text-side preference collection therefore confounds subjective presentation with program behavior.

The problem is to collect code-generation feedback in an environment where people can inspect and interact with execution outcomes while still expressing human preferences about usability, explanation, and workflow. The feedback object must connect an instruction, competing code responses, execution environment and results, multi-turn interaction, and a human choice. Such data can separate what execution verifies from the residual judgments that still require people, and can reveal preferences that vary by programming language, task type, and framework.
