The intended user is a code-model or reward-model researcher. The task is to test whether a judge, reranker, or preference learner agrees with users after they observed executable behavior. Input is the released preference subset with code, conversation, environment, and output fields. Evaluate a judge with and without execution context, or train while preserving provenance and split boundaries. Output is execution-aware preference accuracy, calibration, or error analysis. Success means improved agreement without hiding environment-specific failures. Do not use the release as a security certification suite, a substitute for integration testing, or a universal measure of production code quality.
