ComplexMCP's central contribution is to make long-horizon MCP interaction evaluable through both required final-state changes and unintended collateral changes. The sandbox exposes many tools over interdependent applications; a deterministic seed establishes initial state and perturbations, and a recursive state-difference evaluator compares the resulting environment with the task target.

The data/evaluation object has two layers. The task layer binds a query and application set to a seed, difficulty level, accepted reference trajectory, reference call count, and target state. The episode layer is an ordered ReAct-style history of model or annotator text, named tool calls with JSON arguments, structured responses or errors, implicit state transitions, an end condition, and a captured final state. The current release materializes one accepted human reference episode for each of 47 tasks; evaluated model histories are reported chiefly through aggregate metrics rather than released as a complete corpus.

The feedback contract is explicit. Let the target-state diff contain `T` required changes. Completion is `M/T`, where `M` is the number of matched required changes. Misbehavior is `Mb/T`, where `Mb` counts collateral changes. Binary success requires completion 1 and misbehavior 0. The evaluator recursively compares nested state, excludes selected timestamp or random-ID fields, and applies special fuzzy matching to content fields. This contract observes encoded final-state requirements and unintended diffs; it cannot establish whether an unencoded semantic requirement was satisfied, whether a valid alternative state should count, or whether a reasoning trace is intrinsically high quality.

The closest comparison in the assigned track is tau2-bench: both treat an executable stateful environment as part of the verifier, but tau2-bench centers dual-control customer-service interaction and releases evaluated success/failure episodes under a paper-era tag. ComplexMCP instead centers large MCP tool spaces, cross-application dependencies, seeded faults, and final-state collateral-change accounting, while its current official release retains only accepted gold/reference episodes and lacks a paper-era release lock.

The direction signal is therefore not “more tools” alone. It is the coupling of stateful tasks, action/observation histories, target-state deltas, and collateral-change checks as one auditable evaluation object. That signal remains bounded by the public evaluator implementation, incomplete rollout retention, and uncalibrated security exposure.
