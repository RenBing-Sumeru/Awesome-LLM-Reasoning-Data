**Inputs and environment.** An undisclosed LLM is used to pre-populate synthetic application entities intended to resemble real-world distributions. Human curators then define cross-application natural-language tasks with deterministic unique outcomes and without explicit tool-name hints. A task selects applications and a seed; the seed controls initial state and execution perturbations, including transient network errors. The configured substrate has 15 MCP servers and 315 tools, split into seven stateful and eight stateless servers.

**Reference construction and acceptance.** Human experts interact through the MCP interface to write a ground-truth trajectory for each task. The inspected construction script serializes text, tool-call JSON, responses, and the end marker, then stores the row only after the annotator answers yes to `Pass this query?`. The full rubric, annotator identities and count, agreement procedure, rejected attempts, and rejection counts are unknown. The resulting parquet contains 47 accepted rows and seven fields: `seed`, `query`, `apps`, `level`, `output`, `tool_cnt`, and `gt_env`; all cells were non-null in the inspected snapshot.

**Model rollout.** The main evaluation uses ReAct. Full-context prompting supplies all tool descriptions, reported as about 29,964 tokens; fixed top-k retrieval and iterative retrieval variants use `all-MiniLM-L6-v2`. Each evaluated model runs independently three times on all 47 tasks. The client opens a new UUID session from the supplied seed, injects the session into stateful calls, and deletes it at logout. This is a seeded process-local reset rather than a released persisted snapshot.

**Stopping and observations.** Ordered model text, tool calls, and response blocks are accumulated. The agent can emit `[END]`; the current runner also stops after 100 turns or five consecutive non-tool responses. Tools can return structured successes or simulated failures. Exact provider revision, temperature, top-p, wall-clock budget, model-sampling seed, dependency lock, and fault-schedule export are not supplied by the current runner.

**Verifier and output.** The evaluator recursively computes the required target-state diff and extra collateral changes. Completion is matched required changes divided by required changes; misbehavior is collateral changes divided by required changes; success requires complete target satisfaction and zero collateral change. Content fields allow exact, substring, or Levenshtein-similarity-above-0.7 matches. The runner prints aggregate metrics but does not persist the complete evaluated rollout, trial identifier, model-sampling seed, environment hash, or result manifest.

**Use and reconstruction boundary.** The paper uses this pipeline only for evaluation. A defensible replay must pin the exact code/data/evaluator commit, dependencies, server configuration, model and provider revision, decoding settings, seed and fault schedule, task row, session behavior, and metric implementation. The official repository's current commit is inspectable, but no tag or release identifies it as the paper-era experiment snapshot.
