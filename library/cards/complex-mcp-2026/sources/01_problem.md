ComplexMCP is an ICML 2026 benchmark for evaluating language-model agents in a dynamic MCP sandbox. The primary paper is the ICML/OpenReview version, cross-checked against arXiv:2605.10787v2 and the official `ATH-MaaS/complex-mcp` repository. Artifact-level statements in this Card use current-main commit `617e963bd838bee5793a39e6b34165b79535828f`, inspected on 2026-07-20, because no tag or release connects that snapshot to the paper experiments.

The paper targets a gap between short, independent tool-use benchmarks and realistic workflows whose actions change shared state, depend on earlier actions, and can trigger transient failures. A task comprises a natural-language instruction, deterministic seed, available tools, initial application state, goal state, and evaluator. The agent must discover relevant tools, inspect state, execute interdependent actions, handle observations or failures, and finish without unrelated state changes. This is an evaluation problem, not a reported agent-training recipe.

The benchmark contains 47 manually curated tasks over 15 MCP servers and 315 tools: seven stateful application servers and eight stateless service servers. The stateful applications are LightOS/System, LightTalk, LightShop, LightWeather, LightFlight, LightStock, and LightNews. Queries omit explicit tool-name hints, while seeded initialization and perturbations make the environment itself part of the feedback contract.

The released data object is a 47-row, seven-column `data.parquet` table. Its fields are `seed`, `query`, `apps`, `level`, `output`, `tool_cnt`, and `gt_env`. Each `output` is one accepted human-authored successful reference demonstration containing reasoning/text, JSON tool calls, tool responses, and an `[END]` marker; `gt_env` is the nested target final state. The release therefore contains 47 successful gold/reference trajectories, not the complete successful and failed model rollouts from every model and trial reported in the paper.

This object belongs in `environment_agent_trajectory_data` because task state, action, observation, mutable transition, final state, completion, collateral change, and terminal outcome can be examined together. Its present evidence supports an L4-depth Card draft, while the accepted metadata correctly remains `L3_summary_ready` and `partial`: paper-era version identity, full replay artifacts, independent rights, and verifier/security calibration are unresolved.
