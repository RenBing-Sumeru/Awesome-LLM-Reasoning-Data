For `environment_agent_trajectory_data`, ComplexMCP is most useful as a version-explicit evaluation and audit substrate. A researcher can connect a task query and seeded initial state to tool selection, JSON arguments, responses or transient errors, mutable state transitions, final target diff, collateral changes, completion, misbehavior, and binary success. This supports failure attribution across tool retrieval, state inspection, planning, execution, recovery, and evaluator mismatch.

The construction pipeline is a concrete benchmark recipe: populate a synthetic application graph, write deterministic cross-application tasks without tool hints, author an executable reference path, gate it through human acceptance, and store both the reference interaction and target state. A stronger implementation should retain rejected candidates, explicit rubric decisions, annotator metadata, per-record provenance, immutable task/evaluator manifests, and complete model runs.

The feedback contract is useful for verifier research. Researchers can perturb required and unrelated state, build semantic-equivalence cases for fuzzy content matching, test every excluded-key path, inject each tool status, and compare automated judgments against blinded human labels. Prompt-injection-bearing LightTalk histories can form a security slice. These uses should report false-positive and false-negative rates rather than assuming that deterministic code is correct.

The released 47 gold/reference trajectories can support schema inspection, task understanding, evaluator unit tests, and paper-linked reproduction attempts. They should not be presented as a complete success/failure corpus, preference pairs, process-supervision labels, or general SFT/RL data. Independent data/model-output rights, split/decontamination controls, full rollouts, and replay manifests are absent.

Safe reuse level is **evaluation and audit only**, matching the accepted `training_use`. Pin commit `617e963bd838bee5793a39e6b34165b79535828f` when using the inspected release, and state that it is a current-main audit freeze rather than a paper-era lock. Benchmark scores compare configurations under the paper's contract; they do not certify data quality.
