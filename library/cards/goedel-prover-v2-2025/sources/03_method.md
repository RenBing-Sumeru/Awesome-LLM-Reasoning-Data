Formalizer construction precedes prover training. The paper reports that an initial 50K examples, including reasoning traces, are generated with Claude Sonnet 4. Goedel-Formalizer-V2 is then improved through expert iteration: proposed Lean statements must pass syntax checking and repeated LLM semantic evaluation before entering the next SFT round. On a 300-problem OmniMath comparison, the paper reports 228 passing formalizations for Goedel-Formalizer-V2 versus 161 for Kimina-Autoformalizer; this is a formalizer evaluation, not a per-item certificate for the training pool.

Scaffolded synthesis has two routes. The formal route applies Lean's `extract goal` tactic to unsolved states appearing in failed proof attempts. Extracted goals plus preconditions become new statements; because such a statement need not be provable, its negation is also added as a candidate. The informal route has Qwen3-32B first solve a source problem in natural language, then propose easier/subproblems if it is unsolved or harder variants if it is solved. These are autoformalized, screened by an LLM for mathematical correctness and difficulty, and exact-match deduplicated. Repeated judging is intended to reduce false rejection of hard items, but the error rate is not reported.

The SFT pipeline begins with teacher-generated, Lean-verified whole proofs (S1). SFT-S1 and DeepSeek-Prover-V2-671B then generate correction annotations; the latter run is reported to use NeMo-Skills on 144 H100s. S2 merges correction data into S1. SFT-S2 is averaged with the Qwen3 base model, used for scaffolded generation, and fine-tuned on S3. The resulting SFT-S3-AVG initializes RL.

RL mixes whole-proof and first-correction prompts equally. The appendix reports 50K challenging statements and 50K self-correction samples; each correction input includes a statement, failed model output, and error message. Training uses VeRL for one epoch, batch size 128, `n=8` parallel rollouts and Lean reward calls, mini-batch size 32, and a three-times oversampling pool. Prompts with pass rate 0 or above 0.75 are removed by dynamic sampling. Maximum prompt and response lengths are 16K and 24K, with a 4K overlong buffer and penalty factor 1. The objective uses token-averaged policy loss without KL or entropy terms. Generation temperature, random seeds, exact theorem-source proportions, and full accepted/rejected record counts remain unknown.

At inference, the main self-correction setup allows two revision rounds in a 40K context. Each failed proof is compiled, the specific error is returned alongside prior reasoning, and the model revises the proof. A 128K-context ablation permits five rounds. Official code targets Linux/Python 3.10 and Lean 4.9 with the corresponding Mathlib; the repository pins a mathlib4 submodule, but no immutable container digest is supplied.
