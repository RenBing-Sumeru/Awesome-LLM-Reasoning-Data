For `environment_agent_trajectory_data`, AndroidLab is a concrete blueprint for mapping an interactive mobile episode into auditable post-training fields: task source, XML or marked-screenshot observation, history, analysis/action target, environment state, completion judgment, and provenance. A reconstruction can use the dual observation modes to compare representation effects while holding the action vocabulary and benchmark tasks fixed.

The operation/query split is useful for verifier design. Builders can test UI-tree/device predicates for alternate valid states and XML drift, separately audit GPT-4o/GLM-4 semantic judging for paraphrases and false decisions, and log agent-selected Finish independently from evaluator completion. Fresh AVD/container reset, fixed time/location, 25-step budget, and direct in-app start form an evaluation baseline whose omitted image/APK hashes should become explicit checklist items.

For SFT, the defensible data recipe is human physical-device execution followed by second-annotator/reward-model cross-verification, privacy filtering, self-exploration exclusion, and XML-to-SoM conversion. The broader 10.5K-trace pool must not be represented as the SFT corpus. Training reuse is blocked pending dataset licensing, archive inspection/hashing, split and overlap disclosure, failure retention, and reconciliation of the 3-versus-5-epoch recipe.

Reuse class: suitable as a paper/code-backed evaluation and audit reference when the repository, environment, judge, and task configs are pinned; suitable as an SFT recipe reference, but not yet as unrestricted training data. The accepted `training_use` remains only `sft` and `evaluation`; the public evidence does not justify RLVR, preference optimization, reward-model reuse, or general agent-RL claims.
