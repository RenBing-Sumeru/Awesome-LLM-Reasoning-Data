Uniform test-time sampling gives every question the same number of responses even though easy questions may be solved once, medium questions may benefit from voting, and very hard questions may remain wrong at larger budgets. Under a shared average budget, independently maximizing each question's accuracy is infeasible because compute decisions are globally coupled. The paper asks how to route a discrete response budget per input before observing its outcomes.

AdaCompute-LLM turns this into an offline data-construction and supervised allocation problem. The central data object is a question-by-budget utility table: prompts are sampled repeatedly, responses are grouped into self-consistency windows for budgets 1, 2, 4, 8, and 16, majority-vote correctness estimates utility, a Lagrangian rule produces one oracle budget label for a target average cost, and a cheap feature vector is paired with that label to train a classifier. At deployment the classifier predicts a budget, the model generates that many responses, and majority voting returns the answer.

This is a test-time compute policy, not a released RL trajectory dataset. The official MIT-licensed repository implements the five-stage pipeline and dataset loaders, but no public release of the paper's 38,400 response records, utility matrices, seeds, oracle-label tables, or trained policies was confirmed. Prompt provenance beyond the stated MATH and GSM8K subsets, split identities, and full replay metadata therefore remain incomplete.
