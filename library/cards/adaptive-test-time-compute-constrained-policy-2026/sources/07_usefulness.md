For this track, AdaCompute defines the minimum lineage needed to audit adaptive sampling: prompt ID and source, model/API revision, 48 raw responses, sampling settings, answer-parser output, window membership at every budget, majority result, correctness indicator, utility estimate, cost definition, lambda, target budget, oracle label, feature vector, split, classifier prediction, and realized deployment cost.

Keeping the response table separate from the derived label enables re-labeling under different cost functions or budgets and reveals estimation uncertainty. It also separates test-time compute from training: the expensive repeated responses build a small supervised routing policy, while online execution uses only the selected budget. The official code is useful infrastructure, but absent raw tables prevent direct reuse of the paper's labels without recollecting model outputs.
