The experiments use 200 MATH questions stratified across difficulty levels 2-4 and 200 GSM8K questions. Three backbones are tested on MATH—DeepSeek-V3, GPT-4o-mini, and Qwen2.5-7B—while DeepSeek-V3 is also tested on GSM8K, giving four model-dataset settings. Temperature is 0.7. The paper collects 48 responses per question in each setting, not 48 responses independently for every question-budget pair. For budget b, it partitions those responses into floor(48/b) non-overlapping windows, majority-votes each window, and averages correctness. The appendix totals 200 times 48, or 9,600 responses per setting and 38,400 across all four.

For each target average budget, binary search over lambda converts the utility matrix into per-question labels. The feature vector contains 16 question-text statistics and a normalized entropy estimate. The default XGBoost classifier uses 100 estimators, maximum depth 5, learning rate 0.1, and multi-class log loss, with an 80/20 split and three random seeds. At inference, the selected number of responses is sampled and majority-voted; the ground-truth answer parser supplies the experimental terminal predicate.

The official repository implements response collection, feature extraction, oracle construction, GBM training, evaluation, figures, and MATH/GSM8K loaders, and displays an MIT license. Reproduction still needs provider credentials and current APIs. No pinned model/API revisions, exact sampled question IDs, raw response table, prompt templates, parser failures, per-window outcomes, stochastic-mixing seeds, trained classifier files, or cost measurements beyond number of samples were confirmed as released.
