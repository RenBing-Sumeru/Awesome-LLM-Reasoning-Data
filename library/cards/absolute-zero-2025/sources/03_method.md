The paper and pinned `paper` branch support the following reconstruction.

1. **Initialize the curriculum.** Begin from a human-specified identity-function triplet. Before any model update, use the pretrained base policy to generate valid seeds. For the 7B setup, `B × S = 64 × 4 = 256` records populate each initial buffer; both inspected 7B seed JSONL files have 256 rows.
2. **Sample proposer context.** For deduction or abduction, uniformly select `K = 6` historical `(program, input, output)` references. For induction, sample one program from the deduction/abduction buffers. Human-written role prompts and task formats wrap this context.
3. **Propose a task.** The current policy emits R1-style reasoning and answer sections. Deduction/abduction proposals specify a Python program and input, after which the executor derives output. Induction proposes ten inputs and a natural-language message for a buffered program; the executor derives ten outputs.
4. **Validate and buffer.** Parse task-specific blocks, run the program with a ten-second timeout, require a returned value, reject configured forbidden modules/keywords, and run twice to check matching outputs. Induction requires all ten inputs to execute. Every valid task enters the buffer regardless of difficulty; current proposals fill solver batches and historical records backfill shortages.
5. **Estimate proposer learnability.** Run eight current-policy solver attempts per proposed task. Let their success rate estimate difficulty. Equation 4 gives learnability `0` when success is zero and otherwise `1 - success_rate`; the implementation maps a non-positive terminal role score to `-0.5`.
6. **Construct solver instances.** Deduction exposes program and input and asks for output. Abduction exposes program and target output and accepts any input whose execution reaches that output. Induction exposes five I/O examples plus the message and checks the generated program on the other five hidden examples.
7. **Assign terminal rewards.** Correct, formatted outputs receive the role reward. Wrong but well-formatted outputs receive `-0.5`; format failures receive `-1`. The reward tensor is attached at the final response token, with no step-correctness labels.
8. **Optimize six role groups.** Task-Relative REINFORCE++ uses six task-role baselines and a clipped PPO objective. The paper setup uses AdamW, learning rate `1e-6`, gradient clip `1.0`, one PPO epoch, entropy coefficient `0.001`, and no KL loss or KL reward.

Main 7B settings are batch `64 × 6`, 500 steps, prompt length 6144, response length 8096, rollout temperature `1.0`, top-p `1.0`, one training rollout, eight accuracy-estimation samples, and six references (paper §4.1; Appendix Table 4). Experiments reportedly took about 3-5 days on A800 clusters; the paper-branch README specifies 2/4/8 80GB GPUs for 3B/7-8B/14B.

Reproduction must pin the `paper` branch because `master` has drifted and the repository has no tag or release. It must also isolate the executor: the released implementation uses raw Python `exec`/`eval` in worker processes, a denylist, and timeout, and its README warns that it is unsafe for production. Exact paper-run buffers, random seeds, complete rollout/reward streams, checkpoint hashes, and run-to-log mappings are not released.
