- **Agreement is not an oracle.** Sixteen candidates from the same QWQ-32B teacher can share an algorithmic misconception. Generated inputs may omit the edge case that separates wrong solutions, and reported oracle-comparison accuracy drops from 96.8% to 92.8% at the larger evaluation scale.
- **Threshold semantics vary.** The paper uses 60% agreement, lowered to 40% for Codeforces-derived problems rated above 1600; 40% is not a strict majority. The released script uses strict `>` and per-input plurality rather than voting on complete output sets, then removes constant-output problems.
- **Seed supervision is mixed.** If no QWQ-32B solution passes a difficult seed problem, the recipe retains all generated solutions. Public `seed_sft` examples also expose `verified` and `is_passed` flags, so “verified dataset” must not be interpreted as every SFT row having passed tests.
- **Generated validators can be wrong.** Test-input generators and validators are written by LLMs and executed, but no independent semantic specification proves that their accepted inputs cover all constraints. The authors explicitly report difficulty with problems whose constraints are implicit.
- **Selection changes the target.** Keeping the fastest passing synthetic solution introduces an efficiency preference beyond correctness and can select brittle or environment-sensitive code.
- **Release lineage is unresolved.** Table 1 reports 380,560 retained synthetic problems and 418,314 total problems; public synthetic configs contain about 398K rows each, the paper trains on 580K pairs, and Appendix Table 6 says 480K unique problems. No row manifest reconciles these quantities.
- **Joins and splits are incomplete.** All five configs are train-only. `synthetic_sft` lacks `question_id`, testcase links, and verification fields, and the test configs are only partially indexed by the public viewer. There is no held-out verifier-calibration split.
- **Code is partial and unsafe to trust directly.** The supplemental LLM helper is unimplemented, `cyaron_docs.md` is missing, and the synthesis CLI references an undeclared argument. Generated utilities and function-based solutions run with `exec`; external container or VM isolation is required.
- **Provenance and rights are coarse.** The release gives platform-level `seed_source` and an aggregate CC BY 4.0 label but not original URLs or a source-by-source license and terms matrix. The separate MIT project repository does not automatically license the supplemental ZIP or data.
- **Reproduction metadata is missing.** Construction model snapshots, decoding settings, seeds, retry policy, accepted/rejected manifests, total token/API cost, exact paper-training membership, and official checkpoint hashes are unknown.
- **Evaluation scope is narrow.** Results cover competitive programming and standard code-generation benchmarks. They do not establish general software-engineering usefulness, security, maintainability, cross-language behavior, or data quality outside the tested protocol.
