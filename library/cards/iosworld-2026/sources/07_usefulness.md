For the `environment_agent_trajectory_data` track, iOSWorld is an evaluation-environment recipe. A robust derived record should preserve task ID and rubric, seed-state version, app/build manifest, simulator and toolchain versions, observation modality, screenshots/XML, normalized actions or MCP calls, execution errors, final state/answer, stop reason, model/API settings, criterion labels, scalar fraction, strict pass, and raw judge response. Joining successes and all failure classes to the same pinned task object would support planning, grounding, loop, premature-stop, judge-error, and environment-drift audits.

The released rubric evaluator is useful for feedback-contract studies. Researchers can compare the full-trajectory LLM judgment with programmatic end-state checks or human labels, stratify false positives and false negatives by criterion/category, test alternate valid paths and harmful intermediate actions, and measure label drift across fixed judge snapshots. The public 1,123 criteria are also an evaluator-gaming surface and should not be treated as hidden reward.

The GUI-versus-MCP setup enables controlled interface studies if model, tasks, 50-step budget, judge, and seed state remain fixed. Such studies should separately report privileged XCUITest or persistence-layer access, confirmation settings, and screen-visible GUI actions; otherwise improved scores can be misattributed to reasoning instead of a stronger action interface.

The current reuse class is **evaluation and audit only**, matching `training_use: evaluation`. Direct SFT, RL, preference, or reward-model reuse is blocked because no full trajectory corpus, training/evaluation partition, decontamination policy, immutable replay bundle, judge snapshot, or complete asset/license lineage is available. Benchmark performance motivates these audits but does not certify episode quality.
