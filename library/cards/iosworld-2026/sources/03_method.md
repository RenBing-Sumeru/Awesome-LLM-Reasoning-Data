**Inputs and construction.** Authors built one synthetic persona and connected seed records across 26 SwiftUI apps. Claude Code, with full app-source and seed-data access, generated 175 task candidates. A Python pipeline normalized app names, rewrote instructions into first person, and generated rubrics. Humans executed every candidate end-to-end, corrected 44, trimmed single-app tasks for coverage and minimal duplication, retained all multi-app and memory tasks, and produced 133 tasks with 1,123 criteria. The generator prompt, Claude Code snapshot, decoding settings, 44 correction diffs, 42-removal ledger, reviewer identities, and record-level provenance are unknown.

**Reset and rollout.** The released runner shuts down and boots the simulator, wipes app and shared-container data, launches all apps to recreate seed state, terminates them, and returns to home. An evaluated provider adapter then receives either a 706x1536 screenshot or that screenshot plus a cleaned XCUITest tree capped at 200 elements and 15 levels. Common actions are coordinate tap, type, swipe, home, wait, and stop; vision+XML adapters can also expose identifier tap, launch, terminate, and URL opening. The loop uses Appium/XCUITest and ends on `stop` or a 50-step cap. Optional MCP mode substitutes typed app-specific tools while retaining screenshots.

**Outputs and feedback.** A generated run can write per-step screenshots/XML, planned and executed actions, execution errors, optional reasoning summaries and LLM messages, pre/post-action views, `trajectory.json`, `events.jsonl`, `task.json`, final state and answer, token usage, evaluator output, and run metadata. GPT-5.4 Mini then judges the full trajectory and rubric. Criterion satisfaction is averaged into a scalar fraction; all criteria must pass for strict success. Runner statuses such as execution `failed` or `safety_blocked` are distinct from ordinary rubric failure.

**Use and reproducibility.** The paper uses these episodes only for evaluation across twelve model-by-modality configurations. Main results report one aggregate outcome per task/configuration, not repeated stochastic rollouts. The code logs simulator UDID, platform/device, Xcode, Python, Node, Appium, macOS, provider/model, temperature, budget, observation/action modes, manifest, and task file, but the published results are not bound to an immutable run manifest. Reproduction requires pinning the repository commit, task file, app builds, Xcode/iOS/Appium/WebDriverAgent stack, device geometry, reset manifest, provider APIs, temperature, seeds, retries, timeouts, judge snapshot, and result checksums. No train/dev/test field, decontamination procedure, complete raw run bundle, or deterministic replay test is released.
