步骤 1：扩展数学题目。
输入：GSM8K 与 MATH 的训练题。
操作：通过改写、条件变换、正向反向变换、双射变换和表达式替换，从多个角度扩展每个种子题。
输出与流转：原题和扩展题按来源与变换方式组成二十个子集，进入解答生成。
检查/停止规则：保留来源与变换类型；题目格式错误或无法建立答案目标时停止推进。

步骤 2：编写前置推理与可执行轨迹。
输入：通过检查的题目，以及要求先分析问题再写代码的教师提示。
操作：让 GPT-4 生成前置自然语言推理、交错 Python 代码、结合执行反馈的后续分析和最终答案。
输出与流转：含推理、代码和答案的候选助手消息进入解释器检查。
检查/停止规则：生成达到配置的执行轮数即停止；语言流畅不能代替正确性证据。

步骤 3：执行代码并保留纠错行为。
输入：候选轨迹中的 Python 代码块。
操作：在外部解释器中运行代码；若执行失败，就追加错误与此前上下文，请求修正代码并再次运行。
输出与流转：轨迹保留失败代码、反馈、修正和成功输出，然后进入答案过滤。
检查/停止规则：得到最终结果或达到最大轮数时停止；复放时只能使用隔离解释器。

步骤 4：使用已知答案或伪答案过滤。
输入：候选轨迹、来源题真值，以及没有真值的变换题的多次预测。
操作：来源题直接匹配真值；变换题先取多数投票伪答案，再保留与之相符的轨迹。
输出与流转：从二十个子集各选 30K 条，形成 600K 条第二阶段示范。
检查/停止规则：答案不一致即删除；伪答案一致只能记为结果证据，不能当作逐步证明。

步骤 5：训练两阶段消费者并检验数据契约。
输入：先使用 751K 条自然语言记录，再使用 600K 条工具示范。
操作：对 Llama-2 或 CodeLlama 第一阶段训练三轮，第二阶段续训三轮，并用解释器辅助解码评测。
输出与流转：MuMath-Code 模型，以及单阶段、无前置推理、无纠错和无伪答案对照共同组成证据包。
检查/停止规则：固定两份数据、模型、解释器、执行预算和评测脚本；归因轨迹组件前必须与单阶段对照比较。
