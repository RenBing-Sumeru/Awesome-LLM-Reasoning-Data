ToRA and related tool-use recipes interleave language and Python over existing question sets, while MuMath diversifies prompts but trains natural-language reasoning without executable correction traces. MuMath-Code changes the released supervision object by combining multi-perspective questions, prefix analysis, failed code, interpreter feedback, corrected code, and an answer target in one SFT record, then separating natural-language and tool learning into two stages. Code execution, CoT, question augmentation, and majority voting are not individually new; the direction signal is the auditable composition and the ablations that remove prefix reasoning, debugging, staging, or pseudo-answer filtering. The evidence does not isolate a universal optimal ordering beyond the tested Llama-2 and CodeLlama consumers.
