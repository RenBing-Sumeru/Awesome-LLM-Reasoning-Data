- 最终答案等价判断只是 outcome check。它可能奖励推导错误但恰好落到参考值的路径，也可能拒绝 parser 不支持形式下的等价答案，还可能继承错误的参考标签。附录 E 就给出一个例子：参考答案漏掉有效端点，导致评估器把模型的正确结果判错。
- 回传的 Q 值估计的是当前策略、价值头、PUCT 规则、temperature、扩展宽度、树数量、simulation 数和深度限制共同定义的回报。它不是稳定、与策略无关的局部逻辑正确性标签；早期轮次的目标还受随机初始化价值头影响。
- Python 执行只能确认代码运行并产生观察，不能证明代码正确建模了题意。论文抽样错误包含生成代码错误、浮点精度错误和逻辑错误；Algorithm 3 只能启发式过滤其中一部分。
- 公开文件只有经筛选的第三轮路径，不包含完整搜索树或全部被拒候选。缺失 visit count、父子关系、选择历史、准确树归属、前两轮数据与逐行来源/标签 manifest，因此难以重放流程或系统分析 checker 错误。
- 论文与官方仓库仍有复现缺口。正文与附录 Table 6 对主实验价值损失权重分别给出 0.01 和 0.1；精确构造 temperature 与随机种子未固定；仓库只发布部分训练函数说明，并明确提示公开代码可能与内部公司代码库不同。
- 论文未报告明确的语义去重、train-test 去污染或基础模型预训练重叠分析。域内评测来自同时提供构造 prompt 的 benchmark 家族，而 OOD benchmark 也不能排除预训练污染。
- 代码仓库采用 MIT，但 Hugging Face 数据卡的 license 字段为空。GSM8K、MATH、其衍生问答记录以及模型生成轨迹的权利与署名义务仍需逐来源审核。
- 主 benchmark 表没有报告运行级置信区间或不同随机种子的变化。报告增益支持所测试的系统配置，却不能证明数据质量、标签校准或对其他生成器与 verifier 的迁移能力。
