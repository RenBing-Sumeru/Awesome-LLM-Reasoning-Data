AlphaMath represents a partial solution as a state and one generated reasoning step as an action. A step may contain textual analysis, Python code, and interpreter output, or it may be a terminal answer step. MCTS explores these actions using the language-model prior and a value head. Nonterminal rewards are zero; when a path terminates, final-answer equivalence supplies +1 or -1. The returned reward or the value prediction at a newly expanded nonterminal node is backed up through the visited edges, and the resulting Q value for an edge becomes the training target for its child state (Paper §2–§3.1).

The resulting data object is richer than a conventional question/rationale pair. The public round-3 file stores top-level `id`, `answer`, `instruction`, `input`, and `output` fields. `output` is a serialized list of step records containing the generated step, policy prior `P`, backed-up `Q`, and depth; the final `Q` identifies the selected path as positive or negative. Correct paths train the language-model policy, while both correct and incorrect paths train the value head (Paper Eq. 6; official implementation notes).

This feedback contract is mixed. The terminal signal is programmatic answer equivalence, optional Python execution supplies observations, and the dense intermediate target is a search estimate produced by the current policy/value model and MCTS budget. A `Q` value is therefore not an independently verified claim that a particular line of reasoning is logically correct.
