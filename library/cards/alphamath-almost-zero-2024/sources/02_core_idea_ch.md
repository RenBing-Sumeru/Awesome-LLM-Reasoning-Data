AlphaMath 把部分解答表示为状态，把一次生成的推理步骤表示为动作。一个步骤可以包含文字分析、Python 代码与解释器输出，也可以是终局答案步骤。MCTS 使用语言模型先验与价值头探索这些动作。非终局奖励为 0；路径终止后，最终答案等价判断给出 +1 或 -1。新扩展节点若已终止就返回该奖励，否则使用价值预测，再沿访问过的边回传；边上的最终 Q 值成为其子状态的训练目标（论文 §2–§3.1）。

由此得到的数据对象比普通的“题目—rationale”对更丰富。公开的第三轮文件以 `id`、`answer`、`instruction`、`input` 和 `output` 为顶层字段。`output` 是步骤记录列表的序列化字符串，每条记录包含生成步骤、策略先验 `P`、回传的 `Q` 与深度；末步 `Q` 标识所选路径为正例还是负例。正确路径训练语言模型策略，正确和错误路径都训练价值头（论文 Eq. 6；官方实现说明）。

这里的反馈契约是混合式的：终局信号来自程序化答案等价判断，可选 Python 执行提供观察，而稠密的中间目标是当前策略/价值模型与 MCTS 预算共同产生的搜索估计。因此，某个 `Q` 值并不是对相应推理步骤逻辑正确性的独立验证。
