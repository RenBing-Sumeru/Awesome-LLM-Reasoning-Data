- Final-answer equivalence is an outcome check. It can reward an invalid derivation that lands on the reference value, reject an equivalent answer outside the parser's supported forms, or inherit a wrong reference label. Appendix E includes a case where the evaluator marks the model wrong because the supplied answer excludes a valid endpoint.
- A backed-up Q value estimates return under the current policy, value head, PUCT rule, temperature, expansion width, tree count, simulation count, and depth limit. It is not a stable, policy-independent annotation of local logical correctness. Early-round targets also depend on a randomly initialized value head.
- Python execution verifies that code ran and produced an observation, not that the code models the question correctly. The paper's sampled errors include generated-code, floating-point precision, and logical mistakes; Algorithm 3 only heuristically filters some of them.
- The released file contains selected round-3 paths, not complete trees or all rejected candidates. It omits visit counts, parent/child links, selection history, exact tree membership, earlier rounds, and a row-level source/label manifest, limiting replay and checker-error analysis.
- The paper and official repository leave reproducibility gaps. The paper text and Appendix Table 6 disagree on the main value-loss weight (0.01 versus 0.1); exact construction temperatures and random seeds are not pinned; the repository releases only selected training-function details and warns that public code may differ from the internal corporate codebase.
- No explicit semantic deduplication, train-test decontamination, or base-model pretraining-overlap analysis is reported. In-domain evaluation uses test splits from the same benchmark families that provide construction prompts, while OOD benchmark use does not remove possible pretraining contamination.
- The code repository is MIT, but the Hugging Face dataset card has an empty license field. Rights and attribution obligations for GSM8K, MATH, their derived prompt/answer records, and model-generated traces require source-level review.
- Primary benchmark tables do not report run-level confidence intervals or seed variation. The reported gains support the tested system configuration but do not establish data quality, label calibration, or transfer to other generators and verifiers.
