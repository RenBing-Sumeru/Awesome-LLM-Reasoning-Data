The contribution is not merely using MCTS at test time. AlphaMath makes the search tree an iterative data-construction substrate. Terminal answer checks yield positive and negative solution paths; MCTS backup turns sparse outcomes and current value predictions into step-end regression targets; a jointly trained policy/value model then generates the next round. Failed paths are retained as first-class supervision for the value model rather than discarded after rejection.

Relative to pipelines that obtain complete rationales from humans or GPT-4, the external semantic supervision is reduced to questions and final answers. Relative to ordinary rejection sampling, the method retains intermediate search statistics and trains a value head on both successes and failures. Relative to a conventional process reward model, however, its target is not independently annotated step correctness: it is the estimated return of a state under a particular policy, tree policy, evaluator, and finite search budget.

The open-release contribution is correspondingly limited but useful. The round-3 dataset preserves selected path-level steps, priors, Q values, depth, source ID, and final-answer reference, allowing audits that a plain SFT `prompt`/`response` release would not support. It does not preserve all candidates, visit counts, parent/child pointers, selection histories, or earlier rounds. The novelty should therefore be understood as a search-derived supervision recipe plus a partial selected-trace release, not a fully replayable search log.
