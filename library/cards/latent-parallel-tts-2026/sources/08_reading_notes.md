Read coverage curves before aggregation results. Coverage answers whether sampling can uncover a correct latent path; LatentRM results answer whether the system can identify one after it exists. The paper's strongest conceptual value is this separation, because it prevents a poor selector from being blamed on a sampler or a low-diversity sampler from being hidden by a strong scorer. The GitHub release is the practical starting point for checking latent-backbone compatibility and the exact noise schedules.
