Construction starts from merged pull requests linked to issues in the 12 repositories. Attribute filters require test-related changes and a linked issue, yielding 14,333 PRs. DeepSeek intent classification plus manual feature rechecking leaves 2,931 feature-addition candidates. Base-commit environment setup, pre-patch FTP failure, and post-gold-patch execution reduce this to 580. GPT-5.2 audits semantic, necessity, and structural quality; 52 are removed, producing 528 instances.

Issue text supplies the feature request, and developer discussion may provide hints. DeepSeek generates concept explanations, goal expectations, entity purposes, and necessity labels. Gold/test patch analysis anchors files and entities; test-driven file ablation helps assess necessity; a fixed taxonomy organizes minimal ordered steps. Two authors inspect 50 auditor-accepted and 50 rejected candidates and agree with GPT-5.2 on 96/100, but all construction prompts, outputs, rejections, and human labels are not released.

The paper describes per-release Environment Docker images and an isolated Instance Docker for each evaluation. The repository is reset to the base commit, cloned, and installed as needed. Agents receive feature request and FTP tests, then search, inspect, edit, and test until emitting a patch. PTP tests, gold/test patches, and reasoning references remain evaluation-side assets.

Full evaluation runs AutoCodeRover, TraeAgent, and mini-SWE-Agent with DeepSeek V3.2 on all 528 instances. One attempt is used per agent-instance with temperature 0, top-p 1, 4,096 maximum agent-generation tokens, and 8,192 summarizer tokens. Lite uses randomized local search to select 100 tasks whose observed patch-success and apply-success rates match those three configurations; it is not an independent holdout.
