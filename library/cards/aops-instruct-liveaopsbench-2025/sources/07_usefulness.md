For the Data Construction and Open Release Recipes track, this paper is a worked example of turning one evolving community source into two different reasoning-data products. A controlled replication can hold the crawl and extraction stages fixed, then compare training selection (10-gram decontamination, proofs allowed) with evaluation selection (timestamp window, 8-gram filtering, concrete boxed answers, dual rewrites, answer agreement). This makes source, behavior, feedback, selection, and audit separable experimental variables.

A reusable training record should retain a stable topic ID, canonical thread URL, first-post ID and timestamp, selected answer-post ID, a privacy-preserving contributor reference, raw question, raw answer, rewritten solution, model and prompt revisions, decoding/retry settings, every filter decision, and source-edit/deletion status. The model-ready view can omit sensitive fields, but a release steward still needs a protected lineage table for correction, attribution, and takedown. A license label should be tied to each source class rather than inferred from the code license.

A reusable live benchmark should bind an immutable snapshot ID and HF commit to exact first/last post dates, source IDs, overlap inventories, answer-normalization code, rewrite-model revisions, rejected disagreements, human-audit sample, and scoring-code version. Evaluators should report the tested model checkpoint, known pretraining/post-training cutoff, evaluation date, and whether that benchmark snapshot was public during training. The 2023 retrospective split, LiveAoPSBench-0824, and the full-2024 release should be named separately.

The paper also supports concrete audit experiments. Re-run extraction on a stratified set of topics and compare selected post IDs; compare Qwen and Llama rewrites with symbolic and expert process checks; measure false accepts/false rejects for string, numeric, and SymPy comparison; test semantic rather than only n-gram overlap; and publish stage-by-stage counts plus accepted and rejected manifests. These studies directly evaluate the feedback and selection contract instead of treating downstream accuracy as a proxy for trace correctness.

Reuse class: currently suitable as a construction, audit, and replication reference. The pinned LiveAoPSBench artifact can support guarded evaluation after checking its terms and the model's cutoff. Training reuse of the linked AoPS-Instruct file is blocked pending author-maintained equivalence, source-level provenance, rights/attribution review, and immutable manifests. The paper supports `sft` as the demonstrated training use, but does not support RLVR, reward-model, or process-supervision claims.
