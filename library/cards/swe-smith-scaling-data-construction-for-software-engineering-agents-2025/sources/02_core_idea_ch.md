核心设计是"先环境、后任务"。对于符合条件的仓库,SWE-agent 最多用 100 步在最新提交上寻找安装和测试命令;人工随后提取并核验这些说明,要求现有测试通过率超过 80%,实现测试输出解析器,并构建 Docker 镜像。同一仓库与提交下的任务复用该镜像,而不是每个任务各自打包环境。

SWE-smith 在环境内通过五条路线生成会引入故障的 diff:LM Modify 尝试在修改函数时加入错误;LM Rewrite 根据函数头和文档字符串重新实现函数;程序化方法变换 Python 语法树;Patch Combination 组合同一文件或模块中已有的修改;PR Mirror 则让语言模型在当前仓库版本上撤销某个拉取请求对 Python 文件的改动。流程应用候选修改并运行测试,只保留至少让一个原本通过的测试失败的候选,并丢弃测试运行超过两分钟的候选。

失败测试是构造反馈,而不是学习得到的奖励。生成问题描述时,语言模型接收故障 diff、随机选取的一个 Fail-to-Pass 测试源码以及测试输出,再写成带复现代码的 GitHub 风格问题。修复阶段的可执行判定器检查 Fail-to-Pass 与 Pass-to-Pass 两组测试。这样,任务构造与轨迹筛选共享同一套程序化契约,而语义现实性仍需单独审计。
