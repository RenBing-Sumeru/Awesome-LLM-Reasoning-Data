论文所呈现的 SWE-smith 不是隐藏测试基准。目标测试仍留在仓库中,而问题生成会使用故障 diff、失败测试和执行输出。论文明确说明,没有检查生成问题是否歧义、描述不足或泄漏解法。因此,一个任务可能可以执行,却不像真实问题、暴露过多信息,或能够通过利用可见测试来解决。

判定器会继承测试套件的盲区。要求至少一个原本通过的测试变为失败,只能证明注入修改改变了被测试覆盖的行为;它不能证明合成故障有实际意义、Pass-to-Pass 覆盖了所有回归,或生成问题准确描述了故障。测试覆盖较弱的仓库候选产率也更低,超时还可能把基础设施成本与候选无效混在一起。

单条数据并不足以独立重现结果。任务行只给出镜像名称,没有不可变摘要;完整结果还依赖仓库提交、镜像可用性、安装与测试说明、输出解析器、SWE-agent 版本、智能体配置、教师 API 行为和解码设置。原始任务发布、后来显示 59,136 行的元数据、按语言维护的后续版本、论文时点 5,016 行轨迹快照,以及后来 24K–26K 规模的发布视图,不能视为同一个固定数据集。

许可同样具有多层来源。工具包和数据卡声明 MIT,但每个源仓库、依赖、测试、拉取请求和生成问题都有各自的来源。排除 12 个 SWE-bench 测试仓库减少了与该基准的直接任务重叠,但模型预训练、共享代码、问题文本或仓库层面的更广泛污染仍未知。最后,40.2% 的基准结果只是聚合的下游证据,不是每个任务或轨迹都有效的证明。
