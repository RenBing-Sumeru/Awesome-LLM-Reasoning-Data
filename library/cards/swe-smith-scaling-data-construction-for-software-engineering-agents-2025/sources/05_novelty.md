The main novelty is not a new test oracle. It is the inversion of the collection order: spend bounded human effort once on a repository-level environment, then reuse that environment to generate and verify many tasks. The paper estimates about seven minutes of manual work to extract installation and test instructions and about one minute to implement a test parser per repository, with roughly 20 total author-hours for the reported collection.

This design changes both storage and sampling. The paper reports 125 shared images using 290.54 GB, compared with an estimate of 50–150 TB if 50,000 instances each followed a per-task-image design. It also makes candidate generation modular: LM-based rewrites, deterministic syntax-tree mutations, combinations of validated patches, and pull-request mirroring all feed the same execution filter.

For reasoning-data curation, the important second contribution is the explicit bridge from task generation to full-episode data. The same executable task can yield multiple attempts; outcomes permit rejection sampling; a per-task cap controls oversampling of repeatedly solved tasks; and action-format conversion makes teacher episodes compatible with the student scaffold. The release therefore connects source task, environment, feedback contract, episode, and training selection more directly than a collection of issue-and-patch pairs.

The novelty has a boundary: the verifier is still the repository's existing test suite, issue descriptions are generated from privileged construction evidence, and the successful training subset removes most information about why attempts failed.
