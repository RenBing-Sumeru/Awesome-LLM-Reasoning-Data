The central design is environment first, tasks second. For an eligible repository, SWE-agent is given up to 100 steps to discover installation and test commands on the latest commit. A human then extracts and verifies those instructions, requires more than 80% of existing tests to pass, implements the test-output parser, and builds a Docker image. Tasks from the same repository and commit reuse that image instead of packaging one image per task.

Within the environment, SWE-smith creates bug-inducing diffs through five routes: LM Modify changes a function while trying to introduce an error; LM Rewrite reimplements a function from its header and docstring; procedural transformations mutate Python syntax trees; Patch Combination joins already generated edits from a file or module; and PR Mirror uses an LM to undo Python-file changes from a pull request against the current repository version. Candidates are applied and tested. Only those that make at least one previously passing test fail are retained, and runs over two minutes are discarded.

The failing tests are construction feedback, not a learned reward. For issue generation, an LM receives the bug diff, source for a sampled Fail-to-Pass test, and test output, then writes a GitHub-style problem statement with reproduction code. At repair time the executable grader checks the Fail-to-Pass and Pass-to-Pass groups. This gives task construction and trajectory filtering a common programmatic contract while leaving semantic realism as a separate audit question.
