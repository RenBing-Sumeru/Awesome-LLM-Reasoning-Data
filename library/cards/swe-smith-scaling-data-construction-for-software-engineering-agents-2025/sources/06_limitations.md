SWE-smith as presented is not a hidden-test benchmark. The target tests remain in the repository, and issue generation is conditioned on a bug diff, a failing test, and execution output. The paper explicitly notes that it does not check generated issues for ambiguity, underspecification, or solution leakage. A task may therefore be executable yet unlike a real issue, overly revealing, or solvable by exploiting visible tests.

The verifier inherits test-suite blind spots. Requiring one previously passing test to fail proves only that the injected edit changes tested behavior. It does not prove the synthetic bug is meaningful, that Pass-to-Pass coverage captures every regression, or that the generated issue faithfully describes the failure. Candidate yield is lower in repositories with weaker coverage. Timeouts can also mix infrastructure cost with candidate invalidity.

Reproduction is not fully self-contained at the row level. Task rows identify an image name but not an immutable digest, and the full result depends on repository commit, image availability, installation and test instructions, output parser, SWE-agent version, agent configuration, teacher API behavior, and decoding settings. The original task release, later 59,136-row metadata, language-specific successors, the 5,016-row paper trajectory snapshot, and later 24K–26K release views must not be treated as one fixed dataset.

Licensing also remains layered. The toolkit and dataset cards state MIT, but each source repository, dependency, test, pull request, and generated issue has its own provenance. Excluding the 12 SWE-bench test repositories reduces direct task overlap with that benchmark, but broader contamination through model pretraining, shared code, issue text, or repositories is unknown. Finally, the 40.2% benchmark result is aggregate downstream evidence, not proof of validity for every task or trajectory.
