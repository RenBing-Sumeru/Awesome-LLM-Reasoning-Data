The central contribution is a two-stage length contract. During data construction, QwQ-32B-Preview writes response trajectories for Code Evol-Instruct questions, producing a training mixture that the paper characterizes as shorter reasoning for lower-complexity prompts and longer reasoning for higher-complexity prompts. During inference, Shifted Thinking Window (STW) limits the first reasoning pass and, if generation stops because of the length cap, appends “I overthought it, the final answer should be:” before continuing toward an answer.

The reusable data object is an answer-level prompt-response pair with a Qwen token count. It contains no step labels, branch structure, reward, judge verdict, execution result, correctness bit, or separate terminal answer. The construction feedback contract is therefore `unknown`: the documented approximately 3% removal targets repetitive reasoning, not answer correctness, and is not documented as a duplicate-prompt or semantic-deduplication check.

The closest comparison is long-versus-short trajectory selection under a fixed 74M-token training budget, together with R1-Distill-Qwen-7B as the efficiency baseline. Z1 differs by combining heterogeneous teacher-trace length with a runtime continuation scaffold. STW is a budget mechanism, not a learned verifier, and the released token count is length metadata rather than evidence that a trajectory is correct or useful.
