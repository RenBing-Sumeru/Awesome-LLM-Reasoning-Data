For **Rollout, Search, and Test-Time Trace Data**, Z1 is useful as a controlled baseline for studying how training-trace length interacts with inference-time thinking budgets. Researchers can stratify the 107,173 released rows by `token_num_qwen`, reproduce longest/shortest/random subset comparisons under a fixed training-token budget, and sweep `max_tokens_for_thinking` while logging natural termination, STW cut-off, continuation length, final correctness, and wall-clock cost.

It is also a practical audit case for distinguishing a response corpus from a verified rollout corpus. A stronger derivative release should add upstream source IDs, complexity and short/long labels, truncation flags, generator settings, all pre-filter candidates, repetition-filter decisions, executable correctness outcomes where applicable, and exact code/data revisions. Those fields would make selector errors and length-budget attribution inspectable.

The appropriate reuse class is **recipe and audit reference; direct training reuse blocked pending license, provenance, overlap, and correctness review**. The available training code makes an SFT reproduction possible in principle, but downloadability and benchmark performance do not resolve rights or row quality. STW may be reused as an inference baseline with benchmark-specific budget sweeps; it should not be presented as a verifier or as a guarantee that a forced answer remains correct.
