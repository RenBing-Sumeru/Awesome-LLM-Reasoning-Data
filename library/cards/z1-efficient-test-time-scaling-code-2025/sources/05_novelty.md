Z1's contribution is not a new correctness signal or a conventional best-of-N selector. It treats response length as a joint construction and deployment variable: Code Evol-Instruct prompt complexity is paired with naturally shorter or longer QwQ-32B-Preview trajectories for SFT, then STW imposes a runtime thinking cap while preserving a route to a final answer after length termination.

The trajectory-length and sample-count ablations make this more specific than a generic “distill a long CoT” recipe. They compare longest-greedy, shortest-greedy, full-data, and random subsets under stated token budgets, so readers can separate some effects of response length from sample count. The public schema also exposes `token_num_qwen`, enabling length-stratified inspection even though it does not expose the paper's latent simple/complex grouping.

The components themselves—teacher distillation, decoder-only SFT, output truncation, and a forced-answer prompt—are established techniques. The track-level value is their explicit coupling and the documented failure when the budget is too small. Before reuse, the missing correctness gate, raw generation/filtering pipeline, rejected trajectories, and per-row construction labels must remain visible; benchmark gains do not fill those gaps.
