Z1 的贡献不是新的正确性信号，也不是常规 best-of-N 选择器。它把响应长度视为一个联合的数据构造与部署变量：Code Evol-Instruct 提示的复杂度与 QwQ-32B-Preview 自然产生的较短或较长轨迹一起进入 SFT，随后 STW 在运行时施加思考上限，并在因长度终止后保留继续生成最终答案的路径。

轨迹长度与样本数量消融使其比泛化的“蒸馏长 CoT”配方更具体。实验在已说明的 token 预算下比较 longest-greedy、shortest-greedy、完整数据和随机子集，使读者能够部分区分响应长度与样本数量的作用。公开 schema 还提供 `token_num_qwen`，可以按长度分层检查，尽管它没有公开论文中隐含的 simple/complex 分组。

Teacher 蒸馏、decoder-only SFT、输出截断和强制回答提示本身都是已有技术。对本 track 而言，价值在于把它们显式耦合，并记录预算过小时的失败。复用前，缺失的正确性门槛、原始生成与过滤流程、被拒绝轨迹和逐行构造标签都必须保持可见；基准增益不能填补这些空白。
