发布规模已直接核验：200 条任务记录、1,225 条 rubric 记录和 200 份生成的 OSWorld 配置。论文给出的难度数量——45 个 easy、46 个 medium、109 个 hard——与公开 JSON 一致。这些制品使任务表述、rubric 要求、起始 URL 和环境启动设置可检查，但不包含论文结果表所用的实际回合。

作者报告的主结果中，Opus 4.6 的 rubric 平均分为 68.9、perfect 为 44.5、平均 81.3 步；GPT-5.4 分别为 55.4、33.5 和 64.4，并取得最高轨迹效率 1.15。把上限扩展到 200 步后，Opus 的 perfect 从 44.5% 提高到 76.5%，但仍有 29/200 次运行触及步数上限。这些数值说明作者环境中的测试时扩展效果，而非确定性重放。

在 120 条 Opus 4.6 轨迹上，作者报告 rubric 评估与人工对平均 rubric 结果的一致性为 Cohen's kappa 0.788、F1 0.949，对 perfect 成功的一致性为 kappa 0.849、F1 0.934。整体 Online-Mind2Web 风格判断仅达到 kappa 0.508、F1 0.762。该比较支持检查点分解，但轨迹 ID、逐标注者标签和裁决记录没有公开。

公开评分器默认跳过缺少数值型 `result.txt` 的目录，只有使用 `--include-incomplete` 才会纳入。因此，在缺少完整运行语料时，无法独立审计论文汇总如何处理崩溃、超时、空动作、缺失截图和不完整运行。
