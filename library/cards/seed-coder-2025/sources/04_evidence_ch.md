第 2.3 节报告了 6T token 的训练安排：1T token 的代码与数学网页数据和 4T token 的精选代码均使用 LR 3e-4；随后 400B 个续训 token 的 LR 降低 sqrt(10) 倍，最后 600B token 使用 LR 3e-5。已披露的数据组成包括约 1T 个保留的 GitHub token、100B 个提交数据 token、1.2T 个代码网页 token、130B 个高质量召回 token，以及 1T 个长上下文续训 token。各集合可能相互重叠，报告没有提供可逐阶段核对的来源矩阵。

第 2.2 节报告从 140K 个代码仓库中获得 74M 次提交。质量评分器在 222,066 个由 DeepSeek-V2-Chat 这一评判模型标注的文件上训练一轮，并在同一评判模型标注的 1,178 个样本上测试；原始 0–10 分制下的总体 MAE 为 0.91，按类别平衡后的 MAE 为 1.37，零分文件仍然难以判断。这些结果衡量的是对评判模型的模仿程度。网页召回实验使用 10M 个候选样本，按 70/30 划分种子集与验证集，召回率为 99%，精确率为 45%。

第 3 节报告最终约有 3M 个 SFT 样本对，SFT 以 LR 2e-5 训练三轮，并得到约 20K 个同策略 DPO 样本对。第 3.2 节报告数千条预热轨迹，以及 GRPO 的 batch 128、LR 1e-6、temperature 0.6、无 KL、裁剪系数 0.28；先在 16K 上下文下以每个提示 16 条 rollout 训练 90 步，再在 32K 上下文下以每个提示 32 条 rollout 训练 160 步。这些条件没有披露正确性与格式奖励公式，也没有给出最终保留的总轨迹数。

发布的 Reasoning 模型上下文长度为 65,536 token；论文称超过 10% 的 IOI/Codeforces 评测样本在 64K 处被截断。官方仓库还修正过不一致的 BigCodeBench 配置，说明评测结果依赖测试框架设置。模型分数本身不能证明训练数据质量。
