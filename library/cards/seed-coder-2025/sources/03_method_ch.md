可重建的流程如下：

1. **获取与过滤代码。** GitHub 数据采用 SHA256 精确去重、MinHash 近似去重和 Tree-sitter 解析。1.3B 质量回归器在 222,066 个由 DeepSeek-V2-Chat 标注的文件上训练一轮，移除相对排名末尾约 10% 的文件；最终得到约 1T 个唯一 token，覆盖 89 种语言。
2. **构造提交、网页与续训数据。** 从满足热度和维护阈值的 140K 个代码仓库、74M 次提交中构造约 100B token。先用 fastText 从 10M 个候选样本中召回网页代码（召回率 99%、精确率 45%），再经 LLM 和类别过滤得到约 1.2T token。约 100K 个高质量种子经 2–3 轮扩张得到约 130B token。长上下文续训使用约 1T token，上下文长度由 8K 扩至 32K。
3. **6T-token 预训练。** 8.2B Base 先以 LR 3e-4 在 1T token 的代码与数学网页数据上训练，再以相同 LR 在 4T token 的精选代码上训练；随后 400B 个续训 token 的 LR 降至原来的 1/sqrt(10)，最后 600B token 使用 3e-5。
4. **SFT 与 DPO。** 合成记录按语法、正确性和难度不低于 3/10 的条件过滤；困难样本借助生成测试进行自我修正。最终保留约 3M 个 SFT 样本对，以 LR 2e-5 采用样本拼接训练三轮。每个提示采样数百个同策略候选，保留约 20K 个由沙箱执行结果构造的 DPO 样本对；DPO 的 beta、LR、训练轮数和选择细节未知。
5. **长 CoT 预热与 RL。** 对 DeepSeek-R1 和开放来源的 CoT 解答做拒绝采样，保留数千条，并以 LR 2e-5 对 Base 进行预热。基于 Verl 的 GRPO 使用 batch 128、LR 1e-6、temperature 0.6、无 KL、裁剪系数 0.28、逐 token 损失和超长样本过滤，并移除正确率高于 87.5% 的提示。先在 16K 上下文下以每个提示 16 条 rollout 训练 90 步，再在 32K 上下文下以每个提示 32 条 rollout 训练 160 步。

由于缺少提示分批、被丢弃的分组、失败样本和重采样记录，无法重建 GRPO 的总轨迹数；本卡不推断奖励公式或沙箱实现。
