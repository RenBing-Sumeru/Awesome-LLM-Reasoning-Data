The scorer inherits category, style, and language bias. Its test labels come from the same DeepSeek-V2-Chat oracle, not humans or execution. It trains on 21 languages but filters 89; per-language thresholds, retention, calibration, and low-resource errors are absent. Relative bottom-10% removal has no disclosed absolute threshold. The paper observes higher web scores for uniformly structured sites and lower scores for forums; category corrections are undisclosed.

FastText recall can amplify this bias. The initial code-web stage reports 99% recall but only 45% precision. Continued-pretraining expands model-selected positives for 2-3 rounds without per-round precision/recall, independent review, drift measurement, or stopping criterion. False positives and teacher preferences can become new positive seeds.

Generated code and generated tests form a correlated feedback loop. The same ecosystem produces solutions, tests, self-corrections, DPO labels, and later executable reward. Weak tests can certify wrong code, encourage test overfitting, and create self-confirming preferences. Sandbox, hidden tests, compilers, time/memory limits, flaky-test policy, exploit controls, correctness aggregation, format parser, reward weights, and normalization are unreleased.

The reported “any 10-gram word overlap” removal is broad but lexical. It cannot establish semantic, translated, paraphrased, solution, generated-test, commit, or repository-level separation. Benchmark versions, tokenization, removed counts, source snapshots, and crawl cutoffs are unknown. The pre-August-2024 LiveCodeBench RL slice versus 2024-10–2025-02 evaluation is only a narrow temporal boundary.
