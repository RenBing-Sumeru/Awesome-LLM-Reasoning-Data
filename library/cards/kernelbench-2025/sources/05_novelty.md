The prior baseline for code benchmarks usually rewards functional correctness, while systems benchmarks often assume human-written or autotuned kernels. KernelBench changes the object to LLM-authored GPU kernels and makes performance a first-class acceptance dimension after correctness. The direction signal is that reasoning benchmarks can include executable, hardware-mediated rewards rather than text-only grading. The quality signal is the released workload set, harness, dataset, project page, and leaderboard. What is not new: CUDA benchmarking, numerical tolerances, randomized tests, and kernel autotuning are established systems practices. Before reuse, inspect license, workload lineage, public-test contamination, hidden/eval split policy, exact environment, and whether the target hardware matches the reported speed claims.
