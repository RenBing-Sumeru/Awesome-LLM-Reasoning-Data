KernelBench asks whether LLMs can write GPU kernels that are both correct and faster than ordinary PyTorch implementations. The primary sources are arXiv:2502.10517, the official Scaling Intelligence repository, the Stanford project blog, and the Hugging Face dataset; the repository labels the work as ICML 2025. The data object is a PyTorch workload, usually a neural-network operator or model fragment, paired with a prompt asking the model to implement an optimized CUDA/C++ kernel. The feedback contract is executable: compile and load the extension, compare outputs against the PyTorch reference on randomized tests, then benchmark speed relative to the baseline. The atlas boundary is executable code evaluation for performance-sensitive reasoning, not natural-language code preference or generic programming QA.
