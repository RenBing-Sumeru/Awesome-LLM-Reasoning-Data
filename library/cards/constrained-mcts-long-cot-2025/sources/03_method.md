The pipeline represents each problem as an MDP. A state is the accumulated reasoning context, an action is one predefined instruction, the transition asks the LLM to produce the next state from the current state and action, and reward comes from the PRM or rule-only configuration. UCT selects a node; expansion evaluates candidate actions; simulation repeatedly expands until summary or the maximum depth; back-propagation updates visit counts and cumulative rewards. After k search iterations, voting over final answers selects a result, with terminal reward as a tie break.

The main experiments use Qwen2.5 instruction-tuned 7B as the generator and Qwen2.5-Math-PRM as learned process feedback, with Qwen2.5 72B CoT and RAP/Native-MCTS variants as baselines. Five math test sets are reported: MATH-500, AquA, GaoKao-Math-QA, CN-Middle-School, and Gaokao-2023, under zero-shot evaluation. A later comparison also reproduces CMCTS with Llama-3-8B-Instruct. Exact temperature, search width, iteration count k, depth limit, seeds, and full model identifiers are not all recoverable from the accepted metadata alone.

The paper explicitly points to https://github.com/pass-lin/CMCTS. The checked repository contains data, examples, reasoners, prompts, search configuration, and reports vLLM 0.7.0 on one A800, but has no tagged release and no clearly established license. For audit, retain repository commit, prompt/action version, every state and edge, UCT inputs, PRM logits, Q/V values, rule masks, code execution output, visits, back-propagation values, vote totals, parser result, and benchmark label.
