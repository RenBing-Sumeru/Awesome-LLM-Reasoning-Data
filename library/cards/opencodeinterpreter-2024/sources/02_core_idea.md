Code-Feedback turns several forms of coding interaction into one reusable target: similar-query packing teaches cross-turn context, execution simulation preserves diagnostics and revisions, explicit code-correction records expose debugging, and LeetCode branches serialize related problems or follow-up constraints. The executable substrate creates feedback during construction, but training consumes ordered role/content messages; this makes the work instruction/demonstration/rationale data rather than an environment-only release or evaluation benchmark.

Google Scholar citations: 317（checked 2026-07-27；https://scholar.google.com/scholar_lookup?title=OpenCodeInterpreter%3A+Integrating+Code+Generation+with+Execution+and+Refinement&author=Tianyu+Zheng&hl=en）

Open dataset: yes. Dataset name: Code-Feedback; filtered seed dataset: CodeFeedback-Filtered-Instruction. Official URLs: https://huggingface.co/datasets/m-a-p/Code-Feedback and https://huggingface.co/datasets/m-a-p/CodeFeedback-Filtered-Instruction. Scale: 68K conversations and 192K turns; the central `Code-Feedback.jsonl` file is 413,476,947 bytes, while the five paper branches contribute about 16K, 51K, 0.5K, 0.3K, and 0.2K records. Record form: an `id` and ordered `messages`, each with `role` and `content`, containing requests, explanations/code, execution output or diagnostics, feedback, and revisions. File/storage format: public JSONL for the conversation corpus, with the filtered instructions released separately on Hugging Face. Domains/languages: primarily English code generation, debugging, efficiency, security, compatibility, resource use, scalability, and best-practice requests. Construction and filtering: Qwen-72B-Chat reduces 287K open queries to 156K difficult seeds; GPT-3.5 writes initial code, execution returns diagnostics, and GPT-4 refines responses or simulates ten feedback categories, with up to three cycles. License/access constraints: public, ungated Apache-2.0; upstream source terms and records generated with GPT-4-0613/GPT-3.5-turbo-0613 require separate provider-policy review. Intended use: code SFT, distillation, execution-feedback refinement, multi-turn code assistance, and feedback-data auditing.
