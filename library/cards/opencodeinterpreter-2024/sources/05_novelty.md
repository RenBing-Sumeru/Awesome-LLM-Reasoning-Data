Earlier code SFT datasets emphasized independent instruction-response pairs, while self-debugging and compiler-feedback systems often left execution state inside an online scaffold. OpenCodeInterpreter changes the auditable object by publishing static multi-turn records that keep explanations, code, diagnostics, simulated user feedback, and revisions together, with five construction branches covering both interaction and related-query context. Findings ACL acceptance, open Apache-2.0 artifacts, strong repository/data adoption, staged feedback results, and line-overlap checks are quality signals, although code execution, synthetic feedback, query packing, and SFT are not individually new. The direction signal is packaging execution-and-feedback behavior as reusable conversation supervision at 68K scale; reuse must test semantic correctness, synthetic feedback artifacts, provider/source terms, benchmark overlap, and safe code replay.
