Open code models in early 2024 could generate programs in one turn but were much weaker than proprietary code-interpreter systems at using execution diagnostics or changing user intent. Runtime feedback was usually transient system state, and existing instruction corpora rarely preserved a complete request, code response, execution result, feedback, and revision as reusable supervision.

OpenCodeInterpreter constructs Code-Feedback, a public corpus of 68K static multi-turn conversations and 192K turns. It uses execution during synthesis, simulates ten categories of user feedback, and serializes the resulting explanations, code, diagnostics, and revisions for SFT; the released data object is a conversation record, not a live execution environment.

**L4 facts:** Primary source and date: Findings of ACL 2024, pages 12834-12859, published August 2024, DOI 10.18653/v1/2024.findings-acl.762; decision boundary and evaluation surface: execution output guides up to three refinements, GPT-4 decides apparent completion, and trained models are evaluated with HumanEval/MBPP EvalPlus tests plus MT-Bench code turns; collection verification: open Apache-2.0 JSONL, id/messages schema, scale, construction branches, SFT consumers, adoption, leakage check, provider-policy boundary, and code-replay risks checked.
