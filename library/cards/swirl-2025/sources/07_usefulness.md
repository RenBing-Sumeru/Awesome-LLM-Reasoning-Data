For `environment_agent_trajectory_data`, SWiRL is a concrete construction reference for serializing tool behavior: preserve the source question, full state prefix, model reasoning/action, structured tool call, tool response, final answer, terminal reason, filter decisions, and the link from each action-ending subtrajectory back to its full episode. A reproduction should retain successful, incorrect-outcome, malformed, and rejected trajectories rather than only the final accepted pool.

For `training_usage_optimization_objectives`, the useful baseline separates three consumers of the same source episode: SFT on synthetic trajectories as the Appendix C comparison; stage-1 process/outcome selection; and offline step-wise RL on reward-bearing action prefixes as the principal method. An ablation should hold generator, trajectory pool, environment responses, judge versions, and budget fixed while changing the filter or objective, because the paper shows that process-only is preferred for SWiRL whereas process-plus-outcome is preferred for SFT.

The paper can guide process-supervision and agent-training experiments in search or calculator environments. It also supplies an evaluation/audit checklist: distinguish environmental observations from learned judgments; calibrate process, outcome, reward, and evaluation judges separately; measure incorrect-outcome retention; test alternative judges; and report weighting induced by prefix decomposition. Table 1–3, Figure 4, and Appendices B–F are the relevant experimental references, not evidence that a reusable corpus exists.

Reuse class: **reading/audit and construction-recipe reference only; direct training reuse is blocked pending verification**. To unblock it, an official package would need immutable source/split manifests, trajectories and failed generations, tool-response snapshots, per-step process labels and rewards, exact model/prompt versions, reward mapping, optimizer configuration, checkpoints, record-level lineage, contamination analysis, and compatible licenses. The work is not safe to reuse as a benchmark because SWiRL does not release one.
