核心机制是在不替代可验证终局条件的前提下，用 guidance 扩展探索。Agent 先在没有 guidance 的情况下尝试任务，并在环境测试中执行生成的 patch；若测试失败或没有生成 patch，外部 teacher 会提供三类信息：解题计划、基于失败轨迹与 stack trace 的环境反馈，以及指向相关代码位置的环境交互提示。Agent 只在训练阶段带着提示再次尝试，同一任务的正确与错误轨迹随后组成 offline DPO 的 preference pair。正确的无 guidance 轨迹还用于 SFT，而 problem statement 与 patch 的配对数据被复用于训练 pairwise reward model，在测试时对 32 个 patch 排序。因此，反馈契约同时包含二值环境奖励、完整 episode 轨迹和派生的成对偏好；guidance 负责辅助搜索，并不承担正确性判定。
