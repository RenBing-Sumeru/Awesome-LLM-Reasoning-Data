相较许多 system card 摘要，这份 addendum 暴露了较具体的安全构造对象：与代码和环境配置配套的恶意软件提示、用于缺失资源场景的扰动/合成环境，以及编码专用 prompt-injection 数据。它还给出一个 RL 信号的方向——惩罚与动作不一致的声明，奖励明确承认限制——而不只是笼统地说做了安全微调。

不过，对本轨道更重要的仍是披露边界。主要现实编码任务 RL 语料与奖励比安全层更不具体，而评测集又比两类训练池披露得更清楚。因此，该 addendum 可以建立“训练披露—安全/部署缓解—评测结果”三分账本，同时避免把高拒绝率、sandbox 或 Preparedness 分类当作数据质量与可复现性证明。
