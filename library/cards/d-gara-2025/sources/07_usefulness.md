Use D-GARA as a recipe for robustness-aware GUI-agent evaluation. Preserve task instruction, app and OS version, initial state, anomaly type, anomaly timing, screen observations, action trace, success predicate, timeout/action budget, and clean-vs-anomalous comparison result. For atlas work, it is useful when designing trajectory datasets that should include recovery behavior rather than only smooth task completion. It also supplies an audit checklist for whether a GUI benchmark measures real environment resilience or merely memorized clean workflows.
