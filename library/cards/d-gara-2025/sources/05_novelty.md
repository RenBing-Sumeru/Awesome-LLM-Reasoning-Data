The prior baseline is GUI-agent evaluation in static or idealized environments where screens behave as expected. D-GARA changes the evaluation condition by making anomalies first-class variables. It also frames robustness as performance degradation under interruptions rather than only task success in clean settings. The direction signal is important for post-training data and evaluation because robust GUI agents need trajectories that include unexpected dialogs, warnings, and app-state shifts. The quality signal is the modular framework for adding tasks, anomaly types, and interaction scenarios. What is not new: GUI control, Android app tasks, and task-success predicates already existed. Reuse requires auditing app terms, anomaly realism, predicate fidelity, device drift, and whether manual checks are used.
