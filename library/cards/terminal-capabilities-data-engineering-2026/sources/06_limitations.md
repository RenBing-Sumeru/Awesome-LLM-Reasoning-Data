Release completeness is the first limitation. The public 366,154 rows equal the adapter and skill-based portions of Table 5, but the 124,366 seed-based trajectories needed to reach the paper total of 490,520 are not confirmed released. None of these row counts is a verified count of unique tasks: the schema separately exposes task, episode, and run identifiers, and task-to-episode multiplicity is unknown. All four public configurations are train-only; scaling-fraction row IDs, curriculum-stage membership, and a conventional validation split are absent.

Outcome semantics are incomplete. The corpus stores actions and observations inside conversation text but has no normalized verifier outcome, reward, test result, failure class, or termination cause. Self-declared `task_complete` must not be substituted for verifier success. Adapter tasks have no tests. For synthetic tasks, representative pytest infrastructure establishes that binary end-state checking exists, but it does not show that every test suite is semantically complete, resistant to shortcut solutions, or free of false positives and false negatives. The paper's no-filter result is label-level evidence for its experiment, not a release-level failure ledger.

Exact replay is not established. The task archive provides instructions, inputs, `task.toml`, Dockerfiles, and tests, but representative files reference a mutable internal `:latest` image, a mutable GHCR `:latest` base, and unpinned apt/pip installs. Image digests, dependency locks, Harbor/Terminus/Singularity revisions, teacher serving snapshot, seeds, network policy, reset/cache/volume/cleanup rules, and original verifier logs are missing. An internal NVIDIA registry reference may be inaccessible to external reusers. A checked `task.toml` exposes 900-second agent and verifier timeouts, a 600-second build timeout, 1 CPU, and 2G memory, but that is representative evidence rather than a corpus-wide budget distribution.

The 14-gram Terminal-Bench 2.0 screen is narrower than a general contamination audit. Its normalization, implementation, removal count, and overlap checks against other terminal, math, code, and SWE benchmarks are unknown. Because tests and tasks are public, post-release benchmark contamination also needs separate handling. Coarse adapter `source` labels and repository-level task/corpus labels do not supply immutable upstream record IDs, prompt transformations, verifier decisions, rejected-item ledgers, or complete lineage.

Both official dataset repositories are labeled CC BY 4.0, but that label does not reconcile record-level rights and attribution for upstream prompts, issues or patches, generated traces, model terms, Docker images, packages, and task assets. Privacy, consent, deletion, and withdrawal procedures are unknown. Security tasks can include exploit payloads, vulnerability analysis, authentication, and network operations; Docker isolation is described, but egress, credentials, malicious-output handling, and corpus-wide safety review are not.

Finally, teacher decoding settings, retry counts, generation compute, and Terminal-Task-Gen or training code are not confirmed released. A nontrivial long tail is truncated at the SFT context boundary without per-row truncation metadata. Domain names also drift between the main text, appendix, and public directories. These gaps justify `partial` status and medium confidence despite verified paper and artifact links.
