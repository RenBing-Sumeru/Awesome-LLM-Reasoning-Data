For dataset adaptation, the pipeline draws filtered prompts from Nemotron-Cascade math, code, and SWE mixtures derived from OpenMathReasoning, OpenCodeReasoning, SWE-Bench-Train, SWE-reBench, SWE-Smith, and SWE-Fixer-Train. It inserts the original prompt and a domain-specific suffix into the Terminus 2 template; SWE code files are instantiated in the environment. These adapter tasks have an instruction and environment but no associated tests, so their correctness contract is not uniformly programmatic.

Synthetic generation has seed-based and skill-based branches. The skill branch typically combines three to five items from a domain taxonomy spanning data processing, data querying, data science, debugging, dependency management, file operations, scientific computing, security, software engineering, and related categories present in the release. A synthetic task specification includes a natural-language instruction, optional input files, `task.toml`, an `environment/Dockerfile`, and pytest-based tests; checked archives contain empty `solution/` directories rather than generated oracle solutions. Nine shared domain images are described, but they are not bound to immutable digests.

DeepSeek-V3.2 operates through Terminus 2 in Docker/tmux. At each turn, the scaffold supplies the current terminal state and requests structured JSON actions; literal keystrokes are executed and the resulting terminal output becomes the next observation. Harbor coordinates generation, with an author extension for Singularity/HPC, while Daytona is used for evaluation. Teacher temperature, seeds, turn/token/time limits, retries, attempts per task, serving snapshot, and generation compute remain unknown.

For checked synthetic infrastructure, pytest evaluates the end state and a representative `tests/test.sh` writes binary `1` or `0` to `/logs/verifier/reward.txt` from the pytest exit status. Task specifications can assign partial-credit weights to individual tests, but the public conversation corpus has no normalized outcome, scalar reward, test result, termination cause, or verifier-log column. The assistant's embedded `task_complete` is self-declared and is not the terminal predicate. Adapter tasks have no tests.

Post-processing removes prompts with a 14-gram overlap against Terminal-Bench 2.0 test prompts, identity leaks, and responses containing Chinese characters. The selected recipe otherwise keeps decontaminated trajectories regardless of teacher-declared completion or test success. Student SFT uses veRL and AdamW for two epochs with learning rate `2e-5`, weight decay `1e-4`, global batch size 128, micro-batch size 1 per GPU, cosine scheduling, 10% warmup, gradient clipping 1.0, and CPU offload. The default maximum SFT length is 32,768 tokens; longer-context and curriculum variants are ablations rather than separate released row manifests.
