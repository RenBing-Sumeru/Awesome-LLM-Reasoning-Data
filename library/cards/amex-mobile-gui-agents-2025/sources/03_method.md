1. Inputs: Android screenshots and XML-like layout signals from emulator collection, target apps, app descriptions when available, and human-written or generated task instructions. 2. Pipeline: collect raw GUI operations from human annotators and an autonomous tool; parse candidate interactive boxes; manually filter visible clickable and scrollable elements; use GPT-4o with marked screenshots and app context to draft screen and element functionality descriptions; manually check descriptions; record or construct stepwise instruction-action chains. 3. Outputs: screenshot records, element boxes and functions, screen descriptions, instructions, action chains, sample data on Hugging Face, a codebase for conversion, finetuning, and inference, and a baseline SPHINX Agent recipe. 4. Feedback: human annotation checks validate annotation quality, while benchmark evaluation tools score grounding or action behavior. Reuse requires pinning the ACL/arXiv version, HF revision, code commit, split files, evaluator scripts, emulator/device assumptions, and whether L1/L2/L3 annotation levels are being used.
