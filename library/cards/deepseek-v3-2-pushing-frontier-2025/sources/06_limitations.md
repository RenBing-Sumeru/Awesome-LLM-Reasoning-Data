Training-data disclosure is incomplete at every major stage. Continued pretraining gives token totals and says its distribution matches V3.1-Terminus, but omits corpus composition, dates, licenses, quality filters, and decontamination. Specialist distillation names domains and response modes but not specialists, prompt counts, generated counts, acceptance rates, direct-versus-reasoning mixture, or final SFT membership. Mixed RL gives reward families and thousands of steps but no prompt mixture, rollout group size, sampled outputs, reward values, rejected sequences, or checkpoint schedule.

Agent environments are described but not released. Search depends on commercial or real web APIs and a search-enabled verifier whose queries, sources, passes, and calibration are absent. Code repair depends on mined GitHub issues, patches, test patches, automated dependency setup, and JUnit parsing; source URLs, commits, containers, logs, failure rates, and licenses are unavailable. General environments include generated databases, function tools, solutions, and verification functions, yet none of those 1,827 packages can be inspected for shortcuts or correlated generator errors.

Several filters establish narrow predicates rather than overall quality. Gold-patch F2P/P2F checks validate a code environment, not the issue description or the model's unseen repair. Non-zero pass@100 removes tasks never solved by the training model, but can favor exploitable verifiers and does not show unique solutions. A search verifier and generative rubrics can inherit factual, calibration, and preference errors. No false-accept audit or retained/rejected ledger is reported.

Evaluation reproducibility is also limited. Some benchmarks use internal environments; search results depend on context management; conversation-role conventions change whether reasoning persists; and long repeated verification can exceed 128K. Speciale spends substantially more output tokens and lacks tool calling, so its olympiad results should not be attributed to the deployable V3.2 tool model. Released competition submissions enable narrow secondary checks, not audit of training data.

Finally, MIT applies to official weights and inference repositories, not automatically to web-derived prompts, GitHub issues or patches, helpful-RL data, synthetic databases, generated episodes, or evaluator inputs. The report states that test tools were unseen during agent RL, but no match ledger or broader contamination analysis is available. Benchmark performance cannot resolve these provenance, rights, or verifier gaps.
