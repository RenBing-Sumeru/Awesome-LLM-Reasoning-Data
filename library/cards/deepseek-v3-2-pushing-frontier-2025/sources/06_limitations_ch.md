所有主要训练阶段的数据披露都不完整。继续预训练给出 token 总量，并称数据分布与 V3.1-Terminus 相同，却没有说明语料构成、时间、许可、质量筛选和去污染。专家蒸馏只列出领域与响应模式，没有给出专家身份、提示数量、生成数量、接受率、直接回答与推理比例或最终 SFT 归属。混合 RL 给出奖励类型和数千步训练，却没有提示混合、rollout 组大小、采样输出、奖励值、被拒序列或检查点调度。

智能体环境只被描述，没有发布。搜索依赖商业或真实网页 API，以及未公开查询、来源、验证轮数和校准情况的搜索判定智能体。代码修复依赖挖掘的 GitHub 问题、补丁、测试补丁、自动依赖搭建与 JUnit 解析，但源 URL、提交、容器、日志、失败率和许可不可获得。通用环境包含生成的数据库、函数工具、解答与验证函数，但 1,827 个环境包均无法检查是否存在捷径或相关生成错误。

多种筛选只建立狭窄判据，不能代表整体质量。金补丁的 F2P/P2F 检查验证的是代码环境，不是问题描述或模型尚未产生的修复。pass@100 非零会删除训练模型从未解决的任务，却可能偏向可利用判定器的样本，也不能证明解答唯一。搜索判定器和生成式评分细则会继承事实、校准与偏好误差；报告没有误接受审计或保留/拒绝账本。

评测复现也受限制。部分基准使用内部环境；搜索结果依赖上下文管理；会话角色约定会改变推理是否保留；重复验证会让轨迹超过 128K。Speciale 使用明显更多输出 token 且不支持工具调用，因此其奥赛结果不能归因于可部署的 V3.2 工具模型。已发布竞赛提交只支持有限的二次核验，不能审计训练数据。

最后，MIT 适用于官方权重与推理仓库，并不会自动覆盖网页提示、GitHub 问题或补丁、helpful-RL 数据、合成数据库、生成轨迹或评测输入。报告称智能体 RL 未见过测试工具，但没有匹配清单或更广泛污染分析。基准成绩无法填补来源、权利或判定器证据缺口。
