For `frontier_reports_data_disclosure_ledger`, this Card is useful precisely because the disclosure is asymmetric. It offers more task-construction detail than many frontier reports while releasing less training data than Llama-Nemotron. Auditors can compare the exact 85,267-prompt table, verifier descriptions, and Scaling GRPO equations against the absence of row files, environment packages, reward artifacts, and training configurations.

The report supplies patterns worth reproducing independently: report prompt counts by source and environment type; define a code-environment success predicate with target recoveries and regression protection; restrict synthetic solution functions from bypassing tools; co-evolve task difficulty with tool coverage; retain conversation-role semantics when reasoning spans tool calls; and preserve sampled routing and truncation masks during off-policy MoE updates. These are design lessons, not reusable data assets.

A credible reproduction manifest would need immutable source records, prompt and episode schemas, specialist checkpoints, generator versions, all candidates, acceptance reasons, environment containers, API versions, verification functions, reward-model checkpoints and rubrics, per-component rewards, policy probabilities, routing and sampling masks, optimizer values, and stage-to-checkpoint membership. It should separately account for SFT, reasoning RL, agent RL, and alignment RL.

Open weights are useful for inference research, behavior audits, quantization, deployment, and secondary checks of released olympiad submissions. They do not support reconstruction of the training corpus. Benchmark users should pin the weight revision and evaluation harness, report whether context management is used, and avoid treating score or task difficulty as evidence of data quality. Until the missing artifacts appear, this entry belongs in the frontier disclosure track rather than the open-release recipe track.
