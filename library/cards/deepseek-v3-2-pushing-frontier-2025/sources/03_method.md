The base lineage begins at DeepSeek-V3.1-Terminus with 128K context. A dense warm-up trains only the DSA indexer for 1,000 steps, 16 sequences of 128K tokens per step, totaling 2.1B tokens. Sparse continued pretraining then selects 2,048 key-value tokens per query and trains the full model plus indexer on 943.7B tokens. The report says both stages use the same data distribution as the V3.1-Terminus 128K extension, but does not identify that corpus, its sources, licenses, or decontamination.

Agent RL contains 85,267 prompts in Table 1: 24,667 code-agent tasks with real environments and extracted prompts; 50,275 search-agent tasks with real search tools and synthetic prompts; 4,417 general-agent tasks with synthetic environments and prompts; and 5,908 code-interpreter tasks with real Jupyter environments and extracted prompts. These are task counts, not trajectory counts. The number of attempts, retained episodes, reward records, and unique real environments is unknown.

Search synthesis samples long-tail web entities, constructs questions through search, generates heterogeneous candidate answers, and uses a search-enabled verification agent over multiple passes. It retains examples where the reference answer is validated and candidates are incorrect, then adds filtered helpful-RL prompts scored by a rubric-based generative reward model. Code-agent construction mines millions of GitHub issue–pull-request pairs, requires an issue description, correlated gold patch, and test patch, and uses an automated setup agent. A build passes only when the gold patch changes at least one target test from failure to pass and causes no previously passing test to fail, with JUnit output used across languages.

General-agent synthesis builds a sandbox database, task-specific function tools, a task, a solution function, and a Python verification function. The solution may use only tools or logic, not direct database access; the generator iteratively raises task difficulty and expands the toolset. After RL trials, only tasks with non-zero pass@100 remain, yielding 1,827 environments and 4,417 tasks. Code-interpreter tasks cover mathematics, logic, and data science through Jupyter, but their sources, filters, and counts before retention are not detailed.

Scaling GRPO changes the optimizer contract: an importance-weighted estimator corrects KL bias; highly divergent negative sequences are masked; MoE routing selected during sampling is reused during training; and the top-p or top-k sampling mask is preserved so sampling and update action spaces match. The equations are public, but the deployed group size, reward weights, thresholds, optimizer values, batch sizes, and rollout ledger are not.
