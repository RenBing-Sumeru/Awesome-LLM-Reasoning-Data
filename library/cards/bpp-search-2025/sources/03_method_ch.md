StructuredOR 从抽象运筹优化模型出发。论文报告其中 77 个样例来自既有框架，另有 47 个样例通过改变参数分布生成。GPT-4o 生成集合与参数分布、问题描述和三个语义等价改写；仿真过程实例化具体数值；解析器与建模工具构造具体线性规划；Gurobi 检查可解性与正确性；字符串插入形成带数值的问题。改写结果再经过人工审核、GPT 打分和规则评估。论文没有披露精确提示、GPT-4o 版本、温度、解析器与求解器版本、判定阈值或各阶段拒绝数量。

搜索阶段把原始的 Q -> S -> P -> V -> O -> C 建模路径合并为 Q -> SP -> V -> OC。所述搜索基底中每个节点至多有三个子节点，主实验固定使用 GPT-4o 作为策略模型。一个二分类 Qwen2.5-Math-1.5B PRM 把“correct”logit 的 sigmoid 当作连续节点分数，beam search 据此保留得分最高的中间候选。完整候选再由第二个二分类器按两个顺序成对比较；系统对每个候选的比较分数取平均，并返回最高分候选。

论文描述了选择器训练配方，但没有发布相应记录。PRM 数据来自 GPT、Llama 和 Qwen 系列模型在 StructuredOR、NL4OPT 与 MAMO-ComplexLP 训练题上生成的 CoT 或 ToT 输出。路径按目标值一致性标注：正确路径被累积切分为中间监督；定位到错误步骤后，后续步骤都继承错误标签；人工扰动补充正负样例。成对数据由目标值一致与不一致的最终路径组成，同一对按两个顺序排列，并以正确路径所在位置作为标签。语料规模、划分、优化器设置、随机种子、检查点与校准过程均未披露。

搜索宽度是明确的实验变量。高度为 4、分支因子为 3 的完整树需要 39 次策略模型调用，分支因子为 4 时需要 84 次。论文报告的 width-2 和 width-3 BPP-Search 配置分别使用 15 和 21 个推理步骤。这些是整体实验配置，不是逐样例日志；单例调用数、token、延迟、成本、重试与停止决策仍为 unknown。
