对于指定的“Rollout / Search / Test-Time Trace Data”方向，BPP-Search 给出了一套具体的搜索反馈分解：解析器与 Gurobi 检查用于构造可解实例；目标值一致性用于标注路径；学习式 PRM 排序中间节点；学习式成对模型选择最终候选。论文报告的宽度和完整树调用次数还把推理预算显式化为设计变量。

在数据集 license 为 unknown 且谱系未解决的前提下，公开 StructuredOR 可作为最终结构化数学建模样例进行研究。论文描述的 PRM 与成对配方与过程监督、奖励建模、偏好学习、评测和测试时搜索有关，但相应选择器语料和检查点并未提供。因此，不能把这份发布登记或使用成包含负 rollout、原始树监督或可重放验证器轨迹的数据集。

作为审计案例，本卡片列出可复用搜索数据至少需要补充的字段：稳定记录 ID 与家族 ID；全部节点和边；入选、剪枝和被拒分支；检查器与求解器输出；PRM 与成对分数；终止原因；提示与模型修订版；以及逐样例的策略调用、验证调用、token、延迟和停止预算。这些缺失项是本方向的核心数据要求，而非可有可无的实现细节。
