The 2025 arXiv paper addresses a specific bottleneck in repository-level software-engineering data: a real GitHub issue is easy to find, but rebuilding its exact dependency, build, and test environment is expensive and often unreliable. Existing routes either attach a new Gym to each historical issue or synthesize many artificial defects inside a few working environments. SWE-Mirror instead asks whether the semantic content of an authentic issue can be moved into a different, functionally similar repository whose Gym already works.

The construction unit is not merely an issue description. A mirrored task binds a target repository and `base_commit` to a generated `problem_statement`, a bug- or feature-reversion patch (`mirror.patch`), a hidden validation patch (`test.patch`), the inverse reference repair (`fix.patch`), and full-suite execution logs. A downstream trajectory is a separate object: an OpenHands or MOpenHands sequence of actions and observations ending in a submitted patch and a test-derived outcome. This distinction matters because the paper reports 60,671 tasks but trains on a 12,456-trajectory success-only mixture.

This belongs in the Environment & Agent Trajectory Data track because the reusable Gym, executable state transitions, hidden tests, agent tool interface, and terminal predicate jointly define the supervision signal. It does not solve automatic Gym construction, establish that every mirrored issue is semantically faithful, or provide a verified public release sufficient for replay. The L4 content depth here is therefore supported by the full paper and appendix, while reuse remains blocked by missing official artifact URLs and manifests.
