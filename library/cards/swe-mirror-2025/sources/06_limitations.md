Programmatic validity is narrower than semantic correctness. The three-state test contract can reject non-applicable patches, missing fail-to-pass behavior, regressions, and some flaky outcomes, but weak generated tests can still admit underspecified or trivial tasks. The human audit exposes this boundary: 21 of 177 majority-labeled tasks are inconsistent with the source issue and 7 more lack a majority classification. Because `fix.patch` is the inverse of `mirror.patch`, the reference solution may encode the generator's chosen edit rather than the full space of valid repairs.

The selection pipeline can produce both false positives and false negatives. Its 84.3% precision and 86.0% recall are measured on a balanced 100-issue sample, not the natural candidate distribution. Mirroring yield falls to 28.0% for Rust and 36.0% for Go, and compile/syntax failures are much more common there than in Python. These differences can bias the final language mixture toward problems and repositories that are easy for the agents and harness to manipulate.

Trajectory reporting is success-only. The 6,431 SWE-Mirror episodes and 6,025 SWE-rebench episodes are retained after terminal success; counts and artifacts for wholly failed, timed-out, flaky, or infrastructure-error rollouts are not disclosed. Error Masking retains an erroneous turn only inside an ultimately successful episode and masks that response's loss. It should not be described as failure-data training or as evidence that unsuccessful episodes were preserved.

No verified task/trajectory split, immutable instance manifest, or overlap audit is available. The paper evaluates on SWE-bench Verified and Multi-SWE-Bench-Flash but does not document task-level checks against those benchmarks, the source repositories and issues, reference patches, or teacher pretraining. This creates contamination and evaluation-to-training leakage risk. It also prevents checking whether repeated source issue patterns appear in multiple target repositories.

Exact replay remains blocked. The paper does not provide a verified public artifact containing target repository commits, container image digests, dependency locks, test parser and harness revisions, per-instance logs, prompts, seeds, teacher endpoint versions, or task-to-trajectory mappings. The arXiv manuscript is CC BY 4.0, but that license does not establish redistribution rights for source repository code, issue and PR prose, patches, tests, dependencies, generated tasks, or proprietary-teacher trajectories. Curator inference: no personal user data is central to the method, yet GitHub issue/PR text can contain names, emails, secrets, or security-sensitive details, so privacy and secret scanning are still necessary before release.
