SWE-Mirror breaks the usual one-task-to-one-Gym coupling. It takes an issue and merged pull request from a source repository, abstracts the functionality, current and expected behavior, symptom, and root-cause pattern, then re-instantiates that abstraction in a similar target repository with an existing executable Gym. The target task retains real-world issue semantics while amortizing the environment across many tasks.

The feedback contract is constructed before the fault. A Test Agent writes `test.patch` so the new tests pass on the current target code. A separate Mirror Agent then edits non-test source code until those tests fail, producing `mirror.patch`; reversing it yields `fix.patch`. The verifier checks full-suite test transitions under three states. It can observe patch applicability and test pass/fail/skip transitions, but it cannot directly determine whether the natural-language issue is realistic, whether the repair is unique, or whether passing tests captures the full intended semantics.

Compared with SWE-Smith, which synthesizes defects inside prepared repositories, SWE-Mirror anchors the abstract problem in an authentic issue from another repository. Compared with SWE-rebench, which scales collection by configuring environments for fresh issues, SWE-Mirror reuses a small Gym pool. Its distinctive contribution is cross-repository semantic transfer plus an executable re-animation contract; the main risk is that the transferred task may pass the contract while no longer matching the source problem.
