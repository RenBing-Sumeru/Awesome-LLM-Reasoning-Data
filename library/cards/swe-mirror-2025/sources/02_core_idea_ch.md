SWE-Mirror 打破常见的“一个任务对应一个 Gym”耦合。它从源仓库取得 issue 与已合并 pull request，抽象其中的功能、当前与预期行为、症状和根因模式，再把该抽象重建到一个功能相近且已有可执行 Gym 的目标仓库。这样，目标任务保留真实 issue 的语义来源，同时让多个任务分摊环境成本。

反馈契约先于故障构造。Test Agent 编写 `test.patch`，使新增测试在目标仓库当前代码上通过；另一个 Mirror Agent 随后只修改非测试源码，直到这些测试失败，形成 `mirror.patch`，其反向补丁成为 `fix.patch`。verifier 在三种状态下检查完整测试套件的状态转换。它能够观察补丁是否可应用以及测试的通过、失败、跳过转换，却不能直接判断自然语言 issue 是否真实、修复是否唯一，或通过测试是否覆盖完整预期语义。

相较于在已准备仓库内合成缺陷的 SWE-Smith，SWE-Mirror 把抽象问题锚定到另一仓库中的真实 issue；相较于通过为新鲜 issue 配置环境来扩大收集规模的 SWE-rebench，它复用一小组 Gym。其关键变化是“跨仓库语义迁移 + 可执行再实例化契约”，主要风险则是迁移任务可能通过契约却不再忠实于源问题。
