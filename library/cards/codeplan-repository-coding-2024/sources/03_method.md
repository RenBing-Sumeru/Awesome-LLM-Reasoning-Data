1. Inputs: a repository before edit, a change request or target location, and static analysis over files, classes, methods, fields, imports, and call relations. 2. Planning: CodePlan uses dependency relations to choose impacted code regions and asks the LLM for edits. 3. Update: generated code is merged, atomic changes are classified, and the dependency graph is updated for subsequent steps. 4. Outputs: edited repository state and diff/block metrics against the target. 5. Reproducibility: use the GitHub replication package, Python >=3.11, required metric packages, fixed repo id, approach name, and saved metric JSON.
