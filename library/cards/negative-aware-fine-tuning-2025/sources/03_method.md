Experiments start from Qwen2.5-Math-7B and Qwen2.5-32B and use DAPO-Math-17k, whose prompts carry integer ground-truth answers and an Apache-2.0 dataset license. Each rollout step samples 512 questions and generates 16 answers per question at temperature 1.0. A programmatic answer verifier assigns r in {0,1}; the implementation stores token-level old-policy likelihoods and the group success rate. Only groups with both positive and negative answers enter the NFT update. Data is divided into 16 mini-batches for 16 gradient steps; 320 rollout steps yield slightly over 5,000 gradient steps.

The shared learning rate is 1e-6 with linear warm-up. NFT inherits VeRL/DAPO dynamic sampling, token-level loss normalization, and no KL regularization. Seven-billion-parameter training uses a 4K context on 64 H100 GPUs; NFT-32B uses a 16K context and 128-256 H100 GPUs. Truncated answers are labeled negative, the negative-ratio clip is 1.0, and harder-question weighting follows the paper's GRPO-aligned option. Evaluation covers AIME24, AIME25, AMC23, MATH500, OlympiadBench, and Minerva Math, using math-verify for training validation and simpleRL for final evaluation.

The official repository supplies training scripts, verifier code, evaluation tooling, and download scripts; NVIDIA publishes NFT-7B and NFT-32B weights under a non-commercial model license. A reusable trace release would additionally need exact dataset/model commits, all generated answers, extracted answers, verifier outcomes, truncation flags, likelihood arrays, dynamic-resampling history, and seeds. Those run-level artifacts were not confirmed as complete.
