For the **Data Construction & Open Release Recipes** track, this paper is most useful as a recipe-comparison framework and release-audit case. The public corpus itself is **blocked for direct training reuse pending license, provenance, and security remediation**.

- **Rebuild a curation ablation matrix.** Hold the base model, optimizer, example count, and evaluation budget fixed while varying one of source choice, source diversity, prompt filter, deduplication, rollout multiplicity, answer filter, or teacher. Report both retained-example counts and compute so a larger unfiltered set is not mistaken for a filter effect.
- **Design verifier-by-scale experiments.** Repeat the paper's verified-versus-unverified comparison across teacher sizes and verifier types. Preserve every candidate, verifier input/output, threshold, failure code, and final decision so false accepts and false rejects can be audited.
- **Use repeated teacher sampling as a controlled variable.** Compare sixteen responses per unique prompt with more unique prompts at equal token and inference budgets. Track prompt identity and candidate groups explicitly; the current release cannot support this analysis because those group IDs are absent.
- **Build a stronger release ledger.** Extend each row with immutable upstream ID/revision/URL, transformation history, license and required attribution, exact teacher checkpoint, chat template, decoding settings, candidate group, dedup group, decontamination match, verifier outputs, and rejection reason.
- **Audit decontamination.** Pin every benchmark version; rerun exact, normalized-edit, n-gram, and semantic-neighbor checks; publish matches, removals, and sampled false-positive/false-negative reviews. Do not treat the reported lexical detector as proof of a clean evaluation split.
- **Use the negative results as baselines.** The Table 7, Table 15, and Table 18 settings are useful reference points for testing whether a new judge or executable verifier adds value. The correct claim is conditional performance under those settings, not a universal rejection of verification.
- **Reproduce only after security repair.** Fork from a pinned commit after removing and rotating the exposed credential, move secrets to environment injection, record a secret-scan result, and pin container/dependency hashes.
- **Separate recipe study from corpus reuse.** The paper, appendix, code structure, and ablation tables are suitable now for reading, audit, and controlled reimplementation. The released 1.2M rows should not be redistributed or used for production training until upstream rights and row-level provenance are reconciled.

The object is not suitable for PRM, preference learning, RLVR replay, or agent training without new labels or interactions: it has no step outcomes, preference pairs, reward, environment state, or action trajectory. It should not be reused as an evaluation set because it is a training corpus and would require an independent overlap audit.
