The many-shot source is the MATH training set. The few-shot mixture contributes four examples from each of 27 BBH categories (108 total), four Game of 24 examples, and four TheoremQA examples; the few-shot examples are upsampled eightfold during tuning. Evaluation uses MATH test, BBH/Game of 24/TheoremQA test or hold-out data, plus OOD DeepMind Math, MMLU-Pro, StrategyQA, and DROP. No decontamination or semantic-overlap procedure is disclosed.

Search is performed separately for GPT-4o-mini, Llama-3-70B-Instruct, and Llama-3-8B-Instruct as task-solving models. Under the paper configuration, \(K=2\) search rounds, \(N_{\text{eval}}=4\) executions per active candidate per round, retained-set sizes \(N_1=8\) and \(N_2=3\), and temperature \(T=0.4\). A fully searched item therefore uses \(12 \times 4 + 8 \times 4 = 80\) candidate-trajectory executions before the GPT-4o explanation call and any variable Self-Verification retries. The maximum Self-Verification retry count is not disclosed.

Each execution produces a reasoning dialogue and extracted answer. Ground-truth checking produces binary success; the algorithm accumulates per-trajectory success rates, retains smaller high-scoring sets, and favors shorter trajectories on ties. The paper excludes examples considered uninformative because the candidate paths uniformly succeed or fail, but it does not publish the exact easy/hard thresholds, rejected-question count, or retention manifest. Search produces 1,722 selected planner examples for GPT-4o-mini, 1,624 for Llama-3-70B-Instruct, and 2,140 for Llama-3-8B-Instruct, totaling 5,486. These counts describe selected solver-specific examples, not raw trial rows or dataset splits.

GPT-4o generates an explanation for the chosen path. The external planner is Llama-3-8B-Instruct trained to emit the explanation and selected trajectory for a frozen GPT-4o-mini or Llama-3-70B-Instruct solver. The internalized version uses Llama-3-8B-Instruct as both planner and solver and trains on the explanation, trajectory, solver reasoning process, and answer. The paper reports LitGPT full SFT with learning rate \(2\times10^{-5}\), global batch size 64, maximum sequence length 4096, and four epochs.

The public artifact is a top-level JSON list stored as `math_collected_trajectory.json`, sized 4,800,046,236 bytes. Inspected records contain `meta info` with source ID, problem, level, type, reference solution, answer, and task-solving LLM, plus `trial result` with trial ID, a four-slot trajectory, full role/content reasoning dialogues, `pred_ans`, and binary `score`. Both successful and failed trials are present in the inspected range. The single-file release has no documented exact row count or train/validation/test partitions, and the dataset viewer fails schema extraction.

The current code is not parameter-identical to the paper. The repository uses two evaluations outside debug, defaults to temperature 0.8, and executes probing plus three exploration stages; its training config uses batch size 32 and two epochs. In addition, current `run_modules` logic appears to count non-empty result objects for accumulated search scoring while binary correctness is stored separately. These observations characterize the checked code revision and may not describe the unpublished run that produced the paper results.
