Release completeness is the largest limitation. The public HF dataset is a single 4.8 GB JSON file with a 24-byte license-only card. Its exact raw-trial count, solver/source partitions, immutable row IDs, schema version, checksums, and train/validation/test splits are unknown. The paper's 5,486 selected examples are solver-specific planner-example counts, not a substitute for those manifests. The current training config mentions a 0.01 validation fraction, but no released split manifest identifies the rows.

The final training products are not verifiable. The README-linked Drive endpoint for searched results and final SFT data returned 404 on 2026-07-25, and no trained external or internalized planner checkpoints were found. The raw HF trials do not by themselves provide the paper's final explanation–trajectory or explanation–trajectory–reasoning–answer tuples. Reconstructing them would require undocumented selection state and explanation outputs.

Search lineage is only partially preserved. Observed records include trials, paths, dialogues, predicted answers, and binary scores, but not explicit accumulated success tables, retained and pruned candidate sets, prune reasons, random seeds, per-path retry/stop reasons, or token, call, latency, and monetary budgets. The exact filter for uniformly easy or hard questions and the number of rejected questions are also unknown.

Outcome scoring can overfit evaluators and formats. MATH uses simple-eval, Game of 24 a task checker, and other tasks exact string matching. Appendix C reports a date-understanding failure caused by Python output formatting. A path can therefore rank well because it matches an extractor, not because its reasoning is semantically stronger. Self-Verification is generated by the same solver, so correlated errors and confident false verdicts can persist.

Planner labels are solver-conditioned. The paper itself reports different CoT/PoT choices across GPT-4o-mini and Llama-3-70B-Instruct; applying one planner to another solver can encode the source solver's capability boundary rather than general problem structure. Benchmark and model-pretraining contamination, semantic deduplication, and overlap checks are undisclosed.

Paper and current code drift on evaluation count, temperature, number of exploration stages, SFT batch size, and epochs. The checked workflow's accumulated-score implementation may also count non-empty result objects while recording binary correctness separately. A tagged paper-exact implementation, configuration provenance, and author clarification are needed before claiming exact reproduction.

The HF metadata declares MIT for the dataset repository, but upstream MATH and benchmark rights and rights for model-generated dialogue derivatives are not documented. The GitHub repository has no recognized code license. Reuse and redistribution therefore require separate rights review; a dataset metadata tag does not settle all upstream or derivative rights.
