Methodologically, the benchmark covers only 36 author-designed problems and the Python track. No configuration solves a complete problem, so the study has little evidence about clean successful end states. Erosion and verbosity are deterministic, but they remain proxies: the cyclomatic-complexity threshold can miss distributed architectural failure or penalize inherently branch-heavy functions, while 137 curated AST-Grep rules plus clone detection cannot establish semantic clarity, security, usability, or maintainability.

Correctness and quality do not share the same missing-data rule. A crash or failure zeros remaining correctness checkpoints, but a missing workspace is omitted from erosion and verbosity. Quality comparisons therefore condition on survival and may favor a system that fails before producing severely degraded later code. Native harnesses, CLI versions, reasoning settings, provider APIs, and failure handling also differ, so model rankings conflate the base model with its scaffold.

Experimental reporting has selection and version boundaries. The main table retains each model's best just-solve run among 15 configurations, whereas fuller reporting contains prompt/harness variants and the live v1.0 leaderboard continues to change. The paper reports 2,869 produced agent checkpoints for quality analysis on a 196-checkpoint correctness denominator, but the complete run ledger, per-configuration retry counts, seeds, temperatures, crashes, timeouts, and infrastructure failures are unavailable. The 2-hour budget has no turn or cost cap, weakening equal-compute comparisons.

Release completeness is the central data limitation. Runner v0.3 and problem v1.0 support fresh reruns, but the official project does not publish the complete historical trajectories, workspaces, snapshots, verifier logs, or quality outputs for successes and failures. Exact replay also lacks paper-bound run IDs, OCI digests, dependency and network snapshots, provider endpoint versions, random-seed policy, and immutable result checksums. A reproducible environment description is not the same as a reproducible historical episode.

Contamination is immediate after release. Tests and reference solutions are public alongside all 36 problems, and canaries only warn about or help detect some direct copying; they do not prove that evaluated models were clean. Some tasks are inspired by popular repositories, with no semantic/code/test-overlap manifest or memorization probe. Direct training on the suite would compromise later evaluation.

Rights, privacy, and security also remain partial. The runner is MIT and the problem repository is Apache-2.0, but those licenses do not automatically clear inspiration repositories, third-party assets and dependencies, the 473-repository human panel, provider outputs, or reasoning logs. Public Git histories may contain identity metadata, and no consent/redaction/takedown policy is reported. Reruns execute untrusted generated code, install packages, allow networking and read-write mounts, and use provider credentials without a documented benchmark-wide egress allowlist, secret-redaction scheme, hardened sandbox, or incident process. These last judgments are curator audit inferences from disclosed and missing controls, not claims that a breach occurred.
