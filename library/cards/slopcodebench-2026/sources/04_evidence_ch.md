论文在固定的 196 检查点分母上评测 15 个模型配置。最佳 strict 结果来自 GPT 5.5 与 Codex CLI 0.124.0，为 14.8%；同一配置的 isolated 为 28.1%，core 为 66.8%。这一差距具有诊断意义：模型保留核心行为的能力，明显强于同时满足当前 error/functionality 要求并维持全部既往回归的能力。所有受测配置中，没有任何一个完整解决 36 个问题中的哪怕 1 个。

纵向质量结果指向同样的退化趋势：77% 的轨迹出现 structural erosion 上升，75.5% 出现 verbosity 上升；高复杂度函数的平均数量从 3.6 增至 23.7。首个检查点到最后检查点的平均成本增长 2.2 倍，记录的 token 总量为 13.18B。这些是论文汇总结果，并非由公开 run bundle 独立重算所得。

人类代码校准分析 473 个公开 Python 仓库和 13,667 个抽样的源码改动 commit。在论文汇总口径下，智能体检查点比人类 panel 平均高 2.3 倍 verbosity、2.0 倍 erosion。这支持指标能够区分智能体产出与所选人类历史基线，但仓库/commit 清单以及指标失败样本的排除记录没有发布，因此无法独立重建。

prompt 干预给出重要的负结果。anti-slop 与 plan-first 能降低初始 erosion 或 verbosity，却通常不能消除后续退化；报告中的平均检查点成本上升 12.1%，strict 正确性反而下降。因此，初始代码看起来更整洁，并不能证明智能体能够在完整序列中同时保持正确性与结构。

公开测试、参考实现、runner、prompt 和指标代码使反馈实现可检查，也允许生成新的运行；但它们不足以让 headline 数值独立复现，因为完整的成功、失败、崩溃和超时论文轨迹、逐检查点工作区、逐运行测试与质量 JSON、模型 endpoint 快照和不变结果清单都未发布。因此，证据对“基准机制与汇总失败模式”的支持最强，对 run-level 因果归因或精确数值回放的支持较弱。
