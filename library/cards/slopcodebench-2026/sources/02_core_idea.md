SlopCodeBench turns long-horizon coding into an explicit state-transition benchmark: at checkpoint i, the agent transforms its own workspace from the previous checkpoint into the next workspace, so an early design decision becomes part of every later task.

The data object is an ordered problem episode rather than an isolated issue/patch pair. Inputs are behavioral specifications and static assets; actions are native coding-agent messages, reasoning, tool calls, shell commands, and edits; persistent state is the workspace; evaluator-side observations include black-box test outcomes, snapshots, diffs, tokens, time, cost, erosion, and verbosity. The released 36-problem, 196-checkpoint suite can generate these records, but the original paper-run records are not released in full.

The feedback contract has two independent parts. Hidden black-box tests produce strict, isolated, and core views: strict includes current and prior regression tests, isolated drops regression tests, and core uses only core cases. Deterministic static analysis separately measures erosion as complexity mass concentrated in functions with cyclomatic complexity above 10, and verbosity as the union of lines flagged by 137 AST-Grep rules or clone detection divided by lines of code. These signals are computed after a checkpoint and are not supplied as online rewards to the agent.

What is observable is equally important: the agent sees the new specification, its workspace, and its own tool outputs. It does not see the verifier tests/results or quality scores during the paper protocol, and prior conversational state is reset. The direction label is path-dependent coding-agent evaluation with regression-aware and source-quality auditing. Compared with SWE-bench-style one-shot repair, SWE-CI-style iterative test progress, or SWE-ReBench-style refreshed repository repair, the defining difference is that every new specification extends the architecture created by the same agent without test feedback.
