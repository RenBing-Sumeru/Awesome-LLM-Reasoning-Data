**Verifier 与建模限制。** 两类奖励都只判断终点答案。Countdown 检查器能够验证格式、数字使用、表达式执行和目标相等；数学检查器比较提取出的最终答案。二者都不验证中间推理。错误或不忠实的路径可能因最终答案正确而得到奖励，实质正确的回答也可能因提取或归一化失败被拒绝。Gemini-2.5-Pro 的整数答案改写还引入了依赖外部模型的上游转换，但完整提示、逐条输出、失败样本和验证决定均未发布。

**多样性代理与树行为。** 归一化 token 编辑距离、suffix match 和 ROUGE-L 都是词面代理。它们可能保留表面不同但语义等价的轨迹，也可能剪掉用词相似但语义不同的路径。概率门控可能接纳低概率分支，增大 KL 或过早耗尽宽度预算。如果剪枝后不足八条，补齐逻辑可以复制存活分支；把分组大小当作不同轨迹数量属于审计错误。这些是基于已披露数据对象的 curator 分析，不是对公开实验运行的独立测量。

**在线数据缺失。** 论文核心对象在 RL 过程中生成，但官方 HF 发布只有预处理提示与奖励元数据。它不包含生成结果、token 概率、父分支与出生元数据、前瞻片段、保留/剪枝决定、完成和被拒绝的分支、逐轨迹奖励、更新组成员关系或 checkpoint 谱系。缺少这些记录时，读者无法重放分支选择、测试其他多样性指标、测量错误剪枝，也无法重建一次更新背后的精确分组。

**配置与版本漂移。** 论文主配置使用 0.25/0.15/0.4 的绝对/相对/编辑距离阈值、20/30/50 的窗口和 LATR 占比指数衰减。公开 Countdown 脚本的阈值与论文一致；数学脚本却使用 0.15/0.25，关闭编辑距离，增加 0.2 的 suffix 与 0.5 的 ROUGE-L，并使用分段混合调度。仓库把调度字典描述为更灵活，但没有说明每张报告表格对应哪份脚本/配置。该差异在得到解释前会阻碍论文配置的精确复现。

**选择、切分与污染。** 发布物包含 Countdown 与 math 的 train/test Parquet 文件；论文则描述人工划分的 1,024 条 DAPO-Math validation set 和独立外部 benchmark。逐文件精确行数、来源版本、选择清单、转换产出、重复规则和记录级 provenance 均为 unknown。已检查材料中没有去污染或 benchmark 重叠流程。公共数学语料和 benchmark 在生态中被广泛复用，因此论文分数差异本身不能排除污染风险。

**系统与泛化。** 论文报告 LATR 每步约慢 10%，八张 H200 的峰值显存约 130 GB；动态序列插入/删除和比较缺少树结构专用批处理 kernel。达到目标分数所需步数减少，并不消除硬件、显存和工程成本。实验覆盖可验证的算术与数学；对代码、证明、agent、开放式任务、不同 verifier 或更大前沿策略的迁移均为 unknown。表 4 中 LATR 训练模型用 LATR 解码得到 68.9 Pass@1、用随机解码得到 70.9，也说明训练时多样性不能自动为推理时使用 LATR 辩护。

**许可证与发布治理。** arXiv PDF 使用 arXiv non-exclusive distribution license，该许可不覆盖代码或数据。固定版本 Git tree 中未发现代码许可证，HF card/API 也没有数据许可证字段或 license 文件。Countdown 和 DAPO-Math 的上游衍生数据权利还需审查。因此，公开可见不能作为再分发、商业训练或衍生发布的充分授权证据。
