**Inputs and preprocessing.** Countdown supplies arithmetic-expression training tasks and an official test set. DAPO-Math supplies training problems; the paper manually partitions a 1,024-item validation set, while MATH-500, AMC-2023, and Olympiad-Bench are external evaluations. Some math questions with non-integer original answers are rewritten into integer-answer tasks using a few-shot Gemini-2.5-Pro prompt. The transformation inputs, outputs, rejected rewrites, and validation log are not released. The public data consists of `countdown-base/train.parquet`, `countdown-base/test.parquet`, `math-base/train.parquet`, and `math-base/test.parquet`; exact source snapshots, row counts per file, deduplication, and overlap controls are unknown.

**Policy and group budget.** Main runs initialize Qwen2.5-3B Base and perform 500 online RL steps. Each prompt requests \(k=8\) responses. Training sampling is reported as temperature 1.0, top-k \(-1\), and top-p 1.0; evaluation uses temperature 0.6, top-k 20, and top-p 0.95. Maximum completion length is 1,024 tokens for Countdown and 8,192 for math. Additional generalization experiments use Qwen2.5-7B and Qwen3-1.7B-Base.

**Branching.** For every active sequence, the top-probability token continues the parent. A non-top token can create a child when its probability exceeds \(\tau_{\mathrm{abs}}\) and its gap from the top candidate is below \(\tau_{\mathrm{rel}}\), subject to the target tree width. The paper’s main configuration reports \(\tau_{\mathrm{abs}}=0.25\) and \(\tau_{\mathrm{rel}}=0.15\). Released scripts additionally cap considered branch candidates at two per token.

**Lookahead and pruning.** Newly born branches are simulated over windows of 20, 30, and 50 tokens. The paper formalizes parent–child divergence through normalized token-ID edit distance and reports threshold \(\tau_{\mathrm{ed}}=0.4\); branches that remain too similar are removed with their descendants. The method therefore uses future trajectory evidence, not the branching token alone, to decide whether a branch deserves rollout budget. Random branching, no/random pruning, and token-level lookahead are studied as weaker alternatives.

**Completion and mixing.** Once the width target is reached, or after the controlled tree phase ends, ordinary stochastic decoding completes the sequences. Pruning can leave fewer than eight survivors; `fill_return_sequences` can duplicate a survivor to satisfy the requested group size, so eight returned rows need not mean eight distinct paths. Training mixes LATR groups with standard stochastic groups to reduce train–test mismatch. The paper specifies exponential decay of the LATR share, with \(\gamma=0.985\) for Countdown and \(0.995\) for math.

**Verification and update.** Countdown extracts the expression enclosed by the task’s answer tags, checks format, confirms that every provided number is used exactly once, executes the expression, and compares the value to the target; format-only success receives 0.1 and full correctness 1.0. Math extracts the `Answer:` result and uses binary exact correctness under the integer-answer protocol. These terminal scalar rewards feed group-relative GRPO or DAPO updates; no step-level label is created. Runs use VeRL 0.5.0, AdamW, constant learning rate \(10^{-6}\), global batch/minibatch size 256, and eight NVIDIA H200 GPUs. DAPO also uses group filtering and a generation batch of 384.

**Released-script drift.** Countdown scripts match the paper’s 0.25/0.15/0.4 thresholds, but the released math scripts set absolute 0.15 and relative 0.25, disable edit-distance pruning, and enable suffix-match 0.2 plus ROUGE-L 0.5. The scripts also encode task-specific piecewise `mix_ratio_schedule` dictionaries rather than the paper’s exponential schedule. A faithful reproduction must pin paper/arXiv v3, Git commit `2adb0edf24cc9a9342ac021892897adcec1a2738`, HF commit `082e3b599960ef8341d1f00be8ae474d994345cf`, VeRL 0.5.0, task data snapshots, reward extraction, all tree parameters, schedule, seed, and hardware—and must choose and report whether it follows the paper or the released math scripts.

**Outputs and use.** Runtime outputs are prompt-conditioned rollout groups with surviving completions and terminal rewards, consumed immediately by RLVR. Raw token distributions, branch parents/birth steps, lookahead segments, prune/keep decisions, rejected and completed paths, reward decisions, group membership, and policy-update records are not published. The HF files can seed the prompt/reward side of a rerun, but they cannot replay or audit the paper’s online tree generation.
