**Verifier and modeling limits.** Both rewards judge terminal answers. Countdown’s checker can validate format, number use, execution, and target equality; the math checker compares an extracted final answer. Neither verifies intermediate reasoning. A correct final answer can reward a flawed or unfaithful path, while extraction or normalization failures can reject a substantively correct response. The Gemini-2.5-Pro integer-answer rewriting adds an upstream model-dependent transformation whose full prompt, item-level outputs, failures, and validation decisions are not released.

**Diversity proxy and tree behavior.** Normalized token edit distance, suffix match, and ROUGE-L are lexical proxies. They can preserve superficially different but semantically equivalent trajectories or prune semantically different paths with similar wording. Probability gating can admit low-probability branches that increase KL or exhaust the width budget early. If pruning leaves fewer than eight branches, padding can duplicate a survivor; treating group size as unique-trajectory count would be an audit error. These are curator analyses grounded in the disclosed data object, not independent measurements of the released runs.

**Missing online data.** The paper’s central object is generated during RL, but the official HF release contains processed prompts and reward metadata. It omits generated completions, token probabilities, parent and birth metadata, lookahead segments, prune/keep decisions, completed and rejected branches, per-trajectory rewards, update-group membership, and checkpoint lineage. Without those records, readers cannot replay branch selection, test alternative diversity metrics, measure false pruning, or reconstruct the exact groups behind an update.

**Configuration and version drift.** The paper’s main setup uses absolute/relative/edit-distance thresholds 0.25/0.15/0.4, windows 20/30/50, and exponential LATR-share decay. Released Countdown scripts are aligned on the thresholds, but math scripts use 0.15/0.25, disable edit distance, add suffix 0.2 and ROUGE-L 0.5, and use piecewise mixing schedules. The repository describes its schedule dictionary as more flexible, but does not identify which script/config produced every reported table. Exact paper reproduction is blocked until this discrepancy is reconciled.

**Selection, split, and contamination.** The release has Countdown and math train/test Parquet files, while the paper describes a manually partitioned 1,024-item DAPO-Math validation set and separate external benchmarks. Exact per-file counts, source revisions, selection manifests, transformation yields, duplicate rules, and record-level provenance are unknown. No decontamination or benchmark-overlap procedure was found. Because public math corpora and benchmarks are reused across the ecosystem, the reported benchmark deltas cannot resolve contamination risk.

**Systems and generalization.** LATR is reported about 10% slower per step and roughly 130 GB peak memory on eight H200s; dynamic sequence insertion/removal and comparison lack tree-specific batching kernels. The claim of fewer steps to a target score does not remove hardware, memory, or engineering costs. Experiments cover verifiable arithmetic and mathematics; transfer to code, proofs, agents, open-ended tasks, different verifiers, or larger frontier policies remains unknown. The Table 4 result—68.9 Pass@1 with LATR decoding versus 70.9 with stochastic decoding for a LATR-trained model—also shows that training-time diversity does not automatically justify inference-time LATR.

**Licensing and release governance.** The arXiv PDF uses the arXiv non-exclusive distribution license, which does not license code or data. No code license was found in the pinned Git tree, and the HF card/API exposes no dataset license or license file. Upstream Countdown and DAPO-Math derivative-data rights also require review. Public visibility therefore is not sufficient evidence for redistribution, commercial training, or derivative release.

The status remains `partial`. Strong paper and artifact verification coexist with missing raw trees, absent failure retention, unresolved paper–script drift, unknown decontamination, unknown code/data rights, undisclosed transformation logs, and no independent reproduction.
