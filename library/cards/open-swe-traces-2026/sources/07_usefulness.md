For the data-construction and open-release track, this work is a concrete recipe for converting executable repository tasks into auditable distillation episodes. It identifies the source-task filter, teacher modes, agent interfaces, structural and behavioral pruning, git-integrity scan, normalized schema, outcome contract, public shard organization, and student-training settings. That makes it useful as a design reference even when exact replay remains incomplete.

The corpus can support supervised fine-tuning, thinking/non-thinking distillation, tool-call modeling, failure-aware curricula, outcome-conditioned sampling, and studies of transfer between OpenHands- and SWE-agent-style interfaces. Patches and terminal labels permit analyses of where reasoning, tool use, and code changes diverge. Unresolved traces may be useful as negative or exploratory data, but only under an explicit objective; `resolved=-1` should be isolated from confirmed failures.

Responsible reuse should pin the HF revision and shard hashes, recover canonical PR and commit lineage, retain repository/license/patch fields, snapshot harnesses and containers, and construct leakage-resistant train/evaluation splits. Test quality and outcome causes should be audited before using `resolved` as a reward. The release is directly suited to SFT and distillation; it is not automatically an online-RL environment or a step-level process-supervision dataset because reset/replay artifacts and per-action correctness labels are not included.
