The central idea is a hierarchical reward contract. Prime remains the first gate: if its programmatic matcher accepts an extracted final answer, reward is 1 and TinyV is not called. Only a Prime rejection is sent to the 1.5B learned verifier, whose binary decision can recover the reward. This preserves a cheap, high-precision path while concentrating learned judgment on the rule verifier's suspected blind spots.

The training data is constructed around that deployment distribution. Four DeepSeek-R1-Distill-Qwen-7B answers are generated for each Big-Math problem. Boxed answers rejected by Prime are re-judged by Qwen2.5-72B-Instruct and Grok-3-Mini-High; unanimous correctness defines real false-negative candidates. Qwen2.5-72B-Instruct also generates semantically equivalent answer variants, which are re-annotated. Positive and negative Prime-rejected cases are balanced for SFT.

This is verifier refresh rather than replacement. The rule system defines the routing boundary and extraction assumptions; the learned model repairs a changing error surface as policy outputs diversify. The paper's own RL analysis motivates refresh by finding false negatives throughout training, but the public release does not contain the per-run trajectory ledger needed to reconstruct that changing surface.
