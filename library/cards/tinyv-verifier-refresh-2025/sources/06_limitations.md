Release completeness is the main limitation. The public 159,136-row balanced set is not the reported 638K precursor pool. It omits raw candidate generations, format failures, judge disagreements, malformed outputs, retry histories, rejected synthetic variants, and the second per-row Qwen/Grok decision. Because only one LLM label and rationale remain, the defining two-judge consensus cannot be independently replayed row by row.

Experiment binding is incomplete. The public 7,009-row difficult-prompt pool is larger than the sampled 5,000 used for GRPO, but sampled IDs and the random seed are missing. Code has no named paper release or manifest binding code, data, prompts, models, environment, and results. The current SFT launcher uses cutoff 2,048, batch 64 per device, and gradient accumulation 2 rather than the paper/model-card values 4,096, 8, and 8. The current GRPO launcher uses response length 4,096 for both bases, while the paper reports 3,072 for Qwen2.5-Math-7B.

Evaluation does not isolate verifier quality. All three public datasets expose only a train split; no source-disjoint verifier validation/test set, precision/recall, false-positive rate, calibration, abstention analysis, or confusion matrix is released. HardVerify's paper composition of 115 Olympiad plus 10 MATH differs from the artifact's 110 Olympiad plus 15 Math_500. Thresholds intend to separate the Big-Math benchmark half from the RL prompt pool, but no complete exact or semantic overlap audit covers all evaluation sets or pretraining data.

Licensing is fragmented. The repository declares MIT and checkpoint pages declare Apache-2.0, while the paper describes upstream Big-Math-RL-Verified as Apache-2.0. None of the three TinyV dataset cards declares a dataset license, and no source-level attribution and compatibility ledger is released. Public access therefore does not establish reusable data rights. Privacy and consent review are unknown.

The terminal contract checks only an extracted final answer. It cannot detect invalid reasoning that happens to end correctly, and a false-positive learned judgment can reward a wrong solution. Synthetic equivalence generation may also change semantics. The evidence is restricted to mathematical answer verification and GRPO, and TinyV is not uniformly better on every reported benchmark/base-model pair.
