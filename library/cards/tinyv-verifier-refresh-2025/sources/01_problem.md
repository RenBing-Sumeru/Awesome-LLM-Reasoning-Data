The authoritative 2025 venue record lists **TinyV: Reducing False Negatives in Verification Improves RL for LLM Reasoning** as a poster at the **2nd AI for Math Workshop at ICML 2025**, not as an ICML main-conference paper. The seven-author arXiv:2505.14625 record was submitted on 2025-05-20 and revised on 2025-05-22; the later 2026-06 TMLR version is version history and does not replace this Card's year, venue, or author list. The L4 review uses the complete paper, workshop/OpenReview records, pinned code, three public datasets, HF model collection, and reward implementation.

Rule-based mathematical verifiers are inexpensive and deterministic, but they can reject answers that are mathematically equivalent to the reference because language, formatting, or notation differs. Such false negatives are not merely evaluation errors in reinforcement learning: a correct rollout receives reward 0, potentially turning an informative prompt group into an all-wrong group with no useful relative-advantage signal.

TinyV treats this as a verifier-refresh data problem. The paper audits Prime Verifier on responses generated from Big-Math-RL-Verified, uses large-model re-judgment to identify missed correct answers, and builds supervision for a compact learned answer-equivalence verifier. The released object is a family rather than one dataset: 159,136 balanced verifier-SFT rows, a 7,009-row hard-prompt candidate pool, a 250-row HardVerify-Math benchmark, verifier checkpoints, and code for a Prime-gated terminal reward.

The contract remains answer-level. Prime extracts a boxed final answer; TinyV receives the question, reference answer, and candidate answer and emits literal True or False. Neither component checks whether the derivation is valid or faithful. The learned verifier may recover a correct answer that Prime missed, but its own false positives can reward wrong solutions.

TinyV belongs only to **Data Construction and Open Release Recipes** because the Atlas decision centers on the verifier-refresh recipe: audit stale rule rewards, construct real and synthetic equivalence supervision, balance labels, train a compact judge, and place it behind a programmatic gate during GRPO. It is not process-supervision data because no reasoning step is labeled, and it is not a preference-data release because the target is a binary correctness label rather than a chosen/rejected pair. HardVerify-Math is an accompanying benchmark, not the Card's primary category.

The L4 evidence boundary verifies the 159,136-row balanced SFT set, 7,009-row public prompt pool, 250-row HardVerify release, checkpoints, prompts, labeler scripts, and online reward code. It does not supply the reported 638K precursor pool, exact sampled 5,000 RL IDs, both per-row Qwen/Grok judgments, held-out verifier precision/recall/FPR/calibration, dataset licenses, or a paper-exact tagged manifest. L4 therefore supports review of the refresh mechanism and release gaps, not a claim that TinyV's recovered reward is ground truth.
