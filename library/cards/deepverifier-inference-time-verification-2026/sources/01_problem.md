Deep-research agents can browse, call tools, write code, and synthesize long reports, but a plausible final response may rest on a missed source, an invalid action, or an unsupported inference buried in a long trajectory. A single final-answer judge is often too coarse: asking another model to re-solve the full task can be as hard as the original task, and a generic critique may not explain what should be checked or how the agent should retry. Human monitoring is also unrealistic when an agent has taken dozens of actions across many pages.

This paper asks whether extra test-time computation can be spent on verification itself rather than only on producing more candidate answers. It formulates a loop that detects likely failure points, turns them into narrower evidence questions, verifies those questions, and feeds targeted advice back to the original agent. The central premise is that checking a localized claim can be easier than generating the entire research result, provided the verifier knows which risky claims deserve the additional work.
