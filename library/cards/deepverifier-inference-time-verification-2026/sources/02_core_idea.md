DeepVerifier uses a failure taxonomy to make reflection concrete. Instead of issuing an undifferentiated verdict over a full research trace, it summarizes the trace, identifies behaviors associated with known failure categories, and asks high-leverage follow-up questions such as whether a cited source actually supports a claim. The verifier then gathers evidence for those questions and judges the answer using a rubric. A rejection produces instructions for the original agent to repair the response rather than merely a scalar score.

The paper treats each feedback-and-retry round as a test-time scaling unit. More rounds purchase more opportunity to discover and correct failures, but only if the verifier's feedback is accurate enough to guide a productive retry. This shifts the allocation target from parallel answer diversity to iterative verification quality. The same framework also creates verified reflection trajectories that can later be used to train an open verifier, while the paper's central evaluation remains the inference-time loop without additional policy training.
