The problem is credit and data acquisition in an LLM multi-agent system. A task may supply a terminal correct/incorrect result or game utility, but it does not label which Physicist, Mathematician, Summarizer, Context Analyst, Actor, Critic, Judgment, or negotiating-player message caused that result. SiriuS uses the terminal outcome as a coarse selection signal: successful interactions become role-conditioned supervised examples, while some failed interactions are repaired with privileged feedback and retained only if the rerun system succeeds.

The training object is therefore not one monolithic chat transcript. For a direct success, every participating role contributes a separate SFT record pairing the task and predecessor messages with that role's output. For a repaired failure, only the regenerated selected role and rerun downstream roles contribute records. This is full-episode outcome supervision propagated onto role messages; it is not verified step-level reasoning, causal agent credit, a preference pair, or policy-gradient reinforcement learning.

The scope spans three settings. Problem solving uses College Physics, College Chemistry, and PubMedQA role graphs; Actor-Critic separates answer generation, judgment, and corrective feedback; competitive experiments use Resource Exchange, Seller-Buyer, and multi-turn Ultimatum environments with deterministic role utilities. This variety supports a construction-recipe reading, but it does not turn the reported task scores into evidence that every retained intermediate message is correct.

This Card belongs only in **Data Construction & Open Release Recipes**. It includes SiriuS for its explicit benchmark/game input → multi-agent episode → terminal evaluation → success library or feedback repair → role-specific SFT → next-iteration pipeline. It is not categorized as an open data release because the paper-run experience libraries, full episodes, failed attempts, critic feedback, role JSONL, rewards, logs, and fine-tuned checkpoints are absent. It is also not an RLVR recipe: optimization is standard role-specific SFT, even though reward/verifier outputs select the records.
