Each agent samples a role message from the task plus all predecessor messages in a directed communication graph. If the terminal reward exceeds symbolic threshold `epsilon`, SiriuS adds every participating message to that role's good-trajectory library. Separate standard SFT jobs then update the role policies, and a later iteration can roll out the updated system to build a new library.

Failed QA episodes take a narrower path. SiriuS selects one role, gives an external critic the task, that role's original answer, and the correct answer, and requests actionable feedback. The role regenerates from its original response and feedback; the result is rephrased to remove explicit references to the error or critique; every successor is rerun. Only if the final parsed answer becomes correct are the regenerated selected-role and downstream messages admitted. Unrepaired failures provide no SFT targets.

The closest **data-loop predecessor** is STaR: both bootstrap supervised reasoning data from successful model-generated solutions. STaR is single-agent, whereas SiriuS decomposes success into role-conditioned records and replays downstream agents after repairing one role. That difference is the main reason SiriuS is useful for this track; it also imports STaR's risk that terminal success may admit lucky or flawed reasoning.

The closest **interaction-only comparator** is the training-free Prompt Multi-Agent System, reported as CoMM/COMM. It uses collaborating agents but does not turn their trajectories into independently fine-tuned role libraries. Single-Agent is the lower-bound structural comparator: it removes role decomposition and multi-agent communication altogether.

TextGrad and DSPy/MIPROv2 are the closest **optimization-object comparators**. TextGrad backpropagates natural-language feedback to optimize agent prompts, while DSPy jointly searches instructions and few-shot examples. SiriuS instead changes model policies through SFT on selected role outputs. Consequently, a gain over TextGrad or DSPy does not isolate “better data” alone; it also changes the trainable object, execution reliability, and provider fine-tuning path.

Actor-Critic is a separate feedback contract inside the paper, not the same as the problem-solving selector. A learned Judgment agent can accept or reject the Actor, and a Critic supplies textual feedback after rejection. Competitive settings use game-state transitions and deterministic role utilities rather than answer equality. These variants explain `verification_contract: mixed`: the framework combines programmatic terminal checks, learned judgment, textual critique, and scalar environmental utility.
