For the `rollout_search_test_time_trace_data` track, DEER supplies a schema for adaptive-compute trace selection. An auditable record should retain the benchmark item and split, model and tokenizer revision, full unmodified CoT, every marker or entropy candidate, saved prefix state, inducing prompt, trial tokens and per-token probabilities, aggregation method, λ, DEER-PRo mean/MAD terms, branch timing and memory, exit action, final answer, external correctness, and the corresponding full-decoding outcome.

Such records could support calibration of false exits and missed exits, imitation of compute controllers, comparative test-time-compute studies, or construction of preference pairs between truncated and continued traces. Reuse must keep model self-confidence, controller decision, benchmark correctness, rationale faithfulness, and actual latency as separate fields. The current code can help reproduce part of the controller, but absent rollout logs and branch-parallel code prevent claiming a complete reusable release.
