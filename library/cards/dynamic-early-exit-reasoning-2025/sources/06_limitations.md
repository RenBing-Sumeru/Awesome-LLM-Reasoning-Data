The central assumption is that trial-answer token probability tracks answer correctness. This can fail under distribution shift, for models with systematically low or inflated confidence, and for long structured code answers. Qwen3 required implementation-specific changes, directly showing that one aggregation and exit predicate does not transfer unchanged. DEER-PRo reduces prompt dispersion but does not create independent ground truth.

Marker monitoring is English- and model-dependent; equivalent transition tokens must be found in other languages. Entropy peaks indicate uncertainty about the next token, not necessarily a semantic reasoning boundary. A confident wrong prefix can exit early, while a correct but low-confidence prefix can waste compute. Truncation can also make the visible rationale incomplete or unfaithful to the returned answer.

Trial branches add compute, latency, and KV-cache overhead, especially for code. Branch-parallel acceleration changes scheduling and memory behavior, but its official code is not yet released. Main experiments often use greedy decoding and a 16k cap; behavior under stochastic sampling, other token budgets, closed models, tools, or open-ended outputs remains incompletely established.

No versioned decision-trace dataset is documented. Raw prefixes, all candidate events, rejected trial answers, token probabilities, thresholds, branch timing, failures, seeds, exact run manifests, and per-example exit logs are unavailable as a stable release. Code has no tagged release. Benchmark accuracy and compression cannot substitute for calibration, replay, contamination, or trace-faithfulness audits.
