SWE-bench and related benchmarks use authentic repository issues, but they predominantly cover conventional software engineering and generally treat test success as a sufficient correctness proxy. AInsteinBench retains the repository-snapshot, patch, and container-execution framework while changing task provenance and audit targets: it selects scientific-software maintainer pull requests and adds domain-expert checks of scientific semantics, numerical behavior, and test discriminativeness. Its novelty is not a new agent architecture but the inclusion of scientific-computing constraints in instance selection and verification, distinguishing generic code modification from scientific-software maintenance.
