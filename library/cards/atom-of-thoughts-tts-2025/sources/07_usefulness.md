Use AoT when a multi-step task has decomposable dependencies and the main bottleneck is repeatedly carrying irrelevant history through search or reflection. The implementation should log a state lineage: input, dependency DAG, subquestion answers, contraction result, answer-equivalence check where available, branch, cost, and final score. This lineage supports auditing both efficiency and correctness: a shorter prompt is only useful when the contracted state retains the information that later decisions need.
