Closed-source mobile applications do not expose the privileged internal states that AndroidWorld- or OSWorld-style evaluators can query. AndroidDaily addresses the resulting evaluation gap: an agent may appear to finish a transaction, booking, cross-app workflow, or generated-content task, yet correctness can depend on output quality, several obligations, and actions it must avoid. The benchmark therefore externalizes each task's success conditions as operational obligations, output-quality criteria, and negative constraints, then judges the observable episode rather than hidden application state (Paper Sections 1 and 3.2).

The 2026 benchmark contains 350 natural-language tasks across 94 high-frequency closed-source Android applications. One evaluation object couples a task instruction and three-tier guideline with a session-identified trajectory of screenshot/accessibility observations and ADB-executed actions; GRADE transforms the episode into step evidence, a structured evidence bundle, per-tier checks, diagnostic signals, and a final Boolean verdict. This is an `environment_agent_trajectory_data` object because environment state, actions, observations, feedback, and the terminal predicate are inseparable (Paper Sections 3.1-3.3; Algorithm 1).

The Card reaches L4 content depth for screening and audit, but its canonical curation level remains L3: the paper claims that task definitions, guidelines, and evaluation code are released without providing a verifiable URL, license, or version pin, and it explicitly withholds raw trajectories (Paper Section 5). The official StepFun 235-task AndroidDaily dataset associated with 2025 Step-GUI/GELab papers is predecessor lineage, not the 350-task/94-app/GRADE artifact described here.
