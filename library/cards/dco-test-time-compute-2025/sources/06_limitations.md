DCO needs a clear correctness signal and an anticipated pass@N regime, so it is easiest to apply to mathematics, code, or formal tasks with efficient verification. Matching one training parameter to one deployment budget yields no single model that is optimal across all budgets; approximate confidence for chain-of-thought adds estimator error, and high-N sampling can still be expensive. The reported results use particular base models, datasets, and proof environments, while the method’s confidence interpretation assumes that model confidence is related to answer correctness. Deployment should therefore validate calibration, diversity, verifier reliability, and real serving cost rather than infer them from loss curves alone.
