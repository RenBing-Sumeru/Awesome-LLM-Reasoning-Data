The central risk is verifier feedback. A false-positive completion can admit a bad trajectory to SFT, label its steps positive, and shape the next agent; a false-negative can discard valid alternatives. Controlled truncation, cross-task substitution, and redundant continuation may also leave detectable artifacts that differ from organic agent mistakes. The custom RM benchmark shares source families and corruption logic with training, so generalization to unseen apps and failure modes remains uncertain.

Published counts and units do not line up cleanly. The paper/name uses 517K RM examples, but the current viewer exposes 472,769 rows. “Agent-16k” is described loosely as trajectories in prose/README, while Table 1 and the file layout support 2,208 trajectories and roughly 16K step examples. The Agent repository also mixes in `AMEX_Agent_34K.jsonl` without documenting whether it is upstream context, a training dependency, or part of the release. There is no generation manifest or record-level acceptance provenance to reconcile these differences.

Reproduction is incomplete. The repository supplies agent SFT and AndroidControl evaluation scripts, but not RM training or the iterative generation pipeline; AndroidLab and Android Arena evaluation scripts are still marked for future release, the 72B checkpoint is not released, and there are no tags or GitHub releases. Exact exploration temperature, stopping policy, task budgets, emulator/app versions, account state, and immutable environment snapshots are unknown. Dynamic interfaces make coordinate replay and success predicates non-stationary.

Privacy, rights, and split controls are also unresolved. Screenshots and typed text can reveal accounts, notifications, contacts, queries, or third-party content. The HF cards label the datasets MIT, but that label does not establish rights to every upstream screenshot, app interface, or user state. The repository's root README claims MIT while no root license file exists and bundled ms-swift carries Apache-2.0. No verified per-record consent/redaction log, source license matrix, deduplication report, or app/task/account leakage analysis is available.

The paper itself notes suboptimal RM rewards, inability to guarantee fully correct trajectories, and high computation/carbon cost. Evaluation confirms substantial remaining gaps: Android Arena hard and multi-frame-query success is 0.0 for the reported 7B agent, and test-time reward selection does not consistently improve hard cases.
