初始 RM 数据由两条分支构成。规则核验按动作类型、空间定位和输入文本语义检查源动作。受控轨迹破坏通过提前截断、用同一 app 中另一任务的动作替换部分轨迹、或在任务完成后继续执行冗余动作来制造结果级负例。困难负例分支先利用 AMEX 的 UI 元素标注，再让 DeepSeek-V3 把功能描述改写为可执行动作描述；被初始 RM 错判为正的样本会被保留为困难负例。

探索采用奖励引导的 beam search。当前 agent 在每个状态提出 10 个动作，UI-Genie-RM 给出步级奖励，系统按累计奖励排序并让前 5 条路径继续。UI-Genie-RM 还判断完整轨迹是否成功。成功轨迹进入 agent SFT，并贡献正的奖励步骤。对于失败轨迹中的某一步，流程采样 5 条续跑路径：只要其中一条成功，原步骤就标为正，否则按负例处理。这是一种由模型中介的标签契约，并非每条记录都由独立环境真值裁决。

三轮迭代逐步扩展任务。第一轮直接使用 AndroidLab 与 AMEX 训练数据中的指令；第二轮让 DeepSeek-V3 根据 app 描述和第一轮示例生成新指令；第三轮重试失败指令，并加入人工编写、需要超过 10 步的复杂场景。因此，论文所称“without manual annotation”针对的是合成轨迹的标注，不代表流程没有人工输入，因为源示范与人工编写的复杂任务提示仍在其中。

论文用 458K 条初始样本和 59K 条探索样本训练 7B RM，采用 AdamW、1e-5 学习率和全局 batch 160。7B agent 每轮之后继续训练 1 个 epoch；3B 使用全参数微调，72B 使用 RSLoRA（rank 64、alpha 256、PiSSA 初始化）。发布仓库包含 3B/7B/72B agent SFT 脚本和 AndroidControl 评测代码，但没有端到端的受控破坏、困难负例挖掘、RM 训练、beam-search 探索，也没有动态 AndroidLab/Android Arena 执行流程。
