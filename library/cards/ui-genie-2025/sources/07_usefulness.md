For the open-release construction-recipes track, UI-Genie is useful as a staged design to compare: seed labels from rules, manufacture several negative types, train a multimodal verifier, use it in bounded search, verify outcomes, recover step labels with continuations, and alternate RM/agent updates. Researchers can study which stage contributes new coverage versus merely recycles the verifier's preferences.

The RM release can support binary GUI reward modeling, history-length studies, corruption detection, calibration, and evaluation of cross-source transfer. The Agent release can support step-level mobile-action SFT, trajectory reconstruction by directory identifier, and analyses of task progress/action-description formatting. Because the public JSONL is step-oriented, users should reconstruct episodes explicitly rather than treating rows as independent trajectories.

Safe reuse should pin Hub commit SHAs and the repository commit; preserve source, episode, step, generation, corruption operator, verifier version/score, and acceptance reason in a new manifest; separate AMEX from UI-Genie-generated records; audit screenshots and typed content; and freeze emulator/app/account state. A new project should validate completion with independent executable checks or human audits, measure verifier calibration by source/app/difficulty, and keep a held-out app/task split before feeding selected trajectories back into training.

The release is not a turnkey reproduction of the full loop. It is best treated as partial data plus an auditable recipe whose missing generation, RM-training, dynamic-environment, licensing, and lineage components must be supplied before deployment or strong causal claims.
