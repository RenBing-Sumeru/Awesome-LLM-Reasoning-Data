移动 GUI agent 同时需要局部动作正确性与整项任务完成度的监督，但动态执行成本高，参考轨迹又只覆盖少量有效行为。仅靠静态模仿数据，无法判断替代点击是否无害、后续界面是否已经满足指令，也无法发现表面成功的动作是否带来不期望的副作用。UI-Genie 研究的问题是：能否用一个学习得到的多模态验证器，把既有示范和新的设备探索转化为更多奖励模型数据与 agent 训练数据。

这里的数据对象并不只是“轨迹”。它还包括由截图、动作历史、候选动作、规则标签、受控破坏和困难负例构成的二元步级/任务级奖励样本，以及被判定成功后用于 agent SFT 的探索步骤。因此，审计时必须区分源示范、合成负例、探索轨迹、验证器决策与最终发布中的行数/轨迹数口径。
