对“开放发布的数据构造配方”这条 track 而言，UI-Genie 提供了一套可分阶段比较的设计：先用规则获得种子标签，再制造多类负例、训练多模态验证器、把它放入有界搜索、核验任务结果、用续跑恢复步骤标签，并交替更新 RM 与 agent。研究者可以据此判断，哪些环节真正扩展了数据覆盖，哪些环节只是重复验证器已有偏好。

RM 发布可用于二元 GUI 奖励建模、历史长度研究、破坏检测、校准和跨来源迁移评估。Agent 发布可用于步级移动动作 SFT、依据目录标识重建轨迹，以及分析任务进度与 action description 的格式。由于公开 JSONL 以步骤为单位，复用者应显式重建 episode，不能把每一行当作独立轨迹。

稳妥复用时，应固定 Hub commit SHA 与仓库 commit；在新 manifest 中保留来源、episode、step、代次、破坏算子、验证器版本/分数和接纳原因；把 AMEX 与 UI-Genie 生成记录分开；审计截图与输入内容；冻结模拟器、app 和账户状态。新项目还应使用独立可执行检查或人工审计来核验完成度，按来源/app/难度测量验证器校准，并在把筛选轨迹回灌训练前保留 app/任务级测试集。

这个发布并不是完整闭环的一键复现包。更合适的定位是“部分数据 + 可审计配方”；在用于部署或提出强因果结论之前，仍需补齐生成、RM 训练、动态环境、许可和逐记录 lineage。
