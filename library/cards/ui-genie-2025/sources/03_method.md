The initial RM set is built in two branches. Rule-based verification checks source actions by type, spatial grounding, and typed-text semantics. Controlled trajectory corruption creates outcome negatives by early truncation, replacing part of a trajectory with actions from another task in the same app, or continuing redundantly after completion. For hard negatives, AMEX UI-element annotations are converted by DeepSeek-V3 from functional descriptions into executable action descriptions; samples misclassified as positive by an initial RM are retained as difficult negatives.

Exploration uses reward-guided beam search. At each state the current agent proposes 10 actions; UI-Genie-RM supplies step rewards, paths are ranked by cumulative reward, and the top five continue. UI-Genie-RM also judges whether a completed trajectory succeeded. Successful trajectories become agent SFT data and contribute positive reward steps. For a step in a failed trajectory, the pipeline samples five continuations: if any reaches success, the original step is labeled positive; otherwise it is treated as negative. This is a model-mediated label contract, not an independently adjudicated environment truth for every record.

Three rounds broaden tasks. Round 1 uses instructions from AndroidLab and AMEX training data. Round 2 asks DeepSeek-V3 to generate novel instructions from app descriptions and first-round examples. Round 3 revisits failed instructions and adds manually crafted scenarios requiring more than 10 steps. Thus the paper's “without manual annotation” claim concerns synthetic trajectory labeling; it does not mean zero human input, because source demonstrations and manually authored complex task prompts remain in the pipeline.

The paper trains the 7B RM on 458K initial plus 59K exploration examples with AdamW, learning rate 1e-5, and global batch 160. The 7B agent is iteratively continued for one epoch after each round; 3B is fully fine-tuned, while 72B uses RSLoRA (rank 64, alpha 256, PiSSA initialization). The released repository contains 3B/7B/72B agent SFT scripts and AndroidControl evaluation code, but not the end-to-end corruption, hard-negative mining, RM training, beam-search exploration, or dynamic AndroidLab/Android Arena execution pipeline.
