For `environment_agent_trajectory_data`, ScienceBoard provides a high-value example of environment-grounded feedback over professional software. The task object links a scientific instruction, assets, initialization, multi-interface actions, multimodal observations, internal state, and a terminal evaluator. This supports research on GUI/CLI planning, scientific tool use, verifier coverage, and environment failure.

Its intended released use is evaluation. The public VM and task code can run frozen agents, while the evaluator templates help compare environmental verification with screenshot-only or judge-based feedback. The trajectory archives may support qualitative error analysis, but absent manifest, licensing, and success/failure coverage prevent treating them as a clean SFT or preference corpus.

A careful reuse pipeline should pin every component, create fresh VM copies per episode, record initializer output, preserve all observations/actions/files and evaluator details, and retain failures and infrastructure exceptions. It should also define task splits, contamination policy, secret redaction, network restrictions, component licenses, and replay tests before producing any derivative training set.
