Five annotators first study tutorials and handbooks and explore unit operations in one scientific application. They draft configuration, question-answering, simulation, computation, documentation, and domain-expertise tasks. An OpenAI chat model standardizes task wording; annotators cross-check diversity, executability, and answer uniqueness before selection.

For every accepted task, annotators implement initialization functions that modify VM or application state and supply required files. They instantiate evaluator templates over exposed internal state and key workflow I/O. Each task is executed by two randomly selected annotators on separate VMs, including intentional attempts to deceive the evaluator, and the evaluator returns either task complete or task fail. Exact/range comparisons and numerical tolerance are examples; the contract can also inspect files and application-specific state.

At run time, the agent receives text-only accessibility trees, screenshots, their combination, or Set-of-Marks observations. GUI actions cover mouse movement, clicks, and keystrokes; CLI actions cover terminal commands and application scripting. `ANS`, `call_api`, `WAIT`, `DONE`, and `FAIL` extend the action space. Scientific software returns an updated state after each action, and recent observations/actions form memory.

The public stack comprises the GitHub code/tasks, a 17.1 GB `VM.zip`, modified-application/plugin links, and a 9.42 GB trajectory repository with five archives for GPT-4o observation variants, a GPT-4o-to-GUI-Actor archive, and UI-TARS-1.5. Exact code commit, VM snapshot ID, application/plugin revisions, episode schema, attempt budget, API settings, and task-to-archive manifest are not pinned as one end-to-end release.
