五名标注者先学习教程和手册，并探索某一科学应用的基本操作，再编写配置、问答、模拟、计算、文档和领域知识任务。OpenAI chat 模型统一任务表述；标注者交叉检查多样性、可执行性和答案唯一性后完成筛选。

对每个入选任务，标注者实现初始化函数，用于修改 VM 或应用状态并提供必要文件；随后把 evaluator 模板实例化为针对内部状态和关键工作流 I/O 的检查。每个任务由随机选择的两名标注者在独立 VM 上执行，也包括故意欺骗 evaluator 的尝试；evaluator 最终返回 task complete 或 task fail。精确/范围比较和数值容差是典型方式，也可检查文件与应用特定状态。

运行时，智能体接收纯文本无障碍树、截图、二者组合或 Set-of-Marks 观察。GUI 动作包括鼠标移动、点击和按键；CLI 动作包括终端命令与应用脚本；`ANS`、`call_api`、`WAIT`、`DONE` 和 `FAIL` 扩展了动作空间。每次动作后科学软件返回新状态，近期观察与动作组成记忆。

公开栈包括 GitHub 代码/任务、17.1 GB 的 `VM.zip`、修改应用或插件链接，以及包含 5 个压缩包、总计 9.42 GB 的轨迹仓库，覆盖 GPT-4o 多种观察设置、GPT-4o 到 GUI-Actor 和 UI-TARS-1.5。代码提交、VM snapshot ID、应用/插件修订、episode schema、尝试预算、API 设置及任务—压缩包 manifest 没有被固定成单一端到端发布。
