For the **Data Construction and Open Release Recipes** track, OpenMathReasoning supports concrete reuse only when the data mode, acceptance contract, and release revision remain explicit.

1. **Build a multi-mode SFT mixture.** Use `inference_mode`, `generation_model`, `problem_type`, and `problem_source` to separate CoT, TIR, GenSelect, and problem-only records. Do not infer a solution for `additional_problems` rows or treat mode splits as held-out evaluation splits.
2. **Reproduce the generation funnel.** Pin the 306K solution-bearing problem universe, teacher versions, decoding settings, answer targets, and per-stage filter policy. Preserve candidate IDs and rejection reasons so the 5.2M-to-3.2M CoT and staged TIR yields can be audited.
3. **Compare answer targets.** Stratify extracted-answer rows, converted proofs, and no-answer majority targets. Measure equivalence-judge and majority-target disagreement with independent symbolic/manual checks instead of treating all retained rows as equally verified.
4. **Represent TIR as episodes.** Parse code calls and outputs into explicit action/observation records and add sandbox image/hash, call budget, status, timeout, exception, and final-answer verdict. Test code-to-prose consistency rather than only code presence.
5. **Audit filter value.** Re-run stage-0 novelty/significance and GenSelect summarization ablations under matched data and compute. The paper's regressions make these useful negative baselines for selector design.
6. **Strengthen source and rights lineage.** Publish the original scraping code, source-post identifiers/revisions, author attribution, deletion handling, and row-level rights; retain decontamination candidate pairs, judge outputs, and decisions.
7. **Use GenSelect for test-time selection experiments.** Keep candidate group size, correctness composition, comparison rationale, selected index, answer verdict, and token budget. Separate training-time comparison traces from the winning Kaggle system, which did not use GenSelect.

Reuse classification is **conditional training and evaluation research use**. The pinned release is directly loadable for SFT and selection experiments, but high-assurance reuse remains blocked by source-rights uncertainty, unavailable original scrape, majority-answer noise, missing verifier/rejection logs, and revision drift. The 193,170 problem-only rows require a new solution-generation and verification contract before they become training targets.
