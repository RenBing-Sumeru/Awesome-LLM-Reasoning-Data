The authoritative paper entry is the [ICLR 2025 proceedings record](https://proceedings.iclr.cc/paper_files/paper/2025/hash/bea94fe9c5573e74294657f692069d89-Abstract-Conference.html), with the final 21-page paper and Appendices A-H published for ICLR 2025; [OpenReview](https://openreview.net/forum?id=1Iuw1jcIrf) records the Spotlight status. MathCoder2 asks whether mathematical code can be made more useful for continued pretraining by pairing it with the mathematical context that ordinary code corpora often lack. Existing Python and Jupyter data may import mathematical libraries, yet much of it serves engineering, machine learning, or testing rather than explaining a mathematical computation.

The work builds MathCode-Pile, a reported 19,487,652-document, 19,184,073,343-token mixture. Its distinctive records are model-translated blocks containing natural-language conditions, a LaTeX computation expression, a teacher-stated result, and executable Python. Accepted blocks are flattened into text and mixed with filtered web documents, synthetic math/science text, code using mathematical packages, and online textbooks.

This belongs in Data Construction and Open Release Recipes because the research object is the source filtering, teacher translation, execution-based selection, flattening, decontamination, packaging, and checkpoint pipeline. It is not primarily an SFT-only corpus card, a standalone execution-verifier benchmark, or an RL recipe. The primary corpus use is continued causal-language-model pretraining, which the repository enum cannot represent directly. The Card retains `sft` only because the paper separately reports supervised math fine-tuning after continued pretraining; it does not relabel MathCode-Pile itself as an SFT dataset.

The L4 evidence boundary is analytic completeness, not release completeness. The final paper, appendices, official supplemental, project page, pinned code, partial Hugging Face data, and four continued-pretrained checkpoints were inspected. The current public release remains partial, text-only, and single-split; item-level provenance, rejected translations, execution observations, textbook manifests, source rights, and an end-to-end working pipeline are unavailable. Paper-scale construction and downloadable artifacts must therefore be audited separately.
