WebSailor addresses a concrete post-training problem: open web agents can follow short or predetermined search chains, but they rarely learn the long-horizon exploration needed when a question has high initial uncertainty and no fixed path to an answer. The stable paper record is arXiv:2507.02592v1, submitted on 3 July 2025. No archival conference venue was confirmed, so the venue remains “arXiv preprint.” The official paper, appendix, repository, public QA sample, and model pages were all inspected.

The paper creates two linked data objects. SailorFog-QA contains synthetic question–answer tasks built from web-grounded graphs and information obfuscation. For cold-start training, an expert LRM solves these tasks; the method keeps successful action–observation traces, replaces the expert’s verbose native thoughts with concise reconstructed thoughts, and serializes the result as a tagged ReAct episode. DUPO then generates new multi-turn web rollouts and attaches a scalar reward based on format and final-answer correctness (Paper §§3–4; Appendix A).

This work belongs in `environment_agent_trajectory_data` because a training example is not just a prompt and answer. It includes a web environment, search/visit actions, observations, reconstructed thoughts, a terminal answer, and a trajectory-level reward. The neighboring problem is benchmark-only web search. WebSailor instead reports SFT/RFT and RL use, but it does not provide a replayable historical web snapshot or a complete public rollout corpus.

The decisive release boundary is scale. The paper says the RFT cold start uses just over 2,000 high-quality examples, yet the official repository publishes only 20 JSONL rows containing `question` and `answer`; its README still says sampled trajectory data will be released soon. Thus the Card can describe the paper pipeline at L4 depth, but the accepted metadata remains `L3_summary_ready` and `partial`: neither the complete successful RFT set nor failed/rejected DUPO rollouts are confirmed public.
