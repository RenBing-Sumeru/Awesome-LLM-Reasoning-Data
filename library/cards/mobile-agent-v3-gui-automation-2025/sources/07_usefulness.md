Use this paper as a schema for GUI-agent feedback loops. Preserve task id, platform, environment image, initial state, screenshot or observation, action grammar, chosen action, model rationale if stored, execution result, verifier outcome, and filtering decision.

It is useful for building trajectory datasets, comparing GUI foundation models, and auditing whether environment feedback is strong enough to support post-training.

For atlas use, keep benchmark evaluation, self-evolution data generation, and model training claims separate. Store accepted and rejected trajectories with the same provenance fields.
