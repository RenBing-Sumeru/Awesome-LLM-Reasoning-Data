Prior work had mobile visual agents, GUI grounding models, and standalone GUI benchmarks. Mobile-Agent-v3 changes the system boundary by treating GUI automation as a foundation-model plus executable-environment plus data-flywheel problem.

The direction signal is not just better AndroidWorld or OSWorld scores; it is the idea that GUI-agent training and evaluation should share state/action traces, environment feedback, and trajectory quality filters. The quality signal is the official arXiv paper and public MobileAgent series repository with model and framework entry points.

What is not new: using VLMs for GUI perception, executing browser/mobile/desktop actions, and benchmark success metrics. Before reuse, inspect model/data licenses, repository revision, environment availability, benchmark split, trajectory filtering rules, and whether private cloud services are needed.
