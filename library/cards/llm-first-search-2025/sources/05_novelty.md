LFS does not newly introduce tree search, LLM state evaluation, or priority queues. Relative to ToT-BFS, it avoids a fixed beam width and depth schedule; relative to BestFS, it lets the model choose when to leave the current path; relative to MCTS, it replaces the hand-set PUCT exploration constant and visit-count policy with a prompted explore-or-continue decision. Its direction signal is that one LLM authors both a discrete search-control decision and scalar values used to rank alternatives. The method still relies on task-specific prompts, action enumeration, reversible environment state, and hosted-model behavior, so reuse requires those components and exact runtime settings rather than the algorithm name alone.
