In one sentence, InSTA turns ranked internet hosts into synthetic but live-site-grounded web tasks, lets LLM agents execute them through Playwright, and uses an LLM judge to select trajectories for SFT.

The mechanism separates three model-mediated contracts. First, a task proposer receives only a URL and either emits a task or `N/A`; this is both task generation and the production safety gate. Second, an agent explores the accepted site, observes compact Markdown derived from HTML, and emits reasoning plus Playwright calls. One recent trajectory is returned to the proposer to create a harder instruction with steps and criteria grounded in current site content. Third, a judge sees the task and recent trajectory, writes a rationale, and scores success, efficiency, and self-correction from 0 to 1.

The SFT selection signal is judge success at the full-episode level. In the demonstrated 20K Qwen3-235B rollout pool, 10.5K records with `Judge(Success) = 1` are retained to train Qwen3-1.7B. Efficiency and self-correction are descriptive outputs, not filters in that experiment. An agent stop call is not proof of completion, and arbitrary live-web tasks have no deterministic ground-truth terminal predicate.

The judge can observe processed recent states and actions, but it cannot recover an archived website state, verify hidden server-side effects, or replace a deterministic oracle. Its reported peak 82.6% binary judgment accuracy is measured on only 100 human-labeled trajectories. The safety proposer likewise cannot guarantee corpus purity, and the separate human feasibility experiment is not a per-row feasibility label or production judge.

Compared with AgentTrek, which starts from web tutorials and replays their procedural instructions, InSTA starts from ranked hosts and synthesizes tasks after direct site exploration. Compared with benchmarks such as Mind2Web, WebLINX, or WebVoyager, its main object is a construction and training recipe over a broad changing web rather than a fixed evaluation surface. The distinctive contribution is the integration of URL-scale proposal, live grounding, learned terminal judgment, and filtered SFT; none of these individual components is new by itself.
