Prior web-agent datasets and benchmarks such as Mind2Web, WebLINX, and WebVoyager concentrate human tasks or demonstrations on comparatively small, curated website sets. Prior synthetic-agent pipelines already use LLMs to generate behavior, and LLM-as-judge work already uses model ratings for filtering. InSTA does not originate Playwright, task proposal, synthetic trajectories, or learned judges.

Its concrete change is the scale and interface joining these elements. A URL-only proposer simultaneously performs an initial safety decision and writes a candidate task over the top one million Common Crawl hosts. One live exploration loop then converts a generic proposal into a task grounded in the current site. A learned judge scores a full browser trajectory, and exact-success filtering converts that score into an SFT selection decision.

This produces an unusual data object boundary. The publicly reusable object is a website-disjoint task row; the training object described by the paper is a multimodal, environment-grounded episode with reasoning, actions, screenshots, HTML/DOM state, and terminal judge output. Treating these as separate release units is essential: a task dataset can support new collection, but it is not the claimed reasoning corpus.

AgentTrek is the closest Atlas comparison because it also creates live-browser trajectories and filters them with an LLM judge. AgentTrek grounds behavior in externally mined procedural tutorials; InSTA begins with ranked sites and lets an LLM propose and refine tasks after exploration. Both expose the same audit dependency on changing sites, learned success judgments, and missing failed-trajectory releases.

The directional value is showing that host-scale task sourcing and live execution can train a small web agent, while the audit lesson is that increasing site count also increases unresolved safety, side-effect, privacy, copyright, and version-control obligations. Before reuse, researchers must check exact data unit, public release surface, action safeguards, judge calibration, website snapshotting, rights, and row-to-run lineage rather than relying on the 150K label.
