Inputs are the top 1,000,000 hosts from Common Crawl's April–June 2024 host PageRank file. A pretrained task proposer receives only the target URL, in-context examples, and safety instructions. It returns either an initial task or `N/A`. The exclusions cover harmful or mature content, APIs and CDNs, account, login, social and forum flows, purchases, posting, personal information, downloads, and web-state changes. The paper reports filtering about 85% of candidates and retaining exactly 146,746 v2 tasks rather than exactly 150,000.

For grounding, a Chromium browser controlled by Playwright attempts the initial task. The observation processor converts live HTML to compact Markdown while the run-local pipeline can also preserve current URL, raw HTML, screenshot, and DOM metadata. The model emits reasoning followed by a JSON Playwright function call; invalid parses are retried. Context retains the latest five observations and actions, with a 2,048-token observation budget, up to 1,024 new tokens for proposer, agent, and judge outputs, and at most 30 browser actions.

One exploration trajectory is fed back to the task proposer. The refinement output can contain a harder `proposed_task`, steps, criteria, and rationale grounded in the recently observed site. This one-loop proposer-agent scaffold is not tree search. Sampling uses temperature 0.5 and top-p 1.0; row-level proposer model, endpoint revision, source timestamp, random seed, retry history, and decoding provenance are not published.

For rollout and verification, LLM agents interact with live sites through broad Playwright access. The success judge reads the task and recent observation/action history, produces a rationale, and returns success, efficiency, and self-correction scores. A success score above 0.5 is used when reporting judge-validation accuracy; the SFT data filter is stricter and retains only success exactly 1. Safety comes from the initial `N/A` decision. Feasibility is assessed in a separate human study and is not a production label attached to all rows.

The demonstrated SFT experiment collects 20K trajectories with Qwen3-235B, retains 10.5K judged successes, and fully fine-tunes Qwen3-1.7B for one epoch with Adam, learning rate `5e-5`, batch size 32, BF16, maximum sequence length 16,384, and 1% linear warmup. The scaled v2 narrative separately uses a fine-tuned Qwen3-1.7B to run approximately one trajectory per task and Qwen3-235B as judge, averaging about 15 steps and reporting 2.2M screenshots and action traces.

Public output stops before the rollout stage. V2 revision `b62e25283471513e3497b973122cceb9b420e0e4` has 143,811 train plus 2,935 test task rows; v3 revision `5a689ac657a24b0e55b1c0a0d690acfadd443c38` has 143,508 train plus 2,933 test rows with a richer task schema. Both splits are website-disjoint, but there is no row migration ledger, semantic decontamination audit, trajectory/failure release, or checkpoint mapping.

A reproduction must pin arXiv v2, the Common Crawl input and hash, code commit `b2386fcf2cdb054bb0e422ed233fd2bee8877393`, the chosen dataset revision, prompts and model endpoints, browser/container and dependencies, locale and network state, PII configuration, random seeds, retries, task and rollout IDs, judge decisions, SFT subset, and evaluation time. Without live-site snapshots, an exact historical replay remains impossible even with the released code.
