The main online-RL prompt mixture is reported as approximately 8,000 MATH level-3-to-5 queries following SimpleRL plus 40,000 DeepScaler samples. The official Hugging Face repository contains `SimpleRL-simplelr_qwen_level3to5.train.parquet`, its test counterpart, `DeepScaler.train.parquet`, `DeepScaler.aime.parquet`, and five aligned evaluation Parquets. Because the dataset card has no usable YAML configuration, the default viewer presents only 3,120 evaluation records as one auto-derived `train` split: AIME 60, AMC 166, MATH 1,000, MINERVA 544, and OlympiadBench 1,350. These viewer rows should not be mistaken for the online rollout corpus.

For online generation, the current Qwen2.5-7B base policy receives a query root and decodes fixed-length segments through veRL with a vLLM backend. The tree maintains an active prompt queue, shared prefix tokens and KV cache, current depth, per-node branching budget, and completed paths. The in-memory `DataSampleTree` records identifiers and ancestry through `tree_idx`, input and full response token IDs, per-token and cumulative log-probabilities, `finished_reason`, status, and token counts per step. Trainer-facing tensors contain prompts, responses, input IDs, masks, and positions, while non-tensor fields retain `tree_idx`, finish step, and fallback counters for the collected terminal samples.

A segment stops when it emits EOS or reaches its segment-token limit. A path can terminate when it produces a legal boxed answer, reaches EOS, triggers repetition detection, reaches the maximum depth, or reaches the response-token limit. The released helper treats a 32-character substring repeated eight times as repetition. That threshold is an implementation detail verified in code; the paper itself describes repetitive-substring stopping without publishing those exact numbers.

Tree construction uses a per-node branching budget and a target width. The reported online settings explore depth-by-segment pairs `28x256`, `14x512`, and `7x1024`, with maximum width 16 and binary branching at each depth. Initial divergence may be fixed or sampled from 2 through 8. The released principal recipe selects `14x512`, width 16, fixed step divergence 2, initial divergence up to 8, and a 7,168-token response limit. Budget is redistributed among active paths. If active paths are exhausted before width trajectories are available, depth-first fallback chooses eligible stopped candidates; the paper requires a formatted answer or EOS, while the released code exposes several configurable fallback policies.

Each terminal trajectory receives a rule-based final-answer reward by comparing its boxed result with the released ground truth. There is no learned judge in the reported mathematics setup and no label that establishes the correctness of intermediate segments. Root query groups whose rewards are all correct or all wrong are dynamically rejected because they have no reward variance. The paper reports sampling up to three times the 512-query batch to retain 512 informative groups and uses 16 trajectories per query for online training and validation.

TreePO then divides each trajectory according to its shared-prefix ancestors. For every induced descendant subgroup, it computes reward minus subgroup mean; the trajectory's hierarchical advantage is the simple average over its ancestor-level subgroup advantages, followed by global variance normalization. Subgroup-size weighting and rejection of all-positive or all-negative subgroups are reported as ablations, not as the selected method. The policy objective is a DAPO-modified GRPO setup with token-mean loss, clip bounds 0.2 and 0.28, no KL reward or loss, learning rate `1e-6`, 10 warmup steps, batch size 512, gradient clipping 1.0, FSDP, and up to 20 epochs in the released script.

The released script additionally sets temperature 1.0, top-p 1.0, and top-k -1. The paper's 16-rollout shared-prefix illustration uses temperature 0.8, so the values belong to different experimental contexts. More importantly, the paper says that training-batch formation permits at most two additional sampling batches, whereas the released script sets `algorithm.filter_groups.max_num_gen_batches=10`. The official sources do not reconcile this 2-versus-10 difference or bind each reported table to an immutable run manifest.

The main training setup reports 64 GPUs, but not the GPU model. Separate offline efficiency experiments use one H100 80GB at 60% utilization, 64 prompts, 64 rollouts per prompt, no tensor or data parallelism, and a 7,000-token per-trajectory budget with depth times segment length fixed at 7,000. Evaluation uses AIME 2024, AMC 2023, MATH500, MINERVA, and OlympiadBench, with 16 rollouts and majority-vote accuracy; the reported metric is estimated over 1,000 sampling repetitions.

Release and construction must remain distinct. The Apache-2.0 GitHub repository includes the veRL/vLLM implementation, launch recipe, scripts, tests, and version notes. The Hugging Face collection includes `TreePO-Qwen2.5-7B`, fixed-divergence and heuristic variants, and `TreePO_data`. The public dataset schema contains `data_source`, a two-message `prompt`, `ability`, `reward_model.{ground_truth,style}`, and `extra_info.{index,split}`. It contains no generated reasoning trace, tree edge, per-branch reward outcome, pruning decision, fallback lineage, or rejected-query record.
