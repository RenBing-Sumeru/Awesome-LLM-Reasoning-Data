Online RL for mathematical reasoning commonly draws several complete responses independently for each query. That organization is easy to implement, but every response recomputes the same prompt and often a long common reasoning prefix. As rollout counts and token budgets rise, redundant prefix work becomes a material part of the training and test-time inference cost.

Independent trajectories also hide useful structure from the optimizer. They provide a set of terminal responses and answer rewards, but do not directly encode which responses share an early decision, where they diverge, or how a reward difference should be attributed to a shared segment. Standard group-relative outcome objectives therefore compare whole responses while leaving the topology of their generation unused.

TreePO studies both problems together. It asks whether a query can be expanded as a tree of fixed-length response segments, with branches sharing prefix KV cache, and whether terminal correctness can be converted into advantages relative to ancestor-defined subgroups. The target is not merely more search: it is a rollout substrate whose computation and credit assignment both follow the same tree.

The data question is consequential for this atlas. A runtime tree can support efficient generation and policy updates without becoming a reusable release. Auditing TreePO therefore requires separating the operational tree used during online RL from the public Hugging Face prompt/reward tables and from the released checkpoints. The official release confirms the latter artifacts, but it does not provide the complete paper-run trees or all branch, pruning, fallback, and query-rejection records.
