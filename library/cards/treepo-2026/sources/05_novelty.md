TreePO's distinguishing move is to make one shared-prefix tree serve two roles at once. It is an inference structure that avoids repeated prefix computation, and it is an optimization structure that defines hierarchical comparison groups for outcome-reward credit assignment. The contribution is therefore the coupling between rollout topology, compute reuse, and policy advantage—not tree-shaped generation by itself.

Compared with independent group sampling, the method preserves the shared decisions that relate terminal trajectories. Compared with a tree used only for test-time search, it feeds ancestry into online policy optimization. Compared with step-supervision methods, it does not require an external label for each reasoning step; it derives segment-sensitive trajectory advantages from terminal correctness and the descendant sets induced by shared prefixes.

The branching and fallback contract is also part of the contribution. Fixed segment lengths make shared computation explicit; width and depth give separate control over the number and shape of trajectories; budget transfer and fallback try to fill the terminal batch when branches finish early. These choices expose a concrete data-construction substrate whose behavior can be inspected in the official code.

The novelty claim should remain bounded. TreePO does not establish a general-purpose process verifier, and it does not release a new branch-complete trace dataset. Its public data contribution is a prompt/reward repository aligned with the method and evaluation, while the richer tree data object exists mainly at runtime. The work is most distinctive as a construction and optimization recipe whose complete lineage would need additional release engineering.
