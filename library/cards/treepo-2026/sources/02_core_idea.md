TreePO replaces a batch of independently decoded responses with a query-rooted tree. The root is the mathematical query; each non-root node is a generated response segment; and root-to-leaf paths are terminal textual trajectories. Width controls the target number of completed trajectories, depth controls the maximum number of segment steps, and segment length controls the maximum tokens decoded at one step. Branches that share a prefix reuse its KV cache instead of recomputing it.

The tree is also the feedback object. Each terminal path receives a programmatic answer-level correctness reward against the ground truth. For a trajectory, every ancestor induces a subgroup consisting of descendant terminal paths that share that prefix. TreePO subtracts the reward mean of each such subgroup, averages the resulting subgroup-relative advantages across the trajectory's ancestors, and applies global variance normalization. This is trajectory-value supervision derived from outcome rewards; it is not a process verifier that certifies each reasoning segment.

Branching is budgeted rather than unlimited. The algorithm allocates branch capacity over active paths, transfers unused capacity, stops paths on answer formatting, EOS, repetition, depth, or response-length conditions, and invokes fallback only when no active path remains before the target width has been collected. Thus branch allocation, stopping, and fallback are part of the construction contract, not incidental implementation details.

The official artifacts expose three different data surfaces. The Hugging Face dataset publishes prompts, ground-truth reward fields, and metadata; its default viewer shows 3,120 evaluation rows. The runtime `DataSampleTree` and trainer-facing objects carry ancestry, tokens, log-probabilities, stop status, step lengths, and fallback counters. The optional persisted diagnostics flatten terminal input/output pairs and aggregate statistics, so they do not preserve enough lineage to reconstruct the complete tree or every discarded decision.
