ITBench's core contribution is to bind an IT task specification, provisioned operational state, tool-mediated agent episode, and domain-specific success check into one auditable evaluation contract. The benchmark runner selects a scenario, provisions a testbed, deploys it, injects the triggering condition, passes an environment manifest to the agent, records interaction, evaluates the terminal output/state against ground truth, deletes the scenario, and aggregates results.

The interaction is modeled as a POMDP. The agent chooses actions from prior observations/actions; an observation proxy exposes only partial system state; and the action set combines domain tools with a stop action. In the SRE example, the substrate includes Kubernetes, OpenTelemetry Astronomy Shop, Grafana, Loki, Jaeger, Prometheus, and fault mechanisms. SRE/FinOps agents query traces, metrics, logs, Kubernetes, and summarization interfaces; CISO agents generate and execute Kyverno, OPA Rego, or scripts through GitOps-style access.

The feedback contract separates **termination** from **success**. The agent stops at `t*`, but success is a separate predicate comparing the next/terminal state or structured output with the desired outcome and scenario ground truth. Paper-era evaluation combines environmental/programmatic checks and domain metrics. The later trajectory release adds a mixed contract: inspected `judge_output.json` identifies `GCP/gemini-2.5-pro` for semantic diagnosis judgment alongside entity precision/recall/F1, propagation-chain, alert-completeness, fault-localization, and ranking calculations. This later judge must not be projected backward onto every paper result.

Relative to static IT QA or incident reports, the change is that diagnosis, mitigation, compliance, and cost-control tasks are executed against stateful testbeds rather than judged only from text. Relative to other interactive-agent benchmarks, the distinguishing scope is three operational IT domains plus explicit domain ground truth and tooling. Provisioning, CrewAI/ReAct loops, Kubernetes telemetry, programmatic metrics, and LLM judges are not individually new; the reusable direction signal is their versioned coupling into a scenario/episode/evaluator object.
