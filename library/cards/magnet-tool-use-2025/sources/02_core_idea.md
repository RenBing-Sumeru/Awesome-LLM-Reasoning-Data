MAGNET's contribution is to convert a graph-derived function-signature path into a multi-turn query/reference-call sequence, then convert that sequence into positive and negative agent trajectories. Functions are nodes; a directed edge means one function's output is relevant to another's input. Merge, Insert, and Split modify initial paths to cover short/nested dependency, long dependency, and missing-function/parameter cases. (Paper §§3.3-3.4)

The feedback contract is mixed. First, selected StableToolBench functions are simulation-tested for executability and references are executed to obtain outputs. Second, Gemini-1.5-pro-002 supplies positive trajectories while being shown correct reference-call hints. Third, ten SFT trajectories per instance are inspected turn by turn by Gemini-1.5-pro-002; an action judged inconsistent with the reference and assigned an error type becomes a misleading hint used to sample a negative trajectory. The paper's keyword filter adds a coarse syntax/execution signal. (Paper §§3.4-3.6; Appendix A)

This observes function interfaces, reference-call outputs, and a teacher's reference-relative error judgment; it does not establish that a complete natural-language trajectory is faithful, safe, or optimal. The nearest baselines generate calls/queries from random APIs or distill teacher trajectories directly. MAGNET's narrower change is to make dependency-path construction and hint-conditioned positive/negative trajectory generation explicit. It is a data-and-environment construction recipe, not a new public verifier or benchmark. (Paper §§2-3)
