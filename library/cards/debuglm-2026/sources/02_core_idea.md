DebugLM converts provenance from external documentation into supervised fields inside post-training records. Every source receives a dedicated single-token tag. For each instruction-response pair, an ordinary variant retains the original answer, while a diagnostic variant adds the paper's DEBUG trigger to the input and appends the source tag to the target. A weighted objective trains both modes so ordinary use need not expose the diagnostic field.

The same tag vocabulary also defines a control channel. A remediation example pairs a record with a sampled quarantine tag. If that control tag equals the record's true source, the target is a standardized refusal; otherwise the target remains the ordinary answer. At deployment, a developer can request source reporting or ask the model to suppress behavior associated with one labeled source.

The resulting feedback contract is label-based rather than execution-based. Provenance supervision comes from known dataset membership, and remediation supervision comes from an equality test between the source tag and control tag. The paper reports no executor, runtime observation, patch verifier, or environmental reward for deciding whether a debugging step repaired a failure.
