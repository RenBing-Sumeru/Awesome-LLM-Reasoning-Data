1. **Define refreshable tasks.** Input recent competitions, publications, news, code, and tabular sources plus task generators; construct difficult questions in mathematics, coding, reasoning, language, instruction following, and data analysis. Output task records with source dates.
2. **Attach objective checks.** Give each task a ground-truth answer, executable test, or task-specific metric; reject tasks that require an unconstrained LLM judge for the core score. The checker determines when a response counts as correct.
3. **Freeze a release.** Package 1,000 questions over 18 tasks and six categories in the paper version, with prompt and scorer versions. A model result must name this release rather than only saying “LiveBench.”
4. **Run and aggregate.** Generate model responses under pinned endpoint and decoding settings, score each with its task checker, then aggregate task and category scores into the overall result. Invalid-output handling and weighting are part of the reproducibility contract.
5. **Refresh without erasing history.** Periodically replace roughly one sixth of the questions with newer material and publish a new dated release. Preserve old versions so score drift can be separated from model change.
