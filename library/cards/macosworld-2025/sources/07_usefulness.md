For `environment_agent_trajectory_data`, macOSWorld is an evaluation-environment recipe: preserve task ID, instruction language, AMI/snapshot ID, preparation command, macOS/app versions, screenshot sequence, normalized VNC actions, conversation history, terminal status, grader output, and safety outcome. Recording both successful and failed episodes against the same pinned task object would support trajectory failure analysis, grounding diagnostics, and environment-version studies.

For `benchmarks_evaluation_surfaces`, the task-specific AppleScript/JavaScript/zsh commands are concrete examples of terminal executable feedback. Researchers can audit each predicate for false positives, false negatives, partial-credit loss, version brittleness, and gaming, then compare binary success with a separately designed fine-grained reward without treating the latter as part of this paper's release.

The 29-task safety subset supports controlled analysis of context deception if all three outcomes—`gold`, `distracted`, and unhandled—remain separate and are joined to ordinary task success only at analysis time. Multilingual variants can test whether prompt language and localized interface jointly change planning and grounding, but language comparisons should control application coverage and right-to-left layout.

The current reuse class is **evaluation and audit only**. Direct training reuse is blocked pending an immutable trajectory manifest, clear train/evaluation partitioning, decontamination checks, evaluator-error analysis, record-level provenance/rights, and a versioned bundle linking task JSONs, AMIs, applications, model adapters, and results. The paper's benchmark scores motivate those audits; they do not certify the data object.
