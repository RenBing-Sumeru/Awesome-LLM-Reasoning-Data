**Inputs and task construction.** Annotators wrote English tasks from the OSWorld/WindowsAgentArena taxonomy, macOS counterparts, and official Apple tutorials/templates. GPT-4o translated supported tasks into Chinese, Arabic, Japanese, and Russian; Google Translate round trips checked consistency. One month later, annotators re-performed every task within 20 user steps. The release has 202 main task JSONs: advanced 30, file management 29, media 12, multi-apps 29, productivity 35, system/interface 29, and system apps 38. Twenty-nine English tasks were randomly sampled for safety and paired with unique manually authored deceptive dialogs (Paper §4; repository `tasks/`).

**Reset and preparation.** Paper experiments use macOS Sequoia 15.2 on AWS EC2 dedicated Mac mini hardware. Before a task, AWS mode replaces the root volume with the language-specific AMI, then runs the task `pre_command` through SSH; the repository's VMware/community path can instead revert a snapshot. Recovery and error-free preparation can be manually overridden. The authors state that snapshot restoration discards post-task content, files, and system changes, but this property was not independently executed for this Card (Paper §§3.3–3.4, Appendix B–C; `constants.py`, `utils/run_task.py`).

**Interaction and observation.** The agent receives the instruction and a full-screen 1024×768 screenshot, emits VNC mouse movement/click/drag/scroll or keyboard typing/key presses, then observes the next screenshot. Experiments retain full conversation history but expose only the three most recent screenshots, except model-specific ShowUI handling. The loop stops when the agent status is no longer `unfinished` or the horizon is exhausted: up to 15 screenshots or 30 dialog turns in the paper, with a released default of 15 steps and 120 seconds per step (Paper §3, §5.1, Appendix G; `testbench.py`, `utils/run_task.py`).

**Feedback, selection, and outputs.** After interaction, one or more task-specific AppleScript, JavaScript, or zsh commands inspect final state through SSH. Reported experiments retain binary outcomes: the final grader assigns 1/0, aggregated as success rate. Safety tasks concurrently execute an injected dialog; `in_process` records the dialog command, injection step, gold labels, and distracting labels, and the checker emits `gold`, `distracted`, or not handled. The runner writes per-task/language result directories with conversation history, `eval_result.txt`, and, for safety, `distraction_result.txt`; no immutable completed-trajectory corpus for the reported runs was found.

**Reproduction boundary.** Reproduction should pin repository commit `e2ca8334b3765537e5c1c428ce57990248a1bb5f`, task JSONs, language AMI IDs, macOS/app versions in Appendix F Table 9, agent adapters/prompts and API versions in Appendix G, step/timeout settings, credentials, and result manifests. No train/dev/test split, decontamination procedure, GitHub Release/tag, fixed AMI/result bundle, or benchmark-wide base model, teacher, temperature, rollout count, and training optimizer is disclosed; the scaffold is evaluation-only.
