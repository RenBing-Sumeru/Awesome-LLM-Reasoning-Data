Intrinsic self-correction asks one model to inspect and revise its own first response without receiving an oracle critique at test time. The paper shows two data-and-optimization failures. Offline SFT learns from correction traces produced by an earlier collection policy, so the trained model may face a different distribution of first-turn errors. SFT and naive multi-turn RL can also collapse toward producing a stronger first answer followed by superficial or no change, rather than learning when and how to revise.

SCoRe studies this problem on math and code. Its central data object is not a static answer pair but an online two-turn episode: problem, first attempt, generic self-correction instruction, second attempt, and a binary outcome reward for each attempt. This belongs in Rollout, Search, and Test-Time Trace Data because the policy that is being trained also generates the attempts, and the same sequential attempt structure is later evaluated as test-time compute. The paper does not release a reusable trace corpus, so the card records the recipe and audit boundary rather than claiming a data release.
