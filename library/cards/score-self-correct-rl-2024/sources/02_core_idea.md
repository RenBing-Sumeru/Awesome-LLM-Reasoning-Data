SCoRe trains on the learner's own two-turn correction episodes instead of fitting a fixed offline repair corpus. At test time, the second attempt sees the first response and a generic instruction to check for an error and rewrite if needed; it does not see the oracle reward, correctness label, or test outcome.

Training has two distinct stages. Stage I creates a non-collapsed initialization: it optimizes reward on the second attempt while using a KL penalty to keep the first-turn distribution close to the base model. Stage II jointly optimizes both attempts and shapes the second-turn reward with `alpha * (r2 - r1)`. The bonus is positive for wrong-to-right transitions, negative for right-to-wrong transitions, and zero when correctness does not change; the reported alpha is 10.

The feedback contract is programmatic and terminal. MATH responses receive a binary reward from ground-truth answer matching, and code receives a binary reward only if all tests pass. These signals label answer outcomes, not intermediate reasoning steps. The online trace plus its two rewards is therefore the reusable conceptual object; reported benchmark accuracy is evidence about the trained policy under the tested setup, not proof that every sampled trace is reliable.
