For math, training uses MATH train augmented with 4,500 problems from the original MATH test set, while the remaining 500 form MATH500 evaluation. Code training uses MBPP and evaluation uses HumanEval; MBPP-R is also used as an offline repair evaluation. Gemini 1.5 Flash is fine-tuned for MATH and Gemini 1.0 Pro for code. The second-turn prompt is fixed and does not reveal whether the first answer is correct.

Each online episode samples a first attempt from the current policy, appends the self-correction instruction, and samples a second attempt conditioned on the full history. The verifier computes `r1` and `r2`: MATH uses binary ground-truth answer matching and code uses whether all tests pass. Stage I optimizes second-turn reward while penalizing KL divergence of the first-turn policy from the base model. Stage II jointly applies REINFORCE-style updates to both turns, with KL regularization and a shaped second-turn reward containing `alpha * (r2 - r1)`. The paper also notes that some experiments add repeatedly sampled base-model first attempts as offline prompts to increase state coverage.

Reported MATH hyperparameters are Adam, learning rate 5e-6, 3,000 steps, batch size 512, sampling temperature 1.0, alpha 10, beta1 0.01, and beta2 0.1. MBPP uses learning rate 1e-5, 1,500 steps, batch size 128, temperature 1.0, alpha 10, beta1 0.01, and beta2 0.25. Evaluation is greedy except inference-compute scaling, which uses temperature 0.7. RL checkpoints are selected by highest training reward. The number of rollouts per prompt, random seeds, exact split manifest, answer-extraction implementation, and test harness are not fully disclosed in a released executable artifact.
