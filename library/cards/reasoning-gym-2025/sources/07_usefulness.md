For the Data Construction and Open Release Recipes track, Reasoning Gym is a reference implementation of an executable construction layer. A builder can reuse its pattern to define a task configuration, generate oracle-bearing prompts on demand, attach a task-specific scalar verifier, combine tasks with explicit weights, expose selected difficulty attributes to a curriculum, and either stream items into RLVR or materialize a frozen snapshot for conventional evaluation.

A responsible RLVR baseline should pin the repository/package and all optional dependencies; serialize task name, configuration, seed, index, mixture weight, curriculum state, native/cascade scorer mode, and reward components; archive the realized evaluation rows; and retain failed, partial-credit, and exception-producing rollouts. Before combining rewards across tasks, test alternative valid answers, oracle-substring attacks, formatting noise, numerical tolerances, malformed strings, timeouts, and dependency-off behavior.

For evaluation, use is conditionally safe only after freezing a generator/scorer revision and a non-overlapping item snapshot. The framework is useful for difficulty curves and capability diagnostics, but regenerated items from mutable `main` are not a stable benchmark. Report accuracy separately from auxiliary format or length rewards and do not compare task scores as if their partial-credit scales were globally calibrated.

For training reuse, the open code is a strong starting point for fresh RLVR, not a ready-made SFT rationale release. Reasoning Gym supplies oracle questions and rewards; a separate policy or teacher must create responses. Any derived SFT or distillation corpus needs its own response provenance, sampling settings, filter, rejected candidates, license review, split, and contamination audit.

Reuse class: **safe as a version-pinned construction and evaluation scaffold after task-level verifier audit; blocked for exact reproduction of the paper's RL experience until the paper-era commit, seeds, realized streams, and rollout ledger are available.** It is also valuable as an audit case showing why executable data require version, dependency, and reward-contract metadata.
