Reasoning Gym's contribution is a common executable interface for broad procedural reasoning tasks: each registered task maps configurable generation parameters to a question, oracle state, and task-aware scalar verifier, and the framework composes these tasks into evaluation sets, weighted mixtures, and optional curricula.

The data object is therefore a versioned generator-verifier execution record rather than only a row ID. At minimum it contains task identity, configuration, seed/index, question, oracle answer, task metadata and difficulty fields; an RL record additionally needs the policy checkpoint, sampled response, native verifier output, auxiliary rewards, mixture/curriculum state, and training step. The public library generates the first layer but does not publish the paper's complete policy rollout ledger.

The feedback contract is answer-level and task-specific. The paper requires every environment to be automatically verifiable and uses an accuracy reward plus, in training curves, a 0.2 format reward; evaluation tables report accuracy alone (Paper §2, §4). A verifier can observe the submitted string or structured solution and the hidden oracle metadata needed by its task. It cannot establish the faithfulness of intermediate reasoning, human-perceived elegance, safety, or cross-task reward calibration. Multiple-solution tasks require task-aware checking rather than a single global exact-match rule.

Relative to fixed GSM8K/MATH-style corpora, the key change is on-demand instance generation with exposed parameters and code. Relative to narrower procedural logic or game environments such as Logic-RL, TextArena, KORGym, and Reasoning Core, Reasoning Gym emphasizes a shared registry spanning many task families and connects it to mixtures, curriculum control, evaluation, and GRPO training. GEM is the closest framework-level comparison in the paper's related work. Procedural generation, automatic verification, curriculum learning, and GRPO are not individually new; the direction signal is their packaging as a reusable, version-sensitive reasoning-data layer (Paper §6).
