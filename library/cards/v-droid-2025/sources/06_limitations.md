- **Release and schema:** the reported 110K pairs are not public. GitHub commit `8d549027634abe65a5721fe6bc3b5e84475db2f6` contains only five `{chosen, rejected}` examples, while task/app/episode IDs, raw states, action sets, scores, entropy, next observations, correction provenance, terminal evidence, failures, and round/split manifests are missing. Pair count cannot substitute for an auditable data object.
- **Verifier ambiguity:** P3 labels every alternative to the selected action as rejected. States can admit several helpful routes, so valid alternatives may become false negatives; conversely, an action judged helpful from current text can later fail. Entropy triage is imperfect and can miss confidently wrong decisions. These are curator inferences from the feedback contract, not measured error rates.
- **Recovery bias:** reverse actions are produced by a fixed mapping rather than a live success verifier. The authors directly observe repeated-back collapse when self-correction data is too prevalent and cap it near 2.5%. The retained mixture may still overrepresent easily reversed errors, while timeouts, abandoned tasks, unrecoverable failures, and unflagged mistakes remain unavailable.
- **Environment and representation drift:** v5 describes Accessibility-Service XML, whereas v1, the five examples, and the HF model card say HTML. Exact preprocessing, screenshots or other UI modalities, emulator and Android versions, app builds, accounts, reset state, credentials, network/service state, timeouts, and benchmark revisions are not pinned. The preview is AndroidWorld-oriented and does not establish complete AndroidLab/MobileAgentBench replay.
- **External-model dependency:** GPT-4 constructs working memory and contributes 3.03 seconds of the reported 4.3-second step latency, yet its snapshot, prompt, decoding, API behavior, retry, and cache settings are unknown. The task-synthesis and action-completion LLMs are also undisclosed. Memory results and latency therefore cannot be replayed from the verifier checkpoint alone.
- **Scaling and evaluation:** the 9K-to-110K curve jointly changes data amount, app/task diversity, annotation mix, human correction, and verifier checkpoint; it does not identify a pure data-scale effect. AndroidWorld is explicitly in domain, and no item-level/semantic decontamination audit is disclosed. Benchmark success is downstream system evidence, not proof of label accuracy, coverage, privacy, or general training-data quality.
- **Versioned claims:** the stable ID ends in 2025, while the final title/year are 2026. The v1/project/README headline says a 9.5-point AndroidWorld margin and 0.7 seconds per step; v5 reports 5.2 points, 4.3 seconds per step, and about 0.7 seconds per decision. Any unpinned summary can mix incompatible claims.
- **Rights, privacy, and artifact safety:** paper CC BY 4.0, project-site CC BY-SA 4.0, and HF model-card Apache-2.0 do not license the GitHub code, five example records, 110K corpus, source tasks, apps, or UI content; code/data license is unknown. Annotator consent, sensitive UI redaction, retention, and privacy review are unknown. The HF release includes PyTorch-serialized `v_head.pth`, whose loading path should be inspected in isolated infrastructure.
