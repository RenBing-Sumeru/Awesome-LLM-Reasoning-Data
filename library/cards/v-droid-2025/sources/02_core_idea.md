In one sentence, V-Droid turns each labeled Android decision state into correct-versus-alternative prompts, trains a generative verifier to assign a scalar helpfulness score to every candidate action, and selects the maximum-scoring action during execution (Paper §§3.2 and 4.1, Figs. 4–5).

At a state, Android Accessibility Service supplies the current textual UI representation and rules extract click, long-press, scroll, type, and clear actions; default actions add open app, wait, home, back, complete, and answer. The prompt given to the verifier combines role, user goal, working memory or action history, UI state, instruction, and one candidate-action question. Rather than decoding an explanation, the model uses first-token logits or probabilities, followed by an MLP head, to produce the candidate's score. Open-app, type-text, and answer still require a separate LLM completion after selection (Paper §3.1–3.2, p. 4).

The feedback contract has three distinct layers. First, a human or the current V-Droid round labels one action as correct at each trace step. Second, P3 treats that action as `chosen` and each other extracted action as `rejected`, training the score difference with a logistic pairwise objective. Third, the deployed agent is judged by each benchmark's terminal task-success contract. The learned score can observe only goal, history/memory, current UI text, and the candidate; it cannot see the future state or terminal success when scoring. Thus it is process feedback correlated with helpfulness, not an executable proof of correctness or direct environment reward.

The self-correction component deliberately visits an erroneous state by executing a wrong action, maps that action to a reverse action, and pairs the reverse action against alternatives. The authors report that too much such data collapses behavior toward repeated back actions, so erroneous states are randomly sampled and self-correction pairs are limited to about 2.5% of training data (Paper §4.2, Figs. 6 and Eqs. 5–6).

Relative to AndroidControl, which releases offline human state-action episodes and evaluates reference-action matching, V-Droid uses task sources including that line of work but changes the supervised object to action preferences consumed by an online verifier. Relative to a free-form mobile LLM agent, it constrains the next decision to an extracted action set and amortizes comparison through prefilling-only scoring. It does not introduce the Android benchmarks, Accessibility Service, Llama-3.1, Q-LoRA, or pairwise preference loss; its direction signal is their integration into an iterative trace-to-verifier data loop.
