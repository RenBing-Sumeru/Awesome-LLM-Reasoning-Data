Earlier agent-tuning sets usually serialized text-form tool calls or narrow single-tool demonstrations. CodeActInstruct changes the auditable training object: executable Python actions, observations, tracebacks, and successful revisions remain together in one multi-turn record, with original task metrics deciding terminal success. The ICML acceptance, explicit five-domain mixture, public records, and controlled SFT comparisons are quality signals. What is not new is code generation itself or environment feedback alone; the reusable change is packaging recovery-bearing interactions as training demonstrations. Reuse checks should focus on execution safety, inherited licenses, source/evaluation overlap, and teacher artifacts.
