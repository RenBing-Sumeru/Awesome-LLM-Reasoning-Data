The evidence-backed pipeline is:

1. **Inputs and retrieval substrate.** The paper evaluates ComplexWebQA, GPQA, and FoolMeTwice. It describes about 100K Bing snippets for ComplexWebQA; 80K Wikipedia passages plus 60K Bing documents for GPQA; and about 30K benchmark passages for FoolMeTwice. Each retrieval supplies the top 10 documents. These paper-run corpora are not released as immutable snapshots.
2. **Node expansion.** Qwen2.5-7B or Llama 3.1-8B selects among A1-A6 and generates direct-answer, reasoning, decomposition, retrieval-conditioned, or summary text. Retrieval proceeds through query generation, query execution, knowledge reflection, and summary or integration. Search uses maximum depth 5, at most two subquestions, and concurrent expansion.
3. **Node scoring and backup.** Multiple completions are grouped by answer equivalence. Majority frequency estimates confidence, mean log-likelihood within the majority cluster becomes the reward, and UCT statistics Q and N are updated. The paper does not disclose numeric retrieval-necessity, similarity, early-error, or consistency-pruning thresholds.
4. **Terminal selection.** A branch stops on a valid answer node or a configured depth or preset limit. Semantically equivalent terminal answers are grouped, trajectory node rewards are multiplied and accumulated, and normalized group score selects the final answer.
5. **Budget study.** Four rollouts are the main setting; 8, 12, and 16 are ablations. The paper-run decoding temperature is unknown.

The public code is a generator implementation rather than a frozen execution record. It can write `Final Solutions.json` for terminal solution nodes, `Rollout Solutions.json` for one node per rollout, optional `Potentials.json`, optional recursive text `.tree` files, `args.json`, and aggregate call or token totals. The optional tree printer can display Q, N, V, UCT, node text, and children, but no generated tree or paper-run output bundle is committed. The discriminator computes confidence, survival rate, and combined scores, yet its checked per-problem persistence path keeps correctness booleans rather than those score vectors.

Reproduction also requires resolving implementation parity. The paper describes Bing Search and LangChain, whereas the checked repository retrieval code uses Cohere embeddings, Azure/FAISS paths, external credentials, unshipped indices or evidence paths, and a hard-coded GPT-4o retrieval-query helper. The example script uses FMT, Llama-3.1-8B-Instruct-Turbo, 16 rollouts, and temperature 0.1; parser defaults include 15 rollouts and temperature 0.4. None of those defaults establishes the undisclosed temperature or exact services used for the main four-rollout paper runs.
