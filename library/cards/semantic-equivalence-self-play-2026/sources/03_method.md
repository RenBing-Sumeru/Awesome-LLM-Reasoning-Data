OpInstruct-HSx is constructed by taking prefiltered OpenCodeInstruct self-instruct rows and asking DeepSeek-R1-Distill-Llama-70B to produce Haskell. The released construction code deduplicates generated code strings, searches for a function binding and an arrow type, recursively synthesizes a type-compatible literal for common base/list/tuple types, then invokes GHC and executes the program on that input. Retained rows expose five fields: `code`, `input`, `status`, `output`, and `size`. This establishes minimal executability on one synthesized input; it does not compare the Haskell program with the upstream Python solution.

For self-play, DeepSeek-R1-Distill-Qwen-7B is used for both Alice and Bob. SEQ adds reflection annotations and a generated lemma to a Liquid Haskell module using PLE; acceptance by Liquid Haskell retains the proof trace. SINQ compiles and runs both programs under a subprocess harness on Alice's proposed input; differing outputs, exceptions, or termination behavior are intended as inequivalence witnesses. Bob is sampled ten times after branch verification. Alice training comprises selected raw generations, difficulty-prediction examples, and all accepted SEQ proof traces; Bob training retains correct equivalence judgments.

The main E0 configuration uses 500 references per round, seven rounds, a nominal 50/50 branch probability, temperature 0.6, top-p 0.95, top-k 20, presence penalty 1.5, and a 32,768-token context. Rejection-sampling LoRA SFT uses cumulative retained data. Generation in round \(i+1\) uses Alice's adapter from round \(i\), but each fine-tune is initialized from the original base model; Bob is fine-tuned once after all seven rounds. The paper reports about three days on four NVIDIA L40S GPUs.
