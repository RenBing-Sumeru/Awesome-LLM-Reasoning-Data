The public release is incomplete for reproducing the central training data. OpInstruct-HSx is available, as are pipeline and evaluation files, but the checked repository does not publish the verified per-round SEQ/SINQ records or trained adapters as a clean release. Consequently, one can inspect the recipe and many result artifacts but cannot independently reconstruct the exact retained training mixture without rerunning the expensive pipeline.

Lineage is weak at the released-row level. The five fields omit the OpenCodeInstruct identifier, original instruction, Python solution, translator prompt/output, model revision, and rejection path. A single successful generated input proves only that the translated Haskell program ran once. It does not prove translation fidelity, broad functional correctness, or equivalence to the upstream program. Exact-code split deduplication does not address paraphrased or semantically equivalent leakage.

Liquid Haskell covers a restricted fragment. Reflection and PLE do not readily handle nontermination, partial functions, unreflectable code, large algebraic rewrites, state, memory, or bit-level behavior. This restricts both what can be labeled positive and what learned behavior should be expected to transfer. The main run's 34/1,750 SEQ yield makes the resulting class and verifier mixture highly imbalanced.

Reproducibility details conflict across official artifacts: the paper states a main threshold of 3, the inspected example run script passes 1, and the CLI default is 5. Moreover, `SEQ.py` appends generation examples to the candidate pool only when difficulty already meets the threshold, then later divides that pool into hard and easy subsets; the easy generation subset is therefore empty in that path, making the advertised 20%-easy sampling unreachable. Package versions and an immutable environment are also not fully specified. These issues warrant `partial` status and must not be silently resolved by guessing.
