The prior-work baseline is a static capability benchmark: a finite set of prompts or tasks is repeatedly administered, so answers can enter training data and leading models can approach the benchmark ceiling. Agent Island changes the evaluation object from a fixed item response to a multiplayer episode in which other evaluated models generate the changing context, opposition, alliances, votes, and terminal outcome.

The concrete data contribution is a structured seven-player trace with visibility boundaries. Private sidebars, public pitches, private votes and rationales, changing active/eliminated sets, parser outcomes, and a final jury winner remain connected inside one log. This makes social behavior and feedback inspectable at state/action and full-episode granularity rather than reducing the run to a scalar score. The frozen manifest, Croissant metadata, direct log URLs, hashes, and replication pipeline add release identity around that object.

The feedback-interface change is equally specific. Adaptive agents act as both environment participants and voters; programmatic parsing and tallying convert their judgments into a terminal winner; Bayesian Plackett-Luce converts winner/player-set records into a posterior ranking with uncertainty. This is not an objective correctness verifier. It also does not attach quality labels to reasoning steps, distinguish truthful from deceptive persuasion, or turn the winner into a training reward.

Agent Island does not newly invent multiplayer games, private/public messaging, voting, random tie breaks, or Plackett-Luce ranking. Its directional contribution is their integration into a versioned evaluation corpus and a continuing benchmark that avoids a finite answer bank. Scale alone is not the novelty: the frozen set has 999 games, while the live source can grow. The important audit consequence is that the paper corpus and live leaderboard become distinct versioned objects with different counts and even different score presentation.

For the assigned track, the useful signal is that an agent benchmark should release observation visibility, action/parser fields, environmental transitions, terminal predicates, failure retention, and immutable version bindings—not only scores. Before reuse, researchers must still verify matchup/schedule effects, tie sensitivity, parser failures, model/API drift, exact generator versions, excluded attempts, license boundaries, and whether a live snapshot is being mistaken for the paper set.
