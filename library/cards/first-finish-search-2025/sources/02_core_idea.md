FFS launches n independent stochastic decodings and returns the first trace that emits EOS; all other traces are discarded. In synchronous FFS, one model copy advances a batch in lock-step, so the first EOS is also the minimum generated length. In asynchronous FFS, n jobs run independently and the first job to finish or hit the maximum length wins, after which the rest are interrupted. The paper expresses the selector as a negative-length reward, but this is a heuristic objective rather than evidence of correctness.

There is no reward model, judge, execution verifier, or majority vote in the selection loop. The only online feedback is the terminal event and the system clock or decoding step that determines which trace finishes first. Ground-truth exact match is used later for evaluation. The closest comparisons are standard decoding, budget forcing, beam search, majority voting/self-consistency, and the paper's last-finish control.

The category fit is Rollout, Search, and Test-Time Trace Data because selection depends on a set of sampled trajectories and their completion order. It is also a cautionary example: a trace filter can raise benchmark accuracy for some reasoning models while encoding a strong length bias. A reusable record must preserve both the winning and cancelled traces; retaining only the winner hides the selection mechanism and prevents counterfactual comparison.
