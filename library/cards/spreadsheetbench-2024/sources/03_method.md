Inputs are a self-contained natural-language instruction, one or more `.xlsx` input files, metadata such as instruction type and answer position, and a model or agent allowed to produce code-like spreadsheet operations. Outputs are transformed spreadsheets and per-test-case pass/fail records.

The construction pipeline starts from solved ExcelForum, Chandoo, MrExcel, ExcelGuru, and related real spreadsheet questions. The authors filter for solvable spreadsheet-manipulation problems, rewrite forum context into standalone instructions with GPT-4, manually check the instruction and answer position, and build extra spreadsheet variants so one instruction can be tested against multiple files. The evaluation pipeline applies the generated solution to each input workbook and compares the selected output ranges against gold answer workbooks. Soft restriction reports partial test-case success; hard restriction requires all test cases for the instruction to pass. Multi-round experiments add ReAct-style code execution feedback for up to five rounds.

Reproduction must pin the dataset archive, evaluator revision, spreadsheet engine, formula recalculation method, Python/OpenPyXL behavior, numeric/date normalization, and whether LibreOffice or Windows Excel is used to refresh cached formula values. The released artifacts to audit are the paper, NeurIPS page, project page, GitHub code/evaluator, and Hugging Face data package.
