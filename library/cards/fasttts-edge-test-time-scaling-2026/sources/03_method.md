The system adds Speculative Beam Extension to the normal beam-search loop. During a generation step, a completed beam may become a speculative candidate according to the prior verifier score; as standard beams finish, available batch slots are filled with its possible future tokens. The system verifies only the ordinary beams, then selects and duplicates them as usual. Speculative tokens are truncated on the duplicates, so the verifier-guided search has the same logical decision path while straggler time is overlapped with potentially useful generation.

FastTTS also uses a two-phase, preemptible scheduler. It first batches active beams continuously within a request, then switches to speculative execution only when no queued standard beams remain; new requests immediately preempt speculation. Dynamic Prefix-Aware Scheduling groups beams with common prefixes to raise KV-cache reuse. Finally, Asymmetric Multi-Model Memory Allocation profiles the generator and process reward model separately and assigns more cache memory where it most improves end-to-end goodput. The implementation is a plug-in layer on vLLM for models of at most seven billion parameters on a 24 GB GPU.
