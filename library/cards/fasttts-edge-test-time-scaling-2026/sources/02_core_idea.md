FastTTS views verifier-guided reasoning as an iterative generation-verification loop over a dynamic tree. That view reveals three system-level opportunities. First, when some beams finish early, their unused execution slots can generate a carefully chosen amount of future work instead of waiting for the longest beam. Second, beams sharing a reasoning prefix should be scheduled together while that prefix remains in the KV cache. Third, the generator and verifier should not receive equal memory by default because decoding and verifier prefilling have different memory-throughput curves.

The key design constraint is algorithmic equivalence. Speculative work must not change which non-speculative beams the original search would select. The system therefore uses previous verifier scores as a cheap proxy for which completed beams are likely to survive, performs speculative extension only in otherwise idle slots, and truncates speculative tokens before ordinary branching. Scheduling and memory allocation then reduce overhead around the search instead of silently replacing the underlying reasoning policy.
