Correctness is only as strong as the validated GT and metric implementation. A model may solve a data-science task in a semantically valid way that fails if the expected output format, aggregation rule, or tolerance is too narrow. Human verification improves GT quality but introduces protocol and annotator-decision boundaries that must be documented. Execution scores can drift with library versions, randomness, hardware, and timeout policy. Public release creates contamination risk. The benchmark should not be treated as a training reward source unless metric code, data rights, and unsafe code-execution controls are separately audited.
