The prior baseline is a benchmark with a single task type, easy ground truth, and direct metrics. DataSciBench changes the construction process by handling uncertain GT and task-specific metrics through semi-automated generation plus human verification. It also changes scoring by representing evaluation as Task-Function-Code rather than one global answer comparison. The direction signal is useful for agent evaluation because many data-science tasks need code execution, aggregate metrics, and validated GT. The quality signal is the explicit metric-validation pipeline. What is not new: code execution, aggregate metrics, and human verification are existing components. Reuse requires checking dataset license, data provenance, metric correctness, GT ambiguity, package drift, and whether tasks have leaked into training data.
