The official NeurIPS 2025/OpenReview record, arXiv v4 paper, MiniMax-AI GitHub repository, and MiniMaxAI Hugging Face dataset are the primary sources for this Card. The paper is a NeurIPS 2025 poster. The arXiv record is 2505.19641, and the public repository identifies itself as the official implementation.

RL with verifiable rewards has concentrated on mathematics and code because those domains provide answer checkers, unit tests, and relatively direct binary outcomes. SynLogic addresses a narrower construction gap: how to create a broad logical-reasoning prompt pool whose quantity and difficulty can be controlled and whose final answers can be checked by task-specific rules. The work does not claim that one universal verifier covers logic. It manually encodes different generators, parsers, constraints, and verifiers for tasks such as Sudoku, Cryptarithm, Dyck Language, ARC-AGI, and Zebra Puzzle.

The public data object is a verifier-ready prompt record, not a completed demonstration. Hugging Face exposes Easy and Hard configurations with task identity, one user-role prompt message, an ability label, reward-model fields, and serialized task state in `extra_info.game_data_str`. During RL, the policy generates 16 responses per prompt online; those accepted and rejected responses, reward outcomes, and training-step decisions are not released. Consequently, the release supports rerunning verifiers and new RL, but it does not reproduce the paper's exact rollout corpus.

Configuration identity is part of the decision boundary. SynLogic-Hard covers all 35 tasks. SynLogic-Easy removes eight tasks that remained at zero 7B training accuracy after difficulty reduction and therefore covers 27. The current release contains 15,837 Easy training rows plus 270 validation rows and 32,840 Hard training rows plus 350 validation rows. A statement that "SynLogic has 35 tasks" describes the framework and Hard configuration, not the Easy training surface.

The work belongs in both `programmatically_verifiable_outcome_data` and `data_construction_open_release_recipes`: it publishes rule-checked answer records and an executable construction/reward interface. Its L4 value comes from the explicit data object, task-specific feedback contract, difficulty calibration, optimizer settings, and release audit. Benchmark gains motivate the recipe but do not certify record quality, verifier reliability, provenance, or contamination safety.
