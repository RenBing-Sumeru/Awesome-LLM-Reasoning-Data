SynLogic's central unit is a generator-verifier pair. The authors select 35 task concepts, identify task-specific difficulty parameters, encode constraints in generation code, formalize each instance into natural language, and dispatch a model answer to the corresponding verifier. Thirty-three task families are independently implemented and generated; Zebra Puzzle and ARC-AGI records are adopted from existing open resources. All 35 released task identities have verifier mappings, although the current repository lacks the Cipher question generator reported in an open issue.

Difficulty is calibrated with model solvability rather than a single handcrafted level. DeepSeek R1 and OpenAI-o3-mini set an upper bound at the highest parameter setting for which pass@10 remains above zero. Unspecified chat models set a lower bound at settings with pass rate between zero and 0.5. These models are difficulty probes, not disclosed trace teachers. The exact checkpoints/endpoints, complete prompts, seeds, and decoding settings for this calibration are unknown.

The public record schema contains `data_source`, `prompt`, `ability`, `reward_model`, and `extra_info`. `prompt` is a one-message list with `role` and `content`. `reward_model` exposes `answer`, `solution`, and `style` fields, but public examples and issue discussion show that these fields may be empty. Official training guidance says reward calculation should load `extra_info.game_data_str`, a serialized task object containing fields such as question, answer, difficulty, and task metadata. The answer may itself be represented differently across tasks, including inside metadata.

The feedback contract is a product of format and correctness. The paper assigns reward 1 only if the response contains the required think/answer structure and its final answer is correct under the task verifier. The repository reference implementation is stricter: the response must start with the opening think tag, end with the closing answer tag, contain each of the four tags exactly once, and then pass the selected verifier after answer extraction. Any failed component makes the final reward zero.

This is answer-level supervision with a binary scalar reward, not step supervision. A successful final answer does not label intermediate reasoning steps, and programmatic acceptance is not evidence that the written reasoning is faithful. The released prompts and verifier state also omit the online responses and reward decisions that actually drive GRPO, so the feedback contract is inspectable but the paper's training trajectory is only partially auditable.
