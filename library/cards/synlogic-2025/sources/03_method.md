Task sourcing begins from two groups: recognized puzzle types from logic communities and task concepts appearing in evaluation suites such as BBH, BBEH, and KOR-Bench. The paper adds other puzzle families, including Mathador and Minesweeper. For each task, the authors identify parameters such as grid size, missing values, density, or constraint count; manually implement rules; generate instances; apply automated correctness and solvability checks; and render task-specific natural-language prompts.

Difficulty control has two model-based bounds. The upper boundary is the most difficult parameter setting still solved at least once in ten attempts by DeepSeek R1 or OpenAI-o3-mini. The lower boundary uses unspecified chat models and retains parameter settings with pass rate above zero and at most 0.5. SynLogic-Hard uses the broader difficulty range for Qwen2.5-32B-Base. After difficulty reduction, Arrow Maze, Goods Exchange, Kukurasu, Minesweeper, Norinori, Object Counting, Space Reasoning Tree, and Wordscapes still produced zero 7B training accuracy and were removed from SynLogic-Easy.

At Hugging Face revision `bb4297b82b9c28ef39249f48386cefd5e856618a`, Easy has 15,837 train and 270 validation rows across 27 tasks; Hard has 32,840 train and 350 validation rows across 35 tasks. Validation contributes 10 records per included task. Training counts vary by task rather than being a uniform fixed quota. Each row provides the prompt and serialized verifier state, not a target reasoning response. The current public release does not expose policy rollout text, reward logs, rejection reasons, or a deterministic ledger linking a prompt to the 16 sampled responses used at each RL update.

The paper trains Qwen2.5-7B-Base on Easy and Qwen2.5-32B-Base on Hard with DAPO-adapted GRPO. The main runs use prompt batch size 128, group size 16, maximum prompt length 2,048, and 16 rollouts per prompt. The 7B run uses learning rate 1e-6, mini-batch 64, and maximum response length 16,384; the main 32B run uses learning rate 2e-6, mini-batch 16, and maximum response length 28,672. Both report clip-high 0.28 and clip-low 0.2. Sampling temperature is unknown.

Mixed-domain experiments combine SynLogic with 17k DAPO mathematics prompts or about 9k online-platform coding prompts for 7B studies. The large Zero-Mix-3 setting uses 35k mathematics, 9k code, and 17k SynLogic prompts with Qwen2.5-32B-Base; that run uses prompt batch 512 and maximum response length 12,288. Code rewards require format compliance and all tests to pass. These mixtures support the paper's transfer study but do not expand the released SynLogic rows into mathematics or code data.

The official GitHub `main` revision audited here is `d8c527fd17edb739172619efb9b681805fc74b8d`, with no tagged release. It publishes generators, verifiers, `task2verifier.py`, a reward reference, and Verl integration guidance. Reproduction should pin both that code revision and the Hugging Face revision, inspect each task's `game_data_str`, and test verifier behavior before training; repository availability alone does not establish a fixed end-to-end environment.
