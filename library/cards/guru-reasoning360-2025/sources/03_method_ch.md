### 来源组装

数学数据来自 OR1、DAPO 和 DeepScaler；代码数据来自 LeetCode、TACO-Verified、PrimeIntellect 与历史 LiveCodeBench 子集；科学数据来自 WebInstruct-Verified。逻辑数据包括 ARC-AGI、ARC-AGI-2、BARC，以及合成的 Zebra、排序和图搜索任务。模拟采用 Code I/O/PyEdu，表格推理采用经过线性化的 HiTab 与 MultiHierTT。流水线把约 68.49 万条原始候选缩减为去重和领域过滤后的 20.96 万条，再经难度筛选得到约 9.19 万条。

### 去重与领域过滤

广义相似度阈值在先导实验中产生较多误报，因此流水线采用更保守的规则：若一个问题是另一个问题的严格子串，就删除较短者。论文报告该步骤移除了 27.2% 的数学候选和 7.5% 的代码候选。随后，各领域规则删除过长提示、定义薄弱或过于简单的样本。代码参考解必须通过测试，标准输入不超过 1 MB，每题随机保留至多八个测试；模拟任务每个程序只保留一个输入输出对；科学任务限于大学或博士水平的物理、化学和生物学，并排除布尔题、选择题和高精度数值题；逻辑任务则使用规模或前瞻深度阈值。

### 难度筛选

每个候选分别由 Qwen2.5-7B-Instruct 和 Qwen3-30B-A8B 采样 16 次。若弱模型至少答对 15 次、强模型一次也未答对，或弱模型通过率高于强模型，该任务会被移除。数学任务还会删除强模型通过率至少为 0.75、但强弱差距不超过 6/16 的样本；科学任务要求差距至少为 0.5。最终通过率作为行字段发布，但候选级拒绝记录与随机种子没有公开。

### 奖励与优化契约

奖励为二元值，并依据 `data_source` 路由。结构化领域从 boxed answer、特定标签或 JSON 中抽取答案并规范化匹配，数学还处理符号等价；Python 代码在 30 秒超时的沙箱中执行，所有选中测试都必须通过，标准输入输出任务允许模糊比较；科学模型验证器根据参考答案判断语义蕴含。

论文中的 GURU-7B 与 GURU-32B 直接从 Qwen2.5 base model 开始，不经过 SFT，在 veRL 中使用 GRPO 训练两个 epoch。每个 RL step 包含 512 个提示，每个提示以 temperature 1.0 采样 16 个回答；mini-batch 为 64，因此每步有八次梯度更新。提示上限为 4K token，生成上限为 8K token。7B 运行使用四个节点，32B 使用十六个节点，每个节点有八张 Hopper GPU；两次训练各约耗时 2.5 天。
