Mobile-Bench asks how to evaluate LLM-based mobile agents when a task may require both GUI navigation and direct API calls across real mobile apps. The primary sources are the ACL 2024 long paper, the arXiv record submitted on 2024-07-01, and the XiaoMi/MobileBench repository.

The benchmark gap is concrete: prior mobile-agent evaluation often used UI-only operations, single-app instructions, or coarse final success metrics, while real phone tasks can require choosing apps, calling app or system APIs, and taking a sequence of UI actions from the home screen. Mobile-Bench is included as an evaluation surface and agent environment, not as a model-training recipe or a general mobile UI dataset.

A Mobile-Bench instance contains an ID, a user query, an app list, and CheckPoints over package names, key phrases, and API calls. The feedback contract is mixed: CheckPoint coverage scores action history against package/key-phrase/API predicates with sequential, conjunctive, and disjunctive relations, while PassRate uses GPT-4 judgment of task completion under step limits. This makes it valuable for atlas work on mobile-agent trajectories, but every score must be tied to the released evaluator, runtime, apps, and device state.
