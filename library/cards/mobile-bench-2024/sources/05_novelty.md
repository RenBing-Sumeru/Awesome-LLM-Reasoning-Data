The prior baseline is mobile-agent evaluation through static screenshots, UI-only Android environments, or final success metrics over single-app tasks. Mobile-Bench changes the evaluation object: tasks start from the phone home screen, may require multiple apps, expose both UI operations and API calls, and carry explicit process CheckPoints.

The novel direction is not that Android automation, ADB, Appium, or API calls exist. The direction signal is their packaging into a benchmark where a row includes query, app/API context, and machine-checkable process predicates. The quality signal is the combination of real voice-assistant queries, GPT-4-augmented complex tasks, author-side quality filtering, quality sampling, baseline comparisons, and a public repository with environment setup and data.

Before reuse, inspect whether the released data matches the ACL paper version, whether code and data licenses permit the intended use, whether all required apps and phone seed data are available, whether CheckPoint definitions are complete, and whether GPT-4 PassRate is treated separately from CheckPoint-l1/l2. Public artifact availability does not remove contamination risk for future mobile-agent training.
