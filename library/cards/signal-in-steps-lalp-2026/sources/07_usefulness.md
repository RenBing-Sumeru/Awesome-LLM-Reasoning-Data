For the **Data Construction and Open Release Recipes** track, LALP is useful as a response-selection design and a failure analysis for global likelihood. Its current reuse class is **reading and audit reference only; blocked for direct training or code reuse** because the selected corpus and implementation are unavailable.

- **Rebuild a candidate-selection ledger.** For every prompt, preserve all teacher responses, teacher and checkpoint IDs, sampling settings, final-answer matcher input and output, exact step boundaries, per-token log probabilities, LocalLP values, response LALP, ties, parse failures, and the final decision. Publish both selected and unselected records.
- **Separate admission from ranking.** Implement a versioned final-answer extractor and equivalence checker before LALP. Audit false accepts and false rejects independently; never describe local likelihood as a replacement for correctness verification.
- **Treat segmentation as a measurable component.** Compare GLM-4.5-Air boundaries with human or rule-based alternatives, report agreement and parse failures, and test split/merge perturbations. This reveals whether gains come from local scoring or from boundary style.
- **Run student-by-selector matrices.** Apply the same candidate pool to multiple student architectures, tokenizers, sizes, and pretraining histories. Report rank correlations and selected-set overlap so “student-specific” becomes a measured property rather than an assumption.
- **Control the locality budget.** Map each run to exact `k`, report token and step context, and compare small local windows, GALP, hybrid local-plus-global coherence, and equal-compute influence baselines. Include long-range inconsistency cases.
- **Compare equal-step and token weighting.** Test whether equal step weights, normalized step length, information-density weights, or learned aggregation explain the gain. Preserve segmentation so each aggregation can be recomputed.
- **Use the 817-response setting as a data-efficiency baseline.** Compare one selected response per LIMO prompt against random, GALP, best single teacher, all candidates, and more unique prompts under matched SFT tokens and compute. Keep the distinct 8,890-prompt within-teacher study separate.
- **Audit the embedding explanation.** Publish the embedding model, revision, pooling, normalization, preprocessing, and neighbor indices for the .935-versus-.760 coverage result. Test whether coverage predicts selection benefit beyond the reported benchmarks.
- **Add contamination and rights ledgers.** Pin source and benchmark revisions; publish exact, semantic, and provenance overlap results; attach prompt and teacher-output licenses, attribution, transformations, and hashes to each record.
- **Require a real release before reuse.** The current anonymous URL returns HTTP 401. A release must expose executable code, the segmenter prompt and parser, configs, dependencies, seeds, selected/candidate data, score ledgers, checkpoints, and an immutable commit or tag. A paper-linked URL without retrievable content is insufficient.

LALP is not directly suitable as PRM data, step-supervision data, preference data, or an RLVR reward. Those uses would require new labels or a validated reward contract. It can be used as an offline preprocessing baseline once reimplemented, and its GALP failure analysis can inform audit checklists for any model-aware reasoning-data selector.
