The evidence supports the following reconstruction, with the main 817-prompt recipe separated from auxiliary experiments.

1. **Build candidate groups.** The main math setting takes all 817 GAIR/LIMO prompts. DeepSeek-R1, QwQ-32B, and Qwen3-32B generate long candidate responses. The paper states that every admitted candidate's final answer matches ground truth, but it does not disclose the answer extractor, equivalence mapping, rejection log, duplicate policy, or exact number of main candidates per prompt.
2. **Segment without rewriting.** GLM-4.5-Air receives the problem and full solution and is instructed to return JSON `sentence_groups`, preserve all wording, maintain order, and skip nothing (Appendix B.1). The output parser, retry behavior, empty-step handling, parse-failure count, model revision, decoding settings, and segmentation validation are not released.
3. **Score each step.** For a response `y=(s_1,...,s_p)`, LocalLP for `s_i` is the token-average log probability under the pretrained target student. Conditioning contains the prompt, tokens already generated within the current step, and only the `k` immediately preceding steps. The student is not fine-tuned before selection.
4. **Aggregate and select.** LALP is the unweighted mean of all `p` LocalLP values. For each prompt, retain `argmax_y LALP(y|x)`. This produces one complete selected response per prompt—817 records in the main LIMO setting. Step boundaries and scores are preprocessing metadata, not training labels.
5. **Fine-tune.** Train the target student on the 817 selected complete responses with LLaMA-Factory SFT. Reported students include Qwen2.5-7B-Instruct and Qwen2.5-32B-Instruct; other experiments also use Qwen2.5-Math-7B and Llama-3.1-8B-Instruct.
6. **Evaluate.** The main suite covers MATH500, AIME 2025, AMC 2023, MINERVA, KAOYAN, OlympiadBench, and CN_MATH_2024. Extensions evaluate GPQA-Diamond and LiveCodeBench v2. The paper reports point estimates without independent training seeds, error bars, or confidence intervals.

The context window is a material data-construction parameter. Teacher-ranking experiments use 5%, 25%, 50%, and 75% of available preceding steps: 5%–25% preserves the reported downstream teacher order, while larger windows converge toward GALP. Appendix C.7 tests integer windows 1–6 and visually peaks near `k=4` for Qwen2.5-7B-Instruct and `k=5` for Qwen2.5-32B-Instruct. The exact run-to-`k` mapping for every headline table is not fully specified.

LALP costs `p` local forward passes per response rather than one GALP pass, although steps can be batched. The paper says 200 prompts recover the full 817-prompt teacher order in its setup, but gives no repeated subsampling variance or measured scoring runtime.

The teacher-sampling table prints alternatives of 1 or 16 samples, temperature 0.0 or 1.0, top-p 1.0 or 0.95, and top-k 1 or 40 without an unambiguous experiment mapping. The main candidate count and settings must therefore remain `unknown`. The separate within-teacher sanity check uses 8,890 MATH level-3-to-5 prompts and 16 responses per prompt; the code extension uses 5,000 OpenCodeReasoning and LeetCode prompts with an undisclosed mixture.

Appendix B.4 reports LLaMA-Factory, BF16, gradient accumulation 8, zero warmup, and alternatives of batch size per device 1 or 2, learning rate `5e-6` or `1e-5`, and 10 or 15 epochs. It does not map every slash-delimited alternative to each result. Training and evaluation use four A100 GPUs; runtime, GPU memory, total tokens, total compute, seeds, dependency versions, and checkpoint-selection rules are absent.

Reproduction requires five unavailable artifacts: the answer checker and mapping rules; raw candidate groups; the exact GLM-4.5-Air segmenter prompt, parser, and model revision; per-step likelihood and selection ledgers; and a run manifest linking sampling, `k`, SFT settings, checkpoints, and evaluation. The paper-linked anonymous repository currently returns HTTP 401, so its contents cannot be inspected and none of these artifacts is verified.
