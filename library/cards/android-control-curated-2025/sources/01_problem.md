The primary record is arXiv:2510.18488, submitted on 21 October 2025; only v1 and a 10-page PDF without an appendix or supplement were available, and no formal conference or journal venue was confirmed. The official GitHub repository, Hugging Face dataset, and redirected Magma-R1 model repository are the artifact sources used by this Card.

AndroidControl evaluates a GUI agent against one annotated action and, for grounding, an exact target point. The paper argues that this can mark an action wrong even when it activates the intended UI element, and that ambiguous instructions, multiple valid next actions, or incorrect ground truth can further confound the score. AndroidControl-Curated therefore treats the benchmark definition and labels—not only the agent—as objects to purify (Paper §2.1, pp. 3–4; §3.4, pp. 6–8).

The released object is a static state-action step, not a verified replayable episode. Depending on the JSON view, a row contains an image path, high- or low-level instruction/task, serialized prior-action history, target action, point and/or bounding-box target, input text, and optional revised task/history, alternative candidate actions, reviewer result, or original-versus-corrected action. Five JSON views and screenshot archives are public; no pinned emulator, app-version manifest, reset protocol, or live terminal checker was verified (official dataset `benchmark_resource/*.json`).

This supports `environment_agent_trajectory_data` because it exposes Android observations, action history, and step supervision, while `benchmarks_evaluation_surfaces` captures the paper's central claim that scoring geometry and label correction materially alter measured success. It does not establish a full environment episode release or a general-purpose mobile-agent training corpus. The Card reaches bilingual L4 content depth through the paper and audited official artifacts, while split, 2.4K training IDs, licensing, replay, and checkpoint mapping remain explicitly unknown.
