AndroidControl-Curated combines two forms of benchmark purification: intent-aligned grounding that accepts a predicted point inside the UI element's bounding box, and task/label correction for cases on which three named expert agents all fail (Paper §2.1.1–2.1.2, p. 3).

The correction pipeline uses Qwen3-VL-235B, InfiGUI-R1, and GUI-R1 as a consensus-failure screen. An undisclosed LLM reviewer then classifies the deficiency, proposes a task revision and/or ground-truth revision, and supplies a rationale; human experts verify correction proposals before accepted changes enter the curated benchmark (Paper Eq. 6–7 and Algorithm 1, pp. 3–5). The paper does not disclose the reviewer model/version, its prompt or decoding, the number of runs per expert, or a complete human-review rubric and agreement record.

The feedback contract has two distinct layers. In the paper, grounding accuracy uses box containment, while success rate is described as requiring all steps to be correct and the intended final screen to be reached (Paper §3.1, p. 5). In the released static scorer, `Step_Success_Rate` is action-type plus grounding correctness for click/long-press and type-only correctness for other actions; input text uses substring/token-F1 logic and improved tasks may accept any retained candidate action (`src/eval/utils.py`; `src/eval/evaluate_actions_androidControl_vllm.py`, lines 205–273). That scorer observes parsed actions and static labels, but not a live Android terminal state.

The closest reference is upstream AndroidControl, which supplies the human demonstration lineage and point-based evaluation. The specific change is to make evaluator geometry, alternative valid actions, and corrected task/ground-truth fields part of the auditable data object. Magma-R1 then uses 2,400 selected curated steps for GRPO post-training, but the selection manifest and train/evaluation separation are unknown (Paper abstract; §3.1, p. 5).
