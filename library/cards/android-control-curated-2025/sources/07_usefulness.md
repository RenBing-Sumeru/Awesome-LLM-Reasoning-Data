For `benchmarks_evaluation_surfaces`, this Card supplies a concrete audit recipe: compare point, Curated-Box, and corrected-label scoring; log action parser outcomes separately from grounding outcomes; and report whether success is a static step predicate or a live terminal condition. Table 2 offers a useful controlled comparison, but benchmark deltas should not be interpreted as automatic proof of data quality.

For `environment_agent_trajectory_data`, the reusable unit is the static step record: screenshot, instruction/task, prior-action history, action target, geometry/text target, correction fields, alternative valid actions, and provenance. Builders can use the five released views to study GUI grounding, action normalization, ambiguity, label repair, alternative-action recall, and scorer false positives/negatives. They should not call the object a replayable full episode without adding a pinned Android environment, state reset, app versions, observation/action log, and terminal predicate.

The purification sequence can be tested as a data-construction baseline: consensus-failure mining, deficiency classification, proposed task/label revision, human verification, and retained correction provenance. The Magma-R1 recipe can motivate an agent-training ablation over dense distance reward and action-balanced sampling, but reconstruction requires the 2.4K IDs, GRPO configuration, train/evaluation separation, and exact 3B checkpoint.

Reuse class: suitable for evaluation and audit reference with pinned files and scorer; training reuse is blocked pending license clarification, overlap/split disclosure, correction provenance, and checkpoint mapping. It is not currently safe to claim unrestricted training reuse or live-environment reproducibility.
