For **Data Construction & Open Release Recipes**, Herald is useful as a worked example of converting a formal library into parallel supervision. It exposes several reusable design choices: enrich targets with library structure, translate dependencies before dependents, retrieve domain precedents, use proof states as additional data objects, separate formal checking from semantic judgment, and publish statement and proof views separately.

The statement release can support supervised NL-to-Lean and Lean-to-NL translation research. Its exact size is 579,883 train rows, and reversing directions creates two task views without creating new underlying pairs. Researchers should preserve this distinction in scaling claims and should not infer a validation split from the release. The proof release’s 44,553 rows can support analysis or training of proof informalization and commented-proof generation, but the paper does not provide a controlled experiment showing that these rows train a proof-producing model.

The datasets are also useful for audit-method development. Statement rows provide a clear case where formal compilation and proof validity differ because `sorry` is present. Table 4 supplies a calibration target for studying learned semantic judges: validation passes are not equivalent to expert correctness. The released evaluator code makes it possible to inspect the precise “no severity error” rule and the back-translation/NLI stack, while the missing row logs expose what an audit-ready release would need to add.

Herald can seed source-aware split and lineage research if users first reconstruct provenance against a pinned Mathlib snapshot. A stronger derivative should attach source declaration/file/revision, dependency component, construction branch, prompt and model revision, retrieved example, compiler log, semantic-review label, and accepted/rejected status. Without those additions, benchmark use should include an independent overlap scan and should avoid treating random train rows as an uncontaminated held-out set.

The artifact is less suitable as a turnkey reproduction recipe. Rebuilding it requires choosing an unreported generator, embedding model, complete prompt set, sampling seeds, exact Mathlib source, and implementation for every construction stage. It is also not an RLVR dataset, preference dataset, or interactive environment trace. Its directly evidenced training use is SFT for bidirectional statement translation; broader proof training or reward-model uses would be extrapolations.

The practical reading lesson is to separate four claims: the data are openly downloadable; some formal objects can be Lean-checked; the translator performs strongly on reported benchmarks; and the natural-language alignment and full lineage remain only partially audited. All four can be true at once.
