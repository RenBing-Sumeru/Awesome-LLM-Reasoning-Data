The main limitation is semantic verification. A Lean compiler establishes properties of formal text under an environment; it does not compare that text with the intended natural-language mathematics. Statement rows contain `sorry`, so successful elaboration is not evidence that the proposition has a proof. The learned back-translation/NLI layer adds a semantic signal but has documented false positives and false negatives. Table 4’s 151 passed versus 101 correct is the clearest quantitative warning.

The construction recipe cannot be replayed from public code. The generator model and checkpoint, complete prompts, decoding settings, retries, token or compute budget, random seeds, embedding model, retrieval index, traversal implementation, and checkpoint selection are unknown. Appendix prompts use ellipses. The linked code repository implements inference and evaluation, not Mathlib extraction, dependency scheduling, corpus generation, augmentation, proof integration, sampling, or packaging.

Source and row lineage are insufficient. Statement rows do not identify the Mathlib source file or declaration, exact Mathlib revision, original/tactic/informal branch, generator run, prompt version, retrieved example, compiler result, or transformation history. Proof rows preserve `name` and `header` but still omit most of this build record. The paper-reported 1:2:1 mixture cannot be reconstructed from public rows.

Sampling and rejects are absent. Random downsampling of similar tactic states and informal variants lacks similarity criteria, seeds, candidate counts, and retained IDs. Generated candidates, compiler rejects, near-duplicate groups, unsampled variants, retries, expert feedback decisions, NLI outputs, and validation logs are not released. Auditors can inspect survivors but cannot measure rejection rates or selection bias.

Both datasets expose only `train`. There is no development/test split and no source-file, declaration-family, or dependency-component partition. No Herald-specific exact or semantic overlap audit is reported against miniF2F, ProofNet, Extract-Theorem, College CoT, or relevant pretraining corpora; decontamination therefore remains `unknown`.

Coverage is selective. Term-style proofs are excluded, biasing the proof corpus toward tactic-oriented Mathlib developments. Some natural-language records retain Lean identifiers or formal notation, while diagrammatic and category-theoretic content remains difficult. Multilingual and implicit-condition augmentation may increase surface diversity while making semantic preservation harder to audit.

Release identity is fragmented. The statement, proof, model, code, and Lean environment have separate verified revisions, but no named release binds them. The accepted ICLR paper and arXiv v2 report different model scores. Herald artifacts declare Apache-2.0, but the linked Lean helper has no detected license, and rows omit exact source revision, attribution, generator terms, and human-annotation consent/provenance.
