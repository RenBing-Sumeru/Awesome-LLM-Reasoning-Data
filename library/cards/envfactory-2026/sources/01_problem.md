The authoritative record is arXiv:2605.18703v1, submitted on 2026-05-18; no peer-reviewed venue was verified, so the venue remains arXiv preprint. The evidence freeze covers the official EnvFactory repository at commit `eff3b22d3fc26afa14165cfe208c2a4c9ecc39e3`, the author-linked VeRL fork at `dab0fcb68c46509ba3120eb8d35aa47e17bdb55f`, and the three pinned Hugging Face dataset revisions listed in the citation section.

EnvFactory addresses a specific agent-data bottleneck: tool-use post-training needs many executable, stateful environments, feasible multi-tool tasks, interaction traces, and outcome feedback, while manual construction and validation of those objects are expensive. Its answer is a source-grounded synthesis pipeline that builds local MCP environments, derives dependency-feasible scenarios, generates multi-turn assistant/user interactions, and converts selected conversations into SFT and RL records.

The data object is a linked bundle rather than a generic transcript. An environment includes research notes or schema sketches, standardized metadata and tool schemas, a stateful database schema, executable Python tools, and an MCP interface. A generated episode adds an initial state, user profile and scenario, dialogue history, reasoning, tool calls and responses, reference calls, a target final state, reward components, and a stop condition. These are synthetic local environments inspired by authentic sources, not execution against the original production APIs.

The paper reports 85 verified environments, 842 tools across seven domains, 1,622 SFT conversations, and 953 RL conversations. The official HF releases contain different units: 26,463 SFT-FILTERED rows, 53,412 SFT-ALL rows, and 3,092 RL rows, all in `train`. SFT rows expand accepted tool-call or user-interaction steps; RL rows are turn-level. Conversation counts and expanded row counts must not be added, substituted, or presented as the same scale.

This Card belongs in `environment_agent_trajectory_data` because state, action, observation, tool schema, environment transition, terminal condition, and composite reward define the training record. It does not establish real-service fidelity, safe unrestricted reuse, or dataset quality from benchmark gains. The accepted metadata remains `partial` and `L3_summary_ready`; the bilingual body supplies L4 reading depth without upgrading workflow state.
