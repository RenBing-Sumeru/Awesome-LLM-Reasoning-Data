EnvFactory 的核心贡献是把 executable environment synthesis、task-chain feasibility、interaction generation 与 state-aware reward 接成一条 post-training data pipeline。EnvGen 使用 Search、Code 和 Test agent：Search 提出 tool ecosystem 并检索真实来源；Code 编写 Pydantic state 与 Python MCP tool；Test 生成测试并修订 environment，直至全部测试通过或达到未披露的 revision budget。测试覆盖 interface/metadata consistency、import 与 execution、expected output 和 database-state transition，但不验证与 live production service 等价。

QueryGen 用 BAAI/bge-m3 对 tool parameter 做 embedding，形成候选 dependency edge，再让 LLM 补充 logical dependency 并删除 spurious edge。采样输入必须是 optional、由用户提供，或由先前 tool 生成；否则 sampler 会递归加入 producer。论文把 dependency recursion depth 设为 3，把 stochastic prior-tool override 设为 0.1。采样 chain 被分成每 turn 1–5 个 tool，再扩展为 profile、scenario、有效 initial database，以及经过 implicit reference、action compression、ambiguity 和 goal expansion 改写的 request。

sandboxed assistant 与 simulated-user agent 生成多个 candidate interaction。generation 在 simulated-user stop signal 或 maximum-step limit 时结束。pipeline 选择解决任务的 candidate，删除 redundant call 与不必要 interaction，并遮蔽不影响正确性的 argument。当前 SFT conversion 还会删除 `REMOVE` step，以及即时 response 含 `Fail` 或 `Error` 的 tool call；rejected candidate 与过滤掉的 failure 没有作为带标签账本公开。

两种公开 record contract 不同。SFT row 包含 `instruction`、空 `input`、可在前面带 reasoning 的 assistant/tool-call `output`、作为 `system` 的 tool definition，以及累积 `history`；每个被接受的交互 step 展开成一条 row。RL row 包含序列化 dialogue `prompt`、标识字段、`reward_model.ground_truth` 下的 reference tool call，以及 `extra_info.mcp_factory_kwargs` 下的 MCP server、序列化 initial config 与 target final config。它提供 reward input，而不是预先计算的 scalar-reward column，也没有显式 terminal flag。

feedback contract 是 mixed，并在执行时具有 programmatic 部分。论文 reward 由 trajectory/reference matching、final database-state equivalence 和 length penalty 组成。发布代码把 trace 项实现为 binary、order-insensitive coverage：每个 ground-truth call 必须匹配一个尚未使用的 predicted call，masked argument 被忽略。state 项对已使用 MCP-server config 的 exact equality 求平均；extra call 与 malformed call 接受 capped penalty，发布 config 默认 trace/state 比例为 0.5/0.5。它可能漏掉有害 intermediate action、接受 reorder call，也可能拒绝语义有效但序列化不同的 state。

accepted metadata 中最接近的 Atlas 对照是 EnvScaler 与 Feedback-Driven Tool-Use Improvements via Automated Build Environments。EnvFactory 的具体方向信号是联合发布 source-grounded environment artifact、step-expanded SFT object、turn-level RL reward input 与 executable reward code。MCP、Python tool、simulated user、SFT、GRPO 和 final-state check 本身都是已有组件；区别在于这些组件的集成方式和发布契约。
