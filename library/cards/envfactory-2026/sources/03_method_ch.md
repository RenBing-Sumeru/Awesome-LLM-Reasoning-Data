输入与 environment discovery。EnvGen 搜索真实在线资源，寻找有用的 tool ecosystem。Kimi-K2-Thinking 参与 environment proposal、drafting、implementation 与 verification。source research note 可以保留官方 documentation、API 或 repository URL，但没有统一的逐记录 manifest 把每个 environment 绑定到带日期的 source snapshot 与 redistribution right。

environment 构造与检查。Search Agent 准备 source-grounded sketch；Code Agent 创建 Pydantic database state、Python tool implementation、标准化 metadata 与 MCP interface；Test Agent 编写测试、诊断 failure 并请求修订。验证检查 interface/metadata 一致性、import 与 execution、expected output behavior 和 state transition。已检查 repository 当前包含 156 个 schema-sketch/research file、88 个 metadata JSON file、86 个 executable tool file 和 84 个 intermediate checkpoint；这些是当前 revision inventory，与论文 85 个 verified environment 的数量存在版本漂移。

dependency-aware task sampling。parameter embedding 提议有向 tool dependency；LLM 补充缺失的 logical edge 并删除错误边。recursive feasibility sampling 使用 depth 3 和 override probability 0.1，再把每条 chain 分成每 turn 1–5 个 tool。QueryGen 创建 profile、scenario、符合 schema 的 state 与自然 request。similarity threshold、paper-run candidate count、generation temperature、source/API version 和 maximum environment-revision budget 均为 unknown。当前代码设置 `pass_k: 4`，但这个可变 preset 不是不可变的 paper-run 值。

interaction、selection 与 conversion。Qwen3-30B-A3B-Thinking-2507 生成 SFT conversation 和 reasoning trace；DeepSeek-V3.2-Chat 生成 RL conversation。sandboxed assistant 与 simulated user 交互，直至 stop 或 step limit。在生成 candidate 中，pipeline 保留最好的 solved trajectory，删除 redundant call/interaction，并遮蔽 correctness-insensitive argument。SFT conversion 展开每个被接受的 tool-call 或 user-interaction step，并移除 failed call。RL conversion 把每个 interaction turn 变成一条 row，并序列化 reward function 所需的 initial state、target final state、MCP server 与 reference call。

SFT training。论文报告在 Qwen3-1.7B、Qwen3-4B 和 Qwen3-8B 上用 LlamaFactory 做 full SFT，learning rate 1e-6、batch size 256、3 个 epoch。后续 RL 从第一个 SFT epoch checkpoint 初始化。当前 repository configuration 与官方 HF model card 却写 1 个 SFT epoch。这些陈述相互冲突；没有确切 paper-run command、checkpoint hash 或 manifest 解决冲突。

RL training 与 reward。论文使用 VeRL 中的 GRPO，learning rate 1e-6、rollout size 8、batch size 256、maximum trajectory length 16k、maximum generation length 4k、10 个 epoch。reward 组合 order-insensitive reference-call coverage、exact target-state comparison、extra-call penalty 与 malformed-call penalty。论文 alpha ablation 在固定 length penalty 时取 0、0.3、0.5、0.7、1；发布 configuration 默认 trace 与 state 等权。

规模、split 与 replay。论文单位是 1,622 个 SFT conversation 和 953 个 RL conversation；公开单位是 26,463 条 SFT-FILTERED、53,412 条 SFT-ALL 与 3,092 条 RL expanded row。当前 processing code 在 row conversion 前请求 conversation-level 95/5 RL split，default seed 42；但官方 HF 发布只暴露 `train`，也没有 immutable split manifest 证明当前代码生成了 paper release。replay 需要固定两个 repository、三个 HF revision、environment code/config、model/API version、dependency 与 seed；没有 lockfile、image 或 paper-run manifest 将它们绑定。
