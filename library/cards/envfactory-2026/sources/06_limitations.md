- Unit mismatch: the paper’s 1,622 SFT and 953 RL conversations are not the HF release’s 26,463 SFT-FILTERED, 53,412 SFT-ALL, and 3,092 RL expanded rows. No immutable conversation-to-row mapping is published.
- Release-label conflict: the two official SFT dataset cards swap their prose scale descriptions relative to inspected viewer counts, and model cards still describe filtered data as 53.4k. Pin revisions and preserve the conflict rather than choosing a convenient number.
- Failure censoring: the pipeline selects a solved candidate, removes redundant interactions, and SFT conversion filters immediate `Fail`/`Error` calls. No candidate-level accept/reject ledger, labeled failed trajectories, recovery corpus, or retained/dropped ID manifest was verified; SFT-ALL does not reconstruct those decisions.
- Reward false positives: trace coverage is order-insensitive, ignores masked arguments, and only requires reference calls to be covered; extra calls are softly penalized. Reordered, redundant, or harmful calls can therefore receive substantial reward. This is a curator inference from released code, not a demonstrated exploit.
- Reward false negatives and blind spots: exact final-state equality may reject semantically valid outcomes with different serialization, while final-state checks can miss harmful intermediate side effects. Reward behavior outside used MCP-server configs is not established.
- Environment validity: generated tests check the synthesized interface and expected state changes, not fidelity to production APIs. LLM-defined dependency edges, user-providable inputs, scenarios, and stop behavior can encode model-specific errors or bias.
- Session isolation: write-capable stateful tools need dedicated per-conversation connections. Incorrect isolation can create cross-session contamination; asynchronous sessions mitigate throughput but do not remove the replay requirement.
- Split and contamination: public datasets expose only `train`; current code’s 95/5 RL split is not bound to the paper run. No semantic decontamination or overlap audit covers source materials, generated environments, trajectories, BFCL, MCP-Atlas, tau2-Bench, or VitaBench.
- Version reproducibility: no manifest binds paper v1, exact source snapshots, main and VeRL commits, three HF revisions, model/API revisions, dependency versions, environment list, seeds, configs, and checkpoint hashes. Most dependencies remain unpinned.
- Recipe conflict: the paper reports 3 SFT epochs and RL initialization from epoch 1, whereas repository config and HF model cards state 1 epoch. The reported checkpoints cannot be assigned an exact recipe from the public artifacts alone.
- Rights conflict: HF data/model cards and the VeRL fork state Apache-2.0, the main repository has no detected license, and the paper says artifacts use restrictive licenses. Source-document/API rights and generated-derivative rights are not reconciled.
- Privacy and safety: no record-level privacy, consent, PII, redaction, or source-rights audit was verified. Online-source and LLM construction may inherit bias, and authors note risks of malicious financial or phishing automation; synthetic state does not by itself prove sensitive content is absent.
- Evidence boundary: benchmark improvements are author-reported and MCP-Atlas uses only 30/36 servers and 291/500 tasks. They do not establish data quality, verifier robustness, generalization, or safe reuse.
