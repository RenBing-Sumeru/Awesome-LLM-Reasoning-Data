EnvFactory’s central contribution is to make executable environment synthesis, task-chain feasibility, interaction generation, and state-aware reward one connected post-training data pipeline. EnvGen uses Search, Code, and Test agents: Search proposes tool ecosystems and retrieves authentic sources; Code writes Pydantic state and Python MCP tools; Test generates tests and revises the environment until all tests pass or the undisclosed revision budget is exhausted. The tests cover interface/metadata consistency, import and execution, expected outputs, and database-state transitions, but not equivalence to a live production service.

QueryGen embeds tool parameters with BAAI/bge-m3, forms candidate dependency edges, and uses an LLM to add logical dependencies and prune spurious ones. A sampled input must be optional, supplied by the user, or produced by an earlier tool; otherwise the sampler recursively adds a producer. The paper fixes dependency recursion depth at 3 and a stochastic prior-tool override at 0.1. Sampled chains are split into turns of 1–5 tools, then expanded into a profile, scenario, valid initial database, and requests refined by implicit reference, action compression, ambiguity, and goal expansion.

Sandboxed assistant and simulated-user agents produce multiple candidate interactions. Generation stops on a simulated-user stop signal or maximum-step limit. The pipeline selects a solved candidate, removes redundant calls and unnecessary interactions, and masks arguments that do not affect correctness. Current SFT conversion additionally drops `REMOVE` steps and tool calls whose immediate response contains `Fail` or `Error`; rejected candidates and filtered failures are not exposed as a labeled ledger.

The released record contracts differ. SFT rows contain `instruction`, empty `input`, assistant/tool-call `output` optionally prefixed by reasoning, `system` tool definitions, and accumulated `history`; one accepted interaction step becomes one row. RL rows contain a serialized dialogue `prompt`, identifiers, reference tool calls under `reward_model.ground_truth`, and MCP servers plus serialized initial and target final configurations under `extra_info.mcp_factory_kwargs`. They provide reward inputs, not a precomputed scalar-reward column or explicit terminal flag.

The feedback contract is mixed and programmatic at execution time. Paper reward is trajectory/reference matching plus final database-state equivalence minus a length penalty. Released code makes the trace term binary, order-insensitive coverage: every ground-truth call must match one unused predicted call, while masked arguments are ignored. The state term averages exact equality over used MCP-server configurations; extra calls and malformed calls receive capped penalties, and the released config defaults to a 0.5/0.5 trace/state mixture. This can miss harmful intermediate actions, accept reordered calls, and reject semantically valid but differently serialized states.

The closest Atlas comparisons in accepted metadata are EnvScaler and Feedback-Driven Tool-Use Improvements via Automated Build Environments. EnvFactory’s concrete direction signal is the joint release of source-grounded environment artifacts, step-expanded SFT objects, turn-level RL reward inputs, and executable reward code. Existing MCP, Python tools, simulated users, SFT, GRPO, and final-state checks are components; their integration and release contract are the distinguishing object.
