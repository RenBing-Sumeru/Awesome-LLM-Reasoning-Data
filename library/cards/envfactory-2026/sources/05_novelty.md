The prior-work bottleneck is framed as insufficient executable environment diversity and task feasibility, not simply too few prompts or rollouts. EnvFactory changes the construction unit from a standalone trajectory to a chain of source research, state schema, executable MCP tools, dependency graph, initialized scenario, simulated multi-turn interaction, selected trace, and reward-ready state/reference records.

The first concrete change is environment synthesis with a multi-agent implementation loop. Search grounds a proposed environment in online sources, Code materializes state and tools, and Test exercises both outputs and state transitions. This creates reusable local execution substrates, while preserving an important boundary: generated tests validate the synthesized specification and do not prove equivalence to the original service.

The second change is topology-aware task construction. Parameter similarity and LLM graph refinement represent tool dependencies; recursive sampling ensures each required input can be supplied by the user or earlier tool output. This targets executable multi-tool chains before dialogue generation rather than asking a generator to invent a plausible trace without an explicit feasibility substrate.

The third change is the released mixed reward interface. RL rows carry reference calls and initial/target states, and reward code combines order-insensitive call coverage with exact final-state comparison and penalties. This is more auditable than a hidden learned judge, but it remains gameable and brittle: masked arguments, extra calls, reordered calls, intermediate side effects, and serialization differences all affect what the verifier can or cannot see.

The work does not invent MCP, Python tool servers, LLM code generation, simulated users, SFT, GRPO, reference-call checking, or final-state rewards. Its novelty is primarily their integration into an environment-first construction/release recipe and the pairing of step-expanded SFT records with turn-level RL reward inputs. The public release does not add a rejected-candidate dataset, explicit process labels, learned reward model, or immutable replay package.

For reasoning-data research, the direction signal is that an agent dataset must audit the environment and feedback contract alongside the transcript. Reuse checks should cover source provenance, task feasibility, state isolation, reward semantics, failed-sample retention, row-unit conversion, split/contamination, privacy, rights, and version binding before interpreting scale or benchmark gains.
