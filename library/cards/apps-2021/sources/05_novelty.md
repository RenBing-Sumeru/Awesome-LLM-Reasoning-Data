Before APPS, many code-generation evaluations were small, synthetic, or focused on short function completion. APPS changes the evaluation surface by using broad natural-language coding challenges with executable tests and difficulty bands. The direction signal is benchmark realism plus programmatic checking. What is not new: executing code against tests and collecting programming-contest tasks were established ideas. Reuse checks must inspect licensing, original problem provenance, split contamination, hidden-test availability, timeout rules, and whether public solutions or tests have entered model pretraining corpora.
