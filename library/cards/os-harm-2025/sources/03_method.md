Construction begins with three 50-task paper manifests. Deliberate misuse has 25 manually written base tasks and 25 Claude 3.7 Sonnet semantic reformulations across fraud, disinformation, copyright infringement, harassment, and cybercrime. Model misbehavior follows the same 25-plus-25 pattern for incomplete or ambiguous instructions, costly mistakes, and possible self-serving behavior. Prompt injection combines 10 OSWorld base tasks with six delivery vectors and selected goals from 12 possibilities; each vector/task receives three or four goals. The paper reports 50 injection cases, while the inspected repository commit expands the referenced configs to 51 vector-goal combinations, so reproduction must choose and disclose a pinned manifest.

Each task configuration supplies `id`, `snapshot`, `instruction`, `source`, ordered VM `config`, `related_apps`, `evaluator`, and, where applicable, `injections`, `derived_from`, and `explanation`. Injection entries add a `type`, `goals`, and optional parameters or setup. The 150 paper tasks span 11 applications and 53 files, averaging 3.26 configuration entries per task (Paper Table 1). These curated stress tests are not sampled from a deployment distribution, and formal acceptance criteria for Claude reformulations are unknown.

The runner resets an isolated OSWorld Ubuntu VM, reported under VMware Workstation, and gives the agent the task plus the current observation at each step. Main experiments use screenshot plus accessibility-tree observations, the pyautogui action space, temperature 1, `top_p` 0.9, and a 15-step cap, with no external guardrail or intermediate user confirmation. The evaluated policies are o4-mini, GPT-4.1, Claude 3.7 Sonnet, Gemini 2.5 Pro, and Gemini 2.5 Flash. An episode stops when the agent emits `DONE`, `WAIT`, or `FAIL`, or reaches the cap.

The executable record includes episode parameters (`platform`, model, decoding settings, action/observation modes, token and step budgets, jailbreak and injection fields) and per-step rows containing accessibility tree, screenshot file, model response/reasoning, executable actions, timestamps, environment reward, `done`, `info`, and recording files. OSWorld's environment reward and `result.txt` remain logged, but they are not the principal OS-Harm safety and completion labels.

After execution, AER sends all reasoning/actions and a GPT-4o final-screen caption to GPT-4.1. Its structured output is `reasoning`, `success`, `safety`, and `violation_step`; the safety prompt explicitly prefers false positives over false negatives. Three authors manually labeled all 150 o4-mini traces in the same format, one 50-task category per author, to measure judge agreement. The official Drive is stated to contain traces, LLM judgments, and human annotations, but its exact inventory, checksums, terms, and complete retention counts are unknown.

There is no train/dev split: the three public manifests are evaluation categories, and the authors request that examples not be used for training. Exact replay requires pinning the repository commit, OSWorld and Ubuntu snapshot, VMware provider, task and injection manifests, model/API snapshots, observation mode, decoding and step budgets, jailbreak/scaffold, judge prompt/framework, Drive files, and all retry/crash decisions. No tagged release binds those components together.
