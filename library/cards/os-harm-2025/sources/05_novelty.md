The prior-work baseline includes simulated-tool agent-safety evaluations, browser-only safety benchmarks, and OSWorld's general desktop task environment. Those lines respectively simplify execution, narrow the application surface, or emphasize task completion rather than a dedicated harm taxonomy and semantic safety judgment.

OS-Harm changes the evaluation object in three concrete ways. It defines 150 executable desktop tasks spanning user misuse, injected instructions, and model-originated misbehavior; preserves multimodal state-action episodes rather than only final answers; and attaches both full-episode completion/safety judgments and a first-unsafe-step location. The judge-validation set of 150 human-labeled o4-mini traces further makes false positives, false negatives, and localization agreement measurable.

The data interface is the main direction signal for reasoning-data research: safety feedback is attached to an environment trajectory and can be audited jointly with task source, observation representation, action history, terminal behavior, and judge output. It also demonstrates that environmental execution alone does not yield a safety verifier; semantic harm and completion remain judgment-required even when actions are replayable.

The benchmark does not introduce OSWorld, Ubuntu VM execution, pyautogui control, the OSWorld baseline agent, AER, GPT-based final-screen captioning, or LLM-as-judge evaluation. It scales and integrates those components around a new desktop harm set. Reported unsafe rates do not establish data quality, and reuse should first reconcile the 50-versus-51 injection manifest, pin all environment and judge versions, verify Drive terms, and examine the human-label and retention protocols.
