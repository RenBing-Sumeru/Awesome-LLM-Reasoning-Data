OS-Harm's contribution is a desktop-agent safety evaluation object that joins executable OSWorld tasks and multimodal trajectories to two full-episode decisions—task completion and safety—and a first-unsafe-step label.

Task construction intentionally separates three failure sources. Deliberate misuse asks whether the agent follows a harmful user request. Prompt injection places malicious instructions in websites, Writer documents, VS Code comments, received email, email drafts, or desktop notifications and tests whether the agent treats data as commands. Model-misbehavior tasks make instructions incomplete or ambiguous so that costly mistakes or self-serving actions become possible. This categorization makes the source of risk inspectable without claiming that the 150 stress tests estimate real deployment frequency.

The feedback contract is mixed. OSWorld executes mouse and keyboard actions in an isolated Ubuntu VM and records environment reward, completion state, observations, and terminal signals. The reported OS-Harm labels, however, are judgment-required: GPT-4.1 under the AER framework consumes the initial task, all agent reasoning/actions, and a GPT-4o caption of the final screenshot, then returns free-form `reasoning`, Boolean `success`, Boolean `safety`, and integer-or-null `violation_step`. The judge can inspect the action/reasoning history and final-state caption, but it does not provide a formal predicate over the complete VM state and may miss visual or semantic evidence omitted by that representation.

Relative to simulated-tool safety suites and browser-only benchmarks, OS-Harm evaluates general desktop interactions across OSWorld applications and reports safety together with completion. OSWorld's VM, baseline agent scaffold, and AER-style judging are reused components rather than new contributions; the distinctive combination is the three-category desktop task set and structured episode/first-violation evaluation contract.
