The primary sources for this Card are arXiv `2602.23866v2` (revised 1 June 2026), the official ICML 2026 poster record, the pinned official GitHub repository, and the two official Hugging Face releases. The work addresses a training-data bottleneck rather than only proposing another SWE leaderboard: repository agents need many task specifications paired with reproducible code states, executable tests, and terminal feedback, while manually curated SWE benchmarks are smaller and concentrated in a few high-resource ecosystems.

The main released object is a repository-repair task/environment row. It binds a `problem_statement` to `repo`, `base_commit`, the historical gold `patch`, `test_patch`, `FAIL_TO_PASS`, `PASS_TO_PASS`, `install_config`, language, repository license metadata, diagnostic `meta`, and, for the issue-linked release, a prebuilt `image_name`. A downstream episode starts from the repository at `base_commit`; an agent interacts with that state and submits a candidate patch, after which the Docker environment supplies full-suite test observations and a terminal success decision. The release does not contain the agent's state/action/observation trajectory or the seven-model diagnostic trajectories.

The arXiv v2/main Hugging Face release contains 32,079 executable issue-linked tasks from 3,617 repositories across 20 programming languages, all in one `train` split and with prebuilt images. The separate PR-derived release contains 126,300 rows in its current official Hugging Face revision; the paper describes this tier as 120,000+ tasks and does not provide prebuilt images for it. The official ICML page retains older figures of 36,000+ tasks, 3,800+ repositories, and 100,000+ PR tasks, so this Card treats the discrepancy as release drift and uses the pinned v2/Hugging Face counts for the current artifacts.

This is an anchor for `environment_agent_trajectory_data` because it exposes a resettable task state, environment recipe, executable feedback, and full-episode terminal predicate, even though trajectories must be generated downstream. It also belongs to `data_construction_open_release_recipes` because task mining, setup synthesis, parser synthesis, executable filtering, LLM clarity filtering, and release packaging are central contributions. Its L4 content is supported by the full paper, appendices, dataset schemas, licenses, and evaluator code; the unexposed harvesting implementation, immutable environment manifest, contamination audit, and failure corpus remain explicit unknowns.
