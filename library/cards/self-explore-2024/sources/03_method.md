The source repository contains `GSM8K_train/test.jsonl` and `MATH_train/test.jsonl`; the paper uses 7,473/1,319 GSM8K train/test problems and 7,500/5,000 MATH train/test problems. The main runs are separate for Mistral-7B, Llemma-7B, and DeepSeek-Math-7B-Base. There is no external rationale teacher: each SFT model generates its own candidate corpus, and the corresponding RFT model explores its own model family's rejected traces.

Raw generation uses vLLM with 100 outputs per problem, temperature 0.7, top-p 1, and maximum lengths of 512 tokens for GSM8K and 1,024 for MATH. The released GSM8K code deduplicates exact strings, extracts final answers, verifies equations enclosed by double angle brackets with Python evaluation and tolerance 1e-3, groups by equation signatures, and keeps up to eight diverse correct responses. The MATH code requires a recognizable final-answer marker, uses task-specific equivalence evaluation, shuffles with seed 42, applies normalized edit-distance deduplication, and keeps up to eight correct and 24 incorrect candidates.

Outcome-pair construction differs slightly by task. GSM8K pairs each retained correct solution with the remaining incorrect solution of maximum raw edit distance, then removes that negative from the pool. MATH searches for negatives above descending normalized edit-distance thresholds and chooses the shortest eligible one, falling back to the shortest candidate; it also removes used negatives. The paper describes a general maximum-edit-distance design and an eight-pair cap, but Appendix Table 5 marks Mistral/GSM8K as an uncapped exception.

For exploration, rejected responses are segmented into line-based steps for GSM8K and heuristic merged steps for MATH. The code tests at most 20 steps. At each prefix it samples four completions and records the prompt, generated continuations, and extracted answers. The first prefix with zero correct continuations supplies the pit. If the pit is the first step, the original question is the prompt and the original correct response is chosen. Otherwise, the prompt ends immediately before the pit and a successful continuation from that prefix is chosen.

There is a paper-code discrepancy in chosen selection. The paper says it randomly selects one correct completion from the prefix before the pit; current `form_gpair` code sorts eligible recoveries by length and takes the shortest unused one after overlap checks. The code also deduplicates chosen and rejected spans across pairs. Before DPO, `prepare_dataset.py` strips a rejected conclusion containing “The answer is,” matching Appendix C's report that retaining conflicting conclusion statements degraded training.

Training proceeds through SFT, RFT, and preference optimization. The paper reports two epochs for the base generator, one epoch for RFT, and three DPO epochs, while checkpoint comparisons span five SFT/RFT epochs. Released DPO configuration uses beta 0.1, seed 42, RMSprop, linear scheduling, and a 100-row evaluation subset copied from training; optimization-time evaluation is therefore not held out.
