Each model first becomes a zero-shot math generator through supervised fine-tuning on the human-curated task solutions. It then samples 100 rationales per training question at temperature 0.7. After heuristic deduplication and task-specific answer checking, correct rationales form the rejection-sampling fine-tuning set; the resulting RFT checkpoint acts both as the preference-training reference model and as the explorer.

Outcome-level pairs match one verified-correct rationale with one verified-incorrect rationale from the same question. The pairing code favors dissimilar negatives and uses each selected solution once. Conventional DPO would compare the two complete responses. Self-Explore instead splits the rejected rationale into steps and asks the RFT model to continue from successive prefixes, sampling four completions at temperature 0.7 at each tested step.

If at least one continuation reaches the ground-truth answer, the current prefix remains recoverable under the search. The first step with zero correct continuations is labeled the first pit. If every tested prefix admits a successful continuation, the alleged negative is discarded because it is not infeasible from the explorer's perspective. The granular row then moves the pre-pit prefix into the prompt, uses the pit step as the rejected completion, and uses a correct continuation sampled from the preceding prefix as chosen.

The construction thus changes what DPO compares. It increases the likelihood of a full recovery completion while decreasing only the localized pit step, preserving correct context before the failure and avoiding direct penalties on everything after it. The label is useful because it is actionable for the target model, but it is model- and budget-relative rather than a semantic proof of error.
