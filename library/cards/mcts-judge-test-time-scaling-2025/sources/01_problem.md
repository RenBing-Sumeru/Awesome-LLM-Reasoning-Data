Code-correctness evaluation needs a binary decision about whether a candidate program implements a problem statement. Executing a comprehensive trusted test suite would provide a strong predicate, but private tests and a safe runtime may be unavailable; direct LLM-as-a-Judge prompts are then vulnerable to shallow analysis, bias, and misread program behavior. The paper asks whether additional test-time search can improve this judgment without training a new judge.

MCTS-Judge decomposes one judgment into a tree of perspective-specific evaluations and uses a fully LLM-driven simulated-execution signal to guide search. The track-relevant data object is a set of MCTS states, chosen subtask actions, textual analyses, binary sub-decisions, UCT statistics, self-assessment decisions, generated test cases, simulated execution traces, terminal rewards, and a final Yes/No judgment. This is evaluation-time feedback data, not a released training corpus. The official arXiv v2 paper is the confirmed primary artifact; no official code, generated-test database, trajectory dump, or executable environment was confirmed, and the paper's limitation section describes their release as future work.
