A root contains the problem statement and candidate code. Actions select non-repeating evaluation subtasks, plus a null action; executing an action asks the base LLM for a perspective-specific analysis and binary decision. Selection combines global UCT from prior rollouts with an LLM self-assessment of whether the proposed subtask improves coverage of the current history. Expansion samples an unused action, simulation continues non-null actions to maximum depth, and a trajectory prediction aggregates its binary sub-decisions with a separate global evaluation.

The terminal signal is not actual program execution. Before search, GPT-4o generates input-output test cases from the problem statement and validates each case repeatedly. At a leaf, the search LLM receives a masked-output case and is prompted to act as an interpreter line by line; repeated simulated outputs vote on whether each case passes, and the simulated verifier declares the program correct only if all sampled cases pass. A trajectory receives reward when its judgment agrees with this simulated result. Compared with vanilla judging, majority voting, Best-of-N, or plain UCT, the contribution is the combination of multi-perspective MCTS, history-conditioned self-assessment, and a cross-checked but still judgment-required pseudo-execution reward.
