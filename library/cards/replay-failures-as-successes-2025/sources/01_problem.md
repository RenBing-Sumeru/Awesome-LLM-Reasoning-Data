Binary reward is sparse for multi-constraint instruction following: satisfying four of five constraints receives the same zero as satisfying none. Averaged constraint reward is denser, but directly optimizing partial credit can blur the distinction between complete compliance and a response that repeatedly satisfies only easy constraints. HiR asks how information in a partial failure can become a successful replay experience without claiming that it solved the original task.

The central data question is attribution. A response, its original instruction, all atomic constraints, per-constraint decisions, and the rewritten instruction must remain linked. If only the relabeled success is retained, later users cannot tell which constraints were removed, whether the checks were reliable, or whether the model learned full instruction following rather than a distribution of easier pseudo-instructions.
