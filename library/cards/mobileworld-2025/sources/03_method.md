**Task construction.** Annotators design long-horizon scenarios over a fixed system state preloaded with contacts, messages, email, calendar entries, and files; fixtures are LLM-synthesized or internet-derived. Complexity comes from composing subgoals across apps, visual extraction, memory across steps, arithmetic/logic, implicit time/location, and strict output formats. Agent-user variants remove a necessary fact and check that it is absent from the device. MCP variants join one of five service families—Amap, GitHub, Jina AI, StockStar, or arXiv—to GUI consumption of the returned data (Paper §3.3).

**Human validation.** A validator starts the task environment, executes actions manually, and runs the same task evaluator. A score of 1 confirms solvability. A score-0 task is retried up to five times; persistent failures return to design for changes to initialization, instruction, or evaluation. The paper does not release validator identities, agreement statistics, attempt logs, rejected versions, or a train/test split.

**Environment and reset.** The release runs a rooted Android Virtual Device, application backends, and an orchestration/evaluation API inside privileged Docker-in-Docker containers. Mattermost and Mastodon use self-hosted PostgreSQL/file state restored from captured backend directories; the AVD begins from a predetermined snapshot. Modified Mail and Taodian apps expose callback records, while local Android apps are inspected through ADB. Reproduction therefore requires both device and backend state, not merely APKs or task text (Paper §3.2 and Appendix B).

**Episode execution.** Agents observe screenshots and choose click, double-tap, long-press, drag, text input, scrolling, navigation, answer, wait, status, `ask_user`, or `mcp_call`. In the planner-executor baseline, a general LMM describes a target element and UI-Ins-7B predicts coordinates. User queries go to GPT-4.1 with hidden task context; MCP calls return structured results. The paper evaluates with temperature 0.0 and a 50-action maximum; per-task seeds, retries, token budgets, and external-service revisions are unknown (Paper §§4.1–4.3).

**Verification and output.** At termination or budget exhaustion, a task-specific evaluator performs answer matching, database queries, local-storage inspection, or callback checks and returns binary score plus a reason. Current trajectory logging serializes task goal, step, model prediction, parsed action, optional user response/tool call, token usage, result, and optionally screenshot-video frame indices. Public `site/trajs` bundles are model-specific post-paper releases; the inspected Seed-2.0-Pro bundle contains 161 tasks and retains both score-1 and score-0 episodes.

Replay must pin the ACL/arXiv version, Git commit, Docker image digest, AVD snapshot, backend-data snapshot, task/evaluator code, Android/app versions, model/scaffold prompts, MCP schemas/endpoints, GPT-4.1 user-agent version, random seeds, and credentials policy. The current repository has no tag or GitHub Release, and an April 2026 fix for expired Mattermost sessions demonstrates that evaluator validity depends on mutable snapshot state.
