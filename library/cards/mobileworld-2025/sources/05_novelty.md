AndroidWorld established reproducible mobile evaluation through emulator resets and deterministic checks, but MobileWorld changes the evaluation surface in four concrete ways: 201 tasks across 20 apps, longer and more cross-app workflows, explicit ambiguity requiring user queries, and GUI-plus-MCP execution. The app stack adds self-hosted Mattermost, Mastodon, and e-commerce substitutes so backend state can be reset and directly inspected (Paper Tables 1 and 5).

The new data object is a hybrid episode. A step may carry a screenshot and GUI action, a simulated-user question/answer, or an MCP request/structured response; all remain in one history that ends in a mobile-state predicate. This makes the boundary between model reasoning, user feedback, external tools, and environmental verification inspectable instead of scoring each channel separately.

The verifier design is integration rather than a single new algorithm: exact/regex answer checks, SQL/backend queries, ADB storage inspection, and app callbacks are assigned per task. The planner-grounder framework likewise combines a general LMM with UI-Ins-7B and extends the action schema. These components matter because they enable the benchmark, but benchmark difficulty and low model scores are not themselves evidence of novel data quality.

Before reuse, compare task manifests and evaluators against AndroidWorld and OSWorld-MCP, verify that user-agent hidden facts cannot leak through device state, and stress-test external MCP drift. The current trajectory release adds research value by retaining both success and failure, but it postdates the paper and must not be treated as the exact ACL experiment corpus without version mapping.
