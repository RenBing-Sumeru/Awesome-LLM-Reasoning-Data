MobileWorld targets a gap left by AndroidWorld-style mobile benchmarks: high leaderboard saturation, limited coverage of third-party productivity/e-commerce applications, mostly clear instructions, and GUI-only execution. It evaluates whether agents can sustain long cross-application workflows, recognize when a request is underspecified, ask a user for missing facts, and combine external Model Context Protocol (MCP) calls with Android actions (ACL paper §§1 and 3).

The benchmark contains 201 tasks across 20 applications: 116 GUI-only, 45 agent-user interaction, and 40 MCP-augmented tasks. Seventy-six use one app, 100 use two, and 25 use at least three, so 62.2% are multi-app. Under the paper's GPT-5 + UI-Ins-7B framework, MobileWorld episodes average 27.8 actions versus 14.3 on AndroidWorld, but this is a model-conditioned measurement rather than an intrinsic optimal-path length (Paper Table 5 and Figure 5).

One episode joins a task goal and predetermined environment snapshot with screenshot observations, GUI actions, optional `ask_user` exchanges, optional MCP requests/results, model responses, and a task-specific terminal score. Current public trajectory bundles additionally retain token usage, evaluator reason, and optional frame indices into screenshot videos. The canonical artifact is therefore an environment-linked evaluation episode, not an instruction-answer row or a training demonstration.

MobileWorld is directly relevant to `environment_agent_trajectory_data` because state initialization, observation/action schemas, external feedback channels, and terminal predicates all determine the meaning of success. This Card uses the ACL 2026 paper, arXiv v3, and current official artifacts; it does not assume that post-paper code or trajectory bundles exactly reproduce the paper-era run.
