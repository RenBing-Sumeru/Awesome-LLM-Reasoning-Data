The central contribution is a controlled Android benchmark in which one decision loop may alternate among three action families: ordinary GUI operations, `ask_user` clarification, and `mcp_call` tool invocation. A planner receives the goal, current screenshot, and history; click-like plans are converted to coordinates by UI-Ins-7B, while user and MCP responses are appended as observations for subsequent steps (Paper §§3.1–3.2 and 4.1; Appendix A).

Agent-user tasks start from a fully specified human-authored goal, remove one critical fact, and verify that the device itself does not leak it. GPT-4.1 plays a simulated user that receives the full goal and omitted information and is instructed to refuse unrelated questions. MCP tasks begin from standalone tool tasks and add GUI actions that consume tool output, creating hybrid traces rather than API-only calls (Paper §3.3).

The terminal feedback is mostly programmatic even though the interaction surface is mixed. Twenty-two tasks use exact/regex text matching, 95 query a self-hosted backend database, 74 inspect local app storage through ADB, and 10 query application callbacks. These verifiers observe selected answer or state fields; they do not establish that every intermediate action was appropriate, that no unqueried side effect occurred, or that an external MCP response was stable (Paper Tables 4–5).

Relative to AndroidWorld, MobileWorld adds self-hosted third-party app substitutes, substantially more multi-app tasks, user clarification, and MCP-augmented execution. Relative to conversational benchmarks such as τ-bench and hybrid computer-use work such as OSWorld-MCP, its distinguishing object is a screenshot-driven Android episode whose dialogue/tool calls culminate in mobile state verified through database, storage, callback, or text predicates. It is an evaluation environment and released trace surface, not an agent-training recipe.
