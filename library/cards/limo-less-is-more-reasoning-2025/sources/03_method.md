The paper supports the following pipeline, while the public repository supports only the training/evaluation tail.

1. **Candidate assembly.** Aggregate tens of millions of problems from NuminaMath-CoT, DeepScaleR (about 40K unique problems), pre-2024 AIME, MATH, and unspecified Chinese elementary, secondary, high-school, undergraduate exercises and exam papers. Exact snapshots, per-source counts, item IDs, transformations, and rights are unknown.
2. **Coarse difficulty filtering.** Give Qwen2.5-Math-7B-Instruct up to four attempts per problem and exclude any problem solved within those attempts. The paper does not disclose decoding settings, the answer checker, or survivor counts for this stage.
3. **Fine difficulty filtering.** Generate 32 attempts per remaining problem with DeepSeek-R1-Distill-Qwen-32B. Retain problems solved in only 1–3 attempts. This produces a 2,125-question LIMO-Pool (paper Section 3.1.1).
4. **Benchmark deduplication.** Run n-gram matching against all evaluation benchmarks; the authors report no overlap. The n-gram size, normalization, threshold, benchmark revisions, candidate pairs, and decisions are not released.
5. **Candidate reasoning generation.** Sample multiple solutions from DeepSeek R1, DeepSeek-R1-Distill-Qwen-32B, and QwQ-32B for each retained question. Exact rollouts per teacher, temperatures, top-p, token caps, seeds, retries, and generation cost are unknown.
6. **Human examination and proxy definition.** All authors examine filtered solutions and identify four desired characteristics: elaborated reasoning, self-verification, exploratory approach, and adaptive granularity. No annotation protocol, agreement statistic, or decision ledger is released.
7. **Rule scoring and final selection.** Score each solution with length (30%), normalized validation-word frequency (20%), tentative-expression frequency (25%), and connective-phrase frequency (25%). Select the highest-scoring solution for each question, rank 2,125 pairs, and keep the top 800. Full keyword lists, tokenizer, normalization code, tie handling, selection ledger, rejected candidates, and the final solution-correctness gate are unavailable.
8. **Released object.** Publish one 800-row LIMO-v2 train split with `question`, `solution`, and `answer`. No per-row construction metadata is retained.
9. **Training.** Full-parameter SFT of Qwen2.5-32B-Instruct uses DeepSpeed ZeRO-3, FlashAttention-2, cutoff length 16,384, learning rate 5e-6, cosine decay, no warmup, 15 epochs, and paper-reported global batch 64. The public YAML gives per-device batch 1 and gradient accumulation 1 but no world-size manifest.
10. **Evaluation.** Use zero-shot CoT. Larger benchmarks use one greedy sample; benchmarks below 50 questions use four temperature-0.6 samples and unbiased pass@1. The output cap is 32,768 tokens. Numerical answers receive rule grading, while complex formats use an LLM evaluator; released code names Qwen2.5-32B-Instruct as judge.

The official repository at commit `2284c6a0e6653aa8894bd12fdecc1212ba706c3a` does not implement stages 1–7. It contains no candidate-pool ingestion, four-attempt or 32-attempt filtering, n-gram audit, teacher-generation pipeline, lexical scorer, or correctness checker. The construction recipe is therefore descriptive, not executable from the release.

The same commit is not a final v2 training package. `train/data/limo.json` contains the 817 legacy v1 rows. `train/examples/train_limo.yaml` sets `dataset` to an angle-bracket placeholder reading “the limo dataset,” and `train/data/dataset_info.json` contains no LIMO registry entry. Reproducing v2 requires pinning the 800-row HF revision `ef8bf143f8cc56ca8634795835b55083a3ae3061`, registering it explicitly, replacing the placeholder, and documenting world size, template, checkpoint selection, and exact model/data revisions.
