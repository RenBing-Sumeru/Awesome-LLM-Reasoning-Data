- **The 800-example claim hides construction scale.** The pipeline starts from tens of millions of questions, uses four and 32 difficulty rollouts, and samples from three large reasoning teachers. Generation tokens, rollout totals, hardware, GPU-hours, wall time, monetary cost, and per-stage acceptance rates are unknown.
- **Difficulty is model- and budget-relative.** A 1–3/32 success band under DeepSeek-R1-Distill-Qwen-32B does not define intrinsic difficulty. Decoding parameters and the answer checker are undisclosed, so the exact band cannot be replayed.
- **The lexical score can reward verbosity and stock phrasing.** Length receives 30% weight; validation-like words receive 20%; tentative expressions and connective phrases receive 25% each. Full lexicons, tokenization, normalization, tie handling, and code are unavailable. A trace can score highly without mathematically valid intermediate steps; this is a curator inference supported by the proxy's observable features.
- **Correctness verification is incomplete.** The exact final-answer checker and rejection gate for generated solutions are not published. The three-column rows contain no correctness output, step label, judge result, or process reward.
- **Selection lineage is absent.** Rows omit source item IDs and revisions, teacher identity, four-/32-attempt outcomes, candidate set, component scores, rank, author-review outcome, deduplication decision, and rejection reason. False-positive/false-negative analysis is impossible from the release.
- **Benchmark deduplication cannot be audited.** The paper reports no overlap after n-gram matching, but does not disclose n, normalization, threshold, benchmark revisions, match candidates, or decisions. Semantic overlap and contamination inherited through base/teacher training remain unmeasured.
- **V1 and v2 can be silently conflated.** The initial official release has 817 rows; the final COLM/arXiv v3 release has 800. The checked GitHub training file still reproduces all 817 v1 rows although the README promotes v2.
- **The v2 training path is not wired.** The example YAML uses an angle-bracket dataset placeholder and `dataset_info.json` has no LIMO entry. Without manual edits and a world-size manifest, the published config cannot reproduce the paper's 800-row run or global batch 64.
- **Construction code is missing.** The official repository has no implementation for candidate ingestion, coarse/fine difficulty filters, n-gram audit, teacher sampling, lexical scoring, final correctness checking, or selection. Only training/evaluation portions are inspectable.
- **License scope is inconsistent.** HF v2 data/model are labeled Apache-2.0. The root README claims MIT and points to an absent root LICENSE; `train/LICENSE` is Apache-2.0. Upstream contest/exam rights and source-specific redistribution terms are not mapped to rows.
- **Transfer depends on the base.** The paper's pretraining-dependence experiment shows markedly weaker elicitation on Qwen1.5-32B-Chat. Results on Qwen2.5-32B-Instruct do not establish the same 800 rows will work for smaller, weaker, or differently pretrained models.
- **Evaluation is not data certification.** Complex answer formats use an LLM judge, most comparisons lack repeated-run variance and item-level outputs, and headline scores combine data, training, decoding, and grading. They do not prove row-level correctness, absence of contamination, or release reproducibility.
- **Migration deduplication remains necessary.** A historical legacy metadata entry already calls this paper `limo-2025`. A later V2 application must reconcile the identity instead of creating a second legacy record.
