The verifier inherits an oracle problem: a generated test can contain an incorrect expected output, miss important behavior, or encode a narrow shortcut. Passing more correlated tests is therefore not equivalent to semantic program correctness. Filtering against one reference solution and model-generated incorrect solutions reduces some false positives but cannot enumerate all valid implementations or failure modes.

The authors report reward hacking in which adding tests lowers best-of-N performance: 9.76% of HumanEval Plus problems and 7.41% of MBPP Plus problems show degradation under their criterion, with the hardest HumanEval Plus quintile especially affected. This directly challenges the assumption that harder problems should always receive more verifier compute. The dynamic method yields modest gains, imports an allocation objective developed for policy sampling, and may plateau as test count grows. Diversity and coverage under scaling are not characterized by a formal law. Evaluation is limited to short, function-level Python tasks; LiveCodeBench reduces but does not eliminate generalization concerns and does not represent repository-scale software engineering. Finally, the paper states that CodeRM-8B parameters and training data would be released, but without a verified official release link their present availability, exact contents, license attachment, lineage metadata, and reproducibility remain unknown.
