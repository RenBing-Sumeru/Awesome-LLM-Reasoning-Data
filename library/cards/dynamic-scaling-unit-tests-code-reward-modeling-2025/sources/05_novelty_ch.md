使用生成测试重排序并非该文首创：CodeT、MBR-Exec 等方法已经通过执行生成测试来排序采样程序，测试时扩展研究也常增加策略模型输出数量。该文组合了三项变化：为专用 8B 测试生成器构造经过执行过滤的合成数据、实证扩展验证器采样数量，以及按难度分配验证器计算。对 rollout、搜索与测试时计算方向而言，其信号在于区分策略采样预算和验证器采样预算，并显式尝试依据估计难度分配后者。

执行契约、监督微调、多数投票、探针和贪心分配本身均非单项新技术。论文没有建立普适扩展定律，而且动态分配器沿用了策略计算目标；作者也承认该目标可能与验证器计算并不匹配。因此，应将贡献理解为面向代码任务的构造与扩展研究，而不能据此认为增加测试数量必然产生更高质量奖励。
