The synthesis pipeline starts from CodeFeedback-Filtered-Instruction and the training split of TACO. Llama3.1-70B filters questions unsuitable for conventional unit testing, including tasks involving randomness, and the retained reference solutions are converted to functional form. Conditioned on each problem and reference solution, Llama3.1-70B repeatedly samples unit tests. Tests are executed against the reference solution: passing tests are retained, while failing tests can be repaired using Python-interpreter feedback. A quality-control stage generates incorrect solutions with a less capable model and removes false-positive tests that fail to reject those incorrect solutions. CodeRM-8B is then supervised-fine-tuned from Llama3.1-8B with the problem plus code solution as the instruction and a filtered unit test as the target.

At selection time, candidate solution Ci receives one binary result per generated unit test: 1 only when it passes all cases in that test, otherwise 0. The selected solution maximizes the sum of these results. For dynamic scaling, repeated policy samples are checked with previously collected correct tests; their mean pass rate supplies the difficulty target. A two-layer feed-forward probe maps decoding hidden states to a scalar predicted pass rate, and a greedy algorithm allocates test-generation budget using the paper's utility q(x,b)=1-(1-λ)^b. Main experiments use HumanEval Plus, MBPP Plus, and 168 functional-format LiveCodeBench problems from 2024-01 through 2024-09. The paper reports temperature 0.8 and top-p 0.95 for solution and test generation. An official ACL paper and project URL are printed in the PDF, but this Card has no verified official code or data-release link; exact released schemas, record counts, splits, checksums, and complete replay logs therefore remain unknown.
