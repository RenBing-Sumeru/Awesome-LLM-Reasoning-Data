For the rollout/search/test-time-compute track, this work supplies a concrete schema for verifier-side traces: problem, sampled candidate solutions, generated tests, execution matrix, aggregate vote, selected candidate, predicted difficulty, and allocated test budget. Such records can support budget-aware reranking studies, verifier calibration, false-acceptance and false-rejection audits, and comparisons between fixed and adaptive verifier compute. The synthesis recipe is also relevant when constructing unit-test-generator SFT data, provided users preserve source-dataset lineage, reference solutions, repair histories, rejected tests, and execution environments.

Reuse should keep two objects separate: the training examples used to fit CodeRM-8B and the test-time execution traces used to rank candidate programs. The reported benchmark improvements justify studying this feedback contract, not treating generated tests as ground truth or expanding the paper into unsupported RLVR, process-supervision, or general software-engineering claims.
