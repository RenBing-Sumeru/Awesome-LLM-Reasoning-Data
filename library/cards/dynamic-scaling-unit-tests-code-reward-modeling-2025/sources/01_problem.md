Published as an ACL 2025 long paper, *Dynamic Scaling of Unit Tests for Code Reward Modeling* studies a test-time code-selection problem: repeated sampling can produce a correct program among many candidates, but selecting it requires a reliable verifier. LLM-generated unit tests provide executable feedback, yet erroneous or low-coverage tests can accept wrong programs or reject correct ones. The paper therefore asks whether scaling the verifier-side computation—the number of generated unit tests—improves the reward signal, and whether that budget should vary with problem difficulty. The relevant data objects are programming problems, candidate code solutions, generated unit tests containing input–expected-output cases, per-solution execution outcomes, selected solutions, difficulty labels or estimates, and per-problem test budgets. This Card treats these as a construction and evaluation recipe for rollout/search/test-time-compute data; it does not infer that complete rollout logs or a reusable corpus are available.
