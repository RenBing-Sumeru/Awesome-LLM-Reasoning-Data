论文扩展的是验证器侧计算，而不只是策略模型侧采样。对一道编程题，策略模型先生成多个候选解答；单元测试生成器根据题目与候选解答产生多组测试；执行过程为每个“解答—测试”组合给出二元结果；多数投票最终选择通过测试数量最多的候选。作者以 Llama3.1-8B 为底座，通过合成监督训练 CodeRM-8B，使其从“题目—解答”输入生成测试；同时利用模型隐藏状态训练轻量难度探针，再用贪心分配器为较难题目配置更多单元测试预算。该反馈契约属于程序化验证但并非完美验证：在论文所述 Python 环境中，执行结果是确定的，但测试输入和期望输出由模型生成，仍可能出错。相较 CodeT、MBR-Exec、MPSC 等固定测试数量的重排序方法，其关键新增对象是在固定总预算下按难度扩展验证器采样。
