该验证器继承了测试预言问题：生成测试的期望输出可能错误，可能遗漏关键行为，也可能编码狭窄捷径。因此，通过更多相互相关的测试并不等同于程序语义正确。使用一个参考解答和模型生成的错误解答进行过滤可以减少部分假阳性，却无法枚举所有有效实现或失败模式。

作者报告了“增加测试反而降低 best-of-N 性能”的奖励黑客现象：按其判定标准，HumanEval Plus 和 MBPP Plus 中分别有 9.76% 与 7.41% 的题目出现退化，HumanEval Plus 最难分位尤其明显。这直接削弱了“较难题目总应获得更多验证器计算”的假设。动态方法的收益较小，并沿用了为策略采样提出的分配目标；随着测试数量增加，收益也可能饱和。论文未用形式化定律刻画扩展后的多样性与覆盖率。评估仅覆盖短小、函数级 Python 任务；LiveCodeBench 虽降低了部分污染风险，但不能消除泛化问题，也不代表仓库级软件工程。最后，论文声明将发布 CodeRM-8B 参数和训练数据，但在尚无已核验官方发布链接的情况下，其当前可用性、确切内容、许可证附着方式、血缘元数据和可复现性均为 unknown。
