Inputs are shopping user instructions, product documents, a sandbox/search index, model/API configuration, and tool definitions. The official README lists dataset files for product, shop, voucher, and web-search intent tests; setup requires decompressing `resources/documents.jsonl.gz`, preparing keys, running `init_env.sh`, and then using `run.sh` for rollout and evaluation.

The construction pipeline samples real-world products, extracts product fields, simulates user queries for four intent families, and runs agents in a sandbox that supports product search, product-detail inspection, web search, and termination. The arXiv HTML reports 3,310 user instructions: 2,410 for training and 900 for testing, with 150 Knowledge test samples and 250 test samples for each of the other intents.

Outputs are trajectories, tool invocations, observations, final answers/product selections, and scores. The paper defines constraint-level scores and overall metrics including cumulative average of product relevance and absolute success rate. For training reuse, the authors generate GPT-4.1 tool-calling trajectories from 2,410 instructions, reject non-successful trajectories, segment trajectories into 5,552 step samples for SFT, and use reinforcement learning for tool calling. Reproducibility requires pinning repository commit, product document archive, search index, intent split, evaluator code, model/scaffold, external web-search provider, and API versions.
