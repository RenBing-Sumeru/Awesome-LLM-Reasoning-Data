Pile construction begins with a semantic prefilter. The paper names Pile-CC, StackExchange, GitHub, HackerNews, PubMed Central, and English Wikipedia as the retained subdomains. The released script averages `all-mpnet-base-v2` embeddings over reference examples from GSM8K, ECQA, ARC-Challenge, and ProofWriter, then keeps Pile text with cosine similarity at least 0.3. The length rule is not reproducibly specified: the methodology says 2,000-word segments, the experiment section says fewer than 2,000 tokens, and the code applies Python `len(text)`, which is a character count.

Llama-3-8B-Instruct is prompted with demonstrations to insert rationales between the literal BOT and EOT delimiter tokens while leaving the surrounding text unchanged. For GSM8K and ECQA, prompts instruct the model not to put the answer inside a rationale. The released extraction script uses temperature 0.0, seed 14, and a 3,000-token output cap, but its input list also includes MATH and MMLU-Pro; the paper's reported final mixture names only GSM8K, ECQA, and the six Pile subdomains.

For a rationale at position i, the paper weights future-token loss by powers of 0.9. It reports thresholds 1.2 for GSM8K, 0.5 for ECQA, and 0 for all Pile sources. A manually labeled positive/negative set of 100 examples is used to select the task-data thresholds for a stated 95% retained-rationale accuracy target; the paper does not clearly say this is 100 examples per dataset. Pile rationales receive no comparable labeled calibration.

The retained pairs train RATIONALYST with token-level cross-entropy, masking the prompt and predicting the rationale. The public example job specifies 20 epochs, learning rate 2e-5, per-device batch size 2, gradient accumulation 8, warmup ratio 0.03, cosine scheduling, and two-GPU FSDP, but the paper does not confirm that file as the exact reported run.

At inference, RATIONALYST generates a rationale for the current trajectory. Llama-3-8B-Instruct samples three next-step candidates at temperature 0.7; the released implicit method chooses the candidate with the highest 0.9-decayed token log-probability conditioned on that rationale. The script uses seed 14 and at most 15 iterations, stopping earlier on a dataset-specific answer cue. No external correctness verifier or executable environment evaluates the chosen step.
