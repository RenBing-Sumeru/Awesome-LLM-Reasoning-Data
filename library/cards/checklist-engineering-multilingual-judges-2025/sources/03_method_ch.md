1. 将任务指令（或翻译源文）与每个回答分别输入，生成抽象概念骨架。
2. 把指令和回答译为英文，使清单生成利用模型更强的语言环境。
3. 沿两个方向生成描述性、内容特定的核对清单，避免过早形成二元判决。
4. 合并清单，以 Qwen2.5-7B-Instruct 基于原文给出反馈和逐点评分或直接的成对胜者。
5. 成对任务对两个回答重复前述阶段后再比较。在 LitEval、MM-Eval 测试；逐点用 Kendall Tau，成对用准确率。提示与代码公开；翻译 API 行为和实际成本须复核。

最终接受检查是与人类标签或排序的一致性，争议判决可回看具体清单作为审计轨迹。逐点任务加入评分指南，成对任务不依赖两个独立分数的相减；若概念或翻译阶段失败，应在判别前回退或人工复核。
