For the Data Construction and Open Release Recipes track, Genius is most useful as a worked schema for label-free preference construction. A reproduction can treat one source query as the root object, preserve every policy prefix and candidate, attach each future continuation and normalized log probability, record beam-selection probabilities and random seeds, and derive chosen/rejected trajectories plus advantage weights. This makes explicit how a policy-internal proxy becomes a training distribution and which information must survive release for that transformation to be audited.

The method also supports controlled comparisons. A lab can hold queries and candidate rollouts fixed while comparing foresight likelihood with an answer checker, unit-test executor, process reward model, independent LLM judge, or human audit subset. It can vary beam size, rollout count, score temperature, continuation length normalization, rejected-path sampling, and ACO versus DPO while measuring both downstream scores and pair-level false positives/false negatives. The paper’s Table 3 and Table 4 provide baseline conditions for those ablations.

As an audit reference, the current release highlights a practical checklist: pin source-dataset IDs and policy hashes; confirm that the query is present in the training messages; separate copied source responses from fields actually used by the algorithm; retain full process pools and failures; record pair lineage and selection probability; test for item-level benchmark overlap; publish software/hardware configuration; and license code, source data, generated preferences, and checkpoints separately. The visible array-length guard is also a useful end-to-end smoke test for any reimplementation.

Reuse class: **blocked pending verification for direct training-data reuse** because the paper-run 100K/128K preference snapshots, exact source manifests, and immutable end-to-end recipe are unavailable. The official code and checkpoints are suitable for **reading/audit reference and reproduction-oriented experiments** after the handoff issues are resolved. The HF source datasets should not be mislabeled as the generated Genius preference data, and the benchmark results should not be used as a substitute for record-level quality validation.
