The intended pipeline is `source record → query selection → stepwise policy exploration → same-policy foresight scoring → beam sampling and preference re-sampling → weighted preference JSONL → ACO training → checkpoint evaluation`.

**Inputs and source selection.** The paper randomly selects 25K queries from Magpie and 32K from OpenHermes-2.5 and runs the two sources separately. Main experiments use LLaMA3.1-8B-Instruct; Qwen2.5-3B-Instruct and Qwen2.5-7B-Instruct are transfer backbones. The official HF source repositories contain `instruction` and `response` fields plus provenance metadata. The released sampler requires both fields and copies `response` to `ground_truth`, but the visible candidate selection and scoring path uses the instruction and model probabilities, not that copied value. Exact selected IDs are unavailable. (Paper §3.1; official HF viewers and sampling script)

**Exploration and self-reward.** At each of four decision steps, Genius keeps two beams. For each beam it samples four candidate next steps at generation temperature 0.6, then generates a future continuation for each candidate. It divides cumulative continuation log probability by continuation length to produce a foresight value, normalizes candidate values, and samples two paths without replacement for the next decision. The paper describes the normalized distribution abstractly; the released script uses softmax temperature 0.1, seed 0 by default, candidate maximum length 1024, and a final completion budget of 3000 tokens. The score is not checked against task outcomes. (Paper §2.2, §3.1, Appendix B.2; official sampler)

**Preference construction.** At each decision, the highest-foresight trajectory is chosen and a lower-ranked trajectory is sampled as rejected. Advantages subtract the previous path value. The paper keeps four pairs per query, so the two runs contain 100K and 128K pairs. The official constructor sorts candidates by stored log probability, picks the top trajectory, randomly chooses one of the rest with seed 42, and writes `prompt`, `chosen`, `rejected`, `chosen_weights`, `rejected_weights`, and `chosen_average_weights`. The full process pools are necessary if another lab wants to recompute the pair or change the selection rule.

**Optimization.** ACO uses a policy and reference model as in DPO, but scales the rejected log-ratio using the chosen/rejected advantage difference. The paper reports 8 A100 80GB GPUs, DeepSpeed ZeRO-3, FlashAttention2, total batch size 128, learning rate `5e-7`, and `alpha=1`. The released command additionally sets one epoch, warmup ratio 0.1, maximum sequence length 1300, and uses the parser default `beta=0.1`; its model, train-file, and output paths are blank. Sampling used 32 A100 80GB GPUs with vLLM. Software versions, paper-run seeds, wall-clock cost, and exact checkpoint hashes are not disclosed. (Appendix B.2; official training script)

**Evaluation and contamination boundary.** Inference uses vLLM at temperature 1.0, with 4-shot GSM8K, 8-shot MATH, and zero-shot evaluation elsewhere. The main reasoning suite covers GSM8K, MATH, ReClor, LogiQA, StrategyQA, GPQA, and ARC-Challenge; additional surfaces include six general benchmarks, AIME 2024, MBPP, and LiveCodeBench. Appendix C compares embedding distributions with t-SNE and average distances over 500 samples per dataset, but does not disclose item-level deduplication, benchmark-overlap removal, or immutable train/evaluation manifests.

**Released-code checks required before reproduction.** On the inspected unpinned `main` branch, the sampler allocates `traj_pool`, `prob_pool`, and `adv_pool` with `num_foresight+1` slots but `step_prob` with `num_foresight` slots; the constructor skips a record unless all four lengths are equal. It also stores `prompt` separately, while the shown ACO encoder reads only the `chosen` and `rejected` message lists. These are curator-observed handoff risks, not author-reported experimental failures. A reproduction should pin a revision, resolve both paths, confirm query conditioning, retain rejected candidates and process pools, and publish the exact selected-source and preference manifests.
