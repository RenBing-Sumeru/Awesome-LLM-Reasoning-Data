The prior baseline is split across large automatic UI datasets, Android view-hierarchy resources, screen-captioning datasets, navigation trajectories, and design-feedback datasets. Those resources are useful, but they do not all provide expert-validated, dense, element-level bounding boxes on real iOS screens with a direct JSON extraction benchmark.

MUIAnno changes the object and the contract. The object is a screen-level set of visible UI components with expert boxes and semantic classes. The contract is exact enough for automated scoring: a model must produce structured elements, and a prediction only counts when localization and label both match. The quality signal is the reported multi-stage annotation and validation process, the public dataset/tool claims, and the model comparison under one prompt/evaluation setup.

What is not new: object detection metrics, IoU matching, UI screenshot datasets, prompt-based multimodal evaluation, and JSON output constraints are all established techniques. Before reuse, inspect the HF dataset files and license, class taxonomy, coordinate convention, split policy, app screenshot rights, prompt/evaluator code, and whether public screenshots have entered training data for the model being evaluated.
