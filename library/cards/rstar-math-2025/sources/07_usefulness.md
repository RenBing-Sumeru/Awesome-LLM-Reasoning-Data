For the **Data Construction and Open Release Recipes** track, rStar-Math is useful as a modular recipe and as a release-audit case.

1. **Rebuild a search-to-SFT baseline.** Implement problem/reference ingestion, stepwise policy generation, cumulative Python execution, terminal answer equivalence, MCTS back-propagation, and Q-ranked correct-trajectory extraction. Treat the published default budgets and the checked public configs as separate variants until reconciled.
2. **Construct process-preference data.** Form shared-prefix comparisons only on mixed-outcome trees; preserve each candidate's terminal reachability, Q, margin, edit distance, policy/checker version, and search budget. These fields are needed to diagnose whether a learned preference reflects local reasoning or search luck.
3. **Compare feedback contracts.** Ablate runtime filtering, terminal checking, direct Q regression, and PPM pairwise ranking under matched generation and inference budgets. Report false accepts/rejects instead of treating execution or benchmark accuracy as verifier calibration.
4. **Design a stronger open release.** Publish the canonical prompt manifest, source/license mapping, raw tree topology, visits, Q-values, execution logs, rejected branches, round/seed/budget fields, filtering ledger, checkpoints, and immutable configs. The existing flattened schemas show precisely what is lost without these fields.
5. **Audit iterative feedback loops.** Track whether policy updates change which branches are explored and whether PPM preferences preserve shortcuts from earlier rounds. Keep train/evaluation overlap and source-derived benchmark reuse visible.

The verified code and data make the work a practical recipe and artifact-inspection starting point. Reuse classification is **partial/conditional**: the released SFT and PPM rows are directly loadable and support policy SFT and pairwise reward/process-model training, but high-assurance training reuse is blocked pending source-level license reconciliation, decontamination evidence, and row lineage. The raw release is not sufficient for tree-level reproduction, and the reported scores should be used as system evidence rather than as a certificate of dataset quality.
