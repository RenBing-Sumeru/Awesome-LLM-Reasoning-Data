The paper combines existing ingredients—MCTS, executable Python, terminal answer checking, SFT, and pairwise preference learning—into a specific self-evolving data interface. Its concrete change is not merely “more synthetic CoT.” One search tree produces two supervision products: selected correct trajectories for the policy and shared-prefix positive/negative continuations for a PPM. The PPM then changes the next round's search, so the data generator and process selector co-evolve instead of remaining fixed.

The preference formulation is also more specific than regressing a Q-value as a local correctness label. A candidate step is positive or negative according to both its search-derived Q and the terminal outcomes reachable downstream, and the released code imposes a Q-margin and edit-distance filter. This acknowledges that a noisy trajectory value is not identical to intrinsic step correctness, although the resulting preference still inherits the policy, tree, budget, and answer checker.

Several boundaries prevent overstating novelty. MCTS, program execution, rejection sampling, Bradley-Terry ranking, and iterative SFT are not introduced by this work. Round 1 depends on a 236B DeepSeek-Coder-V2-Instruct bootstrap policy, GPT-4 expands the prompt pool, and ground-truth answers remain the terminal supervisory source. The public release is an engineering integration and large-scale flattened export, not a new record schema preserving search evidence.

For reasoning-data research, the directional value is the explicit policy–verifier refresh loop and the separation between rich internal tree state and training-ready exported rows. Before reusing the claimed recipe, a curator should verify whether later revisions publish raw trees, Q/visit values, rejected branches, source mappings, paper-exact configs, and checkpoint identities; without them, the mechanism can be studied but its selection decisions cannot be replayed record by record.
