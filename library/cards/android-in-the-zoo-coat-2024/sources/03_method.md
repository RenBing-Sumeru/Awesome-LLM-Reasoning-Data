1. Inputs: Android screen-action episodes, natural-language instructions, screenshots, previous-action context, and target next actions. 2. Pipeline: build CoAT annotations for each timestep, including screen description, action thinking, next action description, and action result; package images and JSON annotations; split the data into General, Install, GoogleApps, Single, and WebShopping subsets; release demo and evaluation scripts for proprietary VLMs and open models. 3. Outputs: PNG screenshots, JSON timestep annotations, split statistics, download links, demo prompting code, and evaluation code. 4. Feedback: action-prediction metrics compare model output with the labeled next action, while CoAT fields provide process supervision. Reuse requires pinning the Google Drive/Baidu archive, repository commit, split definitions, prompt mode, model API version, action parser, and whether process fields are used for training or only prompting.
