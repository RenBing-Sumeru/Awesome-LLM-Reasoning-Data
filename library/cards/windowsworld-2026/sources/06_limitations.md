- **Task-definition release is not trajectory release.** The official repository exposes 181 tasks and a runner that can create `traj.jsonl`, screenshots, and judgments locally, but it does not publish the authors’ complete successes, failures, timeouts, execution errors, retries, or raw judge calls. Aggregate failure analysis cannot substitute for record-level retention.
- **Public status inconsistency.** The paper describes human-reviewed final tasks, yet pinned JSON marks 126 rows approved and 55 pending, with 160 validity flags true and 21 false. No release note explains whether these are stale fields, intentionally retained invalid examples, or unresolved curation states. Treating all rows as uniformly ready can propagate broken tasks.
- **Environment initialization gap.** Standard `hf_run.py` calls `env.reset()` without passing the task and does not visibly materialize `environment_setup`. Ninety-seven rows request generated files and 16 list downloadable resources. Unless the mutable VM image already contains the exact states, missing setup can turn feasible tasks into accidental failures.
- **VLM false positives and false negatives.** Qwen3-VL-Plus sees actions and screenshot history rather than authoritative application state. The paper reports false positives from occluded current state and false negatives from transiently achieved states. Closed, unpinned service revisions add temporal judge drift.
- **L4 reward hacking.** Empty action history or a final FAIL is scored as correct without validating the cause of infeasibility. An agent that refuses broadly or crashes before acting can receive credit; the paper’s UiPath analysis already shows that frequent incompletion can inflate L4 performance.
- **Checkpoint coverage is not causal supervision.** State predicates are human-reviewed and path-tolerant, but they need not capture harmful side effects, ordering constraints, or global consistency. A high `S_int` can coexist with terminal failure and does not prove that the agent followed a coherent, safe, or efficient path.
- **No split or contamination boundary.** All 181 tasks, checkpoints, final criteria, and the judge prompt are public. There is no train/dev/test split, hidden test, task-overlap audit, model-pretraining decontamination, or future submission policy. Memorization and criterion-specific evaluator gaming can grow over time.
- **Replay and version drift.** The repository has no tag or GitHub Release; the OneDrive VM has no digest; Windows, apps, URLs, accounts, model APIs, and dependencies can change. Exact paper-run snapshots, seeds, retries, prompts, costs, and result hashes are absent, preventing immutable reproduction.
- **License and external-resource boundary.** Repository code declares Apache-2.0, but the Windows image, installed proprietary applications, external URLs/downloads, and generated agent trajectories have separate or unstated rights. Availability of a link does not establish redistribution permission.
- **Scope limitations reported by the authors.** Full-trajectory execution and manually reviewed checkpoints limit large-scale or online RL; the OS interface is primarily single-language despite bilingual instructions; and MCP tools are not evaluated. Results should not be generalized to multilingual operating systems, MCP-augmented agents, training efficiency, or real-world deployment safety.
