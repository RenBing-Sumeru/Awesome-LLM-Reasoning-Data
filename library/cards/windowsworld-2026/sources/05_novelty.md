The relevant prior baseline is not “no desktop-agent benchmark.” OSWorld already provides scalable VM interaction and programmatic evaluators; Windows Agent Arena focuses on Windows execution; ProBench, SPA-Bench, and A3 motivate intermediate or process-sensitive evaluation. WindowsWorld explicitly inherits OSWorld-derived infrastructure. PyAutoGUI control, accessibility observations, LLM generation, VLM judging, and professional personas are components rather than isolated novelty claims.

The concrete change is the evaluation object. A WindowsWorld record couples a professional multi-application instruction with declarative preconditions, environment dependencies, path-essential intermediate states, a final state criterion, and an infeasible-task category. Executed episodes can therefore be compared at multiple semantic states even when final success is nearly saturated at zero. The 77.9% multi-app concentration and 27.81 average minimum expert actions for L3 make this interface a test of coordination and state persistence, not only visual grounding.

The construction recipe also changes the cost profile: persona-based DeepSeek-V3.2 generation feeds a four-node refiner, human filtering, and file synthesis with smart merging. The notable design is the linkage among task generation, setup dependency, state-based metrics, and VM execution. However, candidate counts, exact refiner/environment models, task revision histories, and synthesized setup files are not released, so automation quality cannot be reconstructed solely from the paper.

The feedback novelty is bounded. Human-verified, action-agnostic checkpoints make partial progress tolerant to alternative paths, and the authors validate Qwen3-VL-Plus against two annotators. This is more informative than final-only success, but it remains post-hoc trajectory judging. The released L4 contract is much weaker than the L1–L3 contract because it accepts a generic FAIL marker, and none of these signals is shown as a scalable online training reward.

For reasoning-data research, the directional lesson is that a trajectory dataset should bind task, environment state, visible evidence, intermediate predicates, terminal predicate, and evaluator version. WindowsWorld supplies most of that schema but not the complete executed corpus or immutable replay manifest. Reuse therefore requires separating benchmark-definition novelty from trajectory-data availability and checking task approval, setup wiring, judge drift, failure retention, split policy, and license scope.
