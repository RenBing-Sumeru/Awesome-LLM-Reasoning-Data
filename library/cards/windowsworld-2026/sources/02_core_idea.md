The contribution in one sentence is: WindowsWorld pairs paper-scale professional cross-application tasks with path-tolerant state checkpoints, so an executed GUI episode receives both partial-progress feedback and a terminal decision instead of only all-or-nothing success.

The task surface is deliberately structured. Sixteen personas in five domains seed workflows across Word, Excel, PowerPoint, Acrobat, Thunderbird, Chrome, File Explorer, system tools, multimedia tools, VS Code, PowerShell, and Windows Terminal. L1–L3 increase application coordination and conditional reasoning; L4 introduces missing files, invalid URLs, authentication, or other infeasibility so that FAIL can be a correct terminal behavior (Paper §3.2; Figure 2).

The feedback contract is mixed. For feasible L1–L3 tasks, Qwen3-VL-Plus sees the instruction, ordered action list, retained screenshots, intermediate state predicates, and final success criterion. It returns binary decisions and reasons; `S_int` averages satisfied checkpoints and `S_final` records final completion. Checkpoints are refined to remove action-specific wording and human-verified as path-essential, allowing menus, shortcuts, or other valid paths. For L4, however, released `hf_run.py` bypasses the VLM and returns success when the action list is empty or the last action is recognized as FAIL.

This judge can observe visible trajectory evidence and semantic task criteria, but not all underlying application state. The paper’s validation identifies false positives when history appears successful while the current GUI state is occluded, and false negatives when a target state was achieved briefly but later becomes invisible. The L4 rule observes even less: it verifies the FAIL marker, not the reason for infeasibility. Intermediate labels are therefore diagnostic state judgments, not causal per-action ground truth.

OSWorld is the nearest environment lineage: WindowsWorld reuses OSWorld-derived infrastructure but concentrates on professional cross-application coordination and explicit process checkpoints. ProBench, SPA-Bench, and A3 motivate process-aware or step-state evaluation, but WindowsWorld’s distinguishing data interface is a Windows VM task with multiple applications, path-tolerant semantic checkpoints, and an infeasible-task level. The novelty is this integrated evaluation surface; PyAutoGUI, VMs, LLM task generation, VLM judging, and checkpoint decomposition are individually established components.
