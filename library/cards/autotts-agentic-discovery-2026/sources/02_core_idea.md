AutoTTS changes the object that a researcher designs. Instead of prescribing a particular test-time heuristic, the researcher specifies a discovery environment with states, actions, feedback, and an objective; an explorer then writes controller code inside that environment. In the width-depth instantiation, a controller sees active branches, their current depths, revealed probe answers, and remaining budget, then decides whether to branch, continue, probe, prune, or answer.

The key enabler is offline replay. The base model's candidate trajectories and intermediate probe signals are collected once, so a proposed controller can replay its decisions against a fixed matrix rather than calling the model again. Beta parameterization forces each controller to expose one monotone budget knob, while execution traces reveal how computation was allocated. Together, these choices make strategy discovery a controllable search over the accuracy-token frontier rather than a collection of incomparable manually tuned rules.
