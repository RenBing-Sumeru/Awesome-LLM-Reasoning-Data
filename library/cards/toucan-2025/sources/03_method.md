The core construction is a five-stage pipeline.

1. **MCP onboarding.** Crawl roughly 2,800 server specifications from GitHub and Smithery, keep 871 credential-free servers supporting streamable HTTP, then test sampled tools and retain 495 functioning servers exposing more than 2,000 tools. LLM-generated domain labels organize servers but are not a human-verified ontology.
2. **Task synthesis.** Mistral-Small, DevStral-Small, GPT-OSS, Kimi-K2, and Qwen3-32B generate tasks under single-server, multi-server, and 25 manually selected featured-server strategies. Reported experiments use at most three target tools. Formatting cleanup and embedding deduplication are applied; public code defaults to cosine-distance threshold 0.1, but the historical production value is not confirmed.
3. **Task review.** Kimi-K2 assigns reasoned 1-5 scores for tool-selection difficulty, tool-selection uniqueness, question quality, scenario realism, verifiability, and stability. The judge choice is supported by a 50-example human comparison with reported Pearson correlation 0.264, which is calibration evidence rather than proof of label accuracy.
4. **Live rollout.** GPT-OSS-120B, Kimi-K2, and Qwen3-32B execute through Qwen-Agent or OpenAI Agents against remote MCP endpoints. The episode preserves native system/tool declarations, user messages, assistant tool calls, tool/function responses, and a final answer. Exact per-row model/framework pairing, decoding, seed, endpoint revision, retries, and collection time are not exposed.
5. **Trajectory review and packaging.** Public rules require an initialized agent, ordinary tool use, at least one meaningful tool response, no assistant error marker, a non-empty final answer, and no exclamation mark in assistant messages. Partial tool failures may remain if another call succeeds. Target-tool coverage and order use substring name matching. GPT-OSS-120B gives 1-5 completeness and conciseness scores. Three extensions then produce irrelevance examples with zero tool calls, persona/constraint diversification with the same target tools, and multi-turn tasks via subquestions or follow-ups.

The three full configurations contain 518,516 Kimi-K2, 457,130 OSS, and 551,613 Qwen3 episodes, totaling **1,527,259**. SFT selection requires question quality 5, scenario realism 5, completeness at least 4, conciseness at least 4, and target-tool coverage 1.0, followed by category rebalancing. This yields **119,287 rows**, approximately 28.3K core, 40K irrelevance, 15.8K diversified, and 35.2K multi-turn examples. That SFT config is a selected subset, not an additional unique trajectory partition.

The only demonstrated training use is supervised fine-tuning of Qwen2.5-7B-Instruct, Qwen2.5-14B-Instruct, and Qwen2.5-32B-Instruct with the Hermes tool-call template, learning rate 2e-5, two epochs, effective batch size 64, AdamW, DeepSpeed ZeRO-3, and maximum sequence length 32,768. Public runner defaults include temperature 1.0, top-p 1.0, 32,768 maximum tokens, a 90-second item timeout, and ten turns for the OpenAI-agent runner, but the paper does not bind these defaults to the released corpus.
