The benchmark measures execution-free judgments of functional correctness, so it does not assess maintainability, security, explanation quality, or project-level constraints. Its labels rely on the selected tests and ground-truth outputs; an inadequate test suite can miss semantically wrong programs. Frontier-generated pairs may age as generators and benchmarks change, and order sensitivity itself means a single prompt run is not a sufficient audit. Reusers should execute additional hidden tests and report both presentation orders. Moreover, candidates come from specific generators; errors and difficulty may differ substantially for human code or tool-use traces.
