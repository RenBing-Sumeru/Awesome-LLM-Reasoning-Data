A team selecting a code judge can load the three released task splits, run each candidate judge on both response orders, and compare accuracy against the verified good/bad label. The output is a task-specific score plus an order-robustness report; success requires accuracy above a chosen baseline and small swap-induced disagreement. Researchers can also use the pairs to compare pairwise and scalar prompts before deploying response ranking. Do not treat it as a replacement for executing code when a safe execution environment or security review is available. Deployment logs should retain candidate order, raw responses, and preprocessing version so inconsistent cases can be replayed instead of retaining only an aggregate accuracy.
