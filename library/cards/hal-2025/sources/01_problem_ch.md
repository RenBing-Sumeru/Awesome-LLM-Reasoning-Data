本卡片特指 **Holistic Agent Leaderboard: The Missing Infrastructure for AI Agent Evaluation**：arXiv:2510.11977v1 于 2025-10-13 首次提交，OpenReview 标识为 `vUaY1t64ZZ`，并被 ICLR 2026 接收为 Poster。“HAL”本身具有歧义，因此必须用 exact title、arXiv 标识、作者名单和 venue 记录共同消歧。Atlas 依据首次公开论文记录保留 `hal-2025` 与 2025 年，同时把后续接收 venue 写为 ICLR 2026 Poster。

论文处理的是评测基础设施问题，而不是新的 policy-training recipe。此前的 agent evaluation 分散在各 benchmark 自有的安装、scaffold interface、model-provider setting、task runner、log format、scoring code 与 cost accounting 中，因而难以在一致运行界面上比较 model-scaffold 组合，也难以从论文分数追溯到 model call、tool call、evaluator output 和执行条件，更难解释一次运行为何成功或失败。HAL 在论文时期把四个领域中的九个既有 benchmark 统一到 common harness 与 leaderboard：web navigation、scientific research、software engineering/coding 和 customer service（Paper §§1–3；Appendix A2）。

一个 HAL evaluation unit 仍然是 benchmark-specific 的，并非统一的 normalized row。benchmark 提供 task identifier、task data/file、runtime constraint，以及 gold answer 或 scoring procedure；agent 实现最小接口 `run(input, **kwargs) -> dict`，返回 benchmark-specific submission。harness 可通过 Weave 记录与 task 关联的 call graph，包括 call/parent identifier、operation name、timestamp、input、output、exception、API attribute、usage summary 和 `weave_task_id`。随后，一个 run archive 汇集 configuration 与 Git lineage、aggregate result、raw evaluator output、raw logging output、usage/cost total，有时还包含 raw submission。state、action、observation、answer、evaluator 与 terminal semantics 仍随 benchmark 而变。

该对象属于 `environment_agent_trajectory_data`，因为 environment、tool/model interaction、task evaluator、failure state、cost 和 lineage 都是记录的一部分。它不是单一可回放 environment package，不是同构的 Hugging Face table，不是 universal reward function，也不能证明轨迹适合 SFT、reward-model training、RLVR 或 agent-policy training。现有证据只支持 evaluation 与 post-hoc behavior audit。
