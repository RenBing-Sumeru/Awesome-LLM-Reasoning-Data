The Card refers specifically to **Holistic Agent Leaderboard: The Missing Infrastructure for AI Agent Evaluation**: arXiv:2510.11977v1, first submitted on 2025-10-13, OpenReview `vUaY1t64ZZ`, and the accepted ICLR 2026 Poster record. “HAL” by itself is ambiguous, so the exact title, arXiv identifier, author list, and venue record jointly define the paper identity. The atlas keeps `hal-2025` and year 2025 for the first public paper record while recording the later accepted venue as ICLR 2026 Poster.

The paper addresses an infrastructure problem rather than proposing a new policy-training recipe. Agent evaluations were distributed across benchmark-specific installations, scaffold interfaces, model-provider settings, task runners, log formats, scoring code, and cost accounting. That fragmentation makes it difficult to compare model-scaffold combinations under a consistent operating surface, inspect why a run succeeded or failed, or trace a published score back to model calls, tool calls, evaluator outputs, and execution conditions. HAL supplies a common harness and leaderboard over nine existing benchmarks in four paper-era domains: web navigation, scientific research, software engineering/coding, and customer service (Paper §§1–3; Appendix A2).

One HAL evaluation unit is benchmark-specific rather than a universal normalized row. A benchmark provides a task identifier, task data/files and runtime constraints, plus a gold answer or scoring procedure. An agent implements the minimal `run(input, **kwargs) -> dict` interface and produces a benchmark-specific submission. The harness can record a task-linked call graph through Weave: call and parent identifiers, operation names, timestamps, inputs, outputs, exceptions, API attributes, usage summaries, and `weave_task_id`. The run archive then combines configuration and Git lineage, aggregate results, raw evaluator output, raw logging output, usage/cost totals, and sometimes raw submissions. State, action, observation, answer, evaluator, and terminal semantics remain benchmark-dependent.

This object belongs in `environment_agent_trajectory_data` because the environment, tool/model interactions, task evaluator, failure state, cost, and lineage are first-class parts of the record. It is not a single replayable environment package, a homogeneous Hugging Face table, a universal reward function, or evidence that the trajectories are suitable for SFT, reward-model training, RLVR, or agent-policy training. The demonstrated uses are evaluation and post-hoc behavior audit only.

The L4 content boundary is supported by the full paper and appendix, official OpenReview/ICLR records, the archived `princeton-pli/hal-harness` repository at commit `16bb03ebc11577fb5ea6dc8bb6c968387085e6aa`, the project page, the complete Hugging Face file-tree enumeration at SHA `e7dcedc82b4f4bc819a170fd6616bdb44841c71e`, and schema inspection of two decrypted official archives. This evidence is sufficient to describe the object and pipeline, but not to claim corpus-wide schema uniformity, deterministic replay, licensing, privacy clearance, or a frozen mapping between the paper experiment and the current release.
