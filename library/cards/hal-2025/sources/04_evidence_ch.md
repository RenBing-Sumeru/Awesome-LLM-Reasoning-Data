论文的主要 operational evidence 是跨 benchmark 的 evaluation run，而不是“发布轨迹已成为高质量训练数据”的证明。论文报告九个 benchmark、九个 headline model 上共 **21,730 个 agent rollout**，language-model call 超过 **2.5B token**，evaluation cost 约 **40,000 美元**（Abstract；§§1、3）。Appendix A4 描述 **186 个 run**，其中 142 个 model-scaffold-benchmark combination 进入主分析，另有 44 个 incomplete-matrix addition。然而，Appendix A10 给出的九个 per-benchmark run count 相加只有 **184**，论文与 release 均未解释这两个 run 的差异。

自动行为分析构成另一层证据。Docent 最初覆盖 AssistantBench、TAU-bench、CORE-Bench 与 SciCode 上 48 个 model-scaffold pair、2,184 个 transcript；从 reliability/failure analysis 中排除 TAU-bench 后，剩余 36 个 pair 与 1,634 个 transcript（Appendix A7.1）。对选定的 rubric/benchmark combination，人工至少检查 30 个 flagged run。Table A2 报告 AssistantBench instruction following 的 precision 为 0.87（`n=49`）、CORE-Bench verification 为 1.00（`n=31`）、TAU-bench instruction following 为 0.94（`n=36`）。这些数字只验证选定 positive flag 的 precision，不估计 false-negative rate 或整体 label accuracy。

最强的 negative result 是 trace-analysis 路径发现的 evaluation-integrity failure。官方 TAU-bench Few Shot scaffold 从 `few_shot_data/MockAirlineDomainEnv-few_shot.jsonl` 载入了实际 benchmark test example；HAL 因此丢弃了约 **1,000 美元**的受污染 evaluation run（Appendix A5）。论文还报告 AssistantBench 中 agent 在 Hugging Face 或 arXiv 找到 benchmark answer 的行为。这些案例说明 evaluator 可能因泄漏或检索到的答案而被满足，而不是因预期能力；log 能暴露 final score 隐藏的 contamination。

release 检查证明具体 run/call record 确实存在，但结论只限于已检查范围。在 Hugging Face SHA `e7dcedc82b4f4bc819a170fd6616bdb44841c71e` 下，官方 repository 含 **380 个加密 ZIP archive**与 `.gitattributes`，总计 **113,072,877,091 bytes**。两个 archive 通过官方机制解密：抽检 SciCode bundle 保留 2 个 successful 与 63 个 failed task identifier，并有 288 个 raw Weave call；抽检 CORE-Bench bundle 保留 45 个 failed task identifier 与 57 个 task-linked log。两者都暴露 configuration/result/evaluator/log/usage/cost/lineage 材料。该 spot check 只证明成功与失败 outcome 都可能被保留，不能证明全部 archive schema 统一或 corpus 完整。

三个规模数字对应不同对象，不能混用。论文实验报告 21,730 个 rollout；2026-07-20 核验时，project front page 显示 **26,597 个 rollout**与九个 benchmark；当前 HF repository 则含 380 个 run archive、约 113 GB。一个 archive 是 run bundle，不是一个 rollout；也没有 frozen manifest 把可变 project/release state 映射回全部论文时期 rollout。benchmark score 只支持报告条件下的相对 evaluation outcome，不能证明 release completeness、verifier correctness、replayability 或 data quality。

证据还有统计边界：高成本使多数 evaluation 只有 single run，没有 statistical validation（Appendix A3）。GAIA 与 AssistantBench 使用 public set，SWE-bench Verified Mini 只用 500 个 task 中的 50 个，论文使用原始 TAU-bench 而不是 tau2-bench（Appendix A4.1）。Docent failure flag 只是相关性信号；作者明确指出，验证 causal repair 需要 checkpoint state、修正 flagged failure 并 replay 剩余 episode（Appendix A4.2）。
