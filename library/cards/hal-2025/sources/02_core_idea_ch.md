HAL 的核心贡献，是在保留各 benchmark 自有 task 与 scoring semantics 的前提下，为异构 agent benchmark 提供统一的 orchestration、logging、evaluation、cost accounting 与 publication surface。这个 common surface 有意保持轻量：benchmark 提供 task 与 evaluator；agent 通过 `run(input, **kwargs) -> dict` 把 input 映射为 submission；local、Docker 或 per-task Azure VM backend 执行任务；Weave 捕获 model/tool call；adapter 运行该 benchmark 的 evaluator；leaderboard 再把 accuracy 或 task score 与 token、美元成本和 latency 一起汇总。

因此，发布的数据对象是一套分层结构，而不是单一 training-record schema。在 task/call 层，Weave log 可保存 operation name、trace/parent-call identifier、task linkage、timestamp、model/tool input 与 output、exception、attribute 和 usage。在 episode 层，benchmark adapter 给出 final submission、success/failure 或 scalar/subtask score，以及 environment-specific observation。在 run 层，官方 release 中已检查的 `_UPLOAD.json` bundle 包含 `config`、`results`、`raw_eval_results`、`raw_logging_results`、`total_usage`、`total_cost` 和 `git_info`。论文与抽检 bundle 都不能证明每个 archive 具有完全相同的字段。

反馈契约是 **mixed 且 benchmark-specific** 的。gold-answer comparison、unit test、environment-state predicate 或 benchmark-specific scoring 判断最终 task outcome；HAL 再报告 effectiveness、cost 与 latency。另一条 audit 路径会去除冗余 Weave call，把清理后的 transcript 与 benchmark metric 送入 Docent，以自然语言 decision-tree rubric 表达行为问题，并使用 GPT-5 Medium 作为 LLM judge。rubric flag 覆盖 instruction following、tool-use failure、environmental barrier、self-correction、verification 和 cheating/gaming。这些是 post-hoc annotation，不是统一的 HAL-wide reward，也不是已验证的 training target。该反馈能观察已记录的 action、output、evaluator result 和 rubric 可见行为，却不能保证未被 instrumentation 捕获的 call 一定存在、benchmark success 一定代表预期 reasoning，或某个 failure flag 与失败 episode 具有因果关系。

最接近的比较对象不是另一个统一 dataset，而是九个底层 benchmark stack——Online Mind2Web、AssistantBench、GAIA、CORE-Bench Hard、ScienceAgentBench、SciCode、SWE-bench Verified Mini、USACO 与 TAU-bench Airline——以及各自的 task-specific scaffold 与 evaluator。HAL 不替代这些 task，也不声称创建了统一 prompt corpus；它改变的是跨 benchmark 的 execution/provenance 层：统一 interface、多种 backend、common call logging、cost/latency accounting、run packaging 和共享的 behavioral-audit path。task 含义与 terminal correctness 仍由各 component benchmark 决定。

对 reasoning-data 研究而言，方向信号是 agent benchmark 可以暴露 final score 之外的对象：task-linked action/call trace、environment/evaluator response、error、success/failure、cost 与 run lineage 可以被联合审计。同样重要的边界是：基础设施整合和 trace 发布本身，并不会自动得到 frozen、licensed、privacy-reviewed、replayable 或 training-ready corpus。
