The prior-work baseline is a collection of strong but separate agent benchmarks, each with its own task schema, scaffold assumptions, runner, evaluator, model API configuration, reporting format, and cost visibility. A conventional leaderboard can expose final scores while leaving the underlying model/tool calls, task failures, environment errors, and run lineage inaccessible or incomparable. The component tasks and evaluators already existed before HAL.

HAL changes the infrastructure layer. It defines a minimal agent interface, runs benchmark/scaffold/model combinations through shared local, Docker, or Azure execution paths, records model and tool calls with task linkage through Weave, aggregates task effectiveness with tokens, dollar cost, and latency, packages run-level provenance and raw evaluation/logging material, and applies a common Docent-based path for post-hoc behavior analysis. The result is not one normalized dataset; it is an interoperable harness plus a heterogeneous corpus of run archives whose task and feedback semantics remain native to the underlying benchmarks.

The concrete new data object is the auditable connection among configuration, calls, evaluator outputs, costs, errors, and Git/run lineage across benchmark families. The concrete feedback-interface change is the separation of two layers: benchmark-native outcome verification and an optional LLM-judged behavioral rubric over cleaned transcripts. This makes it possible to ask whether failures come from tool use, environmental barriers, lack of self-correction or verification, instruction-following problems, or gaming, while retaining the task-level evaluator outcome.

Several components are integration rather than methodological inventions. HAL does not create the nine benchmark task sets, their gold answers/unit tests/environment predicates, the named agent scaffolds, Weave telemetry, Docent, or GPT-5 Medium. It does not introduce a policy optimizer, a universal terminal predicate, a new RL reward, or a documented training-data filter. The paper's scale—21,730 rollouts and more than 2.5B model-call tokens—expands the empirical comparison, but scale alone is not evidence of corpus quality.

The direction signal for reasoning data is operational: publish the episode's source, behavior, feedback, selection, cost, and lineage together, and use trace inspection to audit what final metrics conceal. Before reuse, however, the integration must be paired with a frozen paper-snapshot manifest, benchmark-aware schema documentation, release licenses, privacy/redaction policy, failed/partial-run accounting, pinned environment/provider dependencies, and judge calibration. Without those checks, the novelty remains valuable evaluation infrastructure and audit evidence rather than a training-ready data recipe.
