论文时期可重建的 pipeline 如下：

1. **输入与配置。** 从九个既有 benchmark 中选择一个及其 task subset，与 task-specific 或 generalist scaffold 配对，配置 hosted model endpoint 与 reasoning setting，并记录 benchmark/agent argument 和 run identifier。headline analysis 覆盖 Claude Opus 4.1、Claude 3.7 Sonnet、o3、GPT-4.1、GPT-5 Medium、o4-mini、DeepSeek R1、DeepSeek V3 与 Gemini 2.0 Flash，另有 reasoning-effort variant 与 appendix configuration。provider-side model snapshot 并非都能不可变固定。
2. **Agent 集成。** 把 scaffold 适配到最小 Python 接口 `run(input, **kwargs) -> dict`。task-specific 系统包括 Browser-Use、SeeAct、Open Deep Research、CORE-Agent、SAB Self-Debug、SciCode tool-calling/zero-shot variant、SWE-Agent 与 USACO Episodic+Semantic。HAL 还评测了基于 smolagents CodeAgent 的 generalist scaffold。
3. **执行环境。** task 可在 local、Docker 或 per-task Azure VM 中运行。local execution 不带 sandbox；Docker 提供轻量隔离；Azure 支持可扩展并行、configured timeout、artifact/log collection 与 cleanup。实际 browser、repository、scientific-computing、search 或 simulated customer-service state 仍由 benchmark 决定。
4. **轨迹捕获。** 使用 Weave instrumentation 记录 model API 与 tool call。`weave_task_id` 把 call 关联到 task，trace/parent ID 可还原 call graph；可记录字段包括 API parameter、input、output、exception、timestamp、usage 与 storage summary。instrumentation failure 仍可能造成 call 缺失。
5. **验证与汇总。** 把 agent submission 交给 benchmark adapter 的 gold-answer check、unit test、environment predicate 或原生 scoring logic；在 adapter 提供时保留 task-level output 与 score，再汇总 accuracy 或 benchmark score、token/美元 cost 和 latency。九个 benchmark 之间不存在统一 terminal predicate 或 scalar reward。
6. **过滤与分析选择。** 论文 Section 4 的主分析保留 142 个 model-scaffold-benchmark combination，并把另外 44 个组合视为 incomplete matrix。Docent 发现官方 demonstration file 含 test example 后，TAU-bench Few Shot 结果被剔除。这些是 evaluation-integrity decision，不是 training-data rejection sampling。
7. **行为审计。** 去除冗余 Weave call，把清理后的 transcript 与 benchmark metric 上传到 Docent，为各 benchmark/rubric 构造自然语言 decision tree，并用 GPT-5 Medium 作为 judge。论文最初分析来自四个 benchmark、48 个 model-scaffold pair 的 2,184 个 transcript；把 TAU-bench 从 reliability/failure analysis 中移除后，剩余 1,634 个 transcript 与 36 个 pair。
8. **打包与发布。** 把 run configuration、result、raw evaluator record、raw Weave log、usage/cost total、Git metadata 与可选 raw submission 聚合到 `_UPLOAD.json`/相邻材料中。upload utility 使用公开固定密码 `hal1234` 将每个 bundle 加密为 ZIP，再上传到官方 Hugging Face repository。由于 key 是公开的，这只是 scraping deterrent，不是 access control。

论文报告 21,730 个 rollout、超过 2.5B model-call token、约 40,000 美元与 186 个 run。HAL Generalist Agent 每四步 planning 一次，最多 200 步；Anthropic high reasoning 通过 LiteLLM 映射为 4,096 token，而 OpenAI reasoning-token budget 未披露。temperature 为 unknown，也没有适用于全部 configuration 的统一 sampling 或 inference budget。高成本使多数 evaluation 只有 single run，缺少 statistical validation。

复现时必须固定 paper/arXiv version、harness commit、benchmark revision 与 task subset、scaffold/model argument、dependency 与 runner image、provider endpoint behavior、reasoning setting、credential assumption、timeout/retry logic，以及 Weave/Docent configuration。run ID、command、Git metadata、`--run_id` 与 `--continue_run` 有助于 lineage 和 continuation，但无法让 dynamic website/API、hosted model、benchmark service 或未固定 VM/container state 实现 deterministic replay。当前也没有 corpus-level manifest 把论文的 21,730 个 rollout 映射到 archive name 与 checksum。
