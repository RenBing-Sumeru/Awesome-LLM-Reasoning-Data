prior-work baseline 是一组能力很强但彼此独立的 agent benchmark：每个 benchmark 都有自己的 task schema、scaffold assumption、runner、evaluator、model API configuration、reporting format 与 cost visibility。传统 leaderboard 可以暴露 final score，却可能让底层 model/tool call、task failure、environment error 与 run lineage 不可见或不可比较。HAL 的 component task 与 evaluator 都在此前已经存在。

HAL 改变的是 infrastructure layer。它定义最小 agent interface，通过共享的 local、Docker 或 Azure execution path 运行 benchmark/scaffold/model combination，以 Weave 记录带 task linkage 的 model/tool call，把 task effectiveness 与 token、美元 cost 和 latency 联合汇总，打包 run-level provenance 与 raw evaluation/logging material，并提供统一的 Docent-based post-hoc behavior analysis 路径。结果不是一个 normalized dataset，而是 interoperable harness 加上 heterogeneous run-archive corpus；task 与 feedback semantics 仍来自底层 benchmark。

具体的新 data object，是跨 benchmark family 把 configuration、call、evaluator output、cost、error 与 Git/run lineage 连接为可审计记录。具体的 feedback-interface 变化，是把 benchmark-native outcome verification 与对 cleaned transcript 的可选 LLM-judged behavioral rubric 分成两层。研究者由此可以在保留 task-level evaluator outcome 的同时，检查 failure 是否与 tool use、environmental barrier、缺少 self-correction/verification、instruction-following problem 或 gaming 相关。

多个组件属于工程整合，而不是新的方法发明。HAL 没有创建九个 benchmark task set、其 gold answer/unit test/environment predicate、具名 agent scaffold、Weave telemetry、Docent 或 GPT-5 Medium；也没有引入 policy optimizer、universal terminal predicate、新 RL reward 或已记录的 training-data filter。论文的 21,730 个 rollout 与超过 2.5B model-call token 扩大了 empirical comparison，但规模本身不是 corpus quality 的证据。

对 reasoning data 的方向信号是 operational 的：把 episode 的 source、behavior、feedback、selection、cost 与 lineage 一起发布，并用 trace inspection 审计 final metric 隐藏的问题。但在复用前，还需要 frozen paper-snapshot manifest、benchmark-aware schema documentation、release license、privacy/redaction policy、failed/partial-run accounting、固定的 environment/provider dependency 与 judge calibration。缺少这些检查时，该工作应被视为有价值的 evaluation infrastructure 与 audit evidence，而不是 training-ready data recipe。
