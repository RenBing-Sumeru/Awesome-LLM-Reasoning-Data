FVQA-auto-vc begins with 10,000 visual concepts sampled from the head and tail of MetaCLIP metadata. For each concept, web search supplies an image and associated page; GPT-4o generates a concise factual VQA pair and classifies its knowledge type. Category balancing yields 6,000 items, split as 5,400 training and 600 test candidates. A parallel route maps InfoSeek training questions into the same taxonomy and selects 7,000 items. Human annotators add 800 questions by choosing a category, locating an image, searching for supporting information, and writing a concise answer.

Search balancing uses a Qwen2.5-VL-7B model trained on the collected pool. It generates eight rollouts per question. Questions for which all eight fail are discarded. An item is labeled image-, text-, or mixed-search-required when correct answers occur only with the corresponding search behavior; any correct no-search rollout makes it search-free. The final FVQA-train contains 5,000 items—about 3,400 search-required and 1,600 search-free. FVQA-test contains 1,800 manually verified or human-authored items: 600 held-out auto-vc, 600 InfoSeek Human Split items with newly annotated answers, and 600 manual items.

RL uses Qwen2.5-VL-7B-Instruct and modified GRPO. Each training step samples 512 questions with eight rollouts each; an episode allows up to three dialogue rounds and two searches, with image search allowed only in round one. Image search returns up to five thumbnail–title webpage results. Text search uses SerpApi, Jina Reader, and Qwen3-32B summaries for up to five pages. Model actions use named reason, image-search, text-search, and answer spans; returned evidence uses a named information span and is excluded from policy loss. Exact-match correctness is binary; a correct answer that used search receives a 0.1 penalty factor, and the format component has weight 0.1.
