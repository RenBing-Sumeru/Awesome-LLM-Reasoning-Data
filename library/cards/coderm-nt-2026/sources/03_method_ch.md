1. **建立搜索状态。** 对每道 Python 题，Qwen2.5-Coder-32B-Instruct 生成代码；系统按缩进边界和 LLM 插入的 print 语句切分，代码前缀成为 MCTS 节点。

2. **扩展并判断执行。** MCTS 以 UCT 选择节点，令 LLM 补全前缀、插入诊断打印和示例调用后执行。LLM judge 阅读题目、代码和轨迹，给出0–1分并回传；没有单元测试决定样本去留。

3. **构造奖励监督。** 收集非根节点的题目、部分或完整响应及 Q 值。12,000道 Magicoder 题中各6,000道形成196,098条标量记录和71,205个有序响应对。

4. **训练和应用模型。** 以 Qwen2.5-Coder-7B-Instruct 为骨干，先用 MSE 拟合标量奖励，再以对比损失训练响应对。GRPO 时只为完整策略输出打分；也可对每题采样8个响应取均分，按由易到难排序。

复现须固定 MCTS prompts、执行沙箱、Qwen2.5-Coder-32B 生成器兼 judge、数据版本和 RL 配置；随机种子、完整计算预算和奖励数据文件格式未完全披露。
