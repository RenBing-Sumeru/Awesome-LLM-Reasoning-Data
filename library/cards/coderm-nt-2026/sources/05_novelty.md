Earlier code-RL systems use ground-truth tests or synthesize tests and then attempt to verify them; both make the test oracle the reward bottleneck. CodeRM-NT instead searches over code prefixes and has an LLM judge the instrumented execution trace, turning node values into scalar and pairwise reward data. Its distinct change is therefore the construction of supervision from partial execution evidence, rather than merely adding another code reward model or using MCTS. The benefit depends on the judge's ability to interpret traces.
