The paper was first posted to arXiv in 2025, revised as arXiv v2 on 2026-02-26, and published at ICLR 2026. This dual date matters: `toolathlon-2025` preserves the paper's first-release identity, while the venue field records the archival conference. The work asks how to evaluate language agents on realistic tasks that require many dependent tool calls, cross-application state changes, and recovery from noisy observations, rather than on a single API invocation or a static answer (Paper §§1–2; official ICLR and OpenReview records).

The benchmark contains 108 concise, deliberately fuzzy long-horizon tasks over 32 MCP-server/application surfaces, 604 MCP tools, and 7 local toolkits exposing 16 additional tools. A task exposes an average of 69.9 tools, with a range of 28–128; 72 of the 108 tasks have scripted state initialization and/or an initial workspace. The environments mix remote services with locally containerized applications such as Poste.io, Canvas, Kubernetes, and WooCommerce (Paper Table 2, p. 6; §§2.2–2.4).

The unit of analysis is not merely a prompt or final answer. A benchmark instance couples a fuzzy user instruction with `task_config.json`, a selected tool surface, optional preprocess or initial-workspace assets, task-specific ground truth, and an evaluation script. Running an agent produces an ordered user/assistant/tool history with tool calls, environment responses, execution status, timing, token and cost statistics, followed by a separate evaluator record. Thus the data object is an environment episode, while the correctness label is attached to the final state rather than to every state-action transition.

This distinction places the work in `environment_agent_trajectory_data`; the released episode preserves interaction with a mutable external substrate. It also belongs in `benchmarks_evaluation_surfaces` because each task defines an executable terminal scoring surface. It does not provide a post-training recipe, a step-level process-reward corpus, or evidence that the trajectories are licensed for training. The later gated Toolathlon-Verified release explicitly prohibits model-training use.

The Card is content-complete for bilingual L4 screening from the full paper and appendices plus official venue, project, code, and dataset artifacts. Its canonical metadata remains at the accepted `L3_summary_ready` level because raw gated archives, detailed decontamination files, general-purpose licenses, evaluator error rates, and an immutable cross-artifact replay manifest remain unavailable or unknown.
