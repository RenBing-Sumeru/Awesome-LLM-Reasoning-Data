**输入与任务构建。** 研究人员和高年级计算机专业本科生先从 50 多个候选应用中自由寻找需求，再有针对性地补充重要但覆盖不足的应用。他们把这些需求改写为简洁、模糊的任务，使预期行为需要从环境、示例、文档或模板中推断。经过数周检查、过滤和细化，最终任务池包含 108 个任务。论文报告每个任务平均需要研究生投入 4–6 小时实现；随后由 5–6 名有经验的作者审核和修改，每轮检查每个任务约投入 5 小时，最后再做全 benchmark 交叉检查和 bug 修复（论文第 3.1–3.2 节，第 5–7 页）。拒绝数量、逐任务来源 URL、贡献者身份、reviewer agreement、裁决记录与 acceptance threshold 均为 unknown。

**可执行任务 bundle。** 一个已发布任务目录可能包含英文或中文 task/系统级指令、`task_config.json`、preprocess script 或 initial workspace、ground-truth workspace/state，以及 `evaluation/main.py`。配置为每个任务选择少于 10 个相关 MCP server，但会加载每个选中 server 暴露的全部工具；配置的本地工具可能包括 Python execution、web search、`claim_done`、`sleep`、超长输出导航和 context-history management。论文快照共包含 32 个 MCP server/application 表面、604 个 MCP 工具和 16 个本地工具；72 个任务具有显式状态初始化（论文表 2，第 6 页；第 2.4 节；官方仓库 `tasks/finalpool/`）。

**交互与生成。** 轨迹由被评测模型而非 teacher 生成：模型通过消息和工具调用，与远程服务及本地容器化软件交替交互。论文实验使用 OpenAI Agents SDK v0.0.15，处理 tool error，将超过 100K 字符的工具输出截断并以 10K 字符分页，还使用 context-history management；每个任务最多 100 turns（论文第 2.2 节与附录 B，第 14–15 页）。当前仓库另有 containerized/decoupled host loop 和初步 Claude Agent SDK 集成，不能把这些后续功能反投射到论文设置。论文没有披露跨 provider 统一的 temperature 或归一化 token/compute budget。

**日志与输出。** 在当前仓库 commit `3b647e60713703d653584c23ff185e3b6cd67722`，主要 episode 日志是 `traj_log.json`，不是 JSONL。它保存 resolved task config、request/session ID、开始与完成时间、tool catalog/choice、执行状态、含 assistant `tool_calls` 和工具响应的消息历史、交互/工具调用次数、token 统计、成本、resume metadata 与 history path。evaluator 写出 `eval_res.json`，包含 `pass=true/false/null` 以及 detail 或 failure；`eval_stats.json` 聚合 run-level success 与 turn statistics。论文时期字段是否完全一致以及原始 archive 是否逐 episode 完整，均为 unknown。

**验证与选择。** 交互结束后，每个任务的人工定制 evaluator 把终态与静态 ground truth 或动态获取的实时 truth 比较。只有这个 post-execution check 提供 binary terminal outcome；论文未披露 step reward。论文评测所有尝试的 episode，并未为了训练而筛选轨迹。后续 Hugging Face card 将其描述为包含成功与失败的完整轨迹，而非只保留成功样本；但原始 gated archive 未被检查，因此 corrupt-run 处理、遗漏情况与逐 episode 完整性仍为 unknown。

**评测用途与发布边界。** 论文 protocol 中，17 个模型各自对全部 108 个任务运行 3 次。Toolathlon-Verified 于 2026-06-30 发布，其 prompt、ground truth、evaluator 与 infrastructure 已有实质修改；该发布为 10 个较新模型各打包 3 次完整 108-task 运行，名义上共有 3,240 个 task-run episode。当前默认值包括每个任务 5,400 秒 timeout，以及每次 agent turn 最多 64K 输出；temperature 与 top-p 继承 provider 默认值。官方 dataset policy 仅允许 benchmark evaluation、reproducibility、auditing、error analysis 与 contamination research，并明确禁止 pretraining、continued pretraining、SFT、preference/RL post-training、distillation、synthetic training-data generation 和用于回答 benchmark 的 retrieval。

复现必须分别固定 arXiv v2、ICLR/OpenReview metadata、仓库 commit `3b647e6`、task container image、dependency、credential 与 reset procedure、remote-service 版本、每个 task/evaluator revision、provider endpoint/default，以及 Hugging Face revision `01deb377e5179d654e4282f62c0c336539480837`。当前没有一个不可变 manifest 绑定这些组件，仓库也没有 Toolathlon-Verified tag 或 GitHub Release。
