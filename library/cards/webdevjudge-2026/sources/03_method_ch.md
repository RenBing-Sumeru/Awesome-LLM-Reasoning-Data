1. **过滤来源对。** 从 10,501 个 WebDev Arena query 与成对代码输出出发，删除过短、重复、不安全、不清晰、不可行、无法部署或无效渲染的案例，保留 1,713 个候选。

2. **制作参考判断。** 抽取 700 个案例，部署两侧网页，并按意图、静态和动态二元检查构建 query 条件化树。具软件工程背景的专家标注后再人工排除，最终保留 654 个。

3. **评估 judge。** 向评审器提供代码、截图或两者，要求给出成对偏好或单答案 Likert 评分。agentic 评估使用 rubric planner、UI-TARS-1.5 executor 与 summarizer。

4. **诊断失效。** 将预测与专家标签比较，并在 502 个 WebDevJudge-Unit 可行性案例上测试。复现须固定部署、树生成、prompt、模型版本、顺序和 agent trajectory；环境版本是重要变异来源。
