**Agreement is not correctness.** The reward favors the most common Math-Verify equivalence cluster. A unanimous wrong answer can earn full reward, as the paper’s repeated-final-answer-0 case demonstrates. The difficulty window removes unanimous groups from training, but a moderately sized wrong cluster remains admissible. Majority-at-16 also does not consistently rise, so benchmark gains should not be treated as evidence that the self-reward is a correctness verifier.

**Verifier behavior is only partly auditable.** Math-Verify can normalize mathematically equivalent forms better than string matching, but extraction or grading exceptions are caught and silently treated as non-equivalence. This can fragment a correct cluster. Released run-local files do not preserve extracted answers, pairwise equivalence matrices, exceptions, selected cluster, or binary rewards, so verifier error rates cannot be measured on the reported runs.

**Paper and code disagree.** Appendix C.4 specifies a 1:3 seed/generated few-shot ratio, while code uses at most two generated examples in an eight-example context, reversing the intended balance. The paper’s shortest-answer tie-break is absent; code selects the first maximum. LLaMA and Qwen templates also drift from paper tables in micro-batches, initial KL, and 2,000 versus 7,500 instructions per iteration. No tagged paper-run config resolves these differences.

**Static snapshots do not reconstruct the online curriculum.** The most conspicuous bundled generated file has 7,532 rows, 4,730 unique normalized prompts, and 2,802 exact duplicates. Its name says iteration 4 although the main paper reports three iterations. The mixed file lacks row-level provenance. No manifest connects these files to a model checkpoint, filter state, experiment, or reported metric.

**The critical RL data are missing.** The release omits complete accepted and rejected questions, all 16 responses, extracted answers, equivalence structures, rewards, filter reasons, verifier failures, expired groups, RNG states, training logs, official checkpoints, checkpoint hashes, and paper-run manifests. Code can generate a new run, but cannot reconstruct the reported one.

**Contamination and licensing remain unresolved.** No semantic overlap scan or upstream pretraining audit is reported. A narrow exact-string comparison over inspected snapshots is not semantic decontamination. The repository code is Apache-2.0, but bundled MATH-derived/generated data have no separate dataset card or dataset-specific/per-component license statement.

**Statistical and domain limits remain.** The paper uses one fixed random seed and reports no error bars or independent RL reruns. Gains are strongest in math/STEM and modest on MMLU-Pro. The medical extension shows portability of the recipe, not safe clinical readiness; self-generated curricula can amplify seed bias, and the authors note explainability and high-impact deployment risks.

**Release versioning is mutable.** The audited default-branch commit is `f8a4f86a797b9a91b22ce53b1fdc7fea4c225693`, dated 2026-01-24, and includes post-paper additions. There is no immutable tag or GitHub Release, no official checkpoint collection, and no public run-log collection bound to the paper.
