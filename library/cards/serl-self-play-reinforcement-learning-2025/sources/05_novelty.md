SeRL’s distinctive move is to place both instruction supply and reward estimation inside the online RL loop while starting from a small domain anchor. Standard fixed self-instruction creates a static synthetic dataset; SeRL generates questions at each training step and feeds accepted questions back into later few-shot contexts. The curriculum is therefore policy-dependent rather than frozen before training.

The same current policy occupies three roles: question generator, response sampler, and source of the answer-consensus distribution. No external teacher or ground-truth label is required for generated questions at the SeRL stage. Math-Verify does not determine the correct answer; it only supplies programmatic equivalence relations so consensus can be calculated over mathematically equivalent forms rather than raw strings.

The dual-ended difficulty filter links curriculum admission to the current policy. Questions with nearly unanimous or highly fragmented answers are excluded, leaving groups expected to provide reward variation for Reinforce++. This differs from selecting only hard prompts or only high-confidence pseudo-labels. The paper’s failure analysis also makes the limitation explicit: consensus difficulty and correctness are different axes.

For data research, the novel object is the full 16-response agreement group and its evolving context, not a static list of generated questions. That object combines source seed, few-shot mixture, question-generation settings, lexical/similarity decisions, response rollouts, answer extraction, equivalence structure, rewards, iteration state, and policy revision. The official release exposes enough code to inspect this intended structure but not the actual paper-run groups.

SeRL should not be described as inventing self-instruction, majority voting, mathematical answer verification, or Reinforce++. Its contribution is their integration into a limited-seed online self-play recipe and the empirical study of that loop across two math backbones and a medical extension. The open-release lesson is equally important: an implementation plus prompt snapshots is not equivalent to publishing the evolving curriculum, verifier traces, failures, and checkpoint bindings.
