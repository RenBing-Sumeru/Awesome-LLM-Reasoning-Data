SeRL couples two loops around the same current policy. **Self-Instruction** generates new domain questions online so the curriculum can change as the learner changes. **Self-Rewarding** samples multiple answers to those questions and converts self-consensus into response-level rewards. Reinforce++ then updates the policy on the generated question-response-reward triples, and the updated policy repeats both roles.

Question generation is anchored by limited real data rather than starting from nothing. For the main math setup, 500 MATH training questions provide the domain distribution. An eight-example context combines seed questions and previously accepted generated questions. The paper’s Appendix C.4 specifies **one-fourth seed and three-fourths generated examples**, which means two seed and six generated examples when the full generated pool is available. The released code does the reverse: it samples at most two generated examples and fills the remaining positions from the seed, so later contexts contain up to two generated and six seed examples; the first context contains eight seed examples.

The online filter targets quality, diversity, and useful difficulty. It rejects candidates whose maximum ROUGE-L against the seed and current generated batch exceeds 0.7, candidates containing configured visual/file/programming keywords, candidates beginning with punctuation or non-English characters, and candidates outside 3–150 words. It then samples 16 answers and admits a question only when the fraction rewarded by majority agreement lies between 0.2 and 0.8 inclusive. This dual-ended window avoids groups with zero reward variation, but it is a learnability heuristic rather than a truth test.

Math-Verify supplies the equivalence layer. The reward implementation extracts mathematical answers, computes pairwise equivalence, counts equivalent neighbors for each response, selects a maximum-count response, and assigns reward 1 to its equivalence group. The paper says that when majority answers tie, the shortest answer should be selected to reduce verbosity. Released code instead uses `maj_count.index(max(maj_count))`, selecting the first maximum and performing no shortest-answer comparison.

The distinctive object is a self-generated, policy-dependent RL group: question, 16 full responses, equivalence graph, majority cluster, and scalar rewards. There are no process-correctness labels for reasoning steps. The “limited data” claim applies to domain seeds and generated-question labels at the SeRL stage; it does not remove pretrained model data, human prompt/filter/reward design, Math-Verify behavior, or evaluation datasets.
