OpenEQA: Embodied Question Answering in the Era of Foundation Models defines an evaluation surface in embodied-ai, open-vocabulary-qa, agent-evaluation: whether model outputs or agent trajectories satisfy the task-specific feedback contract. The primary source and artifacts are paper: https://open-eqa.github.io/; project: https://open-eqa.github.io/; code: https://github.com/facebookresearch/open-eqa; data: https://github.com/facebookresearch/open-eqa; the local metadata records the source as 2024 / CVPR 2024.

The decision boundary is benchmarks_evaluation_surfaces with roles benchmark and verification contract judgment_required, mixed. One benchmark instance is: episodic memory or active-exploration setting, environment/video or scan context, open-vocabulary question, ground-truth answer, model answer, and LLM-Match evaluation output. This is not a model-training recipe unless the paper separately releases training data; the card treats it as evaluation, audit. It matters for the atlas because the reusable object is an evaluation/data record with a named scorer, judge, verifier, reward, or environment predicate rather than an abstract capability claim.
