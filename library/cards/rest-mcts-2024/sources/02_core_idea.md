The central object is a search state, not an isolated sentence. A node stores a partial solution, visit count, and quality value; an edge appends one generated reasoning step; root-to-leaf paths are candidate solutions. The learned process value model and visit statistics decide where MCTS* spends further expansion and rollout budget.

The same searched tree is read through two feedback contracts. First, unfinished branches are pruned and completed answers are checked against a reference by string matching or GPT-4 judging; verified-correct paths become positive policy data. Second, observed reachability of a correct terminal and the minimum observed remaining reasoning distance produce scalar targets for partial solutions, which train the next value model. The process model therefore influences which data are explored before it is used to construct new labels.

This feedback can observe whether the finite search found a verified terminal from a prefix, how far away the nearest observed correct terminal is, and what value the current model assigns. It cannot establish that each retained step is logically valid, that no unobserved correct continuation exists, or that a target stays calibrated after changing the policy, verifier, or budget. Search stopping at value 0.9 is also distinct from later terminal-answer acceptance.

Relative to ReST^EM, the method adds process-value-guided search rather than filtering plain CoT only by final outcome. Relative to MATH-SHEPHERD-style random-rollout process labels, it derives targets from a structured searched tree and observed reasoning distance. Relative to TS-LLM and AlphaLLM, its distinctive data claim is mutual iteration of both policy and value model while using one tree to produce policy trajectories and process-value records. It does not claim to have invented MCTS, PRMs, or final-answer filtering in isolation.

The construction object is richer than the release object. Verified public policy data expose `instruction` and `output`; verified value data expose `prompt_answer` and `label`. Parent links, visits, competing branches, rejection reasons, and per-example search settings are absent from those tables.
