核心数据对象是搜索状态，而不是孤立句子。节点保存部分解、访问次数和质量值；每条边追加一个新生成的推理步骤；从根到叶的路径构成候选解。学习到的过程价值模型与访问统计共同决定 MCTS* 把后续扩展与 rollout 预算分配到哪里。

同一棵搜索树通过两种反馈契约生成数据。第一，剪除未完成分支，用字符串匹配或 GPT-4 判断将完整答案与参考答案核对；核验正确的路径成为正向策略数据。第二，利用“是否观测到可达的正确终点”与“观测到的最短剩余推理距离”，为部分解生成标量目标，用于训练下一轮价值模型。因此，过程价值模型不仅参与构造标签，也会在筛选之前改变被探索的数据分布。

该反馈可以观察有限搜索是否从某个前缀找到了核验正确的终点、最近的已观测正确终点有多远，以及当前模型给出的价值。它不能证明接收轨迹中的每一步都逻辑有效，不能证明未探索区域不存在正确延续，也不能保证换用另一策略、验证器或预算后目标仍然校准。价值达到 0.9 触发的搜索停止，也不同于之后的终点答案接收。

与 ReST^EM 相比，本文加入过程价值引导的搜索，而不是仅按最终结果筛选普通 CoT。与 MATH-SHEPHERD 式随机 rollout 过程标签相比，它从结构化搜索树和观测推理距离推导目标。与 TS-LLM 和 AlphaLLM 相比，其数据层特点是策略模型与价值模型共同迭代，并从一棵树同时生成策略轨迹与过程价值记录。论文并未声称单独首次提出 MCTS、PRM 或终点答案筛选。

构造对象比发布对象更丰富。已核验的公开策略数据只含 `instruction` 与 `output`，价值数据只含 `prompt_answer` 与 `label`；父子链接、访问次数、竞争分支、淘汰原因和逐样本搜索设置均不在这些表中。
