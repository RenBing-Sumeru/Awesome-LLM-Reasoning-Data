**Inputs.** Initial process-value supervision uses MATH training questions and 11,554 lean-science questions from SciInstruct. The science route extracts prefixes from supplied step-by-step solutions, assumes those solutions are reliable and concise, and treats added ChatGLM2 continuations as incorrect. The math route expands MATH questions by breadth-first search with Mistral-7B: MetaMATH, verifies terminal answers, and derives targets from the resulting trees. Later policy generation uses questions selected from MATH, GSM8K, and TheoremQA training sets; exact item IDs and proportions are undisclosed.

**Search state and selection.** For each question, a node records `(partial solution, visit count, quality value)`. Selection uses an upper-confidence score combining learned value with visit statistics. The selected partial solution receives a self-critique from the current inference model, either signaling End of Inference or advising further search.

**Expansion and rollout.** If search continues, the policy samples `b` next reasoning steps and the value model scores the new partial solutions. The highest-valued new child receives a greedy rollout; at each rollout step, multiple continuations may be proposed but only the highest-valued observed continuation is followed. Its best value updates the rollout node, and a weighted-average backup updates ancestors.

**Budget and stopping.** Appendix E.2 reports evaluation defaults `T=50`, `b=3`, rollout depth cap `m=2`, `alpha=0.5`, and end threshold `0.9`. The checked code defaults additionally expose a rollout branch count, exploration constant, and temperature, but those code defaults are not evidence for every paper-run release. Exact per-release sampling settings and per-example token budgets remain unknown. A node value at least 0.9 can stop search before reference-answer verification.

**Terminal verification and selection.** For data construction, unfinished branches are removed. Completed answers are compared with reference answers by string matching or, where learned equivalence judgment is required, GPT-4. The exact GPT-4 revision, complete judging instruction, and error analysis are not disclosed. Verified-correct complete paths become positive SFT trajectories; the official repository distinguishes these positive-only ReST-MCTS*/CoT releases from DPO baselines that also use negative samples.

**Value-target inference.** In the pruned tree, whether a correct terminal is observed downstream supplies reachability information, while the minimum observed distance to such a terminal represents progress. These quantities are converted into bounded quality values for partial solutions. The initial value model is trained with MSE and AdamW; Appendix E.1 reports learning rate `1e-6`, whereas repository instructions list backbone-specific rates that must be reconciled for reproduction.

**Mutual iteration.** The next policy trains on selected positive trajectories, and the next process value model trains on derived partial-solution targets. Both then generate the following iteration, so the sampling distribution, accepted traces, and targets co-evolve.

**Public outputs.** At the verified Hub revisions, initial PRM data contain 473,833 `prompt_answer`/`label` rows; Llama3 first-iteration policy data contain 33,722 `instruction`/`output` rows; and Llama3 first-iteration PRM data contain 673,492 `prompt_answer`/`label` rows. These files do not preserve tree topology, rejected branches, visits, terminal-verdict provenance, or per-example search settings.
