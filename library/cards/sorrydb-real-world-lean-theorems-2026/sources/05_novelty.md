Existing formal benchmarks usually curate a set of theorems and keep it static for years, optimizing comparability on standardized mathematical problems. SorryDB changes both the source and lifecycle of tasks: it does not rewrite problems manually but continuously indexes genuine `sorry` statements from active repositories, treating commits, dependencies, and Lean versions as part of each task.

Its novelty is not compilation-based verification itself. It unifies temporal freshness, project realism, and original-environment reproduction in the benchmark contract. A system optimized for one leaderboard snapshot must still solve new community obligations appearing in later nightly snapshots, reducing static-test contamination and overfitting to competition-problem distributions.
