For RL prompt curation, an SFT model samples each prompt ten times at a relatively high temperature; pass rate is used as a difficulty proxy. Automatic filters select questions requiring rich reasoning and straightforward evaluation. Multiple-choice, true/false, and proof questions are removed, and a no-CoT answer guesser removes general-QA prompts it can solve within N=8 attempts.

Long-CoT warmup uses prompt engineering to generate accurately verified paths for text and image inputs. Vanilla SFT begins with human-annotated seeds, trains a seed model, generates multiple responses, and has annotators rank and refine the best response. It also uses rejection sampling for math and coding. The report states approximately one million text SFT examples and one million text-vision examples, but does not release them.

For code RL, base Kimi k1.5 generates 50 test cases per problem using CYaRon, tests them against ten ground-truth submissions, retains a test case when at least seven agree, and retains a problem when at least nine submissions pass its selected test set. For math, the report describes a classic 800k-example reward model and an equally large CoT reward-model dataset; the latter emits step-by-step reasoning and a JSON correctness judgment.

The RL scaffold is a synchronous rollout/train loop with rollout workers, replay buffer, reward models, trainer workers, partial rollouts, Megatron, vLLM, checkpoint-engine, and a Kubernetes sandbox. Partial rollout segments are reused from the buffer; the long2short branch uses n=8 shortest rejection sampling, DPO pairs, or a separate RL phase with a shorter maximum rollout length.
