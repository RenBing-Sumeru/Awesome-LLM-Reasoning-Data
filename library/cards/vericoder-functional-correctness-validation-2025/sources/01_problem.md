Existing RTL datasets usually verify only whether Verilog compiles, not whether the circuit implements the natural-language specification. Training on syntactically valid but functionally wrong examples teaches models to produce compilable hardware with incorrect behavior. The paper therefore studies how to add functional validation while scaling RTL data, using simulation feedback to repair both code and tests. Its direct artifacts are specification–RTL–passing-test triplets and the VeriCoder model fine-tuned on them.
