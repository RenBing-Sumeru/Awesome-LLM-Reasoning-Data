Use ARES as a recipe for auditable evaluator construction: define component criteria, store query-context-answer triples, train or select a judge per criterion, keep a labeled validation set, and report confidence intervals rather than only point estimates. A reusable schema should preserve corpus version, retrieved passage IDs, generated answer, criterion, judge prediction, validation label provenance, unlabeled sample size, PPI configuration, and ranking date. It is especially useful for atlas entries that need to separate evaluation-only feedback from reward-model training data. It also provides a checklist for RAG benchmark contamination: public triples, prompts, and validation labels must be versioned.
