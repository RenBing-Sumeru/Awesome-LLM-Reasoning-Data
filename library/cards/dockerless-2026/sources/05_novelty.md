Relative to software-agent RL that executes a repository-specific test suite for every sampled patch, Dockerless learns a surrogate feedback contract from earlier execution-labeled issue/patch records and applies it in a minimal image. Relative to verifiers that judge only the prompt and patch text, it decomposes verification into dynamically generated questions, parallel read-only repository investigation, evidence-backed answers, and a final judgment. That makes repository state and evidence-gathering trajectories explicit parts of the reward-producing object.

The direction signal for the atlas is the join between two formerly separate pipelines: programmatic execution creates labels for verifier training, while complete downstream agent episodes receive a learned patch-level score for selection and GRPO. The same paper also provides a controlled comparison between global 16K-to-4K rollout selection by learned score and by executable environment reward, plus evidence of compiler-dependent gaps.

Learned code judging, ReAct-style search, rejection sampling, SFT filtering, GRPO, and test-based labeling are not individually new. The contribution is their particular reference-patch-conditioned construction and deployment recipe. It should not be described as removing execution altogether, solving reference-free verification, or establishing that learned scores are equivalent to tests.
