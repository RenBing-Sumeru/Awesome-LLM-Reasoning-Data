The SFT pool contains about 1.5M math, 1.1M coding, 2.0M science, 400K tool-calling, 1.5M conversational, 2K safety, and 5.0M multilingual samples. DeepSeek-R1-0528 generates math/science/code and safety responses; Qwen3-235B-A22B generates tool and chat data. Tool records include single-turn, multi-turn, and multi-step conversations in which Qwen simulates User, Assistant, and API Server agents; a rule layer retains only successful trajectories. Multilingual records translate English data line by line, enforce bracket extraction, and filter by language ID; safety responses pass guard models.

SFT has three stages: the broad mixture plus roughly 10% reasoning-stripped outputs for reasoning-off behavior; un-concatenated tool data to repair tool accuracy; and long-context plus traces abruptly truncated to 1–2K tokens while preserving final answers for budget control. IFEval RL uses 16K LMSYS prompts augmented with constraints and a rule verifier. WorkBench DPO generates on-policy positive/negative pairs from successful and failed tool trajectories, with correctness defined by database-state comparison. GRPO uses English HelpSteer3 contexts, generates rollouts with and without thinking, and scores them with a Qwen-based reward model. Reasoning and chat checkpoints are interpolated after a sweep.

For the 9B reasoning model, the aligned 12B parent is pruned to 56 layers and distilled with forward KL: 60B tokens at 8,192; after width pruning, 50B at 8,192, 25B at 49,152, and 1B at 262,144; then DPO, GRPO, 0.4B-token long-context KD, RLHF, and a 0.5 merge. Shorter-sequence KD uses 70% stage-2 post-training and 30% pretraining data; 262K KD uses stage-3 data only.
