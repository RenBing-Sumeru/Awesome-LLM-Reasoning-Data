For `environment_agent_trajectory_data`, OpenWebRL is a concrete schema for separating four layers: task specifications, selected SFT episodes, runtime online rollouts, and judge examples. A reusable episode record should preserve task/source/filter hashes, site/session state, screenshot and text-history policy, tool calls and environment feedback, terminal reason, format/judge/combined reward, timeout/infrastructure status, loss mask, group membership, optimizer step, checkpoint, and all model/judge/config revisions.

For SFT, the public 3,085 turn rows can train browser reasoning/tool-call formatting when grouped back into 412 trajectories. Their success-only construction is appropriate for imitation but unsuitable for studying failed recovery without additional negative episodes. Users should retain `rollout_idx`, turn index, last-turn flag, screenshot, messages, total steps, and reward metadata rather than treating each row as an independent trajectory.

For distillation and reward modeling, Judge-13K plus the released judge weights provide a starting point for reproducing a trajectory-success classifier and comparing it with GPT-4.1. Reuse requires verifying the actual train count, 500-example test split, class balance, schema, privacy, model cards, and licenses. Agreement with GPT-4.1 should be reported separately from human correctness and reward-hacking robustness.

For RLVR and agent training, the released tasks, browser harness, hybrid reward, MM-GRPO launcher, sandbox isolation, and policy weights form an executable recipe. Reproduction must choose explicitly between the 2,198-task release and 2,102-task default snapshot, pin judge and environment state, preserve loss-masked infrastructure failures, and record every generated rollout. The paper's approximately 54K trajectories cannot be reused as data until they are actually released with lineage.

For evaluation, WebVoyager, Online-Mind2Web, and DeepShop results can be reproduced only approximately on live sites. Report official success and success excluding aborted non-agent failures separately, and record site/date/region/cookie/CAPTCHA state, browser service, judge, and step budget. Current supported uses are exactly **SFT, distillation, reward modeling, RLVR, agent training, and evaluation**; preference learning, process supervision, offline RL, or safety-alignment data are not evidenced.
