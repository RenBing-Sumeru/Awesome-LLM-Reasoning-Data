OpenWebRL's core contribution is a live-browser environment-to-optimization loop: filter web tasks, collect success-filtered teacher trajectories for SFT, warm-start a visual policy, generate grouped online trajectories from the current policy, score complete interactions with a hybrid reward, and update with multimodal multi-turn GRPO. This couples the data object to both the mutable web environment and the verifier used during optimization.

The browser interface exposes 13 tools for click, hover, drag, write, key presses, scroll, navigation, wait, tab operations, and `done`. Each action returns rule-derived textual feedback from URL/tab/scroll/focus/element changes and exceptions. That feedback describes environment transition but is not an expert process label or dense learned reward.

The reward contract is mixed. Deterministic rules parse response format and check status; a binary VLM judge evaluates valid completed trajectories using the task, final answer, three recent screenshots, tool/action history, and environment feedback. A trajectory receives positive reward only when it is format-valid and judged successful; malformed format is penalized, while other incomplete/non-success cases receive zero. Judge timeout or infrastructure failure can be loss-masked, so they are not equivalent to negative policy examples.

Relative to offline web-agent imitation, the key change is current-policy data generation and full-trajectory reward inside isolated live-browser sandboxes. Relative to simple terminal exact-match verification, OpenWebRL combines format rules with semantic VLM judgment and preserves environment feedback. The judge remains fallible: the paper reports that a naive base-VLM judge yields high training reward while evaluation collapses, whereas the distilled judge tracks GPT-4.1 more closely.
