**Task filtering and SFT collection.** The paper starts from 292K WebGym tasks and removes evaluation overlap, decomposed subtasks, unstable/long-tail sites, and semantic near duplicates, yielding 15,601 SFT-candidate tasks and roughly 2.2K RL tasks. Qwen3-VL-235B-A22B-Thinking samples four live-browser trajectories per SFT seed; GPT-4.1 judges completion. Default selection keeps the shortest successful PAE-WebVoyager trajectory per task group, breaks ties by shorter response length, and caps tasks per website, producing 412 successful trajectories across 70 websites. The official SFT release expands these into 3,085 turn-level rows and publishes no failed demonstrations.

**SFT and online RL.** The reported main system uses Qwen3-VL-4B-Thinking. A three-epoch LLaMAFactory SFT warm start is followed by multimodal multi-turn GRPO. Online sampling draws groups of five current-policy trajectories per RL task, dynamically collects 48 effective groups per iteration, and discards groups with identical rewards. The rollout curriculum uses 15 steps followed by 30 steps; Appendix Table 7 reports sampling temperature 0.8, maximum response length 1,024, and context length 32,768. The paper reports about 90 iterations, 300 B200 GPU-hours, 80–100 concurrent sandboxes, and approximately 54K online trajectories.

**Environment lifecycle.** Playwright/Chromium interacts with live websites. Paper training assigns each rollout a separate Kubernetes/Orchard browser server to reduce stale cookies, crashes, leaks, and cross-trajectory side effects; public code also supports local-process and Browser-Use-hosted modes. Episodes end on `done`, budget, or failures. Exact browser image, site state, time, locale, region, cookies, personalization, CAPTCHA/anti-bot state, dependencies, and paid Browser-Use settings for paper runs are not pinned in one replay manifest.

**Reward and judge construction.** Format/status checks gate a GPT-4.1 binary full-trajectory judge. Invalid format is penalized; non-success/incomplete results are zero; judge or infrastructure failures may be loss-masked. An 8B judge is distilled from 12.5K diverse online rollouts labeled by GPT-4.1. Judge-13K exposes train data and a 500-example test file, but its complete indexed count, class balance, privacy audit, and license are unknown. Dynamic masking/filtering means generated rollout count differs from optimizer-consumed examples.

**Released RL tasks and reproduction boundary.** The official JSONL has 2,198 tasks: 1,464 `insta-v3` plus 734 `pae-webvoyager`. The repository's default launcher instead uses a filtered **2,102-task parquet snapshot**. Exact paper-run membership therefore requires a pinned manifest. Reproduction should also fix code commit, containers, browser/model/API versions, seeds, task/filter hashes, reward constants/config, judge checkpoint, optimizer launch, site/session state, and retention/masking ledger; the roughly 54K rollout corpus and full paper-run manifest were not confirmed public.
