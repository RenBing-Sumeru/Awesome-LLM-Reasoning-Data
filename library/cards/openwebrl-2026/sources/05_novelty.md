The closest baseline is offline web-agent imitation: select completed browser demonstrations and train assistant turns without collecting current-policy interaction. OpenWebRL extends this into a live environment-to-optimization pipeline in which the policy generates new multi-turn trajectories, whole-trajectory hybrid rewards determine group-relative advantages, and MM-GRPO updates the same policy. The important new data object is the optimizer-linked online episode, even though the full reported 54K set is not released.

A second change is the explicit separation between environment feedback and reward. Browser rules return textual state-change diagnostics after actions; deterministic format/status checks gate a semantic VLM judge that scores the full trajectory. This makes feedback inspectable at two layers and supports judge distillation, while also exposing how formatting, infrastructure masking, identical-reward group dropping, and teacher-judge errors alter which rollouts train the policy.

The release itself is unusually multi-part: success-only SFT turn rows, RL task specifications, Judge-13K, judge/policy weights, and browser/optimizer code. Treating these as one “trajectory dataset” would hide crucial differences. The 3,085 SFT rows must be grouped into 412 trajectories; the 2,198 RL rows are prompts rather than demonstrations; the 2,102 default snapshot is a different membership set; and the approximately 54K online rollouts remain runtime data.

The work does not newly introduce browser tools, ReAct, SFT, PPO/GRPO, Kubernetes isolation, VLM judges, or success filtering individually. Performance breadth and GPU scale are not record-quality proof. Reuse still requires a paper-bound run manifest, release/masking ledger, judge error audit, exact decontamination report, live-site replay strategy, privacy/copyright review, and explicit Judge-13K/model/site-content rights.
