The canonical source is arXiv:2606.02031v2, supplemented by the official OpenWebRL project, code repository, SFT Trajectories, RL Tasks, Judge-13K, and model releases at the revisions recorded in `paper.yaml`. OpenWebRL addresses the systems and data problem of training visual web agents with online, multi-turn reinforcement learning against live websites rather than only cloning offline demonstrations.

The primary agent episode begins with an instruction and start URL. At each turn the policy receives the current browser screenshot, active URL, viewport, tabs, and rule-derived textual environment feedback; it emits reasoning plus one or more structured browser tool calls. The main context policy retains one current screenshot while preserving prior reasoning and environment feedback as text. An episode ends on `done`, step-budget exhaustion, or environment/infrastructure/generation/format failure; `done` alone is not proof of task success.

Three released data objects must remain separate. The SFT release contains **3,085 turn-level prompt/response examples grouped into 412 successful complete trajectories**; every top-level reward is 1 and every status/terminal reason indicates successful completion, so it contains no failed demonstrations. The RL release contains **2,198 task specifications**—1,464 `insta-v3` and 734 `pae-webvoyager`—but no actions, screenshots, rewards, or terminal states. Judge-13K supplies judge train data plus a 500-example test file, while the roughly **54K online policy trajectories** reported for main RL training were not confirmed as a public corpus.

OpenWebRL belongs in `environment_agent_trajectory_data` because it exposes task, observation, action, environment feedback, terminal status, whole-trajectory reward, and optimizer use. It is not a single homogeneous dataset: success-selected SFT turns, RL prompts, judge examples, and ephemeral online rollouts have different retention, replay, split, and rights properties. The bilingual body is written at L4 review depth while canonical metadata remains `L3_summary_ready` and `status: partial`.
