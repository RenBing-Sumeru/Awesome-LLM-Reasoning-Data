For the **Rollout / Search / Test-Time Trace Data** track, MM-PRM is useful because it exposes the full conceptual conversion from search traces to a selector: multimodal seed -> rollout tree -> terminal judgment -> node value -> sampled process path -> learned step scorer -> Best-of-N ranking. This is a reusable schema for studying how test-time search artifacts become process-supervision data.

The released code supports controlled reconstruction studies. Researchers can replace the terminal judge, vary rollout budgets and search priorities, compare soft and hard targets, preserve rather than balance failure branches, or test aggregation-induced length bias. The checkpoint provides a deployable scorer for cross-model transfer experiments, while MM-K12 supplies a public seed interface.

Reuse should retain the contracts as separate columns or artifacts. Store raw image/question/reference data, exact policy and judge revisions, all rollouts and judge responses, tree topology and search statistics, sampled/filtered paths, per-step MC labels, PRM scores, aggregation rule, and selected terminal answer. Without this ledger, a downstream user cannot tell whether a result comes from better generation, more search, answer-judge behavior, label selection, PRM generalization, or aggregation.

The public package is therefore best treated as a recipe plus seed set and checkpoint, not as an open 747k process-label dataset. Rebuilding the missing annotation layer is necessary before claims about data composition, label quality, failure coverage, or reproducibility can be audited.
