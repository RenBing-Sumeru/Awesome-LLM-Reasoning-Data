MM-PRM turns terminal answer judgments into step-level soft targets through an OmegaPRM-style search. MM-Policy generates multiple continuations from a reasoning prefix. Each completed continuation is compared with the reference answer by a Qwen2.5-72B-Instruct judge in the released code. A node's Monte Carlo value is the fraction of those continuations judged correct. Binary-search expansion follows failed continuations to locate an earlier prefix where future success collapses.

This value is not a direct label that the immediately preceding step is logically valid. It estimates the probability that the rollout policy and answer judge can still reach an accepted final answer from a prefix. It therefore mixes local reasoning quality with problem difficulty, future-sampling quality, candidate diversity, and judge error. The paper deliberately retains the real-valued Monte Carlo score as a soft label rather than thresholding it into a binary step label.

The learned PRM has a separate interface. Given the image/question and an ordered reasoning trace, a special prm marker token is inserted after every step. At each marker, the model produces Yes and No logits; the normalized Yes probability is the step score. During Best-of-N inference, an aggregation rule compresses the score vector for each of 16 candidate paths into one path score, and the highest-ranked path supplies the answer.

Thus the complete feedback chain is: reference answer -> final-answer judge -> rollout outcomes -> node Monte Carlo soft labels -> learned per-step PRM scores -> path aggregation and selection. No link in this chain should be treated as a human proof-validity annotation.
