Inputs -> DAPO starts from math problems and answers scraped from the web and official competition homepages, plus manual annotation. Because source answers can be expressions or formulas, the authors select problems and instruct an unspecified LLM to rewrite each task so the requested result is an integer. Appendix A describes four transformation steps - identify the answer form, rewrite the task, solve the rewrite, and emit an integer - with few-shot examples or guidelines. The released row does not retain the source URL, original answer, rewrite trace, or acceptance decision.

Collection and release -> After selection and transformation, the paper reports DAPO-Math-17K with 17K prompt-integer pairs (Paper §3.5). At Hub revision `65877096c24ffa7abc4e4fa5edb95cf3413a5674`, Dataset Viewer instead exposes one `train` split with 1,791,700 rows and the fields described in §02. Row 0 recurs at offsets 17,917 and 179,170; consumers must not treat the visible row count as 1.79M unique tasks.

Online rollout and feedback -> For each prompt, Qwen2.5-32B samples 16 responses. The paper defines reward as +1 when `is_equivalent` accepts the predicted final answer and -1 otherwise. Dynamic Sampling oversamples and filters groups with accuracy 0 or 1 until 512 eligible prompt groups fill the update batch. Soft Overlong Punishment is zero through 16,384 tokens, decreases linearly over the next 4,096, and reaches -1 at the 20,480-token cap; it is added to correctness reward.

Optimization and outputs -> DAPO removes the KL term, uses group-normalized advantages, Clip-Higher bounds of 0.2/0.28, and token-mean policy-gradient loss. The paper reports AdamW at constant 1e-6, linear warm-up over 20 rollout steps, a 512-prompt training mini-batch, and 16 gradient updates per rollout step. The output is an updated policy, not a curated rollout release. AIME 2024 evaluation repeats the set 32 times with temperature 1.0 and top-p 0.7; those evaluation settings do not disclose paper-run training decoding.

Reproduction boundary -> The current official verl-recipe pins paper reproduction to verl commit `4f80e465c2ec79ab9c3c30ec74b9745de61d0490` and documents 128 H800 GPUs, a container image, and a script using training temperature 1.0/top-p 1.0. The paper does not bind its reported run to that exact artifact, and the DAPO repository's current README still points to a removed `gm-tyx/puffin` branch. Exact reuse therefore requires pinning dataset, verifier, recipe commit, container, hardware, and seeds together.
