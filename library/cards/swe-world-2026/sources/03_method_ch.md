该 pipeline 包含三条相互连接但不等同的数据流。

1. **World-model supervision。** task 来自 SWE-Gym、SWE-rebench 与 R2E-Gym。GLM-4.6 和 MinMax-M2 以 temperature 0.7 在真实 Docker 环境中运行，最多 100 turns。损坏的环境/日志被移除，但有效的 reward-0 与 reward-1 rollout 都会保留。每次执行 record 监督 SWT，终局测试 record 监督 SWR；SWR label 被下采样为 1:1 reward balance。Qwen3-235B-A22B-Thinking 以 Docker output 为条件补充 reverse CoT，之后经过 LLM-judge 过滤。论文报告 26K non-CoT + 26K CoT SWT examples，以及 21K non-CoT + 21K CoT SWR examples。SWT/SWR 从 Qwen2.5-Instruct-32B/72B 进行 SFT；judge 身份、judge sampling budget、acceptance rate 与完整 example release 均为 unknown。（Paper §4.2；Appendix B。）

2. **Docker-free policy data。** 确定性 sandbox 处理导航与编辑，SWT 回答执行 action，SWR 评估 submit action。新的 task pool 从 2010–2025 年 GitHub Archive 约 627K 条记录出发，利用 bot、bug keyword、文本长度、评论数、修改文件数、churn、patch 长度以及相对公开 SWE dataset 的去重规则，筛到 3,763 个 repository 中的 16,550 个 Python Issue-PR task。GLM-4.6/MinMax-M2 在 SWE-World 中 rollout；invalid tool、timeout、context/turn overflow 与 no-submit episode 被删除，SWR 再只保留 reward-1 episode。最终 SWE-World-only policy-SFT set 有 5.7K 条成功 trajectory，因此它与 world-model supervision 不同，会有意丢弃 failure 与 near miss。（Paper §§5.1–5.2；Appendices C、F。）

3. **Policy optimization 与 selection。** Qwen2.5-Coder-32B-Instruct 和 Qwen3-4B-Instruct-2507 进行五个 epoch 的 SFT，maximum context 80K、batch 256、AdamW/cosine schedule、learning rate 从 5e-5 到 5e-6。RL 从这些 checkpoint 初始化，在 GRPO++ 下使用 SWT-32B step feedback 和 SWR-32B terminal reward：每次 update 32 个 problem、每个 problem 四条 rollout、policy temperature 1.0、150-turn 与 108K-context 上限、每条 trajectory timeout 5,400 秒、learning rate 1e-6。TTS@8 采样八个 candidate episode，对每个 candidate 查询 SWR 三次，并选 mean reward 最高者。总 RL steps/rollouts、seed、hardware、compute 与 tie handling 未披露。（Paper §§5.3–5.4；Appendix D。）
