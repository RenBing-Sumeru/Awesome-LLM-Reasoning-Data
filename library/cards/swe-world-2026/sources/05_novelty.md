The prior baseline executes repository commands and tests in Docker-backed SWE environments such as R2E-Gym, SWE-Gym, and SWE-rebench. SWE-World changes the feedback substrate: it learns an action-level transition model and an episode-level reward model from real executions, then composes them with deterministic filesystem operations so policy data generation, RL, and candidate selection can run without per-episode Docker. It also couples that environment recipe to a filtered 16,550-task GitHub pool and to reverse-CoT supervision for the simulators.

The concrete direction signal is the separation of environment feedback into observable contracts: deterministic edit state, SWT-predicted command response, SWR-predicted terminal test outcome, and Docker ground truth used outside the learned loop. This makes it possible to measure which proxy replaces which expensive operation and where false feedback enters an agent trajectory. The paper's reward-hacking analysis is part of the contribution because it demonstrates that cheaper learned environments change the optimization target, not merely the runtime cost.

The individual ingredients are not new: SWE task mining, Docker execution, teacher rollouts, SFT, learned reward models, GRPO-style RL, and best-of-N selection all predate the work. Scale and integration alone do not establish better data. Before reuse, a builder must inspect whether gold-patch conditioning creates shortcuts, whether SWT/SWR calibration transfers across repositories and commands, which failed samples were retained at each stage, and whether the unreleased task/trajectory records can be licensed, split, and traced. Thus the novelty is a specific learned environment/feedback architecture and its measured failure surface, not a claim that Docker-free trajectories are intrinsically higher quality.
