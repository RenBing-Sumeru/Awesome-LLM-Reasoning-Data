The official source is arXiv v1 (submitted 2026-02-03), with an official `RUCAIBox/SWE-World` repository and RUC-AIBOX model collection. SWE-World addresses the cost and throughput bottleneck created when repository agents need a Docker container for every execution and test interaction. Its target is a trainable environment and feedback interface for software-engineering agents, not a new leaderboard whose scores alone establish data quality. It belongs in Environment and Agent Trajectory Data because the episode state, tool action, observation, and terminal predicate are the objects being produced and consumed.

Four related objects must be kept separate. A task is (I=(R,b,d,U)): repository (R), base commit (b), problem statement (d), and validation tests (U); Appendix A additionally exposes fields such as `instance_id`, hints, F2P/P2P tests, `gold_patch`, and `test_patch`. A full episode joins that task to a sequence of thought/action/environment-feedback triples and a final submitted patch. An SWT example is narrower: it attaches to one code-execution action and targets structured `stdout`, `stderr`, and `exit_code`. An SWR example is terminal: it combines the final patch and test context with a generated test report and binary reward. The reported 16,550-task crawl, 26K SWT / 21K SWR supervision sets, and 5.7K policy-SFT trajectories are therefore different counts over different objects, not interchangeable dataset sizes. (Paper §§3–5; Appendix A–C.)

The L4 evidence boundary is asymmetric. The paper, pinned code snapshot, demo trajectory/SFT/RL records, and released model weights were verified, so the environment interfaces and construction recipe can be analyzed. No complete official release was located for the 16,550 tasks, the 26K/21K world-model corpora, or the 5.7K policy trajectories; the Card consequently remains `partial` and at the accepted `L3_summary_ready` curation level rather than treating demos as a reusable corpus.
