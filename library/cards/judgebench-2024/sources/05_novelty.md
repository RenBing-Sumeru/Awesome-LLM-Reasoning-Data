The prior baseline for LLM-as-judge evaluation is usually agreement with human preferences or with a strong teacher judge on open-ended responses. JudgeBench changes the target to objective correctness on hard response pairs, so a judge must know or reason which answer is correct rather than choose the more fluent answer. The quality signal is the released pair schema, official runner, leaderboard space, and support for several judge families and reward models. What is not new: pairwise judging, answer-order bias checks, and reward-model evaluation already existed. Before reuse, inspect source-dataset lineage, whether the public pairs overlap with model training data, MIT dataset terms, prompt templates, order-swap accounting, and whether the objective label truly resolves the pair for the intended domain.
