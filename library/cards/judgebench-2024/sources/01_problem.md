JudgeBench asks whether LLM-based judges can identify objective correctness on hard answer pairs, rather than merely match crowd preferences. The primary source is the arXiv paper submitted on 2024-10-16 and revised as an ICLR 2025 conference paper; official code and data are in the ScalerLab GitHub and Hugging Face releases. Its evaluation object is a question with two model responses, a source-task identifier, a response model, and an objective preference label such as `B>A`. The atlas boundary is judge/reward meta-evaluation: it is not a general chat preference dataset and not a training recipe for better assistants. It is useful because it turns factual, logical, math, and coding correctness into a compact pairwise feedback contract that can audit prompted judges, fine-tuned judges, multi-agent judges, and reward models.
